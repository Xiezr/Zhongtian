> 老板 2026-09-17 指示（初版）：「增加一个文字游戏，依附于城内外建筑、野地和其他城池。
> 设计 500 个故事，要求每段故事至少 1 千字，包含 3 种以上结局分支。开始设计文本」
>
> 老板 2026-09-17 **样张反馈（v2）**：「3段式可读性好，交互性差，适当增长篇幅，5-7段选择。
> 最好还能有背景壁画的变换。」
> → 结构升级为 **5~7 段（层）· 全路径同层 · 每段带壁画**；阅读器满幅背景随段交叉淡入（§八）。
>
> 本目录 = 500 篇故事的**生产现场**（规范 / 正文 / 工装同处，输入输出不分离）。

## 三、单篇结构（v2 · 分层小 DAG）

```
              ┌─→ n2a ─┐    ┌─→ n3a ─┐               ┌─→ e1
n1（第 1 段）─┤        ├──→ ┤        ├──→ ……  →  nN ┤─→ e2     N ∈ 5~7
              └─→ n2b ─┘    └─→ n3b ─┘               └─→ e3
```

- **第 1 段**：启幕（单一幕，开场把"麻烦"立起来）；
- **第 2 ~ N-1 段**：每段 2 个**变体幕**（同层、同题、不同文）——
  读者走进哪一侧，读到的场面、人物、代价都不同；
- **第 N 段（末段）**：单一收束幕，3 个选项 → **互不相同的 3 个结局**；
- **全路径同层**：任何走法都是固定 N 段 + 1 个结局，篇幅可控、节奏一致；
  幕的选项**只能指向下一层**的幕，结局**只能由最深层**指向（`check.py` 判据 4 把关）；
- **层内变体不改变结构**（都汇向下一层），只改变"读到的戏"——这是控成本的关键。

**幕（node）**：`s` 幕题 + `bg` 壁画键 + `t` 正文（≥240 字）+ `o` 选项（2~3 个）
**选项**：`l` 文案 + `d` 后果提示（**必填**——玩家要先知道代价再选）+ `to`（下一层幕；末段为结局）
**结局（ending）**：`id` + `grade`（win / partial / lose）+ `bg` + `t`（≥180 字）+ `reward`

## 四、数据格式（纯 JSON，JSON 是 JS 的子集）

```js
/* story/vol-NN.js */
window.STORY_DATA = (window.STORY_DATA || []).concat([
  {
    "id": "bld-guanfu-01",
    "anchor": { "kind": "building", "id": "guanfu" },   // building | ext | wild | city | misc
    "title": "衙前夜审",
    "hook": "一句话钩子（列表页显示）",
    "tags": ["内政", "悬疑"],
    "when": { "govMin": 1 },                            // 可选触发门（读运行期现有出口）
    "nodes": [
      { "id": "n1", "s": "幕题", "bg": "yat", "t": "≥240 字……",
        "o": [ { "l": "选项文案", "d": "后果提示", "to": "n2a" } ] }
    ],
    "endings": [
      { "id": "e1", "grade": "win", "bg": "xiao", "t": "≥180 字……", "reward": { "gold": 800, "rep": 60 } }
    ]
  }
]);
```

| 字段 | 说明 | 消费点 |
|---|---|---|
| `id` | `<组前缀>-<锚点id>-<两位序号>` | 台账 / 图鉴 / 去重 |
| `anchor` | 依附对象（建筑 / 城外 / 野地 / 城池 / 世事） | 入口挂点 |
| `hook` | 一句话钩子 | 列表与分享 |
| `tags` | 题材标签 | 筛选 / 后续联动 |
| `when` | 触发门（可选） | 引擎侧读现有出口（`govMin`/`lvlMin`/`terrainMin`…） |
| `nodes[].bg` / `endings[].bg` | **壁画键**（下表 13 键） | 阅读器满幅背景（交叉淡入） |
| `nodes[].t` | 幕文 | 阅读 |
| `o[].d` | 后果提示 | **必填**：不给代价的选项 = 猜谜 |
| `endings[].grade` | win/partial/lose | 结算与成就 |
| `endings[].reward` | 奖赏 | **只能用运行期已有 id**（粮木石铁金/声望/人口/精铁/锦囊…），防死数据 |

## 五、校验判据（`python story/tools/check.py` · v2，任一不过退码 1）

| # | 判据 |
|---|---|
| 1 | 数据体是合法 JSON（可从 `concat( … )` 解析） |
| 2 | 篇 id 全局唯一 |
| 3 | `anchor.kind` / `anchor.id` 在白名单内（与真表一致） |
| 4 | **段数 5~7 且全路径同层**：幕的选项只能指向下一层；结局只能由最深层指向 |
| 5 | 每幕 ≥ 2 个选项；选项 `to` 必须指向存在的幕或结局；`l` / `d` 均非空 |
| 6 | 全部幕从首幕**可达**；全部结局**可达**（无孤儿、无死结） |
| 7 | 字数：幕文＋结局文 ≥ 2400；每幕 ≥ 240；每结局 ≥ 180 |
| 8 | 结局 ≥ 3 且覆盖 win / lose；**同一幕的选项不得指向同一结局** |
| 9 | 壁画：每幕 / 每结局必须有 `bg`，且在白名单内（与 `ui.SG_MURAL` 一致） |

## 六、生产流程（可停可续）

```
写 N 篇 ──→ 追加进当前卷 vol-NN.js ──→ python story/tools/check.py        # 卡 9 条判据
                                    └─→ python story/tools/gen_manifest.py # 刷台账
```

- **卷文件**：`vol-01.js` 起，按 25 篇滚动填充；一批写完 A 卷再开 B 卷。
- **台账** `manifest.json`：500 篇的全量计划（id / 锚点 / 序号 / 状态 / 字数 / 结局数 / 所在卷）。
  **下一批该写什么** = 台账里 `status: pending` 的前 N 条 —— 这就是断点续传的接口。
- **每批交付**：卷文件 + 校验结果 + 台账进度；**任意时刻中断都不丢工作**。
- **顺序**：按台账 `seq` 推进（先 16 城内建筑各 10，再城外，再野地，最后城池与世事）。

## 七、写作规范（文风基线 · v2 增补）

- **语体**：半文半白、短句为主，与游戏现有文案同源（例：「斥候来报：此地盘踞着一伙贼寇，倚险扎寨」）。
- **世界观**：汉末三国 + 灵气（已立设定）。**轻仙侠、重江湖、贴三国**。
- **可用**：汉末风物（投壶 / 石经 / 屯田 / 五禽戏 / 煮酒）、28 名将、13 州郡县、灵物（灵鲤 / 白鹿 / 灵蛇 / 灵驹）。
- **每段三件事**：一个具体的场景、一个正在逼近的麻烦、一个**必须现在做的决定**。
- **v2 增补**：
  - 同层两个**变体幕要"真的不同"**（走进哪一侧，读到的场面/人物/代价都不同）；
  - **选项的后果提示要说人话**（给代价，不给谜面）；
  - **末段**是把全线收拢的一问；三个选项必须落在三个**不同**结局；
  - 壁画 `bg` 跟着"这一幕在哪"走（进库房就换 `ku`、出城就换 `men`），随段有变换。
- **结局必有代价**：win 也要写清失去了什么；lose 也要留一条可续的线。
- ⛔ **不写**：现代词汇与网络语、擦边、暗黑血腥、与本作设定冲突的仙侠神通。
- ⛔ **不夹带机制**：故事里不承诺数值效果（奖赏由 `reward` 字段承担）。

**入口（依附锚点）**：城内建筑弹窗 · 城外建筑弹窗 · 野地弹窗（**已占 / 未占两个分支都有**）· 城池面板。
**无故事的锚点整块不出现**（不给空壳）。

**阅读器（v2）**
- `#story-fx` 骨架一次建成：**两层 `.sgr-bg`**（壁画）+ `.sgr-scrim`（沙幕，保正文可读）+ `.sgr-body`（正文）；
- 换段 = 换画：`ui.sgBg(key)` 双层**交叉淡入**（550ms；同键不闪）；
- 段进度：「第 N 段 · 共 M 段」+ 进度点（`sgr-dots`，M = `GAME.SG.rankCount`）；
- 段入场动效 `sgrIn`（340ms，每次换段自然重放）。

**口径（与既有系统的边界）**
1. 数据源 `window.STORY_DATA`（`story/vol-*.js` 追加）；引擎不存内容。
2. 奖赏**唯一出口**复用 `STORY.applyReward`；本引擎只把扁平 `reward` 折成它的入参形状。
3. 运行态 `GAME.SG._run` **不入档**；进度 `s.stories` **入档**（老档懒初始化，不动 `SAVE_VERSION`）。
4. 故事**不进战斗与生产链**、不改任何数值公式；结局奖励里声望不为负。
5. 全屏层 `#story-fx` 与 `#scene-fx` 同规格（body 直挂 · z=1500），互不干扰。

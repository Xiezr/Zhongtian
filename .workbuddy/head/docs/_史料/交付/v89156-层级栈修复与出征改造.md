## ① 病根与修法

### 1.1 「关闭闪烁关不掉」——**live 每秒重绘被误判"进下级"压栈**（本轮最贵 · debug）

**现象**（老板逐字）：「放弃完回到附属野地界面，点击关闭界面按钮之后界面并没有直接关闭，
而是闪烁了一下维持在界面中，并且被删除的那一行又闪烁出现了。需要快速点击几下才能关掉界面。」

**根因链**（jsdom 探针确定性复现，见 §3.1）：
1. `ui.openWilds` 的标题含**动态数字**「🏕️ 附属野地（N/M）」；
2. 放弃一片后 N 变化 → **live 每秒重绘**（`ui.liveModalTick` → `openWilds()`）走 `openModal`；
3. `openModal` 的"标题不同 = 进下级 → **压栈**"判定被命中（数据变化 ≠ 进下级！）→ **每秒压一层**；
4. 关闭键 = `closeModal()` **只弹一层** → 弹出的是**旧快照**（含已被删的行）→
   「闪烁一下维持在界面中、被删的行又出现」；live 下一拍又压回来 →「要点几下才关掉」（只有在两次
   点击间隔 < 1 秒、赛过 live 时才能连弹两层关净）。

**修法三件（全部落在唯一入口）**：

| # | 改动 | 文件 |
|---|---|---|
| ① | `ui._liveRedraw` 标志：live 重绘期间 `openModal` 一律走"同级 replace"，**绝不压栈** | ui.js `openModal` / `liveModalTick` |
| ② | `closeModal` 弹栈后**立即按新数据重绘**（该层是 live 层时）—— 旧快照不再闪现 | ui.js `closeModal` |
| ③ | `sameAs` 接线（v89.117 立的旗 `openShell(opts.sameAs)` 此前**从未被 openModal 消费** = 空承诺） | ui.js `openModal` |

**同类受害面**：一切标题含动态数据的 live 面板 —— `openMarches`（行军队列（N））、
`openLandModal`（等级变化）、`openBuildModal`（升级后 Lv 变化）等，本轮一并愈合。

### 1.4 侦察失败（老板 4）

- **参数表** `DATA.SCOUT_RULE = { base: 0.85, perLv: 0.015, perStar: 0.05, lo: 0.40, hi: 0.97 }`（唯一旋钮）。
- **成功率唯一出口** `GAME.battle.scoutChanceOf(gen, t)`：
  `P = base + perLv×(我方等级 − 守将等级) + perStar×(我方资质星 − 守将资质星)`，clamp [lo, hi]；
  **目标无守将 → p=1（必成，不掷骰）**。
- **失败 = 一无所获**（无情报、无顺手所得、无宝物线索）；落**失败公文**「侦查失败 · X」
  （**不带 `scout` 字段** → 公文列表不可展开面板；正文含【侦查失败】【缘由】（守将名/资质/等级 vs 我方）【建言】）；
  行军抵达的 toast / 军务 msg 走独立文案（`fail: true` + `msg`）。
- 侦察面板（成功态）与分层逻辑不受影响；大雾（降级）与失败（没成）是两个独立概念。

## 6. 诚实缺口

1. **弹栈快照的通用性**：`closeModal` 弹栈仍恢复"旧快照"，只有 **live 层**会立即重绘；
   非 live 层的"回退即旧值"（v89.117 §24.5 的老缺口）仍在 —— 等"opts.reopen"需求出现再改。
2. **调运隐藏三块的边界**：station（己方野地驻守）同样"不接战"，但本轮**未动**（不溢出就最小改动）；
   若要统一口径（station 也隐三块），一句话即可改。
3. **侦察失败率体感**：base 0.85 是"势均力敌"档；若试玩觉得"探野地也老失败"，
   调 `DATA.SCOUT_RULE` 一处即可（lo/hi 已留 40%~97%）。
4. **失败公文与战报图标**：失败报告 `win:false` 在侦查列表里的角标沿用了通用"败"样式，未专门美化。
5. **门禁偶发一次（未复现 · 已复跑 4 次全绿）**：有一次 smoke 报 3095/1（未记录到具体项名就复绿），
   随后单跑 + 连跑 3 次 + gate 复跑全部 3096/0 —— 疑似与时间相关的旧用例偶发（本仓历史上有同类）；
   若再现，按"失败清单逐条重建"处理。

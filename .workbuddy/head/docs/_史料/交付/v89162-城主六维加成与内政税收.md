## ① 列举：城主的六维 → 生产 / 战斗（改后定稿）

| 六维 | 生产 / 经营（**城主**职位生效） | 战斗 |
|---|---|---|
| **统率** | — | —（城主不参战） |
| **内政** | 产量 +1%/点（封顶 +150%）· 建造 +1%/点（+150%）· **税收 +1%/点（+150%）← 本轮新增** | — |
| **勇武** | — | — |

| **体力** | — | — |

- **未任命城主**：以上全为 0（界面写明"未任命（内政/智谋加成为零）"，不静默回落给守将）。
- **界面落点**（三处，真机截图见下）：
  - 将领详情 **六维悬停**：该将任城主时自动带出「城主加成：产量 +X% 建造 +X% 税收 +X%」；
  - **城池面板** 城主行悬停：「内政 → 产量/建造/税收 · 智谋 → 研究/城防」全部加成；
  - 防御体检帮助文案同步（内政→产量/建造/税收）。

**附（对照 · 该将「带队出征」时的六维战斗链，与城主职位无关）**：
勇武→全军攻击 +0.05%/点 · 智谋→全军防御 +0.05%/点 · 统率→统率×100 名士卒吃满加成（覆盖率）·
速度→战斗/行军速度 · 体力→全军生命厚度与出征消耗池。

## ② 内政 → 税收（落地）

| | 改前 | 改后 |
|---|---|---|
| 出口 | 无 | `GAME.mayorBonus(city).tax` = `min(1.5, 内政×0.01×忠诚折扣)` **与产量/建造同率同封顶**（0.01 与 1.5 三个出口同源） |
| 结算 | `(1 + 税制加成)` | `(1 + 税制加成 + 城主内政)` —— **同层相加**（v89.157 加法口径） |
| 实测 | 城主在任税收分毫不变 | 内政 200（封顶）→ 税收 **×2.5**；内政 80 → +80%；解任即还原 |

**顺修的真 bug（探针实证）**：税收**分解与结算在"带税制加成"时分叉** ——
`cityProdPerSec` 乘了 `(1 + cityBonusNum('taxPct'))`（名城/爵位/主城/神器），而 `prodBreakdown`
的税收行没乘（爵位 10 级实测：结算 331.21 vs 分解 331.10，**差 0.11/秒**）= 显示与结算两本账。
修法：分解改**逐城求和**并补「税制加成（名城/爵位/主城/神器）」「城主内政」两行；
俸禄行按 `productionPerSec` 原乘子直接给最终值。修复后探针差值 **0.00e+0**。

## ⑤ 诚实缺口

1. **税加成率（1%/点 · 封顶 +150%）是与产量/建造对齐的建议值** —— 老板未指定具体数值；
   若要更保守（如 0.5%/点、封顶 +100%），改 `domain.js` 的 `mayorBonus` 一行（并同改 GEN_DIMS 无）。
   影响面评估：满城主（内政 ≥150）时税收 ×2.5；GOLD_GATE.tax=0.3 闸门仍在，净量级可控。
2. **城主"战斗侧"仍只有智谋→城防**（城主不参战是 v89.113 定的分工：城主文治 / 守将武功）——
   若要城主也给"守城全军加成"之类，属新设计，等老板点名。
3. 分解的「税制加成」行含四层（名城档位/爵位/主城/神器）合并显示；如要逐层拆分再议。
4. 老档无需迁移（`tax` 是纯派生值，未任命即 0）。

### 2.3 抓到的漏洞（1 个系统性 · 已修）

**战报沙盘重跑与史实不一致** —— 首跑 108000 tick 报出 **23 场 `sandbox-verify-false`**（守城与掠夺两路）。

- **病根**（探针 + 代码审查）：引擎在**重跑**时读的是**当前**的全局加成 ——
  `systems.techBonus`（科技）、`STORY.combatMod`（天时/年号，由 `world.weather/eraIndex` 推导）、
  `STORY.atkMult/siegeMult/cityDefMult`（羁绊）、`state.buffs`（战鼓）。
  30 小时里这些都会漂移（科技升级、换季换天气、羁绊解锁、战鼓到期）→
  **史实读"那一刻"、重跑读"现在"**，校验必然出现假不一致。
  这与 v89.102 的经典教训（"配方必须与开打那一刻逐字节一致"）是同一类病，只是漏在**全局状态**上。
- **修复 = 战斗加成快照**（架构级，跳出了"配方只存军队/将领"的旧框架）：
  - `GAME.battle.boostSnapshot()` —— 唯一出口，开打那一刻把引擎侧全部全局加成打成小快照
    （`techs / world / buffs / atkMult / siegeMult / cityDefMult`，纯数据 ~几百字节）；
  - `GAME.battle.withBoost(bs, fn)` —— 结算与重跑期间把快照**临时装回全局读点**，`try/finally` 逐项还原；
  - 快照随**配方**（`rc.boost`）与**挂起会话**（`_sim.boost`）随身走 ——
    史实结算、挂起重放、沙盘重跑三者同源；出征与守城两条路都接。
- **证据**：修复后 40k 短跑 19/19 真 → 108000 终跑 **56/56 真、0 违规**。
  smoke §98 还留了一条**对照断言**：清掉配方里的 `boost` 后，同一批"篡改全局"使 verify 变 false
  （证明快照真的在起作用，而不是判断被放松）。
- 附带排除：首跑那 1 场"错位假阳性"（`pendingVerify` 布尔标记会在下一次脑周期读到别的战报）→
  驾驶舱改为记**战报引用**，违规消息带 `hist/sim` 明细。

## 四、诚实缺口

1. **斗将 0 次触发**：30h 里没有"双方都有将"的战斗样本；斗将机制只有 smoke §95 的构造用例覆盖，
   缺"真实玩法里触发"的观感证据（见 2.4-C）。
2. **旧档战报的 verify**：无 `boost` 快照的旧战报仍会显示"⚠ 与史实不一致"（2.4-D 待定夺）。
3. **快照清单靠人维护**：`boostSnapshot` 覆盖了当前全部全局读点，但**新增读点时要记得补**
   （2.5-1 给了"哨兵 getter"的解法，尚未实现）。
4. **驾驶舱覆盖边界**：城只到 2 座（建城前提）、爵位只到公士 —— 30h 的"大帝国"场景
   （多城轮转 / 领地管理 / 大规模会战）未覆盖；100 城性能另有专测（v89.107）。
5. **视图体检是"调用级"**：22 个视图函数不抛错、文本无坏值，但**版面几何**（溢出/排版）
   还需 `audit_v89105_modals.js` 与截图体检补位（本轮都已跑，0 溢出）。
6. `npcAtkMsg` 首次记录为"兵力未达 20000（当前 0）"：驱动在 tNow=2400 首次尝试时兵力确实为 0
   （都在行军/采集里）—— 记录口径正常，但**首次记录**可能让人误读，驾驶舱已改为只记首次失败原因。

# v89.167 · 自动升级：每城独立建造位（逐城遍历、分别升级）

> 版本：v89.167 ｜ 日期：2026-09-27 ｜ 老板 1 条需求
>
> **老板原文（逐字）**：
> 自动升级建造，应该每个城池均遍历，分别升级，而不是所有城池一起，总共只升级3个建筑

---

## ① 病根（"3 个"的来源）

`GAME.autoUpgrade`（`js/domain.js`）改前的闸门：

```js
var city = GAME.currentCity() || s.cities[0];
var slots = GAME.buildSlots(city);                        // 当前城的建造位（基础 3）
if ((s.queues.build || []).length >= slots) {             // ⛔ 全境队列总数 vs 单城位
  s.autoState = { paused: false, msg: '队列已满（' + slots + '）' };
  return null;
}
```

**全境一共排 3 条**（3 = 单城基础建造位）就判"队列已满"——其余城池永远轮不上。
叠加第二个因素：试建循环**"第一条成功就 `return`"**（一次调用只排一条）——
两者合成"所有城池一起，总共只升级 3 个建筑"。

---

## ② 修法（五处）

| # | 改前 | 改后 |
|---|---|---|
| 闸门 | 全境队列总数 vs `buildSlots(当前城)` | **`cityRoomOf(ct)`** = `buildQueueUsed(ct.id) < buildSlots(ct)`（两个**既有出口**逐城核对）+ "所有城都满"才报「各城队列已满（合 N 位在办 · 每城独立）」 |
| 候选收集 | 全城一律收 | **跳过位满的城**（不是失败，不污染暂停文案） |
| 试建循环 | 第一条成功就 `return` | **排满各城空位**：成功继续试；某城排满后其候选跳过；`upgradeAt` 内部自带 `checkBuildSlot`（按城位），天然按城封顶 |
| 返回 | `{ ok, target }` | `{ ok, target: 第一条成功, last, count }`（target 兼容旧断言语义） |
| 文案 | "队列已满（3）" | 排入时「本轮排入 N 项（各城独立建造位）· 最新：X → LvN」· 满位时「各城队列已满（合 N 位在办 · 每城独立）」；**面板说明与开启提示同步**补"每城独立建造位 · 逐城遍历、各自排满" |

**没有新造任何数值或口径**：`buildQueueUsed` / `buildSlots` 都是既有出口；
暂停语义完整保持 v89.160（资源不足顺延、全试遍仍无一可动才 paused）。

## ⑤ 诚实缺口

- 一次调用把"各城空位"尽量排满（受各城位与**各自资源**限）——调用频率仍是主循环每秒一次；
  全部满位时靠 `some(cityRoomOf)` 早退（不空转全量试）；
- 离线补算（tickOnce 序列）走同一口径——离线会更快把各城队列排满（设计一致，非缺口）；
- 资源策略未变：自动升级仍"先升等级最低者"（跨城按等级混排），各城在**自己的额度**内排——
  "每城几条"由 `buildSlots(城)` 决定（基础 3 + 专精/爵位/名城/节钺/徭役令加成）。

### 附：本轮升级的旧断言清单（口径变更影响面的活文档）

| 位置 | 旧口径 | 新口径 |

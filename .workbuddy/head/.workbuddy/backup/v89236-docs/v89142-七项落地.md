### 5. 收编 = 转兵 + 支金（`battle.js` / `ui.js` / `data.js`）

```
收编前： 人口 += Σ(数量 × pop)                （免费）
收编后： city.army[t] += n（逐兵种直接入军）   支金 = Σ(n × 兵种造价黄金当量) × 50%
```

- 三出口：`GAME.troopGoldCostOf(tid)`（市场**平价**折金：粮1 木2 石3 铁4 / 每 20 单位 1 金）·
  `GAME.conscriptPlanOf(camp)`（`{byType, men, cost, pct}` 一次取整）· `GAME.doConscriptCaptives`。
- 常量：`DATA.CAPTIVE.conscriptPct = 0.5` · `unknownAs = 'minfu'`（无明细 → 民夫）。
- 金不足**整单拒绝**（不动兵、不扣金、俘虏还在）；`captivePopOf` 旧出口删除。

**单价打表（实测）**：民夫 12.25 · 义兵 16 · 长枪 46.25 · 弓手 70 · 铁骑 425 · 象兵 525（金/人，已含 50%）。

## 五、诚实缺口（请老板拍板 / 已知边界）

1. **地块"从中间向周边"的形态**：12 块时呈**顺时针半环**（中心 2×2 + 右上→右下→下→左下 8 格），
   视觉略偏（不是居中矩形）。若想要"居中矩形块"（如 4×3），换 `GAME.extSlotOrder` 的排序键即可（一处改）。
   三档实机图已给：`v89142-ext-lv1/lv12/full.png`。
2. **「上限」的分配顺序**：按**兵种表顺序**（= 表格行序）依次填满 —— 若希望"强兵优先"（铁骑/象兵先带），
   改 main.js 里的一行排序即可。
3. **候选上限 24**：名城/野地按距离取最近 24（全图 174 座、周边 1459 处）—— 数字是设计选择（`ui.ACT_LIST_N`），可调。
4. **斗将行位置**：固定压播报窗**最底**（时间最早）—— 打开战斗界面时视口在顶部（最新），
   首屏**看不到**它，要滚到底（随后回合推进会自然把它往下压）。若要"一眼可见"，可改为
   顶部状态栏也给一句（一句话改动）——**请老板定**。
5. **折算基准**：支金按市场**平价**（1:2:3:4 每 20 单位 1 金），**不含**市场折损与"物多价贱"——
   与"此刻卖值多少"不同源（那是浮动价）。若要与卖出价挂钩，需接受"支金随市场波动"。
6. **e2e 覆盖**：斗将播报的"必触发"依赖 `DATA.DUEL.chance` 临时置 1（用完还原）；
   真实 50% 概率下的播报由 smoke §123⑦ + 实机 c 脚本覆盖。
7. **12×8 vs 12×9 的对照口径**：只量了格子边长与棋盘尺寸（`fitTile` 算法级），
   未做整屏"缝隙像素"统计 —— 老板的判据是像素块观感，已按算法口径给出 102 vs 91 的差别。

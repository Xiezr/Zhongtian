## 1. 校场出征：限制**总兵力数**，不再按人口

**老板原话**：「谁家校场按人口，不是按人数」。

| | 改前 | 改后 |
|---|---|---|
| 计量 | Σ(兵种.pop × 数量)（人口当量） | Σ(数量)（**人头/人马**） |
| 轻骑 1000 + 义兵 500 | 2000+500 = 2500（轻骑吃双份） | **1500** |
| 报错 | 「校场容量不足（需 Lv N 校场）」 | 同文案（按人马折算等级） |

- **唯一出口**（新）：`GAME.battle.marchCapOf(city)` / `marchMenOf(army)` / `marchCapLvFor(men)` / `MARCH_MEN_PER_LV`。
  出征校验（`battle.prepare`）、调兵校验（`domain.doTransferTroops`）、**抵达复验**（`expedition` owncity 分支）、
  校场面板、建造浮层、`data.js` 描述 —— 全部改读它，**不许再各算一遍**。
- ⚠️ 顺手修掉一处**口径不一致**：调兵与抵达复验原先是"裸容量"（不含满级专精 / 年号 / 军事增益），
  比出发时的门更严 → 会出现"刚发出的兵到自家城门被拦折返"。现在四条路径一把尺。
- 人口仍是**募兵**时的消耗（`GAME.train` / `trainLimitOf` 一字未动）—— 改的只是"出征这道门"的量纲。

## 2. 战报沙盘（固定沙盘 · 逐兵种逐帧）

### 2.1 老板要的格局 → 实际界面

```
🎬 沙盘 · 胜利 · 掠夺 青石寨        共 16 回合 · 114 帧（每个兵种的每次移动/攻击各一帧）· ✅ 与史实逐项一致
┌ 顶栏：第 N/30 回合 · 间距 X · 帧 k/K · 我 <兵力> 敌 <兵力> · 🏯 箭塔 87/100 ┐
│ 我方（竖排 · 306px）        │      沙盘（距离轴）      │   敌军（竖排 · 200px） │
│ 🐎 6.0k [前进][驻守][后退] ▾ │ ●──────►        ◄──────● │ 🏹 3.0k  驻守         │
│ 🏹 4.0k [前进][驻守][后退] ▾ │  （每支部队一条固定泳道）  │ 🛡️ 2.0k  前进         │
└ 帧流（逐帧一行）· 首帧 ◀ 上一帧 ▶播放 下一帧▶ ──────── 🔮沙盘推演 ──────────┘
```

- **固定沙盘**＝每支部队一条**固定泳道**（`--lane` 由行数算出），令牌只在自己泳道上左右移动；
  版式不随帧重排（`left` 走 CSS `transition` 做位移演出）。
- **逐兵种逐帧**：`move / retreat / attack / counter / tower / wall` 六种动作各占一帧，
  帧结构 `[回合, 阵营, 兵种, 动作, 目标, 值1, 值2]`。
- **动作与目标选项框**：我方每行三选（前进/驻守/后退）+ 目标下拉（敌方兵种 / 城防箭塔）；
  回放态显示**该兵种当回合的实际动作**，推演态即改即用。
- 弹窗用 **max 档**（铺满视口）；泳道高度自适应 → **不做弹窗内下拉**（硬规矩）。

### 2.2 数据侧：**存配方，不存帧**（关键设计）

| 方案 | 单场体积 | 风险 |
|---|---|---|
| 存全量帧 | 5~20KB（实测 190 帧 ≈ 7.7KB 原始 JSON） | 60 份战报 ≈ 0.5~1.2MB |
| **存配方**（实装） | **0.8~1.4KB**（实测三场：824 / 996 / 1398 B） | 无（引擎完全确定，见下） |

引擎头注写明「**完全确定（不含 Math.random）—— 同样输入必得同样结果**」，
所以沙盘打开时用**同一把引擎**重跑一遍，得到的就是那一仗的逐帧画面：

- 配方 = 双方配兵 + 双方将领快照（`U.deep(gen)` 实测 337B）+ 战场参数（`simOpts`）
  + **初始阵位**（动作/目标）+ **逐回合指令快照**（观战路径的 `history`）；
- 重跑时以 `opts.stances` 覆盖双方动作/目标 —— 否则玩家事后改了出征战术，同一份战报会跑出另一场仗；
- **校验**：重跑的回合数 / 我方损失 / 敌方损失必须与史实逐项相等（`sb.verify`）；
  不一致（战后又升了科技）→ 沙盘界面标题栏写明"⚠ 与史实不一致（画面仅示意）"，
  并**禁用推演**；旧档战报（无配方）→ 正文页顶部写明原因，退回 v89.94 关键帧回放。

### 2.3 沙盘推演（老板「直至一方兵员消耗完毕」）

「🔮 沙盘推演」从**同一份配方**起一个真会话（`GAME.tactic.begin`，不是另写一套规则）：

1. 起点阵位照史实（`opts.stances` 覆盖），改动作/目标 → `env.setCmd('atk', …)`；
2. 点「完成回合」→ `env.step()` 按引擎规则结算：**目标在移动后仍不在射程内 → 打射程内任意目标**
   （引擎既有语义），出下一帧；
3. 循环至 `env.over`（一方兵员耗尽 / 满 30 回合）→ 帧流给出**史实 vs 推演**对照；
4. 「↩ 回到史实回放」随时切回。

### 2.4 侦查报告不再自动弹出

| | 改前 | 改后 |
|---|---|---|
| 抵达带情报 | **自动弹**分层面板（盖住玩家正在做的事） | `ui.toast` 一条 + 落公文（图标闪黄） |
| 查看 | 只能看当场那一份 | 公文里点开 → 「🔭 展开侦查面板（分层情报）」 |
| 数据 | 面板数据只在内存 | 面板字段**随公文存档**（`report.scout`），旧档照旧走正文 |

## 4. 未实现想法：落地清单与解法

### 4.1 ✅ 已落地 —— 全境营造总览（官府 → 🏗）

- **为什么是它**：测评把城数推到 9 座、建造并行 27 条，而界面只能"一座城一座城点开"——
  城一多，玩家根本看不到全境在办什么，**队列吞吐**于是成了天花板。
- **做了什么**：`GAME.buildOverview()`（跨城摊平：城 / 工程 / 等级 / 进度 / 剩余 / 提速价）+
  `GAME.rushAllBuilds()`（逐条走 `queueRushPay` 同一计价出口）+ `GAME.buildQueueOf(cityId, gridIndex)`
  （**两字段一起比** —— 不复用只比 `gridIndex` 的 `queueAt`，城一多必然撞号）+ max/xxl 弹窗 + 分页。
- **验收**：smoke 3 条（列表 / 定位 / 一键提速）+ e2e 3 条（入口 / 渲染 / 按钮）。

### 4.2 ⏳ 长线目标可视化（节钺 / 名城）

**问题**：节钺只从"首占名城"来，而县城守军当量 1.16 亿 —— 18.75 年不可及，玩家根本不知道这条路存在。

**解法（三步，都可小步落地）**：
1. **看得见**：爵位面板加一行「下一节钺：首占县城（守军当量 ≈ X 万战力，现军力 Y）」；
2. **够得着**：把"磨城"（围攻打到守备归零再决战）做成**显式战术提示**（已有 `siegeChip` 机制，只差引导）；
3. **算得清**：给出"按当前军力还差 N 倍"的读数 —— 把"不可及"变成"还差多少"。

### 4.3 ⏳ 兵种解锁路线图（扩展兵种）

**问题**：6 个扩展兵种全挂"特定州城 + 科技"条件，玩家在募兵页只看到卡片是灰的。

**解法**：`GAME.canTrain` 已经给出精确原因（"需占领青州州城　需科技行军 Lv5"），
只需在募兵页底部加一块**「🔒 未解锁（N）· 达成路线」**：
逐个列出 `兵种 → 缺什么 → 现值/目标值`，并按"还差几项"排序（离得最近的排最前）。
**零新逻辑**（全部读 `canTrain` 的失败项），只加一层呈现。

### 4.4 ⏳ 多城资源调运（辎重车物流）

**问题**：城流之后资源碎片化（9 城各一处库房），而训练/建造吃的是**本城**库存。

**解法**：资源运输**已有**（`domain` 里的城池间运输，带损耗）。缺的是：
① 目标城的选择从"下拉"改成"缺口最大的那座"（一键补库）；
② 运输量默认"补齐目标城的 N 天消耗"；
③ 辎重车（`load 5000`）参与时降损耗 —— 让"带车运输"有正收益。
**注意**：这一条会动经济，必须先在 600× 沙盘上跑对照（`play_rush_1x.js` + 配对统计）。

### 4.5 ⏳ 据点日刷进脑（非游戏侧）

246 座据点每日重生 + 掠夺掉落全表 + 磨城声望 +30/座。**游戏侧无需改动**（`fortRazedToday` 已记录额度），
需要的是自动脑里加一条"日刷循环"：晨间扫 26 格内未掠据点 → 按体力排队 → 晚间补做未完成的。

### 4.6 ⏳ 人口-训练配比（非游戏侧）

工具齐备（民房 / 增民令 / 义兵银行 / 解散归农），缺**定量标定**：
建议在 `play_rush_1x.js` 的 `span` 模式加三个旋钮（民房抢建比例 / 增民令阈值 / 银行比例），
跑 3×3 网格对照，选"骑兵成军时间最短"的组合。

## 6.5 本轮抓到的真 bug（值得记一笔）

**症状**：真浏览器里沙盘**打不开**（推演按钮禁用、回到正文页）。

**根因**：战报配方里的我方兵力是 `{qingqi:0, gongjian:0, …}` ——
`expedition` 里 `returnArmy(city, atkArmy, …)` 结算归队时会把 `atkArmy` **逐项清零**，
而配方是在战报写入处（`returnArmy` **之后**）才取的 `atkArmy` → 重跑成空阵。

**为什么三个测试都没抓到**：
- Node 探针里传的是**副本**，且探针脚本没走到 `returnArmy` 之后；
- 校验写的是 `fin.rounds === hist.rounds` → **`0 === 0` 假通过**（空阵"完美复现"了空史实）；
- `sandboxOf` 之前也没有"至少一帧"的下限。

**修法（三道闸）**：
1. 快照取在**开打前**（`var _sbArmy = U.deep(atkArmy), _sbGen = gen ? U.deep(gen) : null;`
   紧跟 `simulate` 之后、`returnArmy`/`gainExp` 之前）—— 顺带修掉"战后升级的将"问题；
2. `sandboxOf`：`marchMenOf(rc.atkArmy) <= 0` → 直接 `null`；重跑 0 帧 → `null`；
3. 校验要求**双方回合数 ≥1** 才可能为真（堵死 `0 === 0`）。

**教训**：`0 === 0` 是最容易被写进校验的假绿 —— **凡是"相等即通过"的校验，
都要先问一句"有没有平凡解"**。

   `techOf` 快照一起写进配方重放（体积再 +200B/场）。

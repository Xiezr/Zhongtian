# v89.126 人口经济重做 + 城墙并入建筑体系

> 老板三条令：
> 1. 「人口增长模式太磨人了…我提议人口增长速度总是**每 2 小时即可补充人口至上限**，即按固定时间速率」
> 2. 「要让人口对玩家形成部分制约…让除民房以外的建筑（城内，城墙，城外）分别固定占用部分人口额（劳作），
>    这部分人口不能用于征兵；建议在各级政府满配建筑下，占人口 10%-15%」
> 3. 「将城墙与其他建筑并列管理，只是一个有特殊功能的建筑」

---

## 1. 人口增速：固定时间速率（每 2 小时补满）

**病根**（老板实测）：旧公式 `max(保底1, 上限 × 0.05%/游戏时)` —— 8 间 1 级民房上限 800，
增速被保底钉在 **1/时**，补满要 800 游戏小时（@120× ≈ **6.7 现实小时**），"人口根本没增加"。

| | 改前（v89.99~v89.125） | 改后（v89.126） |
|---|---|---|
| 基数 | `上限 × 0.05% / 游戏时`，保底 1 | **`上限 ÷ fillHours`（现实小时）** |
| 补满时长 | 随上限变（且被保底钉死） | **恒定 2 现实小时**（`DATA.POP_CFG.fillHours`） |
| 单位 | 人 / 游戏小时 | 人 / **现实小时**（"跟上玩家游戏时长"） |
| 杠杆 | 守将内政 / 增民令 / 税制 | 保留（补满因此可短于 2 小时） |

**口径**：`popGrowthOf`（唯一出口）返回"人/现实小时"，tick 增量为 `增速 ÷ 3600 × 现实秒`；
侧栏悬停写明"（现实时间）"并给出**预计补满时长**；`base` / `minPerHour` 两字段退役。

**证据**（`probe_v89126_labor_calib.js` + smoke §105）：
```
8 间 1 级民房 → 上限 800 → 增速 400/时（旧公式只有 1/游戏时）→ 补满恰好 2.00 现实小时
tick 真推进 1 现实小时 → pop = 400（= 上限一半）✓；再 1 小时 → 800 封顶 ✓
上限大 40 倍（37440）→ 补满时长同为 2.00 小时 ✓
```

## 2. 劳作占用：非民房建筑占人口（满配 = 上限 × 12.5%）

**模型（唯一出口组，domain.js）**：按"满配进度"折算 ——

```
劳作占用 = 上限 × fullPct × min(1, 已建级数 ÷ 满配级数)
  已建级数 = Σ 城内非民房建筑（含城墙）等级 + Σ 城外地块等级
  满配级数 =（城内建筑数−1 + 城外地块数）× 建筑等级上限
  fullPct  = 12.5%（老板区间 10%-15% 中值，DATA.POP_LABOR）
```

**为什么不用"每级固定人数"**：人口上限随民房按 ×1.18^L 指数涨、建筑级数按线性涨 ——
实测固定人数在县城满配 ≈13%、都城只剩 ≈6%、45 级时 <1%，撑不住 10%-15% 的验收区间。
折算模型让**任何规模的城池满配都是 fullPct**：

| 城池（满配） | 上限 | 劳作占用 | 占比 |
|---|---|---|---|
| 自建城 Lv12 | 23.4 万 | 2.9 万 | **12.50%** |
| 县城 Lv12 | 23.4 万 | 2.9 万 | **12.50%** |
| 郡城 Lv16 | 45.6 万 | 5.7 万 | **12.50%** |
| 州城 Lv20 | 89.1 万 | 11.1 万 | **12.50%** |
| 都城 Lv24 | 173.8 万 | 21.7 万 | **12.50%** |

未满配按级数比例（实测：半配 → 占用比 = 级数比 ✓）；前期小城 ≈0（产业规模小）。
**制约在征兵**：`popFreeOf = 人口 − 劳作`，`GAME.train` 与 `trainLimitOf`（上限按钮）
全部读它；缺额时报"可征人口不足（需 X，可征 Y；劳作占用 Z 不可征兵）"。
界面：侧栏人口悬停显示"劳作占用 X（城市产业，不可征兵）· 可征 Y"；募兵三段条的"可征"即 `popFreeOf`。

## 3. 城墙并入建筑体系（占一格，与其它建筑并列）

| | 改前（v16~v89.125） | 改后（v89.126） |
|---|---|---|
| 占格 | 不占格（`city.wallLv`） | **占城内一格**（cells 里的普通 build） |
| 建造/升级 | 独立出口 `wallCost/buildWall/upgradeWall` + `type:'wall'` 队列 | **通用出口** `buildAt / upgradeAt / cancelRefundOf / queueValueOf` |
| 面板 | 独立 `openWallModal` + 专有动作 `wall-build/rush-wall` | **通用建筑面板**（含珠宝行 / 取消 / 提速，与其它建筑一字不差） |
| 建造菜单 | 不在册 | **在册**（BUILD_ORDER 末尾，第 2 页可见） |
| 环城视觉 | 有 | **保留**（isoWallSVG 外框；点环城 = 打开城墙格面板） |

- **老档迁移**（loadGame）：`city.wallLv > 0` → 搬进第一个空格（无空格则覆盖最低级非官府格），
  之后 `wallLv` 一律删除 —— 不留第二个等级出口。
- **NPC 城**：`CITY_PLAN.order` 收录城墙 → 满配布局 17 → 18 项、民房 30 → 26；
  `npcCityShadow` / 攻占继承 / 战报 `buildReport.wallLv` 全部改读格子（同一读法）。
- **城墙时间口径**：`levelCost` 时间列仍是**哨兵 0**（v89.125 修复保留）→ 占格后走通用兜底
  `等级 × 60` 游戏秒（前 10 级被"最短 5 现实秒"地板抬平，11 级起随等级微增）。
- **顺带修复两处历史不一致**：① 城防技术（citydef）对城墙的折扣过去"修建打折、升级不打折"，
  现在统一走 `cityDefCostOf`（两头都打）；② "珠宝不足（…）"提示原只在城墙升级里，现迁入通用
  `upgradeAt`（12 级后所有建筑升级都受益）。

## 5. 诚实缺口 / 观察项

1. **城墙 1~10 级升级时间被 5 现实秒地板压平**（基准 60~600 游戏秒 < 地板 600）——
   实际观感"每级 5 秒"，11 级起才随等级增长。若要多档区分，需给城墙单列时间曲线。
2. **前期劳作占用 ≈0**（小城产业规模小）：这是"按满配进度折算"的自然结果；
   若希望"建了军营就起码占 1 人"，可给 `popLaborOf` 加保底 1（一句话可加）。
3. **老档迁移策略**：`wallLv` 搬进格子时若城池全满，会覆盖一座**最低级的非官府建筑**
   （优先民房）——城墙不可丢、民房可再建；迁移静默无提示。
4. 劳作占用只约束**征兵**；不影响生产 / 税收 / 人口增长（`popGrowthOf` 不受它影响，§106⑤ 钉住）。

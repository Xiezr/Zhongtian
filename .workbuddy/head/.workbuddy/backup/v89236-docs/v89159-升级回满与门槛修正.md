# v89.159 升级回满 / 多座建筑门槛修正 / 官府总闸严格化（老板 3 条）

> 老板原文（逐字）：
> 1.升级时将领刷新状态，恢复所有体力，精力
> 2.为什么目前民房3级，官府4级，但是民房点不了升级，说需要官府5级。关于官府的等级，有一条应该是其他建造等级不能超过官府等级吧
> 3.记录所有需求，复核是否有未完成项（→ 见 `docs/v89159-需求全量复核.md`）

**两处口径先问后做（老板已拍板）**：
- 第 1 条的"升级"主体 = **将领自身升级**（不是官府升级）：将领练功/战斗/用经验道具升级时，
  该将领体力与精力回满、状态焕然一新。
- 第 2 条遇主城爵位解锁 = **严格 ≤ 官府等级**：爵位解锁抬的是**官府自己**的上限，
  其他建筑随官府同步上去，不再"超前官府 N 级"。

---

## 一、病根（一句话）

| # | 病根 |
|---|---|
| 1 | 将领升级**只加点、不回状态** —— 体力/精力仍是出征后那点余量（升级这个"里程碑"没有任何刷新感） |
| 2 | `buildPrereqOf` 的默认 `next` = **全城最高一座 + 1**（`buildingLevel` 取 max）；民房/军营/仓库可多建 → "另一座已 Lv4、本座 Lv3"时，**本座被按 4→5 的门槛拦下**，报「需官府 Lv5」 |
| 3 | 官府总闸口径是 `官府等级 + 爵位解锁`（v89.102 设计）—— 主城其他建筑**可以超前官府 N 级**，与"其他建造等级不能超过官府等级"相悖 |

## 二、改法（改前 / 改后）

| # | 位置 | 改前 | 改后 |
|---|---|---|---|
| 1 | `battle.js` · `checkLevelUp`（升级**唯一出口**） | 只 `applyLevelGrowth` + 公文一行 | 升级后 `setStaNow(gen, staMax)` + `setEnergyNow(gen, energyMaxOf)` + 公文「✨ X 升级刷新：体力 a/b · 精力 c/d（已回满）」；**多级连升只回一次** |
| 2 | `domain.js` · `upgradeAt` | `buildPrereqOf(city, cell.build.id)`（默认取全城最高级+1） | `buildPrereqOf(city, cell.build.id, cell.build.lvl + 1)` —— 传**本座**目标等级 |
| 2 | `ui.js` · 建筑面板 | 同上（面板与内核各算一份） | 传本座等级（**界面与执行同一把尺**） |
| 3 | `domain.js` · `buildCapOf` | `cap = min(cap, govLv + lift)` | `cap = min(cap, govLv)`（**严格 ≤ 官府**） |
| 3 | `domain.js` · `buildPrereqOf` 闸门 | `next > govLv + lift && govLv < govCap`，`need = max(govLv+1, next−lift)` | `next > govLv && next <= govCap`，`need = next`（报一个**真能到达**的数字；到不了的交由「已达最高等级」报） |
| 3 | `ui.js` · 「等级上限」行 | `Lv{cap}（档位 24 + 爵位解锁 +N）`（被官府压住时数字对不上账） | 被官府压住时写「**受官府 LvN 限制 · 升官府可提升**」，否则仍写"档位 + 爵位解锁" |

**副产物（复核轮抓出的真 bug）**：`finishGather` 是全站**唯一** clamp 的奖励入账，
写法"先加满再截回 cap" —— 在**存量已被奖励顶到上限之上**（v89.158 起的既成事实）时，
这一笔收获会把库存**削回** cap（与「只封增长、不削存量」相悖）。
→ 新增**奖励入账唯一出口** `GAME.addResCapped(key, amount, city) → { added, trimmed, cur }`：
存量 ≥ 上限则一点都不加（也不削）；否则加到上限为止；**装不下的量写进收获明细**
（「粮食 +66.0万（仓容已满，66.0万 未入库）」），不再静默丢弃。

## 五、诚实缺口 / 需要老板定夺

1. **爵位解锁的"体感"变了**：主城现在必须先升官府，其他建筑才跟着上去
   （改前可超前官府 N 级）。**这是按您第 2 条的规则改的**；若您希望保留"超前"，
   改回去是 `buildCapOf` 一行（`govLv` → `govLv + lift`）+ 三条断言。
2. **升级回满的边界**：只回**体力/精力**，不动忠诚/状态标签（出征中/驻守中）；
   多级连升只回一次（多余的部分不叠加成"超额体力"）。
3. **采集入账的城池归属**：顺手把入账对象从"当前城"改成"采集队所属城"
   （`GAME.res()` 是当前城的 getter —— 切城看一眼时收获会落错城）。正常玩法下两者同城，
   无感；老档/多城排队时更正确。
4. **仍未做**（见复核文档）：在途队列是否撤 / 自动出征挑将 / 大罗金丹下架 / U5 溢出口 等，
   已按性价比给建议，等您划范围。

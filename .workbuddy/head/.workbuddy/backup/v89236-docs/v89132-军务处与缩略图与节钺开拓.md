## 三、抓到并修的真 bug（4 个，全部实机量出）

### ① 我城红点被名城层整个盖住（"标注不清晰"的第二重病因）

`diag_v89132_reddot.js` 实测：许都 (357,240) 与某州城近邻重合，读我城**中心像素 = 州城金**
`rgb(253,213,105)` —— 因为旧顺序"我城点先画、名城层后画"，18px 的州城方点把红点吃光。
→ 修：**我城（红点 + 名称）移到 labels 层之后绘制**（自己的位置最优先）。
修后同点实测 `rgb(255,58,42)` ✓。

> 老板说"我城的标注不清晰"其实有**两重**病因：金点与州城金撞色（第一重）+ 被名城层覆盖（第二重）。
> 只改颜色不修顺序，重合的城照样看不见。

### ② `.camp-card` / `.camp-rule` 类名从未定义（静默失效三件套家族）

grep 全仓：这两个类名在 index.html **0 处定义** —— v89.117 加的两营卡片一直是裸 div
（`.wounded-box .wb-head` 是后代选择器，camp-card 内根本不匹配）。→ 本轮补齐样式。

### ③ camp-card 行内兵种图标无尺寸约束 → 两列被带偏 1098 : 272

`diag_v89132_grid.js` 实测：两列应为 685:685，实为 **1098 : 272**；
元凶 = `res-line` 里兵种 `svg.ico` **无 width/height**（按固有尺寸渲染）→ `scroll=1072`，
grid 的 `1fr = minmax(auto,1fr)` 用 min-content 分列 → 左列吃掉 80% 宽。
→ 修：图标定尺寸（`.camp-card .res-line .lbl .ico { 1.15em }`）+
`grid-template-columns: minmax(0,1fr) ×2`（项目既有惯用写法，全仓 15 处）。
修后 **685 : 685** ✓。与本仓既有教训同族（index.html：“`.eq-ico .ico{width/height:100%}`
尤其关键：少了它，位图会按固有尺寸…”）。

### ④ 弹窗审计工具引用已退役出口（工具而非产品）

`audit_v89105_modals.js` 的城墙条目还写着 `ui.openWallModal()` —— 该出口在 v89.126
城墙并入建筑体系时已退役（ui.js 有墓碑）。→ 修工具为 `ui.openBuildModal("wall")`（环城槽，与 `open-wall` 动作同一落点）。
修后 modals 审计 **44/44 · bad 0**（城墙面板 650×611 打开 ✓）。

## 六、诚实缺口与建议（§41 建议式研判）

1. **缩略图波纹只在满界面档**（38px 小图用 1Hz 闪烁替代）—— 尺寸所限；若要小图也画波纹请说一声
   （小图上波纹会被压缩成 1px 光晕，观感存疑，**建议维持现状**）。
2. **我城名称未做重叠避让**：名城层有"压字翻上"的启发式，我城层是直画（城多时会互相压）。
   实测当前规模无碍；若您建到十几座城看着挤，**建议做**，成本一处函数（给 `ui.miniMeLabels` 加同款避让）。
3. **节钺来源未开拓**（仍只有"首占名城 + 爵位"）：这是**故意的** —— 来源一多，稀缺性被通胀侵蚀，
   "限制器"定位就散了。若您想加（如击退来犯给 1 枚），**建议先加消耗不加来源**（当前 4 用途的
   消耗已经能吃掉产出），一句话可改。
4. **每城 2 次上限**（三种扩编共用口径）：按 8 城估算，全扩满 = 48 枚，与中期产出（~47 枚）
   恰好持平 —— 是"真正的取舍"。**建议维持**，嫌紧改 `DATA.JIEYUE` 的 `*Max` 三个字段即可。
5. **招贤纳士的席位加成计在"招贤馆满级专精 +2"之后**（同一出口 `genSlotsOf` 累加）——
   界面上不区分来源；若要拆开显示（"基础/专精/节钺"三段），一句话可加。

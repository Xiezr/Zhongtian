## 一、两条 bug 的病根（先取证，再动手）

###  bug 1｜「战报异常跳转」= 报告身份用了**渲染时刻的数组下标**

| 现场 | 证据 |
|---|---|
| `state.reports` 是**会被 unshift 位移**的数组（新战报永远插最前） | `battle.js` 四处 `s.reports.unshift({...})` |
| 列表页**不随主循环重绘** | 主循环只重绘 `city/ext`（建造数变）、`tasks`（可领数变）、`map`；`reports` 不在其中 |
| 行上写的是**下标**，弹窗内翻页的回调也捕获**下标** | `data-i="' + i + '"`（i = 渲染那一刻的 indexOf）；`modalPage('rlog', …, function () { ui.viewReportText(i); })` |

**后果**：列表渲染后若来了一份新报告（侦察回报 / 守城战报…），所有旧行的下标全部 +1 位移；
点「下页」/点某行时按**新数组**去查 → **打开位移后落在该位置的另一份报告**——正是"掠报弹出侦察报告"。

探针 `probe_v89120_report_nav.js` 的复现读数（改前语义，见 §101 对照实验）：

```
掠报=index 0；unshift 一份新侦察报告后：
  旧下标 0 → 「新侦察丙」（= 老板看到的"跳转"）
  rid    → 「掠报甲」（正确）
```

### bug 2｜「兵种实际行为和设定不一样」= 回放态改设定**静默失效**

沙盘默认落在**史实回放（replay）**态，而 `ui.sdSetCmd` 首行是：

```js
if (!sd || sd.mode !== 'sim' || !sd.sim) return;   // ← replay 态直接 return，连提示都没有
```

老板在回放态点「驻守」chip：**界面显示选中变化、设定完全没生效**。
探针 `probe_v89120b_sim_behavior.js` 对照（改前）：

| 场景 | 读数 |
|---|---|
| 回放态改 yibing=hold | `advance → advance`，`sim=false`，`cmds=(无 sim)` ← **静默失效** |
| 推演态改 yibing=hold + 完成回合 | `advance → hold`；adv **100 → 100**（其余兵 100 → 410）← 引擎侧正常 |

结论：**引擎没问题，是"回放态"这道隐性门槛**——必须先点「🔮 沙盘推演」才能改，界面却没拦也没提示。

## 二、改法

| # | 需求 | 改前 | 改后 |
|---|---|---|---|
| 1 | 战报身份 | 数组下标（`data-i` / `_repView` / rlog 回调） | **稳定身份 `rid`**：`GAME.repRidOf`（自增号、随档走、老档惰性赋号）+ `GAME.repByRid`（唯一取报告出口）；行带 `data-rid`，`_repView → _repId`，**全仓 `_repView` 绝迹** |
| 2 | 推演设定 | 回放态改设定静默 return | **设定即生效**：回放态改设定→**自动进入推演**（`sdSimEnter` 内含 verify 校验；不过则 toast + 重绘回弹，不假装成功） |
| 3 | 三键位置 | 弹窗底栏（xxl 大按钮） | `.bt-top`（读秒行）**正中间**：`.bt-top` 改 **grid 三列**（左读数 / 中三键 / 右提示），按钮降 `btn sm`；底栏不再挂它们 |
| 4 | 回合记录 | 正序追底（`appendChild`），自动滚到底 | **整块置顶**（`insertBefore(frag, firstChild)`）——块间倒序（最新在上）、**块内保持正序**（块首虚线→回合头→逐兵种行）；裁剪改**从末尾删最旧**（`lastChild`）；视口钉在顶部 |

细节三处（都是踩过才知道）：

* **回合块必须"整块"前插**：逐行前插会把块内顺序也倒过来（`第 N 回合` 跑到行下面）；
  用 `DocumentFragment` 一次插入即解。
* **裁剪方向必须反向**：旧版 `removeChild(firstChild)` 删的是顶部 —— 倒叙后最旧的在**底部**。
* **三键用 grid 中列而非绝对定位**：绝对定位在窄屏会**盖住**左右读数；grid 三列是结构性居中，永不重叠。

## 五、诚实缺口

1. **旧档报告的 rid 惰性赋号**：首次访问时按当时数组顺序赋值并随档保存 ——
   若同一份老档在两台设备上分别赋号，编号可能不同（**存的是号不是顺序**，
   所以不影响打开哪份；只影响"跨设备的号"对不上，而它本就不该被人肉引用）。
2. **沙盘「回放态改设定=自动进推演」**：推演从**开战前**重新开始（引擎会话是一次性的，
   不能从当前帧中途接）。提示行已写明"已进入沙盘推演"，但 chip 上没有"点了会进推演"的预告 ——
   若老板希望先提示再切，一句话可加。
3. **回合记录窗口 40 行**（≈5 个回合）：倒叙后从**底部**裁最旧。想看得更多/更少改
   `ui.BT_LOG_MAX` 一处（已抽常量）。
4. **`ui.btLogPush`（逐条流）也已改为"最新在上"**：该路径当前唯一调用是 `btEvent`（且全部
   `quiet=true` 不写日志）——行为一致性保留，若将来启用"逐条字幕"要注意同回合内会倒序。
5. **窄屏**：`.bt-top` 三列在 <1000px 视口下左侧读数会折行（`flex-wrap`），
   三键仍居中不重叠（grid 保证）；未做窄屏专项（本项目一直桌面横屏口径）。
6. **`shot_v89119.js` 等历史工具同步改了 rid 调用**（`viewReport(GAME.repRidOf(...))`）——
   历史补丁脚本（`patch_v89*`）保留原样（它们记录的是当时的状态，不属于运行时工具）。

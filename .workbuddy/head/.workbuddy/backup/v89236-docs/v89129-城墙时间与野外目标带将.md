# v89.129 城墙独立建造时间 + 野外目标带将梳理

> 老板两条（2026-09-26）：
> 1. 「城墙作为建筑，理应有独立的建造时间，和其他任何建筑一样。规划建造时间，结合现实里耗材，耗资，耗时的特点」
> 2. 「任何野外目标（野地，城池，名城等）均应有将领带领，根据等级配备相称资质和等级的将领，梳理当前设置」

---

## ① 病根（一句话）

**城墙此前"耗材/耗资/耗时"三者严重倒挂** —— 资源全表最轻（8 万，仅体系的 **0.34%**）却耗时第二重（10h）；
**据点此前"没有将领带领"** —— 野地/城池/名城守军都有守将（吃加成/侦查可见），唯独据点 `resolveTarget` 无 `guard` 字段。

---

## ② 改法

### 需求 1：城墙 = 双料之王（数据表重排）

| 维度 | 改前 | 改后 | 依据 |
|---|---|---|---|
| **耗时** | T_max 10h（第二重）、1.5 次幂曲线（起 0.58h） | **T_max 24h 顶格 + 独立线性曲线**（起 2h → 终 24h，其他建筑仍是 1.5 次幂） | 现实城墙无"廉价期"，任何一段都是高强度工程；"同一圈墙的连续加固"工程量均匀 |
| **耗材/耗资** | 10 档、80000 封顶、全表最轻 | **12 档 ×2 曲线：17,000 → 3,482 万**（全表之最，超驿站 2,355 万）；**石料占 66%** | 砖石夯土工程石料绝对主导；国家级工程投入最巨 |
| **比例** | 资源/小时 8,000（全表最低） | **145 万/时**（体系带 68~294 万内） | "耗材/耗资/耗时"三者相称 |
| buildCost | 与 levelCost(0) 不一致（3000/2000/10000/2000=17000） | 与 levelCost(0) **逐字一致**（2000/2400/11200/1400） | 项目惯例（民房/军营都一致） |

**独立曲线实现**：`DATA.BUILD_TIME_EXP = { chengqiang: 1.0 }`（默认 1.5）——
唯一出口 `buildTimeSec` 读取；12 级循环 / 单次 ≤24h 两条硬规矩不动。

**城墙新档位速览**（游戏时间）：

```
Lv1→2  2h  ·  17,000 料（石 66%）
Lv6→7  12h ·  544,000 料
Lv11→12 24h · 3,481.6 万料   ← 全表最重
Lv13+ 12 级循环（升到 13 用升到 1 的时长 = 2h）
资源 12 级后封顶（3,481.6 万 · 改需珠宝）
```

### 需求 2：野外目标带将 —— 梳理表 + 缺口修复 + 相称尺子

#### 梳理（当前设置全表 —— 探针实证）

| 野外目标 | 等级范围 | 守将现状（改前） | 守将规则 | 我方出征带将 |
|---|---|---|---|---|
| 野地 | Lv1-10 | 概率（0%→80%，`WILD_GEN_CHANCE`） | 资质随等级：良材→天授（档位 `1+⌊lv/3⌋`）；等级 `max(3,lv×2)+rand(0~4)` | ✓ |
| **据点（野外城池）** | Lv1-10 | **✗ 无（缺口实锤）** | —（本次补上） | ✓ |
| 城池 / 名城 | county / jun / zhou / capital | 必有 | 天授 + 等级档位（60~100 / 100~140 / 140~190 / 190~240） | ✓ |
| 我方城（调兵） | — | 己方守将 | — | ✓ |

- **我方出征"均应有将领带领"已成立**：全部军事入口（出征/掠夺/占领/调兵/驻守/采集/自动出征）
  都过 `battle.prepare` 唯一硬闸；实测真调 `dispatch(genId='')` 与 `expedition(genId=null)`
  **全被拒**（"请选择出征将领"）且不扣兵。
- **据点缺口实锤**：改前 `resolveTarget` 的 fort 分支 `guard=undefined` →
  ① 战斗侧 `scGen = t.guard || null` 恒 null（守方不吃将领加成、不参加斗将）；
  ② 侦查面板"守将"行恒显示「无（守军无将，即无加成）」。

#### 缺口修复：据点守将（`GAME.fortGuardOf`，唯一出口）

| 项 | 口径 | 理由 |
|---|---|---|
| 资质 | `GEN_RANKS[min(4, 2+⌊lv/3⌋)]`：**Lv1-2 英杰 / 3-5 名世 / 6-10 天授** | 比同级野地高一档（据点是"城"，守军 ≈10 倍于野地） |
| 等级 | `max(10, lv×4+20)+rand(0~5)`：**Lv1 → 24~29 · Lv10 → 60~65** | Lv10 据点 ≈ 弱县城守将（60~100）下端，与"野地里的城"定位相称 |
| 必有 | 非概率 | 野地贼寇可无大当家；据点是有建制的守备军 |
| 确定性 | 名字/资质/等级/特性/四维按 **(x,y,level)+map seed** 经 `_fortHash` 派生（`makeGeneral` 新增第 8 参"确定性 rng 流"） | 同一天"侦查看到的 == 打起来遇到的"（与野地/城池同规矩） |
| 刷新 | 随据点等级变（每日） | 不存档、不占 `generals` 列表（与 `npcCityGuard` 同族：接触时派生） |

**防御战引擎自动生效**：战报"守方阵容"、侦查名册、斗将（50% 战前触发）——
全走 `t.guard`，零额外接线。

#### 相称尺子（"根据等级配备相称资质和等级的将领"）

- **`GAME.guardRankIdxOf(kind, lv)`**：资质档位映射**唯一出口**（野地守将 / 据点守将 / 建议行 三处共用）。
- **`GAME.recGenOf(t)`**：出征某目标"宜派"的档位（纯按**公开信息**：目标类型+等级；
  守将实情请侦查 —— v89.64「不然还要侦察何用」；**软提示、非门槛**）：

| 目标 | 相称建议 |
|---|---|
| 野地 Lv1 | 良材 Lv3+ |
| 野地 Lv10 | 天授 Lv20+ |
| 据点 Lv1 | 英杰 Lv24+ |
| 据点 Lv10 | 天授 Lv60+ |
| 县城 / 郡城 / 州城 / 都城 | 天授 Lv60+ / Lv100+ / Lv140+ / Lv190+ |
| 调兵（owncity） | null（无建议） |

- **出征面板**：「主将 · 可用道具」区新增一行 `相称建议：宜 英杰 Lv6+ 带队`（实机真渲染验证）。

## ⑤ 诚实缺口 / 待老板定夺（建议版）

1. **野地"概率有将"是否改"必有"**：
   - 现状：`WILD_GEN_CHANCE = [0,0,0,0.04,...,0.8]`（Lv1-3 无将、Lv10 才 80%）——"贼寇不一定有大当家"的设计。
   - **建议维持概率**（野地与"城"性质不同；且新手区不因守将变难）；若要"野地也必有将"，
     一句话可改（该表全置 1）。**等您拍板。**
2. **相称是否升级为"硬门槛"（不相称禁止出征）**：
   - 现状：**软提示**（面板建议行；出征本身不拦）。
   - **建议维持软提示**（玩家自由度高；小将打大城是玩家的战术选择，打输自担）。
3. **自动出征的"按等级配备"**：
   - 现状：自动出征**固定一位将领**打所有目标（`cfg.genId`），目标等级不参与选将。
   - **建议改造**：把"出征将领"由"固定一位"升级为"**自动按目标等级挑相称者**"
     （从空闲将领中选；仍可手动锁定一位）。成本：`autoMarchOnce` 选将 + 配置 UI + 断言，约一处小轮。
     **等您拍板**（这是本轮唯一"我判断需要您决策"的项）。
4. **据点守将让据点战变难**（守方吃加成）：Lv10 据点 ≈ +10~20% 有效战力；
   本轮门禁全量通过（既有据点战断言未受影响），实战平衡建议试玩观察。

## ⑥ 本轮抓到的"假 bug"（记档 · 调试干货）

截图脚本首版**直接调 `scoutTarget`** 渲染面板 → 面板全锁（"侦察技巧 Lv0 / 需 Lv99"）。
排查后确认**不是产品 bug**：实机链路走 `expedition` 的 scout 分支，
**它才把 `sc.intel` 包装成面板要的 `intelTiers` 字段**（内层 `scoutTarget` 返回 `intel`——
这个名字在别处是"战报日志行数组"，面板注释明确警告过拿错）。
教训：**探针/截图要走"用户真实链路"，调内层函数会漏掉包装层**（与 §18.2 "面板读解析后的那份"同族）。

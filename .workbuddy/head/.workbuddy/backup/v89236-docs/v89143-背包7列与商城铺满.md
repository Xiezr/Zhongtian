## 二、改法

### 1. 背包（`ui.js`）

| 项 | 改前 | 改后 |
|---|---|---|
| 物品子页网格 | `pageRows(…, 16)` → **4 列** `.shop-rows` | `pageBag(…, rows)` → **7 列** `.bag-grid`（与材料/图纸/装备同网格） |
| 每页格数 | `BAG_PER_PAGE = 16`（= 2 行 + 2 格，**末行缺 5 格**） | **28**（= 4 行 × 7 列，整行不截） |
| 物品分段 | 无分组标题（裸格子平铺） | **按类型分段**（标题 + 网格，与材料/图纸页同构） |
| 「全部」分类 | chip 首项 + 三段并排分支 | **整条退役**；归一出口 `bagSubNorm` / `bagSubFirstOf` |
| 归一规则 | — | 老的/空的/失效的分类值 → **第一个有货分类**（材料 → 类型序 → 图纸）；全空 → 材料页（空态） |
| 摘要 | `'all'` 分支（材料 N 个 / K 种） | `{当前分类} N 件（宝物共 M 件）` |

### 2. 商城（`ui.js` + `index.html`）

```css
/* 满高 flex 列：标题/分类条按内容，物品区吃掉剩余高度 */
.ui-page.shop-page { display: flex; flex-direction: column; height: 100%; box-sizing: border-box; }
/* 满页（16 件 = 4 行）时 4 行平分可视区；窗口小到 <116px/行 退回滚动 */
.ui-page.shop-page .shop-rows.shop-fill { flex: 1 1 auto; min-height: 0;
  align-content: stretch; grid-auto-rows: minmax(116px, 1fr); }
/* 卡片内部同步撑满：信息区吃剩余高度、操作行钉卡底 */
.ui-page.shop-page .shop-rows.shop-fill .item-row { grid-template-rows: minmax(0, 1fr) auto; }
```

- 渲染端：`ui.shopHTML` 给页面加 `shop-page`；**满页**（`slice.length >= per`）时给物品区加 `shop-fill`。
- **不满 4 行不拉伸**（两张卡被撑成巨型是丑态）—— 只有满页走自适应。
- 列数仍固定 4（v89.140 的"四行四列"口径不变）：变的只是**行高**。

## 五、诚实缺口（已知边界）

1. **不满 4 行的分类不铺满**：商城某分类只剩几件时，物品区保持 116px 行高、下方留白（内容本来就不够）。
   若要"无论如何都撑满"，需接受"两张卡被拉成巨型"的观感 —— 当前选择是**只对满页铺满**。
2. **背包每页 28 格的高度**：材料/图纸页按系列分组，多分组时 4 行可能略超一屏（`.view-box` 可滚动）。
   本局 24 种材料在一屏内 ✓；材料全满（如 40+ 种）时会出现内部滚动 —— 若老板要求"永远一屏"，
   把 `BAG_PER_PAGE` 降到 21（3 行）即可（一处改）。
3. **「全部」分类删除的连带**：老深链 `openBag('item')` 现在落到"第一个有货分类"（材料），
   不再有"一眼看全部"的入口 —— 若老板仍想要"总览"，建议做成**摘要行**而不是一个分类页。
4. **像素对照的口径**：只量了"下半屏内容占比"（同背景基准）。
   "全屏内容占比"因背景基准漂移不可用（本次实测里它给出"改后更低"的假象，已在体检脚本注释说明）。

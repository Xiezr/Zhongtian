## ② 排版对齐的三级病根（都是"真布局"才暴露的）

**目标**：人口行增速列右缘 = 资源行增速列右缘（实测基准 **359px**）。

| 迭代 | 现象（实测右缘） | 病根 |
|---|---|---|
| 首版 | 439 vs 359（差 80） | `.val` 第一列用 `1fr` —— 它**吸收**容器全部剩余宽，把定宽 72px 的增速列**挤出行外**（资源行第一列是定宽 74px，所以没事） |
| 改 `auto` 后 | 449 vs 359（差 90） | **裸文本节点 = 独立网格项**：HTML 里 `2,880` 没包 span，于是 `2,880`/`cap`/`rate-wrap` 各占一列 → 增速列被顶到第三列（`1.1em` = 15px）里溢出 |
| 包 `.amt` 后 | 369 vs 359（差 10） | 人口行行级模板缺**第三列占位**：资源行 `56px 1fr auto` 的 `auto`（徽标位）+ 列间距把 `.val` 右缘推到 373；人口行 `44px 1fr` 的 `.val` 贴到 383 → 差 10 |
| 补 `auto` 列 | **359 vs 359（差 0）** ✓ | `44px 1fr auto`（首列 44px 给 `.val` 让宽——人口存量文本比资源存量宽约 25px） |

**定稿 CSS**：

```css
#city-attrs .pop-line     { grid-template-columns: 44px 1fr auto; }   /* 行级：与资源行同构 */
#city-attrs .pop-line .val { grid-template-columns: auto 72px 1.1em;  /* 值级：与资源行一字不差 */
                             justify-content: end; }
```

## ⑤ 诚实缺口

1. **像素级对齐不能在 Node 桩里断言**（无布局，`getBoundingClientRect` 恒 0）——
   本轮的守护是"结构断言（smoke §103②）+ 实机脚本自带判定"两层；
   若日后有人动这两行的 CSS，实机脚本会给出量化差值（差 >2px 打 ✗）。
2. 首列宽度两行不同（人口 44px / 资源 56px）——标签都靠左（左缘实测一致），
   若未来给资源行加宽首列内容（如四字标签），需同步复查。
3. 资源行的第三列（`auto`）在 badge 绝对定位（v65 改）之后**恒为空**——
   它现在的实际作用是"**空占位**"：让 `.val` 右缘左移一个列间距（与资源行一致）。
   人口行照抄了这个占位；若日后资源行去掉该列，两行需同步改（实机脚本会当场报差值）。

# UI 设计交接（给外部设计 AI 的现状与需求说明）

> **用途**：把这份文档 + `.workbuddy/shots/ui-review/` 下的 20 张图（17 张现役界面截图 + 3 张素材拼图）
> 一起交给外部设计 AI，让它**在这个项目的现有基础上做界面重设计**。
> 最后更新：v70（2026-09-14）。

---

## 〇、30 秒速览

- **是什么**：《热血三国》复刻 · 单机「经营 + 回合制战斗」中文网页游戏。当前 v70，迭代 70 轮。
- **技术栈**：纯前端 HTML/CSS/JS，**零构建、零外链依赖**，双击 `index.html` 即玩（`file://`），localStorage 存档。
- **规模**：15 个 JS 模块 / 23,800 行；`index.html` 2,575 行（含全部 CSS）；13 个主视图 + 约 57 个弹窗；4 套主题 / 73 个 CSS 变量。
- **视觉基底**：暗金 / 木质古典（深绿底 `#1e2a1e`、木框 `#6b3f1d`、暗金描边 `#c9a24b`、羊皮纸 `#efe6cf`）。
- **一句话现状**：功能密度高、结构纪律好，但**视觉统一性靠"补丁式统一"**（弹窗骨架、字体层级、命名都统一过一轮），
  整体观感偏"功能与风格仍在收敛中"——这就是本轮要找设计 AI 的原因。

---

## 一、硬约束（重设计不能违反）

| # | 约束 | 说明 |
|---|---|---|
| 1 | **零外链 / 零依赖** | 不能用 CDN、外部字体、图标字体、任何运行时网络请求。字体只能用系统字体栈（当前是中文衬线/黑体混合栈） |
| 2 | **无构建** | 没有打包器。CSS 在 `index.html` 的 `<style>` 里，JS 是普通 `<script>` 顺序加载。设计落地 = 改这一个 HTML 的 CSS + 少量 JS |
| 3 | **纯 DOM + CSS** | 仅地图用 Canvas 2D。tab、卡片、弹窗全是 DOM 元素 —— 设计稿必须"能被 CSS 实现"（复杂 SVG 可以内联） |
| 4 | **多主题** | 4 套主题：默认（暗金木质）/ bamboo（竹）/ silk（绸）/ night。**所有结构色必须走 CSS 变量**（JS 里不允许出现色值）；新配色要能在 4 套主题下成立 |
| 5 | **存档兼容** | UI 改动不能要求改存档结构 |
| 6 | **测试锚定** | 项目有 1985+ 条 smoke 断言与 681 条真实 DOM e2e 断言，部分锚定具体 DOM 类名/文案。重设计落地时需保留这些锚点（详见第六节） |

### 2.2 弹窗体系（约 57 个）

**弹窗骨架**（v68 统一后）：

```
┌─────────────────────────────┐
│ m-head   标题（金色 heading）│
├─────────────────────────────┤
│ m-body   正文               │
│   ├─ 功能行（用建筑）        │  ← op-zone 分区标题 + op-row 按钮行
│   ├─ 升级行（费用 + 按钮同行）│  ← op-row-between
│   └─ 危险操作 / 底栏         │  ← [拆毁] [关闭] [移动] 三格
├─────────────────────────────┤
│ m-foot / bldg-foot  按钮区   │
└─────────────────────────────┘
```

**三档宽度**：sm 440×420 · lg 860×600 · xl 960×700（`max-width: 94vw` 兜底）。

**动线规范**：建筑详情弹窗固定三段——**功能（使用）→ 升级（建设）→ 管理（拆毁/移动）**；
底栏固定 `[拆毁(左)] [关闭(中)] [移动/交换(右)]`，关闭居中是防误点的缓冲带。

**功能多的建筑**（军营/铁匠铺/官府/客栈/校场）弹窗内容各异 —— 这是被允许的；
被统一的是**骨架、页脚、按钮位、命名规则**。

截图：`16-modal-guanfu.png`（官府面板）、`17-modal-bldg.png`（普通建筑）。

### 2.3 全局组件

- **顶栏导航**：13 个 tab + 分组分隔符 + 右侧"天时"（季节/天候/年号）。tab 图标是内联 SVG 线描。
- **左/右侧栏**：君主卡（头像/声望/爵位）+ 资源列表（名称/存量/产量三列）+ 城防值。
- **悬停浮层**：全站唯一一层（`#tip-layer`），鼠标悬停产量/属性时显示明细。
- **toast**：轻提示（右下/顶部）。
- **导航徽标**：仅"待办型"（任务可领取数）；状态型不挂（行军队列数已撤）。

## 三、已固化的设计规范（重设计需保留的语义）

### 3.1 字体层级（当前）

| 变量 | 值 | 用途 |
|---|---|---|
| `--fs-lead` | 14px | 强调正文 |
| `--fs-body` | 13px | 正文 |
| `--fs-sub` | 12px | 次要信息 |
| `--fs-cap` | 11px | 说明/角标 |

> 历史上老板明确要求过："**各字体适当处理，同级别界面的字体一致性要好，不同功能的字体大小颜色得当**"。
> 标题字号另设（gold-heading 等），比正文大 1~4px。

### 3.2 间距与圆角

`--sp-1..6` = 4 / 6 / 8 / 10 / 14 / 18 px；`--r-sm/md/lg/xl` = 4 / 6 / 8 / 10 px。

### 3.3 色板（默认主题核心变量）

| 变量 | 值 | 用途 |
|---|---|---|
| `--gold` / `--gold-light` / `--gold-dark` | `#c09640` / `#edd08a` / `#5f5010` | 主强调（描边/标题/主按钮） |
| `--teal` | 青蓝 | 次按钮 |
| `--red` | 朱红 `#8a2b1f` 系 | 危险操作 |
| `--green-ok` | `#7bc96f` | 成功/正向 |
| `--bg-dark` / `--bg-2` / `--bg-3` | 三层背景 | 页面底 / 面板 / 凹陷区 |
| `--surface*` | 卡片面 | 内容承载 |
| `--line` / `--sep-gold` | 分隔线 | 常规线 / 金线 |

> 半透明阴影与描边统一走三个 RGB 三元组（`--sh-rgb` / `--hl-rgb` / `--gold-rgb`），保证换主题时整体换向。

### 3.4 历史审美要求（历轮原话提炼 —— 重设计务必遵守）

1. **"要人类的好看，不要工程的美感"** —— 禁止"工程正确但难看"的排布（如等比拥挤、机械对称）。
2. **简洁优先** —— 一个地块上方不要叠多层文字；"现在地块全飘起来，根本看不清"是历史事故。
3. **图标代地块** —— 建筑/资源用图标本身表达，等级用**图标内右上角数字**，不要图标下方多行文字。
4. **禁止下拉框 / 滚动条** —— 选项用 chips（圆角点选按钮组）；内容多就**翻页**，不要出现长滚动条（弹窗内）。
5. **删"备注型"信息，留"信息型"** —— "游戏怎么运作/怎么操作"的说明文字删除；"当前事实是什么"保留。
6. **对齐** —— 资源列表的名称/存量/产量按**末尾文字逐位对齐**，不允许错位参差。
7. **三层界面统一** —— 大界面（整页）/ 弹窗 / 地图的视觉语言要互相一致（曾做过统一整改）。
8. **命名要合理** —— 操作入口名要覆盖其全部内容（反例：官府面板曾叫"征收"，实际含征调/特产/岁贡/改名四件事 → 已改"官府事务"）。
9. **悬停有明细** —— 数值悬停时用小浮层显示"基础值 + 各类加成/扣除"。
10. **不要 emoji 当图标**（历史 v12 要求"图标不要色块+emoji，要手绘"）—— 现役建筑/资源图标均为 AI 生成的写实风 PNG；emoji 仅兜底。

### 3.5 现有可复用的视觉语言（不要另造）

- 卡片系：`.troop-card`（兵种卡）/ `.story-card` / `.q-card`（任务卡）/ `.inn-card` / `.auto-card` / `.set-card` / `.lord-card`
- 专用槽位：`.doll-slot`（12 装备槽）/ `.eq-cell` / `.bag-cell`
- 通用件：`.wood-frame`（木框）/ `.inner-panel` / `.gold-heading`（金色标题）/ `.chip` / `.btn`（glyph 系：gold/red/dim/sm/lg）/ `.attr`（键值行）/ `.op-row` / `.note-warn`
- 分区标题：`.op-zone-t`

**风格说明**：图标是 **AI 生成的写实/厚涂风**（暗金木质基调、精细材质、透明底）；
头像池是**写实古风人物**（半身、脸居中）；名将头像是**同名专属绘制**。三者风格已基本统一，但**并非同一批次生成**，细节有风格差。

### 5.2 素材使用规则（历史事故换来的）

- **地图素材必须是"俯视正方形铺满"**（不能用等距菱形）—— 判据：不透明区四角 α≈1 且实心≈1。
- 切图用"象限 + 四边内缩 2%"（切掉素材自带白线），**不抠底**。
- 图标显示尺寸上限 **84px**（兵种卡），城格 **76px**。用 1024 源渲染到 84px = 12 倍过采样；
  实测 **256px 与 1024px 无感差异**（差异 >8/255 的像素仅 0.27%），素材重采样是既定优化方向。
- ⚠️ 已知缺陷：地图地形位图（12 个 `ai_terrain_*` / `ai_city_*`）**已从磁盘移除但代码仍在请求**（外部 AI 无需处理，标注备查）。

### 5.3 素材原料（不进版本库，另行备份）

`assets/icons/raw`（33 张 / 39MB）、`assets/portraits/_raw`（28 张 / 42MB）、`pd_src`（29 张 / 3MB）——
AI 生成的原始大图。**设计 AI 如需风格参照，以运行期素材拼图为准**（原料不随仓库分发）。

## 六、设计要求与交付方式

### 6.1 建议交付什么

| 优先级 | 交付物 | 落地方式 |
|---|---|---|
| ★★★ | **CSS 变量新值**（色板/字号/间距的调整建议） | 直接替换 `:root` 区块，4 套主题各给一组 |
| ★★★ | **待设计界面的布局稿**（线框/视觉稿，标注尺寸与状态） | 照现有类名体系出一份"HTML+CSS 片段"最容易试装 |
| ★★ | **组件规范修正**（按钮/卡片/弹窗的层级、间距、状态色） | 说明改哪个类的哪条属性 |
| ★★ | **创建界面 + 地图导航条 的重设计** | 同上 |
| ★ | 图标素材的替换建议（如需要，给出**生成 prompt 口径**而非直接换图） | 项目素材全部 AI 生成，prompt 可复现 |

### 6.2 不许做的事

1. 引入任何外部资源（字体/CDN/图片外链/图标字体）。
2. 用 canvas/WebGL 重写界面（地图除外）。
3. 破坏 4 套主题中的任何一套（暗金是默认，但夜/竹/绸都必须仍可用）。
4. 依赖 hover 才能完成的操作（要能纯点击完成）；不依赖右键菜单。
5. 不要把"说明文字"塞进界面（见 3.4 第 5 条）。

### 6.3 落地验收（回传后项目侧会做）

- 跑 `smoke-test.js`（1985+ 断言）+ `e2e-test.js`（681 条真实 DOM）确认没打破锚定结构；
- 用既有截图脚本（`.workbuddy/shots/ui-review/` 同款）重截对比；
- 4 套主题逐一截图验收。

## 附录 A · 给外部 AI 的开场提示词（可直接粘贴）


# 逐步场景玩法设计（江湖路 · 可变深度）

> 老板 2026-09-17 指示：「检索全网，建立逐步场景玩法，增加玩家自主性，**别固定 3 步走**」。
>
> **本文件只做设计，不动代码**（照项目惯例：规划 → 拍板 → 落地）。每条给：数据表 / 唯一出口 /
> 可验证判据 / 工作量级，以便拍板后**直接照做**。
>
> **与既有文档的分工**（防重复）：
> `江湖场景与玩法素材库.md` 管**内容清单**（34 场景 / 37 玩法候选，回答"有什么好玩"）；
> **本文件管推进结构**（回答"一次游历如何展开"）。两者不重叠，可并行落地。

---

## 〇、一句话结论

把现在的「**固定 2~3 幕线性剧本 + 系数累加**」换成
「**故事块池按状态筛选 + 动词分支 + 玩家自己决定何时收手**」——

**深度不再由数据写死，而由三个来源共同决定：玩家收手 / 世界收束 / 条件开门**，
一次游历的步数落在 **2~7 步**之间，且每个状态不同的玩家看到的是不同的戏。

## 一、现状与问题（逐行核实，不采信印象）

| # | 现象 | 代码证据 | 玩家感受 |
|---|---|---|---|
| A1 | **幕数写死** | `DATA.SCENE_FLOW[act].stages` 是定长数组；`scenePick` 用 `fx.stage >= fly.stages.length` 判结束（`state.js:3525`） | 每个活动永远 2~3 幕；第二次玩一模一样 |
| A2 | **选择不改走向** | `scenePick` 里只有四路累乘：`mods.pow *= e.pow` / `.reward` / `.wound` / `luck += `（`state.js:3520-3523`） | 选什么只改最终数字，**看不见差别**；没有"选这条路"的感觉 |
| A3 | **中途零收益** | 结算只在末幕一次发生（`jianghuRoll`） | 前三幕是纯过场，没有"每走一步都有进账"的推进感 |
| A4 | **无条件门** | 幕序列与角色状态无关（只受活动/地形/等级门） | 天授装备的君主与空手新手看**同一套剧本**——状态不影响"看到什么" |
| A5 | **不能见好就收** | 只有 `sceneEscape`（中途退出＝放弃本次全部），没有"落袋为安" | 要么走完、要么全弃——**没有中途决策**，这是自主性缺失的核心 |

> 归因：这套系统是 v89 按"**脚本演出**"思路做的（幕题/对白/时机条、演出很完整），
> 但它本质上是一条**写死的轨道**。演出值得保留，缺的是**结构**。

## 二、全网检索：四条脉络与本地化

### 2.1 故事块 / 质量驱动叙事（Storylet · QBN）★ 主结构来源

Fallen London / Sunless Sea（Failbetter）与 Emily Short 的"质量驱动叙事"（quality-based narrative, QBN）：
**内容是离散、自足、可复用的小块（storylet），由"品质"（状态变量）决定此刻哪些块"够格出现"**；
作者写块，玩家编织自己的故事。要点：

- 三条性质：**离散 / 自足 / 可重排**——块之间**不互相依赖**，因此不存在分支树爆炸；
- 选择改变状态（"效果"），**状态反过来改变下一批候选**→ 形成涌现叙事（emergent narrative）；
- 内容浮现策略（Kreminski 综述）：① 全给玩家自己选（自由度最高）② 编成小图 ③ 按显著度
  （salience，如 Hades）④ 加权随机——**本项目宜用「加权随机 + 条件门」**（确定性友好、可测）；
- 四种序列形态（Short）：短决策推进、**强制线性（为张力）**、**开放探索（可随时退出）**、
  **专属随机牌堆（可随时退出）**——本设计取「可随时退出」这一族。

### 2.2 推进-收手（Push-your-luck）★ 自主性核心来源

Chicken Road / Can't Stop / Incan Gold / Aviator：**收益随步数上升、失败率同步上升**，
"停在哪一步"本身就是全部决策。设计要点：

- 张力来自**亏损厌恶**（保不住的痛 > 多得的爽）与**沉没成本**（"都到第 5 步了"）；
- 有效的做法是给玩家**可控的减震器**（护符 / 跳关 / 加倍或归零），
  让"继续"是**计算过的风险**而不是纯赌；
- 研究结论一句话：「**决定何时停止、何时继续，本身就是一种自主感**」。

> ⚠️ 本地化红线：本项目基调是"**不卡点不惩罚**"——所以**只赌倍率、不赌本金**
> （逐步落袋的小收益永不失去，见 §六.1）。这是与"赌博式"设计的分界。

### 2.3 动词系统（太吾绘卷 / 鬼谷八荒）★ 选项形态来源

两款游戏让玩家**用"动词"作用于世界**（闲聊/夸赞/赠礼/决斗/切磋/叙旧/请教/偷师/交换/唬骗…），
动词触发事件、检定出结果，玩家自由排列而叙事自洽。

> 原话提炼：「一种'动词'，其实就是一种相比'故事块'更微小的'事件块'」。
> **动词的产出不是数值，而是"接下来会发生什么类型的事"。**

### 2.4 风险-收益双结局 + 结果随实力变化（鬼谷八荒奇遇）

同一事件**因境界不同而结果不同**（低境界吃苦头、高境界得增益）；**纯坏事件与好事并存**；
选择带道德/风险对立（帮谁 / 趁乱取利 / 静观）。

### 2.5 不适用项（明确排除）

| 来源做法 | 为什么不做 |
|---|---|
| 多人社交向事件（拍卖/联姻/结义） | 单机不成立（素材库已同判） |
| 偷窃/下毒/暗杀类"暗黑动词" | 与"轻松明亮"基调冲突（素材库已同判） |
| 大规模对话树（BG3 式） | 组合爆炸，维护不了；本设计用**可复用块**规避 |

## 三、设计总览：一次游历的生命周期

```
① 入局      jianghuCheck（现有，不动）
                ↓
② 起幕      从「本活动 × 本地形 × 我的状态」的候选池里抽一个开场块
                ↓
③ 选动词    2~4 个动词（察 / 谈 / 取 / 隐 / 息 / 秘）
            —— 动词不只是改系数，它**决定下一批候选池**（真分支）
                ↓
④ 继续/收手 ★每一步之后都是决策★
            继续 → 深度 +1：收益倍率↑ 风险倍率↑，并**当场落袋**一小笔
            收手 → 立即结算，保留全部已得倍率
                ↓
⑤ 收束      三个来源之二：世界（块自带 end）/ 条件（池空 · 深度上限）
                ↓
⑥ 结算      现有 jianghuRoll 内核不动（深度与路径折算成 mods 入参）
```

**与今天的差别**：幕序不再是数据里写死的数组，而是**每次现抽**；
选项不再是"三句回答"，而是**六个动词**；深度不再是 `stages.length`，而是**玩家停在哪儿**。

## 四、数据结构（三张表）

### 4.1 `DATA.SCENE_VERBS` —— 六动词（唯一来源，UI 徽章同读此表）

| k | 名 | 语义 | 默认效果 e | 可通向的池标签 `yields` |
|---|---|---|---|---|
| `cha` | **察** | 观察、试探、侦察 | `pow +0.03 · luck +1` | `probe` `avoid` |
| `tan` | **谈** | 交涉、劝降、论价 | `reward +0.08` | `parley` `gift` |
| `qu` | **取** | 强攻、速取、硬夺 | `pow +0.10 · wound +0.15` | `fight` `greed` |
| `yin` | **隐** | 潜行、绕行、藏形 | `wound −0.20 · reward −0.05` | `stealth` `avoid` |
| `xi` | **息** | 休整、疗伤、整队 | `wound −0.30 · pow −0.05` | `rest` |
| `mi` | **秘** | 施法、布阵、用计 | `pow +0.06 · luck +2`（可耗**锦囊**换强选项） | `arcane` |

- 六动词是**全部活动共用**的——这是"加内容=加数据"的关键：新增活动只需配块，不必配动词。
- `mi` 与既有 **计谋/锦囊体系**（v86）咬合：走"秘"时可选择消耗 1 枚锦囊换取本步强选项
  （消耗走现有 `s.items.talis` 出口，不新增道具）。

### 4.2 `DATA.SCENE_NODES` —— 故事块池（新表 · 内容都加在这里）

```js
DATA.SCENE_NODES = {
  'tao_probe': {
    act: ['tao'],                  // 归属活动；也可写 terrain:['hill','forest'] 当地形通用块
    w: 10,                         // 基础权重
    when: { lv: [0, 10], stam: 20,  // 品质门：野地等级区间 / 体力下限
            items: ['talis'],       // 需求（可选）
            season: ['spring','autumn'], weather: ['clear','wind'],   // 天时门（可选）
            depth: [1, 4],          // 只在此深度区间出现
            verbs: ['qu','cha'] },  // 需要此前走过这些动词（可选）
    once: true,                    // 本局至多一次
    s: '试探虚实',                  // 幕题（沿用 v89.1 的幕题位）
    t: '寨门半开，鼓声不密 —— 像是虚张声势，又像是请君入瓮。',
    art: 'fort',                   // 场景画（复用 map.paintScene 的 12 种）
    tags: ['probe'],               // 命中的池标签（供上一动词的 yields 收窄）
    bank: { jinghua: 2, gold: 30 },// ★本步当场落袋（永不失去）
    verbs: [                       // 本块给出的动词（覆盖 4.1 的默认效果，可只给 2~3 个）
      { k:'cha', l:'先观其形', d:'按兵不动，看清虚实', e:{ pow:1.05, luck:1 } },
      { k:'qu',  l:'骤然发难', d:'兵贵神速，趁其未备', e:{ pow:1.15, wound:1.3 } },
      { k:'tan', l:'寨前喊话', d:'先礼后兵', e:{ reward:1.1 } },
      { k:'yin', l:'寻路摸寨', d:'避开正面', e:{ wound:0.8, reward:1.05 } } ],
  },
  'tao_ambush': { act:['tao'], end: true, s:'强敌压境', t:'…', bank:{…} },   // 世界收束
  ...
}
```

**字段说明（每个字段都必须有消费点，否则 audit 报死数据）**：

| 字段 | 消费点 |
|---|---|
| `act` / `terrain` | `stageCands` 归属过滤 |
| `w` | `stageDraw` 加权抽取 |
| `when.*` | `stageCands` 品质门（各键一一对应现有出口：lv→`chk.lv`、stam→`staNow`、items→`s.items`、season/weather→`story`、depth→`fx.depth`、verbs→`fx.path`） |
| `once` | `stageCands` 去重（`fx.seen`） |
| `s` / `t` / `art` | 渲染（沿用 `.sxf-*` 位） |
| `bank` | `stageTake` 落袋（走现有资源/材料入库出口） |
| `verbs[].e` | 并入 `fx.mods`（四路累乘，机制不变） |
| `verbs[].k` | 写 `fx.path`（下一轮 `when.verbs` 与 `yields` 都读它） |
| `tags` + `yields` | 下一批候选池收窄（真分支） |
| `end` | 自动收束 → 结算 |

### 4.3 `DATA.SCENE_ENGINE` —— 引擎常量（**调平衡只改这张表**）

```js
DATA.SCENE_ENGINE = {
  minDepth: 2, maxDepth: 7,     // 深度上下限（下限定 2 保证"至少两幕"的演出体量）
  gainPerStep: 0.18,            // 每深一步：收益倍率 +18%
  riskPerStep: 0.15,            // 每深一步：负伤倍率 +15%
  failBase: 0.06, failPerStep: 0.08,   // 大失败率：首步 6%，之后每步 +8%
  stepCost: { energy: 0, stam: 0 },    // 步进成本（默认 0 = 不额外扣；要加难度再开）
  deepBonusAt: [5, 7],          // 深入奖励档：第 5 / 7 步各触发一档额外产出
  bankKeep: true,               // 收手是否保留全部倍率（false = 打折，见拍板项 2）
}
```

**深度表（由上表推导，UI 直接读同一函数 `GAME.depthCurve()`）**：

| 深度 | 收益倍率 | 负伤倍率 | 大失败率 | 深入奖励 |
|---|---|---|---|---|
| 1 | ×1.00 | ×1.00 | 6% | — |
| 2 | ×1.18 | ×1.15 | 14% | — |
| 3 | ×1.36 | ×1.30 | 22% | — |
| 4 | ×1.54 | ×1.45 | 30% | — |
| 5 | ×1.72 | ×1.60 | 38% | ★ 材料档 +1 |
| 6 | ×1.90 | ×1.75 | 46% | — |
| 7 | ×2.08 | ×1.90 | 54% | ★ 精华档 +1 |

## 五、引擎与唯一出口

### 5.1 出口清单（全部挂 `GAME`，登记进备忘「十一、单一出口全量清单」）

| 出口 | 职责 | 备注 |
|---|---|---|
| `GAME.depthCurve(d)` | 深度 d 的倍率/失败率读数 | **唯一数值口**，UI 与结算同读 |
| `GAME.stageCands(fx)` | 当前候选池（归属 × 未走 × `when` × 池标签） | **唯一筛选口** |
| `GAME.stageDraw(fx)` | 按种子抽块：`invasionRoll(seed + '\|sel\|' + fx.depth)` | 确定性 |
| `GAME.stageTake(i)` | 选动词：记账 → 落袋 `bank` → 收窄池 → 判收束 | 替代今天的 `scenePick` 语义 |
| `GAME.stagePush()` | 继续深入：深度 +1（含步进成本、上限钳制） | 新增 |
| `GAME.stageBank()` | 见好就收：按深度折算 mods → 调既有 `jianghuRoll` | 新增 |
| `GAME.sceneFlowOf(actId)` | **兼容层**：老 `SCENE_FLOW` 编译成定长节点链 | 老内容零迁移 |

### 5.2 与现有系统的接法（**零改动的部分**）

- `jianghuCheck` 不动（地形门 / 逐地分布门 / 君主门 / 精力体力 / 日锁）；
- `jianghuSpend` 不动（首次选择才扣费＋落锁，`fx.spent` 语义保留）；
- `jianghuRoll` 内核不动 —— 新引擎只是把"深度倍率 × 路径修正 × 大失败判定"折算进它的
  `mods`（`pow` / `reward` / `wound` / `luck`）四个入参；
- `GAME.sceneFx` 仍是**运行期状态、不入档**（一次游历是短会话，撕档/关窗即结束——与今天一致）；
- `sceneEscape`（弃掉本次）保留为「未动身零消耗 / 已动身所耗不返」的原语义。

### 5.3 确定性不变式（项目硬规矩）

> **同 (x, y, act, day, 动词序列, 收手点) → 同块序 → 同结算。**

实现：抽取与判定全部走 `GAME.invasionRoll(seed + salt)`；`fx` 里只存**已发生的事实**
（`depth` / `path` / `seen` / `mods`），不存随机数。任何"重开同一场景"的测试可逐位复现。

### 5.4 老内容零迁移（兼容层）

`GAME.sceneFlowOf(actId)`：
若 `DATA.SCENE_NODES` 中没有该活动的块，则把 `SCENE_FLOW[actId].stages` 逐幕编译为节点
（每幕一块、动词 `yields` 为空、`minDepth = 幕数`、无 `bank`、无 `end`）→
**行为与今天逐位一致**（判据：编译前后 `mods` 序列相等）。12 个活动可**分批迁到新表**，不要求一次到位。

## 六、自主性的四个抓手（这是本次设计的核心）

### 6.1 推进 / 收手（深度自主）

- 每走一步：**当场落袋**一小笔（`bank`，如精华 2 / 金 30）——**永不失去**；
- 结算倍率随深度上升（×1.00 → ×2.08），但**大失败率**同步上升（6% → 54%）；
- 大失败 = **倍率归 1**（回到基准结算）＋ 一次负伤——**不没收已落袋的收益**；
- 玩家可**任何一步之后收手**（`stageBank`），保留当前倍率完整结算。

> 为什么"只赌倍率不赌本金"：项目基调是"不卡点不惩罚"。
> 深了失败 = "白忙一场但没亏"，浅了收手 = "稳但少"——**两头都不劝退，只有取舍**。

### 6.2 动词（走向自主）

选项不是"回答"，而是**动作**。动词的 `yields` 标签**收窄下一批候选池**：
选「察」→ 下一幕偏"试探/回避"类；选「取」→ 偏"交战/贪取"类。
**不同动词序列 → 不同戏路**，且这个差别**玩家看得见**（下一幕的幕题就变了）。

### 6.3 品质门（"我能看到什么"的自主）

四类门全部读**现有出口**，不新增状态：

| 门 | 读什么 | 玩家侧表现 |
|---|---|---|
| 身份/灵力 | `GAME.lingPowerOf(g)`、`chk.lv` | 灵力高 → 解锁 `arcane` / `probe` 深块（"秘境入口"） |
| 行装 | `s.items`（锦囊 / 止血散 / 马鞭） | 带锦囊 → 「秘」动词出现强选项 |
| 天时 | `story.currentSeason/Weather` | 春秋/晴风各有专属块（复用既有季节·天气表） |
| 状态 | `staNow` / `energy` / `fx.depth` / `fx.path` | 带伤 → 出现休整块；走深 → 出现高危高酬块 |

→ 同一格野地、同一个活动，**天授装与新手看到的是两套戏**。

### 6.4 深度账本（让自主"被看见"）

结算屏除现有战果行外，新增三行（照 v89.1 的"耗用账单"先例）：
```
此行第 5 步收手　│　收益 ×1.72　负伤 ×1.60
若再深一步：×1.90，大失败率 46%
落袋：精华 8 · 金 120（此项不受大失败影响）
```
**"若再深一步"这一行是关键**——它把"我本可以"变成可见的选择，而不是隐藏概率。

## 七、UI 规格（沿用现成组件，不新造视觉语言）

| 位 | 内容 | 复用 |
|---|---|---|
| 顶部横幅 | 地形染色 + 幕景水印 + 活动双章 + 深度标尺 | `.sxf-hero`（v89.1）＋新增 `.sxf-depth` 步进条 |
| 深度标尺 | `● ● ● ○ ○ ○ ○` + 右侧双行读数「获 ×1.36　险 ×1.30」 | 令牌：金=收益 / 红=风险 |
| 幕题条 | 第 N / ≤7 步 + 幕题 | `.sxf-stage-tag`（现成） |
| 动词行 | 2~4 枚动词按钮，各带**派生倾向徽章**（攻/获/险/稳/缘） | `.sxf-badges`（v89.1 现成：由修正系数直接派生） |
| 决策行 | **「继续深入」（金）／「见好就收」（默认）** | 新增 `.sxf-push/.sxf-bank` 两枚按钮；底部固定 |
| 结算卡 | 光晕徽记 + 战果行 + **深度账本三行** | `.sxf-result`（现成） |

**红线（照项目既有规矩）**：
① 字号只走 7 档令牌、字重三档（400/700/800）；
② 逐格率/深度账本的数字**全部来自 `GAME.depthCurve`**，界面不做二次计算；
③ 动效 ≤400ms 且可跳过（与"关动效"开关同处）；
④ 不出现 emoji 之外的"新符号体系"——倾向徽章沿用 v89.1 的五枚。

> 视觉稿见画布「热血三国 · UI改善提案」第 ⑤ 区（深度标尺 + 动词行 + 继续/收手 + 深度账本）。

## 八、可验证判据（照项目习惯，每条都能翻转）

| # | 判据 | 做法 |
|---|---|---|
| 1 | **深度可变**（不固定 3 步） | 同活动跑 200 组随机动词序列 → 出现 **≥4 种深度**、`min ≤ 3`、`max ≥ 6` |
| 2 | **收手即锁定** | `stageBank()` 后 `fx.phase==='result'`；再调 `stagePush/Take` 一律拒绝并给理由 |
| 3 | **同选择同结果** | 同 (x,y,act,day,动词序列,收手点) 跑 2 次 → 结算逐位相等 |
| 4 | **老剧本零迁移** | `sceneFlowOf(老活动)` 编译后与今天 `SCENE_FLOW.stages` 的 `mods` 序列**逐位相等** |
| 5 | **无死标签** | 每个块的每个 `yields` 标签，在候选池里**至少有一个可命中块**（否则报错——防死数据） |
| 6 | **无死字段** | `when` 的每个键都有消费点；`bank` 的每种资源都走既有入库出口 |
| 7 | **上限硬钳** | 深度永远 ≤ `maxDepth`；池空时**自然收束**并给出文案（不留空界面） |
| 8 | **大失败不没收本金** | 桩定 `failPerStep` 使其必失败 → 落袋收益仍在（可翻转） |
| 9 | **成本可关** | `stepCost` 置 0 时全程零额外消耗（默认态断言） |

## 十、待拍板（设计不做决定）

| # | 事项 | 备选 | 影响 |
|---|---|---|---|
| 1 | **深度上下限** | 2~7（建议）／ 2~5（保守）／ 3~9（激进） | 一次游历的时间（现在约 40 秒，2~7 步约 1~3 分钟） |
| 2 | **收手是否打折** | 不打折（建议，`bankKeep:true`）／ 收手 ×0.85（更劝退贪心） | 决定"继续"的诱惑强度 |
| 3 | **是否引入步进成本** | 默认 0（建议先关）／ 第 4 步起每步 +1 精力 | 深度是否消耗资源 |
| 4 | **"世界收束"要不要**（块自带 `end`） | 要（建议：让世界也有决定权，避免"玩家永远能走满"） | 深度可变性的第二来源 |
| 5 | **大失败的手感** | 倍率归 1（建议，不亏本金）／ 倍率归 1 + 额外负伤 ／ 本次全失（不推荐） | 体验红线 |
| 6 | **迁移节奏** | 先两个样板（建议）／ 12 活动一次迁完 | 风险与周期 |

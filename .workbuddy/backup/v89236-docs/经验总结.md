## 二、可复用工作流（四条）

### 1. 补丁式改动流程（七步 · 本会话标准动作）

```
① 侦察定位（精确到行号 / 字节）→ ② 写补丁脚本（预检命中 count==1；幂等：命中 0 且新文本已在 → SKIP）
→ ③ 落盘回查（assert 新文本存在）→ ④ node --check 语法
→ ⑤ 行为探针（无头 Node 跑真实逻辑，如「120× 15 秒 → +1 且零公文」）
→ ⑥ 三件套门禁（audit → smoke → e2e，缺一不可）
→ ⑦ 文档补录（需求档案 / 设计规范 / 工作备忘 / 工作记忆）+ 提交
```

要点：一条一处 · 锚点唯一断言 · **补丁幂等**（中断可安全重跑）· **改完先 check 再跑测试**（曾两次被 `node --check` 当场抓住拼接符号错误）。

### 2. 故事库产线（五步）

**选题**（防撞名逐条比对全库题名 + 锚点分配 + **卷号由主会话统一发号**）
→ **并行生产**（子代理写 `.part` 暂存文件；任务书直接给定题名与判据，不许改动）
→ **独立复验六件套**（逐卷复跑 check_file / 双转义字节扫 / 半角标点 / 撞名 / id 唯一 / 志怪红线）
→ **统一入位**（改名 + 全库 check）
→ **单方接线**（index.html 载入 + smoke 卷断言 + e2e VOL89 表一行）+ 三件套。

### 3. 并行子代理纪律（四条 · 血泪换的）

- **卷号统一发号**：子代理不得自己 `max+1`——曾多路并发抢写同一 vol-31，互覆丢稿；
- **共享文件单方收口**：`index.html` / `smoke-test.js` / `e2e-test.js` 只在全部卷落盘后由单一方一次性接线（曾有截断前例）；
- **同文件修改串行执行**：一次消息里两处 Edit 以同底稿写回，后者会吞前者（补丁脚本曾自吞跳过逻辑）；

## 三、技术教训（15 则 · 现象 → 根因 → 对策）

### A. 内容质量类（4）

1. **双转义**：「\n」被写成「\\n」——游戏里直接露出字样、段落不换行；双转义是合法 JSON，常规校验拦不住。
   对策：追加文本一律用 raw 字符串（`r'''...'''`）；`check.py` 判据 10（文本禁字面反斜杠）+ 字节级扫描
   （`反斜杠总数 − \n 对数 = 残余，应为 0`）。
2. **补字回声**：给不足字数的幕补字时复述前句（如同幕「更鼓敲过三更」出现两遍）。
   对策：**补字必须新增信息、禁止复述前句**；相似度扫描（≥0.55 阈值）纳入复验。
3. **英文残留 / 幽灵物品**：`itself` / `risk` / `timing` 等混入正文；reward 出现白名单外物品（`talis`，会被照写进存档）。
   对策：判据 11（英文残留）/ 判据 12（reward 白名单），全库扫描归零。
4. **志怪红线**：志异线必须「妖物不出场 · 不落实锤 · 志怪 ≠ 志恐」。
   对策：专项扫描（恐怖词 / 实锤词清单）+ 显示层抽读，纳入每批复验。

### B. 测试断言类（4）

5. **快照断言陷阱**：`SG.anchor(...).length === N` 写死数字，被后续批次顶高即误红。
   对策：一律**下限语义（≥ N）**——语义是「防数据丢失」，不是「锁快照」。
6. **成本改动踢爆老测试**：耗粮 ×3 后，「靠环境资源恰好够」的募兵加速测试拒绝第二条队列。
   对策：**测试补环境、不改判据**（补足资源后只管「加速定位」这一个断言）。
7. **被调用 ≠ 被消费**：烽火预警 IIFE 返回值被丢弃（函数确实被调用，躲过死函数审计，但横幅从未上屏）。
   对策：**返回值流向也要断言**；修复后补运行时断言钉住。
8. **测试自身也会挖坑**：smoke 早期把 `generals.length = 1` 截断，导致新断言「缺君主对象」而走跳过分支。
   对策：断言构造**现场补对象**（临时补一位君主、打完移除），不让断言放空。

### C. 文件写入类（3）

9. **文件末尾无换行的边界**：「行后插入」把新行拼到了旧行行尾（`|| 21 |` 粘连）。
   对策：插入逻辑先**归一化「文件末尾换行」**；插入后统一复检「行首前 2 字节 / 行尾 / 下行首」。
10. **混合行尾**：README 表格行 CRLF、正文 LF；按错行尾匹配即静默失配。
    对策：**逐处探测字节**，读写用 `newline=''` 原样保留。
11. **大文件三段式落盘**：85KB 的卷分 3 段写（Write 头 + 2 篇 → 追加 2 篇 → 追加尾 2 篇 + 收口），
    每段做「命中 == 1」回查；中断可安全重跑。

### D. Git 与协作类（4）

12. **「.gitignore 是权威」**：hero 回退层 30 张被工作区误删（半途迁移遗留），但 .gitignore 注释、「运行期素材」定性、
    代码回退链引用三处证据一致 → `git restore` 恢复并探针验证（28 人 ↔ 文件一一对应）。
    判「该不该恢复」看三处证据，不靠猜。
13. **跟踪引用丢失 → 自动推送静默失效**：`origin/main` 引用缺失（`git status -sb` 显示 `[gone]`）→
    post-commit 钩子 `@{u}` 计算失败、静默跳过。修：`git fetch origin`；极端环境（`update-ref` 不落盘怪癖）
    可 shell 直写 ref 文件。**查同步状态用 `ls-remote` vs `HEAD`，别信 `status`**。
14. **沙箱网络 vs 真网络分层**：工具沙箱内 GitHub 不通（代理 502）≠ 机器不通（提权通道 SSH/TLS 握手正常）。
    网络类操作先「分层探测」（`ls-remote` / `curl`）再下结论。
15. **脚本自身陷阱**：① 三引号嵌套炸（文本里嵌 `"""`）；② 非 raw 字符串转义被吃；③ 占位残留段混进脚本；
    ④ 一次消息双 Edit 自吞。对策：脚本先跑 `py_compile` / 分段执行；同文件修改串行。

## 四、设计方法论（从老板反馈提炼 · 五条）

1. **入口哲学三级跳**：列表菜单（信息全但打扰）→ **概率奇遇**（独立 asset + 轻量随机）→ **动作触发**（上下文相关 + 因果感）。
   每次演进都更「贴情境」、更「不打断」——「一个故事作为一个独立 asset」是本会话最重要的产品判断。
2. **题材写作四口径**：轻仙侠重江湖贴三国（江湖线）· 志怪 ≠ 志恐（半解 + 留白 + 妖物不出场）·
   平视笔法（四夷线一律本地视角，不猎奇不贬损）· 克制白描（不堆辞藻、不喊口号、不替玩家讲道理）。
3. **判据先行**：任何批量生产先立**可验证判据**（check.py 12 条），再生产——「不能自动判的批量，一定会烂尾」。
4. **批量工程三件套**：台账（manifest + pending 断点）· 校验（check / check_file）· **独立复验**
   （独立于生产者的第二双眼睛，哪怕生产者是 AI）。
5. **系统退役方法论**：退休一个系统 = 列「唯一出口清单」逐处退役（引擎 / UI / 测试 / 审计 / 文档），
    让 audit 兜底；严禁「半复活」残留。

## 五、给下一次会话的提醒（Top 6）

1. **故事库 500/500 已完成**——增量需求走「修订 / 扩建」而非新建卷；改动仍走 check + 复验。
2. **逸闻入口三层**（点击掷骰 / 动作触发 / 世事并入）——改机制前先读 `GAME.SG.TRIG / SG.ACT / actPool`。
3. **门禁三件套是硬门槛**；断言一律 ≥ 语义；改动涉及成本 / 数值时，先跑一遍老测试看谁「靠巧合」。
4. **写文件补丁前**：探字节（行尾）、探末尾换行、保幂等；**同文件修改串行**。
5. **git**：提交即自动推送（post-commit 钩子）；先确认跟踪引用健康（`git status -sb` 无 `[gone]`）。
6. **文档四件套随每轮更新**：`需求档案.md`（唯一台账）+ `设计规范.md` + `AI工作备忘.md` + 工作记忆。

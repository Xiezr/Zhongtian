## ① 自动征兵「触发线 / 目标」数值框不可填写（上轮清单 · 真 bug）

**病根（实机取证）**：click 委托只把 `<select>` 排除在外（v53 的老修）——数字输入框带着
`data-action="autotrain-set"`，**点它的那一下就被当按钮派发**：
`autotrain-set → ui.renderView('auto')` 重建整页 DOM → **输入框当场被替换、焦点秒丢**。
实机证据（修复前）：`afterClick: {focused:false}`、打字不落地，而"点击"却把当时的旧值提交了。

**修法（两处，缺一不可）**：
| # | 落点 | 内容 |
|---|---|---|
| ① | `main.js` click 委托 | 排除名单 `SELECT → SELECT + INPUT`（输入类一律由 change 三条监听线处理） |
| ② | `main.js` `autotrain-set` case | change 落库重绘后，**把焦点还给同一个数值框**（连改多个值不必重新点） |

**验证**：实机 ①b「真点后焦点保留」/ ①c「真打字 value=1234」/ ①d「change 落库 state=1234 + 焦点归还」；
e2e「点输入框不派发动作（框未被重建 · 值未被点击提交）」+「change 真落库(777)」。

## ② 解雇 / 晋升按钮错开（防误点）

**修法**：新增 `--gp-ops-stagger: 40px`（一个按钮宽 36 + 4）；`.gp-rankops190` 改
`margin-left: calc(var(--gp-ops-shift) + var(--gp-ops-stagger))` —— **晋升右移到 x=682**，
两条点击带横向重叠 = **0**（点歪落空，不会误触）。

**实机复量**：解雇 (642, 121.7) / 晋升 (682, 143.7) · dx=40 · overlapX=0。

### 3.2 配对闸（老板 3-①②）：口径 = 「只能追、不能甩」

`cap = 对方等级 + 2`（单向上限 → **天然无死锁**：落后方永远能追，老档大差距自然收敛）。
- 例：城墙 Lv3 / 作坊 Lv0 → 城墙上限被压到 **2**，升 4 报
  「城墙与工匠作坊等级相差不得超过 2 级 —— 需先把工匠作坊升到 Lv2（当前 Lv0）」；
- 作坊侧不受限（cap=5），先追平再一起爬。

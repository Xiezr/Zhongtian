# v89.182 将领对军队战的加成 —— 全链路取证

> 老板问：「目前是否考虑了将领对军队战的加成呢？」
> 本文件是**取证型交付**（零代码改动）：把将领进战斗的完整链路、五条通道、
> 实测数字全部摊开。全部读数走真实出口（`GAME.genAttrs` / `GAME.staHpBonus` /
> `T.perAtk/perDef/perHp` / `T.simulate`），不自行复算公式。

## 一、结论（一句话）

**已全面接线**：将领通过 **五条通道** 影响军队战——攻 / 防 / 生命 / 速度 / 统率覆盖，
全部由 `unitsOf → perAtk/perDef/perHp` 在**引擎级**注入（攻守两侧同规，
NPC 守将 / 我方出征将 / 守城将走同一套）；玩家在**战斗悬停**里能看到加成后的
"全军血量 / 全军攻击 / 全军防御"（脚注"已含科技 / 将领 / 装备加成"）。

## 二、五条通道（唯一出口 → 落点）

| # | 通道 | 换算（唯一原子） | 落点（引擎） | 生效面 |
|---|---|---|---|---|
| ① | **攻** | `atkPct = 勇武×0.05%/点 + 装备攻值÷10÷100`（`GAME.atkPctOf`） | `perAtk = 兵种攻 ×(1 + atkPct×cover)` | 全部兵种 |
| ② | **防** | `defPct = 智谋×0.05%/点 + 装备防值÷10÷100`（`GAME.defPctOf`） | `perDef = 兵种防 ×(1 + defPct×cover)` | 全部兵种 |
| ③ | **生命** | `hpMult = 1 + 0.8×体力/(体力+800)`（双曲 · 渐近 +80%） | `perHp = 兵种血 ×(1+科技) ×hpMult` | 全部兵种 |
| ④ | **速度** | `spd ×(1 + 速度属性÷300)` | `unitsOf` 的 `spd`（行动顺序 / 先手） | 全部兵种 |
| ⑤ | **统率** | `cover = min(1, 统率×100 ÷ 兵力)` | 决定 ①② 打几折（**守城战强制 1**） | 全军 |

关键链路（代码实锤）：

```
GAME.genAttrs(g)                 ← 基础 + 装备/套装 + 丹药 + buff
  ├─ a.atkPct = atkPctOf(yw, atk)      domain.js:5388
  ├─ a.defPct = defPctOf(zm, def)      domain.js:5389
  └─ a.spd                                （含等级成长：每 5 级 +1）
T.unitsOf(army, side, gen, ctx)   ← 注入 cover / atkPct / defPct / spd
  └─ T.perAtk / T.perDef / T.perHp(u, gen)   ← 结算与悬停同一把尺
```

**守城战特例**（v89.115）：`ctx.playerDef` 且本方为守方 → `cover = 1`（守将加成
"城内所有军队"人人有份，不打统率折扣）；NPC 守城不在此列（不给攻城平衡添变量）。

**出征硬闸**：不带将无法出征（`prepare`：`请选择出征将领`；唯一例外 = 野地已有
驻将时的 station 增援，只并兵不换将，v89.137）。

## 六、诚实缺口（如实列）

1. **属性通道（勇武/智谋）的百分比看似小**（0.05%/点，天授 124 点才 +6.2%）——
   这是 v89.96 的标定（避免"裸将数值"碾压兵种纸面数值）；将领的**大头在体力
   （×1.59）与装备**（装备攻/防值走同一条链，每 10 值 +1%，满配可达 +几十%）。
   若老板觉得"名将该更强"，改 `YW_PCT/ZM_PCT` 两处常量即可（probe 里有现成的对照表）。
2. **速度通道在镜像对局里影响微弱**（±1%）：它的真实价值在"行动顺序 / 更快接敌 /
   风筝撤退"（v89.180 已另证）；本轮没有为它构造专门场景。
3. ⑤ 的 cover 对"守城 vs 野战"的语义差（v89.115 决策）本轮只复核未动。
4. 城主六维（内政/智谋→生产/税收/城防）与守将（勇武→征兵）属**非军队战通道**，
   本轮只确权"不走战斗伤害链"，未逐项复测。

# 图标适配流程

> 用途：**换风格、换素材库、批量新增图标**时照此执行。
> 目标：任何一次风格转换都能在**不改动业务逻辑**的前提下完成，且验收有硬判据。

---

## 一、总览：六步

```
① 选库        用「领域元素覆盖度」量化，不凭感觉
② 建映射表    业务 id → [素材 key, 色调]，只登记数据
③ 生成素材层  脚本产出 js/gicons.js（含缩放换算 / 色调 / defs）
④ 接入        延迟绑定包装层 + 自动回退，不动原手绘实现
⑤ 验证        几何体检优先（越界必须 0），像素统计仅作辅助
⑥ 署名        CC BY 系必须产出 CREDITS 文件
```

**核心设计原则（决定"换风格快不快"）**：
- **素材与业务解耦**：业务代码只认 `ICON.forXxx(id)`，永远不知道底下是哪个库
- **换风格 = 换生成脚本的映射表 + 色调表**，不改 `ui.js` / `domain.js` 一行
- **不删旧实现**：手绘版本留作兜底，未命中自动回退 → 零风险、审计无死函数

---

## 二、Step 1 · 选库：量化领域元素覆盖度

```bash
npm.cmd install --registry=https://registry.npmmirror.com @iconify-json/<库名>
```

定义 30~50 个**本领域专属元素**逐个探测命中（脚本参考 `.workbuddy/tools/show/scan6.js`）：

| 库 | 命中 | 结论 |
|---|---|---|
| game-icons | 30/30 | 唯一专为游戏绘制 |
| fluent-emoji / noto | 21/30 | 缺领域专属件 |
| emojione | 15/30 | 最老 |
| MingCute | 部分 | 国风融合但覆盖不足（农田/沼泽/平原/腰带 无） |
| IconPark | 部分 | 有 `general`/`medicine`/`necklace` 等独特项 |

**判据**：看**领域专属元素**能否命中。通用库在这类元素上必然塌方。
**同时看画风**：覆盖度够 ≠ 气质对（GI 覆盖满分，但西方奇幻风对不上三国）。

---

## 三、Step 2 · 建映射表

在生成脚本里维护 `MAP`：`分组 → id → [素材 key, 色调]`。
登记到 `docs/图标素材注册表.md` 第三节（**唯一台账**）。

要点：
- **一元素一行**，不要写逻辑
- 素材 key 用**候选数组**（`['pagoda','indian-palace','castle']`），
  第一个不存在就自动降级到下一个 → 换库时只改数组顺序
- 色调用**语义名**（metal/gold/wood/...），不要写死色值

---

## 四、Step 3 · 生成素材层

生成脚本职责（参考 `.workbuddy/tools/gen/gen_gicons.js`）：

1. 读库的 `icons.json`
2. **校验**：映射表里每个 key 必须存在，缺失即 `exit(1)`（不要静默放过）
3. 抽出用到的 path，写入 `js/<lib>.js`：
   - `D` 素材表（key → path）
   - `MAP` 映射表
   - `TONE` / 材料色阶
   - `defsHTML()`（渐变 + 滤镜）
   - `paint()`（**含画布换算**）← 见 Step 3.5
4. 同时产出署名文件
5. 文件头注明「自动生成，勿手改」

### 3.5 画布换算（**漏了必崩**）
```js
var LIB_VB = 512, SCALE = 64 / LIB_VB;      // 64 是 wrap() 的 viewBox
'<g filter="url(#emb)"><g transform="scale(' + SCALE + ')">' + path + '</g></g>'
```
| 库 | 画布 | scale |
|---|---|---|
| game-icons | 512 | 0.125 |
| MingCute | 24 | 2.667 |
| IconPark | 48 | 1.333 |

漏了这一步的表现是「**图标全没了**」（图形被裁到只剩一角），不是"尺寸略偏"。

## 五、Step 4 · 接入：延迟绑定包装层

在 `icons.js` 的 `ALL` 快照**之后**包一层：
```js
var hand = ALL[key];                       // 原实现留作兜底
ALL[key] = function (k, arg2) {
  var art = giDraw(group, id);             // 运行时查表
  return art || hand(k, arg2);             // 未命中 → 自动回退
};
function giDraw(g, id) {
  if (typeof GICONS === 'undefined' || !GICONS) return '';   // 必须 typeof 延迟检查
  ...
}
```

**三个必须**：
1. **延迟绑定**：素材层在 `icons.js` **之后**加载 → 包装时全局变量还不存在，
   必须 `typeof` 检查，不能直接引用
2. **自动回退**：未命中回退手绘 → 零风险，且不产生"死函数"审计告警
3. **三处加载列表同步**：`index.html`、`smoke-test.js`（`require`）；
   `e2e-test.js` 走真实 index.html，自动跟随

## 六、Step 5 · 验证：可靠性分级（**最重要的一节**）

| 级别 | 方法 | 能否证伪 | 说明 |
|---|---|---|---|
| **① 首选** | `getBoundingClientRect()` 几何比对 | ✅ | 渲染后视口坐标，比对「路径矩形 ⊂ 自身 svg 矩形」 |
| ② 辅助 | 像素统计（颜色数/彩色占比） | ⚠ | 必须**只采本体区域、排除承台背景** |
| ③ 不可用 | `getBBox()` | ❌ | 不含自身 transform，验不出缩放 |
| ③ 不可用 | `svg.getBBox()` | ❌ | 被整格装饰 rect 撑满，永远"正常" |

几何体检脚本（批量）：
```js
var svgR = svg.getBoundingClientRect();
svg.querySelectorAll('g[transform] path').forEach(function (p) {
  var pr = p.getBoundingClientRect();
  var over = Math.max(svgR.x - pr.x, svgR.y - pr.y,
    (pr.x + pr.width) - (svgR.x + svgR.width), (pr.y + pr.height) - (svgR.y + svgR.height));
  if (over > 3) bad++;
});
```
**验收判据：全部图标逐个跑，越界数必须为 0。**

另两项必查：
- **完整性**：逐个 id 取图，统计"非空数量"，缺失必须为 0
- **差异化**：同系不同档（如材料 4 品阶）的 SVG 字符串去重后仍为 4

### 假绿陷阱（v32 真实事故）
v32 用"整格颜色数 4173 / 彩色 27.1%"判为通过 —— 但那是**承台暖土圆盘 + 光晕**
贡献的颜色，**图标本体一片空白也照样"五彩斑斓"**。假绿让 bug 交付到用户手上。

其他陷阱：
- **不能**把 SVG 转 data URI 画到 canvas 验证（独立文档后外部引用的渐变会丢失）
- **"数量少" ≠ "没渲染"**：v33 页面只有 2 个图标，实为新开局只建了官府 + 1 建筑；
  要查容器的 built/empty 分布，不要用图标数量推断故障

## 七、Step 6 · 署名

CC BY 系（game-icons 等）**必须署名** → 生成 `docs/<库名>-CREDITS.md`
（许可、作者、站点、完整使用清单表）。**让生成脚本一并产出**，不要等交付前补。

## 八、换风格时的快速适配路径

**目标：一次换风格 ≤ 30 分钟，且不碰业务代码。**

| 场景 | 要改的地方 | 不用碰的地方 |
|---|---|---|
| **只调色**（同一套素材） | `TONE` 色值表 | 映射表、业务代码 |
| **换素材库**（形状变、语义不变） | 映射表的 key 列 + `LIB_VB/SCALE` + 署名文件 | 业务代码、色调表 |
| **换画风**（上色方式变） | `paint()` + `defsHTML()` 的滤镜 | 映射表、业务代码 |
| **加新元素** | 注册表第三节 + 映射表一行 | 业务代码 |
| **整体换库**（含新语义） | Step 1~6 全套 | 业务代码（只要 id 不变） |

**换库的标准动作**（已跑通两遍，30 分钟内可完成）：
1. 拉库 → 跑 `show/scan6.js` 类脚本探覆盖度
2. 改生成脚本的：`LIB_VB`、`MAP`（key 列）、色调表（若色系也要换）
3. 重跑生成 → `node --check js/<lib>.js`
4. 跑几何体检（越界 0）+ 完整性（缺失 0）
5. 跑三件套
6. 更新注册表第一节 + 重出总览图

## 九、踩坑清单

1. **画布尺寸不换算** → 图形被裁到剩一角（"图标全没了"）
2. **用颜色统计验证渲染** → 被承台/背景骗，给假绿
3. **用 `getBBox()` 验缩放** → 不含自身 transform，永远看着"没生效"
4. **`node -e "长字符串"` 打补丁** → shell 吃掉引号/`$`/反引号，静默失败；写成 `.js`/`.py` 文件再跑
5. **bash 缺 PATH** → PortableGit 的 `usr/bin` 不在 PATH，grep/sed/awk 全找不到，
   每条命令前 `export PATH="/c/Users/18811/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:$PATH"`
6. **脚本不幂等** → 重跑两遍把函数定义两遍；替换前判"已应用"并跳过
7. **素材层加载顺序放错** → 放在 `icons.js` 之前会导致包装时就引用未定义变量
8. **忘记同步测试加载列表** → smoke 的 `require` 列表要手动加
9. **忘记署名** → CC BY 系许可违规

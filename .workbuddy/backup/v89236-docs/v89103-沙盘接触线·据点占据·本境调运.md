# v89.103 · 沙盘接触线 · 据点占据 · 本境调运

> 老板三条令（2026-09-23）：
> ① **沙盘**：两半的兵没有接触——两方应该在同一片战场上战斗；最前方的兵种前方有一条线，
> 　　代表该兵种/该方的最前线，也就是**接触线**；劣势方兵种被歼 → 接触线向其出发线推进，
> 　　推到出发线 = 被攻入大军腹地，战斗结束。
> ② **拔除据点可以占据该据点**（成为自己的城池）。
> ③ **任意自身城池向其他城池运输资源，应当采用出征界面**（将领 / 兵种 / 资源数量三确认）；
> 　　出征界面加入资源调配（资源及数量框）。**目前主城向分城点运输会提示"城池不存在"** —— 完善后测试。

## 1. 沙盘：从"两半各走半场"到"同一片战场 + 接触线推进"

### 1.1 病根（一句话）

改前两个方向各自映射到半个战场：**我军 4%→46%、敌军 96%→54%**，
中间 `46%~54%` 是**永久空档** —— 无论打多久，"两半的兵"都不可能碰上。
（实测最小屏上间距恒为 **8%**，见探针 ⑥。）

### 1.2 改法

| 项 | 改前 | 改后 |
|---|---|---|
| 横向位置 | 各自半场（4→46 / 96→54） | **共享距离轴**：0 = 我军出发线、D = 敌军出发线，一律映射 4%~96%（`ui.btPosPct` 唯一出口，实时战场与沙盘共用） |
| 泳道 | 每队一条，两军同号同排 → 交战时牌叠牌 | **交错**：我方偶数道、敌方奇数道（`ui.sdLaneOf`）→ 接触时"我方第 i 队 vs 敌方第 i 队"上下相邻 |
| 前线 | 无 | **三条线**：`我军前线` / `敌军前线`（虚线，各画在本军最前部队**前方**）；已交手 → 合成一条**接触线**（实线） |
| 收尾 | 无 | 一方被全歼 → 接触线**钉在其出发线**，标「被攻入腹地」，顶部战况同步 |

几何口径**只有一个来源**：`GAME.tactic.frontsOf(atkUnits, defUnits, D, hot)`（`js/tactic.js`）

```
我方前线 = 我方最前**存活**部队的 adv      （frontAdvOf；全灭返回 null）
敌方前线 = D − 敌方最前存活部队的 adv
间距     = D − 两方最前之和                （与引擎每回合记的 gap 同一公式）
接触     = 已交过手（hot：出过攻击/反击/城头火力帧）或间距 ≤ 0
接触线   = 两条前线的中点（全灭时钉在被歼方出发线）
```

界面只负责画：`ui.sdLineHTML`（首绘）与 `ui.sdPaint`（逐帧只改 `left` 与 `hide`，不重建 DOM）。

## 2. 拔除据点 = 据为己有（成为自己的城池）

### 2.1 语义

改前：占领打下一座野外城池 = **拔除**（当日移除、次日重置、谁也不得）——
于是 v89.94 那套"磨守备值"的围攻机制对据点毫无回报：磨下来一场空。

现在：**拔除 = 据而有之**（`GAME.claimFort`）：

| 项 | 口径 |
|---|---|
| 建筑 | **就地转正** —— 与侦查面板看到的"满配布局"逐格一致（同一出口 `npcCityShadow` / `cityPlanOf`） |
| 人口 | 城里的人跟着留下 = 该布局民房满员（与侦查面板同一个数字） |
| 库藏 | 不继承（据点本就没有库藏 —— 掠夺所得是"打下来才有"的），发一份新城启动物资 |
| 城档 | `type='self'`：无岁贡，靠城外地块与税收（与"打下来的一座野城"相称） |
| 永久 | `GAME.map.markFortTaken` → `fortAt` 直接返回 null：渲染 / 出征目标 / 自动出征 / 侦查**全看不到**（一个出口，处处生效） |
| 文案 | 据点按钮改「🚩 拔除并占据」；占领方式 desc、出征面板注、战报战果行同步改写 |

## 3. 资源运输整合进出征界面（含"城池不存在"老 bug）

### 3.1 老板要的三确认 = 出征界面的一块新区域

「本境调运」= 选好己方城池目标后，在**出征界面**里：

```
左列：目标（己方城池）· 主将 · 方式锁定「🚚 调兵 · 辎重」· 方案 · 预估（改为"随军载重"）
右列：辎重 · 资源调配（粮/木/石/铁/金 五行：拥有 / 数量框 / 全 / **实收**）
      + 派遣兵力 · 兵种数量（既有表）
底栏：🚚 起运（兵 + 辎重）
```

* **运力**（唯一口径 `GAME.cargoCapOf`）= Σ(兵数 × 兵种载重)。`DATA.TROOPS[].load` 从此真的在用
  （民夫 200 / 辎重车 5000 / 义兵 20）——**想运得多就得多带挑夫**，这是"兵种"在运输里的角色。
* **实收**（每行右侧）实时读 `GAME.transportPlanOf` ——与抵达落账**同一个函数**，界面不许另算。

### 3.2 一条运输的完整生命周期（任何一步都不许让货凭空消失）

| 阶段 | 行为 | 出口 |
|---|---|---|
| 出发 | 校验（库存 / 运力 / 校场容量 / 带队将领在本城）→ **扣兵 + 扣货** → 进行军队列 | `GAME.doTransferCargo` → `march.dispatch(extra.cargo)` |
| 在途 | 货在队列上（`m.cargo`），**不能再花第二次** | — |
| 抵达 | 兵入城 + 辎重落账（距离损耗 + 目的地仓容；装不下的**原路退回**出发城） | `expedition` 的 owncity 分支 → `GAME.transportCargo` |
| 失败/召回 | 兵与货**原路退回**（结算异常、超容折返、手动召回三条路都退） | `march.arrive` / `march.recall` |

唯一出口组（`js/domain.js`）：`cargoCapOf` · `cargoLoadOf` · `transportPlanOf`（纯函数）·
`transportApply`（落账）· `transportCargo`（一批货的抵达账单）。
界面预估、出发校验、抵达落账 —— **三处读同一对函数**。

### 3.3 老 bug：为什么"主城向分城点运输"必报「城池不存在」

根因不是距离、不是城池数据，而是**面板显示的和提交的不是同一个值**：

* 旧面板 `ui.openTransport` 里，目的地默认值只写进了**局部变量** `to`（用于渲染）；
* 而提交出口 `ui.doTransport` 读的是 `ui._trTo[from.id]` —— 从"资源运输"按钮进来时**它从没被写过**；
* 于是提交带着空 id → `GAME.doTransport(from.id, '', ...)` → `if (!from || !to) return '城池不存在'`。

改法不是打补丁，而是**整条路退场**：运输现在只有出征界面一个入口（`city-transport` 按钮与
`ic-res` 都指向 `ui.openExpModal({kind:'own'})`），旧面板 / 旧动作 / 旧 `GAME.doTransport` 一并删除，
连"城池间操作"小面板也退役（它的三件事各有更正入口）。**没有面板了，也就没有"显示 A、提交 B"的落脚点。**

## 5. 诚实缺口（下迭代）

1. **接触判定用"已出手"（hot）而不是逐兵种射程**：两军远程对射（都带射程科技）时，
   线画在两条前线中点上（真实），但不会预告"再近 X 就开打"。若老板要看"射程圈"，得把
   `frontsOf` 的 reach 从基础射程升级为"含科技的 effRange"（引擎内已有，只是没往外给）。
2. **实时战场（bt-field）只改了轴与错行**：没有像沙盘那样画三条前线。它现在是"一眼看谁在哪"，
   若要同样的战线感，把 `sdLineHTML` 那套搬过去即可（几何函数已共用）。
3. **调运的"载重"没有科技加成**：`负重技巧`（tech `load`）目前只作用在掠夺/采集收获上；
   若让"多运"也吃它，需在同一条链上加（一行），但那会改经济节奏 —— 等老板拍板。
4. **辎重区只在"本境调运"出现**：出征打别人（据点/名城）时不能带辎重随军。
   若要做"前线补给车"（打下来就地补），需在 expedition 里加一条"随军辎重可用于战后补给"的分支。
5. **据点占据后没有"弃城"提示**：占下来即我方城池（含人口），若玩家不想要，得用既有的
   「放弃城池」（`GAME.abandonCity`）——界面没有在占据成功时就地给这个提示。

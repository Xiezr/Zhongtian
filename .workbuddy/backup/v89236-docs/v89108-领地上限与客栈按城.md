# v89.108 · 领地上限（随爵位解封）+ 客栈候选按城

> 老板两条：「① 限制城池数量，参考爵位和主城等级设置，可建造控制的城池数量随爵位解封；
> ② 分城的客栈只有 Lv2，但是有 14 个候选将领，应该跟随建筑等级提供候选数量」

---

## 一、领地上限：口径 = 「下一档爵位的城池要求」

| 爵位 | 领地上限 | 爵位 | 领地上限 |
|---|---|---|---|
| 平民 | 2 座 | 左庶长 | 12 座 |
| 公士 | 3 座 | 右庶长 | 13 座 |
| 上造 | 4 座 | … | … |
| 簪袅 | 5 座 | 位列诸侯 | 22 座 |
| 不更 | 6 座 | 裂土封王 | **22 座（封顶）** |

### 为什么不直接用"本档的城池列"

爵位表里本就有一列 `city`（平民 1 → 裂土封王 22），但它一直是**晋升门槛**：

```js
if (s.cities.length < next.city) return { ok:false, msg:'需要 N 座城池' };   // 晋升条件
```

若上限取**本档值**（平民 = 1 座），而晋「公士」需要 2 座 —— **永远凑不齐 → 死锁**。
所以上限取**下一档的依据**：`cap(i) = RANK[i+1].city`（满档 = 本档值 22）。

> 语义：**爵位允许你把地盘扩到"够格觐爵"的规模**。打满上限的那一刻，恰好就是该求晋爵的时候 ——
> 门槛与上限天然同值，不另立第二张表（同 v89.102「主城随爵位解锁建筑等级」的写法：也读 `DATA.RANK`，也是"每档 +1"）。

### 三条得城路径全过闸

| 路径 | 位置 | 闸门 |
|---|---|---|
| 自建城 | `GAME.canBuildCityAt`（domain.js） | 地理 → **领地上限** → 资源（逐层归因） |
| 占系统城 | `GAME.battle.prepare`（battle.js） | 发起与抵达都拦；`onConquer` 兜底 |
| 据点转正 | 同上 | 同上；`claimFort` 兜底 |

- **唯一出口**：`GAME.cityCapOf()` / `GAME.cityCapChk()`（state.js）。界面（出征方式锁、建城入口、
  两个弹窗的按钮）与硬执行读**同一判据** —— 不会出现"按钮能点但打了被拒"。
- **抵达也拦**的原因：出发后别处先占了城 —— 兵原路折返（军账守恒护栏在 `march.arrive`），
  不会"白占一座超编城"。
- 野地占领**不受影响**（占野地不产城）。

### 老档保护：只拦新增、不削已有

上限上线前打下的城（试玩里见过 28 座）**一律保留**；只是不能再扩张，提示
「领地已超编（28/22 座）—— 既往城池保留，新的扩张须待爵位提升」。

## 二、客栈候选：病根是"全局一份池"

老板看到「分城客栈 Lv2 却有 14 个候选」的成因有**两条**，都在代码里：

1. `s.inn.candidates` 是**全局一份**候选池（不分城）—— 主城刷出 14 位贤士（Lv12 + 专精 2），
   切到分城照样显示，且 5 分钟内不换批；
2. `GAME.innSlots()` 里 `innLevel()` **漏传 city** —— 拿的是当前城的客栈等级，不是目标城的。

### 修法

- 池改**按城独立**：`s.inn.byCity[cityId] = { candidates, at }`，由唯一出口 `GAME.innPoolOf(city)` 收发；
- `innSlots/innRefresh/innRefreshLeft/innRefreshCost/innRecruit/innAutoRun` 全部改为**按目标城**；
- **老档迁移**：旧的全局池归给主城（无主城 → 首城），一次性、不丢人。
- 候选数量 = **该城客栈等级 + 满级专精**（Lv6 → 6 位；Lv2 → 2 位）。

## 三、实测

### 门禁（`gate.py --full`）

| 闸门 | 结果 |
|---|---|
| audit（死函数/孤儿/重复/零引用） | 0/0/0/0 |
| smoke-test | **2648 通过 / 0 失败**（含新增 §89 六条） |
| e2e-test（真实 DOM） | **1043 通过 / 0 失败** |

新增 §89 断言（6 条）：

1. 逐档核验「上限 = 下一档门槛」（22 档全程 ≥ 门槛 → 不死锁），封顶 22；
2. 达上限后建城被拦（真出口 · 提示「领地上限」）→ **晋爵放行**；
3. 达上限后出征「占领城池」被 `prepare` 拦；**野地占领不受影响**；晋爵放行；
4. 老档超编 → 既往城池保留、禁止再扩张；
5. 客栈候选数随该城客栈等级（**6 / 2 位**）且**两池互不串** + 老档迁移不丢人；
6. 界面同源 —— 方式锁/建城/prepare 读同一判据（源码 + 行为双验）。

## 四、给老板的决定点

1. 上限曲线用的是爵位表**既有**的城池列（平民 2 → 封顶 22）。若您想换坡度
   （例如"每两档 +1"或满档再放宽到 30），只改 `GAME.cityCapOf()` 一处即可。
2. "参考爵位和**主城等级**"：本版口径是**爵位主导**（主城等级体系是 v89.102 的既有参照写法）。
   若您希望主城（官府）等级也参与（如官府 Lv≥20 再 +1 座），说一声，加一处因子即可。
3. 客栈候选池已按城独立；**自动招募**仍只作用于当前城（现状如此）——若要"逐城自动招募"，另开一轮。

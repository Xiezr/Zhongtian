## ① 侦查报告单页化

**病根（一句话）**：侦查面板自 v65 起是**两页签**（⚔ 敌情与缴获 / 🔭 虚实与可图之利）——
v65 当时的理由是"满级六层 950 屏溢出 89px"，用分页绕过；老板现在要"一页看全"。

**改法**：

| 面 | 改前 | 改后 |
|---|---|---|
| 结构 | 两页签（SCOUT_PAGES / scout-page 翻页） | **单页四板块**：敌情 / 城中虚实 / 可图之利 / 顺手所得 |

| 退役四件 | — | `SCOUT_PAGES` / `scout-page` case / `ui._scoutPage` / `ui._scoutLast` 全清（墓碑注释留档） |

**信息零缺失核对**（逐字段）：守军总数(gNum/totalExact) · 兵种编制(roster+合计) · 守将(guard) ·
资源(resReport) · 规格/城防/城外/城内(buildReport) · 珠宝/可采/产量加成/材料/军械(spoils) ·

## ② 铁匠铺多选一次打造

**病根**：打造是"单选一件 + 底部一个键"（v89.117），打一整套要一件件点。

**改法**：
- 选中从单值 `_forgeSel` 升级为**保序数组 `_forgeSelList`**（旧单值整条退役）；
- 点选 = toggle（点一件加入、再点取消）；卡片选中态沿用金框 + "✔ 已选"；
- 底键：`⚒ 打造`（0 件受阻）/ `⚒ 打造：件名`（1 件）/ **`⚒ 打造 N 件`（多件）**；
- 新增 `✕ 清空选择` 与 **`⚑ 全选`**（toggle；作用域 = 当前筛选池 —— 打整套的场景）；
- `GAME.doForge` 无参取选集**逐件结算**：能造的扣料造出、缺料的留下并汇报
  （选集中的失败件保留 —— 补料后可直接再按）；成功的自动移出选集。

**实测**：真点两张卡 → 底键「⚒ 打造 2 件」→ 真点 → **两件一起入包（15→17）· 选集清空**。

## ③ 百炼强化专属界面 + 滚动回顶修复

**改法（界面）**：单列小窗（lg）→ **专属界面**（xxl）：

| 面 | 改前 | 改后 |
|---|---|---|
| 布局 | 单列列表（每行一颗"强化 +N"键） | **3 列网格卡片**（品阶图 68px + 名称·序号 + 品质 + 大号 `+N/上限` + 下级成本） |
| 操作 | 每行一个按钮 | **点选 + 底部唯一强化键**（与打造面板同款形态，老板点名"参考打造界面"） |
| 筛选 | 无 | 全部 / 未满 / 满级（chips 带计数） |
| 分页 | 无（长列表滚动） | 15/页（`ui.modalPage`） |
| 实时 | 静态 | `live` 每秒刷新（黄金随税收即时变） |

**滚动回顶修复（真因 + 修法）**：

- **真因**：弹窗的**真滚动容器是 `.m-body`**（结构 = `.inner-panel.inner-shell`（`overflow:hidden` 弹性列）
  → `.m-head` / `.m-body` / foot；滚动发生在 `.m-body`）——而 live 快照/回填
  （`_liveSnap/_liveRestore`）的容器清单是 `'.inner-panel, .panel-body, .modal-scroll'`，
  **漏了 `.m-body`** → 任何"操作后重开 / live 重绘"的面板滚动位都保不住（"点一次回顶部"的真身）。
- **修法**：① 容器清单补 `.m-body`（**机制级** —— 所有 live 面板一起受益）；
  ② 新增通用出口 `ui.reopenKeepScroll(fn)`（复用快照两出口），接线三处：
  `doEnhance` / `enhPick` / `doForge`。
- **实证**：33 件装备 → 面板滚到 scrollTop=300 → 点选触发重开 → **仍 300**（修前必为 0）；
  实机 40+ 件场景（可滚 1524/672）同样 300→300。

## 诚实缺口

1. **侦查面板档位**：xxl+tall 在极低分辨率（app-h < 500）下高度随 `calc(var(--app-h) - 40px)` 缩，
   极端时多出的内容由 `.m-body` 滚动兜底（低于设计下限的窗口不再保证零滚动）。
2. **打造"全选"的作用域** = 当前筛选池（含本页之外的同池件）；跨筛选的多选靠逐件点选。
3. **蕴养面板（修炼装备）未同步改版**：老板本轮点名的是百炼（军装），蕴养仍是原单列形态
   （如需同款专属界面，下轮可照抄本套组件）。
4. **历史老档里 `_forgeSel` 无残留**（它是内存态非存档字段），无需迁移。

## 由需求引出的真 bug（本轮抓到）

- `ui._liveSnap / _liveRestore` 滚动容器清单漏 `.m-body`（真滚动容器）——属于**机制级**缺陷：
  影响所有"操作后重开 / live 重绘"的弹窗（百炼强化只是最显眼的一个）。已修 + 补断言。

# v89.111 · 来袭改「每日 9 时一场」（轮转目标 · 提前 4 时只报一次）

> 老板两条：
> ① 「自动攻城固定每日9点即可，提前4h提醒一次，无需频繁报告来袭预警。」
> ② 「其他势力攻打，烽火警讯显示其军队来袭剩余时间。」

---

## 一、病根（改前是什么样）

旧口径是"**每城各排各的**"：每座城一个 `city.inv.nextAt`，间隔 = `max(2, 4 - (城数-1)×0.12)` 天；
预警窗 = `12 时 + 烽火台等级×12 时`（最长 48 时）的**滚动窗**，进窗各城各自报一条。

后果（老板的体感就是这两条）：
- **来犯时刻随机**（哪座城、哪一天、几点，全不可预判）；
- **预警频繁**：28 城时每天约 14 场来袭 × 各自的预警 —— 消息流被烽火刷屏（v89.107 试玩里
  烽火事件曾占 10.4%）；预警还是"约 N 游戏时后"这种**相对且粗糙**的报法。

## 二、改法（v89.111）

| | 改前 | 改后 |
|---|---|---|
| 节奏 | 每城各自 2~4 天随机 | **每天固定一场**（全场唯一来犯时刻） |
| 时刻 | 随机（游戏时刻不定） | **每天 9:00**（游戏时，`DATA.INVASION.attackHour`） |
| 目标城 | 各城按自己的排期 | **按日轮转**：`cities[日序 % 城数]`（确定、可预判、人人有份） |
| 预警 | 12~48 时滚动窗，各城各自报 | **提前 4 时只报一条**（`warnHours`）—— 5:00 报、当天不补报 |
| 警讯内容 | 「约 N 游戏时后将有兵马犯境」 | 「『郡国游兵』将于今日 9 时犯『许都』（**剩余 3时30分**）」（老板第 2 条） |
| 烽火台 | 每级 +12 时"提前预警" | **情报等级**：Lv1 +敌军战力 / Lv2 +兵种明细（不再改提前量） |
| 排期状态 | 每城 `city.inv` | 全局 `s.inv = { lastDay, warnedDay }`（入存档） |
| 退役 | — | `baseDays/minDays/tightenPerCity/beaconBonusHours/warnBeaconMax/invasionIntervalSec/city.inv` 全删 |

**保留不动的红线**：`unlockCities=2`（别一开局就挨打）、`ratioMin/Max`（来袭规模按全境战力缩放）、
`loseCity=false`（输了不丢城）、`loss`（战损比例）、`invasionResolve`（真打一场 + 防御战报）。

**唯一出口（新增）**：`invasionDayOf` / `invasionDueOfDay` / `invasionTargetOfDay` / `invasionSrcOf`
（势力——**预警报谁就是谁来打**）/ `invasionIntelLvOf` / `invasionIntelTextOf`。
界面（烽火页 + 烽火台闪烁）与消息、断言全部读它们。

## 五、诚实缺口（需要老板定夺/知晓）

1. **压力曲线变了**：改前"城越多挨打越频繁"；改后"每天一场、按日轮转"——大帝国每座城被袭的
   频率反而降低（28 城 ≈ 每城 28 天一次），小帝国（2 城）约两天一次。压力靠"来袭规模随全境战力
   缩放（0.28~0.45）"维持。若要"城越多、每天场次越多"，加一句"每天场次 = min(城数/10, 3)"即可。
2. **首次宽限**：新解锁/新档的首个 tick 只排期不结算（不会"上来就挨打"）；之后每天 9:00 一场。
3. **离线补算上限 30 天**（guard）；超过部分跳过（不追溯报账）。
4. 烽火台情报 3 档的实现：Lv1 = +战力，Lv2+ = +兵种明细（前 3 类，超出以"等"收尾）。
5. 旧的 `warnHours: 12`（提前 12 时）退役为 `4` —— 如果您希望"提前 4 时"之外再给一条
   "今晚备防"的夜间提示，说一声即可加（不影响主预警的单次原则）。

# v89.160 逾溢折损（鼠灾/火灾/风化/腐蚀）· 自动升级顺延（老板 2 条）

> 老板原文（逐字）：
> 1.资源超过容量上限，设计每隔一段时间，扣减超出部分的百分之25%，系统提示鼠灾，火灾，风化，腐蚀，损失XX资源XXX
> 2.自动升级取消城内优先，某建筑资源不足时，顺延升级下一个建筑，直至所有可升级建筑均无法升级，或所有建筑均达到当前等级上限

## 一、① 逾溢折损（超出仓容的部分会被"天灾"吃掉）

**口径（唯一出口群 · 调平衡只动 `DATA.OVERFLOW` 一张表）**

| 项 | 值 | 说明 |
|---|---|---|
| `keys` | 粮 / 木 / 石 / 铁 | **只吃有上限的资源** —— 黄金是货币、不受仓容约束，天然豁免 |
| `ratio` | **25%** | 老板定的数：扣"**超出上限部分**"的 25%（不是总库存的 25%） |
| `periodGameHours` | **24**（1 游戏日） | 周期走**游戏时间** —— 产出按游戏时间走，折损必须同刻度；否则高倍速下等于没有折损 |
| `maxPeriods` | 20 | 离线很久也最多折算 20 期（防"一夜清零"式暴击） |
| `events` | 🐭 鼠灾 / 🔥 火灾 / 💨 风化 / 🦠 腐蚀 | 老板点名的四种，每次随机取一 |

**四件套（唯一出口，界面与结算同源）**
- `GAME.overflowRotOf(city)` → 本城超出清单 `[{ k, excess }]`（纯读，供界面/断言）
- `GAME.overflowLossOf(ex, n)` → n 期折损额 = `ex × (1 − (1−ratio)^n)`，取整；**超出 ≥1 至少损 1**
- `GAME.overflowEventOf()` → 随机灾种
- `GAME.settleOverflowRot()` → 结算（锚点 `s.overflowAt` = 游戏秒，**与月俸 `salaryAt` 同一手法**）

**边界（都写进断言）**：超出 ≥1 至少损 1（否则小额溢出"折"不动 = 机制摆设）·
未超上限完全静默（不掉链不刷屏）· 不足一期不结算 · 首次只登记锚点（老档首期从当前时刻起算）·
一次结算**只发一条**公文（灾种 + 逐项损失 + 城数）。

**挂钩**：`tickOnce`（历法推进之后 → 锚点读到刚推进的 `world.elapsed`）+ `simulateBulk`（离线补算末尾）
—— 两处**同一个函数**，在线/离线不各写一份。

**界面出口（机制可见）**：① 侧栏资源悬停 —— 已超上限时写明「⚠️ 已超上限：超出部分每游戏日折损 25%
（鼠灾 / 火灾 / 风化 / 腐蚀）」；② 仓库面板 —— 常驻一行「⚠️ 逾溢折损：…每 1 游戏日折损 25% …
当前超出上限：X」。

**实测（实机・真跑 1 游戏日）**：
```
🔥 火灾：仓廪逾溢，损失 粮食 8.0万、铁锭 2.2万（1 城 · 超出上限部分每游戏日折损 25%）
```
（消息按 v89.157 的主题体系落在**内政**主题 = 青色竖条 + 徽章，与其它播报同一套呈现。）

## 二、② 自动升级：取消城内优先 + 顺延试下一项

| 面 | 改前 | 改后 |
|---|---|---|
| 排序 | `KIND_ORD = { city: 0, ext: 2 }`（同级**城内优先**） | **该分档整条退役** —— 只按等级从低到高；同级按候选收集序（`c.ord`，遍历序） |
| 试建循环 | 第一项"资源不足"就 `return`（**暂停**）→ 后面升得起的项永远轮不到 | **顺延**：不足项记下继续试；全部试遍仍无一可动 → 才置暂停态（文案写明「N 项试遍」） |
| 状态行 | 「资源不足，暂停中（待升级 X）」 | 「资源不足，暂停中（N 项试遍 · 待升级 X）」；非资源类失败则显示「暂无可升级项（原因）」 |
| 文案 | 「按等级从低到高、同级城内优先」 | 「按等级从低到高（**不再区分城内城外**）…某项资源不足就**顺延试下一项**」 |

**判据（实测）**：池子只够民房（1720）而铁匠铺（6238）排在遍历序前面 →
`autoUpgrade` **顺延过铁匠铺、命中民房**（队列里只有民房那一条，状态是"正在升级"而非"暂停"）；
池子清零 → 全部试遍 → `paused: true`（开关不关）。

> **连带口径（写清，免得误解）**：建造花费走 `s.res` = **当前城**的 getter ——
> 多城自动升级实际是"在同一个池子里挑便宜/低级的项"。本轮的"顺延"正是靠这一点才有意义。

## 四、诚实缺口 / 待老板定夺

1. **折损周期是"1 游戏日"**（= 现实 12 分钟 @120× / 24 分钟 @1×）—— 一处可调
   （`DATA.OVERFLOW.periodGameHours`）。若您希望更频繁（如半天）或更慢（如 3 日），一句话改。
2. **`maxPeriods: 20`** 是"离线很久也只折算 20 期"的上限 —— 目前离线只在不超上限时生产，
   真正会吃到这条的是"带着超额库存离线很久"。要不要取消这个上限，听您的。
3. **折损走游戏时间，入侵走现实时间** —— 这是两套刻度：入侵是"现实感官事件"，折损是经济压力，
   我按"约束什么就用什么刻度"定的；若您要把折损也改成现实时间（如每 30 分钟），
   改 `periodGameHours` → 现实分钟字段即可。
4. **同级排序不再有规则**（只按遍历序：城内格 → 城墙 → 城外格）—— 若您要一条同级规则
   （如"便宜的先"），加一个排序键即可，一条断言跟上。
5. **建造花费仍从"当前城"扣**（既有口径，非本轮引入）：多城时会用当前城的资源去升别城的建筑。
   要不要改成"谁的建筑扣谁的资源"—— 这是个**中等改造**（`canAfford/payCost` 要带城参数，
   连带 4~6 条断言与既有存档行为），等您拍板。

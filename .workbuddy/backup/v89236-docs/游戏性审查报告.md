# 《热血三国·单机版》游戏性与趣味性审查报告

> 审查对象：`E:\Deepseekdb`（纯前端单机三国经营，v89.6 基线）
> 审查方式：逐模块读代码 + 读项目自留文档（设计规范 / 玩法扩展规划 / 经济审计 / 每日日志），
> **不采信文档结论，全部回代码复核**；每条短板附证据出处。
> 本报告只做诊断与开方，不改一行代码。

---

## 〇、结论先行

**一句话诊断：这是一座修得极好的「内容博物馆」，但它的参观动线还是三年前那条。**

近 10 个版本（v87→v89.6）把全部工程量投在**野地/江湖/修炼**支线上，做出来的东西（12 活动 ×
12 幅程序化场景画 × 36 幕剧本 × 三种交互轮转 × 24 条见闻录）**质量是真的高**；
而**主线征服循环**（建造→募兵→出征→占城）自 v86 之后没有新增过机制，
且它最该有的三样东西——**看得见的战斗、够响的反馈、有名字的目标**——至今是空的。

三条主结论：

| # | 结论 | 一句话依据 |
|---|---|---|
| 1 | **最有趣的内容锁在最窄的门后** | 江湖游历全链**君主专属**（`state.js:3227`），且藏在野地弹窗的第三区块；12 活动 / 36 幕 / 24 见闻录只有 1 个角色能用 |
| 2 | **反馈层是空的** | 全仓 **0 音效**；瞬态反馈只有 1 个 toast（2.2 秒 / 单一样式）；全站动效 **4 组 keyframes**；最核心的攻城战**只有文字** |
| 3 | **没有「今天该干什么」** | 无成就/军情/待办汇总；且"每日"存在**三把钟**（历法年 57600s / 现实秒制日 86400s / 现实日），口径互相对不上 |

**三个最高杠杆的动作**（成本都在"小~中"，且全部是**接线**不是造轮子）：
① 里程碑演出层 → ② 战报可视化 + 反馈分层 + 程序化音效 → ③ 今日军情 + 章节骨架。

## 二、短板分析

### 2.1 核心玩法：主线坍缩为单循环，且决策被自动化消解

#### 短板 A1 —— 玩法投资严重失衡（近 10 版全在支线）

| 版本 | 内容 | 落在哪条线 |
|---|---|---|
| v86 | 计谋/锦囊（8 计） | **主线**（最后一条） |
| v87 | 野地六地形专属场景 | 支线 |
| v88 / v88.1 | 灵气双轨装备 + 江湖游历 12 活动 | 支线 |
| v89 / v89.1 / v89.2 | 君主专属 + 全屏剧本 + 视觉化 + 场景化 | 支线 |
| v89.3 / v89.4 / v89.5 / v89.6 | 灵物志 + 野地生态 + 灵机之地 + 奇遇见闻录 | 支线 |

**证据**：`设计规范.md` §27（v86）之后，§28~§36 九章全部是野地/江湖主题；
全仓 grep `DATA.SKILLS / DATA.MONSTERS / STORY_CH / WUXUE / DATA.MANOR / DATA.FACTIONS` **零命中**
——规划中的主线件（§九 卡牌、§十 技能、§八 庄园、§三 势力）一件都没开工。

**玩家感受**：想玩的部分（打天下）三年没变过；变好看的部分（江湖）是"点开野地才看得到"的小菜。

#### 短板 A2 —— 最有趣的内容锁在最窄的门后

**证据**：`state.js:3227`
```js
if (!GAME.canCultivate(gen)) return { ok:false, msg:'江湖游历乃君主亲历之事 —— 只有君主可前往' };
```
江湖游历（12 活动 / 12 幅程序化场景 / 36 幕剧本 / 热点选点 / 应对卡 / 时机条 / 结算演出）
**只允许君主 1 人触发**，且消耗君主精力 + 体力，每格每日一次；
而普通将领（玩家会有 10~20 名）与它完全无关。

**这不是说"主角单修"该推翻**（那是拍板过的设定），而是：
内容体量与**入口地位**严重不匹配——它藏在「点野地 → 弹窗第三个区块」，没有常驻入口、
没有推荐、没有情报预告（v89.5 青旗只标"有事"，不标"是什么事"）。

> 参照：同样的内容如果做成"每次出征前可选一场遭遇戏"，覆盖面会从 1 个角色扩到全局。

#### 短板 A3 —— 决策被"自动化 + 一键正解"消解

| 现象 | 证据 |
|---|---|
| 游戏能自己玩 | 「自动」独立菜单：自动升级 / 自动研究 / 自动出征（`main.js` 有整段实现） |
| 出征一键正解 | 出征面板「全带 / 清空」两键 + **战力估算**（直接告诉你打不打得过，`设计规范 §15.3`） |
| 经营无数可调 | **开工率调整 UI 在 v77 整条退役**（`设计规范 §18.5`：机制与取值保留、界面下线）——若它有用，不会被砍 |
| 金币无约束 | 项目自己的 `economy_audit.js` 实测：**税收占自动收入 90~100%**，后期攒一件 4 级打造（9 万金）仅需 **0.5 游戏时** |

**玩家感受**：中后期真正需要玩家做的决定只剩两个——**打哪座城**、**什么时候点领取**。

#### 短板 A4 —— 经营层无张力（资源不做取舍）

- 建造只受「同时建造数」与「官府等级」两道**门槛**限制，不受资源**取舍**限制（盈余）；
- 所有建筑最终都能满级、所有科技都能研究完 → **没有机会成本**；
- 城间运输虽有损耗模型，但收益侧没接（`玩法扩展规划 §11.8` 自述）。

**结论**：这是"资源**约束**"型游戏，不是"资源**分配**"型游戏——前者只考验耐心，后者才考验判断。

#### 短板 A5 —— 将领之间没有"打法分化"

将领只有：等级 + 资质 + 四维 + 装备 + 内功（5 门，每门只加一条属性）。
两名同资质同将格的将领练满后**完全一样**——没有技能、没有流派、没有取舍。
这正是项目自己判定的 **A 级核心缺失**（`玩法扩展规划 §十二`），我复核后同意。

### 2.2 互动反馈：一条通道、零声音、零演出——反馈层基本是空的

#### 短板 B1 —— 全站零音效

**证据**：全仓 grep `AudioContext / new Audio / .mp3 / .wav / sfx / playSound` → **0 命中**。
建造完成、募兵完成、出征、攻占城池、爵位晋升、奇遇探成——**全部静音**。

**这是性价比最高的一块空白**：Web Audio 程序化合成（oscillator + envelope）零素材、
file:// 可用、与项目"程序化绘制地图/场景"是同一条路线（v67 已把地形改成全程序化绘制）。

#### 短板 B2 —— 瞬态反馈只有一个 toast

**证据**：`ui.js:17` —— 单元素、`textContent` 直接覆盖、2200ms、**没有类型/图标/队列**。
连续操作时后一条直接吃掉前一条；成功与失败长得一模一样。

而全站事件流（`GAME.log`）只写进「公文」视图（`#msg-log` 仅在公文档可见，`ui.js:776`）
→ **主界面上没有任何事件流**。玩家在城池/地图页时，世界发生的事只有 2.2 秒的 toast 和两个角标：
任务徽标（数字）+ 公文闪黄（v41）。建造完成、行军抵达、月俸欠俸、敌人来袭预警**都没有角标**。

#### 短板 B3 —— 重大时刻零演出

**证据**：全站 `@keyframes` 只有 4 组 —— `docBlink`（公文闪）/ `rankPulse`（资质徽章）/
`sxfIn`+`sxfPop`+`sxfPing`（江湖剧本专用）。逐个核对"高光时刻"的演出待遇：

| 时刻 | 现在的待遇 |
|---|---|
| 攻占一座城（核心目标） | 战报里一行字 + 一条 toast |
| 爵位晋升（22 档，仪式感最强的成长） | `GAME.log` 一行 |
| 时代之志达成 | `GAME.log` 一行 + 资源入账 |
| 名将归心 | `GAME.log` 一行 |
| 统一天下（终局） | 一个 🏆 emoji + 两行字的 modal（`main.js: checkVictory`） |
| 奇遇探成 | ✅ 有（v89.1 结算卡）—— **全游戏唯一有演出的地方** |

**讽刺点**：v89.1 已经建好了一整套演出组件（横幅/时间线/结算卡/倾向徽章/入场动效），
**却只给江湖剧本用**。主线最该演出的地方一次都没用上。

#### 短板 B4 —— 战报是纯文本，最大的情绪峰值被浪费

`tactic.js` 内部有完整的**距离轴逐回合推演**（野地 2000 / 野外城 3000 / 城池 4000）、
阵位、兵种克制、箭塔存亡、撤退判定——**但玩家一个字的过程都看不见**，
只看到结算数字和几行日志。

**现成条件极好**：程序化绘制能力（`map.js paintScene` 已画 12 幅景）+ 逐回合数据 +
四主题变量 + 品质色/兵种色板。这是"看得见的战斗"最低成本的一次机会。

#### 短板 B5 —— 静默机制过多，成长感被藏起来

| 机制 | 设计 | 后果 |
|---|---|---|
| 羁绊 11 组 | `story.js` 注释明写"**界面不作任何提示**" | 集齐五虎上将的玩家不知道自己变强了 |
| 灵淬（资质升档隐藏加成） | "**不写进任何提示文案**"（有 smoke 守卫） | 养成反馈为零 |
| 时代之志 | 只在达成时 log 一行 | 长线目标无存在感 |

**判据**：发现型秘密（奇遇点位）保密是**对的**；增益型秘密（羁绊/灵淬/保底）保密 =
玩家永远不知道自己变强了多少 → **成长感与掌控感双失**。

### 2.3 内容循环：开局没有高潮、中期没有台阶、日常没有答案

#### 短板 C1 —— 开局 10 分钟：没有首胜、没有引导、以等待为主

**证据**：新档 = 选头像/名字/州 → 官府 Lv1 + 资源 6000 + 1 将领；
首批任务 g01~g03 **全是"建民房"**（2/6/10 座，`questdata.js:32-37`）；
第一次战斗需要：建军营 → 募兵（受人口与资源限制）→ 出征；
而建造有**最小 5 秒现实保底**（`MEMORY §一.5`）。

**结果**：前 10 分钟是"点一下、等一等"。项目自己的平衡核查验证的也只是
**"不会卡死开局"**（`玩法扩展规划 §16.2`）——不是"开局有趣"。

#### 短板 C2 —— 目标层级断层：只有"当下"与"很久以后"

有：单次操作目标（建/造/打）· 时代之志（年号级，**被动等待**）· 统一洛阳（终局）。
缺：**20~60 分钟级的、可选择的**台阶。
爵位 22 档本该承担这条线，但晋升主要看声望（被动累积），玩家没有"下一步做什么"的指引。

#### 短板 C3 —— 任务系统形态单一：「指标 → 奖励」

50 成长 + 36 随机，**全部**是 metric 判定（`questdata.js` 通篇 `{metric, sub, goal, reward}`）。
没有：剧情任务 / 选择分支 / 链式任务 / 限时挑战 / 条件挑战（如"以少胜多"）。
44+ 条任务共用同一种体验：**看数字 → 达标 → 领奖**。

项目自己在 `玩法扩展规划 §十二` 里说得最准：「有任务但没**故事**」。

#### 短板 C4 —— 日常驱动缺失，而且"每日"有三把钟

**A. 没有"今日可为"入口**：每日刷新（随机任务 5 条）、日锁（江湖/奇遇）、周期结算（俸禄/岁贡）、
预警（入侵倒计时）分散在 5 个不同界面，没有任何汇总。玩家必须自己记住去哪儿看什么。

**B. 时间口径三把尺**（逐行复核）：

| 钟 | 定义 | 谁在用 |
|---|---|---|
| 历法（游戏年） | `secPerYear = 57600` 游戏秒 | 季节 / 年号 / 史册 / 羁绊 |
| 现实秒制"日" | `86400` 游戏秒（= 1 现实日 @1×） | **月俸 7 日** · 江湖日锁 · 种田"游戏小时" |
| 现实日 | `Date.now()/86400000` | **随机任务刷新** · **岁贡（每日结）** · 野地日增 · 每日次数 |

**连坐后果（可实测）**：
1. 「月俸 7 游戏日」= 7 × 86400 = **10.5 个游戏年**（史册写着"是岁改元"时，俸期才过一半）；
2. 「岁贡」名字是**年**，结算是**日**（`domain.js:1445` 用现实日）；
3. 「月俸」名字是**月**，游戏里其实没有"月"这个单位。
   → 玩家侧表现为：三种周期互相对不上，**习惯回路建立不起来**（无法形成"每天来看一次"的节奏）。

#### 短板 C5 —— 无局外成长 / 无周目价值

重开 = 全部归零（50 条成长任务原样重跑）；见闻录 24 条、史册、称号都是**单档内数据**。
单机游戏最便宜的"回锅价值"（跨档收藏 / 成就 / 图鉴）没有做——
而**见闻录、史册两套数据结构已经现成**。

### 2.4 公道话：已经做对的地基（建议不要动）

审查看短板，但也必须说清**哪些是真资产**：

| 资产 | 为什么是好东西 |
|---|---|
| **史册**（记账式纪传体：19 规则 + 逐年快照 + 变量替换） | 稀有且有品位的情感装置；"是岁改元…"的文体是别人抄不走的味道 |
| **单一出口** 架构 + 三件套护栏（2241/793/audit 0） | 让任何改动都便宜、可验证——本报告中所有方案的成本都被它压低了一档 |
| **程序化绘制**（地形 / 12 幅场景 / 缩略图 / 州郡距离场） | 零素材成本的可视化能力，"看得见的战斗"直接可以建在它上面 |
| **江湖剧本的交互轮转**（热点选点 / 应对卡 / 时机条） | 真正打破了"读三行字 + 点三个一样按钮"，是全局最"现代"的一段设计 |
| **演出组件族**（v89.1 的 `.sxf-*`：横幅/时间线/结算卡/徽章/动效） | 已经建好，只差**接到主线的高光时刻**上 |
| **固定画布 1440×900 + 四主题 + 令牌体系** | 界面不随窗口漂移；换肤与新增组件都有据可依 |

## 三、改进建议

> 分类按老板点的三类：**机制拓展 / 节奏优化 / 情感激励**。
> 每条给：做法 → 接到哪（单一出口）→ 预期体验提升 → 成本 → **验收判据** → **UI 同步改善**。
> 原则照项目铁律：**加内容=加数据不改业务代码**；**一个概念一个出口**；**派生数据不入档**。

### P0 —— 一档：立即改变"手感"（三件，成本小~中）

#### P0-1【情感激励】里程碑演出层（Moment FX）

**做法**：新建 `ui.moment(spec)` 唯一出口 + `#moment-fx` 层（body 直挂，z=1400，
与 `#scene-fx` 同规格）+ `.moment-*` 组件族。三档规格：

| 档 | 形态 | 时长 | 用于 |
|---|---|---|---|
| `inline` | 横幅条（44px，金线扫光） | 2.2s 自动过 | 奇遇现形 / 灵机发现 / 任务达标 |
| `card` | 居中卡（印章 + 账本行） | 手动关 | 占城 / 名将归心 / 时代之志达成 |
| `full` | 全屏（复用 `.sxf-hero` 布局） | 手动关，Esc 可退 | 爵位晋升 / 统一天下 |

**接 6 处**（全部读既有出口，不新增状态）：
`占城` → 缴获账本（现有 loot 出口）；`爵位晋升` → 金印 + 绶带 + 新特权；
`时代之志` → 目标达成文案；`名将归心` → 头像 + 属性卡；`奇遇` → inline；
`统一洛阳` → full 终局（替换现在那个 🏆 modal）。

**预期体验提升**：把"数值变化"变成"被记住的事"。攻下第一座名城、升到第一个爵位、
集齐第一个羁绊——这三个瞬间会在玩家脑子里留下画面，而不是一行日志。

**验收判据**：① 六处触发点均可翻转（关掉开关不出）；② 不阻塞操作（inline 2.2s 可点穿，
card/full 可 Esc 关）；③ 开关 `settings.moment` 入档；④ 演出内容全部取自既有出口，不写死字面量。

**UI 同步改善**：见画布稿「里程碑演出」——含三档规格与占城/晋升两例。

#### P0-2【互动反馈】反馈分层 + 浮动账目 + 程序化音效

**做法**（三件一起做，都属"反馈层"）：

1. **`ui.notify(type, msg, opt)` 四型**：`success`(绿) / `info`(蓝) / `warn`(琥珀) / `danger`(红)，
   左色条 + 图标 + 最多 3 条堆叠队列；旧 `ui.toast()` **保留为 `info` 的别名**（零迁移，现有
   200+ 调用点不用动）。
2. **浮动账目**：侧栏资源行与中央关键数值变动时 `+1,200` 上浮 900ms（占领/赏赐/任务/市易）；
   唯一出口 `ui.floatGain(el, delta)`，数据取自各处已有的 `reward` 返回值。
3. **程序化音效** `GAME.audio.play(key)`：Web Audio 合成 10 个音——
   点击 / 建造完成 / 募兵完成 / 出征 / 胜利 / 战败 / 升级 / 晋升 / 奇遇 / 警报。
   **零素材**（与"程序化绘制"同路线），设置页给开关 + 音量三档（0/30/60/100），**开关入档**；
   音频不可用时静默降级（不抛错）。

**预期体验提升**：操作有"手感"，事件有"存在感"。这是"趣味性"里最便宜的一块——
玩家对"有没有反馈"的敏感度远高于对"画面好不好看"。

**验收判据**：① 音频不可用（桩掉 AudioContext）时不抛异常；② 开关入档且生效；
③ 旧 `ui.toast` 调用点零改动全绿（smoke/e2e 不红）；④ 浮字不改变任何数值。

**UI 同步改善**：见画布稿「反馈分层」——toast 四型样式 + 资源浮字位。

#### P0-3【互动反馈】战报可视化（回放条 + 分回合明细）

**做法**：公文 → 战报详情重做两段式：
- **上：回放条**（回合轴，一帧一回合）——双方单位块（兵种色）· 距离轴推进 ·
  事件标记（计谋生效 / 箭塔倒塌 / 克制生效 / 撤退 / 城墙破损）；
- **下：分回合表**（每回合双方损失与剩余）+ 既有【计谋】行。

**数据**：`tactic.js` 已有逐回合推演，补一组**结构化关键帧**落进 report
（⚠️ 只存关键帧 8~12 帧/场，抽样实测存档增量 < 2KB/场——存档是 localStorage 的稀缺资源）；
老战报（无结构化字段）**优雅降级为纯文本**。

**单一出口**：`ui.battleReplayHTML(report)`；数据侧 `GAME.battle.replayOf(report)`。

**预期体验提升**：核心高潮（攻城）从"文字流水账"变成"看得见的战役"。
这也是"趣味性"最直接的来源——玩家会为了看战报去打下一仗。

**验收判据**：① 同战报渲染可复现（种子化）；② 老档战报不报错；③ 存档体积抽样实测达标；
④ 回放内容全部来自结构数据，UI 不做二次计算。

**UI 同步改善**：见画布稿「战报回放」。

### P1 —— 二档：结构级（决定"能玩多久"，四件）

#### P1-4【节奏优化】今日军情（Daily Briefing）

**做法**：城池视图顶部常驻**军情条**（1 行 chips，带数字与状态色），点击展开完整面板。
汇总源**全部是既有只读出口**（不新增状态、不入档）：

```
可领取任务 N（questSummary().ready，与顶栏徽标同源）
时代之志进度 / 月俸下期倒计时（现实时间表述）/ 入侵预警倒计时
灵机之地 N 处（带「前往」→ 复用 mapCenterOn）
未现形线索 N（带「前往」）/ 伤兵可治 / 建造队列空位 / 城墙可升 / 科技可点
```

**单一出口**：`GAME.briefing()` 返回条目数组——UI 只渲染，不做判定。
**空态必须指路**（照任务面板的既有规范）。

**预期体验提升**：回答"今天上线干什么"。这是**留存**的关键件——
现在的游戏里，玩家下线再上线，面对的是同一个没有任何提示的城池界面。

**验收判据**：① 每项与源数据同源（改源即同步，写一条守卫断言）；② 空态指路；
③ 派生不入档；④ 与顶栏徽标口径一致（任务数两处必相等）。

#### P1-5【机制拓展 + 叙事】章节骨架：把 50 条成长任务重组为 7 章三国叙事链

**做法**：`DATA.CHAPTERS`（汉室倾颓 → 群雄并起 → 逐鹿中原 → 官渡 → 赤壁 → 三分 → 一统）+
现有 50 条成长任务各加一个 `ch` 字段归属；
每章 = **入场卡（moment）→ 章内任务 → 章末结算（赏 + 演出）**。

**为什么现在做**：项目自己判定的 A 级缺失是「有任务但没故事」（§十二）。
完整卡牌战斗（§九）成本大、周期长；**章节骨架是它的前置且不冲突**——
先给"故事感"（纯数据 + 演出，零判定改动），后给"新玩法"（卡牌）。

**单一出口**：`DATA.CHAPTERS` + `GAME.chapterOf(questId)`。
**验收判据**：① 每条任务恰好归属一章（无孤儿/无重复，写断言）；② 章节顺序不可跳；
③ 章末演出一次性；④ metric 判定零改动（任务判定测试全绿）。

#### P1-6【节奏优化】开局重排：首胜前置 + 军师条

**做法**：
1. **教学战**：新档在出生点 3 格内生成一处 0 级野地（黄巾小寇）+ 初始给 60 义兵
   → 让玩家在 10 分钟内走完「出征 → 战报 → 占领」的完整闭环；
2. **首建加速**：新档第一个建筑 0 秒完成；开局 48 游戏时内建造槽 +1；
3. **军师条**：7 步非阻塞提示（第一步就是"打一场"），可跳过、可关闭。

**预期体验提升**：第一印象从"等"变成"打"。首胜时刻前移是全游戏留存最敏感的 10 分钟。

**验收判据**：① 新档探针计时：首胜必在 10 分钟内可达；② 引导可跳过且状态入档；
③ 不破坏既有开局平衡核查（`玩法扩展规划 §16.2` 的"不卡死"断言保持全绿）。

#### P1-7【机制拓展】将领差异线：武学（被动）→ 技能（主动）

**做法**：照项目自己的 §一 / §十 分批——
**先被动武学**（4~6 门，每门接 `genAttrs` 现有属性链，加内容=加数据），
**后主动技能卡池**（为 §九 卡牌铺路）。

**交叉判据（关键）**：同资质、同将格的两名将领**练满后必须不同**——
否则这条线是假的。写一条可翻转断言：给两名同构将领各点满不同武学，`genAttrs` 输出必须不等。

### 附：时间口径修正（P1 小件，与 C4 对应）

**建议只改口径与文案，不动数值**（数值改动会连坐建造/行军/生长时间与全部测试）：

1. 「岁贡」→ 明确"日结"（或改称"贡赋"），消除"年"的误导；

### 4.2 与既有路线图的关系（不推翻，只重排）

**建议调整一处顺序**：把 `玩法扩展规划 §十三` 的
「第 3 期 §十 技能 → 第 4 期 §九 卡牌」**后移**到 B1~B6 之后。

理由：技能与卡牌的价值有一半在**演出与反馈**（出牌、命中、胜负时刻）。
现在演出层是空的（B2 未做），做了卡牌也只能"读日志"——
先用 B1~B3 把反馈层补齐，B6 章节骨架把故事感补上，再做卡牌，**同样的工作量能多收一倍效果**。

主序列建议：`B1 → B2 → B3 →（B4/B5/B6 可并行）→ B7 → B9 → B8/B10`。

## 四、缺陷清单

### 4.1 【P0】数值改动对老存档完全不生效

| 项 | 内容 |
|---|---|
| **现象** | 修改 `DATA.NPC_CITIES` 或守军公式后，读旧档仍是旧数据 |
| **证据** | 实验：改 `NPC_CITIES[0]` 为坐标(1,1)、改名「改过的洛阳」→ 读档后仍是「洛阳 (265,215)」；且存档副本与 `buildNpcCities()` 重建结果**不一致** |
| **根因** | 174 座 NPC 城整份写入存档 `map.cities`（**53.9 KB / 全档 56 KB = 96%**）。`loadGame` 中 `if (!s.map.cities)` 为假 → 不重建。而守军在游戏全程**从不被修改**（纯派生） |
| **影响** | 此前多次数值调整（元氏坐标修正、守军难度 `garrisonMul=0.55`）**对老档全部无效**。玩家感觉"难度没降"却查不出原因 |
| **建议** | 存档只留 `map.seed`；读档时始终 `buildNpcCities(seed)` 重建，仅叠加玩家可变部分（`owner`、已攻占记录 `fortsRazed`）。存档体积预计 56 KB → **约 2.5 KB** |

### 4.2 【P0】科技树 17/24 无任何效果

| 项 | 内容 |
|---|---|
| **现象** | 研究「城防技术 Lv8」「统帅能力 Lv7」等，花费黄金，但没有任何属性变化 |
| **证据** | 全项目 `techBonus()` 仅以 `'atk'`、`'train'` 两个参数被调用；`game.techMult()` 仅处理 `grain/wood/stone/iron`；此外无任何 `techLevel()` 读取点 |
| **生效（7 项）** | 种植技术 · 砍伐技术 · 挖掘技术 · 冶炼技术 · 练兵技巧 · 战斗技巧 · 研究技巧 |
| **失效（17 项）** | 打造技巧 · 侦察技巧 · 防护技巧 · 负重技巧 · 行军技巧 · 抛射技巧 · 驾驭技巧 · 建筑技术 · 储存技术 · 补给技巧 · 统帅能力 · 城防技术 · 维修技术 · 抢掠技巧 · 合成技巧 · 车轮技术 · 驯马技巧 |
| **附带** | `applyBuildCostDiscount` 只读 buffs 不读科技 → 建筑技术失效；`storeCap` 只读仓库等级 → 储存技术失效 |
| **建议** | 按类型逐个接消费点（射程→`range`、负重→出征携带上限、统帅→带兵上限、城防→`cityDefense`、抢掠→掠夺倍率、补修→伤兵回收）。**这是投入产出比最高的一项**：数值已在表里，只是没接线 |

### 4.3 【P1】三座建筑是纯装饰

| 建筑 | 描述承诺 | 实际 | 证据 |
|---|---|---|---|
| **驿站** | 城池间行军提速 1.5–6 倍 | 无任何功能 | 除 `UNIQUE` 表与图标映射外 0 引用 |
| **烽火台** | 8 级看兵力 / 9 级看将领 / 10 级看科技 | 无任何功能 | 同上 |
| **联盟楼** | 1 级入盟 / 2 级建盟 | 无任何功能 | 同上，且**联盟系统整体不存在** |

> **叠加问题**：出征是**即时结算**（`s.marches` 数组恒为空），所以"行军提速"类内容**天然无法生效** —— 除非先补行军队列机制。

### 4.4 【P1】在线粮食可被扣成无限负数

| 项 | 内容 |
|---|---|
| **证据** | 实验：20 万铁骑 + 粮 1000 → 5 个 tick 后 `粮 = -1,515,638` |
| **根因** | `tickOnce` 中 `s.res.grain -= feed` **无下限钳制**；而 `offlineCatchup` 有 `if (s.res.grain < 0) s.res.grain = 0` → **在线/离线口径不一致** |
| **影响** | 界面显示负粮；刷新页面负粮被抹平（等于离线偷跑）；无任何负面后果 |
| **建议** | ① 统一钳制到 0；② 补**断粮后果**（逃兵 / 禁止出征 / 士气下降），否则粮草系统只有"扣"没有"后果" |

### 4.5 【P1】胜利条件形同虚设

`GAME.checkVictory()`（攻占洛阳 → 天下统一弹窗 + 重新开局入口）**从未被调用**。全项目仅定义处出现一次。玩家打下洛阳不会有任何反馈。

| 字段 | 承诺 | 消费点 |

| `scout` | 大雾斥候难察 | ❌ 无 |
| `move` | 行军速度 ± | ❌ 无（且行军机制不存在） |

### 4.7 【P2】赛季国策与羁绊失效

| 失效项 | 承诺 | 原因 |
|---|---|---|
| 青龙「大兴土木」 | 攻城伤害 +20% | `boon.siege` 无消费点 |

### 4.8 【P2】道具两项无实现

- **急行军令**（`target: 'march'`）→ 改写恒为空的 `s.marches`，使用后无效果且**不报错**（静默失效）

### 4.9 【P2】数值与产能的张力

| 实测 | 数值 |
|---|---|
| 官府 Lv10 + 满农田（约 29 块 Lv10） | 粮 159,500/游戏时 → 可养**义兵 5.3 万**或**铁骑 4,557** |
| 攻打都城洛阳所需 | 约 **20 万**混编（实测 20 万重装 100% 胜、5 万义兵 0% 胜） |
| 投石车耗粮 | **250 粮/兵/游戏时** → 10 万辆 = 2,500 万/游戏时 |

单城路线在"养兵"与"攻洛阳"之间存在**数量级断层**，必须依赖多城（每城独立外城地块）或掠夺补给。多城可解，但**单城发展路线封死**，早期玩家容易卡死。

## 附：本次审计使用的探针脚本

审计过程产出的结构性检查已固化为项目根目录 **`audit.js`**（与两套测试互补）：

```bash
node audit.js            # 五项结构审计
node audit.js --strict   # 有孤儿按钮/重复定义时以退出码 1 失败（可挂进提交前检查）
```

| 检查项 | 抓什么问题 |
|---|---|
| ① 函数引用完整性 | 死函数、重复定义 |
| ② 按钮动作绑定 | 点了没反应的按钮 / 不可达的 case 分支 |
| ③ 科技效果消费点 | 研究了但无收益的科技 |
| ④ 叙事层消费点 | 国策 / 天气 / 羁绊修正值是否有人读 |
| ⑤ 数据字段引用 | 「改 data 不生效」的零引用字段 |

> **建议此后每次改动后跑三件套**：
> ```bash
> node audit.js && node smoke-test.js && node e2e-test.js
> ```
> 三者分工：`audit` 管结构完整、`smoke` 管逻辑正确、`e2e` 管真实 DOM 交互。

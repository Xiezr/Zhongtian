## 0. 「为啥每分钟都被打一次」—— 诊断与修复（先答这一条）

**结论：不是重复结算的 bug，是"周期口径"错了** —— 旧口径把来犯定在**游戏时间**"每日 9 时"，
而老板挂机在 **600× 时速**：一天 = 86400 游戏秒 ÷ 600 = **144 现实秒 = 2.4 真实分钟**，
于是"每天一场"= 每 2.4 分钟挨一场（挂机一小时挨 25 场）。日志里的三连炸正是三个游戏日。

| | 改前（v89.111） | 改后（v89.115） |
|---|---|---|
| 周期口径 | 游戏时间：每日 9 时一场 | **现实时间：每 30 分钟一场**（`DATA.INVASION.realMin`） |
| 目标城 | 按**游戏日**轮转 | 按**场次**轮转（同一套"人人有份、可预判"） |
| 预警 | 提前 4 游戏时（600× 下 ≈ 24 秒） | 提前 **5 现实分钟**（`warnMin`），文案写明"（现实时间）" |
| 离线补算 | 跨几天补几场（无上限逻辑） | 最多补 **3 场**（`catchUpMax`），其余"敌军见无隙可乘自行散去" |
| 首 tick | 进城可能立刻挨打 | **只排期不结算**（从下一场开始） |

函数族整条改名（**语义变了就换名字**，逼全仓过一遍）：
`invasionDayOf/DueOfDay/TargetOfDay` → `invasionSlotOf/DueOfSlot/TargetOfSlot`；
`invasionDueAt` 返回值从"游戏秒"变"**现实毫秒时间戳**"；`s.inv = { lastSlot, warnedSlot }`。
新增 `GAME.realNow()`（现实时间唯一出口）—— **测试可覆写 `GAME._realNowOf` 拨钟**（§92 就是这么测的）。

> 顺带：`DATA.INVASION.realMin` 想调（15/30/60/120 分钟）改一处即可；要让它在界面上可调，说一声加个设置项。

## 3. 需求 1：守将属性对守城**全军**加成

**病根**：将领加成一直按"**统率覆盖**"打折（统率 ×100 名之内的部队才吃满，见 `T.unitsOf` 的 `cover`）。
守城里守将统率 5 → 5000 守军只有 10% 的人吃加成 —— 与老板要的"城内**所有**军队"不符。

**改法**（tactic.js 一处）：
```js
if (ctx && ctx.playerDef && side === 'def' && a) cover = 1;   /* 守城守方：全覆盖 */
```
- 只对**我方守城**（`playerDef`）生效；野战/攻城仍是"阵前指挥半径"的既有语义；
- **NPC 守城不在此列**（其守将是系统派生的，口径不动，不给攻城平衡添变量）。

**实测**（smoke §95）：同一守将（统率 5），守城 `cover=1`（全覆盖），野战 `cover=0.1`（按统率打折），
`atkPct` 两者一致（说明只改了覆盖、没动加成原子）。

**界面**：城池面板守将行显示 **"征兵·对阵 · 守城全军加成：攻 +X% 防 +Y%"**（与实战同一原子 `genAttrs.atkPct/defPct`）。

## 4. 需求 2：斗将战（战前 · 50% · 胜者 +10% 临时）

**数值全在 `DATA.DUEL`**：`chance 0.50` · `bonusPct 0.10` · `rounds 3`。

| 环节 | 做法 |
|---|---|
| 触发 | 军队**战前**掷一次；**只在双方都有将领**时才有得斗（出击打野地/据点/名城：我方主将 vs 守将）。敌方无将（如流寇来袭）→ 不触发 |
| 对拼 | 逐合比 `勇武×2 + 统率 + 智谋×0.5 + 等级×2`（各带确定性抖动），3 合先占先多者胜 |
| 加成 | 胜者将领拿到一份**属性 ×1.1 的副本**（深拷备、原件不动 → 天然"只此战"），经 `genAttrs` 加成链（攻/防/统率覆盖/速度）传导成**全军战斗力**。`_duelBoost` 标记可查 |
| 确定性 | 结果随 `opts._sim` 存走：观战挂起 / 沙盘配方 / 逐帧重放**绝不重掷**（配方里的主将也换成"斗将后的那份"，否则校验必然对不上） |
| 战报 | `【斗将】第1合 甲 占先；…；斗将 3 合，甲 胜（2 : 1） · 甲 得势：其全军将领属性 +10%（限本战）` |
| 出征面板 | 军师估算下方追加预告：`⚔ 斗将：我方 甲 vs 守将 乙（战前 50% 触发 · 胜者全军 +10%）` |

**实测**：`rollDuel` 400 次触发 192 次（≈50%）；同 seed 同结果；无将返回 null；
端到端（`DATA.DUEL.chance=1` 必触发）→ 战报正文含【斗将】行、`result.duel.done === true`。

## 5. 本轮顺带修掉的真 bug：出征面板预估区整块空白

**症状**（实机诊断抓到）：按 **id** 打开城池目标的出征面板时，预估区显示
`🛫 目标无坐标，无法估算行军`，且**军师估算 / 搬运预估三框全空**。

**根因**（两处叠加）：
1. `battle.resolveTarget` 的**城池分支返回值没有 x/y**（只带 id/npc/守军…）；
2. `ui.updateExpMarch` 读的是**原始 target**（`{kind:'city', id}` 这种本来就没有坐标）。

**修法**（正本清源）：
- `resolveTarget` 城池分支补 `x: npc.x, y: npc.y`；
- `updateExpMarch` 一律读**解析后的那份**：`var t = ui._expRes || ui._expTarget;`
  （与 v89.114 的 haul 预估同一条口径 —— **面板读的就是结算读的那个 t**）。

修后实测：`🛫 行军 170 格 速度系数 69% 预计 02:03` · 军师估算与搬运预估都正常出数。

## 8. 诚实缺口 / 请老板定夺

1. **来袭间隔**：现固定 30 现实分钟（`DATA.INVASION.realMin`）。要 15/60/120 分钟，改一处；
   想在界面上调，可在自动化右栏加一个档位选择（老板发话即加）。
2. **斗将只在"双方都有将领"时发生**：流寇/敌军来袭（敌方无将领）**不会触发斗将** ——
   若希望"守城也斗将"，得给来袭部队派生一个敌方将领（会改守城战力口径，请老板定夺）。
3. **NPC 守城不吃"全覆盖"**：老板令只提"守将"（我方），故 NPC 守城的统率覆盖口径保持原样，
   攻城难度不变。要一并改也就一行。
4. **背包二级分类只列"有货"的类**：空分类不显示（老板要"快速检索拥有的"）。
   若想看到"全部 18 类"（含 0 件）以便知道还有哪些品类，说一声切换成常显。
5. **斗将/守将加成的平衡**：守城全军 +0~5%（守将勇武/智谋的实际百分比）、斗将 +10%（本战）——
   首次进入实玩后建议留意守城手感；要调就是 `DATA.DUEL` 与 `YW_PCT/ZM_PCT` 两处数值。

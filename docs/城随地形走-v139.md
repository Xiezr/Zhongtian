# v139 · 城随地形走（含水中据点）

> 老板口径：「城随地形走。但不能排除水里有浮动城市，这样吧，水中据点，城市分布约为三分之一。」

## 一、改前是什么样

`DATA.NPC_CITIES` 是**旧 2D 平面时代**硬编码的 x/y 坐标表，而地形早在 v90 就换成了
cube-sphere 生成。两张皮对不上，实测（v135 量的）：

| | 数量 | 占比 |
|---|---|---|
| 落在湖上 | 113 | 64.9% |
| 落在山/沼泽 | 9 | 5.2% |
| 落在平原 | 3 | 1.7% |
| **不合格合计** | **122** | **70.1%** |

也就是说整个游戏世界有七成城市泡在水里。

## 二、口径（三条，都按老板原话落地）

1. **城随地形走** —— 不是把地形改成平原去迁就城；
2. **不排除水城** —— 保留一部分做「水中据点」（浮动城市）；
3. **约三分之一** —— 按总城数算，174 × 1/3 ≈ 58 座。

## 三、实现

唯一挂点是 `GAME.buildNpcCities(seed, sphere)` —— 这张表**不入存档**、每次按 seed
确定性重建（见 `map.generate`），所以必须挂在这里而不是改常量表：直接改字面量会让
换星球后城留在上一颗球的位置上。

```
_relocateNpcSites(list, seed, SP)
  ├─ 第一遍：ciOfXY 定 ci，读 cells[ci].type
  │    ├─ 地形合格且不占出生点 → 原样保留（少改一处是一处）
  │    └─ 湖/沼泽/山，或与出生点冲突 → 进候选池
  ├─ 候选按 hash(seed|id) 排序（确定性，不随调用顺序变）
  ├─ 名额内且**原本就在湖上** → 留作水中据点，打 water:true
  └─ 其余 → 逐环外扩找最近的合格陆地（plain > caoyuan > forest > desert）
```

关键取舍：

- **只有湖面能漂城**。第一版用「湖 + 沼泽」判定，实测涌出 1 座「沼泽上的浮动城」——
  沼泽是滩涂不是水面，说不通，改为只认 `lake`。
- **NPC 城必须让开出生点**。`jianghuActsAt` 对城格一律返回空，有城压住出生格时
  开局第一屏就是「可做 0 件」。出生点 2 环内先占位。
- 「原样保留」的城也要过这道避让检查（第一版漏了，湖里那座城正好压在出生格上）。

## 五、过程中修出的三个既有缺陷（这才是真正花时间的部分）

### ① 一局两套地形（v91.61 就记着，一直没修）

`newGame` 里建球面那一步读 `GAME.state.map.seed`，而它跑在「新 state 组装之前」——
全新会话首局用 **seed 1** 建球面，基于这颗**错的星球**建 NPC 城；等 `map.generate()`
再 `ensure()` 时按真 seed 重建 → 地形全变。

实测（seed 61024）：同一个格 16993 先是 `hill`、之后是 `lake`；城「灰烬城」先在
ci 16999、之后 17191。

修法：建球面前把 seed 喂进去（`_seedOverride`），建完**不还原旧值**（旧值是别的星球的
seed），新局落地后清成 null，此后由 `state.map.seed` 说了算。

### ② `ciOfXY` 把失败结果永久缓存

`_xyCi` 缓存只认「查过没有」，不认「查成了没有」。球面还没建好时第一次查询会拿到 -1
并**永久钉死** → 之后 174 座城的 `ci` 全是 -1、全叠在第 0 格。

修法：负结果不写缓存；兄弟球复用数组时也清 `_xyCi`（每个球的记忆是各自的）。

### ③ `P.begin` 的时序（前传出生点）

`P.begin` 原来跑在 `newGame` 中段，那一刻球面还没定型。实测：第一次 begin 得到
`pos=0`、脚下 0 件事；手动再跑一次才得到 `pos=5891`、2 件事。

修法：`P.begin` 后移到球面定型 + NPC 城落位之后。前传开局选址（找有事的格、找最近平地）
全靠球面，早一步跑就是空转。

## 六、测试基础设施：两条断言原来"静默不跑"

改完跑 smoke，断言数从 **4129 掉到 4127**。查出来少的正是 `§331① ②`（村社回礼）。

原写法：找不到「已探明 且 pop>50 且未死」的村 → `return` 跳过整块。
而村社位置与人口随地形/seed 变（v139 之后变了），于是「测过了」其实是「这次没跑」。

这比红更难发现——**红的会喊，跳过的不会**。

修法：自造前置（挑一个真存在的村，点亮它、把人口拉到 200）。这两件事都是生产代码
真实会做的（探明、人口增长），不是给断言开后门；本块结尾本来就有 `bak` 还原。
现在 `§331①` 报「回礼到账 · giftAt=5」，`§331②` 报「被抢过掉 3 · 没抢过掉 -1」。

## 七、没做的

| 项 | 原因 |
|---|---|
| 村庄 4×4 格子 | v138 遗留。`city.col/row` 是结构常量（UI 网格/建造下标/居所上限/存档/基线），改它必须同时做「村庄 → 城市」扩建迁移，属独立一轮 |
| 水中据点的**玩法** | 现在只有落点与地图标识（城名后挂「· 水上」、颜色偏青）。登城、造船、水上贸易都没有——这是内容设计，等你定 |
| NPC 城与玩家的交互规则 | 迁移后与玩家的距离关系变了（部分城被挪近/挪远），出征目标列表的实际体验未做专项评估 |

## 八、补：3D 地图这一侧（v139.1）

第一版只改了**数据**（`s.map.cities` 的 ci/x/y），没改**地图渲染**。收尾核验时用截图发现：
截图对准湖面，看不到任何「· 水上」标签。追下去是三处读错了名单：

| 位置 | 原来读的 | 问题 |
|---|---|---|
| NPC 红标记 | `DATA.NPC_CITIES`（原始常量） | 仍画在旧坐标上；13 座都城/州里有 6 座的旧位置是湖 |
| 都城/州金名 | `DATA.NPC_CITIES` | 湖面漂着没有对应实体的城名 |
| 水中据点标签 | `mapSliceOf().cities` | 那个列表只有**玩家自己的城**（`sliceOf` → `by(s.cities)`），NPC 城在 `s.map.cities` —— 所以「· 水上」一条都没画出来 |

更麻烦的是标记的 `cellRef`：点中旧位置的红点，拿到的是**原始模板**（x/y/ci 全是过期的），
出征目标会错位。

修法：

- 标记与金名一律改读 `state.map.cities`（buildNpcCities 产、已迁移、带守军与 `water` 标志），
  原始表只在「还没 buildNpcCities」时兜底，避免开局一瞬没有标记；
- 自己的城照旧蓝名，NPC 浮动城单独青色 + 「· 水上」。

**取证**（实机）：点亮水域 → 重建地图 → 等一帧（`rebuild()` 只是置脏，真正重建在下一帧，
第一次读到的还是旧标记，差点误判）→ 截图并放大：

```
寒松 · 水上      ← 青色标签，压在湖心格上
红色据点标记      ← 与标签同格
```

程序化核对：`marked: "npc"`、`onLake: 1`、每座城的 `water` 标志与脚下的地形
**零不一致**（`inconsistent: 0`）。

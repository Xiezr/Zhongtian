## 二、世界账本：溢出 1968px → 0

### 实测（多星球 + 推进 10 天，六条线全有数据）

```
.m-body  scrollHeight: 2481   clientHeight: 513   overflow: 1968px   overflow-y: auto
→ 弹窗内部出现滚动条，且内容被压缩到 1/5 可视
```

项目铁律明写「弹窗里不许滚动条」。v129 逐屏核查记的就是这条（当时是 2180px）。

### 三步改法

| 步 | 做法 | 结果 |
|---|---|---|
| 1 | 每节改成可折叠（标题常驻 + 一行摘要，明细默认收起） | 1968 → **285** |
| 2 | 六条线改**两列** grid | 285 → **0** |
| 3 | 修 grid 子项 `min-width:auto` 撑破（右列被裁） | 内容不再被裁 |

第 3 步是踩出来的：

```
第一版：grid-template-columns: 1fr 1fr
        → 右列内容被弹窗边缘裁掉（「竞争者 你之9」「遗骸科技 一3」）
修：    grid-template-columns: minmax(0,1fr) minmax(0,1fr)   ← 限制列轨道
       + .world-grid > * { min-width: 0 }                    ← 让内容能收缩换行
       两条缺一不可
```

> 顺带被 smoke 照出一条：`gap: 0 16px` 里的 **16 不在间距标尺**（1/2/4/6/8/10/12/14/18/24），
> 改成 18px。这条铁律是项目自己定的，我写的时候没查。

### 改后

```
收起态：overflow 0（滚动条消失）
展开两节：overflow 仍 0（两列吸收了增量）
```

## 五、斗将 `power × 0.6`：确认生效（上轮欠的账）

前两次尝试都失败了，原因都值得记：

**第一次（胜率对照）**：把君主设成 Lv30 跑 30 天，两组建模都 100% 胜 ——
**天花板效应**，本来就稳赢的战斗看不出难度差异。

**第二次（降等级）**：Lv1 也是 92% 胜 —— 前传清剿（`tao` power 200）对君主太简单，
根本没有"中间地带"可以对照。

**第三次（直接拦截赋值）**：在 `DATA.LING_ACT[id]` 上装 `setter` 记录每次写入。
第一版又错了：

```
无优惠 4 → 有优惠 4.8     ← 反而涨了 20%？
```

不是 0.6 没生效，而是**两次跑之间升级了**（一次给 4000+ 经验），tier 从「近野」跳到「远郊」，
`tier.powerMul` 跟着变 —— 两次根本不在同一档。

重置等级后：

| | power 写入值 | 等级 | 档位 |
|---|---|---|---|
| 无优惠 | **4.0** | Lv6 | 远郊 |
| 有「头目服了」 | **2.4** | Lv6 | 远郊 |

`4.0 × 0.6 = 2.4` ✅ 同档对照有效。用完恢复 200（表没被污染）。

**所以这一条现在是真的验过了**，不是"代码写了"。

## 七、这轮的教训（全部来自撞墙）

1. **`scrollHeight === clientHeight` 不等于"没溢出"** ——
   我第一次量的对象是 `.inner-shell`（flex 容器，`overflow:hidden`），
   真正滚动的是它的子元素 `.m-body`。**量错对象会得出"没问题"的假结论。**
2. **"没测出差异"要先问"样本有没有落在可测区间"** ——
   胜率 100% 的对照测不出难度调整；这是我第二次犯同类错（第一次是 v130 的浮动容忍度）。
3. **对照组必须控制所有变量** —— 等级、tier、combo、精力，任何一个在两次之间变了，
   结果就没有可比性。这次是"升级导致 tier 变了"，非常隐蔽。
4. **口径不对的统计不如没有** —— 那个 246/438 的数字我一开始想写进报告，查清后撤掉了。
5. **写进报告的东西要标清楚"验到什么程度"** —— 上轮我写"只验了递减链路"，
   这轮才补上真正的倍率验证。**先标缺口，再补，比事后补不上强。**

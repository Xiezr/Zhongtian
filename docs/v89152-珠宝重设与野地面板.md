## ⑥ 诚实缺口（等老板一句话）

1. **夜明珠"转正"口径**：老档手里的旧夜明珠按**原名原物**保留、自动升格（48→150 价位，数量不变）——
   这是为我定的（技术上无法区分"旧夜明珠"与"新夜明珠"，同 id）。若您觉得"白升值"不可接受，
   替代口径 = 给新夜明珠换名字（如"照夜珠"），旧夜明珠并入蛋白石（等值）。
2. **爵位数量节奏**：新的 21 档需求**颗数更少、单价更高**（例：裂土封王 390 颗 → 160 颗，
   但按 price 折算的总价值 7740 → 11460 元宝）。若要"颗数也维持原量级"，改 `DATA.RANK` 数量即可。
3. **森林/山地两档改名**（璞玉 / 独山玉）是撞车后的替代名——若您有更想要的名字，一处替换即可。
4. **建筑高阶升级档位**：Lv13 蚌珠 → Lv45 阴沉木（阶梯前 9 档）——若想"高等级吃更高档珠宝"
   （如 Lv45 应吃夜明珠级），要调 `DATA.JEWEL_COST.tierEvery`（现 4）——**会连带改难度曲线**，请示意。

## ⑦ 本轮教训（已入技能 §66）

- **新增物品 id 必须全表查重**（不只 `ITEMS`：材料 / 装备 / 州郡 / 图标映射都要过一遍）——
  id 撞车的表现是"**后来者被静默去重跳过**"（表里还在、ITEMS 里没有）。
- **按值盲替换会打穿"同名键的其他表"**（`qingyu: ` 在 `CITY_MATERIAL` 里是"玉系材料标识"）——
  改名前先 `grep -c` 清点全部消费面，只改目标区。
- **概念重叠也要避**（和田玉 vs 昆山玉）——"撞车"不只是 id 层面的。
- **产出行判据用"标签形态"**（`>产量加成<`）而不是裸词 —— 危险操作区的"失去产量加成"会误伤（第 N 次）。

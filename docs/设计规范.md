# 设计规范（当前）

> 本文件 = **只看这一份就够了的当前规范**（原 `DESIGN.md` 第 1~10 章）。
> **本章号与原文一致**（1~10），所以别处写的「DESIGN.md 第 N 章」都能对上。
> 逐版本编年史（v2 → v67 的全部过程与踩坑）→ `docs/_史料/设计史.md`（同章号，从第 11 章起）。


> 复刻《热血三国》核心玩法，单机网页游戏，纯前端 HTML/CSS/JS，localStorage 存档，双击即可游玩（file:// 协议，使用普通 `<script>` 而非 ES module，避免 CORS 限制）。

## 1. 总体架构

采用**全局命名空间 `GAME` + 多个普通 script 文件**，通过 `index.html` 加载。所有代码挂到 `window.GAME`，避免模块加载问题。

```
index.html      — 页面骨架 + 古典UI主题CSS（一次加载）
js/data.js      — 全部静态配置：资源、建筑、兵种、地形、任务、将领模板
js/state.js     — 游戏运行时状态、存档/读档（localStorage）、世界时间轮
js/domain.js    — 核心逻辑：资源结算、建造/升级、造兵、人口、将领任命
js/map.js       — 全国地图生成、地形渲染、城池/资源点标记、路径计算
js/battle.js    — 回合制战斗模拟（兵种克制、兵损、胜败、战报）
js/ui.js        — 各面板渲染（创建角色/城内/将领/军队/任务/统计/公文/信件/宝物/装备）
js/main.js      — 启动入口、导航路由、全局事件绑定、计时器驱动
```

## 2. 文件加载顺序（依赖顺序）

`data.js` → `state.js` → `domain.js` → `map.js` → `battle.js` → `ui.js` → `main.js`

## 4. 核心数据结构

### 4.1 资源
```js
RES = { grain, wood, stone, iron, gold, pop }  // 粮食/木材/石料/铁锭/金币/人口
```

### 4.2 建筑 BUILDINGS（城内空地格子建造，可升级）
每个建筑：`id, name, icon, desc, baseCost{build}, maxLevel, produce(res/sec per level), costPerLevel(exp), unlockLevel`

建筑列表（第一阶段核心）：
- `house` 民房 → 每级 +人口上限 & 人口增长
- `farm` 农田 → 每级 +粮食产出
- `forest` 伐木场 → 每级 +木材产出
- `quarry` 石料场 → 每级 +石料产出
- `mine` 铁矿场 → 每级 +铁锭产出
- `market` 市场 → 金币交易
- `barracks` 兵营 → 解锁造兵，每级加快造兵速度
- `wall` 城墙 → 每级 +城防
- `academy` 校场 → 每级 +统率加成/兵力上限

城内为二维网格 `grid[cols][rows]`（如 5x4=20 格），空地格可点击建造，已有建筑可点击进入升级/详情。

### 4.3 兵种 TROOPS
```js
// 兵种属性: 攻击atk/防御def/血量hp/速度spd/耗粮food/耗资cost/占用占位/解锁所需
TROOP = {
  minfu 民夫, yibing 义兵, binghou 兵侯, changqiang 长枪兵,
  daodun 刀盾兵, gongjian 弓箭兵, qingji 轻骑兵, tieji 铁骑兵,
  zhouche 辎重车, chuangnu 床弩, chongche 冲车, toudan 投石车,
  ...青州兵/藤甲兵/突骑兵/虎豹骑/西凉铁骑/南疆象兵(高阶段)
}
```
兵种循环克制：枪克骑、骑克弓、弓克枪，盾克远程，象兵克制近战等（做简化克制表 `ATK_MULT`）。

### 4.4 将领 GENERAL
```js
{
  id, name, avatar, level, exp,
  tong_unit 统率, neizheng 内政, yongwu 勇武, zhimou 智谋,
  attack, defense, speed, hp, stamina, energy,
  loyalty 忠诚, salary 俸禄, status 状态(空闲/出征)
}
```

### 4.5 地图 MAP
- 全国大地图 `grid[cols][rows]`，每个地块 `{ terrain, cityId?, resource?, level }`
- 地形：`plain 平原, hill 山丘, forest 森林, water 水, desert 沙漠, city 城`
- NPC 城池：`{ id, name, x, y, owner, level, defense, garrison{兵种:数量}, troops, loot }`
- 玩家占领城池后纳入 `state.cities[]`，可远程建设

### 4.6 任务 QUESTS（成长任务链）
参考截图：建造民房 → 奖励粮/木材/石料/铁锭/人口。任务链：`{id, title, desc, guide, target{type,count}, reward{res, ...}}`

## 5. 游戏循环 / 时间轮

- `state.time` 世界时间（游戏内分钟），`setInterval` 每 1s 现实时间 = 若干游戏分钟。
- 每次 tick：结算资源产出（所有城市建筑产出 → 资源累加）、人口增长、建造队列/造兵队列倒计时、军队行军到达。
- 存档：`localStorage['sanguo_save']`，自动每 10s 存档一次 + 手动按钮。
- 关键数值随时间推进，重新打开从存档恢复。

## 6. 战斗系统（回合制）

`battle.js`：
- 攻方 `armyAttack`（将领+兵种数量），守方 `garrison`（NPC城驻军）。
- 回合制，每回合按速度排序，计算双方伤害 = Σ(兵种数量 × atk × 克制倍率)；按防御/血量减员。
- 城防（城墙等级/驻军）影响守方加成。
- 胜负：一方兵力归零或兵力少于某比例撤退。
- 胜利 → 战报，目标城归属玩家（`city.owner='player'`），获得战利品 + 声望。
- 战报存入 `state.reports[]`（公文报告）。

## 7. 称霸 / 胜利条件

- 地图上预设若干 NPC 城池（州郡）。玩家占领全部 NPC 主城 或 声望达阈值 → 统一称霸，显示胜利界面。
- 提供「再战一局/继续游戏」。

## 8. 第一阶段 MVP 范围（核心循环主线）

1. **创建角色**：选头像(男女)、君主名、开始 → 生成 1 座玩家城 + 初始资源 + 1 名初始将领。
2. **城内建设**：城内 20 格，点击空地建建筑（民房/农田/伐木场/石料场/铁矿场/兵营/城墙/市场），升级、拆除。
3. **资源产出**：建筑按等级产资源；人口随民房增长。
4. **造兵**：兵营内选兵种造兵，消耗资源与人口，有队列与倒计时。
5. **将领**：将领列表、属性、任命守将/出征、经验升级。
6. **地图**：全国地图，可点击移动/查看，显示玩家城与 NPC 城。
7. **战斗**：选将领带兵出征攻打 NPC 城 → 回合战报 → 打赢占领，输则损失兵力。
8. **任务**：成长任务链引导（如"建造民房"），完成后领取奖励。
9. **统计/玩家信息** 面板（复刻截图）。
10. **存档/读档** + 胜利判定称霸。

## 9. 命名空间约定

所有暴露对象挂 `GAME`：
- `GAME.DATA`（data.js 配置）
- `GAME.state`（运行时状态）
- `GAME.save/load`（存档）
- `GAME.domain`（逻辑）
- `GAME.map`（地图模块）
- `GAME.battle`（战斗）
- `GAME.ui`（渲染）
- `GAME.main`（启动/路由）
- 事件用 `data-action` + 全局委托监听，按钮统一调用 `GAME.action(name, payload)`。

## 10. 复用 / 扩展

- 所有配置集中在 `data.js`，新增建筑/兵种只需加配置项即可被各系统识别。
- 后续阶段可扩展：联盟、在线多人（需后端）、装备/宝物、信件、统计图表等。

## 11. 弹窗规范（v68 考察后统一）

> 由来：老板 2026-09-14「点击建筑出来的弹窗还是不好看，要求尽量统一（除非功能多的建筑），
> 按钮位置合理，操作项的命名合理（官府那个操作入口叫征收，有点扯淡了）。
> 也考察一下其他弹窗界面，做到风格统一」。

### 11.1 骨架与尺寸
- 所有弹窗走 `ui.modalShell` / `ui.openShell` 三段式：`m-head`（标题栏）·`m-body`（内容区，滚动）·页脚（操作栏，固定）。
- 尺寸四档 `sm / md / lg / xl`：按内容量挑档；**不许出现"弹窗内滚动条撑破"**（挑大了比挑小了好）。

### 11.2 页脚与按钮位
- 四套页脚同规格：`.m-foot` / `.modal-foot` / `.panel-foot` / `.bldg-foot`（实线、同间距、flex 居中或两端）。
- 按钮惯例：**主操作在前**（`btn gold`）、关闭在后；纯关窗文案一律「关闭」。
- 「取消」只用于**中止一个动作**的确认框（取消建造 / 取消移动）；纯关闭不叫「取消」。
- 不可逆操作的确认框：主操作（`btn red`）+「取消」+ **必须逐项说清代价**。

### 11.3 建筑详情弹窗统一骨架（城内 / 城外 / 城墙 · 动线：使用 → 建设 → 管理）

```
[头部]   图标 40px ·「名称 · LvN」· 描述（居中）
[信息区] attr 行 —— 各建筑特有（功能多的建筑允许差异化：军营队列、作坊箭塔…）
[功能行] op-zone「功能」：使用建筑（金色主按钮，进功能面板）
[升级行] op-zone「升级」：费用（左）· 升级按钮（右）—— 费用与按钮**同行**
[底栏]   bldg-foot：拆毁（左）· 关闭（中）· 移动 / 交换（右）
```

- **施工中弹窗与正常态同构**（图标 + 名称 · Lv→Lv + 描述），危险操作（取消）进底栏。
- 底栏三格摆位延续 v28 的设计（拆毁左下、移动右下、中间留白防误点）——
  关闭按钮居中，正好充当误点缓冲。

### 11.4 操作命名（`BLDG_FUNC`）
- 格式：**图标 + 用途短语**；多功能面板写「用途A · 用途B」。
- **名字必须覆盖面板的全部内容**（点名不副实就是误导）：
  官府面板含征调民力 / 本城特产 / 岁贡 / 改名 → 入口叫「官府事务」，不叫「征收」。
- 反面检查表：入口名 ⊂ 面板功能 时，改（校场·出征与伤兵 → 出征 · 伤兵；名录 → 将领名录）。
## 12. 任务列表规范（v69）

> 由来：老板 2026-09-14「已完成的任务自动浮动到最上方，右侧直接添加领取按钮」。

### 12.1 区块顺序（固定）

```
✅ 可领取奖励 → 已完成 → 随机任务 → 成长任务 · 进行中
```

- 「可领取奖励」块**自动出现 / 自动消失**：无可领取任务时整块隐藏（不留空壳）。
- 达标任务从原区块**浮**到顶块 —— **一处占位**：浮上去的项不再在原区块重复出现。

### 12.2 行内领取

- 顶块行右侧直接挂「领取」按钮（`btn gold sm`）—— **一步领取**，不必再进详情窗。
- 行本身仍可点（`data-action="quest-detail"`）：想看背景 / 需求 / 奖励明细照旧。
- 按钮**复用既有 action**：随机 → `claim-rand-quest`、成长 → `claim-quest`（不新造出口）。
- 非达标行**不带**领取按钮（避免误导），右侧仍显示 `当前 / 目标` 进度。

### 12.3 计数与空态

- 各区块的计数**只算本区块实际渲染的项**（浮上去的不重复计入）。
- 空态文案必须**指路**：`本批 N 项均已可领取 —— 见上方「可领取奖励」`。

# UI 立骨稿 · 交付说明（v70 → v-next）

> **本轮性质**：《UI 设计交接》的回应稿 —— **立骨轮**，不是全量重设计。
> **战场**：设计系统 + 3 个最高频界面。**主题**：默认墨玉（暗金）先行。
> **交付物**：① 画布《热血三国 · UI 重设计》② `docs/ui-tokens-vnext.css`（可直接追加的令牌增量块）
> **日期**：2026-09-14

---

## 一、一句话结论

**这个项目不缺风格，缺系统。**

暗金木质基底是对的，4 套主题 + 三色三元组（`--sh-rgb` / `--hl-rgb` / `--gold-rgb`）换向机制是教科书级的。
真正的问题在 **节奏与层级没有推导关系** —— 所以每加一个新系统就会跑偏。70 轮「补丁式统一」的根因在这里，不在审美。

---

## 二、诊断（按严重度）

### P0 · 唯一真问题：token 是「收敛过的数字」，不是「可推导的关系」

| 层 | 现状 | 病在哪里 |
|---|---|---|
| 字号 | 20 / 16 / **13** / **13** / **14** / 12 / 11 | `h3` 与 `body` **同为 13px**；`body` 与 `lead` **只差 1px** |
| 间距 | 4 / **6** / **8** / **10** / 14 / 18 | 前四档全挤在 4~10，相邻差 2px，**肉眼不可辨** |
| 圆角 | 4 / **6** / **8** / **10** | 四档差 2px，**软硬关系建立不起来** |

项目里所有「统一」都是**对齐到同一个数**，而不是**对齐到同一个关系**。

这一条直接解释了老板反复提的「各字体大小得当」为何始终没达标：`h3 = body = 13px` 时，标题和正文只能靠颜色和字重硬分 —— 小字号下必糊。

### P1 · 缺两个层：状态层、海拔层

- `hover / active / disabled / focus` 没有语义变量 → 同类按钮在不同界面反馈不一致。
- 阴影散落在各条规则里，没有 `elev-0..3` 阶梯 → 卡片 / 弹窗 / 浮层的深度关系不稳定。

### P2 · 色板族没有秩序

100+ 变量里，辨识色（`q1-4` / `rank-*` / `tag-*×8` / `strip-*`）各自为政，没有「基色 + 深浅档」的族关系 → 新增玩法就得新增硬编码色，主题化立刻出现漏网。

### P3 · 缺「一屏容量」的硬约束

地块飘字、弹窗长滚动条、下拉框 —— 三次历史事故是同一件事：**没有密度上限**。
交接文档第四节那 10 个待设计系统会继续踩这个坑。

---

## 三、设计方向：立骨，不换皮

保留暗金木质 + 4 主题机制，只把 token 从「数字」升级为「关系」。

| 维度 | 现在 | 改为 | 收益 |
|---|---|---|---|
| 字号 | 20/16/13/13/14/12/11 | **22/17/15/14/13/12/11** + `--fs-display 34` | 标题终于比正文大 |
| 间距 | 4/6/8/10/14/18 | **4/8/12/16/24/32** | 4 基偶数，档差 ≥4，可辨 |
| 圆角 | 4/6/8/10 | **4/8/14 + 胶囊** | 三档，每档对应明确物件类别 |
| 新增 | — | **状态层 · 海拔层 · 组件尺寸** | 反馈一致、深度稳定 |
| 色板 | 平铺 100+ | **只加族关系标注，色值一个不动** | 零风险 |

**关键**：这五步全是「改数值 + 加新变量、不动结构」。落地时业务 CSS 一行不碰，4 套主题的机制原样保留。

具体数值见 `docs/ui-tokens-vnext.css`（含素绢 / 青竹 / 夜阑三套主题的覆盖值）。

## 四、画布索引（Ardot《热血三国 · UI 重设计》）

| 位置 | 内容 | 用途 |
|---|---|---|
| 左上 | **设计系统 · 墨玉**（6 个区块） | 色彩三层结构 / 字体七级 / 间距 / 圆角 / 海拔 / 状态 |
| 左下 | **组件规范 · 墨玉**（5 个区块） | 按钮族 / chips / 资源行（逐位对齐）/ 卡片与槽位 / 弹窗骨架 |
| 右上 | **城池主界面 · 重设计** | 顶栏 + 13 tab 分四组 / 左栏 / 8×6 棋盘 / 底栏 |
| 右中 | **建筑详情弹窗 · 重设计** | lg 860×600 骨架 + 动线三段 + 页脚三格 + 标注 |
| 右下 | **创建首屏 · 重设计** | 立绘列 + 立绘 / 形貌 / 名号 / 十三州 chips / 开局 |

### 值得单独说的四处改动

1. **顶栏与导航分离**：原来 13 个 tab 挤一行还要塞「天时」。现在上排是身份与天时（季节·年号·存档状态），下排是 13 个 tab，**分四组 + 金色分组线**，右侧挂「司隶 · 京兆尹 · 长安县」行政全称 —— 密度问题一次性解决。
2. **城格用「图标内右上角数字」表达等级**，不再有图标下方多行文字。资源类地块用四色（麦黄 / 青绿 / 石灰 / 棕黑），功能建筑用金线标记，民房去掉金线 —— 三级层次一眼可辨。
3. **资源行三列末尾逐位对齐**：数值列右对齐并等宽，个位永远在同一条竖线上。负值走 `--red-light`，正值走 `--green-ok`。
4. **弹窗骨架不动，只对齐新节奏**：动线固定三段（功能 → 升级 → 管理），费用与升级按钮同行，页脚三格 `[拆毁] [关闭] [移动]`，关闭居中做误点缓冲带 —— v28/v68 已定的设计全部保住。

## 五、落地步骤（务必分批）

见 `ui-tokens-vnext.css` 文末「上线顺序」。要点：

| 批次 | 内容 | 风险 | 验收 |
|---|---|---|---|
| 0 | 状态层 / 海拔层 / 组件尺寸（纯新增） | 零 | 无（没有既有规则引用） |
| 1 | 排版七级（只改 3 个数字） | 低 | 重跑截图对比 |
| 2 | 圆角三档 | 中 | 重跑截图对比 |
| 3 | 间距阶梯 | **需回归** | smoke + e2e + 逐屏截图 |

**第 3 批是最需要小心的一批**：`--sp-*` 被大量固定宽高面板引用，`sp-5`(14→24) 与 `sp-6`(18→32) 幅度较大，个别窄面板可能溢出。
出现溢出时，**优先把该处的固定宽度改成 `hug_contents` / `fill_container`，不要把 `--sp-*` 改回去** —— 否则又退回「补丁式统一」。

## 六、与硬约束的对照（交接文档第一节）

| 约束 | 本稿是否违反 |
|---|---|
| 零外链 / 零依赖 | ✅ 未引入任何外部资源。画布上的字体（Noto Serif SC / Noto Sans SC / Inter）**不是新增依赖** —— 落地时仍走现有系统字体栈 |
| 无构建 | ✅ 只改 `index.html` 的 `<style>`；`ui-tokens-vnext.css` 是纯 CSS 文本，直接粘贴 |
| 纯 DOM + CSS | ✅ 画布上每一处都能用 CSS 实现（棋盘用绝对定位 + flex，弹窗用 flex；无 canvas/WebGL） |
| 4 套主题 | ✅ 色值零改动；新增层给了四套的值（墨玉 / 素绢 / 青竹 / 夜阑） |
| 存档兼容 | ✅ 不涉及任何存档结构 |
| 测试锚定 | ✅ **不动任何类名、文案与 DOM 结构**。v-next 只增删 CSS 变量值 |

## 二、需求 1：时间口径总表（1 倍速基准）

**口径定义**：`timeScale` 可选 1/10/30/120/300/600（1 现实秒 = N 游戏秒）。
**设计基准 = 1 倍速**（1 现实秒 = 1 游戏秒）——所有数值表以"游戏秒"为单位直接对玩家体验负责；
倍速只缩短现实等待，不参与设计。

| 系统 | 数值（1x 口径） | 判定 |
|---|---|---|
| **建造** | 曲线制（见 §三）：单次 8 分（民房 Lv1）~18h（官府 Lv12） | ✅ 本轮重设计 |
| 训练 | 20 秒（义兵）~5830 秒（投石车）/个 | ✅ 合理 |
| 研究 | 60×2^cur：Lv1 = 1 分 → Lv10 = 8.5 小时 | ✅ 合理 |
| 行军 | 60 游戏秒/格（标准步卒）；200 格 ≈ 3.3h | ✅ 合理 |
| 采集 | 1~24 游戏小时（封顶）；同时 3 队 | ✅ 与自动轮次同轴 |
| 农田 | 6~96 游戏小时（天授果 4 天） | ✅ 合理 |
| 定期来袭 | 每 30 **现实**分钟一场（v89.115 口径） | ✅ 现实时间 |
| 城墙 | 曲线（T_max 10h） | ✅ 本轮并入 |
| 最短建造地板 | 5 现实秒 × 倍率 | ✅ 保底 |

**修正记录**：建造时间从"指数爆炸（11→12 要 37~76 天）"重构为"曲线 + 12 级循环（单次 ≤24h）"（§三）；
城墙时间从"哨兵 0 兜底（全 45 级 ≈ 1 分钟）"并入同一曲线。其余系统经逐项核对**已在 1x 口径内合理**，不动。

## 三、需求 3+4：建造时间重设计

**唯一出口**：`DATA.buildTimeSec(bid, lv)` = `T_max × ((k+1)/12)^1.5`，`k = lv % 12`
（`lv` = 升级前等级，0 = 建造；返回"升到 lv+1 级"的游戏秒）。

| 规则 | 落法 |
|---|---|
| **单次 ≤24h** | 最重建筑（官府）T_max = 18h；全表实测无超 24h 档（§108①） |
| **12 级循环** | 升到 13 级用升到 1 级的时长、…、升到 24 级用升到 12 级的；25-36 再循环；37-45 用前 9 档（§108② 逐档恒等） |
| **各建筑区分度** | 官府 18h · 门派驻地 15h · 市场 12h · 军营/书院 11h · 城墙 10h · 招贤馆/工匠作坊 9h · 仓库/驿站/烽火台 8h · 铁匠铺 7h · 马厩/客栈/民房 6h · 校场 5h；城外 4 座 6h（§108③） |
| 曲线形状 | 1.5 次幂（舒缓递增，不再指数爆炸）；起点 = T_max/41.6 |
| 资源列 | **不循环**：保持 v89.104「12 级后封顶在 11→12 档 + 珠宝」——高等级持续高投入 |

**对照（官府）**：旧 Lv11→12 = **910 小时（≈38 天）** → 新 = **18 小时**；
Lv13 起新周期回到 1.2h 起步（循环）。实机图 `v89128-build-18h.png`：营造总览显示"官府 → Lv12 余 17时58分"。

**连带**：城外建筑（`extBuildCost`）同走曲线（旧农场 Lv12 = 59h → 新 6h）；旧表"哨兵 0/等级×60 兜底"时代终结（§104 重写）。

## 四、需求 6：城墙 → 环城结构（不占格 · 与城内建筑并列）

- **数据形状**：`city.wall = { build: {id:'chengqiang', lvl}, pending }`（与格同形）；
  **唯一访问器** `GAME.cellOf(city, key)`（数字 → cells[key]；`'wall'` → city.wall）+ `wallSlotOf`（补槽）。
- **全出口槽化**：建造/升级/拆除/取消/提速/队列完成/自动建造候选/劳作占用 —— 全部走 `cellOf`；
  槽位键归一 `slotKey`（UI dataset 字符串 → 'wall' | Number）+ `slotEq`（比较）。
- **视觉**：环城一圈（isoWallSVG）**只在修建后绘制**（环城是"城墙建筑"的外观）；
  环城热区常驻（未建 → 点它 = 「修建城墙」面板；已建 → 通用建筑面板）。
- **老档迁移**：`wallLv`（更老）与"格子里的城墙"（v89.126）**统一归一到环城槽**——
  等级保留、格释放、消息流提示（"🏯 城墙调整：城墙改为环城结构"）。三处旧痕（wallLv 字段 / 占格 / 找格出口）全删。
- **顺手**：攻占转正 / 据点转正也做"影子格 → 环城槽"提取（玩家侧永不占格）。

## 六、需求 5：自动采集/自动收获 + 野地驻军规则

### 6.1 自动采集/收获（每 24 游戏小时一轮）

- 开关：自动化面板新增「🌾 自动采集/收获」（`settings.autoGather`）；状态显示"上次执行/有驻军野地/采集队数"。
- 每轮（`GAME.autoGatherTick`，与采集封顶 24h 同轴）：
  ① **先收获**：所有 ready（≥1 游戏小时）的采集队 `finishGather` 结算（兵力按既有口径回驻军）；
  ② **再开采集**：有驻军、可采集、且无采集队的野地 → **驻军全部转入采集**（老板原话"所有驻军进入采集状态"）。
- 与手动共用同一批出口（`startGather` / `finishGather`）——不另写第二套结算；收完立即无缝重开（§110② 实证）。

### 6.2 驻军规则（每野地一队 · 一个将领）

- **首队**（该野地尚无驻军）：必须带将、走行军通道（带队立编）；
- **增援**（已有驻军）：**只收无将军队**——带将反而报错；增援为**点位直补**（真扣城兵、超上限回城）。
- 每野地一队：早就是单池语义（`w.garrison` 单对象）；本轮以"增援无将"规则强化 + 断言钉住（§110④）。

**诚实缺口**：无将增援为**瞬时到位**（不走行军）。行军链路以"带队将领"为轴
（`dispatch → arrive → expedition` 全程读 gen），无将队伍走那条链需四处判空、风险大于收益。
如需"无将增援也走行军/也要时间"，请老板示下，另开一轮评估。

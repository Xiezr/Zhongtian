# v140 · 2.5D 场景系统（把"PPT"换成"能走进去的地方"）

> 老板：「目前前20级还是 PPT，这不是个正经游戏。做场景，玩家在地图上自由走动：1）采集：出来一片可发掘的废墟，砍伐的林地、收割的庄稼等。2）垂钓，出来一个垂钓场景。3）拜访，出来一个拜访背景，要求 2.5D 或 3D，类似星露谷界面，风格为废土科技或匹配的场景风格。456……要求建立 10 个场景，不只是放 PPT 那种，是 3D 场景宝贝。如何将城内外转成 3D」

这一版交的是：**一个场景运行时 + 10 个能走能动手的 3D 场景 + 城内 3D 原型**，外加第 4 问的落地方案。

---

## 一、五个决定（都是权衡，不是偏好）

### 1. 正交相机 + 固定倾角，不是透视

星露谷那种视角的本质是 **正交投影 + 45°~60° 俯角**：

- 正交没有近大远小，物件大小恒定 → 玩家能读"距离"和"格子"；
- 固定倾角 → 不转镜头，WASD 与屏幕方向永远一致，不需要学操作；
- 透视俯视会把远处压扁，走起来晕。

镜头跟随玩家但不旋转（旋转会让"上=北"失效，在只有 WASD 的操作里是纯负担）。

### 2. 自己的 renderer，不复用 map3d 的

`map3d` 的 renderer 绑在离屏 canvas 上，还带着 globe / 云层 / 标记一整套状态，且它的 rAF 与"当前星球"强耦合。场景要能进 20 次、退 20 次不泄漏，所以自己一个 renderer + 自己一条 rAF，**只在场景开着时跑**。

### 3. 美术全部程序化，零外链

项目纯静态、断网可跑，`assets/` 下只有奇迹的 glb。所以断墙、针叶树、芦苇、钓台、帐篷、辐能塔、坠机残骸……**全部由 three 的基本体拼**（Box / Cylinder / Cone / Icosahedron / Plane + 顶点色 + 程序生成的噪声贴图）。

好处不只是"没有资源依赖"：

- 每个场景约 60 个 Mesh，手机也跑得动；
- 换配色即换风格（废土橙锈 / 辐光青 / 夜紫），10 个场景共用一套道具库；
- **加第 11 个场景 = 加一条配置**，不用等美术。

### 4. 交互只走一条结算出口

场景里动手 → 调 `GAME.prologue.act(ci, actId)`（前传既有出口：扣精力体力、掷骰、给辐能核心/经验）。**场景不自己算产出**。

上一轮斗将的教训（HP 和比分两本账）就是"呈现层偷偷算了一份"，那种 bug 查起来极贵。

### 5. 场景只是"动作的前置演出"，不改数据

`P.act(ci, actId)` 直调仍然立即结算（324 处测试走的就是它）。UI 入口改成进场景，场景里动手再调同一个出口。所以**测试基线零改动**。

## 三、城内 3D（第 4 问的答案）

### 为什么城内比野地简单

城内**本来就有坐标**：`city.cells[idx]`，`idx = row * col + col`。所以"转 3D"不是重建世界，而是换一层呈现：

```
col/row            → (x, z)                    每格 2.1 米
cell.build.id+lvl  → 建筑模块（层数随等级长）
cell.official      → 政务厅（2×2 占地）
c.wall.build       → 围墙（建了才画，与 2D 同一判据）
```

**数据一个字段都不改**：存档、建造、产出、科技前置全部照旧走原来的 `city`。3D 只是"换个角度看同一份数据"——这也是它能安全上线的唯一理由。

实测：48 格全部有节点；建筑等级看得见（Lv≥3 多一层、Lv≥4 加塔尖）；走近按 E 出信息卡（名称 / 等级 / 「回城内界面」），**信息卡不提供建造操作**——那件事只属于城市页，两边都能改就一定有两笔账。

### 城内外怎么连起来（三步，已走第一步）

| 步骤 | 做法 | 状态 |
|---|---|---|
| ① 城内俯瞰 | `scene3d.open('city')` 照 `city.cells` 现搭；城市页右下角「🏙 用 3D 看一眼」进入 | **已实现** |
| ② 城门口过渡 | 城外地图（已有 3D 球面）点到自己的城 → 播一段"推门"过渡 → 进城内场景；出城反向 | 未做（需接 map3d 的点击与相机） |
| ③ 城内可行走街区 | 现在城内是"俯瞰整城"（固定镜头）。要变成"人走在街上"，得把每格拆成 2×2 的街道块 + 建筑贴边，镜头改回跟随 | 未做（工作量 ≈ 重写一次城内布局） |

### 现在的城内 3D 是什么、不是什么

- **是**：一张按真实数据现搭的俯瞰图，能看到格子、建筑、等级、围墙；能走、能点、能回 2D。
- **不是**：不是一个能"逛"的街区。镜头固定、建筑是低模盒子、没有门窗、没有行人。

要走到"像星露谷那样在城里逛"，缺的是**街道层**：每格 2.1 米太窄，人走不进去。方案是把城内改成"建筑占格 + 格间留 0.6 米巷道"，或直接放大到每格 3 米、镜头跟随、只渲染视野内的格子。

## 四、踩的坑（都记进代码注释）

### ① `DATA` / `U` 不是全局

`var D = DATA;` 在 bundle 里直接 ReferenceError，而它在包最外层，一抛就把后面的 `main.js` 一起打断——**创角界面根本不出现**。`U` 同理（每个模块自己 `var U = GAME.utils;`）。

### ② 隐藏层里算尺寸 → canvas 只有 1×1

`layer.style.display='none'` 时 `clientWidth=0`，正交相机按 0×0 算视口，canvas 后备缓冲 1×1。**顺序必须是先显示、再装配、再 resize**，而且它不报错，只是白屏。

### ③ 参数位置传参是定时炸弹

道具函数签名不统一（`gTree(scale,dead)` / `gWall(w,h,seed)`），第一版按位置摊开传 `fn(p.s, p.seed, …)` → `gTree` 的 `dead` 拿到 seed（数字，真值）→ **整片针叶林全渲染成枯树**。现在每个类型在 `ARGS` 表里显式声明吃什么参数。

### ④ 水面：方向、基准高度、透明

- 镜头朝 **-z** 看，"前方"是负 z。第一版把湖放在 `+18`，整片湖跑到画面最底部；
- 水面基准 `y=0.03` + 波幅 `0.03` → 波谷把顶点推到地面以下，不透明水面"缺一块"，透出浅色地面，**看起来像湖里有洞**。基准必须 > 波幅（改 0.12）；
- 半透明水 + 半透明地面斑块 + 无水下透射 = 排序不稳，透过水看见两块 18 边形浅斑。改成**不透明水面**，问题消失。

### ⑤ 动作被改写时标签必须跟着改

节点写「翻找碎石堆」，但这格今天只能拜访 → 代理成 `bai` → 结果卡是「拜访 · 行商的水囊」。玩家只会觉得系统乱了。标签跟着动作走，宁可朴素也不能说一套做一套。

### ⑥ 加模块要改**两处**清单

`build_bundle.py` 的 `ORDER` 和 `smoke-test.js` 里那份**独立的 ORDER**（故意不复用脚本，就是为了构建脚本自己算错时测试还能抓到）。漏了 smoke 那份 → 源码同步守卫假红。

### ⑦ 命名 IIFE 会被审计当成死函数

`(function scatterGround(){…})()` 被"闭包内局部死函数"断言抓到，改匿名。

## 六、没做的（诚实清单）

1. **10 个场景的美术还是低模**：形体能读、配色分层，但没有贴图细节、没有动画角色、没有音效。
2. **城内 3D 是俯瞰，不是街区**：镜头固定、不能"逛"，缺街道层。
3. **城门口过渡未接**：城外地图点自己的城还不会进屋。
4. **场景内没有事件**：只有"动手 → 结算"，没有随机遭遇、没有 NPC 走动。
5. **场景没有存档状态**：每个节点"这一趟收拾过没有"只在本次进入有效（退出即重置）。
6. **移动端未适配**：没有虚拟摇杆，只有键盘。

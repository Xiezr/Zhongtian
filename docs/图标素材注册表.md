## 二、画布尺寸适配规则（**最容易出事的一步**）

各库画布不同，而本项目 `wrap()` 输出的是 `<svg viewBox="0 0 64 64">`。
**塞进去之前必须换算，否则图形会被裁到只剩一角（表现为"图标全没了"）。**

| 库 | 原始画布 | 缩放系数 | 写法 |
|---|---|---|---|
| GI | 512×512 | **64/512 = 0.125** | `<g transform="scale(0.125)">` |
| MC | 24×24 | 64/24 ≈ 2.667 | `<g transform="scale(2.667)">` |
| IP | 48×48 | 64/48 ≈ 1.333 | `<g transform="scale(1.333)">` |

**通式**：`scale = 64 / 该库的 width`，在素材层的 `paint()` 里显式写出来，不要假设一致。

> 血泪教训（v33）：v32 接入 GI 时漏了这一步，512 路径塞进 64 视窗 →
> 只显示左上角 1/8，而图标主体在 512 画布正中 → 用户看到「图标全没了」。

## 五、新增一个图标（操作步骤）

**场景 A：新元素能用现有素材**
1. 在 `js/data.js` 里加上元素定义，拿到它的 `id`
2. 在**第三节对应分组**加一行：`id: [素材key, 色调]`
3. 重跑生成脚本：`node .workbuddy/tools/gen/gen_gicons.js`
4. 跑几何体检：99+ 个图标**越界必须为 0**
5. 跑三件套：`audit.js` / `smoke-test.js` / `e2e-test.js`

**场景 B：素材库里没有合适的 key**
- 先在库里找**近似语义**的（按关键词遍历 `Object.keys(icons)`）
- 找不到 → 用现有 key 里语义最近的**降级**（在生成脚本的候选数组里往后排）
- 仍找不到 → 保留手绘兜底（不写进映射表即可，会自动回退）

**场景 C：要整体换画风/换库**
→ 走 `docs/图标适配流程.md`。

## 七、已知限制

- **GI 是西方中世纪奇幻风**：骑士、盾徽、猛兽类素材大量存在，
  而三国是汉代中国，**建筑/兵器/服饰的时代感对不上**（这是 v34 要解决的问题）
- 备选库 MC/IP 是**现代 UI 线性图标**，覆盖度不如 GI（农田/沼泽/平原/腰带 MC 无），
  但线条更适合"墨线木刻"式改造
- **不存在"三国题材的开源图标库"**：真要贴合时代背景，只有三条路 ——
  ① 中国色 + 墨线风格改造（改观感不改造型）② AI 生成 ③ 从 iconfont 等平台手动下载成品素材

## 八、AI 位图生成与切分流水线（v35）

### 8.1 降本核心：图集生成
**一张 2×2 图集 = 4 个图标**，91 张图从 91 次生成降到约 23 次，**成本降 75%**。

prompt 结构：
```
A 2x2 grid of 4 separate game UI asset icons arranged in a perfect square grid,
evenly spaced with wide flat pure white gaps, each icon perfectly centered
within its own quadrant.
Top-left: <元素 A 的汉代形制描述>
Top-right: <元素 B>
Bottom-left: <元素 C>
Bottom-right: <元素 D>
All four icons share one identical art style: refined realistic game art in the style of
Rise of Kingdoms / Three Kingdoms strategy games, highly detailed material textures,
warm golden light from upper left, slight three-quarter view.
IMPORTANT: the entire background including all the gaps must be a perfectly flat
uniform pure white #ffffff with no gradient, no sky, no haze, no environment,
no ground plane, no shadows cast on the ground.
No text, no labels, no borders, no frames, no dividing lines, no people.
```

### 8.2 三条必须遵守的规则
1. **背景必须锁死纯白 #ffffff**（写上面那段 IMPORTANT）。
   不写会出**灰色渐变背景**导致抠不净（首版官府四角偏差 37、主体满框 100%）。
2. **`background:"transparent"` 参数不生效**（实测透底率 0.0%）→ 统一出白底再抠。
3. **四象限描述必须逐格写清**，AI 才会把每个图标居中在自己的象限内。

### 8.3 脚本清单

| 用途 | 路径 | 用法 |
|---|---|---|
| 切分图集（均分+抠底+重裁+居中） | `.workbuddy/tools/gen/atlas_split.js` | `node atlas_split.js <图集.png> <id1,id2,id3,id4>` |
| 单张/批量处理 | `.workbuddy/tools/asset/rename_matte.js` | 直接跑 |
| 拼总览图 | `.workbuddy/tools/show/tile_show.js` | `node tile_show.js <输出名> <标题> <列数> "<id:中文,...>"` |

**切分算法**：均分象限 → 每象限独立四角采样抠底（T=42，羽化 SOFT=26）→
按 alpha 内容 bbox 重裁 → 居中到 1024 统一画布（四周留白 6%）。

### 8.4 抠底质量复检判据
| 指标 | 合格 | 说明 |
|---|---|---|
| 四角背景一致性偏差 | < 15 | > 30 说明背景带渐变，抠不净 |
| 透底率 | > 50% | 太低说明主体占满 |
| **主体占宽/占高** | **< 95%** | **≥99% 就是没抠净**（残留"非四角同色"的背景） |
| 内容占象限比 | 40~95% | ≥97% 说明可能切到邻格 |

### 8.5 实测数据（91 张全部合格）
- 象限背景：`#fbfcfb` ~ `#ffffff`
- 内容占象限：47% ~ 91%（**从未触碰象限边界**）
- 单张体积：约 1.4~1.7MB（1024×1024 PNG），91 张共 38MB

## 十、接入实现（v35-e 已完成）

### 10.1 位图登记表 `js/bitmaps.js`
由 `.workbuddy/tools/gen/gen_bitmaps.js` **扫描 `assets/icons/ui/` 目录自动生成**（勿手改）。
含 93 个文件名 + 前缀规则表 + `BITMAPS.src(group, id)`。

**加载顺序（三处必须一致）**：`icons.js` → `gicons.js` → `bitmaps.js` → `portraits.js`
（后两者靠 `typeof GICONS` / `typeof BITMAPS` 延迟绑定，放在 icons.js 之前会拿不到）

需要同步的位置：`index.html`、`smoke-test.js` 的 `require` 列表（e2e 走真实页面自动跟随）。

### 10.2 取图优先级
```
① js/bitmaps.js（AI 位图，最高）
② js/gicons.js（game-icons 矢量）
③ icons.js 手绘 SVG（最底回退）
```
`ICON.get` / `ICON.forEquip` / `ICON.forItem` 三个入口各有位图优先判断；
未命中自动降级，**零风险**。

### 10.3 为什么位图不套 `wrap()`
`wrap()` 会补 `lightPass()`（光晕暗角）与 `plate()`（承台圆盘）。
位图 PNG 自带透明轮廓，**不套 wrap 就自然没有承台** —— 这正是需求
「单个地块不再显示背景（透明），直接以图标轮廓」的实现方式。

### 10.4 必须的 CSS
```css
img.ico-img { object-fit: contain; }                      /* 否则被 100%/100% 拉伸变形 */
.tile-art img.ico-img { filter: drop-shadow(0 2px 3px rgba(0,0,0,.42)); }  /* 接地投影 */
```

   **正确处置：收窄断言作用域**（剥掉 `.tile-art img.ico-img{}` 这条合法规则再查），
   而不是删掉业务需要的投影。

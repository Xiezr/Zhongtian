# v89.208 · 实证评估 —— 换框架后的新发现

> 框架见 `docs/v89208-全面评价体系.md`（12 维）。
> 本报告只写**上两轮框架看不见的东西**：⛔ 缺陷 3 个、⚠ 风险 1 类、✅ 正面证据 6 条。
> 全部结论由**真执行**得出（jsdom 起真游戏），不是读码推断。
> 评估时点：v89.207 交付后（门禁全绿：audit 0 · smoke 3554/0 · e2e 1251/0）。

## 结论先行

1. **⛔ 存档导入门过宽**：16 种畸形包中 **7 种被接受**，其中 **5 种接受后载入静默失败**。
   校验只查 `cities` 是**非空数组**，不查元素结构、不查其他字段类型。
2. **⛔ `adoptState` 不是原子的**：它第一行就 `GAME.state = st`，迁移中途抛错时**内存已被换掉**；
   而调用方 `loadFrom` 把异常吞了并返回 `null`——调用方以为"没有存档"，
   实际手上已经是一个**结构不全但被当真档用**的状态。已实证半迁移。
3. **⛔ 坏档会连锁锁死玩家**：导入 `generals` 为字符串的档后，**连「新游戏」都开不了**
   （`newGame` 抛 `TypeError`）。玩家手上：旧档坏了、新档开不了，只能手动清 localStorage。
   根因是 `((s && s.generals) || [])` —— `|| []` 只兜 null/undefined，**兜不住"非数组的真值"**；
   同类写法全仓 **36 处**。
4. **⚠ 测试保险的免赔区 = 63.4%**：1,479 个出口中 **938 个**在 smoke/e2e 里**一次都没被直接提及**，
   其中 **925 个仍被产品代码使用**。这是本体系量出的**最大结构性风险**（非缺陷）。
5. **✅ 引擎本身很稳**：200 轮随机极端存档 × 200 tick（共 4 万 tick）**零不变量违例**；
   资源往返保真**零差异**。→ **坏的不是引擎，是门口**。
6. **✅ 性能无悬崖**：后期规模（50 城 / 500 将）**2.54 ms/tick**，是基准的 145× 而实体数是 183×
   ——**次线性**，远在 16ms 帧预算内。

## ⛔ 缺陷 1 · 存档导入门过宽

**位置**：`js/state.js:2803` `GAME.importText`（校验阶梯在 2808~2815）

```js
if (!pack.state || typeof pack.state !== 'object' || !pack.state.cities || !pack.state.cities.length)
  return { ok: false, msg: '存档内容不完整（没有城池数据）' };
```

**只验了"`cities` 是非空数组"，没验元素**。`[{}]`、`[null]`、`Array(5000).fill({})` 全部放行。

### 打靶结果（16 包 · 真跑）

| 畸形包 | 判定 | 接受后真载 |
|---|---|---|
| 空文本 / 非 JSON / JSON 非对象 / 无 `_fmt` / `_ver` 错 / 无 `state` / 无 `cities` / `cities: []` | ⛔ 拒绝（8 条） | — |
| 正确内容 · `_check` 填假值 | ⛔ 拒绝（校验和拦住） | — |
| **`cities: [{}]` + 正确校验和** | ✅ **接受** | **静默失败/半迁移** |
| **`cities: [null]` + 正确校验和** | ✅ **接受** | **静默失败/半迁移** |
| **`cities × 5000 个 {}`** | ✅ **接受**（提示「5000 城」） | **静默失败/半迁移** |
| **`generals: 'oops'`** | ✅ **接受** | **静默失败/半迁移** → 见缺陷 3 |
| **`map: null`** | ✅ **接受** | **静默失败/半迁移** |
| 正确内容 · **省略 `_check`** | ✅ 接受 | 载入 ok |
| 带 `__proto__` 键 | ✅ 接受 | 载入 ok（`JSON.parse` 不污染原型，✅ 无风险） |

> **「省略 `_check` 被接受」判 ~（设计如此）**：`state.js:2662` 注释原文
> 「FNV-1a 32 位。只为'文本在传输/粘贴中没被改坏'，**不是防篡改**」——
> 它是**防复制掉字**的，不是防改；省略即表示"没做过校验"。**不判缺陷。**
> 其余 6 条被接受的是**结构问题**，与校验和无关（校验和只能证明"内容没被改过"，
> 证明不了"内容结构对"）。

**建议**（任一即可，代价都低）：
- **A（推荐）**：`importText` 对 `cities[0]` 与 `generals[0]` 做一次**结构抽检**
  （`col/row` 是数字、`generals` 是数组）——一行 `Array.isArray` + 一个必填字段检查。
- **B**：导入后**先在内存试跑一次 `adoptState`**，成功才落盘（顺带修掉缺陷 2）。

## ⛔ 缺陷 2 · `adoptState` 非原子：半迁移状态会留在内存

**位置**：`js/state.js:2303`（adoptState 首行）· `js/state.js:2761-2771`（loadFrom）

```js
GAME.adoptState = function (st) {      GAME.state = st;      // ← 第一行就把内存换掉了
  ...迁移逻辑，中途任何一步抛错，GAME.state 停在半迁移态...

GAME.loadFrom = function (id) {
  try { ... return GAME.adoptState(st); }
  catch (e) { return null; }                                // ← 异常被吞，调用方以为"没有存档"
};
```

### 实证

```
载入前：cities=1 gold=20000 ver=3
loadFrom 返回：**null（静默失败）**
载入后 GAME.state：cities=1 · 首城 col=undefined · res={"grain":0,"wood":0,...}
⚠ 半迁移实证：内存里已是畸形档，而调用方拿到的是 null
```

**为什么这比"崩了"更糟**：崩了会留下堆栈。这里是**静默**——
调用方以为"没有存档"，于是继续用着一个 `col=undefined` 的状态去渲染地图/结算产出。
症状会是**莫名其妙的画面错乱或数值异常**，而不是一条报错。

**建议**：`adoptState` 改成"先在**临时变量**上迁移完毕，最后一步才 `GAME.state = st`"
（或 `Object.assign` 到一个构造好的对象上）。这是纯机械改动，不涉及玩法口径。

## ⛔ 缺陷 3 · 坏档连锁：玩家连「新游戏」都开不了

**位置**：`js/state.js:625` / `js/state.js:641`（`nextGenId` / `generalUsedIdOf`）

```js
((s && s.generals) || []).forEach(function (g) { ... });
```

`|| []` 只兜 **null / undefined**，兜不住**"非数组的真值"**（字符串 / 数字 / 对象）。

### 隔离复现（真跑）

```
① 导入 generals:"oops" 的档（_check 正确）→ ✅ 校验放行（缺陷 1 开门）
② loadFrom → 半迁移（缺陷 2）
③ 玩家点「新游戏」（case 'new-game' → GAME.doNewGame）
   → 💥 TypeError: ((s && s.generals) || []).forEach is not a function
   at GAME.nextGenId (js/state.js:641) ← GAME.makeGeneral ← GAME.newGame
```

**玩家处境**：旧档坏了、新档开不了，**只能手动清 localStorage**。无 UI 出口。

**同类写法全仓 36 处**（`(x || []).method()` 形态），分布：
`domain.js` 15 · `state.js` 10 · `ui.js` 8 · `battle.js` 3。
缺陷 3 的这一处在 `GAME.syncSeq`（state.js:625）与 `GAME.nextGenId`（state.js:641）。

> 注意：**这 36 处在正常玩法下都是安全的**——状态由 `newGame`/`adoptState` 构造，
> 类型天然正确。它们之所以变成风险，**只因为缺陷 1 把非数组真值放了进来**。
> 所以修**门**（缺陷 1）比修 36 处**更划算**；若要纵深防御，再把这 36 处换成 `Array.isArray` 兜底。

## ⚠ 风险 · 测试保险的免赔区 63.4%（维度⑧ · 元层）

前两轮都在量产品，没人量**测试本身**。本维度从出口面反向查：`audit_v89208_cover.js`

| 指标 | 数值 |
|---|---|
| 唯一出口 | **1,479** |
| smoke 直接提及过 | 508 |
| e2e 直接提及过 | 104 |
| **零直接提及（smoke 0 且 e2e 0）** | **938（63.4%）** |
| ├ 其中**产品代码仍在用** | **925** ← 真盲区 |
| └ 其中产品也不用了（只剩定义） | 13（与 `audit.js`「仅测试引用」互为镜像） |

真盲区按文件分布：`domain 371 · ui 247 · state 123 · main 81 · battle 79 · map 23 · story 1`

**必须说清口径**（否则是误读）：
这是**"测试文件里有没有直接写出这个出口名"**，**不是行为覆盖率**。
大多数零提及出口是**被上层入口间接走到的**——例如 `GAME.popTaxMul` 会在
`GAME.tickOnce` 里被调用，所以它的行为其实被测了，只是测试里没写它的名字。

**它的真实含义**：这 925 个出口的**具体逻辑**没有专属断言。一旦重构其中某个，
**没有任何一条断言会因它而红**——回归保险在这里是空的。
这是"每 15 行一条断言"这个密度数字**掩盖掉的**结构性事实。

**建议**：不必补 925 条断言。优先给**三种**出口补：
① 有分支/边界判断的（`canXxx` / `xxxOf` 类）；
② 被多个上层复用的（改了影响面大）；
③ 数值/口径类（`popTaxMul`、`scaledCost` 这类——正是 v89.207 出漂移的那一类）。

## 与前两轮的关系（为什么这些以前看不见）

| 新发现 | 为什么旧框架看不见 |
|---|---|
| 导入门过宽 | 旧框架的"输入面"只数了 `<input>` 个数（5 个 `type=text`），**从没把畸形输入喂进去过** |

## 二、这轮做的三件

### 1. 场景节点状态按天入存档

改前：`userData.node.done` 只活在内存里，**退出场景再进来，翻过的碎石堆又满了**。

现在记在 `state.sceneDone`，键是 `场景#节点#游戏内天数`：

```
ruin#0#42    ← 第 42 天，废墟场景的第 0 个交互点
```

- 同一天内进出、存档读档都记得（这才是"收拾过了"该有的意思）；
- **第二天自动复位**——荒野之事每天重长，与 `P.act` 的每日锁同口径；
- 键里带天数，所以不需要额外的过期逻辑；顺手 prune 掉 3 天前的键，防存档膨胀。

实测：`做前 done=false → 做完 done=true → 退出重进 done=true`，存档键 1 个。

### 2. 场景内确定性遭遇 → 直接进斗将

这是让"十张地图"变成"一个世界"的第一步：走进去不一定只有三个摆好的点。

- 用 `hash(场景 | 格 | 天)` 决定"这一趟会不会撞上、撞上哪一头、它站哪"——
  **同场景同格同天永远同一头**，读档重进不会换个对手；
- 实测 40 格里 13 格有遭遇（约 32%），其余是清静；
- 撞上之后按 E → `P.duelBegin(ci, foe)` → 打开 v136 那套斗将面板（左右对峙/血条/出招动画/结算）；
- **只有前传**（君主一个人在外面走）才有遭遇；立城后不再抽（`§351③` 守着）。

为此把斗将入口从"只能打脚下这一格"解耦：

```
duelStart()  = duelBegin(P.pos(), duelFoe(P.pos()))   ← 原行为，一字不变
场景遭遇      = duelBegin(ci, duelFoe(ci, speciesId))  ← 指定物种
```

并把对手**快照**存进斗将状态（`foeFull`）：`duelStep` 每合要复算，而遭遇的对手未必等于
`duelFoe(ci)`（那是"这一格的头目"）。不存快照就会重演 v136 的"每合换人、比分倒退"。

### 3. 城内加城门节点

3D 城内原来只能点右上角"离开"，那就是个弹窗。

现在城南边缘有一道门（两根柱子 + 门楣 + 一条辐光条），走过去按 E → 走出城门、回到野外。
**出城是个动作**，走过去的动作比点按钮更像在城里。

实测：`nodes=49`（48 格 + 城门），按 E 后 `opened=false`（场景关闭）。

## 三、踩的坑

### ① 指定物种被"野地守将"静默吞掉

`duelFoe(ci)` 第一行是"这格有守将就用守将"。我加了 `speciesId` 参数却没动那一行 ——
结果是：场景里撞见一头**辐光孢子母体**，打的却是该格的**掠夺者头目**。
面板上写着 A，实际打的是 B，而且不报错。

修：`if (!speciesId && d && d.gen …)` —— 指定了物种就跳过守将分支。
断言 `§351④` 逐个物种核对，七个全 ✓。

### ② `_state()` 返回的是副本数组，`indexOf` 恒为 -1

探针里写 `nodes.indexOf(n)` 去拿"真实节点下标" —— 但 `nodes` 是 `.map()` 出来的**新数组**，
`indexOf` 永远 -1，于是 `nodeList[-1]` 是 undefined，报「附近没有可动手的东西」。

这不是产品 bug，是我探针的写法错。教训：**调试接口返回的拷贝，不能拿去做身份判断**。

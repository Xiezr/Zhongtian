## 一、节钺设定（老板：「只有攻打名城才给的那什么节X，列出其设定」）

**它就是「节钺 🪓」**（v89.95 A1 立的经济资源，「黄金买不到」是设计核心）。
全部数值在 `DATA.JIEYUE` 一处，下面是**实测打表**（探针 `probe_v89131_jieyue.js` 全链真调）：

### 1. 获得（两条路，都不是钱）

| 来源 | 数量 | 细节 |
|---|---|---|
| **首次攻占名城** | 县 **1** / 郡 **2** / 州 **3** / 都 **5** 枚 | **幂等**：同一座城只算一次（`jieyueClaim('city:'+id)`，实测重复申领返回 0） |
| **爵位晋升** | 每 **4** 档 +1 枚 | 22 档爵位共可得 **5** 枚（实测 `rank % 4 === 0` 触发） |

- 商城**没有任何黄金入口**（断言钉着：`DATA.ITEMS` 里没有名为"节钺"的商品）——这是刻意设计：
  「有钱也得到战场上挣那枚符」（v89.95 原文），是**发展速度的限制器**。

### 2. 用途（两条，都是"卡脖子"级）

| 用途 | 消耗 | 细节 |
|---|---|---|
| **名世 → 天授**（资质顶档） | **1 枚** | 用「天授果」晋升时自动校验：没节钺 → 链**停在名世**（实测拒绝文案：*节钺不足（需 1 枚，现有 0）—— 节钺只能靠攻占名城与爵位赏赐获得*）；有 → 真扣 1 枚、资质变天授 |
| **城池扩编** | **1 枚 / 次** | 每城建造位 **+1**，**每城至多 2 次**（实测：3→4→5 格，第 3 次被"每城上限 2 次"拦下且**不扣**） |

### 3. 存储与出口

- 存储：`s.jieyue`（枚数）+ `s.jieyueTaken`（防重复领取的键表，随档走）
- 唯一出口组：`jieyueOf`（读）/ `jieyueGrant`（可重复赏）/ `jieyueClaim`（幂等赏）/ `jieyueSpend`（扣）——
  上层不许直接改 `s.jieyue`
- **平衡点的意味**：全链 54 万金打通资质的路被掐断在最后一档（天授），
  一枚符 = 至少要打下 1 座郡城（或打 1 座县城 + 攒 4 档爵位）

### 4. 本次顺手补的界面落点（可见性）

此前**只有**城池面板的「🪓 节钺扩编」按钮悬停里能看到余额与说明——
玩家看不到自己有几枚、从哪来。本轮在 **君主信息面板**（`ui.openLordInfo`）加一行：

```
爵位加成  产+1%…
节钺      🪓 ×3 （攻占名城 / 爵位每 4 档 +1）      ← 悬停 = DATA.JIEYUE.desc 全文
主城      …
```

实机图 `shots/v89131-lord-jieyue.png`；断言 smoke §112⑥。

## 二、将领档案版面（老板：「装备界面没占满、底下留空」）

### 病根（实机量测得来，不是猜）

| 现象 | 根因 |
|---|---|
| 底下留空 | `.gp-body` 有 `align-items: start` → 装备栏**不撑满**（394px vs 六维栏 449px）；且装备栏内部 人形 358px、属性汇总只有 186px → 右下角一大块 **282×171 的空白** |
| 六维排太宽 | 列宽 `0.92fr : 1.08fr`（≈ 45% : 55%） |
| 装备栏显小 | `.doll` 上限 `max-width: 300px`（且实际被列宽压到 282px） |

### 改法（老板口径：1/4 : 3/4，内部 2/4 : 1/4）

| 位置 | 改前 | 改后 |
|---|---|---|
| `.gp-body` 列宽 | 0.92fr : 1.08fr | **1fr : 3fr**（六维/状态 **24.7%** · 装备栏 **74.0%**） |
| `.gp-doll` 内部 | 1fr : 1fr | **2fr : 1fr**（装备图 **66.7%** · 属性汇总 **33.3%**） |
| 人形框 | 282×358（max-width 300） | **400×507**（max-width 400，面积 ×1.78） |
| 方槽 | 54×54 / 图标 22 | **62×62 / 图标 28** |
| 属性汇总列 | 高 186（下缘空 171px） | **撑满 507**（`align-items: stretch` + 按钮组 `margin-top:auto` 钉底） |
| 自由属性点备注 | `升级获得（每级 = 成长值）　点右侧 ＋…` | **撤除**（只留数字） |

**实机复量（13 项全达标，`shot_v89131_pane.js` 自带判定）**：

## 三、精力公式 + 体力精力行 + 回复 + 道具（老板第 3 条）

### 3.1 精力上限 = 六维公式（新）

```
精力上限 = 40 + 统率×0.25 + 勇武×0.25 + 智谋×0.5 + 内政×0.25 + 速度×0.5 + 体力上限×0.03
```

- 唯一来源 `DATA.ENERGY`；出口 `GAME.energyMaxOf`（零件分解 `energyPartsOf` 供悬停与断言，同一份数）
- 权重来由：智谋最高（运筹最耗心力）；速度次之（奔波）；**体力只取 0.03**——
  它是 161~2245 的大数池，权重一大就把其它五维吃满，精力会变成"体力的复制品"

**实测打表**（40 样本/档）：

| 资质 | 精力上限 | 对照：体力上限 |
|---|---|---|
| 开局首将 | **115** | 100 |
| 凡品 Lv60 | 97~107（中位 101） | 161 |
| 良材 Lv100 | 126~137（中位 131） | 309 |
| 英杰 Lv140 | 162~176（中位 169） | 549 |
| 名世 Lv180 | 208~224（中位 214） | 1079 |
| 天授 Lv240 | 279~309（中位 291） | 2245 |

对照消耗侧（远征 5~9 / 计略 8~18 / 游历 6~20）——名将能连轴转、新兵跑两趟就得歇。

### 3.2 回复：现实时间百分比 · 24h 回满（老板口径）

| | 改前 | 改后 |
|---|---|---|
| 口径 | 固定点数 / **游戏**小时（`staPerHour 3` / `enePerHour 2`） | **百分比 / 现实时间**：速率 = 上限 ÷ 86400 /秒 |
| 600× 下体力 | 每现实小时回 1800 点（小池子几十秒满） | **任何倍速都是 24h 一循环** |
| 精力上限 | 回复段硬顶 **100** vs 显示读 `staMax`（**两个口径**） | 统一走 `energyMaxOf` |
| 实机验证 | — | 2.4 现实小时（8640 tick）→ 体 10.00/池 100 · 精 12.00/上限 120 **恰 10%** |

- 体力按"可用池"（`staBaseMax`，装备那份是常备额度）→ 显示值从下限到上限恰 24h
- **实现坑（记档）**：回复必须**直接写 `g.stamina/g.energy`**，不能走 `staNow/setStaNow`——
  那两个出口带 `Math.round`，读-改-写会把每 tick 的零头抹掉（永远涨不上去）

### 3.3 体力/精力行 + 「＋」道具入口（老板：「参考赏赐」）

- 行序改为 **体力 → 精力 → 攻击 → 防御 → 忠诚**（忠诚落最底）
- 两行各带「＋」→ 打开道具选择窗（与赏赐/经验同构：选道具 → 填数量 → 使用；背包空则置灰并提示去商城）
- **精力道具族是新建的（4 档）**：清心丸(20%,12金) / 提神散(40%,24金) / 养神丹(70%,48金) / 凝神玉露(100%,80金)
  —— 见下方"真 bug ①"

## 四、由需求引出的真 bug（3 个）

### ① 悬空引用：四处提示"可服**清心丸**"，而清心丸**不存在**

`battle.js` / `state.js` / `ui.js` 共 4 处"精力不足…可服清心丸"——全仓却**没有这件道具**
（v89.121 抓到的 `item:'chest'` 同族：文案指着一个不存在的出口）。
修：新建 `energy` 族 4 档（清心丸 20% 打头，正是提示点名的那个）。
防回归 smoke §112④（断言"提示引用的道具真实存在"）。

### ② 精力上限"两个口径"（显示 vs 回复）

显示读 `staMax`（几千），回复段硬顶 100 —— 高资质将领的精力条永远"半满"且怎么涨都不到头。
本轮的六维公式一次收口（显示/回复/道具三处同源）。

### ③ 装备栏"底下留空"是两处叠加

不只 `align-items: start`（列不撑满），还有**汇总列自身内容只到 186px**（按钮组往上飘）。
只改一处都不够——实机量测才看得见（Node 桩无布局）。

## 五、诚实缺口 / 待老板定夺

1. **人形框放大后页面会略微滚动**：400×507 的人形框让档案页高约 784px（视图区 789px，
   刚好放得下）；但若将领带"资质晋升"行等长内容会超出 ~40px（视图页允许滚动，§30.3）。
   嫌滚动可在 380~400 之间微调 `max-width`（一处 CSS）。
2. **精力上限的权重是首版**（`DATA.ENERGY.per`）——中位 101（凡品）→291（天授）。
   要更平（都 ~150）或更陡（天授 400+）都只改这一处。
3. **体力/精力回复 24h 是"从 0 到满"**；道具是唯一加速（4 档精力 + 14 档体力）。
   若嫌慢，`DATA.GEN_COST.recoverHours` 一处可调（如 12h）。
4. 节钺余额行进了**君主信息面板**；若想再显眼（如顶栏常驻）请说一声。

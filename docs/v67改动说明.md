## 二、存档系统（本轮主项）

### 2.1 先量，再定设计

设计不能拍脑袋，先跑 `.workbuddy/tools/probe/probe67_save3.js` 量了三件事：

| 指标 | 实测值 |
|---|---|
| 开局档 | **3.8 KB** |
| 中期档（20 城 / 120 将 / 公文堆满） | **115.6 KB** |
| 单次写盘耗时 | **0.8 ms**（20 次采样中位） |
| localStorage 实测配额 | **5.00 MB** |
| → 5MB ÷ 115.6KB | **≈ 43 份**中期档 |
| 唯一会长期增长的字段 | `msgLog`，已有 `MSG_MAX = 800` 封顶（≈51 KB） |

**结论：不上 IndexedDB。** 它异步 + 事务 + 容量大（≥250MB），但这里的量级差两个数量级；
而 localStorage 的**同步**语义正合用 —— 关页 / 切后台要能立刻落盘。

### 2.2 设计：槽位 + 轮换 + 自带校验的导出文本

| 键 | 槽位 | 说明 |
|---|---|---|
| `sanguo_save_v3` | **主档** | 首页「继续上次的游戏」读它；自动存档写它 |
| `…_s1` `…_s2` `…_s3` | **手动槽 ×3** | 玩家自己存/读；可清空 |
| `…_a1` `…_a2` `…_a3` | **自动备份 ×3** | 每次自动存档前 `a3←a2←a1←main` 整体后移 |
| `sanguo_slots_v3` | 索引 | 一个键存**全部槽位摘要** → 打开面板只读一次，不解析主档 |

⭐ **轮换的意义**：单档式最惨的失败模式是"存进去才发现已经坏了，上一份也被覆盖了"。
有 a1~a3 就总有三份可退。

**导出**：一份 JSON 文本，自带说明头 —— `_fmt` / `_ver` / `_exportedAt` / `_slot` /
`_ruler` / `_summary` / `_check`（FNV-1a 32 位校验和）+ `state`。
既能"下载成文件"，也能"整段粘贴"，**同一份东西不需要维护两种格式**。

**导入的校验顺序**（任一不过都明确报哪一步，不给"导入失败"这种没信息量的提示）：
能不能解析 → 是不是本游戏的存档 → 版本对不对 → 内容完整（有城池）→ **校验和**。
目标槽位默认取**第一个空的手动槽**，三个都满就拒绝 —— **绝不覆盖**玩家已有档。

### 2.3 两个"唯一出口"

改造中顺手把两处会分叉的地方收成单一出口（本项目最忌"同一份数据两份实现"）：

- `GAME.savePayload()` —— 序列化（含"派生数据不入档"的瘦身）。`saveGame` 与 `saveTo` 都调它。
- `GAME.adoptState(st)` —— **读档后的全部迁移与后处理**（9213 字符），
  原先整段内联在 `loadGame` 里。现在主档读档与任意槽位读档共用，
  **迁移逻辑不可能只对新档生效**（v53/v60/v64 都栽过这个坑）。

### 2.4 界面

入口两处：**首页**「💾 存档管理」（换台机器导入存档正是从首页开始）与**设置页第一张卡**
（老板规矩：重要功能入口不许放在面板末尾）。

面板 `ui.openSaveManager()`：7 行槽位一屏放完 + 导入区（选文件 / 粘贴文本）。
空槽只给「存入」；有档才出现「读取 / 导出 / 清空」；**读取前有二次确认**并写清
"当前进度会被完整替换"；主档不可删。

**实测三分辨率均不出滚动条**（`.workbuddy/tools/probe/probe67_save_ui.js`）：
1600×950 正文 533/533 · 1440×900 533/533 · 1366×768 524/524。

### 2.5 已知取舍（等老板一句话）

- **换浏览器 / 清缓存仍然会丢** —— 这是 localStorage 的天然边界，导出/导入是唯一的补救。
  真要"跨设备自动同步"就得有后端，与"单机网页游戏"的定位冲突。
- 自动存档仍是 5 分钟一次（`AUTO_SAVE_MS`）。写盘只要 0.8ms，"更频繁"技术上毫无压力，
  但意义不大 —— 要不要改成"关键节点也存"（出征归来 / 攻城得手）等你定。

## 八、本轮踩的坑（已进记忆与技能）

1. ⛔ **内联 `python -c` 里的反斜杠会被 shell 层改**：`'E:\$RECYCLE.BIN'` 实际传进去是
   `E://///.BIN`。**证据**：某份清单里出现 `E:/Deepseekdb\assets\...` 这种混合分隔符 ——
   不是拼接写错，是**命令行文本被改写**。→ 凡涉及路径一律**写 .py 脚本再执行**。
2. **回收站 API 会"抛错但已删"**：`send2trash` 的 modern / legacy 两个接口在本机都抛
   `FileNotFoundError`，可文件其实已经进了回收站（用 `$I` 元数据核实的）。
   → 判据**不能是"接口没抛错"，必须是"删后 `os.path.exists == False`"**；
   并且逐项 `try/except` + 逐项回查，别让一次抛错中断整批（上一版就是这么删到一半停的）。
3. **目录体积要递归算**：`os.path.getsize(目录)` 只给 4KB 的条目大小，
   我把 55MB 的备份目录记成了 28KB。**统计脚本必须 `os.walk` 求和。**
4. **断言名与断言内容都要跟着改**：改名后破坏测试的"注入前校验清单"立刻报"断言不在文件里"
   —— 这道自检救了场（否则会得出"零反应"的错误结论）。
5. **"名字骗人"的断言**：smoke 里那条写着「面板 7 行槽位」，实际只查了 `.sv-row` 样式类在不在。
   破坏测试注入 `list.slice(0,6)` 时**零反应** → 改成查"渲染源是 `list.map(...)` 全量、
   且不含 `.slice(`"。**这条是这轮最有价值的发现**：断言没守住时，先怀疑断言。

# v98.6 「世界是空的」—— 一次长跑探针挖出的根因

## 怎么发现的

前面几版一直在加系统，门禁一直全绿。这轮换了个办法：写一个**长跑探针**
（`_sim_run.js`，不进版本库），新开一局跑 240 个游戏月，每月打一张表看趋势。

第一张表就打脸了：

```
第 240 月 · 城 1 · 人 246 · 兵 0 · ... · 竞争者 0/0人 · 村社 0(被占0)
```

**20 年过去，村社 0 处、遗迹 0 处、竞争者 0 支。** 而前面五版做的
rival / village / ruin / faction / land / taint / climate / surge / expose
全都在"跑"，只是跑在一个**空球**上。

## 根因：双球面 + `||` 的假兜底

本项目是双球面：
- `GAME.sphere` —— 逻辑球面（城所在星球），**开局就有 cells**
- `GAME.mapSphere` —— 地图球面（渲染），`makeSphere()` 造出来时**没有 cells**，
  要等 map3d 第一次渲染才 build

而九个模块全都写：

```js
function SP() { return GAME.mapSphere || GAME.sphere; }
```

`mapSphere` **对象存在**（所以 `||` 不走到兜底），但它没有 `cells` ——
于是每个模块的 `if (!s || !s.cells) return []` 直接返回空。
**这就是"世界是空的"，而且没有任何报错。**

## 修法：复用既有的 `GAME.sphereOf()`

`state.js` 里本来就有 `GAME.sphereOf(pid)`（按星球 id 取那颗球的球面，
默认当前星球 → 返回**有 cells** 的 `GAME.sphere`）。九个模块统一改走它：

```js
function SP() { return GAME.sphereOf ? GAME.sphereOf() : (GAME.mapSphere || GAME.sphere); }
```

⚠️ 中途踩了一个坑：我先在 `sphere.js` 里**又定义了一次** `GAME.sphereOf`
（同名不同义），直接把既有的"按 pid 取球面"覆盖掉 —— audit 的"重复定义"
计数从 0 变 1 当场照出。**加出口前先 grep 这个名字。**

## 附带修好：污染会把每个玩家压死

长跑表里还有一行：`污染 478`。一座小城什么都没做，20 年涨到 478
（变质线是 120）。算一下：`每级 0.15 × 建筑总等级 − 衰减 2`，
**建筑总等级超过 14 的城永远不会自净** —— 而任何正常城都超过 14 级。

改成 `0.08 / 3.2`，平衡点放到 40 级（约 10 座四级建筑）：
小城自净（−1.6/月），大工业城才涨（+3.2/月）。

## 附带：18 处断言用的球面也统一了

修完模块后 smoke 有 4 条红，全是"村社在水上 / 竞争者在湖里"。
根因是**双球面的 ci 不通用**：模块用 `G.sphere`、断言用 `G.mapSphere`，
两套索引查同一批数字 → 全错位。断言也统一走 `sphereOf()` 之后归零。

## 修完之后的世界（240 个月长跑）

```
第 240 月 · 城 1 · 人 246 · 竞争者 5/5133人 · 村社 133(被占 39) · 污染 0
竞争者明细：灰烬车队(1213 moved129) · 铁鸦拾荒团(1267 moved239) · ...
```

五支人在废土上走了几百格、抢掉 39 处村子（142 → 133，被抢空的会消失）。
这才是"你不是唯一在重建的人"。

# v99 兵源：人从哪来（老板「兵种代价从控制来源，强化出路」）

## 原来错在哪

「造兵贵不贵」根本不是问题 —— **"人"不是稀缺品**：

```
popGrowthOf = 有效上限 ÷ fillHours，而 fillHours = 2（现实小时）
```

人口两小时自动补满。于是：
- 遗迹里"收容幸存者 600 人" → 两小时后你自己也长出来了，白拿
- 战后俘虏收编 → 一样
- "打完仗缺人"这件事，在日历上只是"等两小时"

**这就是提案开篇那个病根「最优解永远是带满最强」的真正来源。**

**一、自然增长慢 7 倍**：`fillHours: 2 → 14`。
打光一支军队要"重新长人"要小半天，不能再靠等。

实际数字（新开局那座城）：上限 1400，增速 **700/小时 → 100/小时**。

**二、补上"从外面拿人"的路**（`js/muster.js`）

|---|---|---|
| 遗迹「收容幸存者」 | 已有（v92.7） | 花粮 |
| 战后逃生者 | 打赢后按敌军损失 3% 来投（上限 400） | 免费，量小 |

| **远征救出** | 地下第 3 层起，越深越多（40~160 人） | 要下去，可能折人 |

**三、面板「🚶 人从哪来」**（玩法台最前）
显示：门外有多少流民（接纳/赶走）、自然补员速度与"还差几小时长满"、最近六个月的人从哪来。

# v101 危险梯度（构想 A5 —— 复核里唯一真缺的一项）

提案原话：「**危险梯度**：迷雾边缘最危险，越往中心越安全」。

之前 `sphere.report()` 里有个 `danger` 数字，但那是**星球的属性**，
跟"你去哪儿"没关系 —— 去门口打野地和去三十格外的废墟，战损一样。
于是"往外推"是纯赚（远处的东西更肥），没有对应的疼。

## 怎么算

```
危险度 = 探明度基础值 + 离家距离
  探明度 0（未探明）/ 1（只见地形）/ 2（全见） → 0.55 / 0.30 / 0.10
  离家距离 = min(0.45, 距离 / 40)
```

| 位置 | 危险度 | 档位 |
|---|---|---|
| 自家城下（全见） | 0.10 | 熟地 |
| 刚探过地形的地方 | 0.30~0.45 | 生疏 |
| 深在迷雾里、离谁都远 | 1.00 | 险地 |

## 它影响什么

**只削攻方生命**，最多 −12%（`DATA.RISK.hpAtFull`）。
不减战利品、不减收益 —— 远处仍然更肥，只是更疼。

这条边界是刻意的：**危险梯度是"有点疼"，不是"不让你去"**。
真正劝退的应该是守军，不是地形。上限压到 12% 就是为了这个。

## 接线（守住 v98.5 定的规矩）

战场加成只有 `goalMod` 一条通道。危险度也是折进 `goalMod.hp`：

```
battle.js  出征瞬间算好 riskHp（存进 simOpts —— 观战重放/读档重跑同源）
   ↓
tactic.js  if (opts.riskHp) goalMod.hp += opts.riskHp
   ↓
unitsOf()  落到每个单位的 hpPer
```

和作战档位、指令牌、老兵走的是同一条路，所以战报里的数字永远只有一份。

## 界面

注册表 order 15（紧跟「人从哪来」之后：**出门前先看这一带危不危险**）：

> ⚠ 危险梯度　家门口 10%（熟地）· 往外 37 格 100%（险地）
> 越往没探过的地方走，伤得越重（最多 −12% 生命）。它只削你的血，不减你抢到的东西。

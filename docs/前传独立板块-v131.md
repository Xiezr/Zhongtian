## 一、根治了什么

### 改前（v130）的荒唐事


就能看到一座完整的城。v128 把地图露出来之后，这个矛盾变成一眼可见。

## 二、独立板块的设计

前传现在是**君主作为个人冒险者**在地图上走，复用的全是现场资产：

| 要素 | 复用的是什么 | 有没有新写一套判定 |
|---|---|---|
| 大地图 | `sphere.adj` 邻接表 + `hopsWithin(ci,1)` 取六邻 | 否 |
| 地块探索 | `jianghuActsAt(ci)`（荒野行动的唯一判据口） | 否 |
| 斗将 / 战斗 | `P.act → jianghuCheck / Spend / Roll`（与正式阶段同一内核） | 否 |
| 立城 | `makeCity` + `attachRes` + `attachGold` + `fog.revealOwned` | 否 |

### 交互：一步一格

```
📍 你站在这里 · 草原        ← 君主脚下这一格的地形
   [清剿] [采集] [拜访]      ← 这格能做的事（由 jianghuActsAt 给）
四周（点一格走过去 · 每步耗 1 精力）
   [北 草原] [东北 湖泊·] [东 湖泊·] [东南 草原] [西南 湖泊·] [西 草原]
```

- 走一步：`P.moveTo(ci)` —— 只判两件事（是否相邻、精力够不够），**不掷骰**
- 走到哪看到哪：`fog.revealAround(pos, 2)`，视野跟着人走
- 方位按球面经纬差算八向并排序（北→东北→东…），玩家才知道"往哪走"

### 出生点的处理

`jianghuActsAt` 对每格有 **30%** 概率返回空（`DATA.JH_SPREAD.noneP`）——那是"地块探索"该有的
不确定性。但**第一格**不能是空的：玩家一睁眼看到"脚下没事、四周没动静"，只会以为自己玩不了。
所以 `P.begin` 里若出生格没事，就**就近挪**到 2 环（找不到再 4 环）内有事的格。
只挪出生点、不改判据 —— 荒僻格仍然是荒僻格，走两步就能遇到。

## 三、修掉的四个真 bug（都是在实跑中撞出来的）

### ① 每走一步都会弹出「世界的账本」（极隐蔽）

```
openWorldPanel ← Object.refresh ← prologue-move
```

前传动作的 handler 用了 `ctx.refresh()`。而 `ctx` 是派发方临时拼的对象，
"世界的账本"面板把自己的 `refresh: function () { ui.openWorldPanel(); ... }` 塞进了**同一个名字**。
于是走一步就把账本弹出来、盖住整个 HUD。

修法：handler 里改成直接调 `GAME.refreshAll()`，**不依赖 ctx 的来源**。

### ② 立城后旧币池是 0 → 研究科技报「资源不足」

`newGame` 里有一句 `attachGold(state, {keepCityGold:true})`，把开盘旧币从城里上收进 `s.gold`（玩家池）。
前传局没有城 → 那一步收到 0；立城时我把随身物资（含 87 万旧币）搬进了 `city.res.gold`，
却**没有重新上收** → `goldOf()` 恒为 0。

实测对照：

| | `cityRes.gold` | `goldOf()` | 研究科技 |
|---|---|---|---|
| 正常开局 | 874,934 | 874,934 | ✅ 开始研究 |
| 前传立城（修前） | 874,951 | **0** | ❌ 资源不足 |
| 前传立城（修后） | 874,951 | 874,949 | ✅ 开始研究 |

修法：立城流程补齐 `attachGold` —— **立城 = 一次"新局初始化"**，newGame 干过的收尾都要干一遍。

### ③ 球面全黑（玩家看不见自己站在哪）

两处叠加：
- v128 那行点亮视野用的是 `currentCity().ci`，现在没有城 → `fromCi = 0` → 点亮的是球面另一头；
- 相机停在整星总览（`dist = R*8`），radius 4 的视野在整颗球上就是一个小点。

修法：点亮用 `P.pos()`；位置一变就 `setZoom(0.02) + centerOn(x,y)`，**镜头跟着人**。

### ④ 无城时写 `s.res = {...}` 被静默吞掉

`attachRes` 的 setter 原来是 `if (c && v) c.res = v` —— 无城时整个赋值无声失败。
读档迁移 / 工具造局 / 测试注入都会踩。改成三层兜底：有城写城 · 前传期写随身物资 · 都没有写内存孤儿池。

## 五、这轮我自己的教训

1. **`ctx.refresh` 不可信** —— 派发方拼的上下文对象可能被别的面板覆盖。动作 handler 应该调明确出口。
2. **"立城"不只是"加一座城"** —— 它等于一次新局初始化：资源、旧币池、迷雾、将领归属、`ui._cityId`
   一个都不能漏。我第一版只加了 `cities.push` + `attachRes`，旧币池漏了，被 e2e 当场照出。
3. **阈值不要绑死在一个位置上** —— `distOf ≤ 20` 这条，出生点一挪就变 21。判据要跟"规模"挂钩
   （O(环内格数)），不是跟"某次实测值"挂钩。
4. **e2e 的红项要先证明是不是自己引入的** —— 我用 `git stash` 跑了基线（1101/0），
   确认 3 条红全是我的，才有资格往下查。否则很容易把"本来就坏"当成"我改坏了"。

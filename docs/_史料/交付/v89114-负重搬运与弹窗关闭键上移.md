### 1.3 标定复核（`probe_v89114_load.js` 实测）

各档位**库藏重量** vs "打赢所需兵力规模"的纯战兵载重（load 中位 40~60）：

| 目标 | 库藏重 | 需兵≈ | 纯战兵载重 | 覆盖率 | 想全搬需要 |
|---|---:|---:|---:|---:|---|
| 野地 Lv5 | 56.9万 | 小 | — | — | 几乎总能全搬 |
| 据点 Lv5 | 62.7万 | 0.6万 | 25.5万 | 40.6% | 民夫 0.3 万 / 车 126 辆（改前值） |
| 据点 Lv8 | 624.6万 | 4.7万 | 188.7万 | 30.2% | — |
| 据点 Lv10 | 2913.6万 | 17.9万 | 717.5万 | 24.6% | **车 ~1457 辆（新标定 2 万/辆）** |
| 县城 | 39263万 | 40万 | 1600万 | 4.1% | 车 ~1830 辆 |

**结论**：纯战兵编队能搬走同级战利品约 **1/4~1/3**；**编入约 1% 的辎重车（或 5% 民夫）即可全数搬回**
——"带不带后勤"从一句空话变成一道真题。

### 1.5 唯一出口（防"两处各算一份"）

```
battle.survivedArmyOf(sentArmy, result)   ← 幸存编制（returnArmy 与搬运共用）
battle.haulCapOf({army, result, cargo})   ← 搬运上限 = 载重 − 去程辎重
battle.lootWeightOf(loot)                 ← 战利品重量（与 cargoLoadOf 同口径）
battle.haulPlanOf({army, result, cargo, loot})  ← 一次搬运的账（纯函数）
battle.lootEstOf(target, mul)             ← 期望口径（genLootEx 同一公式、不掷骰不落账）
```

`genLoot` 重构为 `genLootEx(c, extMul, rnd, dry)`（随机源与落账开关显式化），
`genLoot` 成为其薄封装——**面板估算与结算永远同一份公式**。

## 3. 需求 3：关闭键统一右上角（圆形套叉）

| | 改前 | 改后 |
|---|---|---|
| 位置 | 底部（`.modal-foot` / `.m-foot` / `.bldg-foot` / `.panel-foot`，**97 处**） | **右上角 `.modal-x`**（28px 圆形描边 + `✕`，悬停转红） |
| 生成方式 | 各处手写 | **`ui.openModal` 统一注入**（全站一个样） |
| 存量关闭键 | 各写各的 | `ui.stripFootClose` **统一剥离** + 剥空的底栏一并撤除 |
| 动作键 | — | **原样保留**（升级 / 拆除 / 提速 / 确定 / 完成…） |
| `noClose` 流程 | 底部也不补 | 连右上角也不给（必选流程无法绕过） |

**设计取舍（重要）**：存量 97 处底部关闭键的 HTML **留在原处**，由 `openModal` 在运行时统一剥离——
不逐条从源码里删（**删必漏、且未来新弹窗一定会再写回来**；统一剥离才是"一个出口删干净"）。
新代码**不必也不该**再写底部关闭键。

**特殊文案的处置**：

| 原按钮 | 处置 |
|---|---|
| 「后台运行」（战场界面，与"完成回合/自动战斗/撤退"并列） | 剥离；在面板副标题写明 **"右上角 ✕ 转后台，战斗继续进行"**（信息不丢） |
| 「继续施工」「稍后再说」「知道了」「合上册子」「取消」 | 统一剥离，语义由右上角 ✕ 承担 |

**× 挂在滚动容器之外**：`.inner-panel` 是 `overflow-y:auto` 的滚动容器，
× 挂在 `.modal` 直属子节点上——内容再长也不会把它滚走。

## 6. 诚实缺口 / 请老板定夺

1. **高级目标的"搬不完"**：Lv10 据点掠夺 2914 万，纯战兵编队只能搬 ~1/4；
   全搬需 ~1457 辆辎重车（≈ 编制 0.8%、一次性成本 ~530 万资源，可复用）。
   —— 这是**有意**的设计（"带不带后勤"是真题），但若老板希望"打得起就自动搬得回"，
   只需把辎重车载重再上调一档（`data.js` 一处）。
2. **名城（县城/郡/州/帝都）量级过巨**：县城一次掠夺 3.9 亿，即便 1830 辆车也只能搬走约 1/4；
   是否需要给名城单独口径（或对名城掠夺做"分批/多次取"机制），请老板定夺。
3. **敌方掠夺我方（`invasionResolve`）未接入运力口径**：保留 v89.109 的损失曲线
   （敌军搬不搬得走不影响我方损失的现有手感）。要接入是一句话的事，但会改动被掠损失的量级。
4. **`stripFootClose` 的边界**：只认四个底栏类名（`modal-foot/m-foot/bldg-foot/panel-foot`）；
   若将来出现第五种底栏容器，需同步加入名单（已加断言覆盖四种）。
5. 历史缺口延续：屏高 ≤768px 时个别超高弹窗仍靠浏览器物理滚动兜底（未在本轮范围内）。

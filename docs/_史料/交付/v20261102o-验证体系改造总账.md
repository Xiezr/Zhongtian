## ✅ P0-1 断言分档（完成）

实现类打 `⚠️ 待修`（不阻断），其余打 `❌`（阻断）。

| 类型 | 条数 | 占比 |

| 剩下 ❌ | 降级 ⚠️ |
|---|---|
| 出生州：落点归属 | 间距（裸 5px） |

## ⚠️ P1 按模块跑：清单能用，"只跑相关段"做不到

**做成的部分**：`gen_seg_modules.js` 按符号表反查"段 → 它直接调用的文件"，`smoke_touching.js` 能列出清单：

```
涉及 js/ui-space.js 的段 8 个 / 断言 111 条
  # 37  34 条  v24 界面与队列
  #190  49 条  v89.190（按钮瘦身 · 自动征兵 · 遗留清账）
  #265   4 条  v91.30 星系界面   …
```

**做不到的部分**：真的只跑那 8 段会崩，两个实证：

1. **缺前置状态**：段 #37 直接调 `ui.mapHTML()`，它读 `GAME.state` —— 全量时前面的段早开过局了，
   切片后没有 → `TypeError`。补一次标准 `newGame` 也救不了所有段（各段要的世界状态不同）。
2. **段嵌在不同作用域里**：段 #266 在原文件里是包在某个 IIFE 内的，平铺出来 → `ReferenceError: check is not defined`。

所以"按需跳段"要成立，得让**每段自给自足**（各自 newGame + fixture），那是 4 万行改造。
**结论：清单用来"知道该重点看什么"，跑还是跑分片全量（222 秒）。**

## ❌ P2 退役过时断言：没有可退役的批量

原计划"退役 849 条读源码的实现断言，2~3 天"。实际统计：

```

  仍有存活符号引用（还在保护现有实现）：1002 条
```

而那 65 条的标题是：

```

"统计页已退役（statsHTML / lgSec / lgRow / stats-goto 均不在册）"
```

**它们不是过时，是"零残留守卫"** —— 故意查"这东西不存在"，防止旧设计被改回来。
删掉它们，等于给回退开门。

**P2 结论：无可退役批量。** 我上一轮那个"2~3 天、849 条"是没测量的估数，作废。

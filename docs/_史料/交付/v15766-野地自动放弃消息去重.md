# v157.66 · 野地自动放弃「重复消息」修复

> 老板 2026-11-15：「📌 系统🏚️ 1 块野地等级归零超 1 日，已自动放弃（驻军/采集已返回）——重复消息」

## 一、结论

**是真 bug，且与 v157.62 辐射云消息重复同构**：不是 `GAME.log` 写得不对，而是**自动放弃本身失败了**，导致每个在线 tick 都把同一块野地重新判定为「该放弃」并重发公告。

## 二、根因（探针实测，非推断）

诊断脚本：`.workbuddy/tmp/probe_wild_abandon.js`（只载 `bundle-core.js` + 最小 state，实时打点）。

| 场景 | 修复前实测 |
|---|---|
| 同星球野地（`pid` 缺省） | 第 1 轮野地移除、公告 1 条；后续轮不再发 ✅ |
| **跨星球野地**（`w.pid=2`，当前星球 `curPid()=1`） | 野地**永远删不掉**（每轮 `wilds剩余=1`），每轮都重发 |
| 跨星球 + 每轮插入一条干扰日志 | **3 轮 = 3 条独立 🏚️ 消息** ← 老板看到的刷屏 |

链条：

1. `js/domain.js` `GAME.decayWilds()` 把 `level<=0 && zeroDay` 超期的野地收进 `toAbandon`；
2. 对每块调 `GAME.doAbandonWild(w.ci)` —— **不传 pid**；
3. `doAbandonWild` 内部用 `GAME.map.wildAt(ci)` 定位，而 `wildAt` 自 v91.74 起按 `(ci, pid)` 匹配、`pid` 默认取 `GAME.curPid()`；
4. 野地 `pid` 与当前星球不一致（切过星球 / 老档 pid 字段异常）→ `wildAt` 落空 → `doAbandonWild` 返回 `{ok:false}` → **不移除 `s.wilds`，也不清 `zeroDay`**；
5. 于是下一个在线 tick（`state.js:4626` 每秒调 `decayWilds`）又把它收进 `toAbandon`、又调一次、又 `GAME.log` 一条；
6. `GAME.log` 的 v129 合并只合并「**连续** + 同文案 + 同类别 + 1 游戏天窗口内」的重复，主循环里必然夹着建造/采集/战斗等别的日志 → 合并条件被打破 → 逐条堆积。

附带风险（同根）：`doAbandonWild` 原本 `s.wilds.filter(z => z.ci !== ci)` **只按 ci 过滤**，而 v91.74 起各星球 ci 会重号 —— 跨星球时会误删当前星球上同 ci 的另一块野地。

## 三、改法（全部只在 `js/domain.js`，未动门禁工具/其它模块）

1. **`doAbandonWild(ci, pid)`**：新增第二参数，`wildAt(ci, pid)` 按野地归属星球定位。不传 `pid` 时 `wildAt` 仍默认 `curPid()` —— 与 `main.js` / `ui-*` 的手动放弃调用点**逐字等价**，零回归。
2. **精确移除**：`filter` 改为按 `(ci, pid)` 匹配，避免跨星球 ci 重号误删。
3. **公告去重**：`decayWilds` 传 `GAME.pidOf(w)`；只对 `doAbandonWild` 返回 `ok:true` 的地块计数 `abandoned++`，`if (abandoned)` 才发一条；放弃失败的地块打 `w._abandonSkip = true`，不再每 tick 重试/重报（异常态静默）。

> 口径与 v157.62 一致：**该发生的事照常发生（该放弃的野地照样放弃、驻军采集照常返回），只是别反复刷系统消息**；这里更进一步把「放弃不了」这个真 bug 一并修掉。

- 新增 **§586h** 三层守卫：① 源码面（pid 定位 / 精确 filter / 只按成功数公告 / 失败跳过 / 不得再出现 `if (toAbandon.length)`）；② 运行面-跨星球（干扰日志插队后连跑 3 轮仍只 1 条 🏚️ 且野地被移除）；③ 运行面-同星球（正常路径不回归）。

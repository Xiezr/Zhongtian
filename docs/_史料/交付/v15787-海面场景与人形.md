## 一、海面场景（水域格 `lake`）

### 选型：全部是成熟做法，没有一处自创

| 环节 | 做法 | 为什么是成熟方案 |
|---|---|---|
| 相机 | 透视 + 第三人称环绕（拖拽转、滚轮远近、WASD 相机相对） | 舰游/开放世界通用控制；正交俯视是"看棋盘"，读不出海有多大 |
| 波浪 | 三重正弦涌浪（**顶点位移**）+ 高频细节波（**片元法线**） | three.js Water 与各家海洋 demo 的标准分工：几何只承担采得动的大浪，小浪交给法线 |
| 水面 | Schlick 菲涅尔（F0=0.02）+ 天空解析反射 + 太阳镜面（窄高光 + 宽光带） | 这就是水面 BRDF 的教科书写法 |
| 地平线 | 天空底部、雾、水面远景**同一个颜色**（`SEA.HORIZON`） | 接缝消失的唯一办法是"两边算出来同一个值" |
| 尺度 | 海面 3 km（跟人平移 = 无限海）、远景军舰按真实舰长拼 | 舰长是真值：驱逐 118 m / 巡洋 182 m / 战列 246 m |

### 一条硬约束（写进代码注释）

**GPU 的顶点位移与 CPU 的站立高度必须是同一个函数。**
`seaWaveY`（JS）与 `seaWaveGlsl`（GLSL）都由同一张 `SEA_W` 表生成 —— 改海况只改那张表。
分开写两套，人就会在浪里沉浮/踩空，而且这种偏差只能靠肉眼才看得出来。

### 场景内容

- **海**：3 km 网格（240×240，12.5 米一格），随人平移并按格对齐（不对齐的话水纹会随相机"游"）。
- **天空**：4200 半径穹顶，渐变 + 太阳盘 + 太阳辉光；跟人平移、不旋转（太阳方向才钉在世界里）。
- **军舰**：3 艘（巡洋 720 m / 驱逐 900 m / 战列 1250 m），极慢前进 + 随浪起伏 + 烟囱冒烟。
- **浮物**：浮筏（钓点）、油桶、木箱、芦苇丛、礁石 —— 全部随浪起伏并顺浪面倾斜。
- **人**：站在浪上，走动时脚下起涟漪。

### 交互没动

`lake_scene`（垂钓）/ `cai`（摸芦苇）/ `xiu`（礁石静坐）三个动作、账本、`jianghuActsAt` 的门槛判定全部原样；
场景 id 仍是 `lake`（`S.pickFor('lake_scene','lake') === 'lake'` 的断言照旧通过）。
旧配置里的 `water: true`（地上一块 30×26 的水面板）撤掉了 —— 海面是场景自带的一整片海。

## 二、人：为什么不用现成的 Soldier.glb

**实测结论：那个资产渲染不出人形。**

隔离取证（关掉海面与天空、灰底、只留玩家）：屏幕上只有**几片碎三角形的残骸**；把 clip 停掉也一样。
`js/gltf.js` 自己的注释写着"绑定姿态空间 0.003 单位 / 骨骼空间 1.5 单位，差三个数量级"，
`js/duel3d.js` 也因此长期把 `CLIP_ON = false`。

所以这一版换成**程序化人形**（基本体 + 分层关节）：

```
髋 → 躯干 → 头 / 肩 → 上臂 → 前臂
髋 → 大腿 → 膝 → 小腿 → 靴
```

- 总高 1.74 m（腿 0.90 / 躯干 0.55 / 头 0.24），有帽子、护目镜、背包、胸口的辐能核心。
- 步态 `personAnim`：腿摆 + 膝弯 + 手臂反相 + 髋部起伏 + 躯干前倾扭转。
- 是这套代码里**唯一**的玩家模型来源（`buildPlayer` 里那条异步 gltf 分支整条删除）。

## 三、地面更精细化（所有陆上场景）

三件事，都是标准做法：

1. **法线贴图**（`groundNormalTex`）：多倍频值噪声 → 高度图 → Sobel 求梯度 → RGB 编码；
   取样按环绕取模（`% N`），所以可无缝平铺。256²，每种地面生成一次。
2. **细分 48×48 → 96×96**：0.83 米一个顶点 → 0.42 米，配合法线贴图，坡度与明暗过渡连续。
   再叠一层 3 米级、幅度 2 cm 的微起伏（只够给法线贴图"几何支撑"，不影响行走与碰撞）。
3. **散落物 34 个 Mesh → 2 个 InstancedMesh**（190 块碎石 + 150 丛草）：
   一次 draw 画几百个，**数量翻了 10 倍，开销反而更低**。

顺带修掉一处配色错误：碎石原来用 `C.steel`（亮蓝灰的钢），在土色地面上是一地**蓝色纸屑**，
改成石头色 `0x6a6358`。

## 五、踩过的坑

1. **"人不见了"** —— 换了三张隔离截图才定位：Soldier 蒙皮坏了，渲染出来是碎片，
   而且在 12 m 外的相机里根本不构成人形。**不是位置错、不是材质透明，是资产本身画不出人。**
2. **涟漪像泳圈** —— 第一版扩到 6.5 倍、不透明度 0.42，一圈圈套在脚下；
   收到 3.6 倍 / 0.20 的二次衰减才只是"水被踩动的暗示"。
3. **太阳反光是一块白斑** —— 宽光带系数 0.20 + 幂 64 太大，像探照灯；
   收到 110 次幂 / 0.07，另加近景噪声斜率做"碎金"（真实海面是无数小面在闪，不是一整块渐变）。
4. **海面像灯芯绒** —— 3 组细节波方向固定，法线干涉成一排平行斜纹；
   加到 6 组不同方向 + 用大尺度噪声调制细节强度，才散开。
5. **雾太厚** —— 0.00062 时军舰只剩一团灰；0.00046 才既在雾里又读得出轮廓。
6. **夜间取证误判** —— 第一次跑的陆上截图整片发黑，以为是法线贴图把光照搞坏了；
   读数才发现主光强度 0.55 = `PHASES.night`：**新局的世界时钟落在夜里**。
   取证脚本现在固定 `st.world.elapsed = 12*3600`。
7. **改文件脚本漏参数空跑** —— 一个 `rep()` 少写 tag 参数，脚本抛异常没写盘，
   后面的 build/probe 全跑在旧代码上（还"通过"了）。**验收要看产物 hash 变没变**。

## 九、诚实说明

1. **军舰是"基本体拼的剪影"**：舰长/舰宽/干舷按真值给，上层建筑、烟囱、桅杆、炮塔都有，
   但没有栏杆、舷窗、涂装细节 —— 720 米外看是军舰，拉到 100 米看是积木。
2. **人是"低模人形"**：关节是真的会转，但没有手指、没有面部、没有布料。
   能读成"一个人在海面上走"，不是照片级。
3. **水下没有体积**：海面是一层网格，没有折射/水下雾，人站在水上而不是涉进水里。
   要做"涉水"，得再写一层水下渲染与深度混合 —— 属于下一轮的量。
4. **地面精细化在陆上场景的可见度有限**：陆上相机是 18 米高、46° 俯视的全景机位，
   细节主要体现在贴近墙壁/碎石时；海面场景是人身高视角，所以那儿的"精细"最直观。
5. **时间只有白天/夜晚两档配色可用**：天空/海水的颜色跟着 `applyPhase` 的 tint 走，
   夜里会一起暗下去，但月亮、星光、夜间海面反光没有单独做。

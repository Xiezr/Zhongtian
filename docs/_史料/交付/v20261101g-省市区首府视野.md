# 占领省/市/区首府 → 看到该行政区下辖地的视野（v156.24）

> 老板原话：「占领省市区首府，可以看到该省市区下辖地的视野」
> 结论：**打下行政中心城，该行政区下辖的每一格立刻全明** —— 省府给全省、市府给全市、区给本区。

---

## 一、先辨口径：仓库里有**两套**"省市区"，做错了就是白做

| | A 套：`DATA.NPC_CITIES.state` | B 套：`map3d._settle`（**本次采用**） |
|---|---|---|
| 名字 | 13 个"州"（霜脊/沉陆/烬环…） | 省 → 市 → 区（三级） |
| 来源 | 母星**出生区**常量表 | `genSettlements()` 按球面 kmeans 生成 |
| 城 | 首府(zhou)/重镇(jun)/聚落(county) | 行政中心城 `M.admCities`，带 `admLevel` |
| UI | 创建界面「城市归属」 | **地图检索栏「选择行省 / 选择城市 / 选择区」** |
| 能占吗 | 能（在 `state.map.cities`） | 能（`map3d.js:126`：`kind==='adm' → ui.openAttackModal(ref)`） |

**判定依据**：老板说的是"省市区"，而地图 UI 上逐字就是这三个下拉，数据源是 B 套 → 采用 B 套。
A 套那一版（已写、已测）**整块撤除**，不留双轨 —— 一套需求只留一套语义。

## 二、实现（4 处，各司其职）

| 文件 | 改动 |
|---|---|
| `js/map.js` | 新增 `adminFields()` / `adminCisOf(fields,level,index)`（**纯函数**）/ `adminCiList()` / `adminOf(ci)` |
| `js/fog.js` | 新增 `F.revealAdmin(level, index)` —— 把该行政区所有格升到 `ALL`（全明） |
| `js/battle.js` | `GAME.onConquer` 里挂钩：`npcCity.admLevel` 存在 → `revealAdmin`；并让新城**保留 `admLevel/admIndex`** |
| `js/map3d.js` | 已占的行政中心不再画成紫色敌方城（否则同格叠两座模型） |

### 为什么门槛是 `admLevel` 而不是 `type`
`type` 是**档位**（zhou/jun/county，决定等级与岁贡），`admLevel` 是**"这是哪一级行政中心"**。
两者取值相近但语义不同：拿 `type` 判，玩家打下一座 **zhou 档的普通名城**（它不是任何省的中心）
也会误点亮一整省。

### 为什么"首府 = 下辖地视野"讲得通
首府是建制的神经中枢 —— 驿传、户籍、田册、山川图志都在那儿。打下它，接手的不只是城墙，
还有**它管辖的那片地**。与既有规则的分工也清楚：
- 普通城仍按 `radiusOf()` 点亮身边几格（探索度换视野）；
- 首府给的是**辖地**，不随探索度缩放 —— 不是"探得更远"，是"接手了一张图"。

### 不褪色，且读档还在
`revealAdmin` 的点亮挂在 `F.revealOwned()` 里（不只是占领那一下）：
- `fog` 包读档后是重建的 → 只在占领时点亮，一出游戏就丢；
- `F.decay()`（迷雾长回来）会把全明褪成半明再调 `revealOwned` —— 辖地属"建制内"，
  和自家城周围同款待遇，**不淡忘**。

## 五、诚实缺口

1. **未做真机观感确认**：以上截图都是 swiftshader 软渲染。最终"揭晓范围看着够不够爽"
   需要老板在本机看一眼（尤其区块边界呈锯齿六边形 —— 那是格子系统的固有形态）。
2. **不写"已占省府"的存档标记**：判据是"我方城市里有同 `admLevel+admIndex` 的城"，
   靠 `onConquer` 里显式写 `newCity.admLevel/admIndex` 维持。若将来有别的路径产出
   "直辖行政中心"（比如和谈割让），那条路径也必须带上这两个字段，否则视野会漏。
3. **行政中心城不进 `state.map.cities`**：这是既有设计（它们由 `_settle` 现算）。
   占下来后靠"己方城"覆盖同格显示，因此**地图上不会多出一座新城图标**，只是紫转蓝。
   若要在城市列表里单独标出"某某府"，需要另开一轮改 UI。
4. **只覆盖"首府 → 下辖地"**：没有做"占任一城取得该区部分视野"。老板要的是首府，就只做首府。

## 七、老存档的回补边界（诚实说明）

判据是"我方城市里存在同 `admLevel + admIndex` 的城"。**本次改动之前**占领的行政中心，
存档里那座城没有这两个字段（旧代码不写）→ 读档后**不会**自动补点亮。
可在游戏内再占一座同级首府，或后续写一次一次性迁移（读 `_settle` 反查旧城格）。
本轮未做迁移：`_settle` 依赖当前星球与渲染初始化，在"存档迁移"这种无渲染场合
反查不可靠，硬做容易把城归到错的省 —— 宁可缺，不要错。

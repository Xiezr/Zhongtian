## 一、城堡朝向：根因（一句话）

**对齐法线之后，绕"世界法线"右乘了一次随机转身。**

```js
// 错（v156.18 及以前）
q.setFromUnitVectors(up, nn);
qr.setFromAxisAngle(nn, rand);   // ← 轴用了世界法线
q.multiply(qr);                  //   右乘 = 先转 qr 再转 q
```

四元数右乘是"先在物体自己的坐标系里转"。绕**世界法线**转，等于先把物体的上轴
从法线上掰开一个大角，再用 q 把它"拉回"法线 —— 每座城因此被随机歪 0~90°。

**实测证据**（`js/map3d.js` 里同一段算式的页面复现）：

| 城 | 位置方向（径向） | 存储的"上轴" | 点积 | 偏离 |
|---|---|---|---|---|
| #1 | (−0.415, 0.291, 0.862) | (−0.681, 0.261, 0.684) | 0.9485 | **18.6°** |
| #2 | — | — | −0.7904 | **142°（几乎倒扣）** |

修复后同一批实例点积全部 = **1.0000000**（float32 精度内），基座严格 ⟂ 半径。

## 二、坐标系（唯一口径，写进 `js/map3d.js` 顶部注释）

```
【世界系】原点 = 球心；+Y = 北极；经度 0° = +X；东 = −Z
          （icoSpheres 末尾翻 z 做经度镜像 → 北极朝上时东才落屏幕右侧）
【格局部系（右手）】+X = 东、+Y = 径向（朝天）、+Z = 南
          → 3D 资产必须按「基座在 y=0、正面朝 +Z（南）」建模，
            摆上去基座自动 ⟂ 半径，脚/底座刚好踩地表。
```

两个出口收敛所有摆位（`M.surfaceQuat(dir, yawDeg)` / `M.surfaceFrame(dir)`），
城镇、据点、奇观、小人、行走插值**全部改走它**，不再各写一套。

> ⚠️ 坑①：转身轴必须是**局部 (0,1,0)**（右乘），不能是世界法线。
> ⚠️ 坑②：平移与旋转必须**同源**（同一个 dir），否则位置在 A 格、姿态按 B 格。

## 三、门禁断言（§587，永久防回归）

> ⚠️ 一个坑：map3d 在**没有 three 的环境**（node 门禁）会走
> `enabled:false · why:no-three` 降级分支，**根本注册不到任何出口**——
> 第一版把 `surfaceQuat` 挂在里面，门禁当场报"不存在"（假红）。
> 正解：坐标数学改成**纯数组实现**（`surfaceQuad` 返回 `[x,y,z,w]`、
> `surfaceFrame` 返回 `{up,east,south}` 数组），**两个分支都挂**，
> 于是不带 THREE 也能把这条不变量验到底。

```
§587 球面姿态唯一出口 surfaceQuad/surfaceFrame 存在（无 three 也要有）
§587 各方向 +Y 严格对齐径向（基座 ⟂ 半径）          minDot > 1-1e-6
§587 绕自身竖轴转身 0°~360° 不破坏立姿（本次回归点）
§587 反例守卫：旧写法(绕世界法线转身)确实歪掉，会被上面断言抓住   ← 防"平凡通过"
§587 切平面基 正交/归一/右手
§587 世界口径「东 = -Z」成立
§587 极点切平面不退化（无 NaN）
```

「反例守卫」是这次特意加的：**断言必须先能判死旧 bug**，否则它只是装饰。

## 四、斗将 3D 舞台（文字场景化）

新增 `js/duel3d.js`（单例场景 + 可重入挂载），把原来"两张画像 + 伤害数字"的
斗将面板换成**看得见两个人真打**的舞台。

- **判定仍只有一份**：胜负/伤害全走 `GAME.duel.play()`（纯函数）。舞台**只读结果**，
  不掷骰、不改血 → "画面演的"与"账上算的"永远同一场。
- **数值仍走 DOM**：名字/血条/攻防做成半透明 HUD 压在舞台两角（3D 里画血条必糊且读不出数）。
- **单例 + 可重入**：面板每走一合整块重绘，`mount()` 被反复调用；场景只建一次，
  画布在 DOM 里被"搬"进新容器（保 WebGL context 不丢）。
- 动作（**v1 只做站桩对打**）：每合双方同时前冲（本作规矩：每合双方各出手一次）
  → 受力方后退 → 归位；结算归位后由 DOM 出"胜/负"大字。
- ⚠️ **骨骼动作播放默认关闭**（`js/duel3d.js` 的 `CLIP_ON = false`）：
  Soldier 资产的"绑定姿态空间（网格 0.003 单位）"与"骨骼空间（1.5 单位）"
  差三个数量级，动作里还带根位移 —— 一旦播 clip，模型被推到画面外
  （实测像素高 187 → **0**，人直接消失）。Robot 没这问题，但两个角色
  一个动一个不动更怪，故 v1 统一不播。要开：先修蒙皮空间，或换 binding 规整的资产。

### 资产标定表 `GAME.gltf.FIT`（这次最花时间的地方）

两个 GLB 的原生尺寸差 **5 个数量级**，且"绑定姿态空间"与"蒙皮结果空间"不一致：

| 资产 | 原生可见高度 | 缩到 1 单位 | 立姿 | 最终采用 |
|---|---|---|---|---|
| Soldier | ≈0.0033 | 像素标定初值 113.4 | **+90°X**（网格挂在带 −90°X 的 Character 节点下） | `scale: 69.0` |
| RobotExpressive | ≈178 | 像素标定初值 0.2201 | 0° | `scale: 0.2201` |

> Soldier 的 113.4 是"单独渲染"标定值；放进舞台（相机更近、构图更满）后按舞台实拍
> 再收一次到 **69.0** —— 标定表就是"以最终画面为准"的表，不是理论推导値。

走过的弯路（都已写进代码注释，避免下次再踩）：

1. `Box3.setFromObject()` 量高度 → **无视蒙皮**，Soldier 量出 0.004 → 缩放 ×225 → 巨人。
2. 改用"骨骼 Y 跨度" → Soldier 是 **T 姿**，臂展 1.77 > 身高 1.55 → 把站着的士兵**放平**。
3. 归一化后再 `bind()` + `skeleton.calculateInverses()` → 静止姿态变非恒等 → 模型摊成一团。
4. `SkinnedMesh.computeBoundingBox()` → 仍吐绑定姿态尺寸。
5. **最终方案**：所有变换施加在**外层容器**（根节点一个字节不动，绑定永远有效）+
   **像素标定**（渲染→读像素→反推世界高），系数固定进 `GTF.FIT`。

标定脚本（新增资产跑一次即可）：

```bash
node .workbuddy/tools/show/calib_actor_fit.js    # 粗标：反推原生尺寸
node .workbuddy/tools/show/probe_anim_scale.js Soldier   # 复核：当前 FIT 下的像素高
```

## 六、诚实缺口

1. **未做真机（老板本机浏览器）观感确认**：沙箱用 swiftshader 软渲染 + 像素统计，
   比例/朝向/构图已按数值校准，但最终观感仍需老板实机看一眼。
2. **斗将面板整链路未端到端跑**：需要游戏内真实进入一场斗将才算完整验证；
   本期验证的是"舞台单独 mount → 两角色站好、面对面、出招/结算动作正确"。
   面板里 `mount()` 有 try/catch 兜底：WebGL 不可用时它返回 false，面板照旧可用。
3. **双方动作集不对等**：Robot 14 段（Punch/Wave/Death…），Soldier 只有 4 段
   （Idle/Run/Walk/TPose）——士兵的"出招"是 Run、"受击/胜/负"都是 Idle，靠位移补戏。
   想更好看：把 `js/duel3d.js` 的 `ME_MODEL` 也换成 `RobotExpressive`（一行），
   或补一套人形动作资产。
4. **城堡自转**：从"完全随机（0~360°）"改成"绕局部竖轴 ±30° 微扰"，
   城门大致朝南（+Z）。如果老板希望**全部正面朝赤道**，改 `buildTowns` 里那个
   `(_townRnd(e.ci) - 0.5) * 60` 为 `0` 即可。



## 七、本期还顺手修掉的三个真问题

1. **蒙皮绑定顺序**：`parseAnimated` 原来是「先绑定、后做立姿旋转与缩放」，
   `bindMatrix` 记的是旧世界矩阵 → 人物摊成一团。正解不是重绑
   （重绑 + `calculateInverses` 反而把静止姿态弄成非恒等，更糟），
   而是**根节点一个字节都不动**，姿态/尺度全部施加在**外层容器**上。
2. **骨骼名不能直接照搬 glTF 原名**：`mixamorig:Hips` 这类名字会被 three 的
   PropertyBinding 清洗规则（剔除 `[ ] . : /`）判成不匹配 → 骨骼动画**静默失效**
   （§586「Soldier Walk 驱动骨骼位移」当场转红）。已按 three 的规则清洗成
   `mixamorigHips`。
3. **换行符事故**：本仓库是纯 LF，用 Python `open(p, 'w')` 改文件会把整篇转成 CRLF →
   ① git diff 从 103 行膨胀到 9237 行；② 依赖 `\n` 的正则断言（§204⑦ `.pager`）转红；
   ③ 构建 hash 与源码不同步。已全部改回 LF；**后续改文件一律用 node `fs`
   （不做换行转换）**。

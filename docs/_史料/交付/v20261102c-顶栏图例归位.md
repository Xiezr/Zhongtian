# 顶栏：图例不该混在页签里

> 老板 2026-11-02：「顶部菜单少了别的，多了图例，这很荒谬」

---

## 一、先量了一遍，问题确实成立

用 `shot_topnav.js` 打出顶栏每一项的实际位置与宽度（1440 宽）：


**两件事同时成立**，所以看着荒谬：

1. **多了图例**：它是 `data-action="terr-legend"`（开弹窗），却被塞在 `data-view` 页签中间，
   而且**不受阶段控制、永远显示** —— 旁边按阶段隐藏的页签一消失，它就成了"第 7 个页签"。
2. **少了三个**：空间站 / 游商 / 收藏 在 `early` 阶段被 `display:none`（宽度 0）。

---

## 二、改了什么

### 顶栏分成两段，语义不同

```
左边 = 页签（data-view：点它换页面）
右边 = 工具（data-action：在当前页面上开个东西）→ 图例 / 世界账本 / 天时
```

```html
<div class="nav-right">
  <div class="nav-legend" data-action="terr-legend">🗺 图例</div>
  <div class="nav-ev" id="nav-ev" data-action="open-world">🌍 世界账本</div>
  <div class="nav-sky" id="nav-sky"></div>
</div>
```

```css
.topnav .nav-right { margin-left: auto; display: flex; align-items: center; gap: var(--sp-3); }
.topnav .nav-legend { /* 不再是 .tab 的页签皮肤，改成轻量工具按钮 */ }
```

图例**不再是页签皮肤**，也不会因为页签增减而移动 —— 由 `margin-left:auto` 的容器整体推右。

改后实测（1440 / 1024 两档）：

```
1440px  图例点击=clicked  弹窗=有「🗺 地形图例…」  内容右缘=1360/1371  ✓不溢出
1024px  图例点击=clicked  弹窗=有「🗺 地形图例…」  内容右缘=1015/1024  ✓不溢出
```

## 三、"少了三个"是怎么回事（**没改**，先说明）

空间站 / 游商 / 收藏 由 `ui.syncPhase()` 控制：

```js
var hide = (ph === 'early') ? ['station', 'shop', 'collection'] : [];
```

`early` 的判定 = **城数 ≤ 1 且 胜场 < 3**（`ui-bag.js` 的 `phaseOf`）。
也就是说：**打下 3 场胜仗，这三个菜单就会出现**。

这是 v150 的设计（「让第一小时只露出这一小时该做的事」，引用了行业参照"前 30 分钟 ≤3 个可见目标"），
并且有一条断言把它钉死了：

```js
// smoke §573②
&& /\.topnav \.tab-locked \{ display: none; \}/
```

### 但这里有一处**自相矛盾**，值得你拍板

`syncPhase` 里写着：

```js
/* 锁着的时候给一句为什么（悬停）：不解释的隐藏＝玩家以为坏了 */
if (locked) tabs[i].setAttribute('title', '站稳脚跟后解锁：' + ui.gateWhyText());
```

**可是 `display:none` 的元素根本悬浮不到**，这个 `title` 永远不会被看到 ——
等于写了一句安慰自己的注释。这也是"玩家以为少了东西"的直接原因。

两个选项：

| 方案 | 改哪里 | 代价 |
|---|---|---|
| **A 保持隐藏**（现状） | 不动 | 玩家开局看不到这三个，打完 3 场才出现 |
| **B 改成灰显可见** | CSS `.tab-locked` 从 `display:none` 改为 `opacity:.45; pointer-events:none` + 同步改 §573② 那条断言 | 顶栏多 3 项（1024 下正好卡在边缘，需再量一次） |

我倾向 **B**（玩家能看到"未来有这些"，也有目标感；且让那句 title 真的能看见），
但这属于改**既定设计 + 断言口径**，没有你的话我不动。

## 四、写断言时踩的一个坑

改完顶栏，冒出一条**新失败**：

```
❌ 顶栏有天时元素（在「自动」「设置」之后，最右）
```

根因：那条断言用的是魔法数字窗口 ——

```js
var nav = hS39.slice(i, i + 4000);   // 只截 topnav 之后 4000 字符
```

而 `.nav-right` 容器 + 注释让 `nav-sky` 距 topnav 起点变成 **4039** 字符，
**只超出 39 就红了**。

已改成按结构定位（截到兄弟节点 `<div class="main">` 为止），以后再往顶栏加东西都不会再撞这个数。

> 这类"固定长度窗口"的断言，本质是在赌"这块永远不会变长"。顶栏恰恰是最容易变长的地方。

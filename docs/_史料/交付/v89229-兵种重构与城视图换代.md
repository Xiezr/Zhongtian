## 三、由本轮需求引出的真 bug（两处 · 都用探针实锤）

### 3.1 `js/map.js` 的 `fortGarrison` 五键全是退役 id —— 据点守军整支为空

```
改前: { yibing:35%, changqiang:25%, daodun:20%, gongjian:20%, qingji:10% }   ← 五个 id 全退役
后果: unitsInit.def = [] → 战斗 0 回合结束 · defLoss 恒 0（俘获/战功/战报全空）
      且「兵力悬殊二次确认」因比值算不出而永不触发（v89.86 用例当场红）
改后: { buxingji:60%, dunwei:20%, daodanche:20%, fujiche:10% }（权重相加 · 总数不变）
实机: Lv6 据点守军 15509（buxingji 8459/dunwei 2820/daodanche 2820/fujiche 1410）→ 真打 9 回合 · defLoss 15509
```
**为什么迁移救不了它**：`fortGarrison` 是**运行时派生**（每次现算），不是存档字段 —— 老档迁移只覆盖存量。

### 3.2 AI 位图按旧 id 命名 —— 14 个新 id 全查不到位图

`assets/icons/ui/ai_<troopId>.png` 18 张全按旧 id（`ai_yibing.png` 等）→ 换代后静默回退矢量层。
处置：按原型继承**改名 14 张**（`ai_minfu.png`→`ai_banche.png` …），4 张未被继承的旧图
（`ai_yibing`/`ai_chongche`/`ai_tieji`/`ai_qingzhoubing`）备份到
`.workbuddy/backup/v89229c9/troop_png/` 后移除；`js/bitmaps.js` 用**官方生成器**
（`.workbuddy/tools/gen/gen_bitmaps.js`）重生成（与手工重生成逐字节一致）。

### 3.3 附带修出的第三处（e2e 真点才暴露）：统一面板的"切页/点卡被当场抹掉"

`renderTroopsModal()` 走 `openTroops(_trainBIdx)` —— 而入口逻辑每次都把 `_trainTab`/`_trainSel`
重置回"入口默认值" → **用户切页点不动、点兵种卡也点不动**（点击后立即被重绘抹掉）。
修法：入口语义与重绘语义分开（`opts.keepState`）——
入口＝预置选中项 + 沿用合法页签；面板内重绘＝**保持**页与选中项。
另：队列页的工位改为"优先取当前解析的那一座"（原来固定取首座 → 队列挂在第二座训练营时显示空队列）。

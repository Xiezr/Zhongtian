# 动手场景 3D 骨骼角色接入 · 交付说明

> 日期：2026-11-01　|　范围：把程序化方块人升级为免费骨骼动画角色，接入三个经典场景
> 关联任务：Task #2 加载器 / Task #3 技能设定 / Task #4 三场景接入 / Task #5 本文档

## 一、结论（先讲结果）

原「动手场景」的角色是 `BoxGeometry/Cylinder` 拼的方块人，动作靠程序化摆腿/晃动，**观感差、无骨骼**。本次：

1. **检索并落地了 2 套免费、自带骨骼动画的 GLB 资产**：`RobotExpressive`（14 段动画）与 `Soldier`（4 段动画）。两者均为 three.js 官方示例模型（源自 Mixamo 绑定，随 three.js 分发，可免费商用）。
2. **写了一套通用骨骼动画加载器** `GAME.gltf.parseAnimated / Actor`（零外链、UMD 兼容、自动立姿+归一化、mixer 驱动骨骼位移）。
3. **做了技能设定**：`GAME.gltf.CLIP_MAPS` 把「走/待机/攻击/防御/胜利/采集…」等技能键映射到各角色的 clip，集中管理、便于调参。
4. **接入三个经典场景**（已改源码 + 重建产物）：
   - **序章君主走动**（球面地图 `map3d.js`）：方块人 → `RobotExpressive`，沿地表弧线走时播 Walking、站定播 Idle。
   - **scene3d 采集·垂钓**（`scene3d.js`）：玩家小人 → `Soldier`，走动播 Walk、站定 Idle、互动采集播 Sit；保留影子/头顶指示三角等既有道具。
   - **斗将/对决**（`scene3d.js` 遭遇节点）：`duel.js` 本身只做结算、无 3D 渲染，本次在其宿主场景补上视觉——玩家身前生成敌方 `Soldier` 播 Guard、玩家播 Attack，玩家移动或退出场景即清场。

## 四、技能设定（CLIP_MAPS 摘要）

技能键 → 角色 clip 的映射集中在 `GAME.gltf.CLIP_MAPS`，场景只调 `actor.skill('walk')` 这类语义键，不散落硬编码：

- **RobotExpressive**（14 段，动作丰富）：`idle→Idle · walk→Walking · run→Running · attack→Punch · guard→Standing · victory→Wave · defeat→Death · dance→Dance · sit→Sitting · yes→Yes · no→No · jump→Jump`
- **Soldier**（仅 4 段，动作少）：`idle→Idle · walk→Walk · run→Run · attack→Run（兜底）· guard→Idle · defeat→Idle · sit→TPose（兜底）`

> 设计取舍：`Soldier` 原模型只有 Idle/Walk/Run/TPose，没有真正的攻击/坐下动画，故 `attack/guard/sit` 等按「语义最接近」兜底到已有 clip（攻击暂用 Run 冲刺、坐下暂用 TPose）。这是资产本身的动作集限制，不是 bug；若日后换更全的模型，只需改 `CLIP_MAPS` 一行。

## 五、加载机制（无外链、可离线）

`loadAnimated(name, cb)` 三级回退：
1. 若 `window.__ACTOR_GLB[name]` 已注入（即 `assets/actors/<name>.glb.js` 已被 `<script>` 加载）→ 同步取 base64 解析；
2. 否则动态注入 `<script src="assets/actors/<name>.glb.js?v=NNNN">`（带 `?v=` 缓存失效，复用 wonders 机制）；
3. 再失败才 fetch。

`assets/actors/*.glb.js` 把 GLB 转 base64 内联，规避 `file://` 的 CORS 限制，**无需起服务器即可双击打开**。

## 六、诚实缺口（需要老板拍板/后续）

1. **未做真机渲染核对**：当前沙箱无法跑浏览器/WebGL，验证靠「headless 解析（node+three）+ mixer 骨骼位移断言 + 三包语法 check」。最终观感（角色比例、朝向、与场景道具的相对位置）需老板在浏览器里实机看一眼。已知两处待调：① 角色归一化身高≈1.0，原方块人≈1.2，可把 `a.root.scale` 从 1.0/1.2 微调；② 头顶标记 `marker` 高度是按模型头顶重新落的（1.35），可能需再降一点。
2. **斗将视觉是轻量叠加**：只生成「看得见的两个人」并播 attack/guard，**没有 hook 进斗将面板的胜/负去播 victory/defeat**——那要改 `duel.js`/UI 面板结算回调，属跨模块改动，本期未动。清场时机为「玩家移动键 / 退出场景」。
3. **双角色动作集不对等**：Robot 14 段、Soldier 4 段，上文已说明 Soldier 的兜底映射。若希望采集场景也用 Robot（动作更丰富、能真坐下），把 `buildPlayer` 里的 `'Soldier'` 改成 `'RobotExpressive'` 即可（Robot 的 Sit 是真坐下动画）。
4. **容量**：`Soldier.glb.js` ~2.8MB 是内联 base64，首次进采集场景会随脚本加载；如对首屏体积敏感，可改为「进入场景才动态注入脚本」（当前已支持，只是默认随包内联）。

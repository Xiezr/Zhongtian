# v157.91 · 明暗改逐像素（治「涂色锯齿」的真正成因）

> 2026-11-21 · 老板：「为什么之前没有这个问题」→ 回答完就动手

## 一、先回答"为什么"

**实验**：同一视角，只切换起伏明暗——

| 状态 | 画面 |
|---|---|
| 起伏明暗 **开**（v157.89 起默认） | 色块边界一格一个亮度台阶，读起来就是锯齿 |
| 起伏明暗 **关** | 边界变成柔和过渡，台阶几乎看不见 |

**结论**：配色一直是"每格一色"，相邻色值接近，读起来像渐变；**是我加的逐顶点明暗**给每个顶点
算了独立亮度，把连续色带切成「一格一档」，网格因此显形。之前没有这层，所以看不到。

## 二、改法

| 项 | 内容 |
|---|---|
| 法线图集 | 与配色同布局（4N×4N，6 格）：RGB = 物体空间法线，A = 曲率遮蔽 |
| 求法线 | **复用**配色烘焙时已算出的高度场 h，差分求梯度（不重复调 `sphElev`，烘焙不翻倍） |
| 夸张 | `tanθ' = 2·tanθ` 搬进烘焙（逐像素的真实法线比网格法线温和，不夸张立体感会退） |
| 采样 | 片元 `dot(N, sun)`；`modelMatrix` 显式声明后转世界坐标 |
| 保命 | `M.RELIEF_TEX = false` 退回逐顶点明暗（对照与回退都用它） |

## 三、两个坑

1. 片元里 `modelMatrix` **不是内建**（three 只在顶点前缀声明）→ 报 `'modelMatrix' : undeclared identifier`。
2. 差分首版写 `(xx-1+N)%N` 环绕 → 面边缘把**地球另一侧**当邻居 → 六个面各一条细黑线。
   改**边缘单边差分**（`xm = xx>0 ? xx-1 : xx`，分母用实际步数）。

## 四、实测

- 烘焙 **1.5~1.6 秒**（配色 + 法线一次烘完），按「种子+精度」缓存。
- 明暗生效：开/关 平均像素差 **6.5**，亮度 91.5 / 95.3。
- 实机三视角：色块边界平滑、面间无黑线、山体明暗在岗、页面异常 0。

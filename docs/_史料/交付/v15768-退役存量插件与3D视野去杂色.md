## 2. 需求 A：退役「现有人口设定」

### 病根
v157.65 加的 `set-pop` 是一次性把每座城 `GAME.res(city).pop` 注入成玩家填的数值，
带输入框 + 通用 `plugin-action` 动作 + `transient` 防刷新重放。老板判定这张卡不要了。

**没有继任者**：存量此后只由游戏既有规则与 v157.67「人口常满」管理，
后者每拍以 `GAME.effPopCapOf(city)` 为准补足，不再接受任意手工注入。

### 改法（全部只在 `js/plugins.js`）

| 面 | 处置 |
|---|---|
| 注册块 / `controls` / `apply` / `actions` / `_on` / `_off` | 整条删除，留墓碑注明老板原话与去向 |
| 输入框 / 「应用到所有城」按钮 / 面板文案 | 随注册块一起消失，不留死代码 |
| `transient: true` / `param: 9999` | 随插件删除（此后无 transient 插件在册） |
| 框架通用能力（`controls` 渲染 / `plugin-action` 分发 / `getParam`-`setParam` / `transient` 启动分支） | **保留**为插件箱 API，供后续数值插件复用；是容器能力，不是退役插件的实现残留 |
| `smoke §586g` 旧四条（在册 / 输入框 / 动作 / 存量 7777） | 按新规则**反向重写**为「零残留」四层守卫，判据未删未放宽 |

`js/ui-all.js` 是 `build_bundle.py` 自动生成的审计镜像，不手改；重建后 `id: 'set-pop'`
在 `ui-all.js` / `bundle-ui.js` 中的计数均为 0。

### 断言（§0.7 规则变更三件套）
- 标题写新规则（「整条退役」）；注释点明 v157.65 旧规则被老板逐字推翻；
- 另配**真调行为断言**：`enable/disable/toggle('set-pop')` 全返回 false、
  伪造旧 id 按钮走一遍通用 `plugin-action` 分发、两城存量 10/20 纹丝不动
  → 证明退役后不存在任何注入路径；
- 运行面同时断言插件箱只剩 1 张卡（`full-pop`）、`viewHTML()` 无旧文案/输入框。

## 3. 需求 B：3D 视野去杂色

### 3.1 取证链（不靠猜，四轮实机 + 像素统计）

| 轮次 | 结论 |
|---|---|
| ① 3D 现状 / 全明 / 隐藏层 / 2D 现状 | 排除整齐的 2D 方格图；3D 全景的灰斑是山地地形本身 |
| ② 贴地逐层关闭云壳 / 加亮层 | `setZoom(0)` 是黑底 + 蓝线，不是老板画面；排除极近视角 |
| ③ 混合 fog 分档（远景 / 贴地） | **发现取证口径错误**：`buildFog()` 是闭包私有、未挂 `M`，脚本里 `M.buildFog()` 全是空操作，fog 桩没触发重绘 |
| ④ `pixel_v15768.js` + `v15768-BOSS-x3.png` | 老板原图 `deepblue 77.4% / green 18.6%`；3 倍放大后碎斑是**硬边六边形**、围绕城市呈环状，深蓝未探明底上散布 |
| ⑤ `shot_v15768_beforeafter.js before` | 改用真正暴露的 `M.paintGlobeFog()` / `M.paintRegionEdges()` 重绘后，复现出「深蓝未探明底 + 中央一圈硬边浅色六边形碎斑」，与老板放大图**同构** |

①②③ 是取证草稿（含已知空操作），**未纳入仓库**；纳入的只有 ④⑤ 两个有效工具与像素统计脚本。

### 3.2 根因
fog 三档（0 未探明 / 1 半明 / 2 全明）在**三个渲染面**各自分档：

| 渲染面 | 旧三档 |
|---|---|
| `paintGlobeFog` globe 顶点色 | `1.0 / 0.78 / 0.34` |
| `buildFog` 贴地加亮六边形层 | `_fogLit` 0.20 / `_fogLit1` 0.10 / 无 |
| `paintLineFog` 地块线框色 | 冷蓝 / 灰蓝 / 隐形（染背景色） |

reveal 半径边缘三档交错 → **已探明范围内部**被切成深浅不一的硬边六边形碎斑，
就是老板说的「杂色」。v157.63 只修了 2D `rectMask`，其交付文档末尾明确写了
「未触 3D 星球（map3d）视野/fog」——本轮补的正是这个洞。

### 3.3 新口径（老板 v157.63 逐字：「要边界感，而不是在视野内增加渲染」）

| 面 | 旧（三档） | 新（两态） |
|---|---|---|
| globe 顶点色 | `1 / 0.78 / 0.34` | `vv>=1 → 1`（原色）、`vv=0 → 0.34`（整体均匀压暗） |
| 贴地加亮几何 | 两层六边形 0.20 / 0.10 | **整条删除**，已探明区零额外渲染 |
| 地块线框 | 冷蓝 / 灰蓝 / 隐形 | 已探明（含半明）统一冷蓝 / 未探明隐形 |
| 明暗交界 | 三档交错成碎斑 | 一条干净的六边形格边 |

`buildFog()` 从 ~185 行缩到 8 行：只 `F.ensure()` + `paintGlobeFog()` + `paintLineFog()`。
连同 `makeMesh` / `cloudMat` / `CLOUD_VS-FS` / `M._cloudMats` 及其每帧 uTime 推进循环一并退役
（`js/map3d.js` **-154 行**），不留死代码。

**不动的**：大气云壳 `buildSkyClouds` 的 `M._sky`（不按格分档，老板 v157.44 要过的云量）、
`fog.get` 控制的内容可见性（半明与全明的差异仍在，只是不再靠颜色分档表达）。

### 3.4 实机前后对照（同一 fog 分布 · 同一 `setZoom(0.14)` · 唯一变量是 `map3d.js`）

| 图 | 观感 |
|---|---|
| `v15768-BEFORE-fogclean.png` | 深蓝未探明底 + 中央一圈层层破碎的深浅锯齿斑块 |
| `v15768-AFTER-fogclean.png` | 中央亮区**连片均匀**，明暗之间一条干净的六边形边界 |

`pixel_v15768_beforeafter.js`（画布中央 680×530，n=360400）：

| 指标 | BEFORE | AFTER | 变化 |
|---|---|---|---|
| 中间亮度带 70–125 | 54.8% | 47.5% | **-7.3pp**（旧 0.78 中间档 / 半强加亮层消失） |
| 亮区 ≥125 | 8.9% | 12.9% | +4.0pp（已探明区恢复原色） |

升到 25.9% —— 中间亮度被挤向两端，正是「三档 → 两态」的定量特征。

### 3.5 断言（§586j 四层）
1. 源码面①：`buildFog` 无 `makeMesh` / `scene.add` / `AdditiveBlending` / `M._cloudMats`，
   全文件无 `_fogLit =` / `function makeMesh` / `function cloudMat`；
2. 源码面②：两处 `kCur` 都是 `(v>=1) ? 1 : 0.34`，无 `0.78` 中间档；线框统一冷蓝，无灰蓝分支；
3. **行为面（vm 真调，不是 grep）**：从 `js/map3d.js` 抽出 `paintGlobeFog` / `paintLineFog`
   两个函数体，注入 3 顶点 + 贪心邻接桩，让 `fog.get` 依次返回 2/1/0，
   断言顶点色系数 `k2=1 · k1=1 · k0=0.34`，且线框 fog=1 与 fog=2 逐分量相等；
4. 台账面：`需求档案.md` 中 v157.68 与老板原话在册。

## 5. 诚实缺口

1. **半明/全明不再有颜色差异**：两档画面上不可区分；内容可见性仍由 `fog.get` 精确控制。
   若老板要求「半明也要看得出来」，应用**边界标记**而非视野内填色，另开一轮。
2. 未探明区仍保留 0.34 整体压暗（v157e 口径「那里有东西，只是看不清」），不是纯黑。
3. 大气云壳 `M._sky` 的 FBM 噪声在中等距离仍叠一层细颗粒；本轮按「不按格分档」原则未动。
   若老板仍觉得那层颗粒算杂色，下一轮单独处理云壳。
4. 实机取证用的是**人为构造的 fog 分布**（新游戏默认几乎全明，复现不出老板存档状态）。
   结构与颜色构成同构，但不是老板那一局的逐像素还原。
5. 前三轮取证草稿含已知空操作，**未纳入仓库**；结论以 `shot_v15768_beforeafter.js`
   的前后同状态对照与 `pixel_v15768_beforeafter.js` 的像素统计为准。

### ② 路线为什么不会「面板一套、结算一套」

同一张 `DATA.AGENDA.routes.list` 被四处读：

```
行动台表格（AG.routeEstOf / routesOf）
        ↕ 同一份系数
出征面板「目标估掠」（ui-exped.js updateExpHaul × routeLootMulOf）
        ↕ 出发时冻结 routeId
main.js exp-confirm → march.dispatch(extra.routeId)
        ├─ dispatch：校验并扣净水粮补给、totalTime × marchMul、m.routeId 随军
        ├─ arrive        → expedition(opts.routeId = m.routeId)
        └─ _settleBattle → expedition(opts.routeId = rec.routeId)
                             ↓
                         落账 genLoot / npcLoot × routeLootMulOf(opts.routeId)
```

出发后改行动台的选择**不影响已在路上的队伍**——`routeId` 冻在 `march` / `battle rec` 上，
不是结算当下读全局。出发日志把「路线 / 补给 / 战果系数」写进那一行，玩家能对着面板核对。

### ⑤ 临时牌为什么不会变成「遗产」

`AG.afterBattle` 先清 `a.tempCard`（上一仗用掉了），再按确定性种子出 3 张；
`AG.draftPick` 只写 `a.tempCard`，**从不 push 进 `s.deck`**；
`DK.effOf` 读 `tempCardIdOf()` 推入 `DK.chosen()` 的**副本**（`tactic.js` 战前攻防、
`goals.js` 战后战果两条链同时消费）；临时牌绕过带队将风格限制，避免「牌没生效却看不到原因」。

触发点两个、不会重复：观战走 `goals.afterBattle`（`rec.id = bt-N`），
即时结算走 `main.js onMarchArrive`（`rec.id = march-N`）。
挂起待指挥时 `r.result` 是空对象，`AG.afterBattle` 按「无 `atkLoss` / `defLoss`」判掉；
`lastDraftBattle` 再按 `rec.id` 幂等，重放 / 重复落账刷不出新牌。

## 四、自审抓到并修掉的五个真问题

1. **护卫费扣两遍**：初版 `laneSend` 先 `goldAdd(-guardCost)`，随后 `earn` 又减了一次
   `guardCost` —— 面板 `net = gross − guardCost` 与真账 `gross − 2×guardCost` 对不上。
   改为 `earn` 只算货款；日志与流水账分列「货款 / 护卫 / 净入」，玩家逐笔可核。
2. **封路写死世界绝对坐标**：初版 `lanes.list` 用 `x/y` 绝对坐标，而辐射云圈心由
   `surge.centerOf()` 在开局按己方城重心钉死、每局都不同，半径从 `startR=55` 收到 `minR=14` ——
   写死坐标意味着「封路」永远不触发，只是句文案。改为相对圈心的 `dx/dy` 偏移
   （10/7、16/14、26/24）：圈一收，最外的荒原近道真的先封，`laneSend` 与发货按钮
   同时被闸拦（按钮经 `softenBlocked` 变「可点 + 说明」，不是弹一句提示）。

3. **界面用了两个根本不存在的 CSS 类**：初版 `AG.html()` 用 `.ui-card` / `.ui-sec` 包订单卡与板块，
   但项目 CSS 里只有 `.ui-page` / `.ui-sub` / `.notice-box` / `.gold-heading` / `.tbl` / `.chips` / `.op-row`
   —— 实机截图显示订单卡没有边框、三张竖排挤在左侧约 300px、右侧大片空白。
   改为 `.notice-box` 卡片 + 三列网格（grid 走 inline style，不新增 `<style>` 类），
   板块间距由 `.gold-heading` 标题条加 inline margin 承担。
   取证图 `v15770-AFTER-agenda.png`（顶部）/ `v15770-AFTER-agenda-bottom.png`（滚到底）。
4. **存档字段撞名会让别人的守卫假红**：商队护卫开关若落成 `s.agenda.guard`，
   `JSON.stringify(state)` 里就会出现 `"guard":`，撞上 `smoke §193`
   「NPC 派生库存不入档」的既有守卫（它按字面查这个串）。改自己的字段名为
   `laneGuard` / `guarded`，**不放宽别人的判据**；最终产物上另用只读探针复核过：
   `newGame()` 存档 `"guard":` 命中 0、`npcCityRes` 命中 0、`s.agenda` 干净。
5. **两层 `renderView` 包装撞上审计判据**：`agenda.js` 初版照 `plugins.js`
   写成 `GAME.ui.renderView = function (v) {...}`，`audit.js` 的 `defRe` 只认
   `X.Y = function (` 为「定义」，于是同一个出口被判「同名函数重复定义 1」，
   首轮门禁 `[0, 0, 1, 0]` 直接拦下（`chain 47/0 · invariants 40/0 · smoke 4509/0 · e2e 1103/0` 全绿）。
   两层其实都是「存原函数再挂回」的装饰器，不是互相覆盖的两份实现 ——
   把第二层改成具名函数 `agendaRenderView` + 引用赋值（与 v157.67 `fullPopTick` 同一形状），
   重建后 `audit` 四项计数回到全 0。**没有改判据、没有加白名单、没有删断言。**

## 六、诚实缺口

1. **④ 年景预告是纯信息层**，本身没有按钮 —— 它的价值依赖玩家拿它去排①②③。
   这是刻意的：加一个「提前准备」按钮会变成又一句空播报。
2. **⑤ 临时牌只在真接战的一仗后出牌**：侦查 / 运输 / 采集抵达被 `modeOf().battle` 判掉；
   守城战也不出牌。多支队伍同时在外的队伍共用「下一仗」的一张牌，不按队伍分。
3. **路线补给只扣净水粮**，未接战方式（调运 / 派驻）也会按所选路线扣补给与改行军。
   若觉得不合理，下一步可在 `dispatch` 里按 `mode.battle` 收窄；本轮先保持「选了就认账」。
4. **老档第一次进行动台会惰性建档**，当月订单按当前月号生成，历史月不补发。
5. 订单「接了没交」到月末自动作废，不计入「搁置」数 —— 只有明确点「搁置」才计数。

# 海面波浪：从"规则斑块"改成"不规整细浪"（v156.22）

> 老板：「海波还是有点太规整太明显了」
> 结论：**病根不是振幅，是形状** —— 5 条固定方向的正弦叠加，相位线性 → 等相位线是平行直线。

## 一、先取证（A/B 隔离变量）

同机位、只把 `uAmp` 从 3.2 改 0 各拍一张：

- `water_z16_flat.png`（关浪）：一片干净深蓝，几乎无起伏；
- `water_z16_wave.png`（开浪）：整片海面浮着一层**规则的大斑块**。

→ "规整"确实来自波浪，而且不是"太亮/太高"，是**形状本身有周期**。

为什么以前加过域扭曲还是规整：
| 层 | 原实现 | 问题 |
|---|---|---|
| 波形 | 5 条 `sin(dot(W, 固定方向) * k + t)` 叠加 | 相位线性 → 平行条纹 |
| 域扭曲 | 3 条慢正弦（周期 300+ 单位） | 扭曲本身也周期 → 只把直条纹弯成弯条纹 |

## 二、改了什么（两刀）

### ① 波形换成值噪声 fbm（`js/map3d.js` 顶点着色器）
- 新增 `hash13` / `vn`（值噪声）/ `fbm2`；
- 相位不再线性：`base`（涌浪 ~12 单位）+ `mid`（~5）+ `chop`（~2.2），权重递减；
- **域扭曲用噪声推噪声**（`warp()` 三个 `vn` 采样）—— 这一条才是"不规整"的关键。
- GLSL 里哈希噪声比三角函数便宜（只有乘加、无 `sin`），13 万顶点撑得住。

### ② 细浪搬到片元级（片元着色器）
根因：水面网格是**每格 7 个顶点**（六边形中心 + 6 沿）。比一格小的浪在几何上
根本表达不出来，只能被采样成"整格一个大斜面" → 屏幕上就是大块软斑。
- 几何只负责**涌浪**（`uAmp: 3.2 → 1.5`）；
- 细浪改为片元里 `rip(vW)` 三层采样（中心 + 沿 T/B 各一步）算法线扰动；
- 加**逐像素距离衰减**（`length(vView)`）：远处的像素细浪自然变淡 —— 不做这个，
  镜头一动就是一片摩尔纹闪烁。

### ③ 远景整体衰减
`uFar`（1.0 贴近 → 0.45 轨道），由 `render()` 按 `camO.dist` 每帧写。

## 四、可调旋钮（老板嫌重/嫌轻时改这三处）

| 想要 | 改哪里 |
|---|---|
| 浪更"高" | `uAmp: { value: 1.5 }`（世界单位，一格 ≈ 5） |
| 细浪更明显/更淡 | 片元里 `float amp = 0.42 * …` 的 `0.42` |
| 远景更平静 | `uFar` 那行 `1.0 - 0.55 * _wf` 的 `0.55`（以及 0.45 下限） |
| 浪更大块/更碎 | `warp(P * 0.085, t)` 的 `0.085` 与 `mid/chop` 的倍率 |

## 五、诚实缺口

1. **未做真机观感确认**：以上都是 swiftshader 软渲染截图 + 帧率统计，
   最终"顺不顺眼"仍需老板在本机看一眼（尤其 1.2× 近景的颗粒感）。
2. 水面仍是"每格 7 顶点"的低模几何：**大浪只能按格起伏**，做不到真正的连绵涌浪；
   要那效果得把水面细分（历史上实测 +150ms/帧，故未做）。
3. 云层（`buildSkyClouds`）用的是同一套 fbm 思路但**没改** —— 若老板觉得
   "海上那层灰雾也规整"，那是云，不是浪，另开一轮改。

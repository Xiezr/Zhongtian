## 一、病根（一句话）

**球体的法线全是径向的，与地形起伏无关** —— 所以山脊和山谷受光一模一样，地形只能靠顶点色区分，看起来就是"贴了一张地图的纸"。

实测（改前，真浏览器采样 101 个顶点）：
```
顶点法线与径向夹角   最大 0.02°   平均 0°
```

**这同时解释了两件事**：
1. 老板问的「全填充」为什么没用 —— 空壳是**看不见的**（单面渲染 + 背面剔除 + 相机恒在球外），填了只是多 9.9 万顶点、画面零变化；
2. 「换 Lambert 受光材质」为什么也会白做 —— Lambert 拿径向法线算，只会得到**一颗光滑的球**（与现有昼夜线同一个结果），山脊山谷照样一样亮。

## 二、改法（三层，全在渲染层）

| # | 改前 | 改后 | 为什么 |
|---|---|---|---|
| ① 法线 | `nor.push(dx,dy,dz)` —— 径向 | 三角面法线**面积加权累加** → 按**方向跨面焊接** | 面法线叉积模长 = 2×面积，天然加权；六片 cube-sphere 在公共边有重复顶点，必须焊接，否则沿六条大圆出现接缝亮/暗线（正是老板最反感的"色斑"类） |
| ② 明暗 | 只有昼夜线（径向 `dot(径向, 太阳)`） | 保留昼夜线**一字不改**，另加一条**按真法线**的起伏项 + 曲率遮蔽 | 昼夜线是球级的；起伏是地形级的 —— 两件事分开算，互不污染 |
| ③ 近景 | — | 起伏强度按**海拔淡出**（≥520 全量、≤210 归零） | 逐顶点明暗贴近地面后被放大成"刷痕"（实机 zoom 0.13 取证），近景细节应归地块层 |

**材质仍是 `MeshBasicMaterial`**，这是有意的：场景那四盏灯（太阳强度 3.2）一旦真正参与，会把整颗球打爆成白，并连带改变地表建筑/单位的观感 —— 那是另一件事，不在 P0 范围。

### 为什么还要"法线夸张"和"曲率遮蔽"

首版只做了「真法线 + 方向漫反射」，实测山地区域局部对比度**只 +10.7%**，肉眼觉得"差不多"。这不是代码没生效，是**物理上限**：朝向太阳的那一片，法线偏 10° 时 cos 只掉 2%；天顶附近无论怎么夸张法线都不会出现明暗（cos 在峰值导数为 0）。补两条：

- **法线夸张**（制图学常规）：切向分量 × `M.RELIEF_EXAG`（默认 2.0），`tanθ' = 2·tanθ` → 平均偏离 10.3° → 16.9°；
- **曲率遮蔽**：顶点高程 − 邻点平均高程 → 谷地压暗到 0.74、山脊最多提亮到 1.06。**这条与太阳方向无关**，把"背光那片仍然平"的死角补上。

两者共用一个闸门 `uRelief`，`M.setRelief(v)` 一个数全关/全调（老板"一个数调手感"的出口）。

## 五、P1 追加：片元级细节法线（近看颗粒）

### 为什么不能直接加 `normalMap`

球体是 **`MeshBasicMaterial`**，three 的 `normalMap` 只对受光材质生效 —— Basic 会**静默忽略**。
加了属性、画面零变化，和"换 Lambert"是同一个坑。所以改成**自己采样、自己扰动**：
把已有的细节灰度贴图（`makeDetailTex('globe')`，384²）当**高度场**，在注入的片元里做 1.6 纹素步长的
有限差分求梯度 → 切线空间法线 → 用球面 TBN 扰动顶点法线，再算受光。

### 两层分工（本轮的结构要点）

| 层 | 信号源 | 闸门 | 生效距离 |
|---|---|---|---|
| 起伏明暗（P0） | 顶点法线（三角面累加 + 跨面焊接） | `uRelief`（按海拔淡出） | 远/中景 |
| 细节颗粒（P1） | 片元采样高度场求梯度 | `uDetail`（独立） | 近景 |

**首版踩的坑**：把细节扰动塞进 `_rel`、与浮雕共用 `uRelief` 闸门 → 近景浮雕淡出时颗粒**一起死**，
实测 zoom 0.13 增益 **0.0%**。拆成 `_relV`（顶点法线）与 `_relD`（细节法线）两个量后，近景才真有颗粒。

### 另一个坑：纯方向明暗必然整幅变暗

加浮雕后实测 **P90 掉 15%**（cos 是凹函数：坡面朝光的收益小于背光的损失）。修法不是削斜率（那是削立体感），
而是**除以平均曝光**：

```
系数 = (0.70 + 0.46·relV) / (0.70 + 0.46·pivot)      pivot = 全球顶点 relV 均值
```

`pivot` 在 `applyLight()` 里按当前太阳方位重算（9.9 万顶点抽 1/5 ≈ 2 万次点积）。归一化后对比度一分不少，
平均亮度回到 1.0（实测略亮 3~9%：枢轴按整球算，可见半球更朝阳）。

### 细节层实测（同源 A/B）

首版参数（`DETAIL_REPEAT 96` / `amp 0.22`，见下表前两行）：

| 视角 | 局部对比度 | 均值 | 削顶 |
|---|---|---|---|
| zoom 0.13（贴地） | 2.06 → 2.41（**+17.0%**） | 46.4 → 46.2 | 0 |
| zoom 0.22（中近） | 4.88 → 5.43（**+11.3%**） | 71.6 → 70.7 | 0 |

细节层**只压暗不提亮**（`1 − amp·max(0, relV − relD)`）→ 永不削顶；mipmap 把远景高度场压平时差值为 0，
远景既不脏也不整体变暗。

### ⚠️ 事故与修复：近景规则网点（老板截图「有斑纹」）

**现象**：贴地视角下地表出现一片**等间距小圆点**（老板截图与我 3 倍放大同型），整幅像蒙了层网。

**根因两条叠加**：
1. 高度场复用的是 **384² 颜色细节图 —— 非二次幂**。WebGL1 下 NPOT 的 mipmap / `RepeatWrapping` 会退化，
   而 `DETAIL_REPEAT` 高达 96 → 高频欠采样 → **摩尔纹**（典型形态就是规则点阵）。
2. 那张噪声只有 8/16/32 三个**规整格**，格点被高倍放大后本身就是等间距的点。

**修复三件**（`makeGrainTex()`，只给法线用，不碰地形配色）：
- **512²（POT）** + `LinearMipmapLinearFilter` + `anisotropy 4` → mipmap 正常，欠采样消失；
- **互质格 6/15/37** 叠加（不同格不对齐，抵消彼此的周期）；
- **域扭曲**：低频场（5 格）把采样坐标推开 ±6% 格 → 格点被揉散。

外加两处定档（扫参得出，不是拍的）：`DETAIL_REPEAT 96 → 120`、`amp 0.22 → 0.12`。
中间试过 40/60/90：贴地视角是**大块迷彩斑**（比网点更难看），120 才是细颗粒。
`repeat` 同时改成 uniform（`M.setGrainRep(v)`），以后调尺度不必重建包。

**修复后实测**：zoom 0.13 增益 **+9.5%**、zoom 0.05（贴地放大）**−0.9%**（该距离下颗粒已是亚像素，
mipmap 自动抹平 —— 这正是"不再有斑纹"的结果）；肉眼检查：无网点、无重复花纹、无迷彩斑块。

### 第二处病灶：**地表层**（老板「还是有规律斑纹」）

第一次修复只动了**球面**的颗粒图，但同一张 `384²` 规整格噪声还被**地表层**用着：

```
js/map3d.js:2216   var dt = makeDetailTex('surf'); dt.repeat.set(28, 28);
```

它当颜色乘子贴在贴地地形上 —— 于是**同一团纹样按固定间距重复**（老板截图 4 倍放大后能看清是同一个钩状小纹样
在斜向格点上一遍遍出现；自相关峰在 (dx 23, dy 10) 处 0.31）。

现在地表也走 `makeGrainTex('c')`（域扭曲 + 互质格 512²），**颜色模式必须保持 0.74~1.0 区间**，否则地表整体变暗。
断言 `§589i` 钉死"地表不许再用 `makeDetailTex('surf')`"。

> 时间线也要记一笔：老板那张截图的时间戳是 **00:31**，而第一处修复的包 **01:0x** 才生成 ——
> 那张图拍的是**修复前**的版本。全档扫描（10 个缩放档）现在只剩 zoom 0.02 的水面区域有 0.51 的峰，
> 陆地各档在 0.02~0.14（噪声量级）。

### 旋钮

- `M.setRelief(v)` —— 起伏明暗（0 关 / 1 默认）
- `M.setDetail(v)` —— 细节颗粒（0 关 / 1 默认 / 上限 2）
- `M.RELIEF_EXAG` —— 法线夸张系数（默认 2.0）
- `M._detailAmpU.value` —— 颗粒压暗幅度（默认 **0.12**；0.22 贴地偏脏、0.30 压暗 12.6% 越红线）
- `M.setGrainRep(v)` —— 颗粒尺度（默认 **120**；uniform，可运行时调）


### GLSL 两个必踩点（记下来省一轮）

1. **`int * float` 非法**：`18 * uDetail` 在 GLSL ES 1.0 直接编译失败，必须写 `18.0`。
2. **`float x = normalize(vec3)` 类型不符**：`normalize` 返回 vec3，声明成 `float` 会报
   `'=' : dimension mismatch`。两处都是静态检查发现不了、只有真机加载才暴露的。

## 六、诚实缺口

1. **close 档仍偏"糊"**：顶点色 + 7×7 细节贴图在近景被放大，是 v155 以来就有的问题，本轮没碰。真要改善得上更高分辨率的地形贴图或 triplanar，属另一件事。
2. **地块层不跟随明暗**：起伏明暗只作用在球面；六边形地块是独立网格，贴地放大时"底下有阴影、上面是平的"这种错位在小尺度可见。因为近景已淡出，实际影响很小。
3. **四盏场景灯仍是"空转"**：这是有意保留（见 II-材质段）。真要接入必须同时重调全部光照与地表材质，风险远大于收益。
4. **`M.RELIEF_EXAG` / 0.74~1.06 这两组系数是"看着定"的**：判据只有"对比度上升 + 不打爆 + 不变暗"。若老板觉得"太脏"或"还不够立体"，改 `M.setRelief()` / `M.RELIEF_EXAG` 即可，无需改着色器。
5. **像素判据的 ROI 是固定的**（中央区域），换视角/分辨率需重设；本次三视角共用同一 ROI（球体在各视角都覆盖该区域）。

## 二、修掉的 bug：「回本城 / 回主城 / 灰烬城」只拉近、不转向

### 玩家看到的现象

点底栏「回本城」→ 画面没有转到城，城反而被推出视野。
城格的屏幕纵坐标从 **0.66**（画面内）变成 **1.05**（出画面）。

### 根因

```js
// js/map3d.js  M.centerOn（修复前）
camO.yaw  = Math.atan2(d[0], d[2]);
camO.pitch = ...;
camO.dist = R * 1.9;  _syncZoom();   // ← 只有这一行真的生效
```

而 `M.CAM_TRACKBALL = true`，`placeCamera` 里刷新姿态的判据是：

```js
var _dirty = M.CAM_TRACKBALL ? !camO.quat : (!camO.quat || yaw 变了 || pitch 变了);
```

轨迹球模式下 **`camO.quat` 才是真值**，只要它有值就**不会**按 `yaw/pitch` 重建。
于是 `centerOn` 改了 yaw/pitch 等于没改，只有 `dist` 生效 —— 「拉近但不转」。

### 修法（3 行，不新开出口）

```js
camO.yaw = ...; camO.pitch = ...;
/* v158.16：轨迹球模式 quat 是真值，必须清掉姿态缓存让下一帧重建 */
camO.quat = null; camO._euler = null; camO.dir = null;
camO.dist = R * 1.9; _syncZoom();
```

与全代码库既有 **7 处**同一写法（`camO.quat = null; camO._euler = null;`），不手写 quat、不改相机口径。

### 验证

| | 修复前 | 修复后 |
|---|---|---|
| 城格 NDC | (0, 0.66) → 点完 (0, **1.05**)，出画面 | 点完 **(0, 0)** 精确居中 |
| 已探明工业格在画面内 | 0 块 | **33 / 33 块** |
| 能精确点中的格 | 0 块 | 10 块（其余被地形高度差 1~2 格） |

## 四、发现但未改（要老板拍板，都是设计/口径）

### 1. 街区里看不到自己（v158.2 遗留）

街区有地面、建筑、NPC，但**没有玩家自己的角色**。野地视角那个橙色小人很醒目，进街区就消失了。

原因：主角模型由 `M.followAvatar` 画在**球面坐标系**（`p.dir * (R + h)`），
而街区相机在 `D.frame` 的局部空间里 —— 两套坐标系不重合，主角不在画面内。

### 2. 进了街区走不出去

`D.step` 把坐标 clamp 在 `plan.bounds`，唯一出口是 Q（直接回高空）。
玩家顺着街走到边界会被无形墙顶住，没有任何提示（实测走了 3.5m 撞到碰撞体就停）。

### 3. 「回本城」只动相机不动人

人物视角下站在野地点它：镜头转到城了，人还在野地（`ci` 不变）。
P0 之前「相机 = 玩家视角」，按钮移相机等于移玩家；有了独立位姿之后这条链路断了。

### 4. 未探明格没有勘探入口（可发现性断点）

- 点**已探明**的森林 → 有「资源地块 · 未勘探」+ 🔍 勘探
- 点**未探明**的森林 → 弹出「⚔️ 森林 Lv10」**出征面板**（侦查/掠夺/占领），**没有资源地块区**
- 开局已探明只有 **61 / 40962 格 = 0.15%**

所以玩家按「城外」页的引导（"找一块带工业价值的地，走近后勘探"）去找地，
点下去看到的是一个打仗界面，**没有任何字告诉他"先派兵侦查"**。

断点在引导文案，不在功能 —— 但玩家过不去就是过不去。

# v157.46 · 软摩擦解锁：从「攒够 3 胜」到「撞到才开」

> 老板：「执行你认为正确的决定，但务必给出正确的评估」
> 本文只讲这一刀做了什么、验证到什么程度、以及**它没解决什么**。

## 一、问题

`ui.phaseOf()` 的出口只有一个：`n <= 1 && wins < 3 → early`。
这道门后面关了 **14 个账本小节**，而其中 12 个系统从第 1 个月就在 tick
（v157.40 的 25 年快进实测给了证据）。

也就是说：**门不是在藏功能，是在藏「已经在运行的系统」的数值。**
玩家在吃污染 / 民怨 / 距离衰减的亏，账本却不给那一行，只会觉得「产量莫名其妙变少」。

## 二、改法

`ui.gatedOut(need)` 是唯一闸门（1 处定义、1 处调用）。在它里面插软解锁层：

```
late        → 仍按里程碑（真后期内容，不剧透）
阶段已达标  → 全开（不变）
early       → 逐条看软触发；触发过 → 开；否则仍灰
```

| 小节 | 触发 |
|---|---|
| 🎯 作战目标 | 任一城有兵 |
| 🛣 领土连通 | 城 ≥ 2 |
| ☢ 污染 | `TN.stats().warn + bad > 0`（与摘要同源） |
| 🔥 民怨 | `UN.lineOf() !== ''`（有城民怨 ≥40） |
| ☁ 辐射云 | **直接放行**（它是时钟，永远有话说） |
| 其余 6 条 + 2 条 late | 里程碑不变 |

- 触发过写 `state.gates[id] = 1`，**单调**：拆了作坊也不回灰。
- 谓词 try/catch，异常一律当「没开」——不许一个坏谓词炸掉整页账本。

## 四、诚实的评估

**改好了什么**

1. 灰行不再是一句笼统的「再打几场」——每一条软触发都写清**它缺什么**。
2. 玩家吃到的亏，账本当场能指出来（污染/民怨/距离衰减）。
3. 修掉两笔旧账：v157.45 那条自相矛盾的断言、账本里过期的「圈心在你所有城的重心」文案。

**没改好什么（这是重点）**

1. **第一小时体验几乎没变。** 新档 5 条触发全为 false，界面和昨天一样（只多了一行辐射云）。
   我上一轮说「把锁着的东西放到玩家面前是最有价值的一步」——**这句话只对空间站成立**，
   对账本这 14 条是「信息问题」，不是「内容问题」。
2. **6 条仍在门后**（废墟科技/伤兵老兵/守城工事/地下远征/指令牌/套装指令）：
   没有可靠字段判定「玩家撞到了它」。按 §十三，G1/G2 不过就不该动。
3. **`shop` / `collection` 两个页签仍锁。** 没有「玩家需要它」的判据；
   提前放出来只会看到空页，比锁着更像坏了。
4. **没测渲染耗时。** 计划里写了「≤ 改动前 +20ms」，实际只凭手感（无延迟）。
   这是计划自己列的验收项没做全，记在这里，不遮掩。

**下一步该做什么（不是继续调门控）**

第一小时的问题是**没有东西可玩**，不是**东西被锁着**。
要做的是 P1：把遗迹 / 村社 / 危险区从面板列表搬到地表上，走过去才触发。
那才同时喂饱「探索」和「种田」。

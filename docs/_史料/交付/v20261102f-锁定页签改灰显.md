# 锁着的页签：从「看不见」改成「在但锁着」

> 老板 2026-11-02：「顶上还是把游商啥的搞没了」

---

## 一、问题

开局（`early` 阶段）顶栏少了三个页签：**空间站 / 游商 / 收藏**。

这不是 bug，是 v150 的设计：`ui.syncPhase()` 给这三项加 `.tab-locked`，CSS 一句

```css
.topnav .tab-locked { display: none; }
```

藏掉，理由写在注释里 ——「让第一小时只露出这一小时该做的事」。

但**玩家视角是另一回事**：菜单凭空消失 = 坏了 / 没做完 / 我是不是少买了什么。
而且 `syncPhase` 里明明写了：

```js
/* 锁着的时候给一句为什么（悬停）：不解释的隐藏＝玩家以为坏了 */
if (locked) tabs[i].setAttribute('title', '站稳脚跟后解锁：' + ...);
```

**`display:none` 的元素悬浮不到** —— 这句解释永远看不到。等于写了一句安慰自己的注释。

---

## 二、改法：在场，但锁着

### ① CSS：藏 → 灰

```css
.topnav .tab-locked {
  opacity: .52;
  filter: grayscale(1);
  cursor: not-allowed;
}
.topnav .tab-locked:hover { opacity: .72; color: var(--text-dim); }
```

（第一版写 `.38`，1024 宽下"游商 / 收藏"淡到读不出字 —— 调到 `.52` 才既明显是"锁的"又看得清是什么。
**这个值不是审美问题，是"读得出字"的下限**。）

### ② 点击：进不去，但给一句人话

```js
// js/main.js 顶栏监听
if (tab.classList.contains('tab-locked')) {
  ui.toast('暂时进不去：' + (ui.gateWhyText ? ui.gateWhyText() : '先站稳脚跟'));
  return;
}
ui.setView(tab.dataset.view);
```

灰着点了没反应，和藏起来没反应，对玩家是一样的。所以要**说出来**。

### ③ 无障碍：`aria-disabled="true"`

`syncPhase` 里跟 `title` 一起加/删（解锁时两个一起清）。

## 三、实测

### 三档宽度都不换行

`.topnav` 是 `flex-wrap: wrap` —— 多三项会**换行**而不是溢被裁。所以必须量：

```
1440px   顶栏高 49   行分布 {13 项同一行}   右侧工具区右缘 1428   溢出 0
1180px   顶栏高 40   行分布 {13 项同一行}   右侧工具区右缘 1170   溢出 0
1024px   顶栏高 35   行分布 {13 项同一行}   右侧工具区右缘 1015   溢出 0
```

三档都是**单行 13 项**，无溢出（项目基准 1180 也稳）。

### 点击行为（真实浏览器）

```
① 锁着时点「游商」  view: city → city
   toast=[暂时进不去：再打几场、或再开一座城就解锁]
② 解锁后（3 胜）  locked=false  title=无
   点「游商」→ view=shop  首屏=[🛒 游商 · 材料…]
```

锁着点不动且有话，解锁后照常进 —— 两个方向都验了，不是"只看能进"。

## 四、断言

### §573② 改口径（正反两问）

```js
// 改前
&& /\.topnav \.tab-locked \{ display: none; \}/.test(h9);

// 改后：① 真做了灰显 ② 不许再用 display:none 躲回去
var m9 = /\.topnav \.tab-locked \{([\s\S]*?)\}/.exec(h9);
var css9 = m9 ? m9[1] : '';
staticOk = staticOk
  && /opacity\s*:\s*\.?\d/.test(css9)
  && /grayscale\s*\(/.test(css9)
  && !/display\s*:\s*none/.test(css9);
```

### e2e 新增一条（行为，不依赖当前阶段）

锁/解锁状态在判据里**手动摆**，不读 `phaseOf()` —— 否则换个存档就假红：

```js
shop.classList.add('tab-locked');  → 点 → 视图不变 + toast 含"暂时进不去"
shop.classList.remove('tab-locked'); → 点 → 真的进了 shop
```

起点若已在游商页先切走 —— 否则"解锁后进去了"恒真（判据自己骗自己）。

## 五、踩的坑：e2e 其实跑在 jsdom 上

第一版用 `shop.getBoundingClientRect().width > 0` 判"看得见"，直接崩：

```
💥 测试主流程异常（已中断）：getComputedStyle is not defined
   结果：142 通过 / 1 失败     ← 后面 900+ 条根本没跑
```

两件事：

1. **`getComputedStyle` 没有全局**，得写 `window.getComputedStyle`（e2e 里其他 5 处都是这么写的）；
2. **jsdom 的 `getBoundingClientRect()` 恒返回全 0** —— 判"可见"不能用宽高，只能看计算样式 `display` / `visibility`。

而且这种崩法是**最坏的**：它让整轮 e2e 只跑到 142 条就停，却被统计成"1 失败"，
看起来像"只红了一条"。日志里那句 `⚠ 本次运行在中途中断` 才是真正的信号。

> 判"通过"之前先看一眼**总条数**对不对：条数掉了就是中断，不是通过。

## 一、射程回落修复（需求 4 下半 · 真 bug）

### 1.1 病根（老板实测复现）

老板日志（战报沙盘帧流）：
> 全局 2300 · 敌军轻骑兵 前进 875 · 我军弓箭手 前进 267（最近距离 1,733）……

- 我弓**默认目标 = 同兵种弓箭手**（v89.149「弓打弓」老板令）→ 引擎按"到目标（长枪/敌弓）的距离"判定开火
  （实测该目标 1733 > 射程 1200）→ **只前进**；
- 而**最近敌人轻骑距我弓 1158 ≤ 1200**（射程内）→ 引擎**视而不见**（`actSide` 的指定目标段**无条件覆盖
  最近目标**，没有射程检查）。
- 引擎注释自己写着"原版语义：指定目标不在射程内 → 打射程内任意目标"——但该口径只对"拆箭塔"实现过。

### 1.2 修法（tactic.js `actSide` 两处）

```js
/* 旧：只要目标存活 → 无条件改选它 */
if (pref) { rec = pref; bestGap = 到 pref 的距离; }
/* 新（v89.192）：目标**须在射程内**才优先；不在 → 回落"打射程内最近的" */
if (prefGap <= effRange) { rec = pref; bestGap = prefGap; prefInRange = true; }
/* fireOnce 调用处：preferId 同步改为"仅射程内才传"（否则会跨射程去打它） */
preferId: prefInRange ? u.target : '',
```

### 1.3 探针实证（probe_v89192a_range.js · 5 场景）

| 场景 | 改前 | 改后 |
|---|---|---|
| ① 目标长枪 1733（外）· 轻骑 1158（内） | ❌ 只前进不开火（复现老板现象） | ✅ **打轻骑**（49 杀） |
| ② 目标在射程内（1100）· 轻骑更近（575） | 打目标 ✓ | ✅ 打目标（指定优先保留） |
| ③ 无目标 · 轻骑在射程内 | （同 ① 走默认目标） | ✅ 打轻骑 |
| ④ 都在射程外 | 前进 | 前进（不变） |
| ⑤ 目标灭失 | 打最近（v89.164 既有最优） | 打最近（不变） |

### 1.4 平衡对照（probe_v89192c_balance.js · 同 seed 单变量）

| 场景 | 改前 | 改后 |
|---|---|---|
| 步重（枪×4） | 21 回合 · 交换比 1.09 | **零变化**（目标即最近，无从生效） |
| 骑重 | 14 回合 · 1.13 | 零变化 |
| 弓重 | 17 回合 · 0.92 | 零变化 |
| **混编（枪盾弓骑）** | 30 回合 · 我损 7037 / 敌损 7154 · 比 1.02 | **23 回合 · 我损 5069 / 敌损 8000（全歼）· 比 1.58** |

**结论**：修复只影响"目标≠射程内最近"的混编场景，效果为**正**（我损 −28%、战斗更快、交换比提升）。
**连带**：smoke §94 载重用例的靶从 Lv1~3 收窄 Lv1~2（Lv3 沼泽属临界局、胜负可翻转 · 摆局适配非放宽断言）。

## 二、观战补历史（需求 2）

**病根**：战斗按 `battleSec` 后台照打；玩家中途点「观战」时 `ui._bt.lastRound` 直接初始化为**当前回合**——
前面已发生的回合**从未渲染**（#bt-log 只有斗将行）。

**修法**：`_makeEnv(rec, collectSteps?)` 加可选收集参（重放时收集每回合 `{r, gap, events, snap}`）+
`ui.btReplayHistory(rec)`（打开观战时用**同一个回合块出口** `ui.btRoundLine` 从最旧补起、
每块插顶部 → 倒序 [N,…,1]，与实时路径完全一致）。**零额外成本**：读档恢复本就重放一遍，
只多收集；已有会话时新增一次毫秒级重放（≤30 回合）。

**实证**（实机）：后台推进 3 回合后点观战 → `#bt-log` 含
`第 3 回合 / 第 2 回合 / 第 1 回合` 三个回合头（倒序）✓；探针另证"重放态与权威会话同源"（784/143 == 784/143）。

### 5.3 诊断（三条）

**D1 · 消耗与功能是否成正比？**

- **基本成正比**的：治疗（10 金 ≈ 1/24 义兵造价，廉价救兵）；加速（对价 = 批量价值 20%、有 30% 天花板——"钱能买时间、买不了全程"）；税所（500/日 ≈ 1/9 座县城岁贡——小补定位 ✓）。
- **偏离的**：
  1. **商城/经验道具的价格锚**：单份总价 2.9 万 vs 单城税收 5 万/日——**"买光商城"只需半天收入**；千古兵圣 4000 金 ≈ 单城税收的 1/12 日——**金→成长的兑换比过高**（对齐参考：OSRS bond "钱换时间需克制"）。
  2. **爵位金价与 rep 门槛错位**：金 5000 万（顶档）但 rep 门槛 10.5 亿——**金到了、rep 到不了** → 顶档大 sink 实际"锁死"（中后期金无处去）。
  3. **中层 sink 空洞**：万~百万金区间**没有"正发展为对价"的出口**（建筑/募兵**完全不花金**：[粮木石铁] 表无金列）——参考口径"高等级升级需要海量金币"在本游戏**不成立**。
- **结论**：金"能消耗"吗——**中前期能（月俸+杂项），中期起堆积**（D2 印证老板"黄金价值升高"的观感）；"全部动作可跳过"吗——**大体不能**（节钺不可买、加速 30% 上限、行军/战斗/研究均无金加速），**唯一大口是经验道具**。

**D2 · 为什么"黄金价值升高"**（老板观感的机制根源）

- 金入账**每秒连续**（税收 + 卖资源容量），大额支出**只有月俸**（且"付不起就欠"不惩罚）；
- v89.189 前据点掠夺"面板 981 万/次"（虽被静默蒸发 bug 吞掉）**放大了观感**；修复后为 19.6 万/次；
- 商城价格体系停留在"义兵 240 粮"时代的量级，**没有随收入曲线重标**。

**D3 · "全部可跳过"风险评估**

| 动作 | 能否用金跳过 | 现闸 |
|---|---|---|
| 建造/募兵等待 | 部分（≤30%） | `BOOST_CAP` ✓ |
| 研究等待 | **不能**（无加速出口） | — |
| 行军 | **不能** | — |
| 战斗 | **不能**（必须真打） | — |
| 将领成长 | **能**（经验道具 12 档、无限制） | ⚠ 唯一大口 |
| 资质/编制/顶档 | **不能**（节钺"只能打出来/赐下来"） | ✓ 设计正确 |

### 5.4 建议（待拍板 · 按"推荐度"排序）

**S1 ★★★ 给建筑/城墙加"金"成本（Lv9 起）**——对齐参考"高等级升级需要海量金币"+"情境化 sink"：
- 方案：`levelCost` 第 5 列（历史时间列）复用为金成本，Lv1-8 = 0（保前期流畅）、Lv9-12 递增。
- 示例档（单座/级）：Lv9 = 3,000 · Lv10 = 6,000 · Lv11 = 12,000 · Lv12 = 24,000（12 级后封顶同值）。
- 效果量级：一座城 ~15 座建筑升 Lv9-12 ≈ **30 万金**；3 城 ≈ 90 万——恰好对上"月俸同级"的日流量。
- 成本：改 `costTable` 一处 + 断言（含"Lv1-8 零金"护栏防误伤前期）。

**S2 ★★★ 经验道具价格对账**（保"追赶"、去"跳级"）：
- 方案 A（推荐）：价格上浮 ×5（兵圣 4000 → 2 万；治军 192 → 960；练兵经验 8 → 40）——仍可买（前期加速），但"一天收入全买"从"几十本"降到"几本"；
- 方案 B（备选）：维持价目 + 每日限购（商店 1 本/档/游戏日）。
- ⛔ 不回到"等级上限闸"（v89.173 老板已撤）。

**S3 ★★ 奢侈/荣誉 sink（不伤平衡）**——对齐参考"珍稀收藏品定期以游戏币拍卖（好评最高）"：
- 可加 2-3 件"金买不到的强度、买得到的面子"：如「大都督仪仗（城徽/金匾）」「宗庙祭器」「年号金印」——
  大额一次性（10-100 万）、纯荣誉/外观。

**S4 ★★ 月俸与收入的比值复核**（数值对账，非新增）：
- 现状月俸是唯一大 sink（10 将 253 万/现实日），**但有"欠俸不罚"兜底** → 养"闲将"几乎零成本。
- 建议：欠俸进入**忠诚/效率**的软惩罚（比对参考"维护费型 sink 必须有真实约束"）——**影响面大，需老板拍板**。

**S5 ★ 维持现状的项（销项）**：
- 加速 30% 上限 / 节钺不可买 / 行军战斗不可跳 / 治军 10 金每兵——**已符合"不全可跳、保持实感"**，不动。

## 七、诚实缺口

   可能与史实不一致（`verify=false → "画面仅示意"`）——新战报全部同源正常；

4. `genSalaryOf` 的四维权重与 rankMul 未逐档复核（本轮核到量级）；
5. 观战补历史在"已结束战斗"上仅走战报路径（战场界面关闭后不可重开——既有设计）。

# v158.60 · 斜坡相机穿模根治

> 老板原话：「在斜坡处，改变相机角度仍然会出现地底下的画面，穿模。解决穿模问题」

## 一、取证：先量出来，别猜

`p_diag_v15860_slope.js` 在 61.6° 陡坡上绕一圈 × 5 档仰角 = 60 个角度：

| 指标 | 旧行为 |
|---|---|
| 近平面切坡（真穿模） | **60 / 60** |
| 相机周边 1~2m 地形相对机位的径向余量 | 最低 **−2.5m**（等于埋进坡体） |
| 机位中心离地 | 0.12m（只有这一点被硬闸保住） |

**根因**：旧硬闸只保「机位中心这一个点」，而 near 平面 = `max(1, d×0.002)` ≈ 0.6~1.74m。斜坡上机位周边 2m 内的地形远高于相机 → 近裁剪面直接扎进坡体，画面下半透出地形内部。观感就是"看到地底"。

## 二、三条弯路（记录在案，别再回头）

| 尝试 | 结果 |
|---|---|
| ① 环形包络抬升（8 方位 × 4 环，抬到周边最高地形之上） | 陡坡把相机顶到 **22m 高**，画面被整个坡面填满（实机图全屏粉褐、看不见人） |
| ② 精确求抬升量（对近平面采样） | 离散采样必然漏台阶 → 平地仍报 **23 个角度切坡** |
| ③ 视线收缩 + 净空抬升交替 | 两个判据互相改写对方前提，收敛不了（抬升后视线又穿） |

三条弯路都源于同一个错位：**把"不穿"当成"抬高到某条线之上"**。真正要的是"存在一个位置，站在那里近平面不碰土"。

## 三、定稿：沿视线从远到近求一个"三项全过"的位置

`_surfCamFit(A, want, up)` 成为唯一出口，对每个候选机位检查：

1. **机位本体不埋土**：`margin ≥ 0.25`
2. **近平面 3×3（含四角）不切地形**：`margin ≥ 0.2` ← 这是"看到地底"的直接成因
3. **锚点→机位路径不穿坡**：每 0.6m 采样 `margin ≥ 0.05` ← 坡脊不许夹在中间

扫描**从远到近**（`t = len → 0.9`，步长 0.35）：先保视角，不行才收。全部不可行（锚点卡在陡坡死角）才沿径向抬升，上限 6m。

### 顺带修掉的真 bug

**锚点贴球壳用了玩家高度**：坡上滞后跟随 1.2m 时，锚点方向的地形可能高出 1.3m，沿用玩家的 `R2` 贴壳 = 把锚点埋进坡里（走动态实测视线穿坡 **−1.27m**）。改成按锚点方向自己的地形高 `max(_aGh, _ppH)`。

### 断言处置

- **新增 §623⑩**：锁唯一求解出口、三项阈值的具体形态、从远到近的扫描方向、抬升兜底上限、锚点贴壳按地形高；**反向禁止** `_surfCamClearLift` / `_surfCamSightPull` / `SURF_CAM_CLEAR` 三段旧补丁复活。
- **§614① 整条重写**（规则变更，不删不放宽）：旧判据锁的 `multiplyScalar(R2 / _aL)` 正是被修掉的病根，改为锁 `_aGh` 形态并反向禁止旧形态。

## 五、诚实缺口

- **陡坡 + 最低仰角（3.4°）时画面仍被坡面填满**（实机图 `v15860-A` 全屏地面）。这是几何必然：从这个角度看向坡，坡就在眼前；不穿模，但看不到远景。要看清远景只能抬仰角或站到坡的另一侧。
- 抬升兜底（≤6m）只在锚点卡在陡坡死角时触发，此时是"俯视特写"，不是原视角。
- 真鼠标拖动的垂直档只测到 el 0.74→1.13（拖 240px），更低仰角由 60 角度扫描覆盖。

# v157.78 · 高空左键旋转没有死角

**老板原话（2026-11-16 12:33）**

> 为什么高空地带左键旋转星球的时候还有死角，就是还有一个地方是无法跨过的？不是说好的全方位吗？

---

## 一、取证：不是 clamp，是几何衰减

用真浏览器连续拖拽，逐步记录相机位置方向 `dir.y`（`= sin(纬度)`）：

```text
向上拖（一把到底）：
  0.4078 0.1709 0.0371 … -0.8909 -0.9127 -0.9281 -0.9303 → -0.8637
                                                        ↑ 到这儿停住并回头
向下拖：
  0.4078 0.6584 0.7492 … 0.9239 0.9297 0.9314 → 0.9295 0.924 …
                                                ↑ 同样停住回头
```

**卡在 ±0.93（≈±68.6°）就推不动了**，极点永远到不了。代码里**没有任何** ±68.6° 的 clamp，所以不是限制，是几何：

抓取式旋转（v157i「揪住球面一点」）用**射线与球面的交点** P0/P1 算旋转。相机在球外（`dist = 870`，`R = 300`）时，球的最上/最下缘在屏幕上被压成极窄一条 —— 鼠标拖到那里，交点几乎不动，**灵敏度衰减到 0**。

而 v157h 早就定过一条能滚过极点的口径：

> 「纬度不 clamp，p 可以无限增长 → 仍能从北极滚到南极连成一个圆；渲染时 dir 由 sin/cos 现算，越界自动折回，不会跳。」

**是 v157i 换成"抓取"时把它覆盖了。**

---

## 二、改法：抓取与增量按位置自动接管

`js/map3d.js` 左键拖动段：

```js
var _edgeA  = Math.asin(Math.min(1, _R0 / Math.max(1, cam.position.length()))); // 球在视野里的角半径
var _angP0  = _P0 ? acos(normalize(_P0) · normalize(camPos)) : Math.PI;          // 抓点离球心角
var _useStep = !M._surf && (!_P0 || !_P1 || _angP0 > _edgeA * 0.86);
```

| 情形 | 走哪套 | 行为 |
|---|---|---|
| 抓点在球面内侧（≤0.86×球角半径） | **抓取**（v157i 原逻辑，未改） | 跟手：揪住的地面点随光标走 |
| 贴边 / 打到球外 | **增量** | 竖拖改纬度、横拖改经度 |
| 地表模式（抓地砖） | 抓取 | 不参与这套 |

增量这一段是关键，写了两版才稳定：

```js
camO.pitch += _sdy * _K;
camO.yaw   -= _sdx * _K;
var _nP = Math.floor((camO.pitch + Math.PI / 2) / Math.PI);   // 跨了几次极点
if (_nP !== 0) { camO.pitch -= _nP * Math.PI; camO.yaw += _nP * Math.PI; }
```

**为什么要"离散归一化"而不是简单反射**：v156.55 记过一版"反射折叠"——每帧在 ±π/2 边界反复穿越，`yaw` 每穿一次加 180°，实测冲到 98 圈、画面震颤。
这里用「离散步数」：一次把 pitch 扣回 `(−π/2, π/2)`、yaw 补 `n×π`（等价姿态）。跨一次只翻一次，之后必须再转半个 π 才会跨下一次 —— **不会在边界横跳**，北极→南极→回北极能连成一个圆。

同时删掉了一段死代码：「边缘打空 → 退回单位球」分支（它在新判定下永不执行，且单位球在屏幕球外会把方向按 `1/|v|` 折回边缘，本身就是死角的一半成因）。

| 层 | 判据 |

   mousedown 没命中 canvas、`drag` 没置 1，测出来"怎么拖都不动"，白查一轮。

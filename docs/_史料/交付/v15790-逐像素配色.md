## 一、先算硬约束，再动手

| 量 | 数值 |

| 顶点间距 | (πR/2)/128 ≈ **3.7 世界单位** |

## 二、改法

| 项 | 内容 |
|---|---|
| 图集 | 4N×4N（4×4 格，用 6 格）；N=256 → **1024²（二次幂）**，mipmap 正常 |
| 求色 | 逐纹素 `sphBiome(e, dy, dir, true)` —— 与顶点**同一条出口**，配色不漂移 |
| 采样 | 顶点加 `aFace`；片元 `vAUv = (uv·(1−1/N) + 1/(2N) + cell) / 4` |
| 顶点色 | 退化为**明暗系数**（1.15 / 0.90），已探索提亮机制原样保留 |
| 缓存 | 按「种子+精度」缓存；globe 每次重建复用，不重复烘 |

## 三、踩的两个坑

1. `FACES.forEach(function (fn) {...})` **没有面号参数** → 顶点循环里 `fi` 未定义，页面报 `fi is not defined`。加 `(fn, fi)`。
2. 面边界 `uv=1.0` 时**采到隔壁格的纹素** → 六个面各一条细黑线。修法：**半纹素内缩**。

## 六、诚实缺口

1. N=256 是「2 倍顶点精度」，边界明显变顺但非无限平滑；N=512 为 4 倍，代价是烘焙约 6 秒 + 图集 16MB。
2. **海岸线锯齿还在**：那是**水面网格**（按水格的六边形拼）决定的，需按高程等值线裁剪水面，本轮未动。
3. 黄褐区有**方向性噪声**（地形自身 `fbm3` 纹理，不是采样错位）；若嫌"刷痕感"，要调 `sphBiome` 的高频项，属另一处。

# v157.51 · 门禁按功能区块分开

> 老板：「门禁太长了，能不能按功能区块，把门禁也分开」
>
> 可以做，但先说清一件事：**9 个脚本本来就是并发跑的**，墙钟 = 最慢那个（smoke 8~11 分钟）。
> 所以"再并发"没用，唯一能砍的是**根本不跑无关的那几块**。

## 一、能砍的和不能砍的

| | 结论 | 原因 |
|---|---|---|
| 脚本之间 | 已经并发 | v156.19 起 9 个进程同时跑，墙钟 = 最慢一个 |
| `smoke`（4455 条） | **不能切** | 共享可变 `GAME.state` 的剧本；实测 4 分片合计 2483 条 vs 全量 4408 条，语义不等价（AGENTS.md 早有记录） |
| `e2e`（1104 条） | 能按域选择跑不跑 | 独立进程、真实 DOM，本身 4~5 分钟 |
| 结构审计（L0） | 20 余秒 | 只读源码，与行为无关 |

于是方案是：**按"改动落在哪个功能区块"决定跑哪一组验证**，而不是把 smoke 切碎。

## 二、分区表

`.workbuddy/tools/git/domains.json`：改动文件 → 区块 → 该区块的探针/测试（+ 秒级 L0）。

| 区块 | 覆盖文件 | 验证组合 | 实测耗时 |
|---|---|---|---|
| `light` | （任何改动都先跑） | audit + 数据表卫生 + dataset + 兵种链 + 旧币出口 | **25 秒** |
| `camera` | `js/map3d.js` `scene3d.js` `sphere.js` `planetgen.js` `land.js` | L0 + `cam_regress`（13 项实机行为） | **26 秒** |
| `battle` | `battle.js` `tactic.js` `duel*.js` `trooplv.js` `fleet.js` … | L0 + `invariants-test`（守恒律属性） | **26 秒** |
| `pop` | `growth.js` `muster.js` `village.js` `market.js` `taint.js` … | L0 + `invariants-test` | 26 秒 |
| `ui` | `js/ui-*.js` `main.js` `index.html` 图标/位图 | L0 + `e2e-test`（真实 DOM） | **~5 分钟** |
| `space` | `ui-space.js` `colony.js` `belt.js` `relic.js` `ruin.js` | L0 + `e2e-test` | ~5 分钟 |
| `full` | 核心文件 / 跨区块 / 未登记代码 | 三件套全量 | **~11 分钟** |

核心清单（改了就回全量）：`state.js` `domain.js` `core.js` `data.js` `systems.js` `cities.js`
`main.js`（主循环/事件/版本号）`smoke-test.js` `e2e-test.js` `audit.js` `chain-audit.js`
`invariants-test.js` `gate.py`。

## 三、保守规则（宁可多跑，不可漏跑）

只有**全部改动都落在同一个区块**才降级；以下任一情况回全量：

1. 命中核心清单；
2. 改动跨 2 个及以上区块；
3. 改动含 `js/**` 里**没登记**的文件（新文件默认保守）；
4. `--full` 或 `GATE_FULL=1`。

实测判定（`--dry`）：

```
$ gate.py --files js/map3d.js --dry
改动全落在「相机 / 3D / 地表」区块 → 只跑该区块（全量：GATE_FULL=1）

$ gate.py --files js/state.js --dry
改动涉及核心/跨区块（改动命中核心文件 js/state.js）→ 全量

$ gate.py --files js/map3d.js js/ui-city.js --dry
改动涉及核心/跨区块（改动跨 2 个区块（camera/ui））→ 全量
```

提交钩子 `pre-commit` 调的是 `gate.py --staged`，所以**自动按暂存文件选区块**；
不放心就 `GATE_FULL=1 git commit ...`。

## 四、camera 区块为什么能替代 smoke

`js/map3d.js` 在 smoke 里有 380 条相关断言，但绝大多数是**源码形态**（正则/字符串存在性）。
真正会坏的是行为，而行为已被 `cam_regress` 覆盖（本次顺带从 10 项扩到 13 项）：

| 判据 | 说明 |
|---|---|
| A1 | 低空半径 = R + 眼高（地形不参与） |
| B1/B2 | 高空右键必须改变朝向 |
| C1/C2 | 地表模式可进、右键仍能转 |
| D1~D3 | 96 方位半径差 ≤ 0.01、滚轮下限覆盖 |
| E1 | 停手 3.6 秒零漂移（无自动抬头） |
| **F1** | 滚轮灵敏度曲线单调、相邻差 < 12%（按高度，不按滚轮位移） |
| **F2** | 跨 62 米阈值相邻档视线变化 ≤ 40°（旧实现一格 75°） |
| **F3** | 切模式点地表层 fade ≈ 0（不叠半透明地形） |

F1~F3 是本次新加的行为判据 —— 以后改相机，"手感"这件事第一次有了可跑的断言。

**代价（必须知情）**：camera 区块不跑 smoke，所以那 380 条源码断言不覆盖。
发版前、或改动触及渲染契约（`TURN` 表 / `_surfRight` / 地表淡出参数）时用 `--full` 补一次。

## 五、命令

```
npm run gate:list        # 看区块
npm run gate:light       # 25 秒
npm run gate:camera      # 26 秒
npm run gate:ui          # ~5 分钟
npm run gate:battle      # 26 秒
npm run gate:pop         # 26 秒
npm run gate:space       # ~5 分钟

python .workbuddy/tools/git/gate.py --domain=camera --dry   # 只打印计划
python .workbuddy/tools/git/gate.py --full                  # 全量（发布/核心改动）
```

## 六、验证

- `--light` 24.9 秒通过；`--domain=camera` 25.6 秒通过（含 cam_regress 13/13）；
  `--domain=battle` 25.5 秒通过（invariants 40/0）。
- 判定矩阵四条（camera / core / ui+docs / 跨区）逐一 `--dry` 核对。
- 全量未变：钩子对核心改动仍跑 5 个测试 + 5 个审计脚本（本次提交即验证）。

## 七、诚实缺口

1. **ui 区仍要 5 分钟**（e2e 本身长）。想更快只能拆 e2e —— 它是真实 DOM 的串行剧本，同 smoke。
2. **smoke 依然 8 分钟**，核心改动一分不少。这条地板由"4618 条断言共享一个进程"决定，
   要动只能重写测试架构，不是本轮范围。
3. 分区表是**人工维护**的：新加 `js/xxx.js` 必须同时登记，否则落回"未登记 → 全量"（保守，不会漏）。

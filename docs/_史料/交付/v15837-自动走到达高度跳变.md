# v158.37 · 自动走到达瞬间「高度跳变」修复

> 老板原话：**「存在高度跳变。」**
> 本轮不引用任何"已实现"结论，从真实开局逐帧取证 → 定位 → 修复 → 三闸门回归。

## ① 病根（一句话）

自动走 `stepWalkTo` 的**到达阈值写死 0.6m**：角色走到距目标格心 0.6m 时，直接把位姿锁到目标格心（含高度采样），
在陡坡上这 0.6m 的水平瞬移对应 **0.518m 的单帧高度跳变**，相机半径跟着跳 0.528m —— 这就是老板看到的"高度跳变"。

**不是**自然地形噪声、**不是**键盘走路、**不是**相机跟随：三者逐帧实测都连续（见③）。

## ② 改法

| 项 | 改前 | 改后 |
|---|---|---|
| 到达阈值 | 字面量 `if (dist <= 0.6)`，埋在分支里 | 具名常量 `M.WALK_TO_ARRIVE_M = 0.02`（2cm），分支读常量 |
| 到达方式 | 距目标 0.6m 就锁格心（水平+高度一起瞬移） | slerp 走完最后一段到 2cm 内，高度仍逐帧走 `_groundAtUnit` 唯一出口 |
| 阈值来由注释 | 无 | 常量处写明"0.6m 在 38° 坡上跳 0.518m/0.528m，收紧到 2cm 让 slerp 走完" |

**唯一出口纪律**：高度仍只由 `M._groundAtUnit(nd)` 采样 → `M.setPlayerPose` 写入，到达帧与行走帧同一条路；
没有新增第二套高度写入，也没有把 `p.h` 直写成某个快照值。

改动文件：
- `js/map3d.js`：新增 `M.WALK_TO_ARRIVE_M = 0.02` + 分支改用常量（含墓碑式注释写清来由）。
- `smoke-test.js`：`§613③`、`§619③` 两条旧断言锚点从 `if (dist <= 0.6)` 同步到新口径（**规则变更重写，不删不放宽**）；
  新增 `§620①~③`：阈值具名常量且 ≤0.05m（挡 0.6m 回退）/ 判据只读常量（无第二魔法数）/ 两处高度都走 `_groundAtUnit` 不旁路直写。
- 三包按 `gen_index.js` → `build_bundle.py` 顺序重建，`index.html ?v=` 同步 `6f46d6f5`。

## ⑤ 诚实缺口

- **进地表一次性落地**：`migrateAvatar158()` 初始化 `_avatar.h = 0`，进地表后第一帧贴地被修正到真实高度
  （实测 `h:0 → 8.686m`，`gap=0`）。这发生在角色**尚不可见**的模式切换瞬间，不是走路观感跳变，本轮**未改**；
  若要连这一下也消掉，需在 `surfaceMode(true)` 入口统一贴地（仍走 `setPlayerPose` 唯一出口），属另一处改动，待老板定夺。
- **单 seed 取证**：探针固定 `mapSeed=20261127`，但真机每次开局地形不同；已确认"阈值收紧"与地形无关（所有坡度 slerp 都走完最后一段），
  未做多种子方差扫描。
- **flaky 探针**：`p_click_e` 用固定 500ms 等待 + 随机目标格，偶发 1 红；本轮复跑 3 次确认非产品问题，未改探针（保持历史口径，避免掩盖真实回归）。

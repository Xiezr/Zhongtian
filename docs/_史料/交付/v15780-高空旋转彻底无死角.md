# v157.80 · 高空左键旋转真的没有死角了

> 老板（第二次问，第一次修过但没修对）：
> 「为什么高空地带左键旋转星球的时候还有死角，就是还有一个地方是无法跨过的？不是说好的全方位吗？」

## 一、先说上一次为什么没修对

v157.78 我判定「抓球面交点在球边缘灵敏度衰减」，加了「抓取 / 增量按抓点离球心角自动接管」。
实测确实能从 ±0.93 走到 ±0.99——但**玩家拿到的还是卡**。因为你说的「死角」不是一个原因，是三层：

| # | 层 | 现象（实测） |
|---|---|---|
| ① | **抓球面交点** | 相机在球外（870/300）时，球的最上/下轮廓在屏幕上被压成极窄一条，拖到那儿交点几乎不动 → `dir.y` 单调爬到 **±0.93（≈±68.6°）** 就停住并回头 |
| ② | **arcball 球外死区** | 换成屏幕→单位球（TrackballControls 同款）后球内均匀，但圆外点一律按 `1/\|v\|` 投到赤道，沿径向拖方向不变 → 「从画布左下斜拖到右上」130 帧里 **34 帧完全不动** |
| ③ | **总根源：placeCamera 每帧反算** | `camO.pitch = asin(camO.dir[1])` **无守卫、每帧执行**。`asin` 主值域是 `[−π/2, π/2]`，于是玩家累积出来的 pitch 一旦越过 ±π/2（= 滚过极点），下一帧立刻被折回 → **极点附近来回打转，怎么拖都过不去** |

第 ③ 条是真正的「死活角」：v157.78 的「跨极点归一化」也是被它反复折回的，
所以才会出现「某轮拖了 3.2° 就不动」——这次探针直接抓到 **pitch 稳稳停在 −1.592，
130 帧累加 3.25 弧度一步没生效**。

## 二、还有一个更隐蔽的 bug（顺带修了）

排查时发现：**慢拖松手会被当成「点击」**。

```js
if (Math.abs(dx) + Math.abs(dy) > 3) moved = true;   // 单帧位移
```

只看**单帧**位移。慢拖（每帧 1~3px，高空精细对位时的常态）永远不达标 → `moved` 恒 false →
`mouseup` 的 `if (!wasDrag || moved) return;` 不 return，继续走点击逻辑 → 点在野地上就**弹出出征面板盖住地图中央**。

实测：141 步 × 3px 连续上拖，`moved` 全程 false，松手后 `document.elementFromPoint(画布中心)`
从 `CANVAS` 变成 `DIV.exp-sec exp-a-est`。**那片区域之后就再也收不到 mousedown** ——
这本身就是第二个「无法跨过的地方」。

修法：累计位移也参与判定（`>4px` 即算拖动）。单帧 >3 保留（快拖立即识别），
手抖 1~2px 的真点选仍按点击处理。

## 三、改法

### 3.1 轨道旋转 = 球坐标双角度纯累加，不归一化

```js
if (!M._surf) {
  var _sdxv = e.clientX - _prevX, _sdyv = e.clientY - _prevY;
  var _K = 0.005;                 // 弧度/像素：拖满一屏约 180°
  camO.pitch += _sdyv * _K;
  camO.yaw   -= _sdxv * _K;
  camO.quat = null; camO._euler = null;   // 让 placeCamera 按 yaw/pitch 重建
}
```

**为什么这样就通**：`placeCamera` 的求向公式是

```
dir = ( cos(p)·sin(y),  sin(p),  cos(p)·cos(y) )
```

`p` 越过 ±π/2 时 `cos(p)` 自然变负，dir 平滑绕到球的另一侧。
**这个公式本来就支持无限累加**，根本不需要「折回/翻转」的补丁。

### 3.2 placeCamera 的反算加守卫

```js
if (camO.dir && M._surfVis === true) {   // ← 只在"刚从地表退回"这一次
  camO.yaw = Math.atan2(camO.dir[0], camO.dir[2]);
  camO.pitch = Math.asin(...);
}
```

轨道模式下 pitch/yaw 完全由输入维护，不再被任何反算覆盖。

### 3.3 退役的东西（不留死代码）

`_useStep` / `_edgeA` / `_angP0`（抓取-增量双分支）、`_nP` 归一化三行、`_arcVec`（arcball 映射）
全部删除。地表模式（`M._surf`）的抓地砖分支**保留**——那里语义是「抓地面」，不是「转球」。

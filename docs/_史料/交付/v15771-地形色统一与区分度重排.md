## 二、取证（先量后定，没先改渲染主路径）

### 2.1 源码：同一份地形信息曾经有三套口径

| 口径 | 位置 | 实际消费者 |
|---|---|---|
| ① `DATA.TERRAIN[t].color` | `js/data.js:2236` | **全仓 grep 零消费者**（只读 `.name` / `.buildable` / `.add` / `.move`）→ 死字段，且还是旧土黄绿 |
| ② `TERRAIN_RGB` 字面量 | `js/map3d.js:503` | 3D 星球 globe 顶点色 `buildCellColors()` + 纹理 `sphBiome()` |
| ③ `TERRAIN_TINT` 亮/暗双色 | `js/map.js:1116` | 2D 方格图立体地块（v45 已按老板拍板原则重排过） |

`map.js:1145` 的 v45 注释早就写下过同一句诊断：「七种地形塌成了两个色族，族内几乎分不开」，
并确立原则 **「色相拉开 + 明度分档 + 同名色相时用饱和度兜底」**。
但那次只改了 ② 之外的 ③，② 从未同步，① 一直没人读 —— 这是同一个问题第三次出现（v45 野地区分度、v155c「对比也差」、本轮）。

### 2.5 根因链

1. 七色本身塌成 1 个色族（最小 RGB 距 32.1、最小亮度差 3.2）；
2. `buildCellColors()` 的四层叠加（海拔 / 坡度 −22% / 气候 ±16 / 两轮 35% 邻域平滑）**放大类内方差、压缩类间距离**；
3. `paintGlobeFog()` 对未探明格统一乘 `0.34`，而实机默认新局 **99.85% 未探明** → 屏幕色差再被等比砍到 1/3；
4. 三套配色各说各话，改任何一处都不解决另一处。

## 四、明确不改什么（守已拍板口径）

- **不动 `paintGlobeFog()` 的 `0.34` 两态**（v157.68 老板「要边界感，而不是在视野内增加渲染」）。
  未探明区仍均匀压暗、仍不泄露地形情报、仍不铺任何加亮几何。改的是**已探明区**能不能认出来。
- **不动 `map.js` 的 `TERRAIN_TINT`**：那是 2D 方格图的亮/暗双色（立体地块），不是同一维度，
  且 v45 已按老板原则重排过。
- **不动 `_markers` / `_cellTint` / 邻域平滑 / 涂色层**：已取证排除为「分不清」的主因，
  动它们等于在视野内加渲染，方向相反。
- 不新建图例、不加按钮、不写新制度。

## 五、断言（`§586m` 五层，带下限防平凡解）

| 层 | 判据 |
|---|---|
| ① 源码面 | `map3d.js` 是派生 IIFE、字面量已消失、`data.js` 含 v157.71 墓碑 |
| ② 数据面 | 真解析出 **7 个 HEX / 21 组两两距离**，最小 ≥60、平均 ≥130 |
| ③ 旧近色对 | 三对旧近色全部 ≥60（只改注释 / 悄悄调回旧值都会翻红） |
| ④ vm 真调行为面 | 抽出派生 IIFE 在独立 `GAME` 上真调两次：真实 DATA → 7/7 逐位同源；塞哨兵色 `#123456` → 结果必须跟着变（防「派生其实是写死一张表」） |
| ⑤ 保留面 | `paintGlobeFog` 两处 `0.34` 仍在、`v157.68 两态` 注释在、`_fogLit` 墓碑允许留但**不许复活成赋值** |

**为什么不直接读 `GAME.map3d.terrainRGB`**：smoke 的 node 桩没有 THREE，`map3d.js` 走
`enabled:false · why:no-three` 降级分支（`map3d.js:143`），只挂 9 个降级 API，`terrainRGB` 根本不注册 ——
首版断言据此假红。改用 vm 真调后比读运行时更强，且不受桩限制。

**顺带修掉的旧守卫缺陷**：`§586k 保留面` 把「四个消费点在岗」和 `GAME.VERSION = 'v157.70'` 锁死，
每升一版就假红（v157.69→70 已手动改过一次）。改为解析数值下界 `verN >= 69`：
以后 v157.72 / v157.80 都不假红，但版本被清空或倒退仍会翻红 —— 不是删断言、不是放宽成永真。

## 七、诚实缺口

1. **未探明区仍然暗**。老板截图里 51.6% 的低饱和灰像素主要来自 `fog=0` 的 `×0.34` 压暗，
   按 fog 设计那本来就是「未知」、不该给地形情报（`buildFlags` 里明写「未探明的地方不显示，否则等于免费探图」）。
   本轮改善的是**已探明区**的地形辨识。若连未探明区也要能分辨地形，等于改 fog 口径、会免费探图，
   且撞 v157.68 刚拍板的边界感 —— **属于需老板拍板的项，本轮未擅自改**。
2. **新色比旧色饱和度高**。总览实机图里绿/黄绿/沙橙更鲜明；这是「拉开色相」的必然代价，
   大气云壳与未探明压暗会在实际游玩视角里柔化，但若觉得偏艳，可单独降饱和再跑一次色差对账。
3. `DATA.TERRAIN.color` 目前仍只被 3D 派生消费；2D 面板/图例若要用地形色，需要另接一次
   （本轮未加，避免顺手改未被点名的界面）。
4. `TERRAIN_TINT`（2D）与 `DATA.TERRAIN.color`（3D）仍是两套数值，但语义不同（立体双色 vs 单色），
   不算口径冲突；已在此写明，避免后人误判。

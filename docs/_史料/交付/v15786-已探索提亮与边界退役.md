## 三、新增：已探索提亮（`paintGlobeExplore`）

```js
已探明格 → 原色 × M.EXPLORE_LIT (1.15)
未探明格 → 原色 × M.EXPLORE_DIM (0.90)      // 相对差 1.28 倍
```

三个必须做对的细节：

1. **从原色乘回来**（`M._globeColBase`），不是就地累乘 ——
   否则每推进一次迷雾就再亮 10%，走两步整颗球就白了。
2. **顶点级软插值**（c0 / c1 / 权重 t，由 `_cellColorSoft` 顺手写出）——
   直接按"最近格"二值提亮会得到一圈六边形硬边，等于把删掉的边界线换成更丑的锯齿。
3. **`buildGlobe` 末尾必须补画一次** —— 见下一节，这是本轮踩得最深的坑。

系数为什么是 1.15 / 0.90 而不是只提亮 1.10：实测只提亮 10% 时，
近景（agl 140）整屏亮度差 < 3%，人眼读不出"这片我探索过"。
给一个相对口径后交界处 1.28 倍差，一眼能分。

## 四、踩坑实录：提亮"改了但不上屏"

第一版加完，探针读顶点色是对的（已探明 `[0.205,0.476,0.289]` vs 原始 `[0.18,0.42,0.255]`，
正好 ×1.14），但**截图完全看不出**。把 `EXPLORE_LIT` 压到 **0.05**（已探明区应该几乎全黑），
画面依然正常 —— 这时才确定不是"系数太小"，是**改动没上屏**。

定位方法：把 `M._globe.visible = false` 截图 →

```
"正在构建星球…  100%"
```

**每次 `renderMapCanvas` 都在重建 globe**。而 `buildGlobe` 会用 `sphBiome` 的原色
重建整条 `color` 属性；fog 版本没变 → `buildFog()` 不会再被调用 → 提亮被静默抹掉。
读 CPU 侧的 `attributes.color` 时看到的却是"改过的值"（重建发生在读取之后、下一帧之前），
所以数值断言全绿、画面全不变 —— 典型的"测到了中间态"。

修法：`buildGlobe` 末尾（`M._globe = globe` 之后）补一次 `paintGlobeExplore()`。

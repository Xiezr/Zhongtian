## 三、执行方向（开工前锁定）

- **一个出口**：`GAME.resource` 是资源地块唯一读写口；`GAME.extGridOf(city)` 是产量链 / 仓容链 / UI 的唯一取材口。
- **只读投影**：迁移态下 `extGridOf` 每次返回 `RS.plantsOf()` **现算的新数组**，形状对齐旧 `extGrid`（`type/lv` + `richness/deplete`）——
  于是 `prodBasePerHourOf`、`extStoreCapByResOf`、`extUsed/extSummary`、自动升级候选**一处不改就乘上丰度**。写它不落档（smoke 有专测）。
- **两把尺**：储量扣减按**理论产出**（基础×丰度），入账产量还要乘环境折扣（连通/严寒/污染，实测 ×0.906）——断言不许互比。
- **不新开经济**：建/升/拆复用 `checkBuildSlot / payCostIn / city.queueAdd('build', …) / applyBuildDone`，只换"目标怎么定位"。
- **确定性派生**：丰度与储量由 `seedOf(ci)` 播种，同格永远一致且**不入档**（存档 <1MB 全线守住）。

## 五、随模型退役（不是偷懒，是新模型下的必然）

1. **改建**（`convertExt / extConvertCost / EXT_CONVERT_RATE / openExtConvert / 'ext-convert' / 'ext-convert-ask'`）整条清 ——
   一块地能建哪种厂由**地形资源**决定（森林→生物质→只有水培温室），"改成另一种类型"没有合法目标。要换用途 = 拆（返还半数）再建。
2. **堆场格子数上限**不再有意义（地块来自星球地形），`ensureExtGrid` 不再是"自动补空地"的活路径。
3. 旧堆场渲染/建造链（`buildExt/upgradeExt/demolishExt/extSlotOrder/extNextLvOf` + `openExtModal`）**保留为 `MIGRATE_EXT=false` 的回退路径** ——
   它是迁移开关的另一端，不是死代码；**迁移确认永久后下一轮整条清**（清单见上）。

## 七、坑（写下来防复发）

1. **投影上的写操作会静默失效**：`extGridOf` 变投影后，所有"往返回数组上塞地块 / 改 lv / 改 type"的老造局都不报错但没效果 ——
   smoke 里统一换成 `mkPlants()` 造局助手（真写 `RS.placePlant`），e2e 里换成 `RS.set`。这是本轮假红的最大来源。
2. **`autoUpgrade` 候选原读 `ct.extGrid`** → 迁移后永远升不到城外（真回归，靠 §167/§21 的断言抓出来），改走 `extGridOf` 并按 `e.ci` 分派。
3. **建造读秒用例原走 `G.buildExt(空地槽)`** → 槽位不存在报"地块不存在"；`buildProgress` 新增 `'plant'` 分支（按 `q.ci` 匹配），读秒口径（`X% · MM:SS`）不变。
4. **smoke §606 在文件末尾跑**，`GAME.state` 已被几十个 fixture 折腾过 → 必须自带一局（固定种子）造局，否则假红。
5. **拆除施工中的厂**会留下一条"落成写到空地"的队列 → `dismantlePlant` 加施工中禁拆（旧城外口径本来也禁）。
6. **断言里的全局计数**（`op-zone-eq` 恰好 6 处、`costLackMsg` 恰好 5 处）会因为新增面板而红 —— 按规则变更改成"锚在具体函数/具体新增点"，不是放宽。
7. 地形放宽要**分两步看**：占比够了不代表成片；出生点 ±5 内的地形种类才是玩家感受的那把尺（`plainAlt 0.55` 时占比 11.68% 但连片过大 → 收回 0.50）。

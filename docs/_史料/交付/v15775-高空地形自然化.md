# v157.75 · 高空地形配色自然化 + 消除六边形硬边

## 一、需求（老板逐字）

> 「目前高空中看的话，这个地块儿地形的颜色有一点别扭，就是太非自然了，他们的边界锯齿状啊或者怎么样，就是一种比较别扭的一个。渲染方式」

两件事：**颜色太非自然** + **边界呈锯齿/拼贴感**。

## 二、诊断

### 2.1 颜色太非自然 = v157.71 拉过头了

v157.71 为了「分得清」把七色按 v45 原则拉到极限，平均饱和度冲到 **0.504**
（湖泊 0.82 / 森林 0.70 / 荒漠 0.67）—— 高空看像「假彩卫星图」而不是地表。

### 2.2 锯齿 = 每顶点硬取最近格

`buildGlobe` 的顶点色走 `sphBiome`：

```js
var ci = SP.nearestCell(d);          // 硬分配最近格
var cc = M.cellColorOf(ci);          // 取该格唯一颜色
```

于是每种地形都成了「一块块六边形硬边色块」。`buildCellColors` 的两轮邻域平滑是在**格与格**之间做的，
但顶点→格是**硬映射**，所以格边界仍是硬切的 —— 高空看就是拼贴 + 锯齿。

## 三、改法

| 项 | 处置 |
|---|---|
| `DATA.TERRAIN.color` 七色 | 统一按自身亮度**降饱和 0.72 倍**（色相、明度分档都不动） |
| `_cellColorSoft(d, ci0, dot0)` | 新增：取最近格 c0 与**次近邻** c1（必在 `SP.adj[ci0]`，最多 6 次点积），按「谁更近」插值 |
| `sphBiome(..., soft)` | 加 `soft` 分支；**只有 globe 顶点传 true**，地表近景三处仍硬边 |
| `§586m` / `§586p` 断言 | 按新口径重写 + 新增接线守卫 |

### 3.1 为什么混合要限幅到 0.28

首版按「边界处 t≈0.5」直接混满，实机 `agl=110` **整屏糊成一片**、没有层次。
原因是 `buildCellColors` 已经在**格级别**做过两轮 35% 邻域平滑，顶点级再混 0.5 = 平滑了两次。
改成 `t = min(t, 0.5) * 0.56`（上限 0.28）：边界台阶软化一半，地块内部的明暗/纹理留住。

### 3.2 性能坑（首屏构建卡在 100%）

`_cellColorSoft` 首版调了两次 `M.cellColorOf()` —— 它每次都走 `buildCellColors()` 的
**版本缓存校验（拼三段字符串再比）**。99846 顶点 × 2 次 → 首屏「正在构建星球…」卡在 100% 出不来。
改成直接读已建好的 `_cellCol` 数组后恢复正常。

## 四、实测数字

| 指标 | v157.71（高饱和） | v157.75（本轮） | 参照：v157.70 之前 |
|---|---|---|---|
| 平均饱和度 | **0.504** | **0.388**（−23%） | — |
| 最小两两 RGB 距 | 62.5 | 52.8 | 32.1 |
| 平均两两 RGB 距 | 142.7 | 124.0 | 113.2 |

降饱和的代价是最小 RGB 距从 62.5 掉到 52.8，但仍**远高于** v157.71 之前的 32.1。
`zhaoze-forest`（52.8）这一对本来就不靠 RGB 距分，靠色相青/绿（约 48°）+ 饱和度 0.24/0.54。

## 五、断言（规则变更三件套）

- `§586m 数据面`：下限从「最小 ≥60 / 平均 ≥130」调到 **「≥50 / ≥115」**，
  并**新增平均饱和度上限 ≤0.45** —— 防「下一轮为了好辨认又把颜色调回假彩」。
- `§586m 旧近色对`：`zhaoze-forest` 下限单独放到 50（另两对仍 60），注释写明原因。
- `§586p 接线面`（新增）：`_cellColorSoft` 存在、顶点调用传 `soft=true`、分支闸门在、
  **反向证据**：三处近景调用 `sphBiome` **不得**传 soft（否则地块会糊掉）、
  插值公式 `a0/a1` 与 `t` 归一仍在（下限，防把函数掏空换绿）。

## 七、诚实缺口

1. **顶点密度是硬上限**：globe 是 cube-sphere K=128（约 99.8k 顶点）、格有 40962 个，
   平均每格才 2 个多顶点 —— 软混合只能把「硬台阶」软化成「浅台阶」，做不到真正的连续渐变。
   要更细就得把 K 提到 192/256，但顶点数 ×2~4、`buildGlobe` 与 `paintGlobeFog` 都跟着变慢，
   本轮没动。
2. **`zhaoze` / `forest` 的 RGB 距只有 52.8、亮度差 3.9**：这对靠色相和饱和度分，
   在极高空 + 远距离时仍可能并成一团；要更稳得单独调这两色的明度（会牵动 `§586m` 阈值）。
3. **降饱和与「分得清」本质上是拔河**。本轮把上限压到 0.45，如果后面又觉得「认不出」，
   正确方向是**调明度分档**而不是加饱和度（断言已禁止后者）。

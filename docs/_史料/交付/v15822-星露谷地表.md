# v158.22 · 操控一小人走在地面上（星露谷样板）

> 老板原话：「星露谷不就是场景样板了吗，什么真的假的，这个那个。操控一小人走在地面上这么难？」

## 结论先说

**难的不是"走"，是"人根本不存在"。**

真实玩家（清档开局 → 滚轮拉近到地表）实测：

```
{"surf":true, "eyeAbove":5.7, "playerCi":-1, "figPos":null}
```

`playerCi = -1`、小人图元 `null` —— **地图上连自己都没有**。
之前几轮所有「小人在画面里 / 能走 / 能点」的验证，都是探针先调 `teleportTo` 造出来的假象。
这轮把三个根因全部修掉，并用**真滚轮 + 真按键 + 实机截图**验收。

## 三个根因

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| ① | 图上没有自己 | `migrateAvatar158` 只补 `_avatar`、**不回写 `_standCi`**；`buildFigures` 建人条件是 `_standCi >= 0`，`playerCi()` 也只读它 | 开局 `playerCi=-1`、`figPos=null` |
| ② | 拉近看到的地不是自己脚下 | 地表层以 `camO.dir`（高空镜头落点）为中心重建 | 小人方向 `(-0.50,0.31,-0.81)` vs 相机视线 `(-0.51,-0.46,-0.72)`，**差 571 米** |
| ③ | 站在湖水里，四周全蓝 | `pickStartPos` 第四轮兜底把「本州任意地形」当备胎 | 出生格 `type=lake`，周边 40 米 **155 格全是水**，顶点色 `(34,65,130)` = 湖水深蓝 |

## 六处改动（全部走既有出口）

1. **开局必有位姿**
   `migrateAvatar158` 回写 `st._standCi`；`M.playerCi()` 读侧补一次迁移（幂等）；
   渲染循环的 `ver` 与 `buildFigures` 都改走 `M.playerCi()`。

2. **出生点不许落水**
   `pickStartPos` 的**所有 return 收口到 `_land()`** —— 出水即用 `GAME._nearestLandCi` 就近换陆地。
   这是硬闸，不依赖某一轮判据写没写对。

3. **站位不压城格**
   玩家城的格地形仍是 `plain`（`city` 只标 NPC 城），所以按 `state.cities` 的 ci 表判断；
   撞上就把站姿挪到 **2 环外最佳陆地格**（1 环 5.25 米，8 米高的城楼仍会挡住 57° 俯角）。

4. **星露谷式地表相机**（`M._surfAvatarCam`）
   站在角色斜上方：**26 米 / 仰角 57°**，看着角色。
   `placeCamera` 的地表分支末尾接管，失败就落回原第一人称。
   **只读位姿**：不写 `camO.dist`、不写位姿（断言里有反向守卫）。

5. **地表 WASD 真能走**
   渲染循环的位姿推进从「只在 FOLLOW」扩到「FOLLOW 或 地表」；`main.js` 的 WASD 条件同步放宽。
   地表**不调** `followAvatar`（贴脸第三人称，老板连说两轮「像老年痴呆」）。

6. **小人每帧摆到连续位姿**
   摆人+摆腿抽成 `M.syncAvatarFigure` 公用出口；地表在 `syncFigures()` **之后**再摆一次
   —— 否则跨格重建会把小人拽回格心（一格 5.25 米的跳变）。

## 没动的（需要老板拍板）

**地表田垄线**：`M.SURF_LINES = false` 是老板 v157.56「线条太杂，不要边线了」定的。
现在对照星露谷，缺的是"一格一格的田垄"（能看到地块边界、知道能点哪）。
开/关是产品口径，不擅自推翻上一轮的明确决定。

## 一个坑（记下来）

`newGame` 不传 `mapSeed` 时走 `U.now() % 100000` —— **测试每次 run 都是另一颗星球**。
`§193②` 的「2 小时练出 300 兵」因此随机浮动（同代码一次 300、一次 232），
看起来像回归，其实是运气。**测试必须注入固定 seed**，否则会把随机当 bug 追。

## 一句话结论

**门禁能证明「代码做了你说的」，证明不了「你说的是对的」**。本轮没有新增任何门禁、断言或 Q，
只做了两件事：把体系里已经自承的零取舍缺陷清掉（项目本身），
把「机器铺地板 / 人守天花板」的分工和独立复核写进规则（review 方式）。
产品代码 0 行改动，玩家侧行为零变化。

**本轮最有价值的动作不是改了什么，而是复核挑出了什么**：按刚写进 §14.3 的通道做了一次
只读独立复核，抓到新增对账工具里的一个**平凡解**（空数据判过），已修并做了破坏测试。
这正是「一堆断言」查不出来的那类问题。

## 二、review 方式：落规则，不落门禁

### 2.1 `AGENTS.md` 新增 §十四

| 小节 | 内容 |
|---|---|
| 14.1 | 三层分工：**L1 地板**（机器 / 确定性 / 零误报 / 卡死）· **L2 趋势**（报告 / 不卡）· **L3 判断**（人 / 不设为门禁） |
| 14.2 | 意图校验 = L3 的入口：四段对账链 `老板原话 → 交付附件 → 验证段 → 点名的段号真的在测试里`；拿不出对照 = 在解决错的问题 |
| 14.3 | 独立复核通道：`实现 → 另一模型只读复核（不给辩护，专挑平凡解与答非所问）→ 人终审`，补体系自承的「自写自验自审」洞 |
| 14.4 | 平凡解专查：禁止为过闸写 trivial 测试、反向证据是标配、80% review 时间给 L3 |
| 14.5 | **防自我膨胀**：不新增 Q / 门禁项 / 断言 / 阈值 / 提交行为；拿不出对账链与复核记录，本节就是注脚，应当删掉 |

### 2.2 `docs/自检体系架构.md` §七

G6 从「仍冲突 · 二选一」改为「**判据冲突已消（已选 ① 观察器化）**」；
余下 ②（定时任务直接调 `gate.py`，1.5 → 11 分钟）保留为工程立项待拍板。
补边界句：观察器可以快、可以简、可以漏，但**不许冒充裁判**，唯一出口仍是 `git/gate.py`。

### 2.3 新增只读对账工具 `.workbuddy/tools/audit/intent_closure.js`

补体系自承的「无需求意图 → 断言闭环」缺口。硬边界写死：

- **只读**、**不进 gate**、**退出码恒 0**（异常也吞掉并退 0，绝不变成拦路的第 8 层）；
- 只列「断链 / 需解释」，**不判绿红、不结案、不替代老板**；
- 校准过真实形态：老板原话含跨行写法、交付附件含图片（截图轮不算缺陷）、
  段号只取 `§数字 + 圈号/字母后缀`，不被反引号和中文标点干扰。

**v1 → v2（独立复核后重写，见第四节）**：加数据下限 · 修自指误报 · 装饰判据退役 ·
复现命令按实际 `--last N`。修后 `--last 12` 实测「12 轮 · 需解释 5 项」，
本轮 v157.52 的原话 / 交付 / 验证 / 缺口四列齐、无自指断链。工具是照妖镜，不是判官。

# v89.122 · 「自动化 · 外敌来犯」开关失效修复

> 老板报：「自动化·外敌来犯看起来没起作用」

## ① 病根（一句话）

**写入端反置**：`doToggleInvasionAccept` 把当前的"接受"状态**原样写回**，
而判据是 `settings.invasion === false`（false = 拒战）——
于是点开关**状态不动**，而 toast/日志却报"已拒战"（**文字与事实脱节**）。

```js
var wasOn = GAME.invasionAcceptOn();   // 默认 true（接受）
s.settings.invasion = wasOn;           // ← BUG：写 true；判据要 false 才拒战 → 永远卡在"接受"
// 正确：
s.settings.invasion = !wasOn;          // 接受中 → false（拒战）；拒战中 → true（接受）
```

## ③ 为什么三闸门没抓住（断言测了一半）

smoke §98 的原断言**只摆 `settings.invasion` 的值再验"读"**：

```js
st.settings.invasion = false;  var off = !G.invasionAcceptOn();   // 测读 ✓
st.settings.invasion = true;   var on1 = G.invasionAcceptOn();    // 测读 ✓
```

—— **从未真调 `doToggleInvasionAccept()`**（写端零覆盖）。
读端没问题、写端反置，断言全绿、功能全坏。

**修法（断言侧）**：新增 smoke **③b**（真调两次 + 连**排期**一起验）：

```js
delete st.settings.invasion;                                  // 默认 = 接受
var a0 = G.invasionAcceptOn();  var du0 = G.invasionDueAt(c) > 0;
G.doToggleInvasionAccept();                                   // → 拒战
var a1 = G.invasionAcceptOn();  var du1 = G.invasionDueAt(c); // 排期必须消失（=0）
G.doToggleInvasionAccept();                                   // → 恢复
var a2 = G.invasionAcceptOn();  var du2 = G.invasionDueAt(c) > 0;
return a0 && du0 && a1 === false && du1 === 0 && a2 && du2;
```

要点：**不只验"变量翻转"，连业务效果（排期有无）一起验** —— 防"只翻变量不翻业务"。

## ⑦ 诚实缺口

1. 这类"写端反置"最阴的地方是**提示文案是照目标态写的**（点击后 toast"已拒战"是对的措辞），
   所以肉眼检查日志/提示发现不了 —— 只能靠"真调 + 验状态"。
   本仓的通用教训：**开关类断言必须真调切换函数**（读端断言的覆盖盲区）。
2. `settings.invasion` 字段名是"接受"语义（`=== false` 才是拒战），
   而非"拒战"语义（`=== true`）—— 命名有歧义，是本 bug 的土壤。
   因涉及存档字段与口径收口断言，**本轮不改名**（改动面不值得），已在 `doToggleInvasionAccept`
   顶部注释写清"写入目标态 = !wasOn"。

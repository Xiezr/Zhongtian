# AB 两个方案：先量，再决定做不做（结论：A 不值得做，B 拆不开）

> 老板 2026-11-02：「AB」—— 两个都做。
> 我先量了一遍，**A 的收益比我上次说的小 10 倍，B 的边界根本不存在**。下面是数据。

---

## 一、A「收敛冗余断言」：实测只能省 1.1%

`assert_density.js`：把 smoke 的 4114 个断言块切开，统计"每个被测对象被多少条断言引用"。

**第一版口径错了**，得出一份荒唐数据：`GAME.newGame` 被 358 条引用、`battle` 226 条、
推算"能砍 3123 条（75.9%）"。错在哪 —— **`newGame` / `currentCity` / `systems` 是测试脚手架**，
358 条断言都开一局，不等于"钉了 newGame 358 次"。拿脚手架当被测对象，什么都能砍。

**修正口径**（只统计界面层 `#id` / `.class` / `ui.*`）后的真实分布：

```
界面层被测对象 137 个
  ≥14 次      2 个   （#modal-root 31 · #city-attrs 16）
  6-9 次      1 个   （.gen-pane 6）
  3-5 次     25 个
  1-2 次    109 个
→ 被钉 ≥6 次的只有 3 个；若每个收敛到 3 条，共省 **44 条 = 1.1%**
```

**我上一轮说"预计能压掉 10~15% 的断言量"，是没测量的臆测，实际 1.1%。**
而 `#modal-root` 那 31 条各有各的被测内容（不同弹窗），不是冗余。
**结论：A 不做。** 收益 1.1% 抵不上改 44 条断言的回归风险。

## 二、B「灵机退役或隔离」：拆不开

| | |
|---|---|
| 开关 | `GAME.jianghuWildMounted = false`（v89.45「不体现在游戏中，但资产保留」） |
| 代码 | 114 处 / **9 个文件**（data · map · map3d · state · prologue · scene3d · ui-craft · ui-mapui · main） |
| 断言 | smoke **13** + e2e **6** |
| 玩家可见 | **零** |

**为什么"隔离"做不到**：那 13 条**不在一个段里**，散在 §72 / §73 / §326 / §353 等多处，
且与别的功能**混编**（§73 的标题就是「辐能双轨装备 **+** 荒野行动」）。
没有"灵机段"可以整体关掉 —— 只能一条条挖，每条周围还有 20~40 行准备代码。

**为什么"退役"也不划算**：删代码要动 9 个文件，其中 map3d 的悬旗渲染、prologue 的场景都牵扯
主渲染路径；而删掉的断言，将来启用时得凭记忆重写。

**所以 B 改成"登记 + 立规"**（已写进 AGENTS.md「已知但暂时不动的债」）：
留着、别再加；真要退役整块一起走，启用前必须补回这 19 条断言。

## 三、那"牵扯多"到底怎么解

A 和 B 都不解决痛点。痛点其实只有一句：**改之前不知道会牵动谁**。

这轮就是活例子 —— 删两个 span，漏了一处 `#map-info`，跑完 10 分钟全量才在 e2e 里炸。

所以做了这个工具：

```bash
node .workbuddy/tools/prof/who_assert.js "#map-info" mapPickText
```

输出（这轮的真实单子）：

```
════ 关键词 mapPickText ════
  smoke-test.js:1524  v156.37：地图底栏信息区整块退役（…四者全无）
  smoke-test.js:17703 v89.5：接线（render 调 drawJhPennant + jianghuSpotInfo）
  → 共 2 条断言牵动
```

**改之前先看单子，比跑完全量等红要快 8 分钟。**
这才是"牵扯多"的正解 —— 不是把断言合并掉（省 1%），而是让牵扯**可预知**。

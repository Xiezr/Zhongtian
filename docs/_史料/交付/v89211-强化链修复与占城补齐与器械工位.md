## 二、需求 2：占领县城后城内一格未建造（"猜测是仓库"）—— 实为城墙原格

**定位**：8×6 布局里 **idx37 = 第五行第六格**，正是**城墙**的原格
（仓库在 r1c4 / r4c6 / r5c4 / r5c5 四座，一座不缺 —— 老板猜的"仓库"位置不对）。

**成因**：v89.128 城墙改为**环城结构**（不占格）后，占城（onConquer）与读档迁移把
原墙格 `build=null` 释放 —— "打下的满配城"于是缺一块。v60 承诺的"满配城"不该有缺口。

**处置（v89.211 新规：释放格补建民房）**
1. 占城（battle.js onConquer）：原墙格 → **补建民房（同等级）**；
2. 读档迁移（state.js）：同口径改补建；
3. **存量档修复** `GAME.migrateWallCell211`（紧签名 · 一次性）：占来的城（origId）＋
   全建满只差**恰一格**且空位恰在墙位 ＋ 城墙在环城槽 → 补民房并写消息流；
   负例保护：玩家自建城（无 origId）、空格 ≥2（被动过工）、在建格（pending）**一律不碰**。

**注意（诚实缺口）**：已占城池若在此前版本已被释放成空格的，**本修复只对签名吻合者生效**
（恰一格空 + 在墙位）；若您已在那格上盖了东西/拆过别的建筑（空格 ≥2），不动 —— 可自行建造。

### 证据

## 三、需求 3：工匠作坊点"造投石车"却提示"本城尚无工匠作坊"

**病根（实锤）**：器械面板**显示**走 `ui.trainBarracks()`（陈旧格会自动回落首座 → 显示正常），
但**提交** `GAME.doTrain` 把陈旧的 `ui._trainBIdx`（**上次点的军营格**）原样交给 `GAME.train`
→ `craftLevel(城, 军营格) = 0` → 假报"本城尚无工匠作坊"。老板的县城明明有作坊（Lv12）。

**处置（三层防线）**
1. `open-siege` 入口：改传**本作坊自己的 idx**（按钮本就带 `data-idx`，此前被忽略）；
2. `ui.openTroops` 入场**归一**：陈旧/跨类 idx → 回落本城本类首座（显示与提交读同一份）；
3. `GAME.doTrain` 读**解析后**工位；域侧 `GAME.train` 防御回落（指定工位对不上而本城该级
   建筑存在 → 回落首座）；真无作坊的城仍原样拒绝 —— **提示与实际情况此时才相符**。

### 证据
- 探针 C：**改前 6/4 → 改后 11/0**（改前 ③a 复现老板原话"本城尚无工匠作坊，无法制造器械"）；
- 实机（真点链）：先开军营面板（污染 `_trainBIdx=18`）→ 开作坊 → 真点「造冲车/投石车等」→
  **归一到 22** → 真点投石车 → 真点提交 → **队列落在作坊 22（q22=1 · toudan）· 无假报**；
- e2e：`§211e① 入场归一` / `§211e③ 真点提交成功` 全绿。

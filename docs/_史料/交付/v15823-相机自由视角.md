# v158.23 · 星球固定、相机自由连续到任何角度

> 老板原话：「星球在场景中固定，只能移动相机的方向和位置，这回我相机视角应该能自由连续到达任何角度了吧」

## 结论

**还不能 —— 卡在一行代码上。** 现在能了。

## 病根（一行）

轨迹球分支本来已经正确地把拖动累积成四元数（这套数学能翻过任意极点）：

```js
camO.quat = _dqP.multiply(_dqY).multiply(camO.quat).normalize();   // ✅ 姿态本身
camO.pitch = Math.asin(_dvT.y);                                    // ⚠️ 只能表示 ±90°
camO.quat = null; camO._euler = null;   /* 让 placeCamera 按 yaw/pitch 重建 */  // ❌ 扔掉了
```

最后一行**无条件清空**刚累积好的四元数，让 `placeCamera` 按 `yaw/pitch` 重建。
而 `pitch = asin(dir.y)` 的主值域只有 **±90°**：

- 跨极点的信息（roll、以及"越过天顶之后继续走"）在这一步全丢；
- 拖过天顶只会沿原经线折回，**永远进不了另一半球**；
- 玩家体感就是"有个地方过不去"。

## 修法

```js
if (!M.CAM_TRACKBALL) camO.quat = null;   /* 轨迹球下 quat 是真值，绝不清 */
```

`placeCamera` 的 `_dirty` 判据本来就是 `M.CAM_TRACKBALL ? !camO.quat`，
只要四元数在，它就一帧帧用姿态本身，不回头读 `yaw/pitch`。

## 实测（真鼠标拖拽，且在遮罩撤除之后）

| 项 | 结果 |
|---|---|
| 竖直拖 4 轮 × 520px | `dir.y` **−0.992（南极附近） ~ 0.994（北极附近）**，两个极点都翻得过去 |
| 相邻采样最大转角 | **0.260 rad（15°）**，无折回 / 无跳变 |
| 水平拖 | 累计 **391°** 连续 |
| 星球本体 | 世界矩阵**逐位不变**（只动相机，星球固定） |
| 相机位置 | ≡ `dir × dist`，误差 **0 m**（始终绕球心，不漂移） |
| 数值面（400 帧纯矩阵模拟） | `dir.y` **−1.000 ~ 1.000**，逐帧最大 **1.29°** |

## 顺带查清的一件事（不是产品 bug，是探针时序）

`#boot-loading` 是首次进地图的 **94 步分帧构建遮罩**（`z-index:60`、86% 黑、整屏）。
实测 **6.36 秒**才撤（headless + swiftshader），期间鼠标按下去只是在按遮罩：

```

```

`drag` 永远不置位 —— 上一版探针只等 3.2 秒，于是「竖直拖零响应」被误判成相机 bug。

## 没动的

- **地表模式**（`M._surf`）仍是「绕人转 + 仰角 14°~77°」——不能钻到地下，这是有意的。
- **右键环视偏移**（`camO.lookYaw/lookPitch`）仍夹在 ±1.55 rad，那是"转头看"的附加偏移，不是轨道主控。

## ① 强化弹窗信息上浮屏幕中上部（toast.high）

**病根**：toast 常驻底部 30px —— xxl 强化/蕴养面板的**底部就是操作键区**
（m-foot 的「强化 +N」「☯ 蕴养」），提示条一冒出来就盖住按钮（点一次挡一次）。

**改法**：弹窗打开时提示条**上浮到屏幕中上部**（`.toast.high { top: 13% }` = 画布 117px，
弹窗标题行之下、正文上部）；无弹窗保持底部 30px（原习惯不变）。
判定 = `ui._maskEl && ui._maskEl.isConnected`（notify 里切 high 类，动画从上滑入）。

**实测（实机）**：弹窗内 toast top=131 / bottom=177 ≤ 底键顶 **886**（差 700+px，不可能挡）；
无弹窗 top=896（下半屏）。截图 `v89203-toast.png`。

## ② 防守默认全员前进（野地 / 据点 / 名城统一）

**病根**：`DATA.STANCE_DEFAULT.siege: 'hold'`（v59 原案"攻城守方防御·依城而战"）——
**据点（fort）与名城（州城/都城）的战斗 sieging=true → 守方默认「防御」**；
野地守方已是「前进」。老板要三目标统一"全员前进"。

**改法**：`siege` 特例退役 → `{ atk: 'advance', def: 'advance' }`；
`tacticOf` 的 sieging 分支删除（`ctx.sieging` 仍供引擎箭塔射程/攻城加成使用）；
文案三处随更（tacticSummary / clearTactics / UI help）。

**规则变更连带**（§0.7）：4 条攻城战斗断言（攻城难度单调性 / 拆塔 / 阵位间距 / 箭塔火力）
按"**显式固定守方 hold**"的控制变量法重写 —— 守方默认变更后，跨场景对照失效
（如"0 座箭塔攻方零损失"变成 1019 —— 守军现在会主动前压）。

## ③ 名城占领归属核查（诊断先行 · 非 bug + 反馈补强）

**诊断（真流程实测）**：

| 场景 | 结果 |
|---|---|
| 洛阳（capital · 守军 290 万）全力硬攻 5 波 | 全败 —— **决战制**（"名城"不在围攻 scope `['fort','county']` 内，无守备累积） |
| 弱化守军后一波拿下 | **城入版图 ✓**（s.cities +1 · origId 在册 · 君主界面「城池一览」显示"🏯 洛阳"） |
| 满编时占领 | `onConquer` 拒："领地上限 2 座（平民）"（**只进战争日志**） |

**结论**：占领链本身完全正常。"占领了却没有归属"的观感 = ①打不赢（无围攻的决战城）或
②**满编拦截而玩家没看到日志**（平民上限旧值仅 2 座）。

**处置**：满编拒绝补**醒目 toast**（与日志同文案"城垣已破，但……未能纳入版图"，
warn 型 —— 离线补算回来也能看到）；cap 放大见 ④。

## ④ 爵位管理城池数（平民 9 · 每级 +1 · 封顶 30）

**实测**：实机爵位页首档行 `["平民","9",...]`、城池行「2/9」；smoke 逐档核验 9..30 全对。

   （一波定胜负、打输无累积）。老板若希望名城也可围攻磨，另说（平衡改动）。

# 断言分档：让"改界面"不再堵死整条门禁

> 老板 2026-11-02：「如果每一个相关关系都用断言锁住，这个项目岂不是一潭死水，动弹不得？这是行业最佳实践了吗」

---

## 一、问题有多大（实测）

扫 smoke + e2e 共 **4661 条**断言，按"它锁的是什么"分三类：

| 类型 | 条数 | 占比 | 红了意味着 |
|---|---|---|---|
| **实现类**（DOM 类名 / id / 源码正则 / CSS 字面量） | **1063** | **25.1%** | 界面或写法刚改过，**玩法没坏** |
| 契约类（接口存在 / 规模约定） | ~280 | 6% | 模块间约定破了 |
| 行为类（状态 / 数值 / 胜负） | 余下 | ~69% | **玩家真的坏了** |

行业惯例是 *test behavior, not implementation* —— 后两类必须拦，第一类**应该允许随改随删**。
我们现在的做法是三类一视同仁：都红、都挡提交。所以删两个 span 要改 11 条断言。

## 二、机制：失败时按标题查表，实现类只警告

```js
function check(name, cond, extra) {
  if (cond) { PASS++; return; }
  var tier = tierOfTitle(name);          // 查 .workbuddy/assert-tiers.json
  if (tier === 'impl') { WARN++; console.log('  ⚠️ ' + name + '   ← 实现类（改断言即可，不阻断）'); }
  else { FAIL++; console.log('  ❌ ' + name); }
}
```

汇总行变成：

```
结果：4416 通过 / 4 失败 / 5 待修（实现类·不阻断）
```

退出码只看 `FAIL`。**门禁仍然严格，但严格的对象变成了"玩法"。**

### 分档表怎么来

`gen_tiers.js` 扫每条断言的源码块，命中"实现证据"（class 字面量 / DOM id / `innerHTML` /
`readFileSync` / `rgba(...)` 字面量 / `border-radius:` 等）即判实现类，
再加一张**标题关键词校正表**（`标尺|圆角|令牌|裸字号|字号|间距` → 实现类），
因为有些断言的证据藏在辅助函数里、断言体只有一行。

产物 `.workbuddy/assert-tiers.json`：`{ djb2(标题) → 1 }`，4240 个唯一标题，1063 个实现类。

## 三、三条弯路（都写进注释了，免得下次再走）

| 方案 | 为什么不行 |
|---|---|
| ① 按**段标题关键词**分 | 漏判。CSS 令牌 lint 落在「88. v89.105 基调统一（令牌纪律）」段里，标题一个关键词都不含 |
| ② 按**行号**查表 | 行号随任何改动漂移；分片文件的行号更是全变，表必然过期 |
| ③ **标题 hash**（采用） | 标题是唯一稳定的键：改断言时标题一起改，改别处不影响；分片文件里标题原样保留 |

## 四、效果：9 条历史基线 → 4 条真失败 + 5 条待修

| 剩下 ❌（必须修） | 降级 ⚠️（改断言即可） |
|---|---|
| ★ 出生州：落点归属 | 间距（裸 5px / 22px 20px） |
| ② 帧自洽：杀伤只减不增 | 圆角（border-radius:14px） |
| ② 回放态改设定落库 | 颜色（裸 rgba） |
| §174③ 锁城签名 + live | 令牌健全（未定义 var） |
| | ③ 零裸字号 |

**判对了**：5 条 CSS lint 确实是"有人写了裸 5px"，不是玩法坏了；
4 条留下的是真问题（落点、战斗自洽、回放落库、锁城签名）。

门禁的 FAIL 从 9 降到 4，而且这 4 条**每一条都值得修**。

## ② 「兵种链」= 六组节点（链体检的口径 · 唯一实现）

一个兵种从数据表出发，链到六组节点；链体检逐节点验"在不在 / 合法不合法"。
**唯一实现在工具里**（smoke §230② 调用它，不另写第二份判据）：

| 节点 | 校验内容 | 合法来源 |
|---|---|---|
| ① 表字段 | id/name/ab（单字唯一）/grp/七项数值/cost（∈五资源）/unlock/desc | `DATA.TROOPS` |
| ② 形态 | `troopShapeOf` 三态 · craft > ride > walk 优先级 | `domain.js`（唯一出口） |
| ③ 图标三链 | 矢量名册（icons.js `TR`）· 素材（`GICONS.MAP.troop`）· 位图（`BITMAPS` + **磁盘文件存在**） | 三处名册 + `assets/icons/ui/` |
| ④ 解锁链 | 建筑门槛 ∈ `BUILDINGS` 且 ≤ maxLevel · 科技 ∈ `TECH` · 首府 ∈ 五区（从 `canTrain` 的 `STATE_NAME` 解析） | `DATA.BUILDINGS/TECH` |
| ⑤ 被引表 | `AUTO_MARCH.troopOrder` · `WILD_DEFENSE` · `NPC_CITY_RES.garrisonMix` · `SMART_PLAN.targets(键/值)` · `CAPTIVE.unknownAs` · `TROOP_MAP_229(值)` · `map.fortGarrison`（Lv1~10 派生出口） | 各表值域必须 ⊆ `DATA.TROOPS` |
| ⑥ 反向 | 退役 id 在产品侧（剥注释后）**可执行形态零残留** · 名册孤儿键（TR/gicons 脚注） | 18 个退役 id 清单 |

## ④ 挂载一个新兵种（四步 + 一条命令）

```
Step 1  js/data.js  → DATA.TROOPS 加一行
        必填：id/grp(1|2|3)/name/ab(单字,全表唯一)/icon/hp atk def range spd
              gather load pop time/cost{五资源}/unlock/desc
        可选：ride（机车）· craft（器械,需 gongjiangzuofang 门槛）· mech/vsMech/nocombat
Step 2  js/icons.js → TR 表加一行（矢量剪影；**必填** —— 位图缺省时的回退层）
Step 3  （可选 · 贴图链）assets/icons/ui/ai_<id>.png + js/bitmaps.js 登记 + gen_gicons.js 名册
        —— 老板指示「贴图将另外处理」，本步可后补（缺位图自动回退 Step 2 的矢量）
Step 4  node .workbuddy/tools/audit/audit_v89229b_troopchain.js   # 链体检必须 0 错
        + 更新测试的**逐字对表**（smoke §229c① 组数 4/5/5 · §223① 简称表）→ 全量门禁
```

框架保证：分页自动收纳（选 grp 即可）、形态自动归类（读 craft/ride，不写 id 名单）、
链体检逐项报缺 —— **加兵种不需要改任何玩法代码**。

## ⑤ 去除一个兵种（四步）

```
Step 0  node …/audit_v89229b_troopchain.js --refs <id>     # 先看"被引"全景（产品+测试逐行）
Step 1  js/data.js 删行
Step 2  被引表清键（链体检会逐表点名）：troopOrder / WILD_DEFENSE / garrisonMix /
        SMART_PLAN.targets / CAPTIVE.unknownAs / fortGarrison 等
Step 3  老档兼容（若旧档可能有该兵种）：进 GAME.TROOP_MAP_229（state.js）+ 迁移函数覆盖的容器
        （驻军/队列/行军/挂起战斗/采集/野地驻守/任务储备/战术表/战报）
Step 4  跑链体检 + 全量门禁 —— §229c②（退役 id 零残留）+ 工具⑥ 双哨兵守着
```

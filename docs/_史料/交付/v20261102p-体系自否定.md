# 验证体系的自我否定（v156.39）

> 老板 2026-11-02：「复核这套体系完备，是可以否定自身的完备，不断自我改进的完备，而不是另一个牢笼」

## 一、先承认：牢笼是我上一轮自己造的

昨天（v156.38）给验证体系加了三个新机制，当时当成"改进"：

| 机制 | 想解决的问题 |
|---|---|
| 断言分档（实现类红了不阻断） | 改一个 span 就要改 11 条断言、跑 10 分钟全门禁 |
| 已知失败基线（只拦新增） | 9 条历史红让门禁永远是红的 |
| 分片并行（458s → 222s） | 每次验证 8 分钟太长 |

**这三个机制，每一个都带着一条"免罪通道"**：

```
分档  → 把断言标成「实现类」，它红了就不用修
基线  → 把失败写进「已知」，它下次就不算红
分片  → 少跑了一段，只要不报错也没人知道
```

上一轮我说"改界面不再堵死门禁"，却没同时建**「谁在滥用这条通道」的检查**。
那不是改进，那是把"红"换成了"可以协商的红"—— 比原来更糟，因为它看起来是绿的。

## 二、五问：让体系审自己

`node .workbuddy/tools/prof/tier_audit.js`，0.4 秒，五问：

| | 问什么 | 对应的牢笼 |
|---|---|---|
| **Q1 假绿** | 这条断言还**能红**吗？ | 恒真断言：永远绿，把"没测到"当成"通过" |
| **Q2 到期** | 豁免有没有**无限期**挂着？ | 降级/基线一旦写入就永不复查 |
| **Q3 覆盖** | 分片有没有**静默漏段**？ | 少跑一段不报错，假绿比红更危险 |
| **Q4 膨胀** | 有多少人靠**降级/跳过**逃避？ | 通道被滥用，红彻底失去信号 |
| **Q5 可推翻** | 体系能不能被**一脚踢开**？ | 不可推翻的体系 = 牢笼本身 |

## 三、它立刻抓出了三个真问题（都是我自己造的）

### ① 15 条恒真断言：永远绿，等于没测

```
check('护甲类装备存在', true, '数据中暂无 def 类装备，跳过')
check('攻取据点后声望增加', true, '本次未破城（随机）')
check('点击地图格子有响应', true, ...)     ← 这条从来就没测过
```

`check(名, true, '跳过')` 的语义是「这次没走到这条路」，
但它被计进**通过数**，而且永远绿 —— 分档只看红，永远看不见它。

`点击地图格子有响应` 尤其典型：**这条断言从写下的第一天起就是恒真的**，
而它声称保护的功能（点地图会弹面板）实际上一直没人验。

修法：
- 补 `skip()` 语义 —— 「跳过」单独计数，不计入通过，总结行显示 `N 跳过`；
- 能补真判据的补（体力→hpMult、点击→可观察响应、导航条→dock 内有按钮）；
- **不能测的诚实标 skip**（如"聚合补算不逐秒循环"——逐秒循环同样能推进到位，无法从结果区分）。

### ② 公共头的 112 条断言，在分片模式下**从未执行**

`smoke_parallel.js` 把前 2 段（公共头）的 `check` 换成空壳，注释写着
「公共头的断言只算一次（在主分片里）」—— **但没有任何一份真的跑它们**。

实测数字：串行 4425 条，分片 4313 条，**少 112 条**，
而 `smoke_fast.js` 里还写着「比串行少 ~116 条属正常」。
这句话本身就是假绿的许可证：**它把"少跑了"解释成了"正常"**。

修法：第一份用原样断言（真跑），第 2 份起才用空壳避免重复计数。
修后分片 4427 条 / 串行 4426 条 —— 不但没少，还多 1 条
（各份自带 newGame，个别条件分支走向不同）。

### ③ 基线 9 条，全部没有 since

`gate-baseline.json` 只记"哪些失败了"，不记"什么时候进来的"。
于是那 9 条从进来那天起就永久免检 —— 包括 5 条**可修的 CSS lint**。

修法：补 `since` 字段，`tier_audit` 按 30 天宽限期报到期；到期必须「修掉」或「由人显式续期」。

## 四、可推翻：`--strict` 一脚踢开

体系必须能被推翻，否则它自己就是牢笼。所以加了两个开关：

```bash
node smoke-test.js --strict       # 忽略分档表：所有断言都按行为类算
python .workbuddy/tools/git/gate.py --strict   # 忽略基线 + 不接受"复跑绿"
```

`--strict` 的语义不是"更严格的检查"，是**「我不信你的豁免，全都要绿」**。
门禁跑 `--strict` 时，9 条基线、5 条实现类待修全部变 ❌ ——
这就是可推翻性的证据：**体系拦不住你说"全都修"**。

## 五、门禁里的元判据

`gate.py` 现在**先审体系，再审代码**：

```
━━ 三件套门禁 ━━
  ✅ 元判据：体系自洽          ← 0.4 秒
  ✅ smoke-test.js ...
```

顺序是有意的：**体系有问题时，它给出的"绿"本来就不可信**。
tier_audit 任一 Q 不过 → 直接 `return 1`，连 smoke 都不跑。

## 七、这套体系抓出的最贵一条：一个功能从来没接线，被恒真断言盖了几个月

`e2e-test.js` 里有一条：

```js
check('点击地图格子有响应', true, ...);     // ← cond 写死 true
```

自审 Q1 把它揪出来后，我把它改成真判据 —— **它立刻红了**。

顺着查下去，是两层问题叠在一起：

**第一层：jsdom 里它物理上测不了。**
`GAME.map.pick()` 内部用 `getBoundingClientRect()` 算点击落点，而 jsdom 没有布局，
这个函数恒返回全 0 → 画布宽算成 0 → 坐标算成 NaN → 格子索引 -1 → **恒返回 null**。
所以「点击有响应」在 e2e 环境里永远不会发生。
这条断言不是"没人想测"，是**测不了，于是被写死成 true 咽下去了**。

（修法：给画布一个 mock 布局再点 —— 项目里早有先例，只是没人把这两件事连起来。）

**第二层：2D 兜底路径的点击处理体是空的。**
查 `js/ui-space.js` 的 canvas click：

```js
canvas.addEventListener('click', function (e) {
  var r = GAME.map.pick(...);
  if (!r) return;
  if (前传期) { …; return; }
  // ← 这里什么都没有
});
```

非前传期点地图 = 什么都不发生。而这个洞是我**上一轮自己挖的**：
v156.37 删底栏读数时，把这里仅有的两行 `ui.mapPick = r; ui.syncMapInfo();`
一起删了（它们只服务已退役的「点选 —」行）。删得对，**但没补替身**。

3D 路径（`map3d.pickAt → _openCellPanel`）本来就开面板，2D 兜底没有 ——
两条路径行为不一致，从来没人发现，因为那条断言一直是绿的。

修法：非前传期点地图 → `ui.openLandModalCi(r.ci)`（2D 时代就有的野地面板，不是新功能）。
修完 e2e：`点击地图格子有响应  [modal=Y …]` ✅。

**这一条把整套机制的意义说清楚了**：

| 没有自审 | 有自审 |
|---|---|
| 那条断言永远绿，功能坏着也没人知道 | Q1 揪出恒真 → 改真判据 → 立刻红 → 追出两层问题 |

**"红"不可怕，"永远绿"才可怕。**

## 八、自我改进的机制：每个漏掉的问题，都要变成一条检查

这轮的三个真问题，都是靠**新加检查**才能被发现的：

| 漏掉的 | 变成的检查 | 以后再漏会不会被发现 |
|---|---|---|
| 6 条断言写死 `true` | Q1 恒真扫描 | 会（每轮 gate 都跑） |
| 公共头 112 条断言没执行 | Q3 分片/全量条数比 | 会（写进 census，永久比对） |
| 基线永久免检 | Q2 since + 30 天到期 | 会（到期自动红） |

**这才是"不断自我改进"的可操作定义**：
不是"以后注意"，而是**把这次的漏法固化成一个每次都会跑的判据**。
否则下一个版本，同一个坑换个地方再踩一次。

反例就在本轮里：`smoke_fast.js` 里那句「比串行少 ~116 条属正常」——
它把"少跑了"写成了**已知的正常现象**，于是再也没人去问为什么少。
**任何"这是正常的"注释，都是一个待查的洞。**

## 十、可推翻性实测

（`node smoke-test.js --strict` 的结果见下方"实测记录"，它红了是**预期行为**：
豁免项全部露出来，验证"体系拦不住你说全都修"。）

真正要看的不是"它红了"，而是：**红出来的那 9 条，是不是每一条都还站得住**。

| 红项 | 还站得住吗 |
|---|---|
| 出生州落点 / 帧自洽 / 回放落库 / 锁城签名 | 是 —— 真问题，待修 |
| 间距 / 圆角 / 颜色 / 令牌 / 零裸字号（5 条 CSS lint） | 是 —— 确实违规，只是不影响玩法 |

结论：**9 条豁免全部成立，没有一条是"为了让它绿"而留下的**。
如果哪天 `--strict` 红出来一条"根本不该存在"的失败，那说明基线里混进了脏东西 ——
这就是 `--strict` 的真实用途：**审计豁免本身**。

### 实测记录（2026-11-02）

```
node smoke-test.js            → 4415 通过 / 4 失败 / 5 待修（实现类·不阻断） / 1 跳过
node smoke-test.js --strict   → 4415 通过 / 9 失败 / 1 跳过        ← 待修标记 0 处
```

4 + 5 = 9。**分档表在 strict 下完全失效**，5 条"实现类"全部按行为类判红 ——
这就是可推翻性的证据：豁免是"我允许自己暂时不修"，不是"它不算问题"。

红了之后逐条看：9 条**每一条都还站得住**（4 条真 bug + 5 条真违规的 CSS lint）。
没有一条是"为了让它绿"塞进来的 —— 如果哪天出现一条这样的，说明基线被污染了，
而那也正是 `--strict` 最该被跑的时机。

## 十一、自审器自己也会骗人（本轮实例）

`tier_audit.js` 的 Q4 第一版读「跳过数」：

```js
/结果：(\d+) 通过 \/ (\d+) 失败(?: \/ (\d+) 待修[^/]*)?(?: \/ (\d+) 跳过[^)]*)?/
```

实际输出是 `… / 5 待修（实现类·不阻断） / 1 跳过（未执行判据）`，
前一段的 `[^/]*` 是贪婪的，把「） 」的**尾随空格吃掉**了，
于是后面要求的 ` / 1` 里的空格不存在 → **跳过数永远读成 0**。

它报的是 `✅ 0 跳过`，而真实值是 1。

发现方式很土：**数字对不上**（总结行明明写着 1 跳过，自审说 0）。
改成 `\s*\/\s*` 后正确。

**教训**：自审器读错数字，比不自审更危险 ——
它会给出一份"看起来健康的体检报告"。所以：

- 自审器的每个数字，都要能和**原始输出对上**（这也是为什么它读的是完整日志而不是摘要）；
- 一个"永远 ✅"的检查项，和它要抓的那类 bug 是同一个形状。
  如果某个 Q 连续很多轮都是 ✅ 且从没红过，就该怀疑它是不是已经失效了。

最后一条暂时只能靠人留心 —— 它正是 Q1 想抓、但抓不到自己的那种情况。
写在这里，当个记号。

## 十二、v156.40：把上一轮自己列的四个盲区逐个补掉

上一轮结束时我写了「这套体系还缺什么」，四条。这一轮全部处理，逐条给结果：

| 盲区 | 补法 | 结果 |
|---|---|---|
| Q1 只能查「条件写成字面量」 | **变异测试**（把功能改坏，看断言红不红） | 已跑通，见 §12.2 |
| Q3 只比条数 | **比断言标题集合**（缺哪条报哪条） | 全量 4420 / 分片 4420，缺 0 多 0 |
| Q4 阈值是我拍的 | 历史化：每轮记 `tier-history.jsonl`，≥8 条后用 p95 | 已接，当前 1 条记录 |
| 没有像素基线 | `visual_baseline.js` 覆盖 UI 静态场景 | 覆盖 3 个场景；**3D 明确不覆盖**，原因见 §12.4 |

### 12.1 Q3 升级：从「少了不少」到「少了哪一条」

条数比有个致命盲区：**条数一样，但换了两条断言**，条数比完全看不出来 ——
而换掉的那两条可能正是唯一守住某个功能的。

做法：smoke 每条被触达的断言都记 `[djb2(标题), 标题原文]`（check 与 skip 都记 ——
skip 表示判据没跑，但断言确实执行到了，不算漏跑），`SMOKE_TITLES` 环境变量控制落盘。

```
标题集合：全量 4420 / 分片 4420　缺 0　多 0
```

（4420 是去重后的标题数，4425 是执行条数 —— 有 5 条同名断言被执行多次。）

**并且验证了它能红**：把 census 里的 missing 伪造成 3，Q3 立刻报
`❌ 分片漏跑 3 条断言` 并列出那三个标题。一个不能红的检查等于没加。

### 12.2 Q1 升级：断言到底能不能抓 bug（变异测试）

`mutation_probe.js`：不用改源码，**运行时替换** `GAME.*` 上的函数。
零恢复风险，代价是只能变异有出口的函数 —— 那也正好是 UI 实际调用的那批。

```
node .workbuddy/tools/prof/mutation_probe.js --run hpMult:no-bonus
```

判定只有两种：

| 结果 | 含义 |
|---|---|
| **killed**（断言红了） | 这个功能有断言守着 —— 好 |
| **survived**（全绿） | 功能改坏了都没人发现 —— 那批断言是装饰品 |

Q1 读 `mutation-log.json`：有 survived → **红**；超过 30 天没跑 → 提醒"结论过期"。
同样验证过它能红（伪造一条 survived，Q1 立刻红，EXIT=1）。

**这条为什么必须做**：Q1 原来只查"条件写成字面量"这种**形式上**的假绿。
但还有一类查不出 —— 断言写得很像样，判据其实永远为真（比如比较了两个恒等的东西）。
形式检查永远查不出这一类，只有"把东西改坏看它响不响"才行。

### 12.3 Q4 升级：阈值不该是拍的

上一轮我承认 35% / 12 / 20 全是拍脑袋。拍出来的阈值有两层骗人：
① 看起来精确（"25.1% < 35%"），其实那个 35 没有依据；
② 不会自己变 —— 项目规模变了，阈值还在原地。

现在：每轮把指标追加到 `.workbuddy/tier-history.jsonl`（同一天同数字不重复写），
历史 ≥8 条后，用**历史 p95** 与拍的阈值比较，超过 p95 且接近拍的阈值就报警：

```
历史 12 次记录，实现类 p95 = 26.8%（当前 25.1%）
```

"相对自己变差"比"相对一个拍出来的数变差"可信。历史不足时它会明说
「阈值仍是拍的（历史只 1 条）」—— **不装精确**。

### 12.4 像素基线：UI 做了，3D 明确不做

`visual_baseline.js`（playwright + pngjs）覆盖三个静态场景：顶栏 / 地图底栏 / 城池页。
判据：整图差异像素占比 > 0.5% 红、> 0.1% 提醒；阈值 12/255 过滤抗锯齿噪声。

**3D 场景不做，理由要写清楚**：
星球每帧都在动（自转 + 海面波浪），而 `map3d` 没有时间冻结入口 ——
直接比像素，同一个静止画面连拍两次都能差出几个百分点，全是误报。
要覆盖它，得先给 `map3d` 加一个 `M.freezeAt(t)` 把 `uTime` 钉死，那是另一件事。

**这一条是本轮最该被记住的**：
做不到的事要写进文档并说明为什么，而不是拿"覆盖了 3 个 UI 场景"冒充"有视觉回归了"。

### 13.2 变异测试的准确数字（修正上一版）

第一版判定用「红了几条」，实测踩坑：hpMult 变异报 8 条红，
其中 **4 条是基线常驻的**（出生州 / 帧自洽 / 回放 / 锁城签名）—— 它们不做任何变异也是红的。

不排除基线，变异测试会**永远 killed**，变成一台永远点头的机器。
修正后：

| 变异 | 新增失败（真被杀） | 基线常驻（不计） | 结论 |
|---|---|---|---|
| hpMult 恒返回 1 | **4 条** | 4 条 | killed |
| adminCisOf 恒返回空表 | **9 条** | 4 条 | killed |

hpMult 那 4 条里，有 2 条正是本轮刚从「恒真」改成真判据的
（`体力经 hpMultOf 放大全军生命`、`装备体力进上限后全军生命真的更厚`）——
**改之前它们永远绿，改之后它们能抓住变异。** 这是"补判据"这件事真的有用的直接证据。

### 13.3 视觉基线的两个"非确定输入"（不修就一定误报）

刚建好的基线立刻比出差异，逐层查：

| 现象 | 诊断 | 根因 | 修法 |
|---|---|---|---|
| 顶栏差 1.027% | 差异全落在 x 1260~1419（右侧工具区） | `STORY.rollWeather` 用 `Math.random()`，**不吃 mapSeed** | 开局后把 `world.weather` 钉成 clear 再 `syncHeader` |
| 城池差 0.150% | 差异全落在 x 23~87 / y 73~134（君主头像） | 头像也吃随机 | 用现成的 `rulerOpts.portraitSeed`（js/state.js 早就留了这个口子） |

修完：**三个场景全部 0.000%**。

两条经验：
- 基线"跑两次不一样"**不是阈值问题，是有非确定输入** —— 调阈值只会把问题藏起来；
- 先看差异**落在哪**（坐标 + 元素），比看总占比有用得多。1% 的差异可能是整屏偏移，
  也可能是右下角一个图标；只有定位才知道该修什么。

### 13.4 gate 自己的盲区：改了测试却不跑测试

`needs_full()` 原来只认 `index.html` 和 `js/**`：

```python
CODE_PATHS = ('index.html', 'js/')
```

于是改 `smoke-test.js`（加 skip 语义、改判据、动分档逻辑）会走
"未触及代码 → 只跑 audit"分支 —— **测试本体改了，一行测试都不跑**。

修：加 `TEST_PATHS`（smoke-test.js / e2e-test.js / 四个审计脚本 / gate.py 自己），
这些文件变动一律触发全量。

**这条和本轮主题是一条线**：门禁也是体系的一部分，它也有"看起来在工作"的盲区。
一个只盯产品代码、不盯测试代码的门禁，正好会放过"测试被改坏"这种情况。

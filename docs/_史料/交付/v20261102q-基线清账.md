## 二、出生州：选哪个州，出生点都一样

### 现象

用真实浏览器逐个测 13 个州（同一颗种子）：

```
烬环  落点(300,179)  stateOfCity=灰野   ← 选了烬环，城在灰野境内
霜脊  落点(344,108)  stateOfCity=灰野   ← 同上
其余 11 州  全部一致 ✅
```

更糟的是 `pickStartPos()` 返回 `{ state: '烬环' }` —— **函数返回的州与落点的实际归属不符，函数在撒谎。**

### 根因

`js/state.js` 的 `pickStartPos` 有四轮：

1. 环带内 + 平原 + 归属该区（严格）
2. 向外扫描 + 平原（**不验归属**）
3. 按距离排序取前 240 个验归属
4. **兜底：全星球找最近的平原（不验归属），却仍然 `return { state: name }`**

烬环（首府是旧都灰烬城，周边没有本州平原）和霜脊落到了第 4 轮，
取了灰野的平原，标成烬环。

老板 v70 的原话是「**城市归属应归属到首府所辖范围内**」——
归属是硬要求，地形（平原）是偏好。**旧版把优先级搞反了。**

### 修法

第 4 轮改成：本州平原 → 本州任意地形（仍非城）→ 才落到 START_POS。
`stateOfCity` 很贵（每次跑一遍全图行政区，注释里记着"13 次 = 195 秒"），
所以限次 400，避免最坏情况。

修后 13 州全部一致：

```
烬环  落点(266,218)  ✅（就在旧都 265,215 旁边）
霜脊  落点(370,49)   ✅
```

## 三、帧自洽：判据拿展示流当结算数据

原判据把 `frames` 里的攻击逐条累减，要求「终局 = 史实剩余」。
实测：**守方累减后剩 4675，史实说剩 2937，差 1738**。

查下去，`frames` 是**展示用的事件流**（每兵种的移动/攻击各一帧，给沙盘播动画）。
同一回合里多个单位并行攻击同一目标，序列化成帧必然出现
"后一帧打的是前一帧刚打死的单位" —— 那不是 bug，是并行的代价。

真正的权威口径是 `per`：`js/tactic.js:1427` 每回合末算的存活总兵力（`_rA` / `_rD`）。

改成：
- 用 `per` 判「每回合只减不增、不为负、终局 = 史实剩余」；
- `frames` 只判结构性合法（伤害量非负）。

**这不是"改判据让它绿"**：被测行为（沙盘能开、能播、终局对得上）一条没少，
只是换掉了那个本来就测错了对象的判据。而且改完更严 —— 原来因为判据错，
真实的终局对账根本没在被验。

## 四、另外两条

**回放态改设定（no wild）**：断言在城周 ±8 内找 1~3 级野地。
实测那片区域的野地等级分布是 `6:91 / 7:128 / 8:57`，只有 4 格是 1 级 ——
条件太窄，换颗种子就找不到。放宽到 ±12 环、1~6 级，并把扫描统计带进 detail。

**锁城签名**：`ui.openBuildModal` 的签名从 `(idx, cityId)` 变成了 `(idx, cityId, mode)`，
断言还在查旧写法。改成容忍可选第三参。
顺带修了分档规则：这类"断言体里对源码做正则、但源码变量在断言外取"的断言
（`var uS = __uiAll()` 然后 `.test(uS)`），原来抓不到 `__uiAll()` 字样，
被误判成行为类 —— 函数加个参数就报"产品坏了"。

## 五、这 4 条的真正教训：基线的粒度错了

4 条里 1 条是产品 bug，3 条是测试自己有问题（判据错源 / 环境脆弱 / 断言过时）。

而它们在 `gate-baseline.json` 里**是同一个标签**：「已知失败」。

后果很具体：
- 3 条测试问题**本来几分钟就能修**，但和 1 条产品 bug 挂在同一张表里；
- 表叫"已知失败"，看的人默认"这些是难修的、先放放"；
- 于是那条**真产品 bug（选州无效）陪跑了很久**，谁也没去动。

**基线的粒度不该是「红不红」，该是「谁该修 / 多久能修完」。**

对应两个不同的宽限期：
- 改断言（2 分钟）→ 不该有 30 天宽限，**当天就该改**；
- 改产品（半天）→ 30 天合理。

这条已经记进 AGENTS（见「基线的分类」）。**没有加新机制**：
只是把 `gate-baseline.json` 的 note 和 tier_audit 的提示文案改清楚，
让人看到"可收缩"就知道该去收。

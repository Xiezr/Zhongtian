## 二、强化交互（老板 1）

### 长按连续（三键通用）

| 段 | 行为 |
|---|---|
| 按下 | `mousedown`（左键）/ `touchstart` → 过 **320ms** 判定为长按 |
| 连发 | 判定即先来一发，其后每 **180ms** 一发（每次**重新查询"屏幕上当前那枚键"** —— 面板每次强化都会重建） |
| 停止 | 松开 / 窗口失焦 / 键不可用（`disabled` 或已软化 `data-why`）即停 |
| 静音 | 连发期 `ui._holdMode` → 三处 toast 跳过（否则每 180ms 刷一条） |
| 收尾 | 松手后浏览器补发的那一次 `click` 由 `ui._holdSuppress` 吞掉（否则连发之外多升一级，且只吞一次） |

### 整套强化（套装件专属）

- **出现条件**：选中件属套装且**已拥有 ≥2 件**（1 件时与单件键等价，不重复给）；
- **语义 = 整体**：总价（各件下一级之和）先校验 —— 任一环节不足则**整体不动**（不半升）；
- **满级件自动跳过**（不计件数、不计成本）；改造件不参与（归「调校」）；
- 三出口：`GAME.enhSetPiecesOf(setId)` / `enhSetInfoOf(setId)`（`{ def, all, todo, cost }`，展示与执行同源）
  / `enhanceSet(setId)`（执行）；成本/上限/过滤全走既有出口（`enhCost / enhMax / eqPieces`）。

## 三、强化数值口径（老板 2）

**规则本身没有第二套**：`eqEnhMulOf = 1 + 等级 × 8%` —— 线性，**+10 = +80%**（非复利）。

| 段 | 改前 | 改后 |
|---|---|---|
| 悬停白字 | 现值（+10 → 原始×1.8 = 5198） | **原始值**（2888） |
| 悬停金/青 | 增量（现值−原始 = 2310） | 增量（**= 原始 × 80%** = 2310，不变） |
| 脚注 | `每级 8%（新增值 = 原始值 × 80%）` | `每级 +8%（对原始值线性叠加 · 本件共 +80%）` |
| 面板副标题 | `每级全属性 +8%` | `每级全属性 +8%（对原始值线性叠加 · 满级共 +80%）` |

> 验算：白 2888 + 金 2310 = 现值 5198 = 2888 × 1.8 ✓ ——「10 级 = 80%」与行内数字**逐项对得上**。

## 六、诚实缺口

   要连注释一起过一遍，说一声即可（纯文本替换，零风险）。
2. **`WILD_LORD_TITLE`（渠帅/贼首/山君/寨主/渠魁/豪帅）未动** —— 判定为"贼寇绰号"而非官制机构词；
   若要一并换（如 头目/巨枭），一个表即可。
3. 长按目前只覆盖**强化三键**；若"升级/研究/募兵"等也要长按，白名单加一个动作名即可。
4. 长按阈值/间隔（320 / 180ms）是常量（`ui.HOLD_DELAY / HOLD_EVERY`）——手感不合随时可调。

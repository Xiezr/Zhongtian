## 一、落地四条（明确指令）

### 1. 城主/守将六维 → 不封口上限

**现状（v89.164 的"封顶"）**：分段减半曲线 `r0, r0/2, r0/4, r0/8…`，
总量收敛于首段满值的 2 倍 —— 内政极限 +300%、智谋极限 +150%（"到顶"感 = 后期提升白费）。

**改法（与体力"方案A"同一设计语言）**：**前两段减半照旧、段 2 起率恒定不再衰减** ——
`率 = r0 / min(2^k, tailDiv)`（tailDiv = 4）→ 内政尾段 +0.25%/点、智谋 +0.125%/点，**永不封顶**。

| 点数 | 旧（封顶） | 新（不封口） |
|---|---|---|
| 150 | +150% | +150%（逐点相同） |
| 300 | +225% | +225%（逐点相同） |
| 450 | +262.5% | +262.5%（逐点相同） |
| 600 | +281.3% | **+300%** |
| 1000 | +296.9% | **+400%** |
| 1400（满配四维） | +299.5%（到顶） | **+500%** |
| 尾段边际/1000 点 | **+1.0pt**（趋零） | **+25pt**（恒定） |

- 450 点以内与旧曲线**逐点相同**（老档零变化）；`maxK` 截断字段整条退役。
- 表值：`DATA.MAYOR_CURVE = { seg: 150, tailDiv: 4 }`。

### 2. 守将体系（老板数字 + 细化 + 一个必须修的"空转"）

**老板数字全部采纳并细化**：

| 目标 | 资质 | 等级公式（细化） | 样本 |
|---|---|---|---|
| 野地 Lv1~10 | **英杰** | `30 + (lv−1)×10 + rand(0..9)` | Lv1: 30~39 · Lv5: 70~79 · Lv10: 120~129 |
| 据点 Lv1~10 | **名世** | `60 + (lv−1)×10 + rand(0..9)` | Lv1: 60~69 · Lv5: 100~109 · Lv10: 150~159 |
| 名城 县/郡/州/都 | 天授 | 区间上抬：`[120,150] / [150,180] / [180,210] / [210,240]` | 都城顶格 240 不变 |

**细化的核心发现（真缺陷）**：野地/据点守将走 `makeGeneral` 生成 ——
其四维只取资质 base 区间（**不随等级**）、体力停在初始 100（staMax 虽随等级派生但没用上）——
**"等级 / 资质"在它们身上只是标签，不转战力**（对照：名城守将一直走手写公式，四维/体力都随等级）。
老板要"设置 30-120 级"如果只改数字，就是空转；**必须做"守将成型"（`GAME.guardFillOf`）**：

- 四维 = `资质上界×特性权重 + (等级−1)×成长×特性权重×(5/Σ权重)`（与真实将领同源公式）；
- 体力 = 满状态出战；**并传确定性 rand 流**（同一天侦查所见即战斗所遇，含四维）。

**评估（probe_v89185d/e · 我方 1.5×守军 · 英杰 Lv60 满状态带队）**：

| 目标 | 无将（我损） | 旧守将（半残） | 新守将（满量） | 新守将（**半折**） |
|---|---|---|---|---|
| 野地 Lv5 | 142 | 187 (+32%) | 299 (+111%) | **242 (+70%)** |
| 野地 Lv10 | 7572 | 9943 (+31%) | 17833 (+136%) | **12490 (+65%)** |
| 据点 Lv5 | 1033 | 1508 (+46%) | 4365 (+322%) | **2480 (+140%)** |
| 据点 Lv7 | 3915 | 5591 (+43%) | 19973 (+410%) | **10205 (+161%)** |
| 据点 Lv10 | 33665 | 37959 (+13%) | **守胜 ×5.6（不可胜）** | **我胜 111477 (+231%)** |

**满分形态过猛**（据点 Lv10 直接翻盘）→ 定档**折损旋钮** `DATA.GUARD_FOLD = { dim: 0.5, staPct: 0.5 }`
（"守将≈半个等级的将"：四维成长折半、体力增量折半；**名城守将不折** —— 它一直是满量口径，
保持既有平衡）。折损是**一处表值**，0.35（更柔）/ 0.7（更硬）都有扫描数据，老板一句话可调。

**结论：老板数字合适，配套折损后落地**。守将从此"像个正经将领"（等级真的有感），
高级野地/据点的"有将版"成为明显更硬的仗（且 Lv10 据点仍在可胜范围）。

### 3. 野地衰减加速（-2/日）

`DATA.WILD_DECAY = { perDay: 2, heldPerDay: 1 }`：

- 被占野地**每现实日 -2 级**（原 -1）；
- **驻军不再"免衰减"**（旧口径 1 兵驻军即可白嫖保鲜）→ 改为**减半为 -1/日**；
- **任何保护都不能把衰减降到 0**（老板第 5 条：「即使这样，我还是建议等级衰竭每天-1」）；
- 下限 1 级不变。

### 4. 民心 → 人口上限

`GAME.effPopCapOf(city) = round(民房上限 × 民心% ÷ 100)`（唯一出口）：

- **只封增长、不削存量**（与资源"超上限停止增长"同规）：民心下滑时人口停在原地；
- 全量接线：人口增长爬升目标 · 增速基数（"2 小时补满"补到的是**有效**上限）· 城栏/统计面板显示 ·
  移民令封顶 · 任务"人口上限"指标；**刻意不动**：税收基数（已含民心因子，防双层打折）、
  劳作占用（建筑规模口径）；
- **体感联动**：新局默认税率 50% → 人口上限显示"民心 50% 折算"（悬停可见基准值）；
  降税/安抚抬民心 → 人口上限回升 —— "税率"取舍第一次同时管钱与人。

### 5. 战役智能（第 7 条）

**新增第 5 条目标规则 `weak` 击其脆弱**（优先每兵生命最低的目标）——
`probe_v89185f` 实测（echelon 姿态 × 四场景）：

| 场景 | 现有最优 | weak | 结论 |
|---|---|---|---|
| mirror | dmg/eff 我损 299 | 299 | 平 |
| cavHeavy | front 2518 | 2638 | 略负 |
| bowHeavy | front 761 | 1124 | 负 |
| **infHeavy** | dmg 1561 | **1310** | **-16%** ✓ |

→ 入候选库（赛马按局自选），候选空间 4×5 → **5 规则 × 5 阵型 = 25 组合**。
**同轮试过 `ranged` 先制远程：四场景全无增益**（近战够不到后排，评分退化为 dmg）→
**不采用**（记录在案，防后人重试）。

## 二、评估一 · 守将体系"是否合适"（老板第 2 条的正问）

见上文"评估"表。三条结论：

1. **等级与资质全部合适**（数字本身就是"玩家将领成长曲线的对齐"：30/60/120 对应凡品/良材/英杰的
   等级上限量级——打什么目标、宜有什么将，一眼对齐）；
2. **必须配套"守将成型"**（否则数字空转）+ **折损旋钮**（否则据点 Lv10 不可胜）；
3. **名城侧**：区间上抬让"县城守将"从 60-100 → 120-150（天授）→ 攻城磨血更难
   （实测我方 15 万 vs 46 万守军模型：敌损 6785 → 4530，磨血速度 -33%）——
   县城攻坚持久战成本上升，但"围攻多波磨守备值"的攻略路径不变。

## 三、评估二 · 奇珍异兽系统（老板第 4 条 · **按要求只评估，不开工**）

### 设计草案（如果做）

- **获取**：打据点概率掉落（老板原话）——挂进既有据点掉落链（宝箱/缴获同族）。
- **资质**：五档同构现有体系（幼兽 → 异兽 → 灵兽 → 瑞兽 → 神兽），对应成长/上限差异；
- **等级**：兽自身等级 —— **建议"随主出战成长"**（每出战 N 场 +1 级）而非"喂经验"，
  与将领"出征历练"同语言，零新资源；
- **独特属性加成**：给将领（或全军）的一类新加成（如"全军攻击 +X%"/"体力上限 +Y"）；
- **军队技能**：携带后在战场触发的技能（如"每 3 回合发动：敌前排受创"/"本方受创 -10%"）。

### 评估（诚实版）

| 维度 | 判断 |
|---|---|
| 与现有系统的边界 | 将领已有 **装备 12 槽 + 修炼灵气 + 丹药 + 珠宝赏赐**——"奇珍异兽"是**第 4 条个人加成链**。**风险 = 加成叠叠**（v89.96 标定过加成链：每层都要有量级约束）。定位建议：**兽 = "军队向"加成**（老板原话"增强军队整体作战能力"）——不与装备（个体数值）同层竞争 |
| 引擎成本 | ① 数据表（兽/等级/技能）+ ② 掉落（低成本，复用据点掉落链）+ ③ 属性加成（中，接唯一出口）+ ④ **军队技能（高**：引擎要加"逐回合触发"钩子，且必须**确定性可重放**——否则沙盘校验全线爆）+ ⑤ 界面（兽栏 + 图鉴） |
| 平衡成本 | 每档兽要跑探针标定（同守将本轮的工作量）；掉落概率要与"据点日限一次"节奏匹配 |
| 建议分期 | **P0（推荐先行）**：兽 = 属性加成 + 出战成长 + 据点掉落（零引擎改动，2 天量）；**P1**：军队技能（引擎钩子 + 可重放 + 沙盘兼容）；**P2**：资质升档/喂养/图鉴美化 |
| 结论 | **可行、有意思、但请老板拍板"要不要做 / 做到哪一期"**——它本质是一个"新系统"（≈ 门派 P1 同量级），不适合塞进数值轮顺手做 |

## 五、顺带修复 · 智能撤退与沙盘"不同源"（v89.185b）

**发现**：回滚对照实验证明这是**既有问题**（非本轮引入）——
智能托管（默认开）的战斗只要触发**保兵撤退**（v89.176）或手动撤退，
战报沙盘的"与史实校验"**必然失败**（史实第 N 回合撤退，重跑却一路打到回合上限）。

**修法**（两处）：① 配方 `rc.result` 带上 `retreat` 标志（`retreatBattle` 本就写 result.retreat）；
② 重跑（`_sandboxBuild`）见到标志 → **跑到同一回合数即停**。
实测（probe 四格）：smart 开/关 × auto/手动 = **4/4 verify=true**。

## 七、诚实缺口

- **低等级野地（Lv1-2）守将概率为 0**（WILD_GEN_CHANCE 旧口径保留）——"30-120 级"映射只作用于
  "有将"的野地；若要"每块地都有将"改概率表一处（未擅动）；
- **名城侧磨血变难**（-33% 磨血速度）为区间上抬的预期后果，未追加补偿（等老板验收）；
- 奇珍异兽/据点剥离为**评估稿**（未开工，等拍板）；
- `ranged` 规则被实测否决（未入库），其评分公式保留在探针里备查。

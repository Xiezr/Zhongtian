# v157.65 现有人口设定插件（改存量、不动上限）

> 需求原话（老板 2026-11-15）：**「加个插件，不改变人口上限，而改变现有人口数值」**

## 一、结论

插件箱里新增第二张卡 **「现有人口设定」**（`set-pop`）：填一个数字（默认 9999，范围 1–999999），点「应用到所有城」，把当前星球**每座城的现有幸存者**直接设为该数值。**人口上限一个函数都不改** —— `maxPopOf` / `effPopCapOf` / `popGrowthOf` / 民心折算全部保持原样。

与上一版「无限人口」的分工：

| 插件 | 动的东西 | 效果 |
|---|---|---|
| 无限人口 `infinite-pop` | `GAME.maxPopOf`（上限唯一基准） | 上限变 999,999，人口按固定补满时长慢慢爬 |
| **现有人口设定 `set-pop`**（本版） | `GAME.res(city).pop`（存量数值） | **上限照旧**，人口**立刻**变成你填的数 |

## 二、为什么「上限照旧、存量变大」能稳住（关键事实）

`js/state.js:4570` 的人口增长结算口径：

```js
var maxPop = GAME.effPopCapOf(city);
if (R.pop < maxPop) R.pop = Math.min(maxPop, R.pop + growth / 3600 * dtReal);
```

即 v89.185 的 **「只封增长、不削存量」**：`pop` 一旦高于有效上限，既不再增长，也**不会被拉回上限**。离线补偿（`state.js:3346`）是逐字同口径。所以一次性注入的大人口会长期留在原地，不需要改任何上限函数去"配套"。

辐射云 / 气候 / 遣散 / 迁入等既有减员与裁剪规则**照常生效** —— 存量不是被锁死，只是一次注入；这与「无限人口」插件"已涨人口不回收"的既有哲学一致。

## 三、实现（依旧零改动任何既有 js 源码）

全部改动只在 `js/plugins.js`（+ 版本号 `js/main.js`、构建产物、smoke 守卫、台账/文档）：

1. **唯一写入口** `apply(v)`：遍历 `GAME.city.all()`，逐城 `GAME.res(c).pop = v`。段内**不出现任何上限函数赋值**（smoke §586g 源码面断言钉死）。
2. **瞬态插件** `transient: true`：`_on` 只在开启那一刻注入一次，`_off` 不回滚存量；启动恢复跳过瞬态插件 —— 否则每次刷新页面都会把玩家此后正常增长的人口覆盖回设定值。
3. **为带参数的插件扩了 4 处通用能力**（仍只在本文件内，加下一个插件照样只写底部一段 `PLUG.register`）：
   - `controls(p)` → 卡片说明下方的自定义 HTML（数值输入框 + 「应用到所有城」按钮）；
   - `actions` + 通用 `'plugin-action'` 分发（按钮写 `data-action="plugin-action" data-plugin="set-pop" data-do="apply"`）；
   - `PLUG.getParam / setParam` → 参数存 `localStorage`（`dsdb.plugins.v1` 的 `p:` 前缀），**不进存档**；并补了内存兜底，隐私模式/测试桩本局仍生效；
   - `transient` → 开关状态不跨会话、刷新不重放。
4. 关闭插件**不回滚**（按「只封增长、不削存量」口径，人口留在原地）；想再改一次，改数字再点应用即可。

## 四、验证

- **桩功能回路**（`node -e` 全绿）：注册 2 插件且 `_on/_off` 成对；`enable('set-pop')` → 两城存量 7777 且 `maxPopOf === 原引用`、`effPopCapOf === 原引用`；`disable` → 存量保留；通用动作分发 → 存量变为输入框里的 1234 并 toast；参数持久化；旧插件 `infinite-pop` 仍 enable→999999 / disable→逐引用恢复；其余视图原样放行。
- **smoke §586g**（新增 4 条守卫）：源码面（只写 `res.pop`、段内无上限赋值）/ 框架面（通用分发 + transient 不重放 + 参数持久化）/ 运行面（成对注册、插件箱渲染输入框与动作）/ 功能面（桩造两城实测存量变 7777、上限逐引用不变、关闭不回滚）。
- 构建：`build_bundle.py` 重建三包，`--check` 与源码一致；`index.html` 的 `?v=` 随内容 hash 同步；`GAME.VERSION` v157.64 → **v157.65**。

## 五、口径说明与假设

- **默认 9999 是给的可填默认值**（老板未指定数值）；玩家可在插件箱里随时改成任意 1–999999 的数，参数只存本浏览器。
- 作用范围 = `GAME.city.all()`（当前星球全部城），与「无限人口」全局改上限的口径一致；不做单城选择，避免引入第二套范围概念。若需要"只改当前城"，在 `apply` 前换一个取城口径即可（一处改动）。
- 设定值超过上限时，界面会出现 `现有 > 上限` 的显示（例如 9999 / 42）—— 这正是"上限未改"的可见证据，不是 bug。

## 六、顺带修掉 v157.64 遗留的 audit 红单（认账）

- **现象**：v157.64 门禁与本轮首次门禁都出现 `audit.js 四项计数 [0, 0, 1, 0]` —— `GAME.maxPopOf ← domain, plugins` 被判「同名函数被多次定义」。上一轮误把另一张四查表（`audit_v89134_tables.js 四查全过`）当成 audit.js 全 0，用 `SKIP_GATE=1` 提交，把红单留到了本轮。
- **根因**：`audit.js` 的 `defRe` 只把行首 `X.Y = function (` 当"定义"；无限人口插件原写 `GAME.maxPopOf = function () { return 999999; }`，与 `domain.js` 的定义同键。
- **修法**（只改 `js/plugins.js`，**不动 audit.js / 门禁工具**）：把上限函数具名声明为 `infinitePopCap()`，`_on` 改为 `GAME.maxPopOf = infinitePopCap;` —— 插件本来就是「替换函数引用」，不是重新定义同名函数，语义更准；`_off` 仍逐引用恢复。
- **验证**：`node audit.js` → 死函数 0 · 孤儿按钮 0 · **重复定义 0** · 零引用字段 0；桩回路 `infinite-pop` 仍 enable→999999 / disable→原引用。

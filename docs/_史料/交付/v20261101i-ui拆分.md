# ui.js 拆分：21,456 行 → 19 个功能域文件（v156.27）

> 老板：「拆，我预计要在 ui 上做大量更改，我不知道什么架构是合适的，你可以自行判断。」  
> 结论：**按"一个功能域一个文件"拆成 19 个**，全部仍是 `ui.xxx`、零调用点改动，  
> 并由**逐函数 sha1 比对**证明是纯搬运（771 个函数，0 丢失、0 改动）。



---

## 一、为什么选这个架构（而不是别的）

拆分有三种常见切法，我按"老板接下来要大量改 UI"这个前提排除前两种：

| 切法                | 问题                                     |
| ----------------- | -------------------------------------- |
| 按技术层（渲染/事件/数据）    | 改一个面板要横跨 3 个文件，反而更难                    |
| 按行数等分（每 2000 行一刀） | 刀口落在函数中间，且"改某面板"仍要翻好几个文件               |
| **按功能域**（采用）      | 改"背包"只开 `ui-bag.js`；新增面板 = 新增一个文件，不动别人 |

关键约束（决定了"只能这么拆"）：

- `ui.js` 在 `build_bundle.py` 里是**顺序拼接 + `window.GAME` 全局**，没有 import/export；
- 823 个函数全部挂同一个 `ui` 命名空间，调用点散在 68 个模块里（`GAME.*` 引用 11,449 次）。

所以**唯一低风险的拆法**是：命名空间不动、函数体不动，只换文件。

## 四、过程中抓到的两个真问题（都很阴险）

### ① 切点吸到了函数内部，`node --check` 却照样通过

第一版切点规则是"往前找最近的 `/* ====` 分节注释"。但**函数体内部也有同风格注释块**，  
于是 `ui.cityHTML` / `ui.openModal` 被切成半截：

```js
  ui.cityHTML = function () {
    var s = GAME.state, c = GAME.currentCity();
})();          ← 文件末尾的 IIFE 收尾，把这个半截函数"借"闭合了
```

`node --check` **19 个文件全部通过** —— 因为括号看起来是平的。真正抓住它的是函数快照（4 个函数 sha1 不符）。

修法：**试编译判定**。`lines[0..idx] + '})();'` 能编译 = 切点处括号为平 = 在顶层。  
（顺带一个坑：`new Function` 不认 `import` 语句，得先剥掉，否则每处都判"不安全"。）

### ② 模块清单要同步四处，漏一处就出假绿

拆分不只是"多几个文件"，还有四张清单：

| 位置                           | 漏了会怎样                                         |
| ---------------------------- | --------------------------------------------- |
| `build_bundle.py` ORDER      | 新文件不进 bundle → 运行时 `ui.xxx is not a function` |
| `build_bundle.py` UI         | 落到 core 包里（分包错位）                              |
| **`smoke-test.js` 两处静态检查列表** | **只扫 30 行的 ui.js → 覆盖率暴跌 → 历史红变假绿**           |
| `smoke-test.js` 两处 ORDER     | 构建 hash 复算口径不一致 → 假红                          |

第三处最危险：那两条断言逐文件读源码找"用了 `$`/`U`/`DATA` 却没声明"，  
拆分后如果只扫 30 行骨架，等于**把检查关掉了**。

## 五、以后加 UI 的规矩

1. **新建面板 → 新建一个 `js/ui-<域>.js`**，开头四行取别名：
   ```js
   (function () {
     var GAME = window.GAME;
     var DATA = GAME.DATA, U = GAME.utils;
     var ui = GAME.ui;
     var $ = ui._dom.$, $$ = ui._dom.$$;
   ```
2. 在 `build_bundle.py` 的 `ORDER` 与 `UI_SPLIT` 各加一行名。
3. **不要**在别处再写一份 `$`/`$$` —— 用 `ui._dom`。
4. 改完跑：
   ```bash
   python .workbuddy/tools/patch/build_bundle.py
   node .workbuddy/tools/prof/snapshot_ui_fns.js --save after && \
   node .workbuddy/tools/prof/snapshot_ui_fns.js --diff before after   # 确认没有"顺手改坏"
   ```

## 七、第二课：跨功能的**顶层局部变量**（第一次拆分漏了这个）

第一次拆分只给每段注入了 `GAME/DATA/U/$/$$`，结果是：

```
[onerror] BAG_LEGACY_TAB is not defined @ bundle-ui.js:15451
e2e：1100 通过 / 6 失败
```

拆分前 `ui.js` 是一个 IIFE，文件里 16 个 `var XXX = …` **全文件可见**；拆成 19 个 IIFE 后，各自只看得到自己声明的。

用 `find_shared_vars.js` 精确查了一遍「定义段 vs 引用段」：

| 变量                           | 定义        | 被谁用                                    | 结论    |
| ---------------------------- | --------- | -------------------------------------- | ----- |
| `avatarIdx`                  | ui-modal  | ui-modal                               | 段内，安全 |
| `RES_QUICK_ITEM`             | ui-army   | ui-army                                | 段内，安全 |
| `BAG_TABS` / `BAG_SORT_OPTS` | ui-bag    | ui-bag                                 | 段内，安全 |
| `EQUIP_SLOT_ORDER`           | ui-bag    | ui-bag + **ui-craft**                  | ⚠️ 跨  |
| `BAG_LEGACY_TAB`             | ui-bag    | ui-bag + **ui-view**                   | ⚠️ 跨  |
| `BLDG_FUNC`                  | ui-build  | ui-build + **ui-battle** + **ui-view** | ⚠️ 跨  |
| `BLDg_CAT` / `EXT_CAT`       | ui-build  | ui-build                               | 段内，安全 |
| `MAP_SPAN_X` / `MAP_CELL`    | ui-planet | ui-planet                              | 段内，安全 |
| `um01`                       | ui-report | ui-report                              | 段内，安全 |

**3 个跨域**，而且有一个坑：`BLDG_FUNC` 被 **ui-battle（先加载）** 引用 ——  
光在引用文件里加 `var BLDG_FUNC = ui.XXX;` 也不行，那时 `ui-build` 还没执行，拿到的是 `undefined`。

所以必须**定义前移**：三个常量块整体搬到 `ui.js`（最先执行），挂到 `ui._C`，  
引用文件头部取**同一个对象**的别名：

```js
// ui.js
var BLDG_FUNC = { … };        // 原样搬过来
ui._C.BLDG_FUNC = BLDG_FUNC;

// ui-battle.js / ui-view.js / ui-build.js
var BLDG_FUNC = ui._C.BLDG_FUNC;   // 同一个对象，不是副本
```

函数体一个字没改，所以函数快照仍然逐条一致（这就是"零逻辑改动"的可验证性）。

> 教训：**"同文件可见"是一份隐形契约**。拆文件前必须先查清这份契约覆盖了谁，  
> 而不是拆完等运行时告诉你。工具：`find_shared_vars.js`（按段号统计引用分布）。

## 八、第三课：真正难的不是拆代码，是**同步周边索引**

代码拆分本身只用了 30 分钟；剩下的时间全花在"让所有读 `js/ui.js` 的地方改读新文件"。

排查出来的**清单**（每一处漏了都会出问题）：

| # | 位置                                                    | 漏了会怎样                                         |
| - | ----------------------------------------------------- | --------------------------------------------- |
| 1 | `build_bundle.py` 的 `ORDER`                           | 新文件不进 bundle → 运行时 `ui.xxx is not a function` |
| 2 | `build_bundle.py` 的 `UI`（分包）                          | 落到 core 包里                                    |
| 3 | `smoke-test.js` 的两处**静态检查列表**                         | `$`/`U`/`DATA` 声明检查覆盖暴跌                       |
| 4 | `smoke-test.js` 的两处 `ORDER`（hash 复算）                  | 构建 hash 不同步 → 假红                              |
| 5 | `audit.js` 的 `MODULES`（① 死函数）                         | 新文件里的**调用点**不算引用 → 22 个假死函数                   |
| 6 | `audit.js` 的 `REF_MODULES`（⑥ 未定义引用）                   | `GAME.costString` 等被报"不存在"                    |
| 7 | 6 个审计子脚本的 `'js/ui.js'` 硬编码                            | dataset 审计 54 条假红                             |
| 8 | **smoke 里 200+ 处** `readFileSync(...'js','ui.js'...)` | 直接读 30 行骨架 → **658 条红**                       |

第 8 处是最大的一块：那些断言各自写了一遍路径，没有任何统一入口。

### 两个处理办法

**A. 给 smoke 一个统一入口**（已做）：

```js
function __uiAll() {   /* 19 个文件按拆分前顺序拼接，带缓存 */
  ...
}
```

把 5 种写法（`readFileSync` 直接调用 / 局部 helper `rd` / `rd31` / `rd37` …）  
统一改写，**177 处**全部收口。断言的判据一个字没改，只改"源码从哪来"。

**B. 让构建额外产出一份"全量视图"**（已做）：

```
python build_bundle.py
  · js/bundle-core.js   ...
  · js/ui-all.js   1433788 字节  19 个 ui 文件（审计镜像，不进 bundle）
```

静态分析脚本改读 `js/ui-all.js`（6 个脚本 8 处），零维护成本、永远与源码同步。

### 这暴露的架构问题

**"模块清单"在这个项目里有 8 份，散落在 8 个地方。** 加一个模块要改 8 处，  
漏一处就出假红/假绿。这不是拆 ui.js 引入的，是原本就有的债 —— 拆分只是把它逼到了台面上。

**建议（下一步）**：建 `js/modules.json` 作为唯一来源，  
`build_bundle.py` / `smoke-test.js` / `audit.js` / 各审计脚本全部从它读。  
以后再拆模块、加模块，只改一处。

> 一句话总结这次拆分：**代码按功能域切是简单的；难的是这个项目有 8 份"模块清单"  
> 和 200 多处硬编码路径 —— 那才是"任何调整都上升到全局"的真正来源。**

## 十、以后怎么加 UI

1. **新面板 → 新建 `js/ui-<域>.js`**，开头固定 6 行（取 `GAME/DATA/U/ui/$/$$`）。
2. 在**这 8 处**登记（漏一处就会假红/假绿）：
   - `build_bundle.py` 的 `ORDER` 与 `UI_SPLIT`
   - `smoke-test.js` 的两处静态检查列表、两处 `ORDER`
   - `audit.js` 的 `MODULES` 与 `REF_MODULES`
   - 审计子脚本若硬编码了文件清单
3. 读源码一律用 `__uiAll()`（smoke）或 `js/ui-all.js`（审计脚本），**不要**再写 `readFileSync('js/ui.js')`。

> ⚠️ 第 2 条那"8 处"本身就是下一笔债 —— 建议收敛到 `js/modules.json` 单一来源。

# v158.26 · 「世界在动」的真相：镜头钉死了人

> 老板：「为啥移动整个世界都在动，而不是相机+人物移动」

## 一、先把两件事分开

**世界没有动。动的是镜头。**

实测（固定种子 `20261126`，真滚轮进地表，真按 W 走 **37.56 米**）：

| 量 | 实测值 | 说明 |
|---|---|---|
| 起点格的世界坐标漂移 | **0.000 米** | 走完 37 米回头看，那一格还在原处 |
| 地表根节点世界矩阵 | 两次逐位相同（恒等） | 整个地表层没被平移或旋转 |
| 地砖位置来源 | `_gridDirOf(绝对格号)` | 由世界格号决定，**不读玩家位置** |
| 树/草/石头落点 | 按 `ci` 播种 `ci*2654435761` | 同一格每次重建落点完全一致 |
| 相机位移 | **39.10 米** | 真正在动的就是这个 |

所以物理上确实是「相机+人物在动、世界静止」。

## 二、那为什么看起来像「整个世界在动」

因为镜头是**硬跟随**，人钉死在画面正中：

```js
cam.position.copy(P).addScaledVector(dirCam, M.SURF_CAM_DIST);
cam.lookAt(P.x, P.y, P.z);        // ← 每帧看玩家
```

`lookAt(P)` 保证玩家**永远在画面正中**。实测走动中玩家 NDC **恒 (0, 0)** —— 一像素不动。

人不动、背景在退，大脑只能读成「世界在搬运」。这正是星露谷里「人在走」的反面。

## 三、改法：镜头锚点带时间常数

| 常量 | 值 | 含义 |
|---|---|---|
| `M.SURF_CAM_LAG` | 0.26 s | 走动中：锚点以 0.26 秒时间常数逼近玩家 → 4.5 m/s 时稳态落后 **≈1.17 米** |
| `M.SURF_CAM_LAG_STOP` | 0.07 s | 停下后：迅速归位（**不做长时间自漂** —— v157.34「停手画面自己动」被否过） |

关键三点：

1. `cam.lookAt(A)` 看的是**锚点**，不是玩家 —— 玩家因此会偏向前进方向。这是「人真的在走」的来源。
2. 每帧把锚点**贴回球壳**（`multiplyScalar(R2 / |A|)`）：两帧之间走的是弦，不修正会一路往地里沉。
3. 进地表时 `M._surfCamAnchor = null` 重置，否则会从上一片地方一帧飞过来。

## 五、顺带查清（都不是 bug）

- **地表层每 2.6 米 `destroySurf + rebuildSurf`** 是性能设计（窗口 45×45 格、约 40 ms）。
  换的是一批窗口内的砖，砖的位置由世界坐标决定 —— 不是「世界在重建」。
- **地形层（46 米半径）质心跟着玩家漂 34 米**：那是窗口跟随，不是地形在移动。
- **球体没有自转**：`js/map3d.js` 里没有任何 `globe.rotation` 写入。

## 六、断言

- `§611④` 按新规则重写：`cam.lookAt(A.x, A.y, A.z)`，并**反向守卫** `cam.lookAt(P.x` 不许回来。
- 新增 `§614` 四条：
  1. 锚点滞后结构面（`SURF_CAM_LAG` / `lerp` / 贴回球壳 / `copy(A)`）
  2. 数值面：走 1 秒后落后 **1.0~1.4 米**，停 0.4 秒后 **< 0.05 米**（带下限，防平凡解）
  3. 进地表重置锚点
  4. 地砖位置只由绝对格号决定（不许读 `playerPose`）

## 七、还差一步（需要老板拍板）

所以走动时脚下是一整片均匀浅绿，唯一在动的是远处树线，这会**放大**「世界在平移」的错觉。

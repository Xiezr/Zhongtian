# 天时：一行只读天气，不该比导航还重

> 老板 2026-11-02：「天时啥的也省约一点」

---

## 一、先看它原来多重

`shot_topnav.js` 打出顶栏右侧工具区的实际宽度（1440 宽）：

```
改前   .nav-right = 207px   （🗺 图例 + 天时）
改后   .nav-right = 180px   （🗺 图例 + 天时）    -27px
```

单看天时这一块，改前是**金色渐变大招牌**：

```css
.nav-sky {
  font-size: var(--fs-sub); font-weight: 700; letter-spacing: 1px;
  color: var(--gold-light);
  background: linear-gradient(180deg, rgba(var(--gold-rgb),.14), rgba(var(--sh-rgb),.2));
  border: 1px solid var(--line-strong);   /* 比页签还重的描边 */
}
```

文字是 `天时 第 1 年 春季 ☀晴天` —— 14 个字，四个词。

问题在于**它和旁边的页签抢注意力**：页签是你可点的地方，字号 `--fs-sub` / 字重 400 / 描边 `--line`；
而一块只读的天气信息，字号一样、字重 700、金色渐变、描边还更强。
视觉上它是顶栏最亮的东西，但你点不动它。

## 二、改了什么

### ① 文字：四段压成三段（新出口 `STORY.skyBrief`）

```js
STORY.skyBrief = function () {          // 顶栏用（~100px 横条）
  return (s.world.year || 1) + '年 ' + se.name.charAt(0) + ' ' + we.icon + we.name;
};                                       // → "1年 春 ☀晴"

STORY.skyLine = function () {           // 公文 / 城市页 / 播报用（不变）
  return '第 ' + ... + ' 年 ' + se.name + ' ' + we.icon + we.name;
};                                       // → "第 1 年 春季 ☀晴天"
```

**为什么开两个出口，而不是直接改 `skyLine`**：
`skyLine` 是完整句，公文里"第 1 年 春季 晴天"读得顺；顶栏只有一条横带，要的是
"一眼扫到变了没有"。同源同数据，只是排版不同 —— 一个数据，两种排法。

去掉的虚字：`第` / `季`（春**季**→春）—— 季节取首字即可，中文单字季节没有歧义。

### ② 视觉：金色招牌 → 与「图例」同档的暗胶囊

```css
.nav-sky {
  font-size: var(--fs-cap); font-weight: 400; letter-spacing: 0;
  color: var(--text);
  background: rgba(var(--sh-rgb), .25);   /* 与 .nav-legend 同款 */
  border: 1px solid var(--line);          /* 从 --line-strong 降一档 */
}
.nav-sky:hover { color: var(--gold-light); border-color: var(--line-strong); }
.nav-sky .ns-k { color: var(--text-dim); }   /* 「天时」标签保持最暗 */
.nav-sky .ns-v { color: var(--parchment); }  /* 值亮一档 = 视线落点 */
```

右侧从此是**两个一样轻的工具**，不再是"一个小按钮 + 一块招牌"。

### ③ 完整信息不丢：进 tooltip

```js
sky.title = '天时：第 1 年 春 ☀晴（季节 / 天候影响全图产出与战斗）';
```

（顺手把 title 里过期的"年号"删了 —— 年号纪元 v90.93 已退役。）

## 三、断言口径同步（两条）

顶栏显示的句子变了，原来"逐字比对 `skyLine()` 全量串"的断言会**假红**：

```js
// 改前（smoke §v26 / e2e §26③）
var want = G.story.skyLine();
return el.innerHTML.indexOf(want) > 0;      // 顶栏不再有 "第 N 年 春季" 全量串
```

改成**按三段数据各自出现**判定，格式怎么排都判得住、少一段就真红：

```js
var y = G.state.world.year;
return y >= 1 && t.indexOf(y + '年') >= 0
  && t.indexOf(se.name.charAt(0)) >= 0
  && t.indexOf(we.name) >= 0;
```

> 这不是"改断言迁就实现"：期望值仍从**数据源**（currentSeason / currentWeather / world.year）算出，
> 不是从被改的那个函数自己算出来 —— 渲染坏了照样红。

另外补了一条守住"省约"本身的断言：

```js
check('顶栏天时是压缩句（省约口径：不含「第 N 年 季」全量句）', ...)
return t.length >= 4 && !/第\s*\d+\s*年/.test(t) && !/季/.test(t);
```

（**不测总长度上限** —— 右侧可能同时挂 1~3 枚状态 chip，长度会随局势变，设上限等于又埋一条假红。）

## 四、三条坑，一条比一条阴

### 坑 1：flex 的 gap 不吃裸文本节点

第一版只压缩了文字，`天时` 和 `1年` 依旧**粘在一起**：

```
天时1年 春 🌫雾      ← 中间看着像没有空格
```

根因：`.nav-sky` 是 `inline-flex`，`gap` 只作用于**flex item**；
而原来是 `innerHTML = '<span class="ns-k">天时</span>' + 文本`，
**裸文本节点不是 flex item**，gap 对它无效。

改法：值也包一层 span（`<span class="ns-v">`），gap 立刻生效，同时顺手拿到"值比标签亮一档"的层级。
间距从 `--sp-1`(4px) 提到 `--sp-2`(6px)。

### 坑 2：smoke 的 DOM 是 stub —— 写 `innerHTML` 不会同步 `textContent`

新断言第一版读 `el.textContent`，**恒为空**，于是判定"顶栏没有天时"→ 假红。

`smoke-test.js` 顶部的 `makeEl()` 是一个手写桩：`textContent` 和 `innerHTML` 是两个**互不联动**的字段，
ui 只写 `innerHTML`。所以 smoke 里判断"玩家看到什么"必须：

```js
var t = String(el.innerHTML || '').replace(/<[^>]*>/g, '');   // 剥标签
```

（e2e 是真实浏览器 DOM，`textContent` 正常可用 —— 两套环境语义不同，不能照抄。）

### 坑 3（最阴）：拆参数时漏了调用括号 → 断言变恒真

为了让失败时能看到实际值，我把 `check(name, fn())` 拆成 `check(name, fn(), detail())`，
手一抖写成：

```js
check('...', (function () {
  return y >= 1 && ...;
}, (function () { return 'txt=[...]'; })()));
//         ↑ 这里少了 ()：第二个参数是**函数对象**，truthy → 永远 ✅
```

跑出来全绿，但日志里那两条**没有 detail 方括号** —— 因为 `extra` 参数位置整个错位了。
`node --check` 也不报（语法完全合法）。

线索是"该出现的方括号没出现"，而不是"断言红了"。修好后重跑才是真绿。

> 教训：断言"通过"永远要看它**还有没有能力变红** —— 一条不再打印详情的断言，很可能已经不再执行判据了。
>
> （`audit.js` 里本来就有一条"恒真断言：把函数当布尔传"的检查，正是为这类事故准备的；
> 它这次没拦住，是因为我把坏版本和好版本混在同一轮里跑 —— 结构审计要在**最终版**上跑。）

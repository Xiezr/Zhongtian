# v157.81 · 把「相机姿态」从结构上收敛成单一来源

> 老板（第二次批评）：
> 「为什么高空地带左键旋转星球的时候还有死角……**通过代码严格实现，而不是测测测测测**。」

这句话是对的。前两轮（v157.78 / v157.80）我都是用探针一段段试出来的，
**修的是"我测到的那条路径"，不是"代码里所有可能的路径"**。所以每次都能测出"通过"，
你却仍然遇到死角。这一轮先做穷举式代码审查，再做结构性删除。

## 一、结构病根

`camO` 是**双真值**对象：

```js
camO.quat          // 姿态（四元数）
camO.yaw / pitch   // 姿态（球坐标参数），靠 camO._euler 与之同步
```

`placeCamera` 里有一段"脏检查"：yaw/pitch 与 `_euler` 不一致，就用 yaw/pitch 重建 quat。
**这意味着任何一处只写了 quat 或只写了 pitch 的代码，都会在下一帧被另一方覆盖。**

grep 全会列出 **11 处** 写 `camO.pitch` 的地方。其中两处是**每帧执行**的：

| 位置 | 形态 | 后果 |
|---|---|---|
| `placeCamera` 轨道分支 | `camO.pitch = asin(camO.dir[1])` | `asin` 主值域 `[−π/2, π/2]` → 玩家累加的 pitch 一旦越过 ±π/2 立刻折回 |
| 拖动分支 `else if (_P0 && _P1)` | 同样 `asin` 反算 | 这条是**死代码**（上方 `if (M._surf) return` 已挡），但同型代码留在链路里就是个待爆的雷 |

第一条就是"滚过极点就来回打转"的总根源。v157.80 我给它加了 `_surfVis` 守卫 ——
**那是给病灶加条件，不是切除**。

## 二、这轮做的：物理删除，不是加条件

### ① 删 `placeCamera` 里的 `asin` 反算（整段）

它名义作用是"从地表退回轨道时把径向折算成欧拉角"。但**这条理由在 v157.48 就失效了**：
现在地表模式全程不碰 `camO.yaw/pitch`（只改 `_surfDir` / `cam.position` / `cam.up`），
退出地表时 pitch/yaw 本来就是进去时的值，**根本不需要重算**。

所以整段删除。相机姿态自此只有一个来源：**输入**（拖动 / 滚轮 / 外部定位）。

### ② 删抓球面交点的整条链

`_ndcG` / `_rayG` / `_P0` / `_P1` / `_tgtG` 两次求交 + `else if (_P0 && _P1)` 分支：

- 该分支**永远不可达**（上方 `if (M._surf) { ... return; }` 已经挡住了地表模式）；
- 它内部就是那两行 `camO.pitch = asin(...)`；
- 顺带每帧省掉两次 `intersectObject`。

### ③ 加运行时**连续性守卫**（写进产品，不是测试）

```js
if (M._camPrevDir) {
  var _ja0 = acos(dot(prevDir, dir)) * 180 / Math.PI;
  if (_ja0 > (M.CAM_JUMP_MAX || 30)) M._camJumps.push({ deg, surf, rAlt });
}
M._camPrevDir = [dir.x, dir.y, dir.z];
```

这意味着：**以后任何人再往这条链路里塞"每帧反算 / 夹取 / 归一化"，不用等玩家投诉，
`M._camJumps` 里直接就有证据（带 surf / rAlt 上下文，能区分预期跳变）。**

这才是「严格实现」该有的样子：把不变量写进产品，而不是靠人一次次去试。

## 八、诚实缺口（本次查出来但**没动**的）

**贴地模式下左键拖动「竖直方向」没有反应**（阶段 C 实测 `frozen=120/120`）。
原因：贴地时 `if (M._surf && M._panDrag)` 走的是**平移**（移动相机位置），
`_panDrag` 为 false 时直接 `return`，没有任何转头动作。
v157.23 的注释写的是"地表左键 = 直接转头"，但那版实现后来被 v157.54 的纯增量平移替换了。
**这是独立的一条**（贴地交互语义），跟高空旋转无关，所以本轮没碰 —— 要不要改成
「贴地左键也能转头」，等你一句话。

# v157.54 · 近地面左键拖拽「整个画面元素剧烈跳动」整改

> 老板逐字原文：「在近地面的时候，鼠标左键长按拖动，有时候会发生剧烈的这个呃整个画面元素的一个跳动。
> 确认一下，我需要一个。绝对我。定的我建议采用最保守的方法。就任何涉及到界面的问题发生不稳定
> 都是因为这会极大的影响玩家的一个感受并影响他继续游戏的这样一个心情」

**一句话**：不改相机架构、不改玩法语义、不加滤波 —— 只把「每帧从当前相机重新求交地面」
这条**输入依赖输出的反馈回路**断开，改成按下时一次冻结尺度、之后每帧纯增量。

---

## 一、病根（探针实测，不是读代码猜的）

v157.24 定的左键语义是「粘住地面一点、相机反向走」，实现为**锚点抓取平移**：

```
每帧：p1 = _groundPtAt(当前相机, 当前鼠标)   ← 射线求交地面
      T  = 按下锚点 − p1
      camO.dir/dist += T                      ← 把差值全量补回相机
```

`p1` 依赖当前相机，而当前相机又由上一帧的 `T` 决定 —— **输入依赖自己的输出**。
贴地平视时俯角 θ→0，纵向每像素地面位移按 `1/sin²θ` 放大；再叠加旧实现写了
`camO.dist` 却**没调** `_syncZoom()`（本文件既有唯一出口，注释明写「否则下一帧被阻尼拉回旧目标」），
于是方向已变、半径被逐帧拽回：地面、标记、云层一起跳。

| 探针实测（`probe_v15754_pan_stability.js`） | 数值 |
|---|---|
| 俯角 42°→2° 每像素地面位移放大比 | **367.607 倍** |
| 贴地 2° 手抖 3px 的单帧位移 | 5.025 米 = **2.956 倍眼高** |
| 90 帧带手抖轨迹，改前单帧最大 | **7.883 米 = 4.637 倍眼高** |
| 同样轨迹在 42° 高空 | 0.010 米（改前近地面是它的 **821.390 倍**）→ 对应「有时候」，只在贴地时出现 |
| 改前 90 帧位移方向反转 | **25 次**（画面来回抽） |
| 反馈回路反证（逐帧累积 vs 每帧从初始相机重算） | 最大逐帧差 **34.763 米** |
| 缩放阻尼拉扯（单帧平移 40 米） | 球心距偏 **2.655 米 = 1.562 倍眼高**，阻尼每帧回拉 20.433% |

**为什么否掉其它路径**（`AGENTS.md §十二` 计划段逐条留痕）：

| 被否 | 理由 |
|---|---|
| 退回 v157.23「左键纯转头」 | 会推翻老板 v157.24 明确要的「移动相机本身」，属玩法取舍，AI 不擅自改 |
| 给回路加阻尼 / 低通 / 滤波 | `map3d.js` 既有注释已写明这类手法「都是把跳摊成漂」；要的是绝对稳定，不是漂得慢 |
| 调小单帧上限 40 / 提高 `rebuildSurf` 节流 | 治标：掠射病态与 `_zoomTarget` 拉扯仍在，还会偷偷改手感速度 |
| 重做相机架构 / 换四元数方案 | 超出「最保守」，改动面会炸到 `placeCamera`、淡出、模式切换 |

## 二、改法（改前 / 改后）

| 面 | 改前 | 改后 |
|---|---|---|
| 尺度来源 | **每帧**从当前相机射线求交，实时算 `T` | `mousedown` 一次采 (x,y)/(x+1,y)/(x,y+1) 三个地面点，由 `panBasisOf` 算出每像素切平面位移 ex/ey 并**冻结** |
| 每帧位移 | `anchor − p1` 全量补回 | `panStepOf(dx, dy, 冻结基准)` = −(dx·ex + dy·ey)，**纯增量、不读相机** |
| 单帧限幅 | 40 米常数 | ≤ 半个眼高（`maxStep = eye × 0.5`）；每像素 ≤ 15% 眼高；掠射爆炸值由 `_panClamp` 收口 |
| 半径 | 改 `camO.dist = _nl`，**未**同步 `_zoomTarget` | **根本不写 `camO.dist`**：新位置归一化到按下时冻结的半径；滚轮阻尼完全不受拖拽干扰 |
| 状态 | `M._panA`（按下锚点 + `M._panDrag`） | `M._panBasis`（冻结基准）；`_panA` 整条退役，不留只写不读的字段 |
| 坏值 | 无守卫 | `dx/dy` 非有限、输出非有限 → `ok:false`，**跳过本帧、不写任何状态** |
| 视线 | 不改 | **仍不改** `_surfDir` / `_surfRight`：平移只搬位置，不转头 |

**两个纯数学出口挂在 `typeof THREE === 'undefined'` 守卫之前**（照 v156.15 先例），
并且**同时**挂到降级 no-THREE 出口和完整 `GAME.map3d` 出口 —— 这样 smoke / jsdom 能
**真调**它们，而不是只 grep 源码在场。

**取证后的两处修正（留痕，不是改需求）**：
1. 原计划「改完 `camO.dist` 后补 `_syncZoom()`」→ 实测发现补同步会把用户**正在逼近的
   滚轮目标**改成当前值，反而多一处写入、多一处干扰。改为根本不写半径，更保守也更彻底。
2. 原计划用「换相机起点」反证回路 → 起点在 `anchor − p1` 中会抵消（探针报 0.000 米，
   是**假红判据**）。改为「逐帧累积 vs 不累积」对照，才拿到 34.763 米的反证。

## 三、实测证据（探针原始输出）

```

BEFORE 近地面 : max=7.883 米  mean=3.654  ÷眼高=4.637  miss=0
BEFORE 高空42°: max=0.010 米  mean=0.007  ÷眼高=0.006  miss=0
AFTER  近地面 : max=0.178 米  mean=0.121  ÷眼高=0.105  miss=0  k=0.058

=== C · 反馈回路是否断开（累积 vs 不累积，同一串鼠标输入）===
BEFORE 累积 vs 不累积：最大逐帧差 = 34.763 米
AFTER  累积 vs 不累积：最大逐帧差 = 0.000 米
```

**改后**：单帧 **0.178 米（0.105 倍眼高）** · 方向反转 **0 次** · 回路差 **0.000 米**。
探针 12/12 判据全绿，每条都带**下限**（放大比 ≥100、帧数 ≥60、改前 ≥1 倍眼高、
对照两套模拟都真跑 90 帧），防 `0 === 0` 式平凡解。

**判据的两层分离**：数值有界 / 回路断开 / 无 NaN 由机器判；
「是否跟手」「还有没有可感跳动」是**主观项，由老板 Ctrl+F5 后实机长按拖动判定**，AI 不代拍板。

## 五、诚实缺口

1. **主观手感未由 AI 结案**：「跟不跟手」「还有没有可感跳动」须老板实机判定；
   本轮只给对比数值与回退路径。
2. **代价**：拖得很远时「点严格贴在光标下」由精确变为一阶近似（轻微漂移）——
   这是「构造上不可能跳」的代价，不是 bug。若要精确跟手，需要重新引入每帧拾取，
   与「绝对稳定」冲突，须老板另行拍板。
3. **工具口径分叉（既有，未擅动）**：`bump_version.py` 把 `?v=` 当数字 BUILD 号，
   `build_bundle.py` 把它当内容 hash；两者并存。本轮照 v157.53 先例只走
   `build_bundle.py`（它同时保证缓存自动失效），未动 `bump_version.py`。
4. **需求档案总览表停在 v157.12**（既有欠账 41 行）：本轮只补本轮一行，未擅自回填历史。
5. **未做实机截图**：本轮是鼠标拖拽时序问题，静态截图无法证明「连续、无跳」；
   老板 Ctrl+F5 后的实机长按拖动才是终审。
6. `README_INDEX.md` 的 `gltf/node_modules` 843 条污染仍在（既有，v157.53 已报备，
   等老板一句话，本轮未扩大改动面）。

**复核销项**（经核查无需动作，附证据）：
- 「偷换语义/方向」：销项 —— 公式对照 + 针孔模型数值验证，相机位移 = −(dx·ex+dy·ey) 与旧式 `cam += anchor − hit` 一阶同向（下拖 = 相机向前）。
- 「`_panA` 残留 / 只写不读」：销项 —— 全仓 grep，源码与 bundle 仅剩墓碑注释。
- 「bundle/hash/?v 不一致」：销项 —— 三包 sha256 现场重算逐一相等（§591④ 的红是 `modules.json` 索引问题，见①）。
- 「mouseup 吞点击 / `moved` 错判」：销项 —— `moved` 来自原始鼠标增量（与旧版同源），`panStepOf` 的 `ok:false` 不影响它。
- 「半径回拉/滚轮干扰」：销项 —— 新分支零写 `camO.dist`，`_zoomDamp`(5477) 独占半径写权。

**复核观察项**（记录，不扩改动面）：
- §600② 段切片边界经复核逐行核实只覆盖平移分支（`indexOf` 双锚全文件唯一命中），切片内无行注释可剥漏。
- 探针 AFTER 判据与 §600⑤「换起点」判据属**构造性平凡**（纯函数无状态）——实现级回路断开由 §600② 负向断言 + 逐行阅读闭环，链条成立但运行期事件接线层证据只到 grep 级；探针头注自称「§601」实为 §600⑤（笔误，不影响判据）。

# v158.24 · 「走近勘探」从假承诺变成真机制

> 老板原话：「城外地块怎么建资源建筑，什么叫做走近勘探后才能建，怎么走近，行为逻辑链真的有吗，真的完善吗」

## 先认账：这是假承诺

`RS.scan(ci)` **零距离校验**，文案却写着「走近勘探后才能建厂」。
实测人站在 **4.6 格外** 点一下「勘探」直接成功，`playerCi` 一步没动：

```
—— 目标地块  {"ci":3867,"type":"forest","res":"wood","away":4.6}
—— 勘探后    {"scanned":true,"richness":1.16,"reserve":18562226,"playerCi":5823}   ← 人没动
```

玩家读到「走近」就会去找「怎么走近」，而游戏里没有这个动作 —— 链路在玩家心里当场断掉。

## 链路本身是通的（已实测到底）

点地块 → 「🔍 勘探」→ 得丰度/储量 → 「⚒ 建采集场」→ 选建筑（水培温室）→ 「🏭 开工建造」→ 施工队列入队 1 条。

所以不是"建不了"，是**没说清怎么建**。

## 真正的断点在别处

```
{total:40962, city:1, fog:40901, noRes:25, scanned:3, near:23, ok:9}
```

全图 **99.85% 在迷雾里**，开局能建厂的野地只有 **9 块**，全在脚边 24 米内。
玩家不是不会建，是**没有路走到别的资源地块**。

## 本轮改动：把「走近」做成真的

| 环 | 行为 |
|---|---|
| 距目标 > 2 格（≈11 米） | 按钮变成 **「🚶 走过去勘探（约 N 米）」**，不再假装就地能探 |
| 点它 | 关面板（不挡路）+ 小人自动走过去 + HUD **立刻**显示「🚶 正在走过去…还剩 24 米」 |
| 到达 | `stepWalkTo` 的**唯一到达出口**执行挂起动作：**自动勘探**（免费）→ 重开面板 → 直接给「⚒ 建采集场」 |
| ≤ 2 格 | 就地「🔍 勘探 / ⚒ 建采集场」（不让人再走一次） |

### 一个结构性修正
到达后的动作原来写在**渲染循环**里，手动驱动（自动化/探针）会整段失效
（实测"走到了却没勘探，面板也没重开"）。
→ 下沉到 `M.stepWalkTo` 的到达分支（到达的唯一出口），UI 仍在外面开。
渲染循环里那段随之删除（避免死代码）。

## 实测（真点击）

探针 `.workbuddy/tools/probe/p_walk_scan.js`：**10 通过 / 0 失败**

| 项 | 结果 |
|---|---|
| 24.3 米外 | 只给「🚶 走过去勘探（约 24 米）」，`res-scan` 不存在 |
| 点它 | 面板关闭、`walkTarget=3867`、`_walkThen={act:'scan'}`、HUD「还剩 24 米」 |
| 到达 | `scanned: true`、面板自动重开、出现「建采集场」、不再是「走过去建」 |
| 站到格上 | 就地建厂按钮（`res-build-open`） |

截图：`.workbuddy/tmp/pwalknear/1_far_panel.png`（远处面板）、`2_arrived_panel.png`（到达后）

## 数据层文案修正

`'尚未勘探（走近勘探后才能建厂）'` → `'尚未勘探（先勘探这块地）'`
（数据层不该提 UI 概念；"怎么勘探"是面板的事）

## 断言

`§613` 新增 4 条：两种入口并存 / 数据层不再提「走近」/ 到达动作在唯一出口 / 点击后立刻刷 HUD。

`e2e` 的「未占领野地有勘探入口」按新规则放宽到 `res-scan | res-go-scan`（两种形态都算入口）。

## ⚠️ 还没解决（要老板拍板方向）

**开局 99.85% 是迷雾、可建厂地块只有 9 块。** 这不是文案问题，是探索范围太小。
三条路，选一条：

1. **开局多探明一圈**（比如首都周边 10 格 + 沿路），让玩家一进游戏就有十几块可选；
2. **让"派队探路"更快**（现在点未探明格是派队流程，没有即时反馈）；
3. **放大可建半径**（允许在已探明的更大范围建厂，不要求走过去）。

我倾向 1 + 2：探索是玩法，但开局不该是"一张黑纸"。

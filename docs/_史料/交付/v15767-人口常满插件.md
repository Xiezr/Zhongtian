# v157.67 · 2026-11-15 · 退役「无限人口」，改为「人口常满」

## 1. 需求与病根

老板逐字：「**我觉得插件的无限人口，上限视为999999没什么用，去掉吧，改为人口总为现有上限人口，随时补足**」。

旧插件（v157.64）的做法是把人口上限**唯一基准** `GAME.maxPopOf` 运行时换成恒 `999999` 的引用，靠派生链
（`effPopCapOf` / `popGrowthOf` / 迁入封顶）一起放大。它"没什么用"的技术原因有两层：

1. **不即时**：增速基数也跟着上限放大，但 `popGrowthOf` 的口径是「固定补满时长」（`DATA.POP_CFG.fillHours`，
   约 2 **现实小时**补满）—— 换上限只是把"要爬 2 小时的那个数"换大了，开启当下人口一点没变；
2. **不贴题**：玩家要看的是界面 `pop / cap` 里的那个 `cap`（居所基准经民心折算的
   `GAME.effPopCapOf`），而插件把分母顶到 999,999，反而让"人口 / 上限"这一对读数失去意义。

需求的实质 = **上限一个都不改，只让存量恒等于现有上限，并且掉下去就补回来**。

## 2. 口径（唯一出口）

| 事项 | 出口 | 说明 |
|---|---|---|
| 「现有上限人口」 | `GAME.effPopCapOf(city)` | 界面 `pop / cap` 的分母，也是 `state.js:4570` 人口爬升的目标（居所基准 × 民心%） |
| 存量写入 | `GAME.res(city).pop` | 与 v157.65「现有人口设定」同一个唯一写入口；不碰 `state.cities` 内部结构 |
| 补足节拍 | `GAME.tickOnce` | 在线主循环与离线逐秒补算**共用的唯一时间刻度**；包装后每拍末尾补一次，开启瞬间先补一次 |
| 上限出口 | `maxPopOf` / `effPopCapOf` / `popGrowthOf` | 三个引用**一律不动**（旧插件替换 `maxPopOf` 的做法整条退役） |

「总为」= **真相等**（`pop === cap`）：减员（辐射云 / 气候 / 遣散 / 战损）下一拍补回；
上限升高（造居所 / 民心回升）同步跟上；上限下降时也同步回落。
关闭插件后游戏既有「只封增长、不削存量」立即恢复，最后一刻的存量不回滚。

## 6. 诚实缺口

1. **「总为」会削存量**：上限下降时人口同步回落，与游戏既有「只封增长、不削存量」相反 ——
   这是本插件的显式口径（老板要"总为"）。若改主意要"只补不削"，把 `topUpAllPop` 里的
   `R.pop = cap;` 改成 `if (R.pop < cap) R.pop = cap;` 一行即可。
2. **补足最多滞后 1 拍**：在线每秒一拍；离线**聚合**补算段（`simulateBulk`，不逐拍）期间不补，
   回到在线的第一拍补齐 —— 不是"零延迟的即时拦截"。
3. **与「现有人口设定」同时开启**：`full-pop` 每拍以当前上限为准，会覆盖 `set-pop` 注入的超限值
   （已写进 `set-pop` 的模块注释）。两插件语义冲突时以"人口常满"为准。
4. **上限口径取 `effPopCapOf`**（民心折算后的分母）。若想改按居所基准 `maxPopOf`，一处读数即可切换，
   但会与界面 `pop / cap` 的分母不一致，不建议。
5. localStorage 里旧 `infinite-pop` 的开关键残留不会被读取（已无对应插件），无需迁移；插件状态仍不写入存档。

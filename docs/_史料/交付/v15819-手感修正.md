# 手感修正：把"老年痴呆"的走法修回正常人（v158.19）

> 老板 2026-11-26：「走的好像老年痴呆一样。」

## 一、先量，再改

不靠目测 —— 探针 `p_walk.js` 量四项：位移速度、转身速率、球面小人腿有没有动、街区步频。

| 项 | 实测 | 真人基准 | 判断 |
|---|---|---|---|
| 球面移动 | 4.5 m/s | 步行 1.4 / 慢跑 4.5 | 速度没问题 |
| **转身** | 103°/s，转 90° 要 **0.87 秒** | 约 0.5 秒 | **迟钝 1.75 倍** |
| **球面小人** | 腿 `rotation.x` 从不变化、`walking` 恒 false | — | **纯滑行** |
| 街区步频 | 写死 `dt*9`（1.43 Hz） | 步幅 1.5m 慢跑约 3 步/s | 改速度就滑步 |

**"老年痴呆"的三个来源**：人贴在地上滑（腿不动）、转身像在磨（0.87 秒/90°）、步频与速度解耦（一改速度就滑）。

## 二、改了什么

### ① 球面跟随态补摆腿（`js/map3d.js` `followAvatar`）

原来只做 `placeFigureAtDir(fg, p.dir, yaw)` —— 摆位置、摆朝向，**腿一动不动**。
街区的 `syncAvatar` 早就有摆腿公式，球面这只没有。现在照同一套补上：

```js
var _mv = !!(avOut && avOut.moved);
M._figMoving = _mv;
if (_mv) M._figPhase += dt * (M.WALK_SPEED / 1.5) * Math.PI;   // 步幅 1.5m 的慢跑口径
else M._figPhase = 0;                                          // 一停立刻归零
var _sw = _mv ? Math.sin(M._figPhase) * 0.6 : 0;
_legs[0].rotation.x = _sw;  _legs[1].rotation.x = -_sw;
```

另加 3cm 上下颠簸（与街区同一口径）—— 纯滑行最大的破绽是"身体高度完全不抖"。

渲染循环把 `stepAvatar` 的返回 **传给** `followAvatar`（原来直接丢弃，所以根本不知道"这一帧走没走"）。

### ② 转身 1.8 → 3.0 rad/s（`map3d.js` + `district.js` 同一把尺）

103°/s → **172°/s**，转 90° 从 **0.87 秒降到 0.52 秒**（真人约 0.5 秒）。

### ③ 街区步频跟速度（`js/district.js` `syncAvatar`）

`dt * 9` → `dt * ((WALK_SPEED||4.5) / 1.5) * Math.PI`。
4.5 m/s 时 = 9.42（旧观感几乎不变），但从此**与大世界同一把尺**，改速度动画自动跟。

### ④ `figureOf().walking` 如实反映（`js/map3d.js`）

这个字段从 v157.85（前传行走插值退役）起一直恒 `false`，探针/调试读到的永远是"没在走"。
现在读 `M._figMoving`：走时 true、停时 false。

## 四、一个算法坑（记录）

首版探针把 `phase/(2π)` 当"步数"算步幅，得出"2.32m/步、滑步 3 倍"的错误结论。
`sin(phase)` 一个 **2π 周期是左右各一步**，所以一步 = **π 相位**。改正后步幅 1.49m —— 街区其实一直是对的。

## 五、没动的

- **移动速度 4.5 m/s 保持**：它是慢跑（16 km/h），降到步行会让大地图走起来更累。
  真正的问题不是快，是"腿不动 + 转身慢"，已在 ①② 修掉。
- **A/D 是原地转身（坦克操作）**：这是既有操控设计（P0 定的），改成侧移会动按键语义和既有断言。
  如果老板仍觉得"不听使唤"，下一步可以做"鼠标转向"或"A/D 侧移"，但那要单独授权。

# v89.106 · 城内建筑配色重做（"颜色很奇怪 + 没有区分度"）

> 老板原话：「**还是有些城内建筑颜色很奇怪，而且没有区分度**」
> 交付物：新配色素材（16 张）+ 可复跑的量测工具 + 前后对照图 + 门禁断言

---

## 一、病根（一句话）

**配色判据错了**：v89.104 把七族全塞进 8°~68° 的暖带、靠"色相 10° 步进 + 明度差 12%"
当"可分"——**色相步进不等于人眼可分**。实机量出来：七族两两 **21 对里 14 对 ΔE00 < 15**，
最像的一对（书院/驿站）只有 **4.4**，等于同一种颜色。

顺带挖出两个真 bug：

1. **城墙被染成金色**：`data.js` 写的是 `chengqiang: mil`（军事），而改色工具里另抄的
   `SER_OF` 表写的是 `gov` —— 三份族归属表（data / 工具 / 测试）各说各话。
2. **改色工具把读写路径写成了同一个**：`apply` 时"从备份读、往备份写"，
   一把火把**原图**烧了（工作区纹丝不动）。靠 `git show HEAD:` 才找回 —— 已加硬断言。

## 二、改法

### 2.1 判据：色相步进 → **CIEDE2000 色差**

| 口径 | 改前 | 改后 |
|---|---|---|
| 资产（PNG 像素）最小族间 ΔE00 | **7.5**（民房/客栈 vs 驿站） | **16.9** |
| 屏幕（实机截图核心区）最小族间 ΔE00 | **4.4**（书院/驿站） | **16.9** |
| 屏幕最小"跳得出地面" ΔE00 | 30.0（全区偏暗所以反差大） | **18.7** |
| 屏幕 ΔE00 < 15 的族对 | **14 / 21 对** | **0 对** |

阈值取 15（>12 肉眼可辨、>18 一眼可辨；族是要"一眼"认的）。
判据写进 smoke：`PIX.de00()`（CIEDE2000 全文实现）+ 两条断言（族间 ≥15 / 与地面 ≥12）。

### 2.2 族归属与配色：三份表 → **一份表（data.js）**

```js
DATA.SERIES = {
  gov:   { name:'官署', paint:{ h: 42,  s:0.46, l:54 } },  // 金瓦
  live:  { name:'民居', paint:{ h: 62,  s:0.36, l:88 } },  // 米白墙
  store: { name:'仓廪', paint:{ h: 35,  s:0.32, l:31 } },  // 夯土褐
  edu:   { name:'文教', paint:{ h:160,  s:0.31, l:34 } },  // 石绿竹青
  mil:   { name:'军事', paint:{ h:212,  s:0.32, l:36 } },  // 铁青
  biz:   { name:'工商', paint:{ h: 10,  s:0.46, l:50 } },  // 朱红陶
  road:  { name:'驿传', paint:{ h:194,  s:0.31, l:62 } },  // 青灰
};
DATA.SERIES_OF = …                       // 由 BUILDINGS[].series 反查，代码生成
```

* `paint` 的 h/s/l 是**目标均值**（改色工具逐图求增量旋转量），不是"每个像素一个色"；
* 素材工具（`recolor_bldg_icons.js`）与门禁（`smoke-test.js`）都**只读这份表** →
  "改数据不生效"从结构上消失；
* 城墙归 `mil`（跟 data.js 走），不再有金色城墙。

### 2.3 素材：一律从原图上色（可反复 apply 不劣化）

工具里 `src`（备份）/`dst`（工作区）**成对出现并在写前断言两者不同路径**。

## 三、实测证据

### 3.1 屏幕级（真机截图 → 按图标 bbox 取**核心区**像素 → 算 ΔE00）

改色**前**（v89.104 暖带盘，21 对里 14 对糊在一起）：

```
edu/road   4.4  <<<   edu/live  5.6  <<<   gov/mil   5.8  <<<
live/road  6.2  <<<   gov/store 8.7  <<<   mil/store 9.7  <<<
live/store 10.2 <<<   biz/store 10.8 <<<   biz/mil   11.9 <<<
gov/live   13.0 <<<   edu/gov   13.7 <<<   edu/store 14.4 <<<
** 屏幕最小族间 ΔE00 = 4.4（edu/road）**
```

改色**后**（全部 ≥ 16.9，`0 对`低于门槛）：

```
biz/gov   16.9 ← 最像的一对      edu/store 21.4    edu/mil   21.5
live/road 24.0                   gov/store 24.9    biz/store 25.4
mil/store 25.9                   mil/road  29.9    gov/road  31.7
biz/mil   33.0                   gov/live  33.7    edu/gov   35.8
edu/road  36.8                   biz/road  38.5    biz/live  40.6
biz/edu   41.8                   road/store 41.8   live/mil  50.7
edu/live  56.5                   live/store 57.1
** 屏幕最小族间 ΔE00 = 16.9 · 最小与地面 ΔE00 = 18.7（road）**
```

> **量测口径的坑（本轮踩过）**：第一次用"bbox 内所有非地面像素"，
> 抗锯齿软边与绿色地面混色，把米白民居拖到"距地面 ΔE00 7.4"（假警报）。
> 改成 **bbox 正中 56% 核心区**才等于"眼睛看到的那一大块"。工具里已写死这个口径。

### 3.2 资产级（解码 PNG）

`recolor_bldg_icons.js check`：七族全部与 paint 目标一致（±10°）、
饱和 31~46%、明度 31~70%（可读区间），最小 ΔE00 16.9、与地面最小 16.7 ✅

## 六、诚实缺口（需要老板定夺 / 下轮处理）

1. **配色是"可量化"而非"已拍板"**：本轮把"分不分得出"钉死成 ΔE00 ≥15，但
   **好看与否只有老板的眼睛能定**。请重点看三张图：
   `v89106-city-closeup.png`（棋盘特写）、`v89106-bldg-icons-prev-vs-new.png`（图标对照）。
   若某族不顺眼，**改一处 + 一条命令**即可（见 §四），不想大改也可单族微调。
2. **最像的一对是 biz/gov（朱红 vs 金，16.9）**：都属暖色、都偏亮，是语义决定的
   （炉火摊铺 vs 金瓦官府）。已把它推到门槛之上，但它仍是"最需要盯着看"的一对。
3. **城墙配色随族改为铁青**（原为金色）：这是按 `data.js` 的既有归属纠正的，
   若老板认为城墙该另立一族（例如"城防"），说一声即可加。
4. **e2e 断言数 1044（比上轮文档记的 1045 少 1）**：本轮未改 `e2e-test.js`，
   原因是 `P-23（兵力悬殊首击拦下）` 是**条件断言**（仅当战力比 <0.5 才跑），
   本轮该分支未命中（找到的野地 Lv4 而非 Lv3）。建议下轮把它改成"两种情形都断言"，
   免得这条断言长期空转。
5. **`live`（米白民居）是全场最浅的族**：屏幕实测 (231,231,213)，
   与地面 ΔE00 = 23.0（达标）。若老板觉得"太素"，把 `paint.l` 从 88 降到 76
   可加深一档（会让它与 gov 的距离缩小，届时以 ΔE00 复量为准）。

# v15789 商业级 3D 路线评估：到底要不要上虚幻引擎

> 日期：2026-11-18　性质：**评估，非版本落地**（本轮不动任何游戏代码）
> 老板口径：「感觉只有虚幻引擎才能继续往下做了」→ 拍板「奔商业级 3D，先出迁移评估」
> 依据：项目家底实测 + 2026-11-17 对 Epic 官方文档与行业现状的事实核查（来源见文末）

---

## 一句话结论

**「上 UE」这个决定本身没错，但要先回答一个更靠前的问题：你要的「商业级」是在浏览器里，还是要变成可下载的客户端？**

因为到今天（2026-11）为止，UE 登陆浏览器有三条路，**没有一条能同时给到「UE 全画质 + 断网可跑 + 零成本 + 稳定」**——而这四条恰好都是本项目现在的立身之本。所以这不是「换个渲染器」的升级，是一次**产品形态重做**。

我的建议：**先花小钱做一个 UE 标杆场景 demo，用实图量出画质差距，再决定要不要付这次重做的代价。** 不要在「差距到底多大」还没量出来之前就推倒 20 万行代码。

---

## 一、先认清：「商业级」是哪一种（这是所有决策的分叉口）

| 目标形态 | 画质上限 | 是否守住「网页断网可跑」 | 代价量级 |
|---|---|---|---|
| A. 网页三件套强化（three.js + 后处理 + 反射 + 正式素材） | 中上，接近但非 3A | ✅ 完全守住 | 小（2~3 轮迭代） |
| B. UE 网页原生（5.9 Wasm/WebGPU） | **受限**：移动渲染器，无 Lumen/Nanite | ⚠️ 守住但仅 Chrome、实验性 | 大（逻辑+UI+资产全重做） |
| C. UE 云端串流（Pixel Streaming） | 完整 UE 画质 | ❌ 必须联网+服务器 | 大且持续烧钱 |
| D. UE 客户端化（放弃网页） | 完整 UE 画质 | ❌ 变成要下载的 exe | **最大**（等于重做游戏） |

**核心矛盾**：老板想要的「商业级画质」，其来源（Lumen 全局光照、Nanite、虚拟阴影、Substrate 材质）在网页端 B/C 两条路里要么不可用、要么要持续付费。换成 UE 未必拿到你想要的画面，却一定丢掉现在的「打开网页就能玩、断网也能跑」。

## 二、家底盘点：我们手上到底有什么（实测）

| 项目 | 现状 | 迁移含义 |
|---|---|---|
| 全项目代码 | **205,363 行 JS / 88 模块** | 体量不小，重做是「人月」级不是「人天」级 |
| 3D 呈现层 | **15,022 行**（map3d 8443 / scene3d 4570 / sphere 988 / gltf 733 / duel3d 288） | 这层在 UE 里 100% 推倒重写 |
| 游戏逻辑层 | 约 **3.3 万行**（domain 9716 / data 7360 / state 6453 / battle 5121 / events 372） | 纯逻辑，可思路移植，但要重绑到 C++/蓝图 |
| 场景 | **11 个**程序化 2.5D 场景（废墟/林地/农田/湖面/村落/试炼/营地/尖塔/集市/坠机/官府） | UE 里要重建 11 个场景 |
| UI | DOM/CSS 体系 | UE 里要用 UMG 全部重做 |
| 门禁体系 | 5 道门禁 + smoke 4508 断言 + e2e 1100 断言 + 构建/审计工具链 | **这是被低估的资产**，UE 项目要重建整套测试基座 |
| 3D 美术资产 | **只有 2 个 GLB**：Soldier 2.1M（蒙皮空间坏，已弃用）、RobotExpressive 456K | ⚠️ 真正的瓶颈在这里 |
| 渲染依赖 | 单文件 `vendor/three.min.js` 670KB，运行期零依赖、断网可跑 | UE 网页构建动辄上百 MB |

**一句话**：代码可以重写，门禁可以重建，但「断网可跑的纯静态单机 + 完整测试基座」是这套系统最值钱也最难复制的部分。

## 三、UE 上网页的三条现实路径（2026-11 最新事实）

### 路径 B：UE 5.9 原生 Web 目标（Wasm + WebGPU）—— 刚出生，别当小白鼠

- 2026-11-09 Epic 发布 5.9 Preview，**首次**把官方 Web 目标加回来（此前 UE5 一直没有，UE4.24 起 HTML5 就被移出引擎）。这是真进展，不是传闻。
- 但限制一大堆，全是硬伤：
  - **实验性、Epic 自称 unstable，完整版预计 2027 年**；
  - **需要源码构建引擎 + C++ 项目**，纯蓝图项目用不了（我们是纯 JS，更没有现成 C++ 工程）；
  - 跑的是**移动渲染器**——**Lumen 全局光照、Nanite 均不可用**，实验性桌面档还在路上；
  - **只有 Chrome 被 Epic 点名**支持，Safari/Firefox 不保；
  - 存档和设置**刷新即丢失**（UE-412003）；Wasm 内存**超过 2GB 崩溃**（UE-411671）；
  - 构建体积：Epic 自己的 Lyra/Development 构建**超过 itch.io 的 500MB 总量 / 200MB 单文件上限**；
  - 纹理须用 ASTC，Bink 视频不支持，移动端多线程会崩。

**判断**：现在用它 = 用 UE 的成本，换一个在浏览器里被砍掉最强画质、还一堆已知 bug 的 UE。等 2027 稳定版再说，届时迁移成本只会更低。

### 路径 C：Pixel Streaming（云端 GPU 串流）—— 和项目定位直接冲突

- 原理：游戏跑在服务器上，浏览器收视频流。Full UE 画质在手，但：
  - **每并发玩家一个 GPU 实例**，必须联网，玩家不联网就玩不了；
  - 成本按小时计：AWS GameLift Streams 约 $0.16~1.82/流小时，托管型 $1.50~9/小时+套餐费；5000 会话/月 ≈ $990~1730/月，5 万会话 ≈ 每月上万美元。
- **这等于把「断网可跑的纯静态单机」改成「联网按量付费的云服务」**，产品形态彻底变了，还引入长期运营成本和服务器运维。

### 路径 B+/D：第三方构建（Strata/SimplyStream）或客户端化

- 有第三方（如 SimplyStream 的 Strata）把 UE5.8/6 编译到 WebGPU，玩家本地 GPU 渲染、$0/分钟、构建可小到 8MB，桌面档支持 Nanite/Lumen。
- 但依赖第三方构建与托管，长期绑定风险高；且仍是「等生态成熟」的路线。
- 真正能吃满 UE 画质的是 **D：放弃网页、做客户端 exe**——但这就是「重做整个游戏」，与「继续往下做」的初衷背离。

## 四、迁移工作量拆解（数量级，非精确报价）

| 模块 | 动作 | 量级 |
|---|---|---|
| 游戏逻辑 3.3 万行 | C++/蓝图重写或桥接，重新验证数值链 | 数人月 |
| 3D 呈现层 1.5 万行 | 球面/相机/11 场景/人形/水面全部重做 | 数人月 |
| UI（DOM/CSS） | UMG 全部重做 | 数人月 |
| 美术资产 | 商业级角色/场景/材质/动画/音效 | **最大头，无上限** |
| 门禁测试基座 | smoke/e2e/audit/invariants/chain 重建 | 数人周~人月 |
| 构建发布 | 从静态 bundle 改为 UE cook/打包/分发 | 人周级 |

**合计：这是「半年~年级别、需要专职团队」的工程**，不是本轮能启动的迭代。

## 五、真正的瓶颈：不是引擎，是美术资产

这是最需要说清的一点。上一轮 `Soldier.glb` 蒙皮空间是坏的（网格 0.003 / 骨骼 1.5），最后只能用程序化人形顶上。现在 `assets/` 虽然 1.7G，但**几乎全是 2D 图标 PNG，3D 模型只有 2 个 GLB，其中一个是坏的**。

- UE 再强，喂进去的还是「程序化基本体 + 坏模型」，出来的画面不会比现在好多少；
- 「商业级 3D」的观感 80% 来自**专业美术资产 + 光照设计 + 后处理**，引擎只是承载工具；
- **换引擎解决不了「没有好素材」这个问题**——这个坑，留在 three.js 里用正式 GLB + 后处理一样能填上，而且便宜得多。

## 六、推荐路径：先证伪，再投入

**第 0 步（强烈建议先做，成本最低）**：选 1 个现有场景（建议湖面 `lake`，最贴近「战舰世界」那种观感目标），做一个 **UE 标杆 demo**（60 秒可走动片段），和当前 three.js 版本并排对比。用实图回答两个问题：
1. 画质差距到底有多大？值不值得迁移？
2. 这个差距里，多少来自引擎、多少来自「我们没买好素材」？

**如果标杆证明差距主要来自素材** → 走路径 A，留 three.js，把钱花在后处理三件套 + 平面反射 + 一套正规 GLB 素材，2~3 轮见效，守住网页单机定位。

**如果标杆证明 UE 引擎本身的差距不可替代** → 再决定是路径 D（客户端化，接受重做）还是等 2027 的 5.9 正式版走路径 B。那时再付代价，付得明白。

---

## 七、待你拍板的 3 件事

1. **画质目标**：要「网页里能跑的中上画质」还是「必须原生客户端的商业级」？（这一条直接决定生死）
2. **产品形态**：能否接受从「打开网页就能玩的断网单机」变成「要下载/要联网」？
3. **美术预算**：是否愿意为专业 3D 资产投入（钱或人力）？没有这条，换任何引擎都到不了商业级。

## 1. 目标（玩家感知）

- **走出城，世界是满的**：星球表面按地形自动长树、草丛、岩石、芦苇——不再只有探索点配套的零星装饰，也不再是「每次开档的空壳」。

## 2. 路径（行业标准 + 仓库出口）

> ⛔ **架构硬约束（老板 2026-11-25 明示：「资产爆炸后，若还是全图加载资产，会不会很难」）**
>
> 量产**绝不允许**「全星球一次性建实例并常驻」——40962 格 × 每格若干件 = 数十万实例，
> 显存/CPU 顶不住，资产一多必卡死。必须遵守下面三条，且**用探针断言锁死**（验收 A 的第 4 条）：
>
> 1. **只铺视距内 patch，不铺全图**：量产物随 `M._surf` 地表 patch 同生共死（人走到哪，脚下那 ~46 米才铺）；
>    实例数**只跟视距 patch 大小挂钩，不随星球总格数涨**。
> 2. **InstancedMesh 批量绘制，不逐棵建 Mesh**：每类资产一个 InstancedMesh（draw call 与实例数无关），
>    逐棵 Mesh 是 draw call 爆炸（同屏上千棵必卡）。
> 3. **按区域分桶 + frustumCulled 按需**：若未来单 patch 内实例量再涨，按「格 → 桶」切 InstancedMesh 子桶，
>    桶级 `frustumCulled`/`visible` 按需开关；当前 `_surfScatter` 已是「5 个 InstancedMesh + 按格播种」的成熟范式，量产复用同一模式。
>
> 这套约束与「星球球壳（`buildGlobe`/`buildTiles`）只在进地图画一次」是同一思路：
> **规范几何可以常驻，海量散布资产必须按需**。

- **行业标准**：程序化散布（procedural scattering）+ 确定性随机（deterministic rng）+ 视距剔除（LOD/culling）+ InstancedMesh 批量绘制。
- **仓库出口（全部复用，不新建）**：
  - 几何真值：`scene3d.js` 的 `gTree/gRock/gReed/gWheat/...` + `rng(seed)`；
  - 地形采样：`GAME.map.heightAt` / `GAME.sphere.cells[ci].e`（高程）+ `cells[ci].type`（地形类型：plain/caoyuan/forest/desert/zhaoze/hill/ocean/lake）；
  - 网格定位：`M.gridCellDir(i,j)` / `M.gridAt(p)`（球面方格坐标，与 placement 同一套）；
  - 地表 patch：跟随玩家视距内重建（`M._surf` 地表模式）。
- **否掉**：

| 路径 | 否掉理由 |
|---|---|
| 给每棵树建独立 Mesh | 同屏上千棵，draw call 爆炸 → 必须 InstancedMesh |
| 全星球一次性铺满 | 40962 格 × 每格若干件 = 数十万实例，显存/CPU 顶不住 → 只铺**视距内 patch** |
| 把量产物写进存档 | 纯派生、由 seed+地形确定，读档原地重建；写入 = 派生回潮（存档梳理明令禁止） |
| 新建第二套几何函数 | scene3d 已有 17 个，重复定义 = 双源真值打架 |

## 3. 代价（文件 / 回退 / 最坏）

- **文件**：
  - `js/scatter.js`（新，core 包）：唯一量产出口 `GAME.scatter`——按 patch 铺视距内植被/地貌，确定性 seed，InstancedMesh 批量绘制；
  - `js/scene3d.js`：把 `gTree/gRock/...` 暴露为可量产调用（或经 `S._geos` 统一出口，不复制函数体）；
  - `js/map3d.js`：地表 patch 重建钩子接 `scatter`（`M.SCATTER=true` 总开关）；
  - `js/modules.json`（加 `scatter` 模块 → 重跑 gen_index）、`smoke-test.js` +4 条；
  - `docs/项目地图.md` 模块数 93→94。
- **回退**：`M.SCATTER=false`，地表照常（回到只有探索点装饰的 v158.6）。
- **最坏**：量产拖慢地表帧率 → InstancedMesh + 视距剔除 + 只铺当前 patch；再不行按地形类型降密度。

## 4. 验收（可量化、可迭代、可验证）

- **A（硬指标，探针实测）**：
  - 地表模式视距内**可观测植被实例 ≥N**（N=200 起步，随 patch 大小标定），且**非 0 平凡解**（采样顶点色/位置确实有树，不只是数组长度）；
  - 同 seed 两次进入同一 patch，铺法**逐位一致**（确定性 rng，验证「记住路」）；
  - 地表 patch 重建 p95 ≤16.7ms（60fps 红线），量产加入后不破；
  - 视距外（远离玩家的 patch）**不铺**（culling 生效，实例数不随星球总格数涨）；
  - **实例数上界独立于星球格数**（40962 格星球与 10 万格星球，同一视距内量产实例数接近 —— 直接锁死「全图加载」这一反模式，是老板点名的核心约束）。
- **B（反向证据，smoke 断言）**：
  - 量产物**不入档**（`savePayload` 无 `scatter`/`scatterPos`）；
  - 几何真值只有 scene3d 一份（`scatter.js` 不重复定义 tree/rock，只引用）；
  - `indexedDB.open` 仍只在 saveidb、E 键分派仍是 P3→P4→P1（P5 前两片不回归）。
- **C（主观，老板实机判定）**：走出城转一圈，确认「世界是满的、不是空壳」，且不挡路、不卡顿。

## 5. 需老板拍板（就一条）

量产**默认地貌范围**——是只铺「纯装饰植被/岩石/芦苇」（零玩法、纯观感，最安全），
还是连带铺「可采集的树/矿」（会与探索点采集系统、placement 玩家放置产生交互，范围更大）。
默认建议先做**纯装饰**一片，观感达标后再决定要不要加采集语义。

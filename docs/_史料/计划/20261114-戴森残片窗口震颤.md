# 2026-11-14 · 戴森球残片奇观转到网页边缘时「窗口震颤」整改计划

> 老板逐字原文：「那个奇观是那个呃戴森球残片的时候。就经常因为戴森纠缠片这个超出窗口之外，
> 所以这个嗯窗口界面就会有一个大小的一个调整，造成震颤。嗯解决一下这个问题，因为我之前讲过
> 我们的这个窗口视窗，人的视窗。大小不应该随意的变动，就它内容可以在这个呃它虚拟的那个空间里头，
> 它内容可以有有有有有这个超出。」
>
> 界面指认（AskUserQuestion 回填）：「网页界面，当奇观转动到网页边缘时」—— 即星球 3D 大地图网页界面，
> 且仅在奇观（如戴森球残片）转到网页边缘时出现震颤。

## 一、目标

星球 3D 大地图的**视窗尺寸恒定**，不随奇观转动而出现任何 resize / 滚动条跳动；
**内容（3D 奇观模型 / 雷霆箭头 #wonder-arrow）可超出虚拟空间（被裁）**，但绝不反向改变视窗尺寸。
这正是老板此前定下的视窗铁律：「人的视窗大小不随意变动，内容可在虚拟空间里超出」。

**不做会怎样**：奇观转到屏幕边缘时，雷霆箭头被 `syncWonderArrow` 夹到距边 `pad=40` 处，
但其 `transform: scale(2.4)` 向界外溢出约 37px；该溢出漏进外层 `.view-box`（overflow:auto）→
触发滚动条（吃 ~15px）→ `.map-wrap`(100%) 随之缩小 → `renderMapCanvas` 每帧按
`.map-wrap.clientWidth` 重定 `#mapCanvas` 尺寸 → 画布每帧重算、箭头位置重算、溢出仍在 →
滚动条常驻；奇观转回中央时溢出消失、滚动条消失、画布跳回 —— 奇观扫过边缘时画布尺寸随滚动条
出现/消失跳变 = 用户感知的「网页界面大小调整 / 震颤」。

## 二、路径（根因链 + 唯一修复点 + 被否路径）

**根因链（已完整取证，非推断）**：

1. 固定画布模型健全：`fitAppSize()` / `#app-scale` 只算等比缩放比，画布恒为 1440×900，
   `--app-w/h` 不再被 JS 改；3D 渲染器容器 `scene-layer`（scene3d.js / bundle-ui.js:9786）
   自带 `overflow:hidden`，不反撑视窗。→ 排除「整体缩放引擎导致 resize」。
2. 星球大地图画布尺寸来自锁高网格链：`.main`(grid 1fr) → `.central`(flex 列 min-height:0)
   → `#view-container`(.view-box, `overflow-y/x:auto; scrollbar-gutter:stable`)
   → `.map-wrap`(100%/100%) → `#mapCanvas`；`renderMapCanvas`(bundle-ui.js:27479) 每帧读
   `.map-wrap.clientWidth/Height` 定画布。→ 唯一可变尺寸源是 `#view-container` 的滚动条。
3. `.map-wrap`（`index.html:2076`）**缺 `overflow` 声明（默认 visible）** → 内部
   `#wonder-arrow`(position:absolute, scale(2.4)) 与 3D 模型溢出 → 漏进 `#view-container`
   → 触发滚动条 → 反馈震荡。

**唯一修复点**：给 `.map-wrap` 加 `overflow:hidden` —— 把溢出**裁在地图框内**，
绝不漏进外层 `.view-box`，切断「溢出→滚动条→画布跳变」整条反馈链。
符合老板铁律「内容可超出虚拟空间（被裁），视窗大小不随意变动」。

| 被否掉的路径 | 为什么否 |
|---|---|
| 改 `syncWonderArrow` 不出屏 / 不缩放 | 那是「让箭头永远在安全区」—— 改动指路标记的视觉语义（老板要的是「指针指向奇观」，缩放是为了醒目），且没治本（3D 模型溢出仍会漏） |
| 给 `#view-container` 去 `overflow:auto` | `#view-container` 是全局滚动容器，去它会影响所有视图的纵向滚动；而且根因溢出在 `.map-wrap`，应在离溢出最近的容器裁，而不是动全局容器 |
| 给 `#wonder-arrow` 加 `overflow:hidden` 父壳 | 治标：只挡箭头，3D 奇观模型（planetRing 外径 2.5R、wonderStep 太空轨行 R×1.6）的溢出仍会漏；且多套一层壳增加布局不确定性 |
| 在 `renderMapCanvas` 里「忽略滚动条尺寸」 | 滚动条已经吃掉像素、`.map-wrap.clientWidth` 已是缩小后的值，忽略它只是让画布跟缩得更慢，震颤仍在；必须从源头（溢出）切断 |

**定稿**：只加一行 `overflow:hidden` 到 `.map-wrap`，附 v157.55 注释说明因果链与老板铁律。
**不新建机制、不动 3D 渲染器、不动箭头定位逻辑、不动缩放引擎。**

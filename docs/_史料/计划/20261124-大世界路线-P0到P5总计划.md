## 0. 总纲（先定终点，再定台阶）

### 0.1 终点的可交付定义（不吹牛版）

「GTA6 式大世界」在本项目里**不**等于写实画质，而等于下面四条同时成立：

| # | 终点能力 | 当前状态 |
|---|---|---|
| 1 | 玩家有一个**连续位姿**的化身，在星球地表自由行走，不是"点格瞬移" | ❌ 只有 `_standCi` 格锚 + 面板传送 |
| 2 | 世界里的东西**走到跟前能用**（采集/开门/对话/上载具），不是只能点面板列表 | ❌ 地标可见可点，但没有"走近按 E" |
| 3 | 从星球格能**无加载地进入城市街区**，街道与建筑是同一世界的一部分 | ❌ 城市是格上的建筑模型，没有街区层 |
| 4 | 世界在玩家背后继续运转（NPC 日程、载具、事件），存读档能恢复 | ❌ 只有回合推进 |

双尺度架构（上一轮已定，本计划沿用）：

```
L0 星球层  ✅ 已有：半径 300 球体 / 40962 格 / 高程图 / 地表 patch / 轨迹球相机
              ↕  同一坐标系（球面 dir + 局部切平面），不切场景、不读盘
L1 街区层  ❌ 缺：城市格展开为街道 + 建筑入口 + 室内外
```

三个已定决策（本计划不再讨论，除非老板改口）：
1. 继续用 three.js 走**风格化**，不换引擎、不追写实；
2. 资产以**程序化生成**为主，GLB 只作可选补充；
3. 存档从 localStorage 迁到 **IndexedDB 分块** —— **需老板授权**（见 §6）。

### 0.2 不做会怎样

现在"走过去"的左键平移只是**移动相机**，玩家没有身体。于是：
- 地形是背景，不是可经历的地形 —— 绕山 30 秒不会遇到任何事；
- P1 已做的实物地标只能"点开面板"，永远进不了"走近—交互—获得"的循环；
- 再往上叠 NPC、载具、任务，全是面板系统，**世界仍然没有形状**。

## 2. 全局骨架（先建骨架，再填空 —— AGENTS.md §十二）

### 2.1 一个状态量

```js
state._avatar = {
  dir: [x,y,z],   // 单位球面方向，L0 上的位置（世界点 = dir * (R + h)）
  h:   0,         // 脚下地形高（世界单位），派生但缓存以保证读档稳定
  yaw: 0,         // 切平面朝向（弧度）
  v:   [0,0,0]    // 切平面速度，读档时清零（不存瞬时动量）
};
```

`_standCi` **保留不动**：它是面板/传送/城市归属用的"格锚"，由 `_avatar.dir` 反算同步，
两者只有一个写入口。旧档没有 `_avatar` → 迁移函数按 `_standCi` 补一份，幂等。

### 2.2 一个唯一出口

| 职责 | 唯一出口 | 禁止 |
|---|---|---|
| 读玩家位姿 | `M.playerPose()`（返回深拷贝） | 直接读 `state._avatar` 改写 |
| 写玩家位姿 | `M.setPlayerPose(pose, opts)` | 任何 `state._avatar.xxx =` 散落赋值 |
| 地形高度采样 | `M._groundAtUnit(dirOrCi)` → 只调 `GAME.map.heightAt` | 在相机/角色里另算一套 |
| 相机跟随更新 | `M.followAvatar(dt)`，在 `placeCamera()` 之后、`_tickSurfFade()` 之前 | 在渲染循环里直接写 `camera.position` |

### 2.3 一组不变量（每条都必须有自动断言）

1. `|footY - groundY| ≤ 0.15`（脚底贴地，跳跃态除外）；
2. 胶囊底不低于地形 `−0.05`（不穿模），胶囊底不高于地形 `+0.15`（不飞天）；
3. 跟随态相机距离/俯角在 §P0 阈值内；相机到角色连线的采样点不在地形以下；
4. `_standCi` 与 `_avatar.dir` 指向同一格（格锚同步）；
5. 存档 → 读档后 `dir/h/yaw` 误差 ≤ 1e-4，`v` 归零；
6. 关闭开关 `M.PLAYER_AVATAR=false` 时，旧行为（点格传送 + 轨道相机）逐字节等价恢复。

## 3. 各阶段四段计划

### ── P0 · 角色与跟随相机（4 片）──

#### 1) 目标
- **玩家感知**：按 WASD 有一个"人"在星球地表走，脚下贴着地形，陡坡会滑下来；相机在他身后 6 米、俯角 15°，平滑跟随且不穿地。
- **不做**：所有上层玩法仍停留在"点面板"，世界没有身体，GTA 路线的其余五阶段全部悬空。

#### 2) 路径
- **行业标准（已查证）**：
  - Unity `CharacterController`：胶囊体 + `Slope Limit` + `Step Offset`（2 米人形取 0.1~0.4）+ `Skin Width ≥ 10% radius` + `Min Move Distance = 0`；
  - Unity Cinemachine `Third Person Follow`：Origin → Shoulder → Hand → Camera 的 rig，`Damping` = 追上目标的时间常数，自带 camera collision 防穿模。
- **仓库既有出口**：
  - 地形高度唯一出口 `GAME.map.heightAt(gx,gy)`（`js/map.js:1216`），0~2.7，×`HSC=26`；
  - 球面点/格互转：`mapSphere.cells[ci].dir` + `GAME.map.lonlatOf`（`js/sphere.js`）；
  - 相机唯一出口 `placeCamera()`（`js/map3d.js:6229`），地表/轨道已由 `_agl` 派生；
  - 玩家格锚 `state._standCi` + `M.teleportTo()`（`js/map3d.js:8178`）；
  - 存档唯一出口 `GAME.savePayload()`，新字段天然入档。
- **被否掉的路径**：

| 路径 | 为什么否 |
|---|---|
| 引入 cannon/rapier 物理引擎 | 运行期零依赖是硬约束；且球面重力方向逐点变化，现成引擎反而要包一层 |
| 直接给 `_collider`（R+0.6 光滑球）做走碰撞 | 那是拾取用的光学球，比真实地表高，站上去会浮空（v157.96 踩过） |
| 沿用旧 `surfaceWalk()` 沿弧插值 | 那是"点格瞬移的动画"，不是连续输入；一格 220ms 没有速度概念 |
| 相机继续用 `camO.dist` 写半径 | 跟随态的位置应由角色推导；再写 dist 会与 `_zoomTarget` 打架（v157.31/32 三补丁的病根） |
| 用 `lookPitch` 当第三人称俯角 | `lookPitch` 是"相对球心的视线偏移"，语义不同；混用会让过极点旧 bug 复发 |
| 把角色贴到 `SURF_GRID_RANGE` patch 的平面 | patch 会随相机移动重建，角色会跟着抖；必须走球面 dir + 高度场 |

#### 3) 代价
- **文件**：`js/map3d.js`（位姿/碰撞/跟随/拾取开关）、`js/state.js`（迁移 + 剔除 `v`）、`js/main.js`（WASD 输入分派）、`smoke-test.js`（§589v~§589ac）、`.workbuddy/tools/probe/pose_probe.js`（新探针）；
- **断言**：新增 8 条（§589v 位姿唯一出口 / §589w 贴地 / §589x 坡度 / §589y 相机 rig / §589z 格锚同步 / §589aa 存档回读 / §589ab 反向证据 / §589ac 开关回退）；改 §589n（传送必须同步 `_avatar`）；
- **验证次数**：4 片 × (域 camera 25s + light 25s) + 阶段末 full 11min + e2e 42s；
- **最坏结果**：球面切平面在极点附近退化（dir 与 up 共线）导致朝向跳变 → 用四元数 + 局部 up 完备基，不用欧拉角；
- **回退点**：改前整文件备份到 `.workbuddy/backup/20261124-P0/`；开关 `M.PLAYER_AVATAR = false` 一键回到旧行为；书包 `js/bundle-*.js` 重建前不提交。

#### 4) 验收（A/B/C）

**A 硬指标**

| 指标 | 测法 | 阈值 | 阈值来源 |
|---|---|---|---|
| 脚底贴地误差 | 探针绕山 30s，逐帧 \|footY−groundY\| 的 p95 | ≤ 0.15 单位 | skin width 0.03 + 采样精度；1.7m 眼高的 9% 肉眼可见 |
| 穿模帧数 | 同段胶囊底 < 地形−0.05 的帧数 | **0** | 硬失败，无容忍 |
| 飞天帧数 | 非跳跃态相邻帧 \|Δy\| > 1.0 的帧数 | **0** | 一帧跨半格即瞬移感 |
| 坡度双向 | 30° 坡可上行；45° 坡 3s 内下滑 ≥1 格 | 两条同时成立 | 老板原话 >40° 滑落；40° 附近留 5° 滞回防抖 |
| 相机距离 | 稳定后 \|cam−player\| | 6.0 ± 0.3 单位 | 上一轮定的 6m；±5% 为阻尼收敛误差 |
| 相机俯角 | 视线与切平面夹角 | 15° ± 2° | 上一轮定的 15°；±2° 容忍地形起伏 |
| 相机抖动 | 屏幕位移二阶差分 p95 | ≤ 0.8 px/帧² | 60Hz 下 >1px 加速度人眼可察（人体极限） |
| 更新耗时 | 1000 帧 `followAvatar` p95 | ≤ 2 ms | 16.7ms 帧预算的 12%，其余留给渲染 |
| 存档回读 | 存→读→位姿三点误差 | ≤ 1e-4 | 单精度浮点往返精度 |

**B 结构指标**：`M.playerPose/setPlayerPose/_groundAtUnit/followAvatar` 各 `grep` 计数 = 1；
反向证据：跟随分支内 `camO.dist =` 计数 = 0、`lookPitch` 计数 = 0；`state._avatar.v` 不入档（`savePayload` 输出中 0 次）。

**C 主观**：老板实机 WASD 绕一座山 30 秒 → 一句"可以"；或出对比录屏。**AI 不结案。**

**切片顺序**：P0-a 位姿与存档 → P0-b 贴地碰撞与坡度 → P0-c 跟随相机（含防穿地） → P0-d 输入接线 + 开关回退 + 全量门禁。

### ── P1 · 走近即交互（3 片）──

#### 1) 目标
- **玩家感知**：走到遗迹/资源/传送点前出现提示，按 E 触发**原来那个面板**或获得物，不需要打开地图点格子。
- **不做**：P1 历史成果（地标可见可点）止步于"点开看"，世界仍然只能被点击、不能被使用。

#### 2) 路径
- **行业标准**：Unity `OnTriggerEnter` + 近距离提示 + 单一 `Interact()` 分派；准星/距离双条件，避免误触。
- **仓库出口**：`M.pickAt` 已有 `figRoot/plRoot` 优先级与 `userData.ci` 反查；`_cellBrief` / `_openCellPanel(ci)` 已存在；背包增删走既有 items 出口。
- **否掉**：

| 路径 | 否掉理由 |
|---|---|
| 进入半径自动触发 | 老板 v157.96 口径：世界不能被"路过就踩雷"；必须显式按键 |
| 复用 `pickAt` 的鼠标射线做交互 | 键鼠语义不同；相机在身后时屏幕中心射线不一定指向角色前方 |
| 新增独立交互面板 | 违反"打开原来那个面板"；只加提示与按键 |

#### 3) 代价
- **文件**：`js/map3d.js`（最近可交互物查询 `M.nearestInteractable()`）、`js/ui-mapui.js`（提示条）、`js/main.js`（E 键分派）、`smoke-test.js` +3 条；
- **验证**：3 片 × 域 camera/ui + 阶段末 full；**回退**：`M.INTERACT_NEAR=false`；备份同 P0 目录；
- **最坏**：可交互物密集导致每帧 O(n) 查询 → 按格哈希，只查当前格 + 8 邻格。

#### 4) 验收
- A：交互目标必须是**角色前方 ≤1 格**且视线夹角 ≤30°；按键到面板打开 ≤100ms；采集后背包增量恰好 1；误触（背对/超距）0 次；
- B：交互分派函数唯一；旧"点面板"路径仍可用（反向证据：删除按键后功能不消失）；
- C：老板走到遗迹前按 E，确认"这就是我想要的手感"。

### ── P2 · 城市街区 L1（4 片）──

#### 1) 目标
- **玩家感知**：站在城格上按"进入"，镜头推近变成可走的街道，能走到建筑门口；按退出回到星球视角，位置不变。
- **不做**：城市永远是球体上的一坨模型，"进城"只是面板切换 —— 大世界缺一半尺度。

#### 2) 路径
- **行业标准**：Open World 的"无缝 LOD 过渡"：同一坐标系内缩放 + 细节层渐显，不切场景、不读盘；Cinemachine 式 damping 做镜头推拉。
- **仓库出口**：`js/placement.js` 的 `seatProp`（已有贴地落座）；`js/cities.js` 城市数据；`GAME.map.heightAt` 地形；地表 patch 的 `gridAt(i,j)` 局部坐标。
- **否掉**：

| 路径 | 否掉理由 |
|---|---|
| 新建独立 three.js Scene 做城内 | 切场景 = 读盘感，且位姿同步会变成两套 |
| 把 40962 格全部细化到街区 | 数据量爆炸；只展开玩家所在城格 |
| 复用旧 2D 城市场景贴图 | 与球面坐标系不通，会回到"面板世界" |

#### 3) 代价
- **文件**：新增 `js/district.js`（街区生成 + 进出状态机）、`js/map3d.js`（过渡钩子）、`js/modules.json`（加模块 → 重跑 `gen_index.js`）、`js/ui-city.js`（入口按钮）、`smoke-test.js` +4 条；
- **验证**：4 片 × camera/ui + full；**回退**：`M.DISTRICT=false`，街区层不建，旧城格显示原样；
- **最坏**：街区与球格接缝出现"穿帮地面" → 过渡期间保留球格渲染 200ms 交叠，渐隐而非硬切。

#### 4) 验收
- A：进出城 **0 读盘**（无 `loadGame` 调用）；过渡 ≤300ms；街区帧 p95 ≤16.7ms；退出后 `_avatar.dir` 与进入前误差 ≤1e-4；同一城重复进出 20 次无内存增长（heap 漂移 ≤2MB）；
- B：街区状态机唯一（enter/exit 各 1 处写）；反向证据：`district.js` 不直接写 `state._avatar`；
- C：老板从星球走进城再走出来，确认"没有切换感"。

### ── P3 · 载具与碰撞（3 片）──

#### 1) 目标
- **玩家感知**：在马厩/车旁按 E 上车，WASD 驱动，撞建筑会停住而不是穿过去，按 E 下车回到原格附近。
- **不做**：大世界只有步行，尺度感出不来；星球格之间的长距离移动仍是"点城传送"。

#### 2) 路径
- **行业标准**：kinematic 移动（不走刚体力）+ capsule sweep 碰撞；上下车用同一个交互出口。
- **仓库出口**：P0 的碰撞采样 + P1 的 `nearestInteractable` 直接复用；载具作为 `userData.ci` 挂到现有 `plRoot`。
- **否掉**：物理引擎（同 P0 否因）；载具独立碰撞层（会和玩家碰撞分叉，两套口径）。

#### 3) 代价
- **文件**：`js/vehicle.js`（新）、`js/map3d.js`（挂载 + 碰撞）、`js/main.js`（输入）、`smoke-test.js` +3 条；
- **回退**：`M.VEHICLE=false`；
- **最坏**：高速跨格时逐帧采样漏碰 → 固定步长子步进（≤0.5 格/步），不做连续检测。

#### 4) 验收
- A：上下车 ≤2 次按键；载具碰撞穿透 0；刹车距离 ≤0.5s×速度；子步进上限 0.5 格；连续 30s 行驶帧 p95 ≤16.7ms；
- B：载具速度/碰撞都调 P0 的 `_groundAtUnit`，不新增高度计算；
- C：老板绕城一圈，确认"撞得住、停得稳"。

### ── P4 · NPC 生态与事件（4 片）──

#### 1) 目标
- **玩家感知**：路上有 NPC 走动，早出晚归，走近能对话，敌对会开打；世界不再只有玩家一个活物。
- **不做**：GTA 式"世界在背后运转"永远缺位，城市是空壳。

# 自然件 GLB 接入地表散点 · 改造清单

> 目标：把当前地表景物（锥形树 / 二十面体石）换成更好的低模 GLB。
> 背景：老板贴图吐槽「3D资产没有好一点的了吗」→ 确认有（Kenney/Quaternius，CC0），
>       当前只落地了 Phase 0.5（材质/光照），几何造型仍是最早手搓件。
> 关联：`docs/3D资产质感升级路线方案.md` 第 8 节决策（先动 Phase 0/1，城堡留 Phase 2）。

## 1. 现状定位（要改的地方）

| 对象 | 当前实现 | 位置 |
|---|---|---|
| 植被几何生成 | `_scatterDefs()` 内 5 个程序几何 | `js/bundle-ui.js:1684-1753` |
| 树冠（截图里的锥树） | `ConeGeometry(0.95, crownH, 7, 1)` | `js/bundle-ui.js:1707` |
| 树干 | `CylinderGeometry(0.10,0.16,trunkH,5)` | `js/bundle-ui.js:1704` |
| 岩石（截图灰块） | `IcosahedronGeometry(0.34, 0)` | `js/bundle-ui.js:1730` |
| 草 / 芦苇 | 交叉片 / Cylinder（观感 OK，可不换） | `js/bundle-ui.js:1714 / 1727` |
| 实例散点 | `InstancedMesh(D.geos[key], mat, n)` 每种一个 | `js/bundle-ui.js:1826` |
| 顶点色着色 | `paint(g, cBot, cTop)` 按高度渐变（unlit 明暗手段） | `js/bundle-ui.js:1688` |
| GLB 解析器 | `GAME.gltf.parse(ab)` → `{parts:[{position,nor,uv,count}], textures, doubleSided}`，**只吃 GLB**（校验 magic 0x46546C67） | `js/bundle-war.js:49` |
| 动画 GLB 加载 | `GAME.gltf.loadAnimated(name, cb)`（base64 注入 `.glb.js`） | `js/bundle-war.js:634` |
| 角色尺寸标定 | `GTF.FIT`（native→世界单位） | `js/bundle-war.js:670` |

**关键事实**：散点材质是 `MeshBasicMaterial({vertexColors:true})`（unlit）。所以：
- v157.61 的 env 反射 **不影响** 这些景物（env 只对受光材质生效）。
- v157.58 的 PBR 解析抽出的 metalness/roughness **也没用上**（材质不是 Standard）。
- 换几何是主收益；材质体系维持 unlit 即可与地砖亮度对齐（代码注释明确警告过"受光会跟地砖打架、太阳强度 3.2 把草照成荧光绿"）。

## 3. 预加载机制（复用既有 base64 注入）

仿 `GAME.gltf.loadAnimated` 的模式，新增**静态**加载入口（不引 GLTFLoader，维持零外链 UMD）：

```
// bundle-war.js 内，紧邻 GTF.loadAnimated
GTF.loadStatic = function (name, cb) {
  // 1) window.__NATURE_GLB[name]（assets/nature/<name>.glb.js 注入的 base64）
  // 2) 否则注入 <script src="assets/nature/<name>.glb.js">
  // 3) GTF.parse(arrayBuffer) → {parts}
  // 4) 回调 {parts, meta}
};
```

- 资源落位：`assets/nature/tree_01.glb` / `rock_01.glb` …（由 fetch 脚本从 Kenney 收口）。
- 启动期预载：地表模块初始化时 `loadStatic` 若干树/石，存到 `GAME.natureGLB = {tree:[...], rock:[...]}`。
- **兜底**：若 `GAME.natureGLB` 为空（没资产/加载失败），`_scatterDefs` 退回当前 Cone/Icosahedron —— 零回归。

## 4. 几何提取 + FIT 标定

从 `parts` 构 `THREE.BufferGeometry`（部件库已有此能力，wonders 渲染即如此）：

```
function partsToGeo(parts) {
  // 取第一个三角形 primitive 的 position/nor/uv → BufferGeometry
  // 多 primitive（如树=树干+树冠两 mesh）→ 拆成两个 geo，分别喂 trunk / crown
}
```

- **FIT 标定**：当前 `crown` 高约 `trunkH(1.0)+crownH(2.4)=3.4` 单位（再乘散点随机缩放 0.78~1.33）。
  新 GLB 需缩到相近世界高度。参照 `GTF.FIT` 做法：在 `GTF.FIT` 或新增 `GTF.NATURE_FIT`
  登记 `{tree:{scale}, rock:{scale}}`（用像素渲染法或手动量原生高度后算 `target/ nativeH`）。
- 朝向：GLB 多为 Y-up；`GTF.parse` 已复合 node TRS（含 Z-up→Y-up 四元数），几何取出即正确朝向。

## 5. 散点接入（`_scatterDefs` 改造，保留兜底）

```js
function _scatterDefs() {
  if (_SCATTER_DEF) return _SCATTER_DEF;
  // —— 原有程序几何（兜底）——
  var trunk = new THREE.CylinderGeometry(...), crown = new THREE.ConeGeometry(...),
      grass = ..., reed = ..., rock = new THREE.IcosahedronGeometry(...);
  paint(trunk,...); paint(crown,...); paint(grass,...); paint(reed,...); paint(rock,...);

  // —— 新：GLB 覆盖（有则替换）——
  var N = GAME.natureGLB || {};
  if (N.trunk && N.crown) { trunk = N.trunk; crown = N.crown; }   // 树的干/冠两 geo
  else if (N.tree)        { trunk = N.tree[0]; crown = N.tree[1] || N.tree[0]; }
  if (N.rock) rock = N.rock;

  _SCATTER_DEF = { geos: { trunk, crown, grass, reed, rock }, plan: {...}, trunkH };
  return _SCATTER_DEF;
}
```

- `_surfScatter`（bundle-ui.js:1755）**无需改**：它只认 `D.geos[key]` 与 `bags` 配对逻辑。
  `trunk`→`crown` 同矩阵配对已写好（1755 内 `if (kind==='trunk') bags.crown.push(mt.clone())`），
  所以 GLB 树只要提供 trunk/crown 两个 geo，就能复用现有"干配冠"逻辑。
- `grass` / `reed` 维持原程序几何（观感已可，且与风力图/GPU 顶点动画耦合，勿动）。

## 6. 材质决策（待老板拍板）

| 方案 | 效果 | 风险 |
|---|---|---|
| **A. 维持 `MeshBasicMaterial+顶点色`**（用 GLB 自带顶点色；无则按类型平涂绿/灰） | 与地砖亮度体系一致，零风险 | 不吃 env 反射，质感提升仅来自几何 |
| B. 改用 `MeshStandardMaterial` + env 反射 | 树/石有金属/粗糙度层次，吃 v157.61 env | 与 unlit 地砖亮度打架（已有警告），需重新调 sun 强度/曝光 |

**建议先走 A**（几何升级已够明显），B 作为后续可选项等实机看效果再定。
> 注：若走 A，GLB 的 PBR 贴图（base/normal）被忽略，只用其几何 + 顶点色 —— 这正是 Kenney 平涂低模的强项。

## 7. 验收

1. **探针**：`node scripts/phase1_probe_glb.js assets/nature` → 统计 PBR 通道（确认 GLB 能被解析器识别）。

   - 树不再是绿锥，是真实树形；石不再是多面体，是圆润岩石。

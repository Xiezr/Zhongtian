# 20261110 · 相机统一模型（架构收敛）

> 按 `AGENTS.md` §十二 出的第一份计划。**计划未批，不动代码。**
> 背景：v157.31/32 两轮各打一处补丁，问题没收敛。按"补丁配额"第 2 次即触发架构收敛。

## 1. 目标

- **一句话**：相机只有一个玩家能改的量（到球心的距离），地形在任何时刻都不挪动这个窗口；
  地面与轨道的差别只是同一套模型的参数不同，切换点看不见接缝。
- **不做会怎样**：继续在 `半径 / agl / rAlt` 三个量之间补，每修一处必坏另一处 ——
  v157.31 修了"跟地形"，v157.32 又冒出"滑块死区"和"外滚被顶"，就是这条路的样子。

## 2. 路径

**行业标准（已查）**：
- three.js `OrbitControls`：状态只有 `target + radius + 球坐标`；地形从不参与位置，
  遇到遮挡用 `minDistance`/射线，不改半径语义。
- `MapControls`：同上，把"平移"放在切平面里而不是改半径。
- 模拟经营类（Cities: Skylines / Anno）：相机 = 焦点 + 距离 + 俯仰，地形只做**碰撞回退**
  （push-in），且回退是"临时位移"，松开即恢复 —— 不是每帧跟随。

**仓库既有出口**：
- `camO.dist`（半径，已有）→ 可作唯一状态量。
- `M.camFloorAt(dir)`（地形下限，v157.31 新增）→ 可作约束层的唯一出口。
- `lookDistAt(r)`（俯角曲线）→ 已有，但现在喂的是 `agl`（含地形）。
- `M._rAlt`（海拔）→ v157.31 新增，语义已稳定，适合当"派生量"。

**被否掉的路径**：

| 路径 | 为什么否 |
|---|---|
| A 相机跟地形走（v157.15~17 平滑+限速） | 老板否过两次：走过山坡会漂 |
| B 三个量各管一段（现状） | 就是不稳定的根因：模式读一个、俯角读另一个 |
| C 碰撞后把相机拉近（push-in） | 会动窗口，与"窗口不动"直接冲突；只能作为可选开关 |
| D 拆成两套相机（地面/轨道各一套） | 切换点必有接缝，等于把跳变制度化 |

**选定的路径**：单一状态量 `r = camO.dist`；派生量（模式 / 俯角 / 地表淡出）全部由 `r` 决定；
地形只进约束层，且**只在输入事件（滚轮/滑块）那一刻**使用一次。

### 顺带挖到的真根因（可能就是你说的"不稳/跳"）

`_surfRightOf` 每帧把"契约右向量"投影回 ⟂ 视线再归一化 —— 这本身是**浮点噪声的累积器**。
贴地静止 3.6 秒，相机朝向自己慢慢转了 **0.0686°**（肉眼在小屏幕上就是"画面在飘"）。
修法：|dot| < 1e-4 时**原样返回，不做任何数值操作**；只有明显不垂直时才校正一次。
修后同一测量 **0.0000°**。

- `§243①` 保持"缩放上下限可查"，`§243①c/⑭` 维持 v157.31/32 口径。

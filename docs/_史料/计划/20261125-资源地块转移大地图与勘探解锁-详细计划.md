## 2. 核心设计（四层玩法，逐层可独立交付）

### 2.1 资源地块 = 地形 × 丰度 × 储量（新概念）

**资源地块定义**：星球上「可建采集场」的地块，由三个量决定：

| 量 | 含义 | 来源 |
|---|---|---|
| **类型** | 产什么资源 | `DATA.TERRAIN[type].add` 的键（forest→生物质、desert→电能、hill→废钢、lake/plain/caoyuan→净水） |
| **丰度** | 单块地产出倍率 | 随机（确定性 seed，按格号），如 0.5×~2.0× |
| **储量** | 可采集总量上限 | 丰度 × 相连同类型地块数 × 基础储量系数 |

**储量公式（初版，待老板调）**：
```
储量 = 基础储量 × 丰度 × (1 + 相连同类型地块数 × 0.5)
```
- 相连同类型地块数（`SP.adj[ci]` 里 type 相同的邻居数）决定「矿脉规模」——连片大矿更值钱。
- 采完（储量归零）→ 采集场停产，需拆场迁到新矿，或开采率降为 0 并提示枯竭。

### 2.2 四层玩法（对应老板「核心玩法（资源）的不同层级」）

| 层 | 玩法 | 现状→目标 | 出口 |
|---|---|---|---|
| **L1 勘探** | 近地面走近资源地块，探测其类型/丰度/储量，登记图鉴 | 现状：地形色块看不出资源；目标：近地面有可交互资源地块，探测后解锁 | 新增 `GAME.scanResource(ci)` |
| **L2 占矿** | 探测到的高丰度矿需占领/驱逐野地守军后才能建厂 | 现状：野地占领已存在（`s.wilds`）；目标：资源地块挂到野地，占领解锁建厂资格 | 复用 `wildDefenseAt`/`occupy` |
| **L3 建厂** | 在地块上建对应采集场（复用净化厂/水培温室/发电站/电弧熔炉四建筑） | 现状：建筑在 extGrid；目标：建筑实体落在大地图地块 | 转移 `EXT_BUILDINGS` 到地块 |
| **L4 生产+枯竭** | 采集场持续产出→入城账本；储量耗尽→停产→迁徙 | 现状：产出入 `prodBasePerHourOf`；目标：产量×丰度、扣储量、枯竭停产 | 改造产量链 + 新增储量扣减 |

### 2.3 地形占比调整（老板「增大平地地形占比」）

- 现状 plain 占比 = 满足 `alt2<0.42 && sl<0.58 && wet<0.74` 的陆地格比例。
- 调大手段：放宽 plain 判定阈值（如 `alt2<0.50` 或 `wet<0.78`），**只改 buildTerrainTypes 内联判定这一处**（注释明示「改比例只改 ⑤ 的数」）。
- 目标：让「可建城的平地」占比提升，同时保持 hill/forest/desert 作为资源矿脉的多样性。
- **风险**：占比调大后需重跑地形生成 + 门禁，确认连续性平滑（邻域投票）不产生孤岛。

### 2.4 战略/近地面匹配（老板「资源地块与近地面匹配」）

- **战略模式**（轨道）：资源地块显示**资源图标 + 丰度色阶**（高丰度更亮），点开地块情报面板显示「类型/丰度/储量/可建厂否」。
- **近地面模式**（地表）：资源地块有**可交互标记**（探测前「？」、探测后资源图标），走近按 E 探测；已建厂地块显示采集场建筑模型。
- 两模式读**同一份资源地块数据**（`GAME.resourceAt(ci)` 唯一出口），保证一致。

### 2.5 老档迁移（老板拍板：清零 + 返还资源）

- **口径**：现有 `city.extGrid` 里所有已建城外资源建筑（farm/forest/quarry/mine），迁移时**全部清零**，并按**已投入成本返还资源**到对应城账本。
- **返还额**：每块已建地块按「该建筑当前等级」返还其累计造价（`DATA.EXT_BUILDINGS[eid].cost` 累加），走唯一收支出口 `GAME.payCostIn(city, -refund)`（负向=返还，与扣除同源，参考既有「撤兵返还」范式 domain.js:2007）。
- **幂等**：迁移打标记 `state.resMigrated=true`，老档只迁一次；迁完 `extGrid` 清空为 `{id,type:null,lv:0}`。
- **新档**：新城不再预置 `DATA.INITIAL_EXT/NEW_CITY_EXT`（或降为 0），采集场改走大地图建造。

### 2.6 软枯竭（老板拍板：降产不硬停，成熟设计）

- **口径**：储量归零后**不停产**，但产量降为**基础值的 25%**（象征性「贫矿残采」），并在地块情报面板标注「已枯竭 · 贫矿残采」。
- **依据**：策略游戏惯例——资源枯竭降产而非归零（保留玩家的既有布局，不强制拆场，但给出「迁徙更优」的经济信号）。
- **软上限**：`reserve ≤ 0` 时 `richness` 有效值按 0.25 折，产量公式里乘这个折减系数。
- **复苏空间**：后续可加「再生技术」科技把残采系数从 0.25 提到 0.5（本期不做，留接口）。

### 2.7 城外（大地图）建造流程（老板拍板：要设计）

**复用现有建造范式，不新造协议**：

| 环节 | 出口 | 说明 |
|---|---|---|
| 入口 | 近地面建造模式（`MODE_BUILD` + `M._surf`） | 玩家滚轮下到地表 → 切建造模式 |
| 目标 | 已勘探 + 已占领的资源地块 | 未勘探显示「?」不可建；未占领提示先占领 |
| 建造 | 新增 `GAME.buildPlant(ci, eid)` | 复用 `checkBuildSlot` + `canAffordIn` + `payCostIn` + `queueAdd('build',{type:'ext_build', ci})` |
| 完工 | `applyBuildDone` 扩展 `ext_build` 分支 | 写入 `state.resources[pid][ci].plant = eid` |
| 升级 | 新增 `GAME.upgradePlant(ci)` | 复用 `upgradeExt` 同构，写 `plantLv` |
| UI | 近地面点资源地块 → 弹 `openResourceModal(ci)` | 显示类型/丰度/储量/可建厂按钮，复用 `openExtModal` 样式 |
| 拆除 | 新增 `GAME.dismantlePlant(ci)` | 返还部分成本（复用撤兵返还口径） |

**流程闭环**（老板验收走查）：`滚轮近地面 → 切建造 → 走到已勘探矿 → 点地块 → 选建对应采集场 → 建造队列倒计时 → 完工 → 产量入账 → 储量递减 → 枯竭降产`。

## 3. 数据与出口设计（唯一出口纪律）

### 3.1 新增状态（入档，唯一写出口）

```js
// state.resources = { <pid>: { <ci>: { res, richness, reserve, scanned, plant, plantLv } } }
// res: 资源键（grain/wood/stone/iron）；richness: 丰度 0.5~2.0（确定性派生）；
// reserve: 剩余储量（入档，会递减）；scanned: 是否已勘探（入档）；
// plant: 采集场建筑 id（farm/forest/quarry/mine）或 null（入档）；plantLv: 采集场等级（入档）
```

- **确定性派生（不入档，可重建）**：`richness` 与 `reserveMax` 由 `seed(ci)` 派生（同格每次一致）。
- **入档（玩家进度）**：`reserve`（剩余储量）、`scanned`（勘探）、`plant`/`plantLv`（采集场）。
- **唯一写出口**：`GAME.setResource(ci, patch)`；读出口 `GAME.resourceAt(ci)`。禁止散落 `state.resources[...] =`。

**储量公式（AI 定稿，数值后期可调）**：
```
reserveMax = RICH_BASE × richness × (1 + 相连同类型地块数 × 0.5)
RICH_BASE = 24h × 单厂满产(7800/h) × 6 ≈ 112 万（约 6 个满产日）
richness = 0.5 + rng(seed(ci)) × 1.5   // 0.5 ~ 2.0
```
- 意义：单矿约够「满产 6 天」的产量（随丰度 3~12 天），连片大矿更持久。
- 枯竭后（`reserve ≤ 0`）产量折减系数 `DEPLETE_MULT = 0.25`（软枯竭，见 §2.6）。

### 3.2 采集场建筑转移

- **保留** `DATA.EXT_BUILDINGS` 四建筑（id/prod/cost 不变），但**位置载体**从 `city.extGrid` 迁到 `state.resources[pid][ci].plant`。
- **迁移**：老档的 `city.extGrid`（每城 12~96 块）→ 自动折算成「已建采集场的地块」或按老板定的降级策略（见 §5 拍板项 3）。
- **回退**：`GAME.RES_ON_MAP=false` 开关，回到城内 extGrid 模式。

### 3.3 产量链改造

- 现状：`prodBasePerHourOf` 遍历 `city.extGrid` 累加 `eb.prod[lv-1]`。
- 目标：遍历「本城势力范围内已建厂地块」，产量 = `eb.prod[plantLv-1] × richness × depleteMult`，且**每日扣储量**（`reserve -= 日产量换算`），储量归零后 `depleteMult=0.25`（软枯竭降产，不停产）。
- 丰度（richness）与储量（reserve）、枯竭折减（depleteMult）是新增的三个乘数/上限。
- **储量扣减唯一出口**：`GAME.consumeReserve(ci, amount)`，每日结算时按实际产量换算调用。

## 6. 验收总则（可量化、可验证）

- **A 硬指标**：同格丰度/储量确定性（seed 一致）；储量扣减与产量严格对应；枯竭后产量折减至 25%（非 0）；勘探→占矿→建厂→产出→软枯竭全链路可走通；地形 plain 占比实测上升且无孤岛；60fps 红线不破。
- **B 反向证据**：`state.resources` 唯一写出口（`grep` 计数=1）；资源地块两模式读同一出口；老档迁移幂等（返还只发生一次）；回退开关关闭后旧 extGrid 行为等价恢复。
- **C 主观**：老板实机「发现富矿→建厂→采到枯竭降产→迁新矿」走一圈，确认「这就是废土资源循环」。

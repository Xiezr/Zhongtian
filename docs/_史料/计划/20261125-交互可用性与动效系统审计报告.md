## 一、第二条指令：动效系统审计（缺口最大，是主战场）

### 1.1 现状取证

项目的设计系统（`:root` CSS 变量，`index.html` line 11~192）已经统一了**颜色 / 字号 / 圆角 / 间距 / 图标尺寸** 5 大类，共 200+ 个 token。**唯独「动效」没有进 token 体系**——这是核心缺口。

实测 `index.html` 全站动效「每处自己发明」的铁证：

| 维度 | 现状 | 违反 |
|---|---|---|
| **时长** | 20 种散落值：`.09s .1s .12s .13s .14s .15s .18s .2s .25s .3s .34s .35s .36s .4s .5s .55s .6s .9s 1s 1.1s 1.15s 1.3s 1.5s 1.6s 2.4s` | 「同一类变化用同一种节奏」 |
| **缓动** | `ease`（11）/ `ease-out`（11）/ `ease-in-out`（7）/ `linear`（90）/ `cubic-bezier(.4,.8,.4,1)`（3）/ `cubic-bezier(.16,1,.3,1)`（3）混用 | 「一套语言，不要每处发明」 |
| **同一类变化** | 「淡入」有 ≥5 种写法：`rp-fade(.34s)`、`mModalIn(.13s)`、`moIn(.25s~.35s)`、`floatGain(900ms)`、`fadeIn` | 「同一类变化用同一种曲线和节奏」 |

**但已有「半套」正确的东西**（`index.html` line 4430~4489，`v89.88` 那批）：
- ✅ 弹窗入场已统一：`.13s` 遮罩淡入 + `.15s` 面板上浮 `cubic-bezier(.16,1,.3,1)`
- ✅ 按压反馈已按族统一：条/页族 `translateY(1px)`、卡片族 `scale(.97)`、`transition .09s ease-out`
- ✅ `prefers-reduced-motion` 全局降级块已有（`*,*::before,*::after` 归零，line 4483），另有 3 处局部降级
- ✅ 焦点环 `:focus-visible` 已统一金色

**结论**：缺的不是「有没有动效」，而是「动效没有统一命名 + 没有收敛时长/缓动的自由值」。这正是老板说的「项目里已有的统一下来，不要每处自己发明」。

| D2 | **「淡入」一类变化多套实现**，节奏不齐（.13s/.25s/.34s/.9s 各来一遍） | `rp-fade`/`mModalIn`/`moIn`/`floatGain` 并存 | 🔴 |

### 1.3 修复方向（下一轮）

**建立动效 token**（追加进 `:root`，与现有颜色/字号 token 同源）：

```
--dur-instant: 90ms     /* 按压下压（跟手，最快） */
--dur-fast:    140ms    /* 悬停/图标切换（快、不抢戏） */
--dur-normal:  180ms    /* 弹窗入场/面板切换（标准） */
--dur-slow:    320ms    /* 里程碑/大场景入场（交代"发生了什么"） */
--ease-out:    cubic-bezier(.16, 1, .3, 1)   /* 出场：快起缓收 */
--ease-in-out: cubic-bezier(.4, 0, .2, 1)    /* 循环/呼吸 */
```

然后**逐类收敛**：淡入→`--dur-normal + --ease-out`；数值跳动→`--dur-fast`；呼吸循环→统一 `--dur-slow + --ease-in-out`；悬停→`--dur-fast`。**全站 `prefers-reduced-motion` 已覆盖，收敛后仍沿用。**

**验收**：grep 断言「全站 transition/animation 时长只允许出现在 token 定义处 + 明确的 `--dur-*` 引用」，类似项目已有的「不许裸 px/hex」断言。

## 三、总体判断（供拍板）

**这个项目的底子是好的**——「逻辑正确性」和「一致性」的绝大部分已经被历史多轮整改夯实（弹窗栈、唯一出口、softenBlocked、live 不打断、高危分层……）。老板两条指令**真正的增量**是：

1. **动效语言缺失**（主战场）：把散落 20 种时长 + 3 种曲线收敛成 token，建立「一套语言」。这是纯增量，不碰任何逻辑，风险最低、收益最直观。
2. **原生 confirm 残留**（唯一逻辑硬伤）：1 处，修掉即可恢复「处处一样」。

**建议的落地顺序**（下一轮）：
1. 先建立动效 token + 逐类收敛（D1~D7）—— 纯 CSS，不碰 JS 逻辑，零回归风险。
2. 修原生 confirm（I1+I2）—— 唯一 JS 逻辑改动，走唯一出口。
3. 跑三闸门 + 亲手用（实机截图 + 点按钮 + `prefers-reduced-motion` 走查）+ 再审查 + 合并。

**待老板拍板的点**：
- 动效 token 的**时长阶梯**是否接受我上面给的 4 档（90/140/180/320ms）？还是有偏好值？
- 「数值跳动」是否要统一加「上浮/变色」动效（会扩大改动面），还是本轮只收敛「已有动效」、不新增？

## 四、实施结果（v158.9，已闭环）

### 4.1 动效 token 化

`index.html` `:root` 新增 8 个动效 token（line ~294~315）：

| token | 值 | 语义 |
|---|---|---|
| `--dur-instant` | 90ms | 按压/瞬时反馈（跟手） |
| `--dur-fast` | 140ms | 悬停/图标/颜色切换 |
| `--dur-normal` | 180ms | 弹窗入场/面板切换/位移 |
| `--dur-slow` | 320ms | 里程碑/大场景入场 |
| `--dur-progress` | 400ms | 进度条/量级推进（linear 保留） |
| `--dur-unit` | 550ms | 战场单位走位演出 |
| `--ease-out` | cubic-bezier(.16,1,.3,1) | 出场：快起缓收 |
| `--ease-in-out` | cubic-bezier(.4,0,.2,1) | 循环/呼吸 |

**收敛结果**：69 处 `transition`/`animation` 裸值 → 全部 token 化（`--dur-fast` 51 次引用最多）。唯一保留语义差异的是**循环呼吸类的 animation duration**（告警 1s 快、排名 2.4s 慢，周期差异是语义，强统会破坏），但缓动曲线已统一为 `var(--ease-in-out)`。

**反模式修复**：`transition: all .14s`（`.bag-sortbar .chip`）→ 拆成 `color/border-color/background` 三项 + token（避免 `all` 连带 layout 重排）。

### 4.2 原生 confirm 清零

`js/main.js` `doNewGame`（重新开始）从原生 `confirm()` 改为自建 `ui.openModal` 确认弹窗：
- 标题「重新开始」+ 写明「当前进度将被清除 · 不可撤销」+ 红键「确定重新开始」（`new-game-do`）+ 「取消」（`close-modal`）。
- 真正的清档动作抽到 `GAME.doNewGameCommit()`，走 `data-action="new-game-do"` 分发。
- 复用项目已有的「高危操作确认弹窗」范式（`gold-heading`/`attr`/`note`/`panel-foot`），零新造逻辑。

### 4.3 断言同步（规则变更三件套）

`smoke-test.js` `§246④`：`/transition: transform \.09s ease-out/` → `/transition: transform var(--dur-instant) var(--ease-out)/ && /--dur-instant: 90ms/`（点明规则变更，未删除未放宽）。

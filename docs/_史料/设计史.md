### 11.2 关键机制
- **时间倍率设置**（默认120×，1~600可调）：1现实秒=N游戏秒，解决真实数值节奏慢问题
- **民心/税率**：黄金=人口上限×民心×税率；税率>50%民心每小时-10×(税-50)/50
- **军队耗粮**：真实每兵每小时耗粮，出征×2，粮尽饿死
- **将领加成**：统率×100=带兵上限；勇武1点=攻+1%；智谋1点=防+1%；内政1点=产量+1%
- **经验公式**：当前等级²×100 升下一级
- **交互**：内外城均地块网格 + 点击弹窗（原版热血三国式）
- **读秒显示**：精确倒计时 `H:MM:SS`（每秒必变）+ 格子内可视化进度条；建造/升级有 5 秒最小现实时长保底
- **时间倍率**：默认 120×（可选 1/10/30/120/300/600），旧档 30× 自动迁移到 120×
- **存档 v3**：`sanguo_save_v3`，旧档自动作废

### 11.6 测试体系（v5 · 2026-09-12）

两套测试互补，**缺一不可**：

| 测试 | 环境 | 覆盖 | 数量 |
|------|------|------|------|
| `smoke-test.js` | node + DOM stub | 数据/逻辑/数值结算/面板渲染 | 107 项 |
| `e2e-test.js` | jsdom + 内置 HTTP 服务 | **真实页面加载**、真实点击、控制台错误、定时器驱动 | 95 项 |

```bash
node smoke-test.js                                              # 逻辑层
NODE_PATH=<...>/node_modules node e2e-test.js                    # 真实浏览器环境
```

**为什么需要两套**：`smoke-test` 的 DOM stub 会让 `document.querySelector` 永远返回一个假对象，
`null` 引用类错误会被掩盖；且它曾**未加载 `main.js`**，导致主循环内的致命错误长期未被发现。
`e2e-test` 用真实 DOM 引擎加载真实 `index.html`，并把 `window.onerror` / `console.error` 纳入断言。

**e2e-test 必须走 HTTP 而非 file://**：jsdom 在 `file://` 下 localStorage 属 opaque origin，
访问会抛 `SecurityException`，与真实浏览器行为不符。

### 11.7 已修复的致命缺陷（v5）

| 缺陷 | 症状 | 根因 | 修复 |
|------|------|------|------|
| **主循环崩溃** | 点升级后**读秒不动**、侧栏空白、生产停滞、队列不刷新 | `js/main.js` 主循环第 376 行使用了 `$('#screen-game')`，但该文件**从未定义 `$`**（它只是 `ui.js` IIFE 内的局部变量），每秒抛 `ReferenceError`，后续 `tickOnce`/`updateProgress`/`renderSide`/`syncHeader` 全部不执行 | main.js 顶部补 `$`/`$$` 定义 |
| **存档静默失败** | 玩家进度无法保存，`saveGame()` 返回 false 且无提示 | `map.grid`（500×500＝25 万格地形）被打包进存档，JSON 达 **9.0 MB**，超过 localStorage 约 5 MB 配额，`setItem` 抛异常被 `catch` 吞掉 | 存档时剥离 `map.grid`（地形由 `map.seed` 确定性重建），存档降至 **40 KB**；读档后调用 `map.generate()` 重建；失败时输出 `console.warn` |

**教训**：测试若使用「永远返回假对象」的 DOM stub，或漏加载某个模块，会给出虚假的通过结论。
凡涉及主循环、事件分发、DOM 引用的代码，必须由真实 DOM 环境的测试覆盖。

### 11.8 资源数值显示（v5 · 可见增长）

**问题**：资源存量用 `U.fmt()` 渲染，而 `U.fmt` 会**向下取整 + 缩写为「万/k」**：
`20000` → `"2.0万"`。当时每秒实际增长 6.67，但文本要涨满 1000 才会变成 `2.1万`
——**约 150 秒才跳动一次**，玩家完全看不出资源在增长。

**修复**（`U.fmt` 保留，用于弹窗中的成本对比等场景）：

| 工具函数 | 用途 | 示例 |
|---------|------|------|
| `U.numHTML(n, dec)` | 存量：整数千分位 + 小数分离（小数套 `.num-frac` 暗色小字） | `20,001<span class="num-frac">.67</span>` |
| `U.numText(n, dec)` | 纯文本精确值（title 提示、日志） | `1,234,567.89` |
| `U.rateHTML(perSec)` | 增速：按 **/秒** 显示，与每秒刷新的画面节奏对应 | `+6.67/秒` |
| `U.fmt(n)` | 保留：弹窗/成本对比等空间受限处仍用缩写 | `2.0万` |

**展示效果**（左栏资源区，每秒刷新）：

```
🌾 粮食        20,001.67  +6.67/秒  +
🪵 木材        20,000.83  +3.33/秒  +
...
每小时（游戏时间）：粮食 200 · 木材 100 · 石料 100 · 铁锭 100
```

**要点**：
- 增速用「/秒」而非「/时」——画面每秒刷新一次，用秒做单位才能让「数字在动」与「速率」对应上。
- `.res-line .val` 用 `font-variant-numeric: tabular-nums` 等宽数字，避免每秒刷新时宽度抖动。
- 侧栏宽 300px，实测亿级资源（`104,857,600.00`）仍可正常显示不换行。

### 12.2 历法天时

- **1 游戏年 = 57600 游戏秒**（默认 120× 下约 8 现实分钟），一年四季，每季轮换天气。
- **四季**：春粮 +10% / 夏 +15% / 秋 +25% / **冬 −35% 且军粮消耗 ×1.3**。
- **天气**：晴 / 雨 / 雪 / 雾 / 大风，各有独立效果并**接入已有数值链**：

| 天气 | 影响 |
|------|------|
| 雨 | 粮 −15%、**弓兵射程 −20%**、火攻失效、行军 −20% |
| 雪 | 粮 −30%、军粮多耗 30%、行军 −50%、火攻失效 |
| 雾 | **侦察失效，偷袭伤害 ×2**、行军 −30% |
| 大风 | **火攻 ×3**、行军 +10% |

接入点：`productionPerSec`（产量）、`foodPerSec`（军粮）、`battle.damageOf`（射程与伤害）、
`simulate`（守方减伤）。

### 12.3 年号纪元（赛季制）

- 取**真实年号**：建安 → 延康 → 黄初 → 太和 → 青龙 → 景初 → 正始 → 嘉平 → 正元 → 甘露 → 景元 → 咸熙。
- 每个年号 = 一个「时代」，立**时代之志**（如「营建八所屋舍」「甲兵三万」）+ **时代增益**（如「百废待兴：全资源 +10%」）。
- 达成 → 结算黄金与声望并记入史册；**未达成不惩罚**，只作史书一笔。
- 年号用尽后循环复始，作为长线延续。
- 待补：各时代增益与目标数值可继续按史实细化（现已给出合理默认值）。

### 12.4 史书纪事（记账式，非事件选项）

按用户要求改为**后台随机记账**：仿《三国志》纪传体，自动记录玩家到了什么水平。

## 13. 守将 / 装备 / 首页 / 存档体系（v7 · 2026-09-12）

### 13.1 守将加成（此前完全未生效）

**问题**：守将只有 `status='guard'` 状态标记与任命 UI，**没有任何加成计算**——
内政不增产、勇武不加速征兵、智谋不加速研究。用户反馈"守将对城池的加成还没有起作用"，属实。

**实现**（`domain.js`）：

```
GAME.guardBonus(city)       → 单城守将加成
GAME.guardBonusTotal()      → 全部守将累加（多城多守将叠加）
GAME.guardBuildMult()       → 建造加速系数（1/(1+内政×1%)）
```

| 属性 | 作用 | 接入点 |
|------|------|--------|
| 内政 | 产量 +1%/点 | `productionPerSec` |
| 内政 | 建造速度 +1%/点 | 城内/城外 4 处建造队列 |
| 勇武 | 征兵速度 +0.5%/点 | `train()` 训练耗时 |
| 智谋 | 研究速度 +0.5%/点 | `systems.research()` 耗时 |
| 智谋 | 城防 +0.5%/点 | `cityDefense()` |

均设 60%~150% 加速上限，避免高属性守将破坏平衡。实测：赵子龙（四维 45）任守将后
粮食产量 `25.16 → 36.48/秒`。

### 13.2 装备属性接入战斗（此前只生效一半）

**问题**：装备的四维（统率/内政/勇武/智谋）已通过 `genAttrs` 生效，
但装备**特有的 `atk`/`def`/`spd`/`hp` 完全没有接入战斗**——
连坐骑速度（报告里"155 速一步到墙"的核心玩法）都无人使用。

**实现**（`battle.js`）：

| 装备属性 | 接入方式 |
|---------|---------|
| `atk`（武器攻击，如倚天长剑 2888） | 全军伤害 ×(1 + atk/10000)，即 +28.9% |
| `def`（护甲防御） | 守方减伤 + def/10000（上限 0.85） |
| `spd`（坐骑速度） | 先手判定中 `armySpeed × (1 + spd/200)` |

实测：义兵 2000 进攻 1500，无武器损兵 32 → 装备倚天长剑后损兵 0。

> 注：本作暂未实现"行军耗时"机制，故坐骑速度只作用于先手判定；
> 若后续加入行军时间，应在此处接入 `spd` 作为速度系数。

### 13.4 存档体系（为离线计算服务）

**主档 + 索引双层结构**：

| 层 | 键 | 体积 | 用途 |
|----|----|------|------|
| 主档 | `sanguo_save_v3` | ~39 KB（剥离 `map.grid` 后） | 完整游戏状态 |
| **索引** | `sanguo_meta_v3` | ~250 B | 首页秒读，避免解析主档卡顿 |

`GAME.metaOf(st)` 是**纯函数**——可从任意 state 对象（含从 localStorage 解析出的）
推算索引，不污染运行中的 `GAME.state`。

**索引字段**（也是离线计算的关键事实源）：

```
name / avatar / cities / army / rep / rank      概况
era / year / yearName / season / weather        天时快照
gameElapsed                                       ← 游戏秒累计（历法事实源）
savedAt                                           ← 现实时间戳（离线时长基准）
lastText / chronicleCount                        史册摘要
```

**离线补算链路**（`GAME.offlineCatchup`）：

```
离线现实秒 = now - savedAt
  ├─ 精确段（≤ 3600 现实秒）：逐秒 tickOnce
  │    → 队列 / 民心 / 人口 / 建造完成的逐秒逻辑保持正确
  └─ 聚合段（> 3600）：一次算完
       → 资源按当前每秒产量 × 时长；队列整段推进后统一判定完成
       → GAME.story.tick(时长 × timeScale) 整段推进历法
```

**与记账的联动（关键）**：

补算期间置 `GAME._offline = true`，`STORY.chronicleAdd` 会**抑制** `annual` / `note` /
`encounter` 类条目（改元与里程碑仍保留）。否则离线 30 分钟会一次性涌出几十条史书。
补算结束后由 `STORY.recordOffline()` 统一记一条：

> 离城10分乃归。延康二年秋，城2座，甲兵10，粟20,000石。

**待完善**（记录在案）：
1. **天气随机不可复现**：现用 `Math.random`，离线补算的天气无法与"真实流逝"一致。
   若要求确定性，应改为带种子的 RNG（`seed = world.seed + world.elapsed`）。
2. **无离线收益上限**：长时间离线（如 24 小时）会全额补算，可能造成资源暴增。
3. **多存档槽**：目前仅单档。
4. **版本迁移**：仅"版本不符即作废"，无字段级迁移函数。

## 14. 建筑功能体系（v8 · 2026-09-12）

### 14.1 设计原则：功能必须有归属

此前的问题不是"没数据"，而是**功能没有归属到建筑上**——兵种解锁数据、科技解锁条件都在，
但玩家点建筑只能看到"升级/拆除"；募兵在「军队」标签页、研究在「科技」页，
建筑本身像一个没有出口的雕像。

现在**点建筑直达其功能**（`BLDG_FUNC` 表）：

| 建筑 | 提供功能 | 入口去向 |
|------|---------|---------|
| 军营 | **募兵**（兵种随等级解锁） | 军队面板 |
| 校场 | **出征**（N 级 = N 队 × N×1万人口） | 地图 |
| 书院 | **研究**（科技需书院 Lv） | 科技面板 |
| 客栈 | **招募将领 / 相亲** | 客栈弹窗 |
| 招贤馆 | **将领名录**（容量上限） | 名录弹窗 |
| 市场 | **资源互换** | 市集弹窗 |
| 仓库 | **储量上限** | 仓储弹窗 |
| 马厩 | **骑兵前置** | 装备面板 |
| 铁匠铺 | 装备 | 装备面板 |
| 工匠作坊 | 器械 | 军队面板 |
| 民房 | 人口 | 统计面板 |

建筑弹窗同时展示其**实际能力数值**（如军营显示"可募兵种 6/18"与"升 6 级解锁：弓箭手"）。

### 14.2 客栈：候选生成与招募

| 项 | 规则 |
|----|------|
| 同时候选数 | = 客栈等级（每级 +1 位） |
| 候选属性 | 基础 `30 + 客栈等级×4` ± 随机 20 |
| 史实名将 | **客栈 5 级起**，35% 概率出现真实名将/美人（属性照搬史料） |
| 美人比例 | 约 30%（候选为女性，内政/智谋偏高、勇武偏低，可"相亲"） |
| 招募成本 | `800 × 客栈等级`（美人 ×1.4；史实名将 ×约 3.75） |
| 刷新 | 每 5 分钟自动换一批；可花 `500 × 客栈等级` 立即换 |
| 招募上限 | **受招贤馆房间数限制**（招贤馆 N 级 = 可容 N 人） |

生成逻辑在 `domain.js`：`innRefresh / innRecruit / innReroll / canRecruitGeneral`。

### 14.3 招贤馆 / 仓库 / 市场 / 马厩

| 建筑 | 效果 | 实现 |
|------|------|------|
| **招贤馆** | 将领容量 = 等级（无空房不可招募，提示指向升级） | `GAME.generalCap()` |

### 14.4 解锁提示改进

`canTrain` 原先遇到第一个不满足条件就返回，玩家只看到"需要军营 Lv5"，

## 15. 自动升级（v9 · 2026-09-12）

### 15.1 规则

开关位于**设置面板**（默认**关闭**，避免玩家不知情被升级耗尽资源）。

| 规则 | 实现 |
|------|------|
| **排序** | 按**等级从低到高**（保持建筑均衡发展）；同级**城内优先**于城外 |
| **范围** | 城内功能建筑 + 城外资源地块（官府取一格代表，4 格同体） |
| **队列约束** | 受建造队列上限约束（默认 2，徭役令可 +3）；队列满则本轮不排队 |
| **资源不足** | **暂停**并记录原因，**不关闭开关**；资源恢复后自动继续 |
| **全部满级** | 置 `autoState.done` 并停止 |
| **调用时机** | `tickOnce` 内每次结算后尝试一次（第 9b 步） |

### 15.2 状态与反馈

`state.autoState = { paused, done, last, want, reason, msg }`

- **队列栏**（底部）显示：`建造队列：…　|　🔨 自动升级：正在升级 民房 → Lv2`
- **设置面板**显示开关状态与当前状态文字，暂停时用告警样式标出

### 15.3 顺带修复：官府 4 格等级不同步的隐患

官府占城内中央 4 格（同体），但升级完成时若只更新发起格，其余 3 格等级会滞后，
导致城内显示等级与实际容量（黄金上限）不一致。

已在 `applyBuildDone` 中补上同步：官府任一格升级完成时，4 格等级一并更新。
测试中有专门断言「官府 4 格等级同步」。

### 15.4 测试

- `smoke-test.js` 第 21 节 19 项：默认关闭、关闭时无动作、开启后排队、优先最低等级、
  队列上限生效、队列满不排队、资源不足暂停（且不关开关）、资源恢复自动继续、

- `e2e-test.js` 第 18 节 7 项：真实点击开关、开启后立即排队、

### 15.5 已知取舍

- 自动升级**不会**自动建造新建筑（只升级已存在的），避免玩家建筑布局被程序改动。
- 自动升级**不区分优先级**（不会优先升官府/军营），仅按等级从低到高。

### 16.2 地图观察框（12×12）

**问题**：原先把 500×500 全图直接绘进 760×540 的 canvas——**每格约 1.5 像素**，
图标退化成像素点，城池无法点击，玩家说"满屏根本没法进行操作"。

**方案**：视口渲染（`map.js`）

| 项 | 实现 |
|----|------|
| 观察框 | **12×12 格**，每格 **44px** → canvas 528×528 |
| 导航 | 方向键（▲◀▼▶，十字布局）+ 坐标输入框 + 「前往」「回主城」「洛阳」 |

| 视口记录 | `GAME.map._view = { vx, vy, span, cell }`，供点击换算 |
| 越界钳制 | `vx/vy` 自动限制在 `0 ~ MAP-span` |

**视觉**：

- 每格纵向双色渐变（上亮下暗）+ 顶部高光 + 底部暗边 = 地块厚度
- **地形图标**：🌊湖泊(粮) · 🌿草原(粮) · 🍃沼泽(粮) · 🌲森林(木) · 🏜️荒漠(石) · ⛰️山地(铁)

- 已占野地金框 + 等级角标
- **视口外的州城/都城在画面边缘显示箭头提示**，避免"不知道外面还有城"

**点击换算**：`pick()` 由"全图比例"改为"视口换算"
（`tx = floor((clientX-rect.left)/rect.width*span)`，再 `+vx`）。

**顺带收获**：绘制量从 25 万格降到 144 格，地图切页不再卡顿。

**配方**（`DATA.FORGE`）：

```
成本 = 品质基准 × 槽位倍率 × (套装件 ? 2.2 : 1)
品质基准：凡 {金800,铁300,木200,石100} → 良 ×5 → 珍 ×25 → 神 ×112
槽位倍率：武器 1.6 · 坐骑 2.0 · 铠 1.25 · 盔 1.1 · 其余 1.0
```

成品属性（散件，品质 1→4）：武器攻 78/264/558/960；铠甲防 98/330/700/1200；
战马速 9/36/82/146；体力 80/220/420/700。
**散件刻意弱于同名套装**，套装仍是长线目标（倚天长剑单件攻 2888）。

### 17.3 将领资质分级（用户要求「差异要大、高资质概率低但更夸张」）

| 资质 | 权重 | 初始四维区间 | **每级成长** | 招募价 | 30 级统率示例 |
|------|------|------------|------------|--------|-------------|

| 良材 | 27 | 46~62 | **+2** | ×1.8 | 112 |
| 英杰 | 15 | 64~84 | **+3** | ×3.2 | 161 |
| 名世 | 6 | 86~106 | **+5** | ×7.0 | 241 |
| **天授** | **2** | **108~140** | **+8** | **×16.0** | **356** |

- **概率与成长双重拉开档次**：天授 30 级统率是凡品的 **5.4 倍**（356 vs 66），
  而出现率仅 2%（实测抽样 4000 次 = 1.98%）。

## 18. 视觉重制 / 任务体系 / 材料与菜单重构（v12 · 2026-09-12）

### 18.1 图标系统：从「色块 + emoji」到手绘 SVG

**问题**：地块是一张彩色渐变背景 + 一个 emoji 字符。emoji 由系统字体渲染，
各平台字形不一、无法统一风格；彩色背景又抢了主体，远看就是一排色块。

**方案**：新建 `js/icons.js`，**52 个手绘 SVG 图标**，地块背景改为深色底，建筑本身成为画面主体。

| 类别 | 数量 | 说明 |
|------|------|------|
| 城内建筑 | 16 | 官府（重檐大殿）/民房（茅顶+烟囱）/书院/军营（军帐+枪阵+帅旗）/校场（箭靶+栅栏）/市场（摊位+箩筐）/仓库（圆仓+陶瓮）/城墙（垛口+门楼）/驿站（驿亭+驿马）/烽火台（高台+烈焰）/马厩/客栈（二层楼+酒旗）/招贤馆（榜文）/鸿胪寺（双阙）/铁匠铺（炉火+铁砧+锤）/工匠作坊 |
| 城外资源 | 4 | 农田（田垄+麦穗）/伐木场（树+斧+树桩）/采石场（石堆+凿子）/铁矿场（矿洞+矿车+镐） |
| 野地地形 | 8 | 平地/草原/沼泽/湖泊/森林/荒漠/山地/城池 |
| 资源 | 6 | 粮食/木材/石料/铁锭/黄金/人口 |
| 兵种 | 18 | 兵卒剪影 + 主武器（枪/刀/弓/盾/斧/车），骑兵带马、南疆象兵为战象 |

**风格统一的三条规则**（写在 `icons.js` 顶部）：

1. **左上光源**：所有立体面朝同一方向，右半侧压暗 22%~45%
2. **建筑三件套**：台基 / 墙体 / 屋顶，中式屋顶带**檐口翘起**与**正脊鸱吻**（金色圆点）
3. **配色克制**：青瓦灰蓝、琉璃暖棕、夯土米黄、木构棕、铜饰金；渐变仅用于大面积

地块样式（`index.html`）：
- 背景改为深色承台，`::after` 换成 `.b3d` 椭圆地面阴影，让建筑「立」在格子上
- 悬停：上浮 3px + 金色描边 + 图标放大 6% + 提亮
- 官府格保留金色描边与内辉光以区隔

**地图改为矢量绘制**（`map.js`）：
- 移除 `TERRAIN_ICON` emoji 表，新增 `drawTerrainArt()`（7 种地形各自画法）与 `drawCityArt()`（城墙+垛口+城门+门楼）
- 只用 `fillRect / arc / moveTo+lineTo`，不依赖 emoji 字体，跨平台一致
- 玩家城绿调、州城金调、都城红调，屋顶颜色随之变化

### 18.2 任务体系（86 条 · 两类）

**旧版问题**：只有 8 条任务，且每种任务要写一段专门的判断逻辑（`q.target.build` / `upgrade` / `train`…），
扩展到几十条会失控。

**新版**：改为**指标（metric）驱动**。任务只声明「读哪个指标、目标多少」，
求值统一走 `GAME.questMetric(metric, sub)`（31 个指标），加任务＝加数据。

| 类别 | 数量 | 特性 |
|------|------|------|
| **成长型** `DATA.QUESTS` | **50 条** | 一次性，领取后永久记入 `quests.done`，从进行中列表移出 |
| **随机型** `DATA.RANDOM_QUESTS` | **36 条** | 可重复抽取，分 7 个类型（军事/征战/营建/科研/内政/招贤/打造） |

**随机任务刷新规则**（`DATA.QUEST_DAILY`）：

```
每日刷新 5 项 · 同批内类型互不相同 · 未完成可累积 · 上限 5 天 = 25 项
```

- **进度用增量**：接取时记录 `base = 当前指标值`，进度＝`当前值 − base`，
  避免「昨天攒的粮自动完成今天的屯粮任务」。存量类任务（如民心 ≥ 85）标 `abs: true` 用绝对值。
- **关于「天」的取法**：游戏内 1 年 = 57600 游戏秒 = 480 现实秒（120×）。
  若按汉历 360 日折算，**1 游戏日仅 1.33 现实秒**，做任务周期毫无意义。
  因此任务刷新锚定**现实日**，并在面板上明示「每日 5 项 · 可累积 5 天（上限 25 项）」。
- **不可刷**：「全部换新」按条数计价（3000 金/条），换新后池大小不变，不会凭空产任务。

**任务面板三分区**（用户要求「已完成单独列表，不与未完成混排」）：

```
📜 任务  可领取 N 项
├─ 随机任务      每日 5 项 · 可累积 5 天（上限 25 项）· 当前 N 项   [全部换新]
├─ 成长任务·进行中   N 项待完成 / 共 50 项
└─ 已完成（默认收起） 共 N 项                                  [展开]
```

任务卡含：标题、类型标签（分色）、状态、描述、指引、进度条、奖励、领取/换新按钮。
导航栏「任务」带**可领取数量红点**。

## 19. 材料体系 / 2.5D 场景 / 三方式出征 / 野外城池（v13 · 2026-09-12）

### 19.1 装备专用材料：六大系列 × 四品阶（24 种）

**问题**：v12 的打造材料只有 7 种（楠木/兽皮/兽筋/玉料/精铁/玄铁/陨铁），
混用资源型命名（楠木、兽皮），且「品质」只体现为数量多少，材料本身没有品阶梯度——
做神品装备和凡品用的都是同一批料，只是多要几个。

**方案**：改为**六个系列，每系列四品阶**，品阶与装备品质一一对应。

| 系列 | 一阶 | 二阶 | 三阶 | 四阶 | 用途 |
|------|------|------|------|------|------|
| **铁系** | 凡铁 | 精铁 | 镔铁 | **陨铁** | 刀兵甲胄之骨 |
| 木系 | 松木 | 楠木 | 檀木 | 建木 | 弓弩器械之干 |
| 革系 | 粗革 | 硝革 | 犀革 | 蛟革 | 甲裳靴履之肤 |
| 筋系 | 兽筋 | 牛筋 | 蛟筋 | 龙筋 | 弓弦索具之力 |
| 玉系 | 河石 | 青玉 | 羊脂玉 | 昆山玉 | 佩饰玺绶之华 |
| 丝系 | 麻布 | 细绢 | 蜀锦 | 云锦 | 战袍旗幡之彩 |

**配方规则**（`DATA.FORGE.matBySlot` 存**系列名**，不存具体材料）：

```
部位 → 吃哪几个系列     品质 → 吃第几品阶
武器 = 铁系 + 木系 + 筋系      凡品(q1) → 一阶料
护具 = 铁系 + 革系             良品(q2) → 二阶料
腰/靴 = 革系 + 筋系/铁系        珍品(q3) → 三阶料
佩饰 = 玉系 + 铁系/丝系         神品(q4) → 四阶料
坐骑 = 革系 + 筋系 + 丝系
```

例：`cr_weapon_4`（神兵）= 陨铁×16 + 建木×11 + 龙筋×6；套装件再 ×1.5。

**散件命名同步重做**（原先「玄铁刀」吃陨铁，名实不符）：每部位 4 档独立命名，
如 铁刀/钢刀/宝刀/神兵、皮甲/铁甲/明光铠/陨铁铠、驽马/良马/骏马/龙驹。

**获取途径梯度**（这是本次的设计重点——让攻城成为必需）：

| 来源 | 产出品阶 |
|------|---------|
| 野地（按地形） | **仅一阶**：森林→松木、山地→凡铁、荒漠→河石、草原→粗革/麻布、沼泽/湖泊→兽筋 |
| **野外城池** | 一阶（6 系齐出） |
| 县城 / 郡城 | 二阶 |
| 州城 | 三阶 |
| 都城 | 四阶 |

即：**低阶料可自采，高阶料必须靠打城**，形成「扩张换强度」的闭环。

**图标**：`icons.js` 新增 24 个 SVG 材质图。造型随系列变化——
铁=锭、木=原木、革=兽皮、筋=筋束、玉=玉璧、丝=布卷；
配色按品阶升级（灰暗→亮银→流纹→紫金），右下角**品阶珠 1~4 颗**直接标出品阶。

### 19.2 背包重构：分类 / 拆分 / 排序

| 维度 | 实现 |
|------|------|
| **分类** | 四页签：装备 / 材料 / 宝物 / 图纸；页内再分组（装备按**部位**或**套件**、材料按**系列**、宝物按**功能类型**） |
| **排序** | 每页签独立排序项：装备（品质/价值/套件/部位）、材料（系列/品阶/数量）、宝物（类型/价值） |

## 20. 资源供需：外城按城独立 / 州特产 / 名城岁贡（v14 · 2026-09-12）

> 本轮起因：梳理「所有资源需求 → 分配产出方式」时，核对原版实测机制发现**四处重大偏差**
> 与三处长期供给断层。完整分析见 `docs/资源产出分配方案.md`，可交互图谱见 `docs/资源供需图谱.html`。

### 20.1 核对原版得到的结论（重要，勿凭印象改）

| 项 | 原版实测 | 本轮处理 |
|---|---|---|
| 野地加成 | **每级线性**：平原/草原 粮+3%/级、沼泽 +5%、**湖泊 +8%**、森林 木+5%、荒漠 石+5%、山地 铁+5% | 记为待改项（现实现为「满级值−缺口」，10 级湖泊仅 +35%，原版应 +80%） |
| 采集 | 占领野地后可派军「采集」：按地形产资源，**不足 1 小时收获为零并重置、24 小时封顶**，将领等级只影响宝物率 | 记为待做项 |
| 野地等级 | 被占野地每现实日 **−1 级**，无主野地 **+1 级**（上限 10） | 记为待做项 |
| 掠夺 vs 占领 | 铁律「**掠夺得资源，占领得地盘**」——占领野地**不给资源** | 记为待调整项 |
| 城池特产 | **原版没有此设定**；资源加成全来自野地，城池只给税收（黄金）+ 建筑位 | 按需求做成「**州特产**」变体（见 20.3） |

### 20.2 外城资源地块改为按城池独立

此前 `state.extGrid` 是**全局单份**，导致多占城池不增加资源地块 —— 攻城只剩税收，缺少经营动力。

- 结构：`state.extGrid` → **`city.extGrid`**（每城一份）
- 统一入口 `GAME.extGridOf(city)`，**不再直接读 `state.extGrid`**（字段已从 state 移除）
- 上限 = `12 + (本城官府等级-1) × 3`；官府升级只扩**本城**
- 攻占新城 → `makeCity` 自动配发该城自己的 12 块外城地块（`type`/`state` 一并从 NPC 继承）
- 受影响函数全部改为按城：`extCap / ensureExtGrid / extCount / extUsed / buildExt /
  upgradeExt / demolishExtRefund / demolishExt / buildProgress / buildPct / cancelBuild /
  applyBuildDone / productionPerSec / questMetric(ext*)`
- **多城时同一下标会重复**，故 `cancelBuild` 与 `buildProgress` 必须同时匹配 `q.cityId`
- 自动升级改为**遍历所有城池**（城内 + 城外），多城时候选名带城名前缀（如「分城·民房」）
- 新增 `GAME.extSummary()` 全境统计（城数 / 已开发 / 总上限）；UI 在城外页显示「全境 N 城共 X/Y 块」
- 存档迁移：读档时把旧的 `state.extGrid` 搬到首城，各城按本城官府等级补齐地块，随后删除旧字段

### 20.3 州特产（与地理绑定）

原版无「城池特产」；此处按需求做成**州级**特产，让「打哪里」直接决定「能造什么装备」。

- `DATA.STATE_SPECIALTY`：**13 州各出一种材料**，覆盖六系
  - 司隶 = **陨铁（四阶）**｜荆州 蜀锦 / 益州 檀木 / 凉州 犀革 / 幽州 蛟筋 / 交州 羊脂玉（三阶）
  - 冀州 精铁 / 兖州 硝革 / 豫州 细绢 / 青州 牛筋 / 徐州 楠木 / 扬州 青玉（二阶）｜并州 凡铁（一阶）
- 州属判定 `GAME.stateOfCity(city)`：显式 `city.state` 优先；玩家自建城按坐标**就近认领**最近的州城/都城
- 州治加成：握有该州州城（司隶以都城为治）时，本州特产产量 **×1.5**（`DATA.STATE_SEAT_BONUS`）
- 意义：都城洛阳产出**四阶材料**，解开「三/四阶仅在州城(12)/都城(1) 一次掉落后占完即断供」的断层

### 20.4 名城岁贡（按现实日结算）

`DATA.CITY_YIELD` 按城档位给出每日 黄金 / 声望 / 特产材料：

| 档位 | 黄金/日 | 声望/日 | 特产材料/日 |
|---|---|---|---|
| 都城 | 30 万 | 200 | 6~10（×州治 → 9~15） |
| 州城 | 12 万 | 60 | 5~9（×州治 → 8~14） |
| 郡城 | 4 万 | 20 | 4~8 |
| 县城 | 1.5 万 | 10 | 3~6 |
| 自建城 | —（无岁贡，靠外城地块 + 税收） | — | — |

- 结算锚定**现实日**（与野外城池等级同源）：`state.yieldDay` 记录上次结算日
- **首日只登记日期、不发放**（`yieldDay === null` → 登记后返回）

## 21. 可玩性修复（v14.1 · 2026-09-12）

> 本轮为 6 项体验级缺陷修复。其中「点第一行操作到第二行」与「训练报参数错误」是
> **同一类根因**：命名空间 / 发号错位。

### 21.1 将领 id 撞号（「点第一行，变动的是第二行」）

**根因**：`makeGeneral` / `makeHero` 用模块级 `GAME._genSeq` 发号 `g1, g2, …`，而该计数器
**页面加载时从 0 开始**。读档后调用 `makeGeneral` → 第一个新将必得 **g1**，与存档内旧将撞号。
此后 `s.generals.forEach(x => if (x.id === genId) g = x)` 取的是**最后一个**同号者，
于是点第一行（旧 g1）打开/操作的是后面那一行（新 g1）。

**修复**：
- 新增 `GAME.syncSeq()`：扫 `state.generals` 与客栈候选，把 `_genSeq / _cndSeq` 抬到最大号之上；
  在 `newGame()` 与 `loadGame()` 后各调一次。
- 新增 `GAME.nextGenId()`：发号前暴力避让已用 id（双保险，即使计数被归零也不撞）。
- `makeGeneral` / `makeHero` 一律改用 `nextGenId()`。

### 21.2 募兵「参数错误」

**根因**：`ui.js` 里写的是 `GAME._trainSel = 'yibing'`，而所有读取处是 `ui._trainSel`
（即 `GAME.ui._trainSel`）—— **两个不同属性**。初始值落空 → `ui._trainSel === undefined`
→ 训练按钮渲染成 `data-troop="undefined"` → `DATA.TROOPS['undefined']` 为空 →
`GAME.train` 返回「参数错误」。

**修复**：
- 改为 `ui._trainSel = 'yibing'`；`troopsHTML` 开头做存在性兜底。
- `GAME.train` 的错误提示细分化：未知兵种 / 城池不存在 / 数量无效 / 单次上限 50 万，
  不再一律「参数错误」。

## 22. 野地重建：线性加成 / 采集 / 掠夺与占领 / 等级动态（v15 · 2026-09-12）

> 本轮落实 `docs/资源产出分配方案.md` 的 **P0 四项**（闭环断裂级）。
> P0 的核心判断：此前的野地只是「占位即享的被动加成」，驻军毫无价值，
> 与「掠夺得资源，占领得地盘」的原版设计相悖。

### 22.1 野地加成改为**每级线性**（P0-2）

**旧**：`add` 存的是"满级值"，实际加成 = `add − (10−lv) × step` → 10 级湖泊只有 **+35%**。
**原版实测**：加成是**每级线性**叠加。

| 地形 | 修正后 | 10 级实得 |
|---|---|---|
| 平原 / 草原 | 粮 **+3%/级** | +30% |
| 沼泽 | 粮 **+5%/级** | +50% |
| **湖泊** | 粮 **+8%/级** | **+80%** ← 此前误算为 +35% |
| 森林 | 木 **+5%/级** | +50% |
| 荒漠 | 石 **+5%/级** | +50% |
| 山地 | 铁 **+5%/级** | +50% |

- 新增统一入口 `GAME.wildAddOf(type, level)`；`TERRAIN` 删除 `step` 字段，`DATA.WILD_ADD` 弃用
- 三处重复实现（`state.js:wildMult`、`ui.js` 野地总览、`openLandModal`）全部收口到该函数
- 效果：高等级野地第一次真正「值得反复争夺」

### 22.2 采集系统（P0-1，全新）

把**闲置兵力**转化为资源 —— 这是野地驻军的唯一价值所在。

- 配置 `DATA.GATHER`：`basePerHour 2`、`levelBonus 0.35`、`troopCap 5000`、
  `minHours 1`、`maxHours 24`、`maxActive 3`、`stamina 6`
- **可采资源按地形**（`DATA.GATHER.resOf`）：湖泊/沼泽/草原→粮、森林→木、荒漠→石、山地→铁；
  **平原无可采之物**（原版：平地不可采集）
- 收成 = `basePerHour × (1 + 等级×0.35) × 有效兵力 × 时长`，
  有效兵力封顶 `troopCap`（防后期数值爆炸）
- **不足 1 游戏小时收获为零，且计时重置**；**24 游戏小时封顶**（原版铁律）
- **将领等级只影响宝物概率**（`√时长 × (base + 等级×0.001)`，上限 0.65），**不影响资源收成**
- 兵力用 `GAME.autoPickTroops` 按「由弱到强」自动抽调（玩家只需填一个数字）
- 收获：资源入账（受仓库上限约束）+ 概率拾得小件宝物 + 兵力与将领归还 + 将领得经验
- 撤回：兵力归还、**无任何收益**（原版规则）
- 主循环 `GAME.tickGathers(ts)` 推进计时

API：`canStartGather / startGather / gatherYield / gatherTreasureChance / finishGather /
abandonGather / gatherAt / gatherByGen / tickGathers`

界面：
- 点地图野地 → 弹窗新增「**派军采集**」（已占且可采时显示）；标明可采资源与收成公式
- 野地总览 → 「📦 采集队 N/3」入口
- 采集队面板：进度条、已采时长、预计收成、宝物率、**收获 / 撤回 / 定位**

### 22.3 掠夺得资源，占领得地盘（P0-3）

新增 `DATA.EXPEDITION.wildResMul = { scout: 0.15, raid: 1.2, occupy: 0 }`：

- **野地占领：不给资源、不给珠宝**（`gains.res === null`），只给归属权 —— 长期加成 + 采集权
- 野地掠夺：仍给资源（1.2×）与珠宝

### 22.4 野地等级动态（P0-4）

| 状态 | 规则 | 实现 |
|---|---|---|
| 无主野地 | 每现实日 **+1 级**（模 11 循环） | `wildLevel(x,y) = (wildLevelBase + 现实日) % 11`，**无需存储** |

- `decayWilds` 挂 `tickOnce` 第 9e 步；旧档野地无 `levelDay` 时**首次只登记、不降级**
- 效果：占领不再是「一劳永逸」，形成轮换争夺；高等级野地会自己长出来

## 24. 结构审计与三件套验证（v16 · 2026-09-12）

### 24.1 为什么要加一层结构审计

两套测试能验证「已写下的逻辑是否正确」，但验证不了**「该写而没写的逻辑」**。
本轮全面梳理即由这一盲区发现：24 项科技里 17 项**根本没有消费点**，而所有测试都是绿的 ——
因为没有任何断言去问「研究这项科技之后，应该变化的是哪个数值」。

因此新增 `audit.js`，与两套测试构成**三件套**：

```bash
node audit.js          # ① 结构完整性（静态，<1s）
node smoke-test.js     # ② 逻辑正确性（806 项）
node e2e-test.js       # ③ 真实 DOM 交互（321 项，jsdom + 内置 HTTP）
```

`audit.js --strict` 在出现**孤儿按钮**或**重复定义**时以退出码 1 失败，可挂进提交前检查。

### 24.2 audit.js 的五项检查

| # | 检查 | 判据 | 能抓出什么 |
|---|---|---|---|
| ① | 函数引用完整性 | 命名空间函数定义 vs 全项目调用/字符串引用 | 死函数、重复定义（后者会静默覆盖） |
| ② | 按钮动作绑定 | `data-action` ↔ `main.js` 的 `case` 双向比对 | 「点了没反应」的按钮；不可达的 case 残留 |
| ③ | 科技效果消费点 | 每个 `type` 是否有 `techBonus('<t>')` / `techLevel('<id>')` 读取 | 研究了但无收益的科技（空承诺） |
| ④ | 叙事层消费点 | `STORY.*` 修正函数、国策 `boon` 键、天气字段的读取点 | 赛季/天气/羁绊的失效加成 |
| ⑤ | 数据字段引用 | 声明字段是否被 data.js 之外的模块读取 | 「改 data 不生效」的零引用字段 |

### 24.3 判据设计要点（避免误报）

审计最容易死在误报上 —— 一旦噪声大就没人看。本轮踩过的三类误报与对策：

1. **内部查表被当成死代码**：`icons.js` 内的 `B.* / E.* / T.*` 图标表由查表函数统一派发，
   静态看不到直接调用 → 以「单字母命名空间」识别为内部实现，不计入死代码。
2. **分发式调用**：`questMetric('extCount')` 这类通过字符串名触发的能力，
   函数名不出现在调用位置 → 追加「字符串字面量引用」兜底。
3. **同名字段混淆**：`scout` 既是天气字段又是出征模式名；`fire`/`move` 同理。
   泛匹配会全部命中 → 天气字段只认 `combatMod().x` / `cm.x` / `we.x` 这几种**真实读取形态**。

同理，`data-view` 的值映射到 `case 'view'`，不能当成独立 action 去比对 —— 这是第四类误报。

### 24.4 本轮审计结论摘要

- 规模：11,545 行 / 523 函数（**0 重复定义**）/ 92 按钮（**全部有处理器**）
- 死函数 15 个（其中 `checkVictory`、`STORY.siegeMult` 属**功能缺口**应「补」而非「删」）
- 不可达 `case` 分支 10 个（历次迭代残留）
- 科技有效率 **7/24**；天气有效率 **1/5**；国策失效 3 项；羁绊失效 1 组
- 两个隐蔽陷阱：**数值改动对老档不生效**（174 座 NPC 城整份入档，占存档 96%）、
  **在线粮食无下限钳制**（可扣成无限负数，与离线口径不一致）

完整报告见 `docs/全面梳理报告.md`，可视化见 `docs/系统全景.html`。

### 24.5 结论：把审计变成惯例

本项目已有两次同类事故——`map.grid` 撑爆配额、NPC 城快照导致数值改动失效——
**根因相同：派生数据入档**。审计脚本的价值不在这次抓到的具体条目，
而在把「写入点必须有消费点」这一条从**人的自觉**变成**可执行的检查**。

## 25. P0 四项落地（v17 · 2026-09-12）

第 24 章的结构审计列出 4 项 P0 缺陷，本章记录落地方式。**共性洞察**：
这四项都不是"算错了"，而是"没接上"——所以它们能被 1100+ 项测试全部放行。

### 25.1 科技接线：有效率 7/24 → 24/24

其中 3 项（打造技巧 / 合成技巧 / 驯马技巧）原本描述的是**不存在的系统**
（装备强化上限、宝石合成上限、坐骑强化上限），因此重映射到真实机制并同步改写描述：

### 25.2 存档瘦身：55.9 KB → 3.2 KB

`map.cities`（174 座 NPC 城快照）与 `map.grid` 同类——**纯派生数据**，一律不入档：

- `saveGame` 把 `map.cities` 置 null 后序列化，`finally` 里复原（存档是快照，不能破坏内存状态）
- `loadGame` **无条件**丢弃旧副本（老档因此才能吃到新数值）
- `map.generate` 由 seed 重建后，依据 `s.cities[].origId` 剔除已被占领的城，防止读档后"复活"

### 25.3 粮食：从"只有扣"到"有后果"

- `tickOnce` 扣粮后钳制到 0（与 `offlineCatchup` 同口径 —— 此前在线可为负、离线被清零）
- 粮尽按缺口比例逃兵（`GAME.applyStarvation`，单次封顶 15%）→ 军伍会自动收缩到产能可支撑的规模
- `GAME.isStarving()` 拦截出征（只在"存粮为 0 且消耗大于产出"时，避免临时缺粮就动不了）
- 侧栏给出红色警示

### 25.4 攻城伤害链

`STORY.siegeMult()` 此前**定义了但无人调用**，连带 4 处失效。现在 `simulate` 增加 `opts.sieging`：

- 攻城伤害 = 羁绊「白衣渡江」× 赛季国策（青龙·大兴土木 / 景元·大将西征）
- `STORY.defMult` 改为单一来源（原先与战斗内联版本重复）
- `rep_gain` 国策经 `STORY.repMult()` 接入占领城池与击破据点的声望
- `GAME.checkVictory` 在 `onConquer` 中调用（攻占洛阳 → 天下一统）

### 25.5 顺带修掉的三处真 bug

| 问题 | 说明 |
|---|---|
| **城防梯度被抹平** | `min(0.6, defVal × 0.10)` 有单位错位：城防值 40~110 一乘 0.1 就远超 0.6 上限，**县城与都城的城防效果完全相同**。改为 `/200` 线性 |

| **攻方护甲完全废弃** | 装备 `def` 与「防护技巧」只在扮演守方时才算，而玩家**只当攻方**，等于两项全废 |

### 25.6 天气从 1/5 → 5/5

`move` 接进行军速度；大雾 `ambush ×2`、大风 `fire ×3`（需带火器）作用于**先手回合**；
大雾 `scout: false` 使情报强制降为 1 级且一无所获。

### 25.7 清理

删除 16 个零引用函数与 11 个不可达 `case` 分支（含 `.side-tabs` 死监听器与死 CSS），

## 26. 行军机制与界面重构（v18 · 2026-09-12）

### 26.0 先说一个更严重的发现：出征的兵从来没回来过

做行军机制时读出征结算代码，发现两条路径都是断的：

- `expedition` 只做了 `city.army[id] -= atkArmy[id]`，**`result.atkRemain` 从未加回城池** ——
  派 10 万、零损失打一场，回来城内是 0
- `applyWounded` 只累加 `s.wounded` 这个数字，`heal()` 也只是把它清零 ——
  「伤兵归队」是空话，**治疗是一笔没有任何回报的金币消耗**

为什么 1100+ 项测试全绿却没抓到：所有断言都只看 `r.result`（谁赢、损兵多少），
**从没有人检查过城池战后还剩多少兵**。这是「只验证返回对象、不验证世界状态」的典型盲区。

修法（`GAME.battle.returnArmy`）：
- 幸存者按 `atkRemain / aStart` 的**同比例**分兵种回城
- 阵亡者按回收率折算伤兵，并记录**兵种构成**（`s.woundedArmy`）
- `heal(cityId)` 真正按兵种把伤兵加回城池；无兵种记录的历史存档则明确提示「已遣散」

### 26.1 行军队列（`GAME.march`）

出征不再是「点一下立刻出结果」，而是**出发 → 行进 → 抵达 → 结算**四段。
这一步的意义不只是真实感 —— 它是让一批既有内容第一次真正生效的前提：

| 原本空转的东西 | 现在如何生效 |
|---|---|
| 兵种 `spd` 属性（原本只影响战斗先手） | **最慢兵种决定全军速度**，带器械明显拖慢 |
| 驿站（「城池间行军提速 1.5 倍起步」） | 按等级提速 1.5~6 倍 |
| 烽火台 10 级（「27×27 内行军 +50%」） | 距离 ≤13 格时 ×1.5 |
| 天气 `move`（雨 −20% / 雪 −50% / 雾 −30% / 大风 +10%） | 直接乘进行军速度 |
| 行军技巧 / 驾驭技巧 / 车轮技术 | 按兵种类型分别提速（`spdMultOf`） |
| 急行军令（原本写 `s.marches` 而该数组恒空 → **静默失效**） | `rushAll()` 立即抵达 |

**参数可调**（`DATA.EXPEDITION`）：`marchSecPerTile=60` / `marchBaseSpeed=300` / `marchMinRealSec=2`。
注意 `DATA.TROOPS` 的 spd 在 100~1000 量级（义兵 200 / 轻骑 1000 / 投石车 100），
所以基准取 300 —— 10 格 ≈ 5 现实秒、50 格 ≈ 25 秒（120× 倍率下）。

**新增** `GAME.battle.prepare()`：出征前置校验抽成一份，`expedition` 与 `march.dispatch` 共用 ——
避免「出发时放行、抵达时才发现非法」的两套逻辑漂移。

**离线**：`offlineCatchup` 末尾 `rushAll()` 一次结清（离线期间出发的大军早已抵达）。
若不处理，玩家回归后会看到一支「早就该到」的军队还在路上。

**UI**：队列栏显示行军进度（可点击）、行军队列面板（表格 + 召回 + 急行军令）、
出征弹窗实时显示「行军 N 格 · 速度系数 X% · 预计时长」。

### 26.2 地块投影改平行四边形

旧的 2:1 菱形（W92×H46）有两个问题：整体轮廓是菱形、四周留白大；在屏幕上被压得扁平。

改为**剪切投影**：
```
地块元素左上角 = (col*W + row*SKEW, row*H)
四角           = (0,0) (W,0) (W+SKEW,H) (SKEW,H)      ← 平行四边形
格心           = (W/2 + SKEW/2, H/2) = 元素盒的 50%/50%
```
最后一条是关键：**元素盒的几何中心恰好就是格心**，于是建筑只要
`left:50%; top:50%; transform: translate(-50%,-100%)` 就精确「站」在格心上，
不再需要任何手工偏移 —— 位置不对应的问题从根上消失了。

密铺验证（测试里有断言）：同行右邻的左上角 x = 本格顶边右端 x；下一行 y = 本行 + H 且 x 偏移 SKEW。

### 26.3 城墙：从「扩一整格的墙环」到「13px 窄带」

v16 的墙环向外扩了整整一格，既占地方又压住边缘地块。现在：
- 带宽 `ui.WALL_PX = 13`，紧贴棋盘外沿
- 用 **SVG 描边**画（多边形外扩 `wall/2` 后描 `wall` 宽 → 覆盖范围恰好是「外沿 → 外沿+wall」）
- `z-index: 0`，低于地块的 `z-index: 2` → **永不遮挡任何建筑**

### 26.4 有建筑的地块隐去色块

`.iso-tile.built` 把地块面改成「一圈极暗的基座阴影」（radial-gradient），
再加一个 `.tile-foot` 椭圆接触阴影 —— 玩家看到的就是建筑本身，
不再是「彩色地块 + 悬浮图标」两层。

### 26.5 固定界面尺寸

视图切换（城内/城外/地图/任务…）内容高度差异很大，以前整页跟着忽长忽短。
现在：`#screen-game` 固定宽 1380px（小屏 `max-width:98vw`）、
`.view-box` **固定高度 624px + 内部滚动**，并按视口高度做两档降档；
弹窗仍是固定尺寸且 `max-height:90vh` 不越界。

### 26.6 商城：分类 + 固定网格 + 分页

73 件商品原本一次铺成一条长列表。改为顶部分类页签（带件数）、
**固定 2 列 × 8 行 = 每页 16 格**（不足则留空白格，尺寸不跳）、底部分页条。
购买后只 `renderShop()` 重绘，保留当前分类与页码。

### 26.7 出生点「全是平地」的原因

`map.generate` 会把出生点周围强制设为平原 —— **因为只有平原才能筑新城**（P2-10），
出生点若被湖泊/山地围住，玩家会陷入「无地可拓」的死局。
但原范围是 ±5（121 格），在 500×500 地图上一眼看过去「周边全是平地」，显得很假。
现收紧到 **±2（25 格）**，只保证城池脚下与紧邻一圈可用，四周立刻恢复真实地形。

### 26.8 图标：暗黑精细风

原调色板偏亮偏粉彩（墙 `#efe4c8` 近白、石 `#d3cfc4` 浅灰），在深色面板上像贴纸。改为：
- **整体压暗 2~3 档、降饱和、拉开明暗差**；只把**金/火**留作暖色高光（唯一亮点）
- 建筑 / 城外 / 地形三类「大地图主体」统一加**暗黑承台**：
  深色径向渐变底 + 暗金细描边 + 内圈压线 + 顶部冷光 → 像嵌在铜框里的浮雕
- 资源小标 / 兵种 / 材料**不套承台**，避免视觉过重
- CSS 对 `.ico` 加 `contrast(1.06) saturate(.94)` 暗场校正

### 26.9 测试

`smoke-test.js` 新增**第 30 节 43 项**：兵力归还（3）、行军（12）、
平行四边形与城墙（8）、固定界面（4）、商城（4）、出生点地形（2）、暗黑图标（6） ——
**总计 898 项**。`e2e-test.js` 新增**第 23 节 15 项**真实交互（出发/队列栏/面板/召回/主循环抵达/弹窗预估），
并把商城的 3 条断言改为「分类 → 网格 → 翻页」—— **总计 343 项**。

## 27. 体验修复十项与界面规范化（v19 · 2026-09-12）

### 27.1 升级改为纯后台过程

此前「施工中」把整座建筑锁死：点开只有进度条与取消按钮，**连募兵、研究、打造都进不去**。
玩家会以为设施废了 —— 而实际上等级只是还没生效而已。

现在 `openBuildModal` 的施工分支按 `cell.build` 是否存在区分两种情况：

| 情形 | 面板内容 |
|---|---|
| **升级**（地块上已有建筑） | 进度 + 目标等级（`Lv2 → Lv3`）+ **功能入口按钮** + 取消升级 |
| **新建**（地块还空着） | 进度 + 取消建造（没有功能可进，明确提示「需等完工」） |

功能按钮直接复用 `BLDG_FUNC`，所以军营→募兵、书院→研究、铁匠铺→打造在施工期间全部照常。
城外资源地块同理：面板显示「**当前产出（施工中不停产）**」与「完工后 LvN 产出」，
让玩家看到产量并没有停 —— 此前只写「施工中」，很容易被理解为停产。

> 附带确认了一条语义：施工期间 `buildingLevel` 仍返回**旧等级**，所以升级不会提前生效
> （不能靠升级白嫖容量），也不影响既有功能。这一条已写成断言。

### 27.2 侧栏与城池属性去重

- 资源行**去掉图标**，只用文字（图标在深色底上反而是噪点）
- 存量**取整**到个位；精确值保留在 `title` 悬停提示里
  （小数在每秒刷新的画面上一直跳，既看不清也无信息量）
- 删掉资源栏底部的「每小时（游戏时间）产量」——用户反馈数值不准，
  且与 `/秒` 增速重复表达同一件事（换算还容易出错）
- 城池属性里的**黄金存量删除**：与资源栏完全重复。但保留「🪙 税收（金/时）」——
  这是资源栏没有的、城池独有的信息

### 27.3 弹窗尺寸与格局规范化

- **会长长**（任务、商城、**将领**、**装备背包**、**史册**）：必须接分页 ——

`data-action="page"` → `ui.setPage(key, n)` → `GAME.refreshView()`。

### 27.10 教训

**删函数必须按括号配对，不能按「下一个 `};`」。**
清理死代码时用的是「定义头 + 找下一个 `};`」，遇到**单行函数**（body 与收尾同行）会
一路吃到下一个函数的收尾，曾因此误删 `U.deep/clamp/rng/now/pad`、`GAME.timeScale`、`ui.renderSide`。
本轮改用**括号配对 + 字符串/注释状态机**的删除器（`_del_fn.js` 模式），
6 个函数一次删净、零误伤，删完立刻跑测试验证。

**「改一处、忘一处」是数据驱动项目最常见的失效模式。**
它不会报错，只会静默地让改动失效。对策有两条：
① 同一份数据只允许存在一个来源（如 `GAME.UNIQUE_BUILDINGS`）；
② 关键改动必须有**运行时探针**，而不只是静态断言。

## 28. 正方形网格：一次把「倾斜投影」这条路线彻底废弃（v20 · 2026-09-12）

### 28.0 先说结论：这不是审美问题，是几何错误

用户反馈「地块全飘起来」「全是一个地块上边飘个图标」「全错位」。读代码后确认
**这不是调参能救的观感问题，而是设计错误**：

```css
.tile-art {
  left: 50%; top: 50%;
  transform: translate(-50%, -100%);   /* 底边对齐格心 */
}
.tile-art .ico { width: 62px; height: 62px; }   /* 图标 62px */
```
而地块高度只有 **48px**。也就是说 —— **每个建筑图标都比它所在的格子高，
必然向上戳出自己的格子、盖住上一格**。再叠加 `drop-shadow` 投影，
在深色底上就形成"飘起来"的观感。用户说的「全错位」是字面意义的错位。

历史包袱：v16 用 2:1 菱形（W92×H46）、v18 改用剪切平行四边形（108×48），
两代都在「把建筑立牌挂到倾斜地块上」这条路上打转 —— 只要地块是斜的、
图标是正的，就必然要算偏移量，也必然在某处对不齐。

### 28.1 解法：放弃倾斜投影，改用正方形网格

**地块就是正方形**，元素盒与地块**完全重合**：

```
地块元素尺寸 = (W, H) = (88, 88)
左上角       = (wall + col*W, wall + row*H)
格心         = 左上角 + (W/2, H/2) = 元素盒的 50%/50%
```

于是：建筑图标只要 `inset: 0` + flex 居中，就**必然**正对格心；
相邻格 x/y 各差整数倍边长，**一行不对齐另一行的情况在几何上不可能出现**。

| 此前（菱形/平行四边形） | 现在（正方形） |
|---|---|
| 格心 ≠ 元素盒中心，需手工算偏移 | 格心 = 元素盒 50%/50%，零偏移 |
| 图标高于格子 → 逐格遮挡 | 图标 ≤ 格子 → 永不出格 |
| 斜向铺排，四角留白 | 密铺，棋盘轮廓即矩形 |
| 地图菱形"跨在界面上" | 画布 span×cell 正方形 |

### 28.2 视觉依据：读了 Linear 的设计规范

用户要求「去找懂行的 skills」。搜索后安装了 **`awesome-design-md`**
（SkillHub，54 份真实产品的 DESIGN.md，纯 Markdown、无脚本、无网络行为）；
其中 Linear 那份正对本题：

> **Don't use drop shadows for elevation on dark surfaces — use background luminance stepping instead.**
> （暗色界面不要用投影表达层级，改用背景亮度分层）

> **Don't use visible/opaque borders on dark backgrounds — borders should be whisper-thin semi-transparent white.**
> （不要用不透明深色边框，应该用发丝级半透明白）

据此重做地块视觉：
- **删掉所有 `drop-shadow`**（深色底上投影几乎不可见，纯属噪声）
- 层级改用**背景亮度分层**：`.tile-face` 深底 → `.iso-tile.built` 提亮一档（弱承托）
- 凹陷感用 **inset 阴影**（规范里明确认可的 Inset 层级），不是外投影
- 边框改 `rgba(255,255,255,.06)` 发丝线，不再用 `#333741` 这类不透明深灰
- 悬停只 `brightness(1.16)` + 描边变金，**不做 translateY/scale** —— 位移正是"飘"的来源

### 28.3 名字与等级写进格子

需求「建筑的名字、等级写在图标里，不要在下边好几行」：
统一为**格内底部一行的标签条**（`<span class="nm">军营</span><span class="lv">3</span>`），
半透明底、单行、超出省略。城外地块原本还有第三行产量，一并去掉（改到点击/悬停看）。

队列栏同步去掉了剩余时间，只留一条迷你进度条 + 百分比 —— 时间在格子和面板里看。

### 28.4 地图：菱形 → 正方形俯视

`GAME.map` 整段重写。菱形（W=cell/2, H=cell/4）铺满方形画布必然四角留白 = "歪着跨在界面上"；
立牌用 `c.y - S*0.78` 定位，与菱形重心不重合 → 拾取与视觉有偏差。

现在：画布 `span×cell` 正方形、格心 `(tx*cell + cell/2, ty*cell + cell/2)`、
**拾取直接整除取格**（`floor((mx-ox)/cell)`）—— 没有三角函数，零误差。
贴角、贴边、格心任意位置都必然命中本格（已写成断言）。

### 28.5 顺手修掉的三个同类 bug：**「重绘错对象」**

三次独立出现同一个错误模式：**动作改了状态，却去重绘另一个地方**。

| 位置 | 症状 | 根因 |
|---|---|---|
| `select-train` | **点兵种毫无反应**，训练永远是最初那个兵 | 调 `GAME.refreshView()`（重绘**中央视图**），而募兵面板在**弹窗**里 |
| `train-qty` | 加减数量没反应 | 同上 |
| 弹窗内翻页 | 点了不翻页 | `ui.setPage` 同样走 `refreshView` |

对策：新增 `ui.renderTroopsModal()` 与 `ui.setModalPage()` / `ui.modalPage()`，
弹窗内的状态变更一律**重绘弹窗自身**（`ui._modalPageRender` 记录当前弹窗的重绘回调）。

> 这也解释了为什么归为「需求 4 兵营根本无法选择兵种」——
> 逻辑层 `canTrain`/`train` 一直是好的，坏的是**按钮点了没反应**。

同时把募兵数量从「渲染函数读 DOM」改为**状态驱动**（`ui._trainCount`）：
原来 `troopsHTML()` 里写 `Number($('#train-count').value)`，
既让渲染依赖 DOM、又让面板未打开时算不准时长，还无法在无 DOM 环境下测试。

## 29. 界面统一、字体层级与信息分层（v21 · 2026-09-12）

本轮五项需求表面上是"好不好看"，实测全都是**结构问题**：同一层级的东西有三套写法，
所以看起来像三个人拼的。做法不是调色，是**把唯一来源找出来**。

### 29.1 五项需求与落地

| # | 需求 | 根因 | 落地 |
|---|---|---|---|

### 29.6 本轮踩到的工具坑

1. **shell 会吞掉双引号里的 `\s`**：`python -c "...re.compile(r'color:\s*#')..."`
   实际传进去的是 `color:s*#`，于是 `findall` 返回 0、`sub` 空转，
   却"看起来执行成功了"。**含正则/反斜杠的脚本一律写成 .py 文件再跑。**
2. **jsdom 不解析 CSS 变量**：`getComputedStyle(el).fontSize` 对
   `font-size: var(--fs-h2)` 返回字面量 `"var(--fs-h2)"` 而非 `16px`。
   jsdom 不能用来验证 `var()` 的最终取值 —— 改验**CSS 结构完整性**
   （花括号平衡、规则体存在、变量全部有定义）。
3. **同一文件里 `border-color:` 会命中 `color:` 子串**：统计文字色时必须用
   负向断言 `(?<![-\w])color:`，否则数字对不上。

## 30. 点选控件、将领肖像与城池视图纯粹化（v22 · 2026-09-12）

### 30.1 三项需求

| # | 需求 | 落地 |
|---|---|---|
| 1 | 全站不用下拉框 | 9 处 `<select>` → 点选按钮组 / 点选列表；**无残留** |

| 3 | 城池界面只留城池与地块 | 头部五样信息全部下沉侧栏，中央只剩棋盘 |

### 30.2 去下拉框：换什么、怎么换

**为什么该换**：① 要两次点击（展开 + 选中）② 展开层盖住下方内容
③ 在弹窗里与外层滚动容器互相打架 ④ 选项只有 4~5 个时纯属杀鸡用牛刀。

替换映射：

| 位置 | 原控件 | 现控件 |
|---|---|---|
| 城池切换（城池一览 / 侧栏） | 下拉 | 城池名点选组（带类型 + 坐标副标） |
| 资源生产·开工率 | 下拉（5 档） | 迷你点选组 `0/25/50/75/100%` |
| 市集·交出/换入 | 2 个下拉 | 两排资源点选组 |
| 出征·主将 / 采集·带队 / 装备·将领 | 下拉 | 将领点选列表（带统率/体力副标） |
| 宝物背包 | **每个宝物各一个下拉**（一屏 N 个） | 弹窗顶部选一次「使用对象」 |
| 创建角色·城池归属 | 下拉 | 点选组 + 隐藏域 |

**关键技巧：点选后回写「同名隐藏域」**。
把 `<select id="exp-gen">` 换成 `<input type="hidden" id="exp-gen">` + 点选组，
点选时就地切高亮并把值写进隐藏域 —— 于是**所有读取端
（`getElementById('exp-gen').value`）一行都不用改**，改动面压到最小。

另外两条设计约束：
- **不重绘**：市集数量、出征兵力是同屏输入框，重绘会清空玩家刚填的数 →
  `ui.chipSet()` 只切 class + 写隐藏域，绝不调 `refreshView()`。
- **样式走令牌**：`.chips .chip` 复用金色高亮（选中 = 金底 + `--ink-on-gold` 文字）。

### 30.3 将领肖像：为什么不做「联网抓网图」

原需求是"联网检索人物网图实时适配后存储"。评估后否掉，三条硬约束：

1. **`file://` 直开时浏览器会拦截跨域请求** —— 这个项目就是双击打开的；
2. **localStorage 只有 5MB** —— 几十张 base64 直接撑爆（v15 存档膨胀就是这么炸的）；
3. 真实网图有版权与"人不对图"风险，且冷门将领根本查无图。

改为**混合双轨**：

| 来源 | 覆盖 | 实现 |
|---|---|---|
| AI 生成（28 张） | 史实名将（曹操/诸葛亮/关羽…） | `assets/portraits/hero_<pinyin>.webp` |
| 程序化 SVG | 其余全部（无限数量） | 由「性别 + 资质 + 四维」确定性生成 |

**存档只写 `portraitSeed`（一个整数）**，不存图片 —— 这是本方案能成立的关键。

程序化立绘的**可读性设计**（让玩家从脸上读信息）：
- 甲胄主色 = 四维最高项（勇武赤 / 智谋青 / 统率金 / 内政绿）
- 冠帽等级 = 资质（凡品布巾 → 良材束发 → 英杰皮冠 → 名世银冠 → 天授金冠）
- 胡须 / 发式 / 五官间距 / 脸型 = seed 决定（同资质的人也不重样）
- `mulberry32` 确定性随机 → **同一将领每次、每台机器都长同一张脸**

**两条健壮性设计**：
- 头像文件缺失时：`<img onerror>` → 就地切换到同屏预渲染的 SVG 备用图，**永不空白/裂图**；
- `ui.faceOf()` 做模块级防御：`portraits.js` 缺席时退回旧 emoji，测试与任何加载顺序下都不崩。

**图片体积**：AI 原图 28 张 1024×1024 PNG 共 **41.3MB** →
压缩为 512×512 WebP（quality 88）后 **1.30MB**（3.2%，平均 48KB/张）。
原图归档在 `assets/portraits/_raw/`，随时可重压。

原先棋盘上方堆了五样，把唯一该看的棋盘压到屏幕下半截：

### 31.2 多城：一个"只认首城"的历史包袱

```

```

地图拾取当年就是这么写的。后果不只是"点不到第二座城"——**自己攻下的城会被当作 NPC**，

```js
} else if (hit.kind === 'player') {

  if (GAME.currentCity() && GAME.currentCity().id === hit.city.id) GAME.refreshAll();
```

### 31.3 野地驻军：必须给驻军找消费点

需求里的"驻军"如果我做成"把兵放到野地上摆着"，那就是**死属性**（本项目吃过这个亏：
stamina/energy 只恢复不消耗、loyalty 只涨不落）。所以先给驻军定价值：

> 被占野地默认**每现实日 −1 级**（`decayWilds`），**有驻军的野地不再衰减**。

于是驻军的收益与代价都具体了：收益=守住等级（否则只能靠轮番占领），
代价=兵力离城（不再计入城内驻军）。落地面板里直接写出来：

```
🛡️ 驻军     1,000 名   来自 新城池
📉 等级衰减  驻军守地 · 不衰减      ← 无驻军时显示「每现实日 −1 级（派军驻守可免除）」
```

三件操作都遵守"不凭空生灭兵力"：
- 驻军：城内扣 → 野地记（兵种构成照搬，不足则整单拒绝，不会出现负库存）
- 撤军：野地 → 城池，并记明来自哪座城（`garrison.cityId`）
- **放弃：先撤驻军与采集队，再解除占领** —— 否则那一批兵会随野地一起蒸发

放弃是不可逆操作，走二次确认弹窗，并把"将失去的加成"与"会撤回多少兵"逐条列出。

### 31.7 单条教训：断言正则要匹配**拼接写法**

界面代码里的 class 常是拼出来的：

```js
'<span class="tile-badge' + (o.lvlMax ? ' max' : '') + '">'
```

于是 `/class="tile-badge"/` 永远匹配不上（引号后面紧跟着 `+`，不是 `"`）。
断言要写 `/class="tile-badge/`。凡是"断言说没有、代码里明明有"的情况，
先怀疑正则与被测文本的**拼接口**，而不是怀疑功能没实现。

> 同类前科：`border-color:` 会命中 `color:` 子串；注释里的同名词会误伤"已清理"断言。

### 32.2 征收入官府（需求 4/5）

征收此前挂在左侧「城池操作」栏，按**全境**人口换黄金。两个问题：
一是位置错（征收是官府的职能，不是侧栏统计项）；二是**只产黄金且数值失控** ——
`人口 × 民心% × 2` 在 19 万人口、90 民心的城里一次就是 35 万金，
而冷却只有 1 游戏小时（= 30 现实秒）。税收线与州郡岁贡线被它整个压掉。

重构后：

| | 普通城池（自建城） | 名城（攻占的都/州/郡/县城） |
|---|---|---|
| 征得物 | 粮 / 木 / 石 / 铁 / 金（5 大资源） | 该州**特产高阶材料** |
| 数量 | 基数 × 系数（粮 .30 / 木 .22 / 石 .16 / 铁 .10 / 金 .06） | 都城 5 · 州城 3 · 郡城 2 · 县城 1（州治在握 ×1.5） |
| 代价 | 民心 −2 | 民心 −4 |

- 基数 = `本城人口上限 × 民心%`，系数合计 0.84 —— **一次征收略少于本城 1 小时的产出**，
  定位为补充渠道而非主要来源
- 冷却**按城独立**（`city.lastLevy`），多城经营时 A 城冷却不再拖累 B 城
- 仓库满仓时按剩余容量折算，全满则拒绝且**不扣民心**（避免"仓库满了民心白扣"）
- 黄金不受仓库上限约束（与产出、岁贡口径一致）

特产的三条收集途径直接写进官府面板，因为这是最常被问到的一点：
1. **州郡岁贡** —— 每现实日自动入府，无需操作（`DATA.STATE_SPECIALTY` + `settleDailyYield`）
2. **官府征收** —— 上方按钮，冷却 1 游戏小时
3. **州治加成** —— 握有本州州城（司隶以都城为限）时，本州特产 ×1.5

### 32.4 城外地块补足 40（需求 7）

旧公式 `12 + (官府等级-1) × 3` 在 10 级得 **39**；棋盘按 8 列排，
末行只剩 7 格 —— 这就是"缺一个很奇怪"的来源。

### 32.5 每座兵营一条独立募兵队列（需求 8）

此前 `s.queues.train` 是**全城一条流水线**：所有队列一起走倒计时，先发起的先完成。

改为按军营分组：

| 军营等级 | 队列位 |
|---|---|
| Lv1–4 | 1（正在募兵） |
| Lv5–9 | 2（1 执行 + 1 等待） |
| Lv10 | 3（1 执行 + 2 等待） |

- 队列条目新增 `bIdx`（城内格子下标）作为军营归属；旧档在读档时补

  却并未开始"的情况判错 —— 渲染出来就是"正在募兵的那条显示成排队等待"。
  这个 bug 是渲染探针（把四个界面的实际输出打印出来逐字看）抓到的，
  单测当时只断言了"第二条 waiting === true"，没断言"第一条 waiting === false"，于是漏过。

**踩坑记录（本轮第二次遇到"同一逻辑写两遍"）**：第一次改动只替换了
`GAME.simulateBulk`（离线补算）里的推进循环，而在线主循环 `tickOnce` 第 7 步

现已抽成 `GAME.advanceTrainQueues(secGame)` 单一实现，两条路径共用，
并在 smoke 里加了"两处都必须调用它、且不得再有内联推进"的断言。

## 33. 城墙环、整页视图、平板适配与美术（v25 · 2026-09-12）

本轮 14 项，两条主线：**① 界面按平板尺寸重排；② 把"解释"从常驻位置全部清出去**。

### 33.1 城墙：从"紧贴窄带 + 文字牌"到"一圈带角楼的环"（需求 1）

改前是 13px 窄带**紧贴**棋盘外沿，另配一枚「🧱 城墙 Lv9 · 点击升级」文字牌。
三个毛病：贴太紧看不出是"墙"、文字牌既是备注又抢注意力、整条带子不是点击目标。

改后引入三段几何：

| 量 | 值 | 含义 |
|---|---|---|
| `WALL_GAP` | 8 | 墙内壁到棋盘外沿的**空隙**（"离建筑地块一定距离"） |
| `WALL_PX` | 18 | 墙带厚度，**同时也是点击热区厚度** |
| `WALL_PAD` | 26 | 版面相对棋盘外凸的距离 = GAP + PX |

Key point：`isoMetrics.x()` 用 `WALL_PAD` 做起始偏移，所以棋盘从 `WALL_PAD` 开始、
墙环只占 `0 → WALL_PX` —— **热区与地块在几何上不可能重叠**，不会抢走地块的点击。

环上画的是城墙该有的东西：夯土墙身（上受光下吃影）、雉堞（垛口做虚线）、
墙根落影、暗金压顶、四角**角楼**（含垛口与门洞）。全文**不含任何文字** ——
等级与操作都在点开后弹出的城墙面板里。

热区用 4 条 HTML 带（不是覆盖整块的 div）：SVG 只有描边时命中判定不稳，
而一个覆盖棋盘的 div 会把地块的点击全挡掉。

### 33.3 平板适配（需求 4）

基准改成 **1024×768**（最常见的平板横屏）。算一遍最宽的一屏：

```
1024 − 左右内边距 20 − 主区间距 8 − 侧栏 288 = 702px
城外最宽 = 8 列 × 76 + 2 × 26 = 660px  ≤ 702 ✓
```

为此地块 88 → **76**、侧栏 316 → 288、`view-box` 高度 624 → 530（并保留两档
`@media (min-height/ max-height)` 升降）。弹窗按视口收：lg 860×600、xl 960×660，
两者都带 `max-width: 94vw / max-height: 9xvh`。

**顺带把测试里写死的尺寸改成参数无关**（`TILE_W === 88` → `TILE_W === TILE_H`），
否则每按一次屏幕调尺寸就要改一遍测试 —— 这是"测试绑死在实现细节上"的典型。

## 34.1 将领经验：从"背后悄悄涨的数字"变成可操作的东西

原先经验有三处入口、四个写入点，公式 `level*level*100` 也在三处各写一遍：

| 位置 | 旧写法 | 问题 |
|---|---|---|
| `battle.js` 攻城 | `gen.exp += Math.round(npcCity.rep * 5); checkLevelUp(gen)` | 玩家看不到涨了多少 |
| `battle.js` 侦察 | `gen.exp += 30; checkLevelUp(gen)` | 同上 |
| `battle.js` 据点 | `gen.exp += …; checkLevelUp(gen)` | 同上 |
| `domain.js` 采集 | `gen.exp += Math.round(y.amount / 500) + 20; checkLevelUp(gen)` | 同上 |

现在统一为：

```js
GAME.expNeedOf = function (g) { return Math.max(1, g.level || 1) ** 2 * 100; };   // 唯一口径
GAME.battle.gainExp = function (gen, amount, why) { … };                          // 唯一入口
```

`gainExp` 负责：加经验 → 结算升级（可能连升）→ 写公文（`📗 名 经验 +N（来源） 当前 LvX a / b`）→
返回 `{gain, level, up, exp, need}` 供战报使用。战报正文新增一行：

```
经验：赵云 +1,200　Lv7（300 / 4,900）　连升 1 级！
```

**操作侧**：将领详情新增「经验」区块 —— 进度条 + `距 Lv8 还需 1,350` +
背包里经验道具的 `用 1 个` / `用到升级`（`GAME.systems.gainExpByItem(itemId, genId, mode)`）。
`用到升级` 会**够用就停**，不会一次把整叠烧掉；批量消耗走 `useItem(id, gen, {silent:true})`，
只在最后写一条汇总日志，不刷屏。

## 35.5 回合制文字战场（需求 5，本轮最大一块）

新模块 `js/tactic.js`。

| 需求原文 | 实现 |
|---|---|
| 抽象成一个网格地图 | 战场是一条**网格化的距离轴**，每回合渲染成 48 字符的条带（`T.strip`） |
| 野地 2000 / 城池 4000 | `T.FIELD = { wild: 2000, fort: 3000, city: 4000 }` |
| 回合制，速度高的兵种先行动 | 每回合把双方存活部队混排、按 `effSpd` 降序行动 |
| 移动「该兵种速度（受将领加成）」的距离 | `step = min(effSpd, gap − effRange)`；`effSpd = 兵种 spd × 科技 × (1 + 将领速度/300)` |
| 直至接触对方最前方的兵种，发动攻击 | 每个单位按"与最近敌军的间距"判断；`gap ≤ effRange` 即开火 |
| 攻击值 = 兵种基础值 + 将领/科技等加成 × 兵种数量 | `per = (t.atk + 装备攻击 × 覆盖) × (1 + 勇武×覆盖 + 科技 + 宝物 + 羁绊 + 克制 + 攻城)`，`av = per × count` |
| 杀伤 = 攻击值 ÷ 受击部队的兵种生命值 | `k = floor(av / perHp)`，`perHp = 兵种生命 × (1+补给技巧) × 将领体力 × (1 + 智谋×覆盖 + 护甲)` |
| 战斗属性均受双方将领加成 | 攻方走勇武/装备攻击，守方走智谋/体力/护甲，守将同时决定守军的攻击 |

两条为了"能打起来"必须加的规则：

1. **溢出杀伤**：一轮齐射打不完一支就顺势打下一支 ——
   不做溢出的话，前排只剩 91 人时整轮伤害只兑现 91，剩下 99% 凭空蒸发。
2. **单轮三成上限**（`T.VOLLEY_CAP = 1/3`）：没有上限时几千弓兵一轮清场，
   战斗永远只有 1 回合、条带只剩一帧，"回合制"就没有内容可看。

引擎是**确定性**的（不含 `Math.random`），所以"装备让损兵更少""体力让损兵更少"
这类对比断言能稳定成立。

**与旧引擎的关系**：`GAME.battle.simulate` 变成分派器，旧掷骰实现保留为

### 41.1 战斗数值：四处"看着有、其实没生效"

**攻城规则（tactic.js）**

### 41.8 本轮踩的坑（写法层面的教训）

1. **同一脚本跑两遍 → 函数被定义两次**。`v28d.py` 第一次在中途断言失败，修好后又整体重跑，
   于是前半段各应用一次 → `GAME.maxTrainCount` / `S.boostTrainQueue` 各出现两份。
   处置：脚本替换改成**幂等**（`count(a)==0 且 count(b)==1` 视为已应用并跳过），另做一次去重清理。
2. **e2e 的 `undefined.elapsed` 偶发**：前面若干节会把时间倍率调到 600x，
   几十个义兵几秒就跑完，队列在断言前消失。处置：这一节先**把倍率压到 1x**再募兵，
   而不是把断言改成"允许队列消失"（那就等于没测）。
3. **断言取错对象**：`shopItems()[0]` 未必在**当前渲染页**上（列表按分类+分页切片），
   点到 `null` 看起来像"买了 0 个"。处置：取页面上真实存在的 `[data-action="shop-buy"]`。
4. **`/class="gen-row/` 会命中容器 `.gen-rows`**（前缀撞车）→ 12 席被数成 13。

### 42.1 战场机动：把"速度"换算成"每回合推进多远"（需求 0a）

改前 `u.adv += u.spd`，而纵深是 2000/3000/4000、兵种速度是 100~1000 ——

"机动突袭，抓将主力"这句兵种说明在战场上根本立不住。

新增 `T.MARCH_UNIT = 2.4`：**每 1 点兵种速度 = 每回合推进 2.4 丈**。

| 兵种 | 速度 | 每回合推进 | 野地 2000 | 要塞 3000 | 城池 4000 |
|---|---|---|---|---|---|
| 轻骑兵 | 1000 | 2400 | **1 步** | 2 步 | 2 步 |
| 虎豹骑 | 850 | 2040 | **1 步** | 2 步 | 2 步 |
| 西凉铁骑 | 750 | 1800 | 2 步 | 2 步 | 3 步 |
| 铁骑兵 | 600 | 1440 | 2 步 | 3 步 | 3 步 |
| 突骑兵 | 450 | 1080 | 2 步 | 3 步 | 4 步 |
| 长枪/刀盾 | 275~300 | 660~720 | 3 步 | 5~6 步 | 6~7 步 |
| 弓箭手 | 250 | 600 | 2 步* | 4 步* | 5 步* |
| 投石车 | 100 | 240 | 2 步* | 7 步* | 11 步* |

（* 射程 1200/1600，提前开火）

### 42.2 采集效率：从"数人头"到"看采集力"（需求 0b）

每个兵种新增 `gather`：

| 兵种 | 民夫 | 义兵 | 枪/盾 | 弓 | 轻骑 | 铁骑 | 虎豹/西凉 | 大象 | 器械 | 斥候 |
|---|---|---|---|---|---|---|---|---|---|---|
| 效率 | 2 | 3 | 4 | 5 | 6 | 9 | 10 | 12 | 2 | 1 |

```
采集力 = Σ(兵种数量 × 兵种采集效率)
收成   = min(采集力, powerCap) × (1 + 野地等级 × 0.35) × 时长(小时) × (1 + 负重技巧)
```

`powerCap = 30000` 是两条约束夹出来的：
① 让 **5000 民夫（10000 采力）的收成与旧版完全一致**，不打破老玩家直觉；
② 又让高级兵种够不着上限，于是"精锐一个顶四个民夫"真的成立。
（触顶所需：民夫 15000 人 / 长枪 7500 / 铁骑 3333 / 虎豹 3000）

旧档或只记人数的采集队按民夫基准折算（`GAME.gatherPowerOf` 里有这条兜底分支）。

### 42.3 野地驻军上限（需求 0c）

`DATA.WILD_GARRISON.perLevel = 10000`，可派驻 = `野地等级 × 10000`。

**只在派驻时校验一次**。野地每现实日 −1 级，但掉级**不会**把已驻扎的军队赶回城 ——
驻军的价值恰恰是"守住这块地不掉级"，若反过来因掉级而强制撤军，
就成了"越守越少"的荒诞循环。

### 42.4 资质等级上限 + 经验曲线重规划（需求 2）

| 资质 | 凡品 | 良材 | 英杰 | 名世 | 天授 |
|---|---|---|---|---|---|
| 上限 | 60 | 100 | 140 | 180 | **240** |

**必须同时改经验曲线**，否则 240 级是一句空话 ——
原版 `等级²×100` 到 Lv240 累计要 **4.6 亿**经验，
而全游戏最大的一份经验道具（治军之道）只有 30 万，差 1500 倍。

```js
GAME.expNeedOf = function (g) {
  var lv = max(1, g.level), C = DATA.EXP_CURVE, s = C.softFrom;   // softFrom = 30
  if (lv <= s) return lv * lv * 100;                    // 与原版逐点一致
  return Math.round(s * s * 100 * (1 + (lv - s) * C.grow));   // grow = 0.006
};
```

| 等级 | 旧累计 | 新累计 |
|---|---|---|
| 30 | 94.6 万 | 94.6 万（不变） |
| 60 | 738 万 | 232 万 |
| 100 | 3384 万 | 837 万 |
| 240 | **4.64 亿** | **3181 万**（≈107 份治军之道） |

Lv ≤ 30 逐点一致，所以老存档的经验进度不受影响。

### 42.5 体力：第六维（需求 11）

```
体力上限 = 100 + (等级−1) × 资质成长点 × 1.0 × (1 + 内政 / 1000)
生命加成 = hpCap × 体力 / (体力 + hpK)        hpCap = 0.8, hpK = 800
```

用双曲而非硬上限，是为了避免"到某个等级后加成恒定"的断崖。
取值：Lv1 +8.9% → 凡品 Lv60 +16.8% → 英杰 Lv140 +32.2% → 天授 Lv240 +58%。

战斗取的是**当前体力**（`GAME.staNow`）而不是上限 ——
于是"休整 / 服止血散"第一次有了战斗意义：刚打完仗的将明显更脆。

**装备降为次要维度**：
- 装备攻击 → 并入攻击（`t.atk + eqAtk × cover`）
- 装备防御 → 并入防御（`t.def + eqDef × cover`）
- 装备生命 → 折算 `min(0.25, equipHp / 10000)` 并入生命
- `applyLevelGrowth` 不再写 `g.hp`（等级血量改由体力承担）
  —— 旧写法让"装备生命"里的大头其实是等级血量，名不副实。

### 42.6 攻防对冲（需求 11）

```
单位攻击 A = (t.atk + 装备攻击×覆盖) × (1 + 勇武×1%×覆盖) × 科技/克制/攻城
单位防御 D = (t.def + 装备防御×覆盖) × (1 + 智谋×1%×覆盖) × 护甲科技
有效攻击   = A × 2A/(A + D)
```

| 情形 | 系数 |
|---|---|
| A = D（攻防相当） | **1.00**（与旧公式同量级，基线战损不变） |
| A = 2D | 1.33 |
| A → ∞ | 2.00（封顶） |
| A → 0 | 0（下限受"至少 1 人"保护，不会绝对免伤） |

取 `2A` 而不是 `A`，就是为了让"攻防相当"这一点与旧公式**同量级**，
避免整场战斗节奏被改写。

**防御从"放大生命"改为独立一维**（`T.perDef`）：旧实现把智谋与护甲塞进 `perHp`，
于是高防部队的表现是"血条莫名很长"，与攻击力之间没有直接的制衡关系；
现在同一个属性不再被算两遍。

### 42.7 自动出征（需求 5）

`GAME.autoMarchCfg / autoMarchOnce / autoMarch / autoMarchFindTarget / autoMarchPickArmy`

参数（配置在 `state.settings.autoMarch`，界面在顶栏「自动」菜单）：
将领 / 单次兵力 / 目标类型（野地·野外城池·名城）/ 目标等级上限 / 出征类型 / 频率（现实分钟）。

**红线（写死在实现里，不进设置）**：
1. 只派**空闲**将领 —— 出征中/守将/采集中的一律跳过
2. 体力不足以支付该出征方式就不出发
3. 器械（床弩/冲车/投石车）、斥候、辎重**不编入**自动队伍
4. 只从**当前城池**取兵，不抽空别的城
5. 已占野地与今日已攻破的据点不重复打

## 45. v32：改用开源素材库 game-icons（需求「建议采用网图」）

建议采用网图」。结论：**手绘 SVG 这条路的上限已到**——用几十条矢量路径拼形状，

### 45.1 选库：4 套开源库实测对比

| 库 | 图标数 | 许可 | 30 个游戏元素命中率 |
|---|---|---|---|
| **game-icons** | 4134 | CC BY 3.0 | **30/30** |
| fluent-emoji-flat | 3174 | MIT | 21/30 |
| noto（Google） | 3800 | CC BY-SA | 21/30 |
| emojione（JoyPixels） | 1834 | CC BY 4.0 | 15/30 |

emoji 三家缺的**恰好全是游戏专属件**（枪兵 / 粮仓 / 铁匠铺 / 兵营 / 铠甲 / 头盔 /

### 45.2 画法：四种上色方案择优

对同一图标测了四种处理，最终选**光照浮雕**：
① 扁平上色（斜向渐变 + 落影）｜② 加描边（版画感）｜③ 加顶光（凸起感）｜
**④ 光照浮雕 —— `feSpecularLighting` 对形状 alpha 做真实光源计算**。

④ 是 SVG 能达到的最高质感：不是"贴颜色"，而是**用光源算高光**。
配合 game-icons 路径自带的镂空刻线，光一打就出层次。

### 45.2 官府贴图没变 —— 根因是「专属渲染器绕过了图标层」

```js
var bmSrc = GAME.icons.bitmapSrc('building', 'guanfu');   // v36 新增查询口
```

### 45.4 顺带修掉的两个测试基建缺陷（本轮真正的收获）

**① smoke 对素材层失明（v32 起，静默 4 个版本）**

`gicons.js` / `bitmaps.js` 用裸 `var GICONS = …` 声明：
浏览器 `<script>` 下是全局，但 `require()` 下是**模块局部** ——
`icons.js` 里的 `typeof GICONS` / `typeof BITMAPS` 恒为 `undefined`，
**素材层在 smoke 里从未生效**。

后果：5 条「图标长什么样」的断言其实只验到了**兜底手绘层**，
却一直当作验了最终输出 —— **测试全绿，位图层从未被验过**。

修法：两个素材层加 `window` 桥接（smoke 已把 `global.window` 指向 `global`），
并加回归门禁：
```js
check('素材层在 smoke 环境可达（否则位图/矢量素材静默失效）',
  typeof global.GICONS === 'object' && typeof global.BITMAPS === 'object' && ...);
```

**② 断言锚在「最终输出」而非「层级」**

素材层恢复可见后，那 5 条断言立刻翻红 —— 它们锚的是 `forBuilding()` 的返回值。
新增 `ICON.raw(type, id)`（跳过位图，直接取兜底层）与 `ICON.layerOf(type, id)`
（返回 `bitmap` / `vector`），把断言拆成两层各验各的：

| 断言 | 锚点 |
|---|---|
| 兜底层建筑为完整 SVG / 含渐变 / 套承台 | `ICON.raw` |
| 兜底层材料品阶珠数量=品阶 | `ICON.raw('mat_xx','')` |
| 位图层优先取到 AI 位图 | `ICON.layerOf` |
| 位图层 24 材料全覆盖 | `ICON.layerOf` |
| 位图层一律不套承台 | `ICON.get` |

### 48.1 界面主题（需求 1）—— 换肤的唯一开关

**机制**：所有结构性颜色收敛到一组 CSS 变量，换主题只换这组值；
业务 CSS 与 JS 一律不动（`ui.theme()` 只读 `state.settings.theme`，
`ui.applyTheme()` 只写 `html[data-theme]`，**JS 里没有任何色值**）。

三个 **RGB 三元组变量**解决了浅色主题的经典难题 —— 深色界面靠"半透明白"
画描边与高光，到了浅底上这些白线会**彻底隐形**：

| 变量 | 深色主题 | 浅色主题 | 作用 |
|---|---|---|---|
| `--sh-rgb` | `0,0,0` | `96,79,50` | 阴影/暗面基色 |
| `--hl-rgb` | `255,255,255` | `92,76,46` | 高光/描边基色 |
| `--gold-rgb` | `201,162,75` | `138,101,22` | 金色线条基色 |

alpha 全部保持原值 → `--line: rgba(var(--hl-rgb),.16)` 一条规则同时服务四套主题。
批量替换结果：**28 处半透明白 → 0 残留**，98 处半透明黑 → 三元组
（4 处 `drop-shadow` 保持纯黑：浅底上黑影才利落）。

**四套主题**（`DATA.THEMES` 是唯一名册）：

| 主题 | 面板底 | 实测亮度 | 定位 |
|---|---|---|---|
| 墨玉 ink（默认） | `#272c37` | 0.025 | 比 v38 整体提亮一档 |
| 素绢 silk | `#f4eedd` | 0.856 | 暖米黄浅色，**长玩首选** |
| 青竹 bamboo | `#e9f0e8` | 0.855 | 浅青灰绿，对比最低 |
| 夜阑 night | `#15181e` | 0.009 | 近黑，夜间用 |

护眼要点：浅色主题**不取纯白**（纯白反光强），正文压到中深褐；
实测素绢对比度 **10.7:1**（落在"够清楚但不刺眼"的区间）。

### 48.3 建筑分色（需求 2/3）—— 一条重要的实测结论

**`hue-rotate` 在这套素材上很弱**：AI 位图是低饱和暖金（色相 59°），
CSS 的 hue-rotate 用线性矩阵近似，**标称 128° 实测只转出 +30°**。
所以：

> 区分度的主力必须放在**明暗与鲜艳度**上，色相只能当辅助档。

落定参数与实测（截屏后逐族算色相/亮度）：

| 系列 | filter | 实测 色相/亮度 |
|---|---|---|
| gov 官署 | （不加偏色，全城色标锚点） | 43° / 76 |
| live 民居 | `saturate(1.40) brightness(1.12)` | 49° / 89 |
| store 仓廪 | `sepia(.28) saturate(.72) brightness(.84)` | 65° / 115 |
| biz 工商 | `sepia(.35) saturate(1.65) brightness(.95) hue-rotate(-24deg)` | 52° / 117 |
| road 驿传 | `sepia(.45) saturate(.50) brightness(.94) hue-rotate(58deg)` | 80° / 86 |
| mil 军事 | `sepia(.20) saturate(.20) brightness(.80) contrast(1.12)` | 72° / 116 |
| edu 文教 | `sepia(.40) saturate(.60) brightness(1.06) hue-rotate(42deg)` | 73° / 75 |

**色相 6/6 唯一、亮度极差 42**（都 ≥ 肉眼可辨阈值）。
`sepia` 先行是关键技巧：先把暖金压成单色暖褐再旋转，偏移量才可预期。

**系列归属是数据**：`DATA.BUILDINGS[id].series` + `DATA.SERIES`（7 类），
CSS 按 `ser-*` 类着色。加新建筑只需写一个 `series` 字段。

**高度随等级**（`ui.lvlScale`）：`1 + (lv-1)×0.018`，lv12 约 +20%；
配合 `transform-origin: 50% 86%` 做到**底部固定、向上长高**，
而不是整体放大（"占地"不变，只是高出的部分更多）。实测 lv1 → 1.000、lv12 → 1.198。

**城外资源四色**（老板点名的田黄/林青绿/石灰/矿棕黑）：地块色 + 图标色**双向呼应**，
实测亮度 63~99（极差 36）、鲜艳度 10~99、色相 4/4 唯一。

   插完当然还在 → 重跑就多插一份（闪黄 CSS、`.gov-img` 各插了两份）。
   正解：判据必须是**新产物里的唯一标记**在不在。
2. **同一文件分多次改却中途 `rd()` 重读**：把内存里未落盘的改动冲掉
   （「行军 tab」改动被冲掉，v37 也犯过同一个错）。正解：**每次改完立刻 `wr()`**。
3. **断言写得太弱 = 假绿**：经验道具那条只检查「main.js 里有没有 `refreshView()`」，
   而 `refreshView` 别处也有 → 漏掉了 case 里残留的 `ui.openGenDetail(...)`，
   一直到 e2e 报页面错误才发现。正解：判据要**截取所在分支的主体**再断言。

### 49.9 两个新的验证手法（可复用）

- **canvas 绘制调用插桩**：地图这类"画出来才对"的东西，静态断言只能验常量。
  在页面里包一层 `CanvasRenderingContext2D.prototype.fillText / roundRect`，
  记录参数 → 直接得到"这一帧到底画了哪些文字/多大矩形"。
  本轮据此证明：地形名 6 种全画了、等级数字画了、**「粮/木/石/铁」一次都没画**、
  地块矩形正好是 `cell−4`。
- **`file://` 下画布会被跨源污染**：地图把本地 PNG 画进 canvas 后，
  `getImageData()` 抛 `SecurityError: canvas has been tainted by cross-origin data`。
  要验像素只能走**元素截图 + pngjs**（合成器路径不受污染限制）。

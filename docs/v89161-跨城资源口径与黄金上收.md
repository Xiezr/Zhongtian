## 一、第 1 条：10 倍速下现实时间是多长？

折损周期 = **1 游戏日 = 86400 游戏秒**；游戏时间随倍速走（`ts` 游戏秒 / 现实秒）：

| 倍速 | 1 游戏日 = 现实 |
|---|---|
| 1× | **24 小时** |
| **10×** | **8640 秒 = 2.4 小时**（144 分钟） |
| 120×（默认） | 12 分钟 |
| 600× | 2 分钟 |

已把换算做成**唯一出口** `ui.rotPeriodRealText()`（读 `DATA.OVERFLOW` + `GAME.timeScale()`），
**侧栏资源悬停**与**仓库面板**都实时显示「游戏日（现实约 X @当前倍速）折损 25%」——
以后不用手算，改数据/换倍速文案自动跟。

## 三、第 5 条（本轮主体 · 中等改造）

### 3.1 花费按城：唯一收支出口 `canAffordIn / payCostIn`

| | 改前 | 改后 |
|---|---|---|
| 取值 | `s.res`（= **当前城** 的 getter） | `GAME.res(city)`（**该城**）+ `GAME.goldOf()`（玩家池） |
| 后果 | 在甲城界面升/建乙城的建筑 → 用**甲城的货**付款（跨城挪用，无声无息） | 报「本城资源不足（跨城需走「本境调运」）」；货分毫不动 |
| 出口 | `canAfford / payCost`（隐含当前城） | 新增 `canAffordIn(city, cost)` / `payCostIn(city, cost)`；旧两个**退化为当前城薄转发**（募兵/科技/门派等当前城语境不受影响） |
| 改的路径 | — | `buildAt` · `upgradeAt` · `buildExt` · `upgradeExt` · `convertExt` · 募兵（自动升级遍历所有城时因此天然按城结算） |

### 3.2 黄金上收玩家层级（唯一存储 `s.gold`）

- **各城 `res.gold` = 同一口池子的访问器**（`GAME.goldBind`，`enumerable: true` 保证遍历仍看得见）。
  为什么用访问器：全仓 ~100 处读写 `res.gold`（市场/俸禄/缴获/治疗/提速/神器/爵位…），
  逐处改**必漏**——漏掉那一处就是"某条路仍按城扣款"的静默错账。
- **老档迁移**（`GAME.migrateGoldPool` · 幂等）：各城 `res.gold` **相加**入池（总量不变，只是从此通用）；
  新档以 `st.gold` 为权威（各城那份只是冗余副本，**不累加**，否则 × 城数）。
- **新城自带金**（开局库存 / 攻占缴获）经 `GAME.registerCity` **并进池子**（三个入库点全部收口）。
- **运维口**：`GAME.goldOf()` / `GAME.goldAdd(n)`（金收支唯一出口）。
- 回来报告的资源快照原本按城累加金 → 改读池子（否则报告里的金会是 × 城数）。

### 3.3 返还进该城（改前还给"当前城"）

- `GAME.refundCert(cost, ratio, city)` 新增城参；拆除（城内 `demolishAt` / 城外 `demolishExt`）传该城；
- **取消建造**按**队列项所属城**返还（改前：在甲城取消乙城的工程，材料还到甲城）。金例外 → 进玩家池。

### 3.4 运输清单去金

`GAME.TRANSPORT_KEYS` = `DATA.RES_ORDER` **去金** —— 金全境通用，运金 = 从池子搬到池子
（途中还要白掉一截损耗，改前正是这样静默漏账）。出征界面辎重区因此自动少一行（粮木石铁四行）。

### 3.5 界面出口

- 资源栏金行悬停：**「黄金：全境通用（各城共用这一口池子 —— 任何城池的建造 / 募兵 / 花销都从这里扣）·
  货币，不受仓储上限约束；无需运输。」**
- 费用悬停（**含金时**才出现）：`（金：全境通用 · 粮木石铁：按本城结算）`。

## 五、诚实缺口 / 待老板定夺

1. **"金全境通用"意味着金不再有城池边界** —— 战报/岁贡/俸禄里的金都进同一口池子；
   若您希望"某类金"仍按城记（如缴获暂存该城），需要给金再分账（本轮**没做**，按您的原话收成一口）。
2. **老档迁移是"各城相加"** —— 若某座城原本是"靠运输养着"的穷城，迁移后它的金被并入公共池
   （总量不变，但该城的"账面"看起来变富了）。**备份 `backup/v89161/` 可回滚。**
3. **运输损耗**：金不再运输，所以"运金损耗"这条路彻底消失（粮木石铁的损耗口径未动）。
4. **UI 未做**：没有"金从哪座城来的"这类明细（金是唯一池，天然没有明细）；
   若您想看"本期金收支流水"，那是一个新面板（可另立一轮）。
5. 上轮遗留（**未动**）：折损 `maxPeriods` 保留 ✓、遍历序保留 ✓（本轮按您第 2/4 条确认）。

## 三、核心机制

**野地**：加成是**每级线性**（平原/草原粮 +3%，沼泽 +5%，**湖泊 +8%/级 → 10 级 = +80%**，
森林木 +5%，荒漠石 +5%，山地铁 +5%），统一 `GAME.wildAddOf(type, level)`。
采集 = `basePerHour × (1+等级×0.35) × 有效兵力(≤5000) × 时长`，**不足 1 游戏小时收益为零并重置计时**，
24h 封顶；**将领等级只影响宝物概率，不影响资源**。
**铁律「掠夺得资源，占领得地盘」**（`wildResMul = {scout:.15, raid:1.2, occupy:0}`）。
等级动态：无主 +1/日（≤10）、被占 −1/日；**有驻军不衰减**；取用 `wildLevelNow(x,y)`。
派驻上限 = 等级 × 1 万，**只在派驻时校验**。

**材料**：6 系 × 4 品阶 = 24 种；`FORGE.matBySlot` 存**系列名**，品质→品阶由 `DATA.MAT_OF` 解析；
落点 野地/野城→一阶、县郡→二阶、州→三阶、都→四阶（高阶必须打城）；
州特产 `STATE_SPECIALTY`（13 州，司隶=陨铁四阶，覆盖六系）、州治 ×1.5、
`CITY_YIELD` 岁贡（锚现实日，首日只登记不发放，离线封顶 30 天）。

**出征**：唯一入口 `battle.expedition(target, mode, army, genId)`；target `{wild|fort|city}`；
调难度只改 `garrisonMul` / `woundedRate`。行军队列 `GAME.march`（`marchBaseSpeed=300`，10 格≈5 现实秒，
**离线必须 `rushAll()` 结清**）；**出征的兵必须回城**（`returnArmy`：幸存者分兵种回城、阵亡折算伤兵）。

**野外城池**：密度 1/12、位置 hash **不入档**、已攻取记 `state.fortsRazed['x,y']`、等级 1~8 按现实日变化。
外城地块**按城独立**（`city.extGrid` + `GAME.extGridOf(city)`，上限 `12+(本城官府−1)×3`）；
**多城时地块下标会重复** → `cancelBuild`/`buildProgress` 必须同时匹配 `q.cityId`。

**战斗**：两引擎（`tactic` 回合制 / `simulateDice` 旧）返回字段一致且**确定性**（无 Math.random ——
这是"装备/体力让损兵更少"这类对比断言成立的前提）；`FIELD={wild:2000, fort:3000, city:4000}`；
**必须有溢出杀伤**（打完一支顺延下一支）；**v43 已删除「单轮齐射上限」**
（原 `T.VOLLEY_CAP` + `T.CRAFT_CAP_BOOST`）—— 它按**人头**压制杀伤，造成"兵力越少越耐打"
（240 人守军能磨 2000 铁骑 14 回合：80→54→36→24 指数衰减），且天然偏袒人多的一方，
会破坏兵种平衡；多回合改由**推进阶段 + 自然杀伤**决定（碾压 2 回合胜、对等仍拉锯 4~5 回合）。
攻防对冲 `clashFactor = 2A/(A+D)`（相当=1.00，纯攻≤2.00）；
攻城器械 ×2.2 + 城头火力 + 守城方全军固守；**体力第六维**（加成 `0.8×sta/(sta+800)`，战斗取**当前体力**）。
兵种阶梯判据：`atk/pop` 与 `hp×(1+def/100)/pop` 双双 ≥ 长枪兵基准 (150/750)。
**改战斗数值前先确认：没有任何「按人头比例压制杀伤」的机制残留。**

**将领**：五档资质（权重 50/27/15/6/2，成长 +1/+2/+3/+5/+8，价格 ×1/1.8/3.2/7/16，
等级上限 60/100/140/180/240）；**等级上限与经验曲线是一对**（`GEN_RANKS[].lvCap` ↔ `EXP_CURVE`，
改一个必查另一个）；升级走 `GAME.applyLevelGrowth()`；五维（统率/勇武/智谋/内政/速度）唯一
定义处 `ui.GEN_DIMS`；经验 `GAME.expNeedOf` + `battle.gainExp`；
**`perm` 只是"每将上限 50"的计数器，不参与属性求和**。

**建筑生产**：`MAX_BLEVEL=12`；升级是**纯后台过程**（施工期功能照常可用，`buildingLevel` 返回旧等级）；
官府固定 4 格（右侧中部）不可移动；仓库储量 = **各仓等级之和** × 200 万；黄金**不受仓库上限**；
募兵队列按 `queue.bIdx` 归属具体军营；队列只有一条数组 `s.queues.train`，靠 `kind`（train/craft）分组，
`trainQueueKey` 必须含 kind。

**任务**：指标驱动（只声明 `metric + goal` → `GAME.questMetric()`），**加任务 = 加数据**；
成长型 50 条 + 随机型 36 条（7 类）；随机任务每日 5 项、同时在手上限 5 项；
「天」锚定现实日（游戏内 1 日仅 1.33 现实秒，无法做周期）；进度用增量（base 快照）。


## 八、界面与玩法约定（按版本沉淀）

- **悬停浮层全站唯一一层**：内容源留原地（`.tip-src` 显隐，**必须显式 `display:none`**），
  显示统一交给 body 末尾 `#tip-layer`（fixed + z-index 9000）；位置纯函数算（下方→翻上方→夹进视口）；
  事件委托驱动（每秒重绘也不失效），滚动/改尺寸立即收起。
- **装备与套装**：门槛统一 **3/5/7/11**（累计生效），三套各 12 件使四档全可达；
  套装件 = 同品质散件 ×1.12；进度唯一口径 `GAME.setProgressOf`。
- **主题化**：唯一开关 `html[data-theme]`；结构色全走 CSS 变量 + 三个 RGB 三元组
  （`--sh-rgb` / `--hl-rgb` / `--gold-rgb`）让半透明阴影与描边整体换向；
  **JS 里不允许出现色值**；新增主题 = `DATA.THEMES` 加一项 + index.html 加一块 CSS 覆盖。
- **地块底色必须用纯色**：逐格渐变会出现色阶接缝，铺成一片后比花纹还扎眼。
- **建筑系列是数据**：`DATA.BUILDINGS[id].series` + `DATA.SERIES`（7 类），CSS 按 `ser-*` 着色；
  等级 → 高度走 `ui.lvlScale()` + `transform-origin: 50% 86%`。
- **地图**：`blitArt(ctx,key,cx,cy,size)` 位图优先、矢量兜底；key = `terrain_*` + `fort` + `city_*`。
  **平地不放图形**（`TERRAIN_TINT.plain` 浅青绿**不透明**底）；其余野地画「地形名（渐隐底衬）+
  右上角等级」，等级 0 也要画。v42：地块改 **2.5D**（方格顶面 + 侧壁暗土色 + 顶棱亮线），
  `TILE_GAP=1`；城外靠 `.iso-board.ext-board .tile-face{inset:1px}`，城内不留缝。
- **地图素材必须是「俯视正方形铺满」，不能用等距菱形**（v44 老板："别菱形横放了"）。
  地块早在 v42 就是正方形，但素材错了照样显得"横放"。
  **判据可程序化**：不透明区四角 α≈0 ＋ 外接盒实心≈0.5 = 菱形；四角 α≈1 ＋ 实心≈1 = 方形。
  prompt 三条：`completely fills its own square cell edge to edge` ·
  `NO isometric / NO diamond / NO perspective / NO side walls — pure overhead top-down` ·
  `cells separated by a thin clean white line`（**必须加**，否则四格连片没法切）。
  切分：象限 + 四边内缩 2%（切掉白线），**不抠底**。旧菱形素材备份在 `assets/icons/ui/_old_iso/`。
- **地图导航条是「一行」+ 水平居中**（v44 一行 / v45 居中）：方向键横排 `◀ ▲ ▼ ▶` ＋
  视野区间 ＋ 点选坐标 ＋ 坐标输入 ＋ 前往/回主城/洛阳，全部同一行。
  **方向键步长 = 一屏**：`ui.MAP_STEP_X = 12`（左右）、`ui.MAP_STEP_Y = 8`（上下）——
  正好等于基础观察框 12×8，点一下翻一屏、不会跳过内容。
  点选坐标走 `GAME.map.pick()` → `ui.mapPick` → `ui.syncMapInfo()`；
  **画布里不要再画一份坐标**（与状态行重复）。
- **地图野地的高低差 = 按地形分档抬升 + 贴图铺满顶面**（v45 老板："野地稍微搞点 2.5D""上边的贴图可太丑了"）：
  `ELEV_FRAC = {hill:.34, forest:.26, zhaoze:.17, caoyuan:.12, desert:.10, lake:.07, city:.06, plain:.05}`，
  `elevFor(terrain)` 取整（下限 3px）。**侧壁仍只在格内** → pick 的整除取格一字不改、
  前后排不会互相遮挡。三个取位函数 `topRect/topCY/topBottom` **都必须带 `el` 参数**，
  `at(gx,gy,fn)` 把本格 el 交给回调（⑤⑥⑦三块画格内东西的地方全靠它，否则错位）。
  **地形贴图铺满整个顶面**（`blitArtRect` 矩形铺图 + 按地块圆角 `clip`），`TILE_GAP = 4`
  露出的缝与侧壁才是"地形色"的可见处。**顶棱亮线与顶面描边抽成 `edgeOf(c, el)` 并放在贴图之后画**
  —— 画在基础层会被铺满的贴图整片盖掉，而 2.5D 的立体感主要就靠那道受光的上棱。
  贴图素材换成"材质样本"画法（俯视、无透视、无立起来轮廓），旧图备份 `_old_terra/`。
- **顶面几何只有一个取值口 `topBox()`**（v47 老板："地图的贴图位置不太正"）：
  `topRect`（路径）、侧壁、地形贴图、`topCY`、`topBottom`、顶棱亮线**全部由它派生**。
  v47 改前的病根就是这段几何被抄了三遍：贴图那份写成 `cell−el−2TG`（顶面是 `cell−el−TG`）
  → 贴图**顶上对齐、下边缺 4px** 露出一条地形底色；`topCY` 又漏减 TG → 图标相对贴图**偏下 TG/2**。
  注意 `h` 只减**一个** g 是**有意的**：下边紧接的是自己那格的侧壁，要连成一体；
  "相邻两格的纵向缝"由「侧壁底 − 下一格顶面上沿」给出 = 2×TG，与横向一致。
  诊断手法见「验证手法 · canvas 绘制调用插桩」。
- **地形贴图走 cover 而不是拉伸**（v47）：顶面高 = `cell − el`，山地（el=cell×0.34）
  的顶面只有 66% 高，直接拉伸会把岩石纹理**纵向压扁 34%** —— 这也被读成"贴图没铺正"。
  `blitArtRect` 用 9 参数 `drawImage` + `k = max(w/srcW, h/srcH)` 只裁不缩；
  实测最终只用素材中心 21%×14~21% 的区域（顺带把 AI 图最易畸形的最外圈裁掉）。
- **减少格子感的四条（v49，老板从参考图里点名）**：① **每格先铺满该地形的土色基底**
  （`soilOf(tint, 0.70)`）—— 缝里露的是邻格土色，而不是画布底那个深色空洞（`#3b3423`），这是主力；
  ② 侧壁改**渐变**（上接基底色 → 下端 0.34），不再是一块纯色；③ 顶棱亮线透明度调淡
  （0.18+0.28 → 0.12+0.20，原来每格顶边一条白线 = 给格子描框）；④ `TILE_GAP` 收到 2（缝 4px）。
  验收指标：**缝线落差 = 缝中心亮度 ÷ 格内亮度**（越接近 100% 越看不出格子）——
  实测 60.3% → 71.0%（参考图 101.9%）。代价：满格土色基底面积大，会把地图整体饱和度拉低约 6 个点。
- **cover 的源取用范围要 sweep 定**（v49）：`USE=0.45` 是实测最优档
  （写实素材铺到格子后 caoyuan 16.5 vs 全用素材 11.0；再小则森林树冠变成大色块）。
  加一层 `maxSide = min(c.width, c.height) * USE` 的裁剪上限即可。
- **地形贴图素材必须做平场校正**（v47）：AI 生成的"材质样本"自带**中心聚光斑** ——
  实测边缘亮度只有中心的 **48%~81%**，且到 40% 深度都没升到 95%。
  铺满格子后每格就是"中心亮一圈暗"，正是"一张小图摆在格子中间"的观感来源。
  做法见 `fix_terra_flatfield.py`：低频亮度场（模糊半径 12%）+ 目标取 **97 分位** +
  `gain = clip(T/L, 1, 2.6)` 只提亮不压暗 + gain 场再模糊避免圈状接缝；
  边缘亮度提到 **79~98%**。原图备份 `assets/icons/ui/_old_terra_v46/`，带 `restore`。
- **地形底色判据：两族要"分得开"，需在 色相≥25° / 明度≥15% / 饱和度≥20% 里有一维达标**。
  v45 改前有 **5 组三维全不达标**（草原/沼泽 9°/8%/12%、草原/森林 23°/13%/9%、
  沼泽/森林 14°/5%/3%、荒漠/城池 5°/14%/18%、山地/城池 3°/3%/17%）=「绿族三兄弟 + 土族三兄弟」。
  **只查色相是不够的**：荒漠与山地是**同色相**（43°/44°），靠饱和度分（73% vs 10%）。
  smoke 有断言按此判据从源码读真值两两校验。
- **将领界面一屏到底**：`ui.generalsHTML()` → `.gen-split`（左 `.gen-list` 清单 / 右 `.gen-pane`
  全部档案含内嵌人形装备栏）；**不再有** `openGenDetail` / `openGenEquip` 弹窗；
  **规则型文案不进页面**。
- **顶栏徽标 = 待办**（任务可领取），**状态类不挂徽标**（行军队列数已撤）。
  公文闪黄：`state.repUnread>0` → `.tab[data-view="reports"].fresh` →
  `animation: docBlink 1.5s infinite`（**同时动底色与图标色**，否则暗色主题里浅图标压黄底糊成一片）；
  进公文页清零；旧档缺字段在 `loadGame` 补 0。
- **补丁式改 UI 的三条硬度要求**：整块替换 CSS 前**先盘点旧块选择器集合**（漏掉仍被需要的规则
  → 曾致位图回退固有 1024px 把槽位撑到 1090px）；**图标容器一律写 `.ico` 类禁止写标签名**
  （`.ia-art svg` 匹配不到位图 `<img>`）；**定位"样式没生效"要遍历 `document.styleSheets` CSSOM +
  `getComputedStyle`** —— 源码里规则写得对，不代表解析后还在（语法错会被整条丢弃）。

## 六、踩坑

**改代码**
- **⚠ CSS 覆盖陷阱（v46 抓出两处长期隐性 bug）**：项目里有一条「共享卡片几何」
  `.q-card, .item-row, .eq-cell, .bag-cell, … { padding: var(--sp-4) /* 10px */; border-radius: var(--r-lg) }`，
  它**与后写的 `.doll-slot` 同权重 (0,1,0) 且更靠后** → 槽位的 `padding: 2px` 被静默改成 10px
  （实测槽内三行只剩 32px 可用）。**修法：选择器提到 `.doll-slot.eq-cell` (0,2,0)**。
  同类的还有 `.eq-inv` 角标：全站只有一条 `right/bottom` 规则却**从来没有 `position: absolute`**，
  于是它一直当流内元素占掉一整行（多撑 18px）。**教训：看到"尺寸不对"先查同权重更靠后的组合规则。**
- **flex 列 + 内容超高 → 子项会被压到 0 高且不报错**：`overflow: hidden` 让 flex 子项的
  `min-height: auto` 解析为 0，于是文字元素被压没（症状是"文字突然不见了"，不是溢出）。
  所以给固定尺寸的 flex 容器算高度时，**必须把边框 + padding + gap 一起算进去**。
- 删函数**必须按花括号配对**定位，绝不能用「找下一个 `};`」（单行函数没有独立收尾，
  曾误删 8 个函数，**项目无 git 只能手工重建**）；删完立刻跑测试。
- `str.replace(a,b)` 里 b 的 `$$` 会被转义 → 含 `$$()` 的替换串用 `replace(a, () => b)`。
- **`node -e "长串"` 打补丁会静默失败**（shell 吃引号/`$`/反引号）→ 一律写 `.js`/`.py` 文件再执行。
- **脚本必须幂等**，且**插入型补丁的守卫要盯「插入物」而非「锚点」**（已踩 4 次）。
- 大批量改造用**函数级 span 替换**（按 `ui.fn = function` 定位 + 花括号配对），比整块字符串匹配稳。

**写测试**
- 断言失败往往**不是功能坏了，而是没隔离环境**（随机 / 天气 / 奇遇 / 地图种子 / 赛季）——
  对策依次：`withFixedRandom`、钉 `weather='clear'`、`encounterRoll=()=>null`、
  "附近必有据点"改螺旋搜索、显式设置时段。
- **CSS 判据一定先剥注释**（注释里写规则原文会被整文件正则命中 → 假红）。
- **禁止恒真断言**；行为断言要**能翻转**才算验证。`class` 是拼出来的 → 断言写 `/class="tile-badge/`。
- 断言要"确定化"不要"放宽"（队列会跑完就压到 1× 倍率，别改成"允许消失"）；
  `G.newGame()` 会替换 state → 用 `withFreshState` 包裹。
- **世界状态也要断言**：只验证返回对象会漏掉「出征的兵没回来」这类致命 bug。
- 偶发失败：跑 20~30 次收集失败断言名，再写复现脚本打印现场。

**工具**
- `audit.js --strict` 在孤儿按钮/重复定义时退出码 1，可挂提交前检查；改控件后**必须重跑 audit**。
- audit 的六类误报**修工具，不要为迁就工具改业务代码**。
- jsdom **不解析 CSS 变量** → 验 CSS 只能验结构完整性（花括号平衡/规则体存在/变量有定义）。
- canvas 测试桩**两处都要覆盖**（smoke `makeEl().getContext` / e2e `makeCtx`）：
  `ellipse / quadraticCurveTo / createPattern / roundRect / save / restore / clip / rect /
  setLineDash / createLinearGradient`。

## 七、验证手法（模型读不了图时，这章是唯一的眼睛）

- **几何验证优先于像素验证**：`getBoundingClientRect()` 能证伪（路径越界 = 被裁切）；
  `getBBox()` 不含自身 transform、`svg.getBBox()` 被装饰层撑满 —— 两样都不可用。
  像素统计只作辅助，且**必须排除承台/背景**，否则暖土渐变本身贡献几千种颜色 → **假绿**（v32 事故）。
- **canvas 绘制调用插桩**（包 `fillText`/`roundRect` 记参数）→ 直接断言"这一帧画了什么"。
  **v47 用它定位过地图贴图错位**：canvas 里的东西 DOM 查不到、截图只能看颜色看不出边界，
  唯一能拿到精确绘制参数的办法就是包一层原型：
  ```js
  await p.addInitScript(() => {                       // 必须在页面脚本执行**前**装
    window.__LOG = [];
    const P = CanvasRenderingContext2D.prototype;
    ['rect','roundRect','drawImage','fillRect','fill'].forEach(n => {
      const o = P[n]; if (!o) return;
      P[n] = function (...a) { window.__LOG.push({op:n, a}); return o.apply(this, a); };
    });
  });
  // 触发一次渲染前先清空日志（setView 会自动渲染一次，不清空两批数据混在一起没法配对）
  window.__LOG.length = 0; GAME.ui.renderMapCanvas();
  ```
  于是「侧壁 `(4,71,77,10)` / 顶面 `(4,4,77,67)` / 贴图 `h=63`」一目了然 ——
  贴图比顶面矮 4px，且**只在下边缺**，问题定位结束。
- **插桩配对的判据要按"位置/键"，不能按索引步长**（v47 假红）：
  同一格里 `roundRect` 会出现 **4 条**（侧壁 / 顶面 / 贴图 clip / 描边），
  而不铺贴图的格只有 3 条 → 按 `i += 2` 取"顶面条目"，走几格后就整体错位一位，
  报出"左右差 85px"这种肉眼不可能出现的错。
  正确做法：按 `x + y` 在日志里 `find` 对应的顶面。
- **断言查"结构证据"而不是"字面串"**：v47 改结构后，锚在旧表达式上的断言集体假红
  （`/cell - g \* 2, cell - el - g/` 在对象写法里多了 `h: ` 就不匹配了）。
  这类"唯一来源"的正确判据是**都引用了同一个函数**（`topBox(`），再加一条数值对拍。
- **要"参考某张图"时，先把图变成我能读的数字**（v48）：当前模型没有视觉输入，
  只能靠量化特征反推。做过的五组指标（脚本 `read_ref_*.py` 已随过程产物在 v67 清理，方法本身记在这里，需要时照这段重写）：
  ① 低分辨率亮度/色相矩阵（46×22）→ 用字符"看"布局，判断哪块是 UI、哪块是地图
  ② 四方向边缘强度 → 斜向/轴向比值 >1.25 才说明有等距菱形结构
  ③ 自相关峰值 → 平铺周期（**顺便推每格多少 px**，这是后面缩放对齐的基准）
  ④ 规则暗谷检测 → **有没有格子缝**（间距杂乱 = 没有规则网格）
  ⑤ 主色直方图 + 局部对比度 + 分区（3×3）指标
  ⚠️ **比较前必须归一化到"每格相同像素"** —— 相邻像素差这类指标完全取决于显示缩放比，
  直接拿 611px 的图和 1366px 的图比是错的（会得出"人家细节好 3 倍"的假结论）。
- ** 这个指标会把"噪点"当成"细节"**（v48 踩坑）：
  用它当优化目标去给素材加噪声，结果是噪声频率越高分值越大（基准 20px → 11.7，
  240px → 2.1），一路加到 ±250% 调制才勉强达标 —— 那时素材已经变成噪点图了。
  **它只能用来"诊断差距"，不能用来"优化美术"**。真实的美术质感差异
  （写实颗粒 vs 平滑渐变）**靠图像后处理补不出来**，只能换素材或重新生成。
- **素材"照明不均"的诊断法**（v47）：把图转灰度，沿四条边取 `0~1%, 1~2%, …` 的条带均值，
  除以中心区均值 → 得到**边缘亮度剖面**。边缘只有中心 48%~81% 且 40% 深度仍未到 95%
  = 中心聚光斑（不是 vignette），铺满格子会读成"小图没铺满"。
- **临时换文件出对照图必须能自证还原**（v47）：把 `js/map.js` 与贴图临时换回旧版截图，
  用 `try/finally` + **逐文件 md5 校验**，输出"✅ 全部与出图前逐字节一致"才算完。
  没有这层校验，很容易把项目留在半改状态。
- `file://` 下画布被跨源污染 → `getImageData` 抛 `SecurityError`，像素验证走**元素截图 + pngjs**。
- **`canvas.drawImage` 不吃 CSS filter** → 测滤镜必须元素截屏 + pngjs。
- 分色量化判据：亮度极差 / 鲜艳度 / 色相唯一数。
- **测渲染色时必须「白底隔离 + 剔除背景像素」**（v45 事故）：
  `elementHandle.screenshot()` 会把图标透明处**透出的地块底色**一起截进来 ——
  绿色的 `--ground` 会把色相拉走、饱和度稀释，据此得出的数字是假的（曾据此错判一次）。
  正确做法：地块底改纯白、只统计"明显不是白底"的像素、图片 URL 加时间戳绕开 `file://` 缓存。
  另注意两个**不同统计量**：`逐像素S求均值`（素材真实饱和度）≠ `均值色的S`（天然偏低，因平均会拉向灰）。
- **`page.screenshot({clip})` 的高度超过视口时会被静默截断**（v45 两次踩）：
  脚本自己算出的 `info.h = 1250`、viewport 只有 1200 → 存出来就是 1200，
  最后一行内容被裁掉而**没有任何报错**。**做法：viewport 开得比预期的图更高，
  并在截图后用 PIL 复核文件尺寸 == 脚本报的尺寸**。
- **布局类断言（尺寸/重叠/溢出）jsdom 一律测不出来**（无布局引擎，高度恒 0）→
  必须真浏览器量盒子。且**判据要用"算出来的数"**：槽位重叠要按 CSS 里的真实盒尺寸 +
  落点表逐对判矩形相交；只查"落点在 0~100% 内且坐标唯一"是**假绿**（v46 就是这样放过了一个
  head 压 neck 的重叠）。同一招用在 css 断言里也行：从 CSS 读出 `max-width / aspect-ratio /
  slot 宽高 / padding` 现算，改错一处就红。
- **`scrollHeight > clientHeight` 不能用来判"文字被裁"**（v46 假报警，12 个槽位全红）：
  `line-height: 1` 的中文字形 ink box 本来就比行盒高（实测 13 对 11）。
  正确判据：把**流内**子元素高度 + `row-gap` 求和，与「clientHeight − 上下 padding」比
  （绝对定位的角标要排除，它本来就设计成压在边框外）。
- **`page.evaluate` 的参数必须是可序列化的纯数据** —— 传函数直接抛
  `Attempting to serialize unexpected value`。函数（如 hsl 换算）在 Node 侧算好再传进去。
- **视觉类任务（裁切 / 构图 / 配色）不能只靠单一程序指标**：
  ① 先跑诊断表看数据分布 ② 用**强先验**约束算法（而不是找"最显著"的东西）
  ③ 产出**对照拼图**交人眼验收（模型读不了图，就必须让用户看）。
- 批量改素材先建**画廊**（一张图排开上百个）。
- **`smoke-test.js` 可自带 PNG 解码做素材级断言**（v45，强烈推荐）：
  `zlib.inflateSync` 解 IDAT + 逐行反滤波（filter 0~4），即得像素。用于断言
  "图标到底什么颜色"这类 **CSS 正则断言根本挡不住**的回归（本项目已为此返工四轮）。
- ~~CSS filter 配色标定法~~ —— **已作废，不要再走**。它能把色距收敛到很好看，
  但**结论本身是错的**：CSS 滤镜的数学性质决定了它做不出饱和、可辨的色相
  （详见第四章配色条目）。染色请直接改素材像素。

## 九、地图改为菱形等距（v50）

老板原话：「**地块侧向菱形分布，不只是地块里的贴图**」—— 澄清了两种理解的区别：
改的是**整张网格的排布**（让每块地在屏幕上就是菱形、斜向错开密铺），
不是把正方形贴图裁成菱形再摆成方格。

### 坐标与几何

```
屏幕 x = ox + (gx − gy) · HW          HW = cell / 2      菱形半宽
屏幕 y = oy + (gx + gy) · HH          HH = cell / 4      菱形半高（2:1 等距）
反投影：a = (mx−ox)/HW, b = (my−oy)/HH
        gx = round((a+b)/2),  gy = round((b−a)/2)
```
`vx/vy` 由「视口左上角格」改为**视野中心格**（菱形视野是斜的，没有"左上角"），
`ox/oy` 让中心格落在画布正中。观察框 12×6 格距（画布 1248×624@cell104）。

### 唯一的几何来源（这次是硬约束）

| 函数 | 职责 |
|---|---|
| `gxy(gx,gy)` | 格心 —— 唯一坐标出口 |
| `diaPath(gx,gy,el,k)` | 顶面菱形路径（k 为内外偏移，纵向按 1:2 跟着缩） |
| `diaBox(gx,gy,el,k)` | 菱形外接矩形 —— 贴图/名带/角标的定位框 |
| `sideSides(gx,gy,el)` | 侧壁两个面（左下/右下） |

**v16/v18 两次在斜投影上翻车，根因不是"斜"，而是同一份几何被抄到六七处**：
"图标要立正"就得反向补偿偏移量，补偿量散落各处，改一处漏一处。
所以这次所有绘制只准引用这四个函数 —— smoke 里有断言查"绘制侧不许再出现裸 `cell/2` 定位"。

### ⛔ 最容易再犯的一条：菱形密铺没有垂直空隙

**本格的下尖角与南邻的上尖角是同一个点**。所以：

- 顶面**不能**向上平移 el（会压到北邻格）
- 侧壁厚度**必须 ≤ 缝宽 `IN`**（抬升只能是 1.2~5px 的绝对像素，不能按 cell 比例）
- 几何依据：格 A 侧壁顶点 `(cx−HW, cy−el)` 所在竖线 `x = cx−HW` 正是北邻格 B 的中心 x，
  B 在该处的 y 范围是 `[cy−2·HH, cy]` —— 只要 `el < 2·HH`，A 的侧壁就落在 B 的菱形内

首版正是这么错的（顶面上浮 el + 侧壁 35px），老板反馈「**地块都叠在一起了**」。
实测侵入量（北邻格菱形内部相对其格心的亮度差）：**−28.0 → −3.8**。

> **厚度感的唯一出路**：画在顶面**内部** —— 沿下方两条边压一道 AO 渐变。
> 不占空间就不会被邻居挡住。任何"真的往外加厚"的方案都必然重叠。

### 城池要显成菱形，不能只靠图标

城池格不铺地形贴图，原来只有一个 ≈90px 的图标 —— 比 104×52 的菱形还高，
把地块整个盖住，读起来就是"这块地还是正方形"。修法两条：
① 图标收到菱形外接框的 95%（≈49px）；② 给城池格描一圈**菱形边**。

### 城池/据点图标：正交俯视 → 2:1 等距

素材实测是 **1024×1024 全不透明方形满构图**（填充率 1.00、四角占用 1.00、上缘剖面全 100），
且强边缘集中在 0°/90° 两桶、上下半部亮度一致 → **正交俯视平面图**。
对这类输入，「俯视 → 2:1 等距」的精确变换是**绕中心旋转 45° + 纵向压缩 0.5**。

```js
// blitArtIso：s = spanW / √2（旋转 45° 后正方形外接宽 = s·√2）
ctx.translate(cx, cy);
ctx.scale(1, 0.5);          // ⚠️ 必须先 scale
ctx.rotate(Math.PI / 4);    // ⚠️ 再 rotate
ctx.drawImage(c, -s / 2, -s / 2, s, s);
```

> ⚠️ **顺序不能反**。canvas 的变换是**矩阵右乘**（后调用的先作用在点上）：
> `translate → rotate → scale` = `T·R·S` = **先压缩再旋转** → 正方形四角落到
> `(±0.177, ∓0.530)·s`，是一个**歪的平行四边形**。肉眼看着"也像菱形"，但顶点对不上地块。
> `translate → scale → rotate`（`T·S·R` = 先旋转再压缩）四角才是 `(±0.707, 0)·s` 与 `(0, ±0.354)·s`。
> smoke 断言按**顺序**校验（查 `indexOf(scale) < indexOf(rotate)`），只查"有没有 rotate"挡不住。

地形贴图**相反**：绝不许斜切（会把沙纹、水波这类方向性纹理拧歪）。
所以那条"不许 rotate"的断言必须**分段查**（只扫 blitArtRect 那一段），
全文件扫会把正确的城池实现判成违规。

### 三个结构性要点

1. **按 `gx+gy` 升序绘制**（斜投影的屏幕纵深）。正方形时代按行扫即可，菱形必须排序，
   否则南边的物件会被北边的穿透。据点/NPC 城/玩家城原本各走各的循环，现在合并成
   `marks` 列表一起排序。
2. **每格两个侧面**（左下受光偏亮 0.60→0.42、右下背光偏暗 0.44→0.24）。
   "一个侧壁"是正方形时代的样子；菱形下两个面才撑得起立体感。
3. **贴图正交铺贴 + 菱形路径裁切**，不做旋转 45° 的真仿射 —— 地表材质是俯视素材，
   铺到菱形上"纵向压扁 2:1"正是等距视角应有的观感；改用真仿射会把沙纹、水波
   这类**方向性纹理拧歪**（静态材质看不出，方向性材质一眼就假）。

### 拾取：菱形反而是最干净的（但有一个坑）

`反投影 + round` 与"最近格心"等价，而**菱形正是格心的 Voronoi 元**，
所以"点在菱形内"⇔"round 回本格"，全程只有乘除，无三角函数、无累积误差。

> ⚠️ **必须扣掉 canvas 边框**：`#mapCanvas` 有 `border: 3px`，`getBoundingClientRect()`
> 返回 1254 而属性宽只有 1248（差 0.5%）。旧公式直接拿 `rect.width` 缩放，
> 实测**贴近菱形边界的点命中率只有 31%**（320 点中 100），而且错得"像手抖"，最难查。
> 改用 `canvas.clientWidth` 并显式减掉边框厚度后 320/320。

### 实测验收

| 项 | 值 |
|---|---|
| 拾取（菱形内 9 点/格 × 40 格） | 安全区 **360/360**、贴边区 **320/320** |
| 菱形边界是否落在预测位置 | 边中点比格心暗 **24.8** 级（63% 显著） |
| 密铺（画布中部兜底色占比） | **0.76%** |
| 结构密度（相邻像素差，同口径） | 正方形 8.45 → 菱形 **13.13** |
| 单次重绘 | **4.56 ms**（fill 2075 / drawImage 328 / stroke 1037） |

### 采样断言的一个数学前提

菱形内条件：`|dx/HW| + |dy/HH| ≤ 1`。
所以「半宽 0.6 倍 + 半高 0.6 倍」的斜向点**已经在菱形外**（0.6+0.6 = 1.2 > 1），
命中邻格才是正确行为 —— 写测试采样点时踩过这个坑，误判成"实现有 bug"。

# 十、v66 的两个新坑（2026-09-14）

## 10.1 ⛔ 同一条消息里对**同一文件**的多次 Edit 会互相覆盖

症状：两处编辑都回"成功"，但只有一处真的落盘（后写的把先写的覆盖掉），
甚至出现过"旧行 + 新行并存"的中间态（`b.hp` 与 `b.sta` 同时存在，不报错、只算错）。

更难查的是**读也不可信**：同一批里用 Bash 的 `grep` 复核，读到的可能是旧内容
（输出有缓存）→ 于是我一度以为"改上了"，其实没有。

**规矩**：
1. 一条消息里**只改一个文件的一处**；多处改动写 `.py` 补丁脚本（脚本每次重新读盘再写，天然安全）；
2. 改完必须跑**落盘核验脚本**（`.workbuddy/tools/audit/verify_v66_edits.py` 是模板）：
   正/反向逐条列标记 + 打印 `MISS` 清单，**不信编辑工具的返回值**；
3. 核验脚本自己也要防写错：反向检查（"不许出现"）要把标记本身写成独立字段，
   别把 `✗` 塞在说明文字里（我第一版就是这样，把"已清除"报成了 MISS）。

## 10.2 ⛔ 破坏测试的备份目录会把之后的修改一起"还原"掉

破坏测试的 `restore()` 从备份目录恢复文件 —— 如果备份是**在修夹具之前**建的，
那么修完夹具再跑破坏测试，收尾的 `restore()` 会把夹具**改回旧版**，
表现为"断言忽然又零反应"。

**规矩**：改测试夹具后要**删掉旧备份目录**再跑；或者给备份目录带时间戳/内容指纹。

## 10.3 断言口径的两个老坑（本轮又各踩一次）

- **夹具必须能让判据区分被测对象**：e2e 里"体力主数字 = 上限"这条，
  夹具给的是**满体力**（当前 == 上限）→ 破坏测试把实现改回"取当前值"时**零反应**。
  改成 `stamina = 10`（当前 ≠ 上限）立刻就红了。
- **`G.newGame()` 不会把 state 装进 `GAME.state`**：凡是走业务函数
  （`useItem` / `gainExpByItem`）的断言都要先 `G.state = st`，否则操作的是上节残留的 state，
  于是"拒绝了"看着像通过 —— 其实拒的理由是"背包没有该宝物"。
  **断言里要顺带校验拒绝理由**（`/上限/.test(r.msg)`），别只看 `ok === false`。
- **断言写死字面量会被属性打断**：`/gd-line">体力/` 在行里加了 `title` 之后就失配。
  判"某一行在不在"要用 `/gd-line"[^>]*>体力/`。


## 10.4 v67：清理脚本与"半截收尾"的教训（2026-09-14）

**事故**：`cleanup_v67.py` 的"保留清单"文件名写在 tmp 的**子目录**里，脚本只在顶层
`os.listdir` 里找它 → 白名单全落空 → 该保留的一并进了删除列表。**实际损失为零**
（搬运先于删除 + 脚本被重复执行），但这是一次真·侥幸。—— 由此定三条硬规矩（已进 MEMORY §二）：

1. **清理脚本先干跑**：只打印「将删 N / 将留 M + 逐条理由」，人工确认后才落盘。
2. **保留清单用"白名单路径集合"，且脚本里断言它非空** ——"清单没读进来"必须表现为**崩溃**，
   不能表现为"全都可删"。**"空集"是最危险的默认值。**
3. **删除前对候选集做引用 grep**：文档/技能/记忆里出现过的名字 → 降级为"搬移"。

**事故 2**：`patch/finish_cleanup_v67.py` 在「合并旧文档」处被中断 —— 合并件写出了、**9 份原件没删**、
路径转接与文字订正全没跑。表现是"看起来做完了，其实半截"。
**对策**：长收尾脚本要拆成**每步可单独重跑 + 每步幂等 + 末尾打印做了什么**；
每步都带**锚点断言** —— 第二次执行时锚点已被替换，正好用来判断"这步做过了"而不是再改一遍。

**事故 3（复核手法）**：`re.search` 替换 HTML 时**先打印实际匹配到的原文**再替换，
别假设自己写对了边界。本次靠打印发现"匹配段比预期短"，逐字核对后确认 `<code>` 标签 5/5 配平。

**教训沉淀 · 清理的判据顺序**：
`先 grep 引用 → 再分"搬 / 留 / 删"三档 → 删之前复核（能逐行比对就逐行比对）→ 最后才是删`。
**"过程产物"里往往混着"下次还要用的工具"**，所以 v67 起可复用工具一律进 `.workbuddy/tools/`。

## 1. 接触判定按双方位移（前沿互锁）

**老板**：「接触判定按双方位移，如果我一步来到你面前，你不能再往前移动，直到我这个兵种被完全消灭，你的后续移动才可以向前」

- 判据从"有没有开过火"（旧 hot 锁）改成**纯位置**：`接触 = 两军前沿间距 ≤ 双方最前部队的有效射程`。
- 为什么用射程而不是 0：引擎的推进规则本来就是"走到能开火就停"（`free = gap − 射程`），
  所以近战也是停在 gap = 射程（10~80）而不是贴到 0 —— 用射程判据，接触恰好出现在**两军都推不动了**那一刻。
- 有效射程由引擎快照给出（`er: Math.round(effRangeFor(u))`），界面不再猜。
- **前沿互锁**由推进规则保证：任何部队都推不过交战线 —— 逐帧断言：**35 次前进全部停在射程上（0 次越线）**，
  两军前沿不相交（探针 ②/②b）；前沿退回出发线 = 被攻入腹地（探针 ③）。
- 配置：负重技巧暂不管、辎重暂不管（按老板「暂不管」留待下轮）。

## 11. 城内建筑配色（素材像素级重做）

**老板**：「现在城内建筑的颜色很不对劲，绿的绿，紫的紫，不美观」

- **先量**（`measure_bldg_icons.js`）：16 张图标的均值色相跨度 **12°~250°（238°）** ——
  书院/招贤馆偏绿(132°)、军营/校场/烽火台偏青(196°)、驿站偏紫(250°)、市集/铁匠铺偏红(12°)。
- **第一版走错了**：把全族统一到 40° 后，老断言「七族两两可分」当场红 —— 族与族再也分不出来。
- **正解**：色相收进 **8°~68° 的暖带**（红铜→金），族间用**色相 10° 步进 + 明度差 12% 兜底**：

| 族 | 色相 | 明度 | 建筑 |
|---|---|---|---|
| 商业 | 8° | 28% | 市集 / 铁匠铺 / 工匠作坊 |
| 军事 | 18° | 40% | 军营 / 校场 / 烽火台 |
| 仓储 | 28° | 28% | 仓库 / 马厩 |
| 政务 | 38° | 40% | 官府 / 鸿胪寺 / 城墙 |
| 民生 | 48° | 28% | 民房 / 客栈 |
| 教育 | 58° | 40% | 书院 / 招贤馆 |
| 道路 | 68° | 28% | 驿站 |

- 手法按素材管线纪律：**改素材像素**（增量色相旋转 + 饱和度微调 + 明度整体缩放），**不叠 CSS 滤镜**；
  原图备份 `assets/icons/ui/_gold_backup/`，脚本带 `restore`。
- 门禁：**像素级断言**（纯 Node 解 PNG：zlib.inflate + 反滤波，逐张核色相 ±10°、饱和 25~46%）——
  查 CSS 的正则挡不住"改回去了"。对照图：`.workbuddy/shots/v89104-bldg-icons-before-after.png`（上=改前/下=改后）。

## 12. 地图放大 20%

- **实测先破了一个假设**：只抬格距上限**没用**（fitMapCell 为了"占满"永远选小格，
  1680×1000 下仍是 20×17@41，上限 44→53 根本没被碰到）。
- 所以放大作用在**搜索结果**上：格距 ×1.2、行列 ÷1.2（`ui.MAP_ZOOM = 1.2` 一处派生两个落点）。
- 实测：jsdom 基准 20×17@41 → **17×14@49**；1680×1000 下 **25×14@53**（画布 1325×742，比改前的 820×697 铺得更满）。
- 同屏块数 −20%、单格 +20% —— 正是"视野窄一点、画面大一点"。

## 诚实缺口（下迭代）

1. **逃兵/降兵**只有判断与口径，没有独立机制（老板点名三件事里的一件半）。
2. **辎重/负重技巧**按老板「暂不管」未动（v89.103 的随军载重仍不吃科技）。
3. **公文"大类"只到三类**（战报/侦查回报/消息）；若要按"州郡/门派/任务"再细分，得先定分类口径。
4. **珠宝上限**：15 档面额目前只用到第 9 档（夜明珠）——顶格 6 档（血珊瑚…传国玉玺）留给爵位/赏赐，
   若要让建筑吃到更高档，改 `DATA.JEWEL_COST.tierEvery` 一处即可。
5. **地图放大是"搜索结果缩放"**：极端窗口（很宽/很矮）下 cell 会被 `MAP_CELL_MAX=53` 顶住，
   这时"再放大"要靠抬上限（一行），但会牺牲"铺满"。

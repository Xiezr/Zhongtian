# 玩法扩展规划

> 老板 2026-09-14 指示：「发掘可玩性，加入更多系统，比如将领加入武学？奇遇？游历。
> 在现有元素上发掘可玩性，建造，建筑功能，野地，将领，出征，防守（定期被攻打？）
> 天下大势（各城归属地势力，曹魏，蜀汉，东吴，胡？夷狄？）。郡县州都城分配，等等。这一条先规划」
>
> **本轮只规划，不动代码。** 每条都标了实施约定（数据表 / 消费点 / 单一出口 / 可验证判据），
> 以便真要动手时能直接照做。

## 〇、一句话结论

**地基比想象中厚得多 —— 13 个州、郡县州都城四档、州特产、县名库、28 名将带坐标、
11 羁绊、9 奇遇、12 年号、19 史册规则、5 天气、4 季、22 爵位、7 称号，全都有了。**

所以这份规划**不是从零造系统**，而是两件事：
1. **接线** —— 把已经写好但没消费点的东西接上（见 §六「空承诺清单」，最便宜的玩法收益）；
2. **补缺口** —— 真正缺的只有四块：**势力层、将领成长线、游历、以及"被攻打"**。

其中 **§四「防守」还顺带修一个真缺陷**：防线的全套零件都已建好（城墙 / 箭塔 / 城防值 /
驻军 / 守将加成），但**没有任何东西会来打玩家**。已逐行核实：`cityDefense()` 的战斗消费点
**只有一处**（`battle.js:720`），且被 `t.kind === 'city' && t.npc` 门控 —— **只对 NPC 城生效**；
其余 4 处调用全是**界面显示**。也就是说玩家掏资源修的城墙与箭塔，
**当前只进一个显示数字，不进任何战斗计算**。这是个空转的系统，不是"少一个玩法"。

## 二、§一 将领：武学（新增）

**缺口**：将领目前只有"等级 + 资质 + 四维 + 装备 + 套装"。等级靠经验道具和战斗升，
**没有"练什么"的选择** —— 同一个资质、同一个风格的将领，练到最后完全一样。

**设计（数据驱动，加内容=加数据）**：

```
DATA.WUXUE = [                      // 武学（将领专属成长线）
  { id:'qiangfa', name:'枪法', kind:'troop', troop:'changqiang',
    maxLv:5, cost:{ exp:…, gold:… }, effect:{ atkPct:0.04 },  // 每级
    lore:'…' },
  { id:'qishe',   name:'骑射', kind:'troop', troop:'qingji',  … },
  { id:'zhizhong',name:'持重', kind:'def',   effect:{ defPct:0.05 }, … },
  …
]
```

- **唯一出口**：`GAME.wuxueOf(g)` → 某将领的武学等级表；`GAME.wuxueBonus(g, key)` → 汇总加成。
  **消费点只有两处**：`genAttrs`（并入现有 `atkVal/defVal/atkPct/defPct` 那条链）与
  `battle` 里已有的 `atkMult`/`defBonus`。**不新增战斗出口** —— 项目现有属性链已经是
  「属性 → 攻防值 → 百分比」（见 MEMORY §七），武学挂在同一个链上即可。
- **可验证判据**：
  ① 结构：`wuxueBonus` 的每个 key 都必须有消费点（照 `audit.js` 现有的"科技效果消费点"那样查）；
  ② 行为：给同一将领加满某条武学 → 战报伤害数字必须变化（能翻转）；
  ③ 边界：武学等级不得超过 `maxLv`；资源不足时拒绝并给出理由。
- **工作量级**：中。主要成本在 UI（将领面板加一栏）与数值标定。

## 三、§二 将领：奇遇 + 游历（扩展 + 新增）

### 3.1 奇遇：扩入口（小改）

现在 `ENCOUNTERS` 只由"探索野地"触发，且奖励全是资源。**扩两个入口、加一类奖励**：

- **入口扩到**：出征途中（行军事件）、驻守野地（每日一判）、城池岁贡（`CITY_OPTS` 已是每日一次）。
- **奖励加一类**：`{ general: { chance, rankMin } }` —— 直接给一名在野将领（招贤馆已有招募，
  奇遇给的是"白捡"，语义不同）。
- **唯一出口**：`GAME.story.rollEncounter(ctx)`，`ctx` 决定可用池与权重（现有 `weight` 字段直接用）。
- **判据**：同一 `ctx` 下跑 1000 次，各池命中率与 `weight` 成正比（±…）；奖励必落入
  `MATERIALS`/`ITEMS`/`TROOPS` 的合法 id（防手写错字）。
- **工作量级**：小。

### 3.2 游历：新增

**缺口**：将领现在只在"城内任职"和"带兵出征"两种状态之间切换，**没有第三种去处**。

**设计**：把将领**派出去游历** —— 占用一段时间，回来带东西。

```
DATA.JOURNEY = {
  destinations: [                    // 目的地 = 复用已有的 13 个州
    { state:'sili',  name:'司隶',  hours:12, danger:3, rewards:{…}, events:[…] },
    { state:'liangzhou', name:'凉州', hours:24, danger:5, rewards:{…}, events:[…] },
  ],
  outcomes: [...]                    // 复用 ENCOUNTERS 的结构：weight + text + reward
}
```

- **语义与出征区分清楚**：出征是**带兵**打资源/地盘；游历是**单人**（或带少量随从）去
  见世面 —— 产出的是**见识与际遇**（武学经验、奇遇、宝物线索、羁绊线索），不是资源。
  这样两条线不抢同一块蛋糕。
- **唯一出口**：`GAME.journeyStart(genId, destId)` / `GAME.journeyResolve()`，
  状态存 `g.journey = { dest, endsAt }`（**入存档**，因为它跨时间且不可派生）。
- **存档注意**：⚠️ 项目铁律「派生数据不入存档」—— 游历的**结果表**是派生的，
  但**在途状态**（谁去了哪、何时回）必须入档。判据：运行中会被修改 → 入档。
- **可验证判据**：
  ① 派出去后该将领在城内"不可用"（出征/任命入口必须拒绝并说明理由）；
  ② 到点后必须回来（时间轮推进测试）；③ 存档再读档，在途状态不丢。
- **工作量级**：中。**与"出征"共用行军时间轮**，别新写一套计时器（项目已有时间轮）。

## 四、§三 天下大势：势力层（新增 · 本规划最大的一块）

**缺口**：数据里有 `state`（13 个州，地理层），**完全没有 `faction`（阵营层）**。
174 座 NPC 城只有一个"州"的属性，没有"归谁"。

**设计**：

```js
DATA.FACTIONS = [
  { id:'wei',  name:'曹魏', color:'#3a5fa8', leader:'曹操',
    homeStates:['司隶','兖州','豫州','冀州','青州','并州','凉州'],
    trait:{ siege:1.10, prod:1.05 },      // 势力特性 → 接现有 attr 链
    lore:'挟天子以令诸侯' },
  { id:'shu',  name:'蜀汉', leader:'刘备', homeStates:['益州'], trait:{ def:1.15, terrain:… } },
  { id:'wu',   name:'东吴', leader:'孙权', homeStates:['扬州','荆州','交州'], trait:{ navy:… } },
  { id:'hu',   name:'夷狄', leader:null,   homeStates:['幽州','并州'边缘], trait:{ raid:… } },
];
```

- **城的归属走派生**：`GAME.factionOfCity(city)` —— **不往 NPC 城数据里加字段**
  （那些城是派生值，见 `GAME.buildNpcCities` 注释），按 `state` + 一张归属表算。
  这样**改归属只改一张表**，不用逐个城市改数据。
- **唯一出口**：`GAME.factionOfCity` / `GAME.citiesOfFaction(fid)` / `GAME.stateOfFaction(fid)`。
- **给"天下大势"加动态（分期）**：
  - **一期（静态）**：只显示归属与势力特性。改动最小，先把版图**看见**。
  - **二期（动态）**：势力之间按回合互攻 —— 版图会变。⚠️ 这需要一台**势力 AI 时间轮**，
    要单独评估（会不会把玩家晾在一边？会不会把玩家开局碾死？）。
- **与现有内容的咬合点**：
  - `TITLES` 里的「扫六合」（`minCities:109`）**天然就是"统一"的判定**，势力层让它有意义；
  - **羁绊 `BONDS` 已经按阵营分组了**（如「曹魏股肱」= 曹操/司马懿/贾诩），势力层直接复用；
  - `HEROES` 28 名将**已带坐标与所在城**（曹操→许昌、周瑜→赤壁），归属可直接推。
- **可验证判据**：
  ① 覆盖完整：**每一座 NPC 城都必须能算出归属**（`factionOfCity` 返回非空），
     且 `citiesOfFaction` 之和 == 174（分母不能为 0，也不能漏城）；
  ② 归属表与 `STATE_SPECIALTY` 的 13 个州名**完全一致**（防手写错字导致某些州无归属）；
  ③ 改归属表一张表即可生效，不需要动 `NPC_CITIES`。
- **工作量级**：一期小（显示层），二期大（AI 与平衡）。

## 五、§四 防守：定期被攻打（✅ **已于 2026-09-14 落地**）

> **落地实况**：`DATA.INVASION` 表 + 7 个唯一出口（`invasionTick` / `invasionDueAt` / `invasionIntervalSec` / `armyPowerOf` / `defensePowerOf` / `invasionPowerOf` / `invasionResolve` / `invasionRoll`）。
> 在线 `tickOnce` 与离线 `simulateBulk` **共用同一个 `invasionTick`**。
> 界面：城池属性栏加一条 `.note-warn`（**复用断粮警示的样式，未新增 CSS**），
> 显示"还有多久 / 守备力 / 有无烽火台提前预警"。
> 护栏：smoke 第 53 节 **18 条**；破坏测试 `tools/break/break_invasion.py` **3/3 变红**、md5 逐字节还原。
> ⚠️ 落地过程中被断言抓出的两个真缺陷：① `DATA.RESOURCES` 是**数组**不是字典，写成 `[key].name` 会 TypeError；② `severity` 先写进返回值再重算，导致**返回明细与真实扣损口径不一致**。

### 5.1 先说缺陷

防线全套零件**都已建好**：

| 零件 | 在哪 |
|---|---|
| 城防值 | `GAME.cityDefenseBase(city)` = `city.def + wallLvl × 20`（守将智谋再乘） |
| 箭塔 | `WALL_TOWER`：2000 血 / 300 攻 / 每座 +2 城防，`GAME.towersBuiltOf` |
| 城墙 | 建筑，每级 +城防 |
| 驻军 | `GAME.armyTotal(city)` |
| 守将加成 | `genAttrs` → `defPct` |

**但 `cityDefense` 的唯一消费点是"玩家去打别人时，对方作为守方"** ——
玩家自己的城防**从来没被读过**，因为**没人来打玩家**。

**后果：玩家掏资源把城墙修到 12 级、箭塔建满 —— 只改变了界面上那个「城防」数字，
不改变任何一次战斗结算。**
这是个**空转的系统**，不是"少一个玩法"。

### 5.2 设计

```
DATA.INVASION = {
  unlockAt:  { minCities: 2 },        // 什么时候开始有人来打（别一开局就挨打）
  interval:  { base: 4, min: 2 },     // 游戏日：每 N 天来一次（随城数与声望收紧）
  warnHours: 12,                      // 提前多少小时给警报（给玩家反应时间）
  strengthOf(ctx) { … },              // 来袭规模：按目标城防御力 + 玩家声望/城数
  sources: ['fort','npcCity','faction'],  // 谁可能来：野外城池报复 / 名城 / 势力
}
```

- **必须可预警**：`warnHours` 前在公文与顶栏给警报（`fenghuotai` 烽火台建筑**天然就是干这个的** ——
  它现在是空承诺之一，正好接上：有烽火台 → 提前预警更久）。
- **必须可防**：玩家能把主力调回目标城（现有"驻军"与"派遣"入口已具备）。
- **必须可败得起**：输了丢资源/掉城墙等级/损兵，**不丢城**（丢城会让玩家重开）。
  ⚠️ 这条是体验红线，建议做成 `DATA.INVASION.loseCity = false` 的**可调常量**。
- **唯一出口**：`GAME.nextInvasionAt()` / `GAME.resolveInvasion()`，
  时间轮在现有 `tick` 里挂钩（**别新起计时器**）。
- **可验证判据**：
  ① 到点必来（时间轮推进 N 天，事件必触发）；
  ② 预警在前（日志顺序：警报 → 来袭）；
  ③ **玩家城防真的被消费了** —— 同一个来袭规模，城墙 Lv1 与 Lv12 的战损必须不同
     （能翻转：把 `cityDefense` 桩成 0，战损必须变化）；
  ④ 关掉开关（`state.settings.invasion=false`）后永不触发 —— 给不喜欢被打的玩家留后路。
- **工作量级**：中。**复用现成的 `battle.js` 守方逻辑**，主要新工作在调度与预警。

## 七、§六 建造 / 建筑功能 / 野地（深挖现有）

| 方向 | 现状 | 可挖的点 | 成本 |

### 11.1 §八 庄园：种植 / 养殖 / 钓鱼（新增）

**实测现状**
- 城外 4 建筑（农田/伐木/采石/铁矿）是**大宗资源自动产出**（农田 Lv12 = 7800/h，表内还有更高档位），
  与"庄园玩法"不同层 —— 庄园不能和它们抢粮。
- `GATHER` 采集系统：basePerHour 2 / levelBonus 0.35 / maxActive 3 / 体力 6，且**带宝概率 0.02 + 0.001×将级** ——
  "耗时产出去"的模型已经存在。
- 湖泽地形（lake）已有；马厩（majiu）建筑 + 驯马科技 + 坐骑装备 —— 养殖的现成咬合点。
- **缺**：种子→生长→收成的时间玩法、钓鱼、养殖 —— 全无。

**设计**（一个界面 = 三个子玩法，共享时间轮）

```
DATA.MANOR = {
  plots: 6,                                        // 地块数（庄园等级解锁）
  crops:     [ { id, name, hours, seed:{}, yield:{}, rare:{ id, chance } } ],
  livestocks:[ { id, name, hours, feed:{},  yield:{} } ],
  fishing:   { rods: [], fish: [ { id, weight, price } ], treasure: 0.02 },
}
```

- ⛔ **不得成为第二出口**（本项目最经典失效模式）：庄园**不产出** grain/wood/stone/iron 大宗
  （那是城外 4 建筑的地盘）；产出走**新品类** —— 接入现有 `MATERIALS` 24 材料体系（MAT_SERIES 6 组）。
- **用途闭环**（否则就是死系统）：作物/渔获 → ① 将领技能书材料（§十）② 犒军/宴会（民心·忠诚）
  ③ 贸易变现（§十五）④ 炼丹（临时 buff）。
- 唯一出口：`GAME.manorOf()` / `manorPlant()` / `manorHarvest()` / `fishCast()`。
- 时间轮：在线/离线**共用 step**（照 `starveStep` / `invasionTick` 先例，⛔ 不许各写一套）。
- UI：新 tab 或并入 ext 面板；卡片复用 `.troop-card` 样式系（已有 selected/disabled 态）。
- **判据**：① 到点必熟（时间轮推进）；② 离线回来结算不多不少；③ 庄园产出**不进**
  `prodBasePerHourOf`（防第二出口，加审计断言）；④ 地块状态入档（运行中会变），生长速率表派生不入档。
- **工作量级**：中。

### 11.2 §九 主线剧情 + 卡牌战斗（新增 · 本轮最大一件）

**实测现状**
- 任务系统是"指标→奖励"（50 成长 + 36 随机/日 + 7 类型 + 35 指标），**metric 引擎成熟**；
  但**没有剧情 / 章节 / 首领概念**。
- 战斗全是"军队对军队"：`tactic.js` 回合制距离轴（野地 2000 / 野外城 3000 / 城池 4000），按速度行动。
- 卡片 UI 传统已有：`.story-card` / `.troop-card` / `.inn-card`。
- 主角：`INITIAL_GENERAL = '赵子龙'`。

**设计**（章节数据 + 卡牌战斗模式）

```
DATA.STORY_CH = [ { id:'ch1', name:'…', nodes:[
    { type:'story',  text, choices:[ { text, effect } ] },
    { type:'battle', monsters:[…] },
    { type:'reward', … } ] } ]
DATA.SKILLS   = [ … ]     // ⚠️ 与 §十 共享同一个技能库（单一出口）
DATA.MONSTERS = [ … ]     // 怪物 = 复用将领结构（四维 + 技能）
```

- **卡牌战斗**：3~5 将领组队（不带兵）；每回合抽手牌（将领技能 = 卡）→ 消耗"将令"出牌 → 结算。
  - ⛔ **不做第二出口**：伤害基数走 `GAME.genAttrs`（现有唯一属性出口），口径与 tactic 相同
    （攻击 ÷ 生命）；卡牌层只加"行动经济"（手牌/将令/回合），不另造一套伤害公式。
- 与出征的边界：主线战斗**不损兵**（小队制），产出走剧情奖励（新装备 / 技能书 / 神兽蛋）。
- **判据**：① 节点顺序推进不可跳；② 分支由胜负驱动（可翻转测试）；③ 卡池与 §十 技能库同源（审计断言）。
- **工作量级**：**大**。分期：先"线性 3 章 + 简化卡牌"验证乐趣，再扩章节。

### 11.3 §十 将领技能：能力倾向 / 生成 / 培养（新增）

**实测现状**
- 将领 = 四维（统 tong / 内 nz / 勇 yw / 智 zm）+ 5 档资质 + 4 将格（均衡/猛将/智将/能臣）+ 装备 + 等级。
- **无技能层** —— 全项目"技能"一词只出现在科技描述里。
- `genAttrs` 是唯一属性汇总出口（已登记于工作备忘 §十一 清单）。

**设计**
- **能力倾向**（老板点名四类）：`phys 物理 / magic 魔法 / support 辅助 / heal 回复`。
  生成时按将格映射默认倾向（猛将→物理、智将→魔法、能臣→辅助…）+ 资质加权。
- **技能生成**：`GAME.rollSkills(gen)` —— 倾向权重 + 资质决定数量与品质；**种子化**
  （同一将领稳定，读档不重 roll；照 `portraitSeed` 先例）。
- **培养两条线不打架**：武学（§一）= **被动属性线**；技能（§十）= **主动行动线**；
  技能升级用"技能书"道具（可由 §八 庄园材料合成）。
- 唯一出口：`GAME.skillsOf(gen)` / `GAME.skillPower(sk, lv)`。
- 消费点：卡牌战斗（主）+ 常规战斗（次要，走 `atkMult` 现有链）。
- **判据**：① 生成分布符合权重（1000 次统计）；② 技能数值只从 `skillPower` 出（审计断言）；
  ③ 技能书可升技能（可翻转）。
- **工作量级**：中。**与 §九 强耦合 —— 先做本项，卡牌才有"牌"**。

### 11.4 §十一 神兽 / 桌面宠物（新增）

**实测现状**：只有"坐骑"（mount 装备槽 + 马厩 + 马鞭道具）。**无独立养成单位**。

**设计**

```
DATA.BEASTS = [ { id, name, icon, rarity, grow:{}, aura:{ prodPct:0.02 }, likes:[…] } ]
```

- 获得：奇遇 / 主线奖励 / 节日限定 / 马厩孵化。
- 养成：亲密度（互动）+ 等级（喂食）；提供**全局光环**（+1~3% 量级，不破坏平衡）。
- "桌面宠物"形态：主界面角落常驻（可关），点击互动，状态表情（emoji / SVG —— 项目已有程序化 SVG 传统）。
- 唯一出口：`GAME.beastOf()` / `beastFeed()` / `beastAura(key)`。
- **判据**：① aura 有消费点（audit）；② 亲密度/数量上限；③ 入档。
- **工作量级**：中偏小（调味性质，建议排在 §九 之后）。

### 11.5 §十二 装备来源：从"有"到"看得见"（扩展）

**实测：地基比预想厚 —— 已有 6 条链路**

| 链路 | 实现 |
|---|---|
| 打造 | `FORGE` + `BLUEPRINTS`(3 图纸) + `CRAFT_SLOTS`(12 槽 × 4 阶：铁刀→神兵) |
| 野地 | `WILD_MATERIAL`（7 地形 × 材料）+ 采集带宝（2% + 0.1%/将级） |
| 城战战利品 | `LOOT_EQUIP` 五档：fort 图纸 4%/装备件 10% → capital 80%/90% |
| 市场 | `marketTrade` + 商铺 |
| 熔炼 | `salvageEquip` |
| 任务 | `QUESTS` 奖励 |

**真缺口**：① **来源不可见** —— 87 件装备没有"从哪来"的标注（图鉴感缺失）；
② 新玩法带来的新来源尚未接（主线 / 钓鱼 / 庄园 / 神兽 / 节日）。

**设计**
- **装备图鉴 + 来源标注**：每件装备标"产出地"（打造 / 掉落表 / 活动）—— 数据补 `src` 或由现有表派生。
- 新来源接线清单：主线 boss 掉落表 / 钓鱼稀有物 / 庄园作物→材料→打造 / 节日限定图纸。
- **工作量级**：小（图鉴 = 读现有数据 + 一栏 UI）。**可随时插做**。

### 11.6 §十三 时装装扮（半新建）

**实测现状**：头像已有**三层体系**（`portraits.js`：pool 40 张 / 名将 28 / 程序化 SVG），
且程序立绘已按"四维→甲胄主色、资质→冠帽"从脸上读信息；emoji 头像（`AVATARS` 2 组）用于快速位。
**无装扮栏位**。

**设计**

```
DATA.FASHION = [ { id, name, slot:'head|body|waist|foot|bg', src, effect:{}, text } ]
```

- 栏位 5 个；效果**以展示为主**（换装改变外观），可带极轻加成（声望/魅力）。
- ⛔ 与 `EQUIP_SLOTS`（12 装备槽）**互不干扰** —— 装扮不是第二套装备。
- ⚠️ 美术资产：走已有 AI 图集管线（`assets/icons` 即此产出）；**风格与需求清单需老板先定**（见文末「十四、新增拍板项」）。
- **判据**：① 换装持久化（入档）；② 不侵入装备数值链（审计断言）。
- **工作量级**：中（成本主要在美术）。

### 11.7 §十四 节日系统（新增）

**实测现状**：**全无节日**。但历法基建齐（`CALENDAR` / `SEASONS` / `ERAS` + `story.js` 历法层每天在跑）。

**设计**

```
DATA.FESTIVALS = [ { id, name, cal:{}, days, activities:[
    { type:'contest', … }, { type:'quests', … }, { type:'shop', … } ] } ]
```

- 触发：`story.js` 历法层（**游戏历法**，非现实日期）—— 每年循环。
- 比赛：**直接复用 metric 引擎**（限时指标 + 奖励）；专属任务同样走 metric；限定商品接 §十五。
- **判据**：① 跨节日推进必触发（时间轮测试）；② 奖励只从表出；③ 节日加成有消费点。
- **工作量级**：中。

### 11.8 §十五 贸易与经济收口（改造 · **平衡类，数据先行**）

**实测现状（金币产出 5 条链）**

| 链 | 实现 |
|---|---|
| 税收 | `taxGold = popCap × (hearts/100) × tax × (1+taxPct)` —— **随人口线性、无上限** |
| 俸禄 | `RANK[爵位].salary`（府库层面） |
| 岁贡 | `cityDailyYield` 每日汇总 |
| 征调民力 | `LEVY_RES_RATE.gold = 0.06`（每日） |
| 其他 | 市场 / 战斗掠夺 / 任务 |

**设计**
- **税收收口**（老板点名）：给税收金币加**边际递减或上限**，或把"金币主力来源"转向**贸易变现**
  （卖资源/材料）—— 让经济有经营感。
- **贸易扩展**（老板点名）：① **名城通商**（`CITY_OPTS` 加一项，按 `STATE_SPECIALTY`
  13 州特产差异定价 —— 把 13 州特产真正用起来）；② **野地城池作为商路节点**
  （`TRANSPORT` 已有运输损耗模型，接上收益侧）。
- ⚠️ **必须量化**：先出"现状金币收入构成"审计（照 `ladder_audit.js` 先例做 `economy_audit.js`），
  改前改后对照，**不拍脑袋**。
- **工作量级**：中。

### 11.9 §十六 主角冒险（并入 §二 游历，补设计）

### 16.2 ✅ 已落地（v68）：建造前置 —— 逐步探索

**老板原话**：「增加建造限制，比如其他建筑等级不能超过官府，先客栈后招贤馆，
铁匠铺 x 级才能建工匠作坊等等，继续设定合理规则，让玩家逐步探索」

**规则表**（`DATA.BUILD_PREREQ`：老板 3 条 + 补充 3 条 + 总闸 1 条）：

| 规则 | 来源 |
|---|---|
| 城内建筑（含城墙）等级 **≤ 官府等级** | 老板指定（总闸） |
| 招贤馆 ← 客栈 Lv2 | 老板指定「先客栈后招贤馆」 |
| 工匠作坊 ← 铁匠铺 Lv3 | 老板指定「铁匠铺 x 级才能建工匠作坊」 |
| 校场 ← 军营 Lv2 | 补充：先募兵（军营）再练兵（校场） |
| 驿站 ← 市场 Lv2 | 补充：驿传通商，先有市场（商队） |
| 鸿胪寺 ← 客栈 Lv3 | 补充：迎来送往（客栈 Lv3 才撑得起场面） |
| 马厩 ← 军营 Lv3 | 补充：养马为骑军基础 |

**实现要点**
- 唯一出口 `GAME.buildPrereqOf(city, bid, nextLv)` —— 建造与升级共用同一把尺；
  新建显式传 `nextLv=1`（可多建建筑的新建第二座不被误判为升级，这是开发中抓到的真缺陷）。
- 总闸同时进 `buildCapOf`（等级上限显示）与 `buildPrereqOf`（操作拦截），读同一个官府等级。
- 「卡在官府上」与「真满级」分开报 —— 前者提示"需官府 Lv4"，后者才报"已达最高等级"。
- UI：建造卡置灰 + 写明原因（"需客栈 Lv2"）；升级按钮同。
- **兼容**：只管新建/升级，不倒查已建；**无官府的城豁免总闸**（异常/测试数据不被误伤）。

**平衡核查（实测）**：开局官府 Lv1 + 初始资源各 6000 ——
官府 1→2 仅缺 225 木（放开局伐木场 100/h，约 2.3 游戏时）→ **不会卡死开局**。
官府自身不受总闸（它是唯一能先升的），形成「升官府 → 解锁其他」的正循环。
⚠️ **城外 4 个资源建筑不受总闸** —— 否则资源供给死锁（城内等级全靠它们供养）。

**验证**：smoke 第 54 节 19 条断言 · 破坏测试 **3/3 变红**（gate 失效/门槛归零/绕开检查各自打中）·
smoke **1917 通过 / 0 失败** · e2e **661 / 0**。

### 16.3 ✅ 经济审计（老板「审计一下」）

工具：`.workbuddy/tools/audit/economy_audit.js`（**改前基线**已跑；税制改动后再跑一次对照）

| 阶段 | 人口上限 | 税收 /游戏时 | 俸禄 | 岁贡 | **税收占比** |
|---|---|---|---|---|---|
| 新手 · 1城·官府3 | 1,200 | 660 | 0 | 0 | **100%** |
| 中期 · 3城·官府8 | 43,200 | 23,760 | 2,000 | 0 | **92.2%** |
| 后期 · 5城·官府12 | 280,800 | 158,764 | 10,000 | 7,292 | **90.2%** |

**结论**：税收金币 = 人口 × 民心 × 税率，**无上限、随人口线性增长，占自动收入 90~100%** ——
金币完全被动化，玩家没有"经营"过程。后期攒一件 4 级打造（9 万金）仅需 0.5 游戏时（金币过剩）。
这就是「限制税收直给」的数据依据。
**待老板定限制方式**：① 税率边际递减 ② 每城税收上限 ③ 转向贸易变现 —— 三个方案改前改后各跑本工具对照。

### 17.3 逐项可行性

**G1 · 计谋 / 锦囊**（大件，收益最高）
- **与网游最大的区别即本作优势**：本作战斗是自动演算（tactic.js）——计谋**全部做成
  "战前计策"**（出征/守城前施加状态，战斗结算时读取），不做战中交互。这与现有架构
  完美契合：计谋 = 改变 `battle` 入参。
- **首批 8 计（每计必须接真实结算点，不许死数据）**：

  | 计 | 效果 → 接到哪 |
  |---|---|
  | 妖言惑众 | 目标城民心 −(智谋/10) → 守军战力与城防随民心下降（`cityDefense` 链） |
  | 火烧粮草 | 目标城/野地守军断粮计时提前（复用断粮链） |
  | 挑拨离间 | 目标城守将忠诚 −(智谋/12) → 忠诚 ≤0 时战胜可"招降"（接 G5） |
  | 金蝉脱壳 | 本军撤退耗时减半（退兵链） |
  | 千里奔袭 | 本军行军 +25%（与急行军令同链、有叠加上限） |
  | 空城计 | 对来袭军（invasion）：触发概率 −30%（"虚张声势"转译） |
  | 坚壁清野 | 被掠夺时资源损失 −30%（守方预施） |
  | 趁火打劫 | 对民心 <50 的城，掠夺量 +30% |

- **技术落点**：`DATA.SCHEMES` ＋ 唯一出口 `GAME.schemeCast(sid, target, gen)`；
  状态挂 `city.scheme = {id, until, val}`（运行中会变 → **入档**）；消耗 = 精力
  （已有链）+ **锦囊**（新道具，商城/战利品产出）；判定 = 施计者智谋 vs 目标守将智谋，
  **种子化**（可复现，照 portraitSeed 先例）。
- **工作量**：中。主要成本 = 每计的结算接线 + 出征/城池面板的"用计"入口 + 战报注明。
- **判据**：① 每计有消费点（audit 新增"计谋效果消费点"检查——照"科技效果"先例）；
  ② 施计后战报数字必变（可翻转）；③ 冷却与"24h 内不重复中计"（照原版）。
- **风险**：死数据（表写了不接线）——由 audit 断言挡住，不会漏。

**G2 · 城防四工事**
- 本作箭塔已是"折数模型"（`cityDefense` 折座数 × 2000 耐久池，tactic.js 可摧毁）。
  四工事按同一模型扩：**陷阱**（开战首回合对步兵一次性伤害）／**拒马**（对骑兵冲锋
  回合伤害 −N%）／**滚木**（近战单位每回合额外损耗）／**擂石**（对攻城器械伤害 ×2）。
- **决策点**：A 延续"折数"（零新增 UI）｜B 新增"城防配置"（城墙等级给工事点、玩家
  分配，有配置玩法）。**推荐 B**（守城从"被动一条线"变"配置一件活"）。
- **工作量**：中。**判据**：不同敌军构成下各工事必能翻转战报。**风险**：守方过强→标定。

**G3 · 装备镶嵌 / 打孔 / 宝石**
- 装备已单件化（`{u,id,enh}`）→ 加 `gems:[…]`。品质定孔数、金刚钻打孔（道具）、
  镶嵌接 `genAttrs` 链、拆下返还。宝石 = 新材料 5 系（攻/防/统/勇/智）× 3 档。
- **工作量**：中偏小。**判据**：镶嵌后属性链必变、拆下必返还、存档持久。
- **风险**：数值膨胀 → 每件孔数上限 + 同类宝石互斥。

**G4 · 军衔（封坛拜将）+ 君主主动科技**
- 本作 22 爵位已管城池上限（= 原版"爵位管城数"）；**军衔**做**君主将四维成长**：
  升级条件 = 城池数 + 声望 + 击败名将数（复用 metric）；解锁**君主科技（主动技·冷却）**：
  背水一战（本次出征军力上限↑）／速战速决（本次行军 −50%）／按兵不动（免战 1 小时
  ——**与 G9 共用出口**）／瞒天过海（此次入侵判定跳过本城）。
- **落点**：`DATA.MONARCH_TECH` ＋ `GAME.mtechCast(id)`，冷却时间戳**入档**。
- **工作量**：中（**与 §十六 主角合并做**）。**判据**：冷却必守 + 效果进现有链。

**G5 · 名将志（剧情任务 + 招降）**
- 本作名将现在是"占城必降"（简化）。转译：**28 名将每人 1 条"入仕条件"**（2~3 个
  metric，如"击败吕布军 2 次""占据洛阳""声望 ≥5000"）——**完全复用现有 QUESTS
  metric 引擎**；达成前占城只掉"信物"，达成后"招降"入口才亮。
- **与 §九 主线的边界**：主线 = 通用章节（卡牌战斗）；名将志 = 每人一条短链（条件 +
  文案），两者互不依赖。
- **工作量**：中（成本主要是文案——**分批**：先 Top10 名将）。**判据**：未达成必拒绝
  （给理由）、达成必可招、进度可查询。

**G6 · 红颜结缘**
- 美人池已有（貂蝉／大小乔／林黛玉…）。接养成链：**好感度**（送礼/带出征）→
  **提亲事件**（一次性）→ **结缘**（称号 + 双修小加成接 `genAttrs`）。
- **明确不做"子嗣"**（单机无需，避免臃肿）；保持历史言情调性，不搞擦边。
- **工作量**：中偏小。**判据**：好感上下限、事件一次性、加成有消费点。

**G7 · 政令（名城特权）**
- 转译：占领的名城按 tier 获得**辖区**（县 10×10／郡／州／全国）——⚠️ 辖区范围
  **直接复用缩略地图的"最近城距离场"**（v85.1 已建，`miniBuild` 一行取域）。
  对辖内**自己的城**：一键集征（便利）；对辖内 **NPC 城**：压榨式收税/抽丁
  （不损兵，但降该城民心、累积敌意）。
- **定位区分**：掠夺 = 现在拿资源（耗兵）；政令 = 占领后的**治理收益**（持续、无损）。
- **工作量**：中。**判据**：辖区查询抽 3 城验证、每日次数限、拒绝理由齐。

**G8 · 钱庄** → **并入 §十五 贸易收口**（就是"资源→金币"的兑换口 + 每日上限），不单列。

**G9 · 免战（休战令）**
- 挂"免战牌"→ 24h 内 invasion 必不触发；代价 = 免战期产出 −15% + 冷却 48h。
- **工作量**：小。**判据**：免战期推进 N 天零触发、过期恢复、与"按兵不动"共用出口。

**G10 · 宣战**（两案待老板定）
- A 案：维持自由攻伐（不做）；B 案（名分版）：攻州城/都城前需"传檄"（消耗声望或
  檄文道具），未宣战强攻 → 攻下后声望重罚 + 周边 NPC 敌意↑。
- **工作量**：B 案中。**判据**：未宣战强攻必受罚（可翻转）、传檄后正常。

**G11 · 祸福"祸"面**
- `DATA.MISFORTUNE` 4 条起：蝗灾（粮 −）／瘟疫（人口 −）／地动（建筑降 1 级·概率）／
  劫掠（在途运输损失）。触发 = 历法层低频 roll；**应对 = 花金"赈灾"减半**（给金币
  一个消耗口，与 §十五 联动）。
- **工作量**：小。**判据**：必触发轮转、损失有上下限、应对手段生效。
- **风险**：惩罚感——保持低频 + 可减免，首批 4 条。

**G12 · 珠宝九品**
- 珍珠／珊瑚／琉璃／琥珀／玛瑙／水晶／玉石／翡翠／夜明珠入库；来源 = 战利品/宝箱/商路；
  用途 = 赏赐（提忠诚链已有）+ G5 名将任务 + G6 送礼。**工作量**：小（纯接线）。

**G13 · 洗髓丹**
- 重置 v74 的自由属性点分配。道具（商城/战利品）。**工作量**：小。

**G14 · 排行榜 → 史册**
- 不做真排行（v19 已裁剪）；轻量替代：史册页记"本局之最"（声望峰值／最快占城／
  名将收集数）。**工作量**：小，**低优先**（可并入 §十四 节日/活动页）。

**G15 · 三合一合成台**
- 3 同名同阶 → 1 高阶（照原版规则 + 保护符），覆盖：宝石（G3）／材料（G12）／
  技能书（§十）。接铁匠铺。**工作量**：小-中（与 G3 共用出口）。

**G16 · 装备耐久 / 修理**
- **建议缓**：持久度管理对单机是"家务"。若有价值 = **战败掉耐久 + 修理费**，
  正好给金币一个持续消耗口（与 §十五 配套）。待定。

## 二、定位与设计原则

### 2.1 门派 ≠ 势力（必须错位，否则两套归属打架）

| 维度 | 势力（§三，规划中） | **门派（本档）** |
|---|---|---|
| 本质 | **政治/地理归属** | **江湖/师承归属** |
| 挂在谁身上 | **NPC 城**（`factionOfCity` 派生，不写进城数据） | **君主与将领个人**（`s.sect` 一人一派） |
| 数量关系 | 一座城恰属一个势力 | 一人恰属一个门派；门派可收多人 |
| 作用面 | 地图版图、攻城特性、羁绊分组 | 个人成长、专属兵种/装备、任务线 |
| 交互 | 玩家不加入，只对抗/吞并 | 玩家**加入或自立** |

→ 两套**可共存**：后期"占据某州 → 该州门派声望加成"即可咬合（§九），不需要改任何一方模型。

### 2.2 设计原则（照本项目既有铁律）

1. **单机可行** —— 不做任何多人/社交依赖（联盟被判 ❌ 的正是这一点）。
2. **加成走既有出口** —— 一切门派加成落到 `GAME.genAttrs` / `attr` 链 / 既有 `TROOPS`/装备表，**不新增战斗公式**。
3. **口径唯一** —— 声望、品阶、加成、任务判定各只有**一个**出口函数，界面只读不算（"算第二遍"是本项目最经典的失效模式）。
4. **不破坏已上线数值** —— 鸿胪寺既有"满级 +6% 全城产量"**原样保留**（有护栏与平衡审计覆盖），门派职能按等级**逐项新增**。
5. **id 与素材键不动** —— 建筑 id 保持 `honglusi`，图标键 `b_honglusi` / `ai_honglusi.png` 不动，只改**显示名与文案**；这样 `UNIQUE_BUILDINGS`、故事锚点 `['building','honglusi']`、建造前置表全部零改动。
6. **可持续验证** —— 每期都给可量化判据（覆盖完整、数值可复算、护栏可红）。

| 项 | 现值 | 改造后 |
|---|---|---|

| series | `'gov'` | **保持 `'gov'`**（配色分组、CSS、既有断言零改动）；若老板要独立门派配色，再加 `'sect'` 并同步 `ui.js` 分组表与配色 |
| desc | 联盟：1级入盟/2级建盟。 | **门派：Lv1 可入派 · Lv2 可立派 · Lv4 启门派任务 · Lv7 得门派兵种 · Lv10 开门派争锋。** |

### 3.1 等级 → 门派职能解锁表（新增，不动旧表）

| 等级 | 解锁 | 说明 |
|---|---|---|
| Lv1 | **入派** | 可从 §四 名录中择一派加入（得一派被动） |
| Lv2 | **立派** | 可自立门派（自定名，得"自立"专属被动，声望从零起） |
| Lv4 | **门派任务 · 日常** | 每现实日 1 次，得门派声望 + 材料 |
| Lv6 | **门派任务 · 阶段** | 每阶位一次，给声望 + 专属装备图纸 |
| Lv7 | **门派专属兵种** | 该派独有兵种 1 种（走 `DATA.TROOPS` 增补） |
| Lv10 | **门派争锋** | 与势力层/州域咬合（§九） |
| Lv12 | **门派名望** | 满级专精照旧 + 全城门派声望产出 ×1.25 |

> 判据：**Lv1/Lv2 的节奏沿用原 desc 的"1级入盟/2级建盟"**，只是把"盟"换成"派" —— 玩家侧的心智模型不变。

## 四、门派名录 `DATA.SECTS`

**取名口径**：本作世界观是**三国 + 江湖武侠**（江湖游历、武人、灵气、蕴养）。史实武林门派（少林/武当）**时代不符**，故建议**架空门派名**，风格与"绿林/豪杰/武人"一致。

| id | 门派 | 风格 | 专属被动（走既有 attr 键） | 专属兵种（Lv7） | 驻地（建议） |
|---|---|---|---|---|---|
| `he` | 玄鹤门 | 轻灵·身法 | 行军速度 +8% | 玄鹤游骑（轻骑上位） | 幽州 |
| `qing` | 青锋阁 | 锐击·兵刃 | 部队攻击 +6% | 青锋锐士（步兵上位） | 兖州 |
| `bai` | 百草堂 | 医道·生机 | 战后伤兵回复 +15% | 药锄队（工兵系） | 益州 |
| `hu` | 虎啸营 | 悍勇·强攻 | 攻城伤害 +8% | 虎啸死士（重步上位） | 冀州 |
| `xuan` | 玄机阁 | 机关·器械 | 器械打造耗时 −15% | 玄机连弩（器械上位） | 荆州 |
| `mu` | 牧云庄 | 蓄养·骑政 | 坐骑产出 +20% | 牧云铁骑（重骑上位） | 凉州 |

- `self`：**自立门派**（玩家自定名，被动 = 以上任选其一，但声望获取 −25%，体现"白手起家"）。
- 每派：`id / name / style / trait{key,val} / troop / homeState / lore(一句)`。
- 加入门槛：无（Lv1 即可）→ 引导玩家尽早接触新系统。
- **不引入门派互斥**：可退派改投（§七），代价见下。

## 五、数据模型与唯一出口

```js
/* 玩家侧（存档）—— 一人一派 */
s.sect = {
  pid: '',            // 门派 id（'' = 无门无派；'self' = 自立）
  name: '',           // 自立门派的自定名
  rank: 0,            // 品阶 0~4（§六）
  rep: 0,             // 门派声望
  joinDay: 0,         // 入派现实日（用于"改投冷却"）
  daily: 0,           // 日常任务已做（现实日）
  stage: {},          // 阶段任务完成表 { taskId: 1 }
  warWin: 0,          // 门派争锋胜场
}
```

**唯一出口**（每个语义只有一个函数，界面/文案一律读它）：

| 语义 | 出口 |
|---|---|
| 门派配置 | `GAME.sectCfg()` → `DATA.SECTS` |
| 当前门派 | `GAME.sectOf()` → `{pid,name,trait,...}` 或 null |
| 品阶（读表推） | `GAME.sectRankOf(rep)` → `{idx,name,need}`（**不存档品阶**，防"存档与表不一致"） |
| 声望增减 | `GAME.sectRepGain(src, n)` / `GAME.sectRepNeed()` |
| 门派加成 | `GAME.sectBonus(key)` → 数值（供 `genAttrs`/`attr` 链统一相乘） |
| 加入 / 自立 / 退派 | `GAME.sectJoin(pid)` / `GAME.sectFound(name,trait)` / `GAME.sectQuit()` |
| 任务 | `GAME.sectTaskList()` / `GAME.sectTaskRoll(id)` / `GAME.sectTaskDo(id)` |
| 争锋 | `GAME.sectWarList()` / `GAME.sectWarDo(pid)` |

> 沿用 §五 防守系统那套"**一个系统一组唯一出口**"的既有范式（`invasionTick` 等 7 出口），便于一次性写齐护栏。

## 六、声望与品阶

| 品阶 | 名称 | 所需声望 | 解锁 |
|---|---|---|---|
| 0 | 记名弟子 | 0 | 入派即得 |
| 1 | 入门弟子 | 300 | 门派任务·日常 |
| 2 | 执事 | 1,200 | 门派商店折扣 |
| 3 | 长老 | 4,000 | 门派兵种提前 1 级可用 |
| 4 | 掌门 | 12,000 | 门派争锋指挥权 |

- **声望来源**（全部走 `sectRepGain`，逐条给权重，便于审计）：门派任务（主）· 江湖游历活动（讨伐/切磋/试炼，与既有 `LING_ACT` 绑定）· 占城（与势力层咬合）· 门派争锋胜场。
- 品阶**不存档**、由声望实时推 —— 改表即生效，且不会出现"存档里写着掌门、声望却不够"。

## 七、互动流程（入口 = **城内门派建筑格**）

```
城内视图 → 点「门派驻地」格（复用 build-cell 点选，不改交互范式）
   └─ 门派菜单（弹窗，复用既有面板样式）
        ├─ 尚未入派： ① 加入门派（列出 §四 名录，含风格/被动） ② 自立门派（Lv2+，输入名）
        ├─ 已入派：   ③ 门派任务（日常/阶段） ④ 门派详情（品阶·声望·被动·专属兵种）
        │             ⑤ 退派改投（代价：声望清零 + 3 现实日冷却）
        └─ Lv10+：    ⑥ 门派争锋
```

- **为什么入口只放城内**（老板已裁定）：门派是"城内建筑职能"，与其它 15 座建筑的"点格开面板"完全同形，玩家不用学新交互；野地侧留给既有江湖游历，避免两处入口互相打架。
- 建立门派不另开玩法：**自立 = 加一个自定名 + 选定被动**，其余流程与加入完全一致（同一条代码路径）。

1. **专属兵种**（Lv7，每派 1 种）：向 `DATA.TROOPS` 增补条目，`unlock` 增加 `sect: 'he'`（**关键：解锁条件从"建筑等级"扩为"建筑等级 + 门派"**，需改 `canTrain` 一处判定，不改其它）。

## 九、门派战（单机化，Lv10）

| 玩法 | 单机实现 | 咬合点 |
|---|---|---|
| **门派挑战** | 挑战 NPC 门派"守擂"（一组带门派标签的守军，走既有战斗结算） | 复用 `GAME.battle` 与出征面板 |
| **门派争锋** | 占下某州城 → 该州门派声望 +X%/日；门派间"声望榜"（单机榜） | 与 §三 势力层共用"州"维度；势力层未落地也能先跑（按 `DATA.STATE_SPECIALTY` 的 13 州算） |

> ⚠️ **不做**：门派之间自动互攻（需时间轮 AI，且会把玩家晾在一边）—— 与势力层二期一起单独评估。

## 十二、数值出口与防错清单

1. 门派加成**只加进** `attr` 链的既有键（`prodPct/atk/def/marchSpeed/...`），不新增键名。
2. 兵种解锁：`canTrain` 由"单一建筑判定"改为"建筑 + 门派"**两条件与运算**，仍需**向后兼容**（无门派时行为与今天完全一致）。
3. 声望/品阶/任务全部经唯一出口，**界面不自己算**（护栏：断言 UI 里不出现 `rep >= ` 之类判据）。
4. 存档迁移：旧档无 `s.sect` → 视为"无门无派"，不做弹窗打扰。

### 16.1 两处口径按拍板修正
- **升阶难度**（老板「难度极大」）——把 §六 的品阶门槛上调为**陡峭曲线**：

| 品阶 | 名称 | 声望门槛（原 → 改） |
|---|---|---|
| 0 | 记名弟子 | 0 → 0 |
| 1 | 入门弟子 | 300 → **2,000** |
| 2 | 执事 | 1,200 → **12,000** |
| 3 | 长老 | 4,000 → **60,000** |
| 4 | 掌门 | 12,000 → **300,000** |

  即每阶门槛 ×5~6.7，**且声望只能靠日常任务/游历/占城/争锋慢积**（不做"一次任务跳两阶"）。

- **声望隔离**：门派声望 `s.sect.rep` 与君主声望 `s.rep` **分开存储、分开出口**
  （`GAME.sectRepGain` vs 既有君主声望出口），界面上也分局显示，避免两个"声望"互相解释不清。

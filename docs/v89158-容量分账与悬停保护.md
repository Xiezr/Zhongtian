> 老板原文（逐字）：
> 1.左侧资源统计的容量显示仍然不对
> 2.资源容量在悬停时闪烁（刷新数据了？），建议按悬停显示的那一刻的数据呈现即可，无需对悬停信息进行刷新（如果是这个原因的话），任何其他悬停显示可能都有这个问题，排查原因并采用更稳健方式构建

## 1. 病根（一句话 ×2）

**① 容量显示不对 = 三个界面各拼各的账 + 实际行为与显示不一致：**

| 界面 | 改前 | 问题 |
|---|---|---|
| 侧栏悬停 | `上限 366.7万（已占 1%）/ 其中城外堆场 +166.7万 / 现有 20,000` | 另外 200 万（基础）**没有出处**——账对不上 |
| 仓库面板 | `未建仓库：仅保有基础储量 366.7万` | "基础储量"里**混进了堆场**（口径混乱） |
| 仓库面板 | `仓库 · Lv0`（无仓库时） | 等级取 `buildingLevel`（最高一座），而容量按**等级和**算——两把尺 |
| 建造面板 cangku 行 | `本仓储量 = storeCap ÷ 等级和`（无仓库时 = 全额） | 公式坏：把城外堆场摊进"本仓"、无仓库时除以 1 得全额 |
| 建造面板 cangku 行 | `全境储量上限` | 标签错——v60 起仓储**按城**（不是全境） |
| **实际行为** | `R += 产; if (R > cap) R = cap` | **奖励类入账顶到上限之上的存量被下一 tick 静默削回**（实测 500 万 → 366.7 万，丢 133 万）——"超出部分将停止增长"的文案与代码不符 |

**② 悬停闪烁 = 每秒周期重绘用 `innerHTML` 重建容器，把鼠标下的节点换掉：**
节点一消失，原生 `title` 提示与 `#tip-layer` 浮层随之收起（鼠标不动时浏览器不会再触发 `mouseover`）
→ 视觉"闪烁"；CSS `:hover` 高亮也同秒重置。
实测（真浏览器）：`hover` 后 300ms 节点已被替换（`same=false`）、3 秒内反复替换。

## 2. 改法（改前 → 改后）

### ① 仓容分账（唯一出口 `GAME.storePartsOf`）

```js
storePartsOf(city) → { base, ext, total, lv }
  · base  = 仓库体系部分（含储存科技/仓专精/名城·爵位·主城·神器加成）——未建仓库时即"基础储量"
  · ext   = 城外堆场（纯加法，不吃仓储加成）
  · total = base + ext（= storeCapOf 的返回值，数值与改前逐字一致）
  · lv    = 本城仓等级之和（多仓叠加口径；buildingLevel 只给"最高一座"）
```
`storeCapOf` 变转发（`return storePartsOf(city).total;`）——一个概念一个取值口。

**三处显示同源：**

| 界面 | 改后（实测原文） |
|---|---|
| 侧栏悬停 | `粮食　上限 566.7万（已占 2%）` `· 仓库（2 级合计）：400.0万` `· 城外堆场：+166.7万（资源建筑按等级所出 · 不吃仓储加成）` `现有 123,464` —— **400.0 + 166.7 = 566.7 账目自洽** |
| 仓库面板 | `🏚️ 仓库 · Lv2（多仓叠加）` ／ 未建时：`仅保有基础储量 200.0万；城外堆场另计 +166.7万，合计 366.7万` |
| 建造面板 cangku | `本座储量 4,000,000（Lv2）` ＋ `本城储量上限 5,666,667（多仓叠加）` |

### ② 只封增长、不削存量（三处结算同改）

```js
/* 改前 */ R = R + 产; if (R > cap) R = cap;            // 超上限的存量被削回
/* 改后 */ if (gold || !cap) R += 产; else if (R < cap) R = Math.min(cap, R + 产);  // 到顶停涨；已有存量保留
```
落点：`tickOnce`（在线）/ `simulateBulk`（离线补算）/ `simulateOfflineOverflow`（离线溢出五折）。

### ③ 悬停保护（唯一出口 `ui.hoverHold`）

```js
ui.hoverHold(sel)  // 鼠标悬停在该容器内 → 本秒"周期性重绘"整块跳过
```
- **只在主循环窗口生效**（`ui._tickPaint`）：操作驱动的重绘（点"+"用宝物 → refreshAll）**永远放行**——
  否则"操作后的刷新"会被悬停挡住（点了 1 秒后才更新）。
- 桩环境（jsdom 无 `:hover`）→ 不保护（行为与旧版一致）；测试用 `ui._hoverOf` 注入。
- ⚠️ 取 `:hover` 链最深元素必须用 `querySelectorAll(':hover')` 取**最后一个**
  （`querySelector(':hover')` 返回文档序第一个 = html，永不命中）。
- **9 处接入**：`renderResBar` / `renderGarrison` / `renderCityAttrs` / `renderWildPick` / `renderLog` /
  `liveModalTick`（弹窗每秒重开）/ 军务总览 + 将领视图（main.js 两处）/ `syncHeader` 头像与天时行
  （后两处改"内容不变不重建"）。

## 5. 诚实缺口

1. **悬停期间数字不更新**（老板钦点口径）：悬停区每秒不再刷新，移开即恢复。
   若某类"必须实时"的读数（如倒计时）出现在悬停区内，需单独放行。
2. **采集收获仍 clamp**（装不下即丢弃、无提示）——与"奖励类允许超上限"并存的口径差；
   是否改为"提示"或"允许超"，等试玩口径。
3. **市场买入 / 市易 / 纪事奖励不 clamp**（允许超上限）：修复"不削存量"后不再静默丢失；
   "买入超上限要不要拦"属设计决策（未动）。
4. `已占 X%` 在超上限时显示"已满"（不再出现"已占 123%"这类读数）——想看真实百分比可改一处。

# 自检体系架构（v157.28 · 2026-11-10）

> 老板令：「自检体系架构」。
> 本文是这套体系的**活文档**：分层、入口、判据、成本、盲区，以及本轮修掉的两个体系缺陷。
> 一条硬约束：**架构必须能被一条命令验证** —— `node tools/selfcheck.js --layers`（本文 §八）。
> 纸面架构不算数，能跑、能红、能被一脚踢开才算。

---

## 一、结论先行

1. 体系是 **七层 + 一个判据出口**：L0 结构契约 → L1 数值规则 → L2 不变式 → L3 状态剧本 →
   L4 链路 → L5 真实 DOM → L6 实机/长跑，最上面 **L7 元判据（六问）审前七层**。
   判据唯一出口是 `gate.py`；其余全是**内环加速器**或**观察器**，不参与"能不能提交"的判定。
2. **这套体系在今天早上是死的。** 元判据 Q3 审的是"分片覆盖"，而门禁跑的是"串行全量"——
   审的对象与判据的链条不是同一条，于是 `gate.py --full` 在跑任何测试之前就 `return 1`，
   任何提交都过不去（实测 `gate_exit=1`，只打印"体系自身不自洽"）。已修，见 §六。
3. 修完门禁恢复可用（**本轮实测**）：
   ```
   ✅ 元判据：体系自洽（1 处提醒：分片记录缺版本签名，不可比）
   ✅ audit 全 0 · ✅ chain 47/0 · ✅ invariants 40/0
   ✅ smoke 4458 通过 / 0 失败（另 12 待修 / 1 跳过）
   ✅ e2e 1104 通过 / 0 失败 · ✅ 数据表四查 · ✅ dataset 66/0 · ✅ 兵种链 0
   并发 8 个脚本，墙钟 707.8 秒 → ✓ 门禁通过
   ```
4. 三个真实软肋没变，只是这次被量化了：
   **27.8% 的断言是"实现类"（红了只 ⚠️ 不阻断）**、
   **smoke-test.js 单文件 47,905 行（自订阈值 5000，超 9.6 倍）**、
   **3D 完全没有视觉回归**（海波/半径两次事故只能靠人眼）。
5. 判据原则（架构的宪法）：**内环可以快、可以漏，但不能冒充裁判**；
   裁判只有一条链 —— 串行全量 + 基线只拦新增 + 抖动复跑确认 + `--strict` 可推翻。

## 二、七层的职责与入口

| 层 | 回答什么问题 | 入口 | 耗时 | 判据 | 进 gate？ |
|---|---|---|---|---|---|
| **L0 结构契约** | 有没有死函数 / 孤儿按钮 / 重复定义 / 零引用字段 / 引用了不存在的成员 / 数据表四查 / dataset 引用 / 兵种链 | `audit.js` · `audit_v89134_tables.js` · `audit_v89179c_dataset_refs.js` · `audit_v89229b_troopchain.js` | 1~2 秒/个 | 计数全 0 | ✅ 常跑（未改代码也跑） |
| **L1 数值规则** | 「改数据 → 结果必须跟着变」 + 调参接线/曲线护栏 | `.workbuddy/tools/fast/fast-test.js`（20 条）· `.workbuddy/tools/prof/param_probe.js`（955 叶子 × 7 出口） | **0.16 秒** / 探针 ~3 秒 | 20 条 0 失败 · 探针 0 死字段 | ❌（内环第一道） |
| **L2 不变式** | 守恒律在随机输入下成不成立（兵力不增 / 账实相符 / 资源封顶不削存量 / 背包下界 / 扣费精确 / 纯函数） | `invariants-test.js` | ~6 秒 | 反例自动收缩，0 反例 | ✅ |
| **L3 状态剧本** | 4.4k 条有状态的行为断言（世界只有一个，段间共享可变 state） | `smoke-test.js` / `smoke_fast.js` | 串行 **~8 分钟** · 分片 4× **261 秒** | 0 失败（实现类计 ⚠️） | ✅ **串行全量** |
| **L4 链路** | 单点都对、串起来断不断（派队 → 行军 → 抵达 → 落账） | `chain-audit.js` | ~2 秒 | 0 失败 | ✅ |
| **L5 真实 DOM** | jsdom 里真点按钮 / 真派事件 / 真渲染 | `e2e-test.js` | ~3 分钟 | 0 失败 | ✅ |
| **L6 实机** | 玩家真走的那条路：渲染性能 / 弹窗几何 / 像素 / 世界长跑 | `audit_v125b_perf_ui.js` · `audit_v89105_modals.js` · `visual_baseline.js` · `sim/sim-run.js` · `playtest/*` · `mutation_probe.js` | 30 秒 ~ 数小时 | 各自 0 问题 / 像素一致 / 里程碑无卡死 | ❌ **手动，按需**（见 §七 G4） |
| **L7 元判据** | 前七层有没有在骗人（假绿 / 到期 / 覆盖 / 膨胀 / 可推翻 / 视觉） | `.workbuddy/tools/prof/tier_audit.js` | 0.5 秒 | 六问无 red | ✅ **先于一切**（体系不自洽 → 直接拦） |

**为什么是七层而不是一条大脚本**：每层失败时的"追责单位"不同 ——
L0 是"代码结构坏了"，L1/L2 是"数值/不变量坏了"，L3 是"某个玩法分支坏了"，
L4 是"两个模块接不上"，L5 是"玩家点了没反应"，L6 是"玩家看着不对"。
混成一条，红了也说不清是谁的问题。

## 三、判据体系（架构的宪法）

| 机制 | 规则 | 落点 |
|---|---|---|
| **三档断言** | 行为/契约红 = 必须修；实现类（DOM 类名 / 源码正则 / CSS 字面量）红 = ⚠️ 待修不阻断 | `.workbuddy/assert-tiers.json`（键 = `djb2(标题)`） |
| **基线** | 只拦"不在此表"的**新增**失败；基线必须人工更新，且带 since / 谁该修 | `.workbuddy/gate-baseline.json`（**当前为空 = 正常态**） |
| **抖动复跑** | 首跑红 → 单独复跑；复跑绿 = ⚠️「不稳定」放行但**可见**，绝不静默当绿 | `gate.py` `flaky` 分支 |
| **可推翻** | `smoke --strict` 忽略分档、`gate --strict` 忽略基线 | 一个从没被用过的开关 = 没有开关 |
| **跳过 ≠ 通过** | 判不得 → `skip(名, 原因)` 单独计数；`check(名, true)` 禁止 | Q4 盯跳过数（上限 12） |
| **元判据前置** | 六问任一 red → 不跑任何测试 | `gate.py` 元判据段 |
| **版本绑定**（本轮新增） | census 的"全量/分片"记录各带 `smoke-test.js` md5；不一致 → 判据降为"不可比"提醒 | §六 |

## 四、入口与成本阶梯（该跑什么，跑多久）

```
改一行数值        0.16 秒   fast-test                ← 只证明"字段真被消费"
改一个模块        2 秒      audit                    ← 结构/契约
改一段逻辑        261 秒    smoke_fast（4 分片并行）  ← 加速冒烟，不当裁判
改完准备提交      ~12 分钟  gate.py --full           ← 唯一裁判（8 脚本并发 + 元判据 + 复跑）
定时（每小时）    ~1.5 分钟 tools/selfcheck.js --fast ← 观察器（bundle/清单/体积/棘轮）
大改 / 世界层改动 分钟~小时  sim-run 240 月 · playtest 驾驶舱 · mutation_probe
视觉/界面        30 秒~     perf_ui · modals · visual_baseline
```

实测耗时（本项目）：fast 0.16s · audit 2s · chain/invariants/dataset/兵种链 各 1~2s ·
smoke 串行 458s · e2e 3min · **gate --full 本轮实测 707.8 秒（11.8 分钟，8 脚本并发）**。
**验证成本的地板是 smoke 的 8 分钟**，所以架构上要尽量把"能秒级判的"挪到 L0/L1 —— 而不是让每轮都等 8 分钟。

## 六、本轮修掉的两个体系缺陷（v157.28）

### 6.1 元判据审错了对象 —— 门禁被自己锁死

**现象**（实测，不是推测）：
```
$ python .workbuddy/tools/git/gate.py --full
❌ 元判据：验证体系自身不自洽 —— 先修体系，别信它的结论
   Q3 ❌ 分片漏跑 3 条断言（集合比对：全量 4420 / 分片 4440）
$ echo $?  → 1
```
门禁在跑任何测试之前就退出了 —— **任何提交都过不去**。

**病根不是那 3 条断言，是层错配**：
- Q3 审的是 **分片**（`smoke_fast` 的 4 份并行结果）；
- 门禁跑的是 **串行全量**（`run_many` 里的 `smoke-test.js`，一份进程）；
- 分片结果从不进入门禁判定 —— 它只是内环的加速器。
  拿"加速器的完整性"去否掉"裁判的结论"，等于用体温计判血压。

**改法**（两处，均在工具层，产品代码零改动）：
1. `gate.py` 起 `tier_audit.js` 时注入 `GATE_SCOPE=1`；
2. `tier_audit.js` 的 Q3 分级：跨版本/缺签名 → ⚠️（不可比）· 门禁作用域 → ⚠️（不阻断，注明"分片只服务内环"）·
   **同版本 + 内环作用域 + 真缺段 → 仍然 ❌**（这是内环唯一结论，必须红）。

判据没有被放水：**同一份缺段证据，在内环仍然是红的**；只是不再拿它去否决一条不读分片的链。

### 6.2 census 没有版本绑定 —— 用旧尺子量新代码

**证据**（三个时间戳来自三个版本 —— 修复前）：

| 记录 | 时间 | 条数 | 签名 |
|---|---|---|---|
| 全量基线 `fullAt` | 2026-11-08 01:30 | 4425 | 无 |
| 分片记录 `lastSplit.at` | 2026-11-09 05:11 | 4447 | 无 |
| 当前 `smoke-test.js` | **2026-11-10 01:19** | — | `967bcd77e06b` |

那"漏跑的 3 条"（§308⑩ 荒废塌房 / §243① map3d 缩放出口 / §250② buildFlags 分片）是**版本差异**，
不是分片漏段 —— 但旧判据没有任何字段能分辨这两件事，只能一律报红。

**改法**：
- `gate.py` 写 census 时记 `fullSig`（`smoke-test.js` md5 前 12 位）；源码一变，旧的 `titles` 集合
  自动作废（否则它会被拿来跟新分母比）；
- `smoke_fast.js` 写 `lastSplit.sig`（同一算法）；
- `tier_audit.js` 比对签名：不一致 → 判据降为"不可比"，并明确要求"重跑重建同版本分母"。

**修后状态**：`fullSig = 967bcd77e06b`（本轮 gate 写入）；分片记录仍是旧的（无签名）→
Q3 现在报"⚠️ 不可比"。**下一次 `smoke_fast` 跑完即自动对齐**，届时 Q3 恢复"同版本比集合"的硬判据。

这样 Q3 的四种状态各自可读：**同版本绿 / 同版本缺段红 / 跨版本不可比 / 缺签名提示重建**。

### 6.3 顺带确认的边界（没有改）

- 元判据仍然**先于一切**（体系不自洽就不跑测试）—— 这个顺序是对的，本轮只是让它别审错层。
- `--strict` 语义不变：忽略基线、不接受"复跑绿"。
- 产品代码 0 行改动；改的只有 3 个工具文件（`gate.py` / `tier_audit.js` / `smoke_fast.js`）。

## 九、调参自检（三轮协议 · v157.29 立）

调参不是"把数字调舒服"，是**先在一条可信的尺子上量，再决定改不改**。三轮各问一件事，顺序不能换：

| 轮 | 问什么 | 工具 | 判据 | 发现后修什么 |
|---|---|---|---|---|
| **R1 接线** | 我调的这个数，**接到出口**了吗？ | `param_probe.js`（933 叶子 × 7 出口）· 源码引用计数 | 死字段 = 源码零引用 **且** 出口无反应 | 删字段（留墓碑指唯一出口），或补接线 |
| **R2 口径** | **尺子本身**对不对？ | `economy_audit.js` · `ladder_audit.js` · `fast-test.js` | 判据必须与**设计口径**一致（多城推进 / 12 级循环都是设计，不是 bug） | 改判据，不改产品；真异常才动数值 |
| **R3 守门** | 这些关系**锁住**了吗？ | `fast-test.js` | 一条关系一条断言；改设计必须改断言 | 补断言（不许删、不许放宽） |

**本轮（v157.29）产出**：

| 轮 | 发现 | 处置 |

## 二、文档三分类与卫生规则（v89.236 立）

| 类 | 位置 | 收什么 | 例 |
|---|---|---|---|
| **活·规范/台账/资产** | `docs/` **顶层（18 份）** | 正在被引用、需要持续更新的 | 设计规范 · 术语映射表 · 图标素材注册表 |
| **历史档案** | `docs/_史料/` | 时点快照 + **逐轮交付记录**（`_史料/交付/`） | 设计史 · v89.235 交付文档 |
| **参考** | `docs/_参考/` · 数值字典 · 出图prompt | 设计输入 / 溯源资料 | 源游戏检索报告 |

**卫生规则**（新轮次照此办理，防顶层再堆历史）：
1. **每轮交付文档直接写进 `docs/_史料/交付/vXXXX-*.md`**（不再堆顶层）；
2. 活文档只在"它还是当前事实"时留顶层；被换代/降级的迁 `_史料/`；**过时材料清理**先备份到 `.workbuddy/backup/`；
3. 引用面随迁随修（路径改写 / 已清理标注），`grep` 复扫零悬空；
4. `需求档案.md` 是逐字铁律档（老板原话），只增不改写。

## 五、一页速查

```
改完代码必须跑（缺一不可）：
  node audit.js                     # 结构：死函数/孤儿按钮/重复定义/零引用字段 全 0
  node chain-audit.js               # 链路走查：基线 47 通过 / 0 失败
  node invariants-test.js           # 守恒律属性：基线 28 通过 / 0 失败（每性质 30~80 例随机）
  node smoke-test.js                                           # 基线：4157 通过 / 0 失败
  NODE_PATH='…\node\workspace\node_modules' node e2e-test.js    # 基线：1132 / 0
  python .workbuddy/tools/git/gate.py --full    # 上列五件套 + 数据表卫生 + dataset 引用 + 兵种链

生成器（路径已带子目录）：
  node .workbuddy/tools/gen/gen_bitmaps.js         # 扫 assets/icons/ui/ → js/bitmaps.js（+ 注册表台账）
  python .workbuddy/tools/gen/gen_tools_index.py   # 重生成工具索引
  node .workbuddy/tools/gen/gen_tables_index.js    # 重生成数据表索引
  node .workbuddy/tools/gen/gen_v89125_build_times.js · gen_v89194_price_table.js   # 两张台账表

同步到 GitHub（收尾唯一入口，默认干跑；门禁不过就不提交）：
  python .workbuddy/tools/git/sync.py                      # 干跑：先看将提交什么
  python .workbuddy/tools/git/sync.py --apply              # 真做：门禁 → 提交 → 推送

两个钩子（安装：python .workbuddy/tools/git/install_hooks.py）：
  pre-commit   提交前跑门禁（改 js/ 或 index.html 才全量；否则只跑 audit）；跳过一次：SKIP_GATE=1
  post-commit  提交后自动推送（后台）；关闭：GIT_NO_AUTOPUSH=1

动手前先问三句：
  ① 这东西有没有唯一出口？（MEMORY §一.8 清单）→ 有就改出口，别改引用处
  ② 我改的是规范还是史料？（`设计规范.md` 才是规范；逐轮交付只进 `_史料/交付/`）
  ③ 改完能不能翻转？（破坏测试注入一次，确认断言会红）
```

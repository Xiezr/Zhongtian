## 0. 先认账：「驻军丢失」的真因与修复（本轮最高优先）

**病根一句话**：v89.135 把「驻军开采」从**从驻军抽兵、收获时还兵**改成了**原地开工、不抽不还**，
但**两代采集记录形状完全相同**（都是 `origin:'garrison'` + `army`，没有版本标记）——
老板档里 v89.135 **之前**创建、还没收获的采集队（兵被抽走在队里），在新代码下点「收获」
→ 兵不回驻军 = **凭空消失**。

**修复（双保险）**：

| # | 位置 | 做法 |
|---|---|---|
| ① | `GAME.migrateLegacyGathers`（新出口） | 读档 / 首 tick 把旧式记录**就地转为新形态**：兵按 `noCap` 加回驻军（野地已易主则回城），标记 `inPlace:true`；幂等（`s._gatherMigrated`） |
| ② | `finishGather` / `abandonGather` 防御分支 | 万一仍有旧式记录被结算 → 按**旧口径还兵**（回驻军，溢出回城）。正常不可达，保命线 |
| ③ | `startGather` 新记录 | 显式写 `inPlace: true` —— 从此"兵在驻军"与"兵在队里"再无歧义 |

**回归断言**（smoke §27）：`【驻军丢失回归】旧式记录收获 → 兵力回驻军（防御分支 · 不丢兵）` +
`【驻军丢失回归】迁移：旧式 → inPlace + 兵力回驻军（幂等 · 一次）` —— **两条都真造旧式记录真跑**。

### 1.3 战斗界面：双方将领 + 悬停六维 + 记录修复 + 结束入流

## 二、架构速览

### 加载方式（v104 起**三包**）
`index.html` 只加载 4 个脚本，**顺序即求值顺序**：

```html
vendor/three.min.js → js/bundle-core.js → js/bundle-war.js → js/bundle-ui.js
```

- **bundle-core**（**53 个模块**）：数据 + 状态 + 领域 + 全部玩法模块（开局就要）
- **bundle-war**（9 个）：`gltf / battle / battlelog / strategy / tactic / icons / gicons / bitmaps / portraits`
- **bundle-ui**（5 个）：`story / ui / map3d / scene3d / main`（必须最后，**`main.js` 是动作层不是入口脚本**）

> 分包只解决「单文件撞线」，**不改求值时机**（全项目 200+ 探针按顺序拼接求值，动态 import 会打破它）。
> 拆分依据在 `.workbuddy/tools/patch/build_bundle.py` 的 `ORDER / WAR / UI` 三张表。

> ⚠️ **改任何 `js/*.js` 后必须重建三包**：`python .workbuddy/tools/patch/build_bundle.py`
> 校验：`build_bundle.py --check` → 应报「三包与源码一致」。
> **新增模块要同步四份静态清单**：`build_bundle.ORDER` + `smoke-test` 的 ORDER +
> `audit.MODULES` + `audit.REF_MODULES`（漏了会被 audit 误报「引用了不存在的成员」）。

### 附：v151–v156 渲染问题根因链（同一个现象报了 8 次，逐条留档）

> 这段是给下一位的"别再走弯路"：**先分层隔离（隐藏其它对象 / 像素读回），再改那一层**。
> 本轮我前三次都是"看到现象就改最可疑的那层"，改对了两个真 bug，但都不是老板看到的那一个。

| # | 现象 | 真因 | 修法 |
|---|---|---|---|
| 1 | 出生点在海里 / 点哪都说没探明 | 出生点选址在**球面建成之前**算（读上一局地形）；且雾被当墙 | 新局顺序改成 种子→建球面→算出生点；雾只遮信息不挡路 |
| 2 | 前传点地图不走路 | 3D 拾取 `pickAt` 没有前传分支 | 加前传分支 → `P.mapClick` |
| 3 | 相机贴地却看不中格子 | `setZoom(0.02)` 被 `centerOn` 里的 `R*1.9` 覆盖；且 `_focus` 让 `dist` 语义从"距球心"变"距那一格" | 局部坐标系绕行 + `dist` 钳 R+2 |
| 4 | 整颗球发白 | 渲染器 `outputColorSpace=SRGB` + 顶点色按肉眼 sRGB 写入 → **编码两次** | 关输出色彩转换 + 关 ACES |
| 5 | 黄的地其实是森林 | 分类（高度+纬度）与上色（高度色带）是**两条独立路径** | `climateOf` 三元组同时决定类型与颜色 |
| 6 | 海面只有色彩变化 / 毫无波澜 | 波相位用了 `normalize(position)`（点积范围仅 ±1）→ 相位几乎不变 | 改用**世界位置**做相位 |
| 7 | 波浪是规律条纹 | 五条正弦相位线性 → 等相位线是直线 | 域扭曲 + 慢变包络 + 相位抖动 |
| 8 | 省市区边有重影 | 另画了一层 `LineSegments`（另一套顶点） | 删掉，改成给**地块自己的边**上色 |
| 9 | 地块浮在地表上 | 顶点抬 `PLATEAU 0.5~0.6` | 0.05 + 共享顶点高度表 + `polygonOffset` |
| 10 | **球面一条笔直分界** | 改成 `FrontSide` 后，cube-sphere **六个面参数化方向不一致**（有的镜像）→ 绕向反的面被剔除 | 逐面探测绕向并翻转索引 |
| 11 | **球体整个透明**（上一条的回归） | 绕向探测用 `(b-a)×(c-a)`，而实际索引顺序是 `(a,c,b)` → **全反** | 判定挪进 `SP.faceFlipOf`，按实际顺序求叉积；**§578⑧ 钉住六面朝外** |
| 12 | 六边形内有三角形（报了 3 次） | 前两次错怪水面深度/地形绕向；真因是**雾层按三角面收集且每格只留第一个** → 只铺了 1/6 格 | 按**格索引**收集 + `makeMesh` 铺整块六边形 |
| 13 | 海洋陆地交界不对劲 | ①"远看换整球"把低洼陆地淹了 ②水面与海床只差 0.02 → 深度打架 ③浪切进沙滩 | 只用水格几何；抬到 R+1.0 + `polygonOffset`；**离岸距离场 `uCoast`** 让岸边浪高归零 |
| 14 | 地标是"乱飘的点" | 营地/村社/遗迹都是 `SphereGeometry` 小球，画在格心上方 3~5 单位 | 改**整格涂色**（`buildCellTint`，每格一个六边形色罩） |

**两条可复用的排查姿势**：
- **分层隔离**：`scene.children.forEach(o => o.visible = false)` 然后逐个打开，看哪一层画出来的东西不对；
- **像素读回**：`ctx.getImageData` 扫全屏统计"与周围明显不同"的像素占比，用数字判断某层是否在漏。

## 六、必守约定 / 常见坑（全是踩过的）

1. **改 js 必须重建三包**；否则 smoke 的陈旧守卫红。
2. **`js/*.js` 保 LF**：CRLF 会挂 smoke 的 `\n` 正则断言（`build_bundle` 与 smoke 两侧已做换行归一再算 hash，
   但**编辑器/脚本重存**仍会污染行尾 —— 用 `newline=''` / `newline='\n'` 显式写）。
3. **禁止正则批量改「键名是变量」的代码**（v91.69：`army[k]` 被写成 `{ k: … }`，25 处静默错兵）。
4. **SSOT**：一个数/一处逻辑只有一个出口；**界面与执行端读同一出口**
   （`goalMod` 是所有战场加成的唯一通道；`ui.expModeAvailOf` ↔ `battle.prepare`）。
5. **设计令牌 lint**：`index.html` 样式表禁裸 px/hex/字号/圆角；网格/canvas 视图用**内联 style** + `var(--*)`。
6. **改规则就改断言口径，别删断言、别放宽到失去意义**（v149.2 有一次把 `||` 写成"标题出现过"就当场被抓）。
7. **版本三连**：`bump_version.py --bump --version vX.YY`；**台账手补**「逐轮明细」+ `LATEST-BATCH` 锚点
   （smoke §199⑥ 校验主版本与 `GAME.VERSION` 一致）。
8. **性能护栏**：`100 城 tickOnce` 取三轮最小值 < 6ms；新增逐城逻辑别破坏它。
9. **`GAME.city.add` 不吃负数**（内部 `n>=0 ? … : 0`）—— 扣资源一律用 `GAME.city.sub`。
10. **「手写字段清单」的打包函数**（`snapUnits` / `simOpts`）必须逐字段核对，漏一个就是静默失真。
11. **新增模块**：四份静态清单都要登记（见 §二末）。
12. 🔴 **产物指纹守卫（v150.1 新增）**：`bundle.hash` 除源码 hash 外还记三包各自 sha256。
    原因是 v150.0 真的漏提交了 `js/bundle-war.js` —— 源码提交了、hash 对得上、**线上跑旧包**，门禁全绿。
    现在 `--check` 与 smoke 都会核对磁盘上的包；**提交前确认 `git status` 里三包都在**。
13. ⚠️ **战斗会话 `GAME._bsess` 是全局内存对象**，换 `GAME.state` 不会清 —— 测试里换局必须手动
    `GAME._bsess = {}`，否则上一局的会话会按 `rec.id` 命中（v150 的 §574 就这么假红过）。
14. ⚠️ **战斗夹具找野地要够远**：只扫 13~20 环时有些地图种子找不到，用例会**静默 return null 假红**。
15. 🔴 **换格网要写迁移**：存档位置全用 `ci`；改细分/换格网后同一个 `ci` 会指到别块地。
    口径 = **按经纬重落**（`GAME.migrateSphereSub`），幂等标记 `_sub153`。
16. 🔴 **`FrontSide` 之前先确认绕向一致**：cube-sphere 六面参数化方向不同（有的镜像）。
    绕向判定**必须按实际 push 的索引顺序**求叉积 —— 用错顺序就是整球透明（v155.6 真事）。
    现成的判定在 `SP.faceFlipOf(fn, du)`，smoke §578⑧ 守着"六面朝外"。
17. ⚠️ **`MeshBasicMaterial` + `FrontSide` 省一半像素**，但**任何双面几何改单面前都要核对绕向**。
18. ⚠️ **深度差 < 0.05 的两个面会打架**（水面 vs 海床实测 0.02 → 三角碎片）。
    同高度的重叠面要么拉开距离，要么用 `polygonOffset`。
19. ⚠️ **改渲染前先分层隔离**：隐藏其它 `scene.children` 逐个开、或用 `getImageData` 像素读回；
    不要"看现象改最可疑那层"（本轮因此错了 3 次）。
20. ⚠️ **`buildXxx` 里"先读后写"的顺序坑**：涂色表 `_tint` 在函数后半段才填，
    构建层若放在前面就是空层（v156 真事）。凡是"收集→构建"的函数，构建**一律放末尾**。

## 九、工作方式（老板偏好）

- **别磨、果断执行**：先一次想全约束/依赖/可行解；探查并行一次到位；别增量试错、反复预览、过度拆分。
- **不清楚就问**：边界不明/多种可能时先问，且**一次问全**（用 AskUserQuestion）。
- **视觉/布局改动**：先截图或量尺寸定位，再改代码。
- **大改先落可验收子集**：每刀过门禁再下一刀，不把半成品留在工作区。
- **「能做的全做」= 按清单一次做完**，但**不擅自 invent 数值**；需要拍板的列清单交回。
- 改完立即跑五件套；报红先判断「口径该更新」还是「真回归」。
- **视觉问题先隔离再改**：隐藏其它 `scene.children` 逐个开 / `getImageData` 像素读回，
  用数字定位到"是哪一层在画"。本轮同一个现象报 8 次，前 3 次都是"看现象改最可疑那层"改错了层。
- **改完必须回看实机截图**：门禁绿只证明"能跑、不报错"，不证明"看得对"（v155.5→v155.6 的整球透明就是这样漏过去的）。
- **收尾六步**：备份 → 重建三包 → 五件套 → bump + 手补台账 → 同步接力卡与本文件 → （涉及出征/自动出征则同步 `docs/出征界面汇总.md`）。

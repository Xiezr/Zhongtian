# 世界生成顺序（v156.71）

> 一句话：**世界不是一次"生成"出来的，是六层按序落成、每层各有不变量。**
> 任何一层变了，下游必须失效重建 —— 这条靠"世界版本号 + 自检"保证，不靠调用方自觉。

## 为什么要写这份文档

老板的原话：「步骤性建立世界生成顺序，星系，星球，地形，地块，省市区划分等。
自检这个过程。**不能生成 10 个星球，10 个都有问题吧**。」

背景：省市区边界"飘出地面"。查下来是两层原因叠加 ——

1. `_rimHMap`（线框高度表）的键是**ico 格心方向**，而格心方向只跟细分等级有关、**跟 seed 无关**。
   换星球后键 100% 命中旧值 → 线框按**上一颗星球**的地形抬升 → 新地形上飘出或埋入。
2. `setPlanet()` 有 **8 个调用点**，全靠调用方记得再 `rebuild()` 一次；漏一个就是
   "数据换了星、画面还是上一颗"。分层自检实测：这种脱节下，线框相对地形的偏差达 **11~25 单位**。

两条都不是"手滑"，是**层间契约缺失**。所以这份文档定义契约。

---

## 一、分层顺序（不可跳步）

```
L0  星系 / 星球参数     seed + PLANET{mountain, oceanDepth, contCount…}
      │                 ↓ 决定一切随机场
L1  球面细分（几何）      icoSpheres(sub) → V(顶点) F(面) cent(面心) adj(邻接) vf
      │                 ↓ 只依赖 sub，与 seed 无关（这点很关键）
L2  地形场              contField → seaLevel → mountainField → fbm 细节
      │                 sphElev(dir) 是**唯一出口**
      │                 ↓ 依赖 seed + PLANET
L3  地块（cells）       每格 type / lon / lat / 高度；cellType 与 sphBiome **同源**
      │                 ↓
L4  地块几何            upos(线框) / fpos(拾取面)，贴地形；区域边界复用 upos
      │                 ↓ 这一层是"渲染层"，必须与 L2/L3 同源
L5  行政划分            genSettlements：省(≈12~16) → 市 → 区，球面 k-means + 域扭曲
      │                 ↓ 只分陆地；海面按最近省心并入省
L6  渲染物              网格/线框/边界着色/标签/城
```

### 每层的输入、产物、不变量

| 层 | 入口 | 产物 | 不变量（必须为真） | 违反后果 |
|---|---|---|---|---|
| L0 | `SP.setPlanet(seed, params)` | `_seedOverride` / `PLANET` | seed 取模 100000 与 `state.map.seed` 同口径 | 两处用例不同地形（"地形按 A、城市按 B"） |
| L1 | `icoSpheres(sub)` | `V/F/cent/adj/vf` | 只依赖 sub；**任何以它为键的缓存都必须带 seed 校验** | 换星球后缓存命中旧值（本次 bug） |
| L2 | `sphElev(dir)` | 归一化高度 | 无 NaN；陆地 5~92%；有起伏 | 全海/全陆/平地 |
| L3 | `build()` 内 | `cells[]` | 每格有 type；邻接对称 | 点击判定错格 |
| L4 | `map3d.rebuild()` | `_globe` / upos | `_worldSeed === seed3()`；线框边中点相对地形 p90 ≤ 1.5 | 线框悬空/埋地（视觉"飘"） |
| L5 | `genSettlements()` | `provOf/marketOf/districtOf` | 省市区 ≥1；陆地 100% 有省；区不跨市、市不跨省 | 三不管地带、行政飞地 |
| L6 | 同 L4 | 场景对象 | 与 L4 同源 | 画面与数据不一致 |

## 二、失效传播（最容易漏的一环）

**规则：key 与 seed 无关、value 却依赖 seed 的缓存，必须带 seed 校验。**

已按此规则审过并修好的：

| 缓存 | 键 | 值 | 状态 |
|---|---|---|---|
| `SP._rimHMap` | 格心方向（与 seed 无关） | 地形高度（与 seed 有关） | ✅ v156.70 加 `_rimSeed` 校验 |
| `SP._seaCache` | — | 海平面（随 seed） | ✅ 原有 `_seaSeed` 校验 |
| `SP._xyCi` | 平面格坐标 | 球面 ci | ✅ 重建时清空（v139 已修） |
| `M._settle` | — | 省市区结果 | ✅ `_settleSeed` 校验 |
| `M._globe` / upos | — | **整块网格** | ⚠️ 靠 `worldVer` 握手（见下） |

`SP.worldVer`：每次 `build()` 完成 +1。`M._worldVer` 记录建网格时的版本。
自检的 L4 就是比对 `_worldSeed` 与 `seed3()` —— 这是"渲染层有没有跟上数据层"的唯一客观依据。

## 三、自检怎么跑

```bash
# 10 颗星球，六层全量
node .workbuddy/tools/probe/gen_audit.js 10
```

产物：`.workbuddy/tmp/gen_audit.json`（逐星球明细）。

检查逻辑在 **产品代码** `GAME.map3d.selfCheck(seed)` 里，不在工具里 ——
因为地形/地块/省市区大量状态是闭包私有，外部探针读不到
（实测踩过：数据都对、返回值拿不到，报告全红其实是探针自己造的）。

### 自检本身也要被检验

**全绿可能是检查器坏了。** 所以每次跑都做一次**故障注入**：
把 `M._worldSeed` 改成 `-12345`（模拟"网格还是上一颗星球"），
L4 必须报「渲染与数据不同源」。抓不到就说明检查器失效，绿灯不算数。

> 第一版反例用"跳过 rebuild"造脱节，结果没抓到 —— 因为其它路径会间接触发渲染重建，
> 时序不可控。改成直接注入才稳定。**验证手段本身不可靠时，先修验证手段。**

## 四、已知缺口（明确没做）

1. **`setPlanet` 的 8 个调用点仍未统一**
   现在靠 L4 自检"事后发现"，没有做到"自动重建"。彻底做法是在渲染循环里比对
   `SP.worldVer !== M._worldVer` 就重建；但会引入每帧判断与潜在递归，暂未做。
   当前策略：**自检兜底**（跑一次就能发现漏了谁）。

2. **星系层（L0 之上）没有独立自检**
   目前只验证"单颗星球内部六层"。"一个星系里有几颗星球、星球之间参数是否重复"
   还没有检查项。素材：`domain.js` 的星球生成、`state.planets`。

3. **省市区没有"沿地形特征"的约束**
   现在是球面 k-means + 域扭曲，边界平滑但**不知道山脉河流**。
   老板质疑的"不是依据地形划分"在这一点上是成立的。若要沿地形，
   需要把 `sphElev` 的梯度作为距离权重（山脊线加权），属新特性而非修 bug。

4. **L5 的省市区缓存只按 seed 校验**
   若将来 `PLANET` 参数变化但 seed 不变（同星球改参数），`_settleSeed` 不会失效。
   与 L1 的 `_pver` 同类问题，加参数版本即可。

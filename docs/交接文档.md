## 七、工作流与纪律（给下一位 AI 的操作手册）

### 7.1 改代码的标准流程（本项目约定俗成）

```
① 侦察（读代码 + 读测试引用面 + 读文档相关章节）
② 写 .py 补丁脚本（放 .workbuddy/tools/patch/，命名 patch_v89XX_*.py）
   · 每条改动「锚点唯一命中 + 落盘回查」；脚本要幂等（命中 0 且新文本已在 → SKIP）
③ 执行 + node --check 语法检查
④ 行为探针（node -e 建局模拟，验证运行时行为）
⑤ 跑三件套：audit → smoke → e2e
⑥ 文档同步五处：需求档案 + 设计规范 + AI工作备忘 +（涉及故事库时）story/README + 工作记忆
⑦ git 不主动提交（老板有同步任务）
```

### 7.2 铁律清单（历史上踩过的坑，均已写入 AI工作备忘）

1. **P 码表/字段改动**：删机制要列「唯一出口清单」逐处退役（死函数会被 audit 抓）；audit 检查清单要同步。
2. **测试断言用下限语义**：锚点计数断言一律 `>=`，严禁 `=== N`（会被后续批次顶高误红）。
3. **同文件修改串行执行**：一次消息里两处 Edit 同一文件会以同底稿写回、后者覆盖前者。
4. **文档混合行尾**：`story/README.md` 表格行 CRLF、其余 LF——补丁匹配先探明字节；需求档案/设计规范为 CRLF、备忘 LF。
5. **插入逻辑先归一化文件末尾换行**（历史事故：待办表末尾无换行时行后插入粘连）。
6. **「被调用 ≠ 被消费」**：返回值流向也要有断言（烽火 bug 教训）。
7. **成本数值改动会踢爆「靠环境资源恰好够」的旧测试**：测试补环境、不改判据。
8. **UI 弹窗预算**：默认弹窗 660×620；改面板先算高度（不出下拉条是硬规矩）。
